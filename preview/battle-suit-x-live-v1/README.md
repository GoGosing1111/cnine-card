# X-BODY 운영 연결 검수 — 2026-09-27

사용자는 기존 X-BODY V2 라이브 배포를 지시했고, 추가 광역기 천룡 강림도 실제 검수 영상을 본 뒤 **“이 연출로 승인”**했다. 원본 107개와 광역기 62개의 승인 해시는 각 프리뷰 `approval-20260927.json`에 고정한다. 승인 자산이나 검 모양을 다시 그리지 않았다.

이 화면은 운영 `project-v-pixi-battle.bundle.js`와 `js/battle-v3-live.js`를 직접 로드한다. 전용 가짜 렌더러·별도 스킬 팩토리를 삽입하지 않는다. `fixtures.json`은 실제 서버 시뮬레이터의 고정 검수 데이터이며 실계정 조회·지급 API를 호출하지 않는다. 카드 원화/프레임/도크/몬스터는 기존 V3 아트 어댑터를 사용한다.

## 운영 어댑터

- `XBodySwordAnimation.js`가 승인된 `XBodyFX.js`와 `DragonFX.js`의 그리기 함수를 그대로 재사용한다. 프리뷰의 자체 타임라인만 생성하지 않도록 오버라이드하고 운영 GSAP 타임라인에 연결한다. PixiJS 8.20.0 / GSAP 3.13.0 각 한 벌을 사용한다.
- 일반 공격은 기존 서버 영수증만 동일 대상별로 순서대로 묶는다. 6타 이상인 묶음에 천광 연섬을 사용하고 짧은 묶음에는 일섬을 사용한다. 폭주 구간의 따라잡기 배속을 마지막 회복까지 유지해 공격 큐가 줄 때 다시 느려지는 문제를 막는다. 피해량·발수·순서·적 신원을 재계산하지 않는다.
- 천룡 강림은 기존 공용 `BattleSuitSkillChipPlayback` 시계와 대상 ID를 사용한다. 2.18/2.24/2.30/2.36/2.42초의 접점, 4.6초의 동작·잔향을 보존한다. 대상이 퇴장·교체되면 새 몬스터에 과거 반동을 주지 않는다.
- 진행 중인 광역기에 일반 서버 타격이 들어오면 공용 지원 액터의 기존 영수증 처리로 반영한다. 서버는 광역 대상과 피해를 확정하며 연출은 피해를 만들지 않는다.
- 단일→다중 전장 재입장 과정에서 폐기된 몬스터 텍스처가 캐시에 남는 기존 문제도 재현했다. `ScrapyardBattleEngine.js`가 텍스처와 소스의 유효성을 확인한 뒤 다시 로드하도록 수정했다.

## 확인 결과

`qa/browser-report.json`: PC 1440×1000·모바일 390×844에서 일섬/천광 연섬, 단일/다중 광역기, 일시정지·배속·취소·PVP 제외를 확인했다. 일반 검수 피해 283,856, 단일 광역 1,064,460(5타), 다중 광역 5,322,300(25타)이 서버 기록과 일치한다. 자산 누락·콘솔 오류 0. 취소 뒤 효과 0. `qa/*-impact.png`를 실제로 확인했다.

`qa/full-battle-report.json`: 같은 운영 번들의 전체 연속 전투를 PC 1배속·모바일 2배속으로 검수했다. 각각 일반 공격 220회/15,549,868, 광역 50회/10,644,600이 서버와 일치한다. 끝난 뒤 피해 큐·등록 타임라인·효과·대기 그룹 0. 49.6초 서버 타임라인을 PC 약 50.4초, 모바일 약 25.2초에 마쳤다. 수치는 검수용이며 운영 밸런스가 아니다.

이 재생 증빙은 수치 승인 직전 동일한 후보 수치를 내부 검수 플래그로 실행한 결과다. 후속 수치 승인으로 운영 플래그를 ON으로 변경했고, 최종 서버 결과가 검수 결과와 완전히 같은지 회귀검사한다. `build-fixtures.mjs`도 최종 운영 플래그를 직접 사용한다. 승인 자산과 재생 로직은 이 전환으로 바뀌지 않았다.

광역 원화·몸 8프레임·효과 48프레임·원본 검 합성·프롬프트·11단계 공정·실제 재생 영상은 [천룡 강림 제작 기록](../battle-suit-x-dragon-v1/README.md), 기존 32몸/60효과는 [X-BODY V2 기록](../battle-suit-x-v1/README.md)에 보존한다.
