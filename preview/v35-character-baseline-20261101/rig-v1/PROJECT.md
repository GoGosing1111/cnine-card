## 작화와 리깅

기준 원본은 [baseline-v4.png](../baseline-v4.png), SHA-256 `fd8eea2da078ba3f7cfcef7da44946612e950ce2b0d0cd778a4b57976e00aa44`다. 원본은 수정하지 않았다. Sharp로 원본 픽셀을 선택·마스킹·크롭해 17개 부품을 만들고, 25개 뼈·4개 IK·메시 3,199정점/6,296삼각형을 구성했다. 선택된 RGBA가 원본과 같은지, 원본의 보이는 픽셀이 빠지지 않았는지 [독립 픽셀 대조](qa/provenance.json)로 확인했다. 관절 경계에는 원본 픽셀 2px 겹침이 있다. 이것은 숨겨진 신체를 보완 작화한 결과가 아니다.

`.spine`은 설치된 Professional 편집기의 파일/CLI import → save → reopen → export를 거쳤다. 최종 파일에 스켈레톤은 하나이며 `setup`, `idle` 두 애니메이션이 유지된다. 이번 단계에서 GUI 원격 입력, Krita·Aseprite·Effekseer, 추가 AI 작화는 사용하지 않았다. 원화 생성 이력은 상위 PROJECT.md에 보존한다.

## 대기와 좌표

- `setup`: 기준 자세 확인용 0.1초.
- `idle`: 4.2초 반복. 들숨 1.45초, 날숨 2.75초. 가슴·머리와 코트 끝의 작은 변화이며, 골반·다리·양발·검·파지 손은 기준 위치를 유지한다. 가슴의 최대 이동은 원화 좌표 약 4.14px다.
- 원화 좌표는 1024×1536, 배치 원점 `(512,1450)`. Spine 변환은 `(x−512,1450−y)`이며 Pixi 런타임의 yDown을 적용한다. 이 배치 원점을 실제 전장 바닥으로 확정한 것은 아니다.
- 양발 접점은 원화 `(143,1440)`, `(846,1422)`, 손잡이 기준 `(279,674)`, 칼끝 `(1011,1113)`. 두 발의 y 차이는 원화 자세 그대로 보존했다. 실제 진형 배치·좌우 반전·전장 표시 크기는 후속 연동에서 검증한다.
- 상체와 옷의 변형은 부품별 가중치를 사용한다. 무기와 파지 손은 같은 강체 변환을 사용하며 검신 자체를 휘지 않는다.

현재 분리는 보이는 원본 픽셀만 갖는다. 크게 다리를 굽히거나 팔·몸통을 돌리는 공격은 관절 안쪽과 가려진 몸, 교체 손/자세의 보완 작화부터 필요하다. 이 대기 리그를 무리하게 늘려 공격 완성본으로 쓰지 않는다.

## 검수 근거와 한계

- 밝음/어두움의 실제 정지 렌더와 원화를 비교했다. 실루엣·머리·손·검 크기와 조립을 직접 확인했다. 전체 화면 RGB 평균 오차는 255단계 기준 어두움 약 0.107, 밝음 약 0.132다. 겹침·알파 합성·래스터화 차이가 있어 픽셀 완전 동일 재현이라고 주장하지 않는다.
- 대기 전체 127시점에서 메시 뒤집힘 0, 비정상 좌표 0, 발·무기·파지 손 정점 이동 0, 반복 경계의 메시 좌표 차이 0을 확인했다. [geometry-latest.json](qa/geometry-latest.json).
- 정상 속도 실시간 재생에서 루프 경계 3회를 관측하고 실제 캔버스를 녹화했다. 주요 시점과 밝음/어두움·390px 화면을 이미지로 직접 검토했다. 영상 전체를 사람이 연속 감상한 검수와 구분한다. [playback.json](qa/playback.json), [visual-review.json](qa/visual-review.json).
- 정지·0.25/0.5/2배속·탐색·화면 비활성/복귀를 검사했다. 단일 Pixi 캔버스와 GSAP 시간을 사용하며 Spine autoUpdate는 꺼져 있다. 검토 화면만 기존 V3 EffectScene에 연결했다. 실제 PVE/PVP 전투·모바일 실기기 성능 검사는 아니다.
- 생성 원본의 최대 알파 254를 보존했다. 이번 배경 비교가 모든 전장과 합성에서의 최종 알파 품질 승인을 뜻하지 않는다.

초기 호흡의 골반 이동은 거의 편 뒷다리의 IK 변화로 허벅지 가장자리가 벌어져 제외했다. 현재 호흡 대기는 하체를 고정한 설계다. 후속 체중 이동은 관절 분리와 가려진 그림을 다시 준비해 검수해야 한다.

## 재현

프로젝트 루트에서 실행한다. 기존 의존성과 Spine 설치를 재사용한다.

```powershell
node preview/v35-character-baseline-20261101/rig-v1/author.mjs --idle
node preview/v35-character-baseline-20261101/rig-v1/native.mjs
node preview/v35-character-baseline-20261101/rig-v1/build.mjs
node preview/v35-character-baseline-20261101/rig-v1/serve.mjs
```

서버 실행 후 별도 터미널에서 `qa/provenance.mjs`, `qa/render.mjs`, `qa/playback.mjs`를 Node로 실행한다. `render`/`playback`은 기록된 로컬 Playwright·Chrome 경로를 사용한다. 이 검사는 Chromium 데스크톱의 모바일 화면 크기를 포함하며 실제 폰 검사가 아니다.

`native.mjs`는 입력 해시에 따른 새 이름에 import한다. **기존 .spine에 `-r`을 반복하면 스켈레톤이 추가되므로 덮어쓰기 용도로 쓰지 않는다.** 최신 .spine이 기록된 해시와 달라지면 사용자 편집을 보존하기 위해 생성 내보내기를 중단한다. 편집기에서 수정한 뒤에는 그 .spine을 새 정본으로 기록하고 다시 export해야 한다.

과거 시도는 로컬에 보존한다. 이름이 해시 없는 `swordsman-v35.spine`은 초기 import 실험 이력으로 현재 전달본이 아니다. 이번 전달은 원격 저장소의 프리뷰/제작 기록 범위이며 게임 운영 배포는 포함하지 않는다.
