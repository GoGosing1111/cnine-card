# V3 배치형 그리드 프리뷰

2026-09-11 · **PC_USER_APPROVED / MOBILE_REVIEW_PENDING** · 운영 미연결.

## 사용자 확정 범위

- 6시 방향의 비효율적인 빈 칸과 전장을 둘러싸는 외곽선을 제거한다. 직사각형 전체를 채우지 않고 실제 배치 자리 아래에만 타일을 그린다.
- 최종 용병 한도는 **진영당 최대 1장**이다. 2장 시안은 사용자가 밀집도를 이유로 철회했다. 두 번째 슬롯·SD·타일·선택지는 없다.
- PVP는 일반 카드 5 + 용병 1 대 일반 카드 5 + 용병 1, 총 12자리다. PVE 아군은 일반 5 + 용병 1 + 슈트 1, 총 7자리다. 현재 PVE 프리뷰의 적은 동시 3마리이므로 초기 바닥은 10칸이다.
- 슈트는 PVE에서만 **아군 진영 가운데**에 놓는다. 전장 전체의 중앙 또는 하단 카드창 뒤가 아니다.
- 사용자의 `PC는 그대로 승인`으로 PC 좌표를 고정했다. 후속 변경은 모바일 간격에만 적용했다. 모바일 수정안은 별도 사용자 검수 대상이다.

## 실행과 검수

```text
npm run build:v3-wide-grid-preview
npm run test:v3-wide-grid
npm run test:scrapyard-v3
node scripts/qa-v3-wide-grid-preview.mjs
```

정적 서버: `http://127.0.0.1:8791/preview/v3-wide-grid-v1/`.

- `?scenario=PVP&grid=wide`: 최종 6 대 6 배치. PVP는 편성 배치 검수만 제공한다.
- `?scenario=PVE&grid=wide`: 용병 1 + 아군 중앙 슈트와 연속 몬스터 전투 검수.
- 기존 / 확장안: 실제 기존 V3 7×6·5인 배치와 비교한다. 기존안은 추가 용병 시안을 숨긴다.
- 아군·상대 용병의 미배치 / 1장 선택은 독립적이다. 미배치하면 해당 SD와 타일을 모두 제거한다. 전투 중에는 모드·배치 변경을 막는다.
- PVE의 용병은 배치 검수용이다. 기존 5장 + 슈트 판정과 9마리 → 보스의 전투 스냅샷은 바꾸지 않는다. 용병 능력치·등급·획득·저장/API 활성화 승인이 아니다.
- 브라우저 검수 스크립트는 외부 Playwright를 사용한다. 필요하면 `PLAYWRIGHT_MODULE_URL`, `QA_CHROMIUM`, `QA_BASE_URL`, `QA_OUTPUT_DIR`을 지정한다. `QA_WIDTH`로 특정 해상도만 재검증할 수 있다. 게임 의존성은 추가하지 않았다.

## 최종 좌표

좌표는 V3 디자인 단위이며 PC 씬 1600×820, 모바일 씬 1050×1500과 루트 배율은 그대로다. 상대 카드·용병은 X만 반전한다. 슈트는 반전하지 않는다.

| 자리 | PC 승인 좌표 | 모바일 수정 좌표 |
| --- | --- | --- |
| 일반 1 | 280, 260 | 248, 641 |
| 일반 2 | 695, 280 | 439, 736 |
| 일반 3 | 125, 425 | 178, 816 |
| 일반 4 | 655, 520 | 435, 994 |
| 일반 5 | 300, 575 | 205, 1059 |
| 용병 1 | 495, 250 | 330, 550 |
| PVE 슈트 | 410, 425 | 311, 869 |

- 타일은 PC 190×78, 모바일 120×68이다. 배치의 좌표를 위해 가상의 빈 칸을 채우지 않는다.
- PC 일반 카드 간 가로 범위는 1350, 모바일은 694다. 모바일 수정 전 890 대비 약 22% 좁혔다. 전체 유닛의 세로 배치 범위도 655에서 509로 약 22% 줄였다.
- 일반 카드와 슈트는 공통 V3가 계산한 기존 `restScale`을 그대로 사용한다. 이동 중 원근 크기도 기존 위치를 기준으로 환산한다. 이름/체력 패널은 해당 SD 바로 위로 배치한다.
- 사망한 유닛은 타일을 숨기고, 증원은 살아 있는 실제 슬롯에만 다시 그린다. 배경 장식이나 영구적인 빈 아래쪽 행은 추가하지 않는다.

## 공통 엔진·리소스

`package-lock.json`: PixiJS **8.20.0**, GSAP **3.13.0**. 버전·라이브 번들 변경 없음.

- `source/WideGridBattleEngine.js`: 기존 `ScrapyardBattleEngine` / 공통 `BattleEngine`을 재사용하는 배치 어댑터다. PVP는 공통 카드 아트 바인딩을 직접 사용하며, 추가 Application·Renderer·공격 판정은 없다.
- `source/MercenaryStations.js`: 기존 Pixi 전투 레이어에 배치 검수 SD만 추가한다. 별도의 `allies`, `enemies`, `characters`나 카드 도크 원소로 넣지 않는다. GSAP 스킬·별도 사운드를 새로 제작하지 않았다.
- 용병 SD는 공용 `createMercenaryBattleArtAdapter`로 단일 로스터에서 V-013 라비에나 / V-017 마레나를 읽는다. `battleSprite`와 발끝 기준점을 사용하며 원화를 전투 SD로 사용하지 않는다.
- `battle-bridge.js`: 기존 연속 전투 검수 브리지의 재생·취소·초기화 흐름에 PVP/PVE 표시 모드만 분리했다. 실제 `ProjectVBattleV3Live.createRenderer`, 원화 카드 도크·등급별 프레임·CSS·아트 어댑터는 공유한다.
- 슈트는 승인된 기존 전신·사격 아틀라스를 그대로 사용한다. 원본 총기 픽셀, 발바닥·총구 기준점, 원음과 사격 주기는 변경하지 않았다.

## 검증과 출시

- 배치 전용 단위 검사 13/13, 기존 연속 전투·서버·복구 검사 60/60 통과.
- 브라우저 자동 검수는 1600×1050, 1366×900, 390×844, 320×740의 PVP/PVE 배치·미배치·초기화, 원래 카드/슈트 배율·원화 도크·전투 스냅샷 보존을 확인한다. 실제 휴대폰 하드웨어 검수와 구분한다.
- 생성 스크린샷과 실행 결과는 `output/v3-occupied-grid-20260911/`에 기록한다.
- 네 해상도의 PVP/PVE 배치·미배치·모드 전환·단일 캔버스 검사 완료. 데스크톱에서는 실제 GSAP 시계로 360개 이벤트, 일반 적 9마리 + 보스까지 10/10 격파와 정상 종료를 확인했다. 공격 경계 일시정지 후 초기화, 사격 큐 0, 사망한 아군 3명·적 10명의 빈 타일 제거도 확인했다. 최종 생존 일반 카드 2 + 용병 1 + 슈트 1 = 4칸이다.
- 브라우저 JavaScript 오류·HTTP 실패는 없었다. 기존 공용 V3 초기화에서 아포칼립스 선택 자산 캐시 경고, 헤드리스 스크린샷에서 GPU ReadPixels 경고가 발생했다. 이번 배치 변경과 별개이며 라이브 코드의 자산 수명은 수정하지 않았다.
- 운영 `preview/project-v-v3/`, `js/`, `css/`, `functions/`, `assets/`는 이 작업에서 수정하지 않았다.
- 이 전장 변경은 `docs/pve-continuous-overhaul-v1.md`의 통합 출시 묶음이다. PC 배치 승인을 전체 개편 출시 승인으로 확대하지 않는다. 전체 묶음·모바일 검수 완료 전 단독 운영 연결/배포를 하지 않는다. 이번 범위 커밋 후, 통합 출시 시 깨끗한 배포 트리에서 `npm run release:gate` → `npm run deploy:production`을 적용한다.
