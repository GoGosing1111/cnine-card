## 프레임 보존과 실제 V3 연결

생성 시트의 간격이 정확한 격자가 아니므로 격자선으로 캐릭터를 잘라내지 않는다. `build-resources.mjs`가 알파로 분리된 16개 몸체를 찾고 가장 가까운 몸체에 잔광 픽셀을 배정한다. Diim은 잔광 두 개가 닿아 핵심 실루엣 판별 임계값만 128로 사용한다. **출력 픽셀의 알파나 색상은 수정하지 않는다.** 모든 비투명 RGBA 픽셀을 정확히 한 번 복사하고 원본 좌표와 해시를 기록한다. 확대·축소·재압축된 JPG·비선형 변형을 사용하지 않는다.

게임 표시는 캐릭터별 고정 몸체 배율을 사용한다. 대기 원본 기준 몸체 픽셀은 봉순 308, 조은 327, 디임 292, 클로 305, 단검 350이며 V3의 몸체 높이 345에 맞춘 균일 배율 하나를 모든 동작에 적용한다. 웅크리거나 쓰러졌을 때 프레임 경계에 맞춰 몸을 늘리거나 줄이지 않는다.

후속 `캐릭터가 작아지는 현상있나 확인해라` 검사에서 동작 시작·종료·취소에 초기 캔버스 기준 배율이 복원되어 몸체가 정상의 **57.0~68.4%**로 작아지는 문제를 확인했다(`qa/scale-before.json`). 중립 자세를 몸체 배율로 다시 등록하고 모든 복귀 경로에도 같은 기준을 적용했다. 5종의 화면상 배율은 PC·모바일의 시작·진행·종료·취소에서 **100%**를 유지한다. 기존의 동작 중 배율 검사는 이 복귀 경로를 놓쳤으므로 별도 회귀 검사를 추가했다.

후속 `캐릭터 대기에 움직임 최소화해라`에 따라 5종의 대기는 첫 대기 자세로 고정한다. 두 대기 프레임의 번갈아 표시와 기본 엔진의 몸체 호흡 배율을 사용하지 않으며, 발 위치·몸체 배율을 유지한다. 원본 두 대기 프레임은 모두 보존하고 이동·공격·피격·쓰러짐 동작은 유지한다.

`source/preview.js`는 기존 `preview/project-v-v3/source/project-v-pixi-battle.src.js`, `BattleEngine.js`, `BattleCharacter.js`, `js/battle-v3-live.js`, 용병 아트 어댑터를 사용한다. 일반 카드 5장과 별도 용병 슬롯, 라이브 카드 도크·원화·프레임을 유지한다. 별도 전투 렌더러를 만들지 않았다.

`source/BloodmoonFX.js`는 PixiJS **8.20.0**의 기존 효과 레이어와 GSAP **3.13.0** 타임라인 하나를 사용한다. 번들에서 각 라이브러리 한 벌을 확인했다(`build-report.json`). 근접 스킬은 준비 0~0.72초, 방출 0.72~1.72초, 충돌 1.72초, 잔광 소멸 3.48초, 복귀 3.6초이며 기본 공격 접점은 0.43초다. 연출은 피해·승패를 계산하지 않는다. 새 사운드는 추가하지 않았다.

`투사체는 일직선으로 빠르게 공격하게 해`에 따라 봉순의 투사체는 고정된 발사 자세의 총구부터 각 표적까지 **등속 직선으로 0.12초**에 도달한다. 기본 공격은 0.18초에 발사해 0.30초에 명중하고 0.82초에 끝난다. 스킬은 0.24초부터 **0.07초 간격으로 세 발**을 발사하여 0.36 / 0.43 / 0.50초에 명중하고 1.2초에 끝난다. 후속 자세 변화가 출발점을 끌어당기지 않으며, 피격 반응은 각 탄이 도착한 뒤 시작한다.

배속 0.25~2배·일시정지·탐색·재시작·취소·화면 종료를 같은 시계로 처리한다. 취소 시 효과와 등록 타임라인을 제거한다. 빠르게 캐릭터를 바꿀 때는 로드와 해제를 순차 처리해 이전 선택이 새 텍스처를 해제하지 않게 했다. 모바일 프레임 높이가 반복해서 늘던 문제는 이 프리뷰의 `fit-preview.mjs`에서 수정했다. 좁은 화면에서는 스킬 효과만 충돌 중심을 유지하며 화면 안에 맞춘다. 캐릭터 배율에는 영향을 주지 않는다.

## 할로윈 SS보다 높은 준비 밸런스

단일 수치 파일은 `balance.mjs`다. 5종 공통 기본 전투력 **356,400**은 현재 바토리 297,000보다 **20%**, 할로윈 기본 7종 237,600보다 **50%** 높다. 연계 능력·자연 속도·추가 행동·PVP 피해 상한도 함께 조정했다. V-960~V-964는 검사에 사용하는 별칭이며 운영 코드 배정이 아니다. SS는 시뮬레이션에서 같은 조건으로 비교하기 위한 등급이다.

| 용병 | 시연 스킬 | 총 스킬 배율 | 재사용 | 자연 속도 | 카드 1행동당 추가 행동 | 바토리 상대 승률 |
|---|---|---:|---:|---:|---:|---:|
| 나무늘봉순 | 적월 섬멸탄 · 개틀링 탄막 | 1,440% | 2행동 | 3.05배 | 3.75 | 66.7% |
| 조은 | 홍련의 속박 · 채찍 제압 | 1,160% | 1행동 | 2.90배 | 3.50 | 86.5% |
| 디임 | 적월 단죄 · 약해진 적 처형 | 1,160% | 1행동 | 2.95배 | 3.50 | 65.3% |
| 독자 캐릭터 A | 혈조 교차참 · 두 행동 연속 클로 | 2,640% | 1행동 | 3.05배 | 3.75 | 84.4% |
| 독자 캐릭터 B | 월영 급습 · 준비 기술 중단 | 1,180% | 1행동 | 3.15배 | 3.75 | 85.4% |

공통 스킬 비용은 20, 행동 에너지 회복은 10이다. 클로의 총 배율은 두 타격에 나뉘므로 타격당 1,320%다. 기존 회피·방어·보호막·중단 면역·PVP 상한을 사용한다. PVE 최소 피해 보정은 **false**다. 보정을 켠 대안은 성장 PVE 표적을 1행동에 제거하는 과도한 격차가 있어 미채택했다(`qa/balance-floor-rejected.json`).

실제 서버 시뮬레이터에 검수 정책만 주입했다. 원본 서버 전투 파일이나 운영 정책은 수정하지 않았다. 9가지 카드/장비/성장 편성 × 16개 고정 시드 × 공격·방어 양쪽 × 5종 × 바토리 및 할로윈 7종 = **PVP 11,520회**다. 40개 용병 조합의 종합 승률 모두 50%를 넘었다. 특정 계정·상대·승자 판정을 위한 보정은 없다. 각 세부 편성에 상성이 남으며 실제 이용자 승률을 뜻하지 않는다.

PVE는 같은 서버 계산으로 13종 × 2편성 × 4시드 = **104회** 확인했다. 블러드문 5종 모두 두 조건에서 4/4 클리어했다. 평균 턴은 카드 2천만 편성에서 봉순 5, 조은 7.5, 디임 5, 클로 4, 단검 6.5(바토리 9), 성장 장비 편성에서 4 / 64.75 / 63.75 / 63.25 / 64.75(바토리 64.75)다. PVE 역할별 피해량과 상대 방어력 영향은 남으며 모든 콘텐츠에서 동일한 우위를 보장하는 설정은 아니다.

## 검증과 재현

`qa/browser-report.json`: PC 1440×1100, 모바일 390×844에서 5종씩 10사례를 확인했다. 6상태 재생, 전용 슬롯, 균일 배율, 근접 충돌, 0.25배속과 일시정지, 취소, 재선택, 1배속 완주와 종료 정리를 검사했다. 페이지 오류 및 404는 0건이다. 전용 패널·버튼 이미지, 장식/글자 겹침, 전체 가로 넘침과 캐릭터 부츠/무기를 스크린샷으로 직접 확인했다.

`qa/resource-report.json`: 승인 원화 해시, 사용자 선택 봉순 해시, 80프레임의 RGBA 원본 대조·중복/누락 없음, 효과 80프레임의 개별 형태, 6상태 범위와 충돌·완료, 비동기 로드 실패 정리, 현재 수치 보고서, 미확정 등급·개방 잠금을 확인했다.

`qa/motion-regression.json`: PC·모바일 5종의 시작·중간·완료·취소 화면상 몸체 배율, 실제 대기 1회 이상 반복 중 자세·발 위치·배율 고정을 검사한다. 봉순의 기본 공격·스킬에서 각 탄의 여섯 시점으로 직선 궤적, 등속 진행, 고정 총구·표적, 0.12초 비행, 명중 전 피격 없음과 취소·완료 시 효과 정리를 확인한다. 실제 1배속 스킬 완주 후 배율과 타임라인 정리도 검사한다.

`finalize-review.mjs`는 자산·화면·번들·밸런스 지문이 검사 당시와 같을 때만 기술 PASS를 기록한다. 콘텐츠별 원화/전투 승인 분리 규칙에 따라 새 리소스의 사용자 시각 승인과 운영 연결은 대기 상태다. 가격·확률·발행량·보유 데이터·운영 API 변경은 없다.

프로젝트·node_modules 복사본을 만들지 않고 기존 체크아웃을 재사용했다. `.codex` 종료 시점 감사는 49.131GiB, 스캔 오류 0건, 50GiB 미만이었다. 원화·프롬프트·생성 원본을 보존하고 재생성 가능한 시뮬레이션 임시 번들만 정리했다.
