## 직접 클릭 드랍

- 확정 KO 이벤트를 재생한 뒤 로컬 서버가 별도 암호학적 난수로 확률·좌표·아이템을 결정한다. 전투 payload에 미래 드랍 목록/좌표를 넣지 않는다.
- V3의 기존 Pixi 효과 레이어에 아이콘을 렌더링하고, 동일한 화면 좌표에 키보드/터치 가능한 버튼을 맞춘다. 고정 보상 버튼이나 자동 흡수 기능은 없다.
- 필드 안 연속 좌표로 무작위 배치한다. 최근 두 위치와 가까운 점 및 현재 아이템의 클릭 영역과 겹치는 점을 피한다. 공간이 부족하면 해당 드랍을 생략한다. 몬스터 사망/교대 때문에 기존 아이템 위치가 미끄러지지 않는다.
- 클릭 요청에는 원정 ID·드랍 ID·토큰·좌표가 필요하다. 서버가 유효 상태/좌표/만료 시각을 검사한 뒤 한 번만 획득 처리한다. 요청 재시도는 같은 영수증을 반환하며 확률·아이템·유효 시간을 다시 만들지 않는다.
- 초당 6회를 넘는 유효 클릭은 제한하고, 미도달 미래 KO/지나간 미확인 KO/다른 원정의 아이템을 거절한다. 늦게 재요청해 소멸된 드랍을 되살릴 수 없다.
- 소멸 시간은 벽시계 기준이다. 전투 일시정지 중에도 흐르며, 정지 중에는 획득할 수 없다. 전투가 끝나면 남은 아이템의 기존 유효 시간까지 획득할 수 있고 모두 사라지면 정산한다. 먼저 정산/철수하면 미획득 드랍은 놓친 것으로 기록한다.
- 프리뷰에서는 실패/철수 때도 **직접 클릭해 이미 획득한 항목만** 결과에 남긴다. 운영의 실패 보존 정책은 별도 확정 대상이다.
- 무작위 위치는 고정 좌표 오토클릭을 방해하지만 화면 인식 봇이나 조작된 API 요청을 완전히 막는 인증 수단은 아니다. 운영 연결 시 계정 인증·권한, DB 원자적 획득/정산, 재접속 복구, 서버 진행 상태와 이상 클릭 탐지가 필요하다.
- 8958 단독 로컬 프리뷰만 메모리 세션이다. OWNER 운영 API는 계정별 서버 상태를 DB에 보관해 드랍·클릭·정산 재시도를 복원한다. 새로고침 시에는 새 검수 원정을 시작하며 실계정 지급·차감은 없다.

- `functions/_battle_v2_preview.js`에는 명시적으로 요청한 프리뷰만 12슬롯/구간 장벽/전투 시계 제한을 사용할 수 있는 경계 검사 옵션을 추가했다. 기본값은 기존 5슬롯이며 기존 PVE/PVP 기본 판정은 동일하다.
- 실제 빌드 입력·현재 엔진/스킬칩/서버/번들 해시는 [engine-build.json](engine-build.json)에 있다. V1 몰이사냥 코드 입력은 0개다.
- `source/HuntBattleEngine.js`: 기존 Pixi effectLayer에 16프레임 등장 아틀라스를 합성하고 공용 GSAP timeline으로 샘플링한다. 등장 0.2초부터 형상이 바뀌는 연속 프레임을 재생하고 0.48초에 전투 진행을 풀며 잔여 연출은 같은 타임라인이 정리한다. 몬스터 발바닥 좌표를 기준으로 한다.
