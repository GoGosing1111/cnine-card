# 하이퍼팩 V1 — 출시 준비 / 개봉 연출 검수

2026-09-09 사용자 요청. 프리미엄 카드팩 판매를 종료하고 같은 상점의 팩을 한 칸씩 이동한다. 기본 순서는 **고급 → 리미티드 → 슈퍼스타 → 하이퍼**다. 기존 프리미엄 큐브·보유 카드·뽑기 이력은 삭제하지 않는다. 이미 지급된 프리미엄 `COMPLETED`/`APPLIED` 영수증 복구는 유지하고 신규·재시도 구매만 차단한다.

## 확정 / 미확정

- 확정: 첨부 원본 팩 이미지, 1회 **500,000,000코인**, 최대 10회 **5,000,000,000코인**, 결과 종류 `MISS / MASTER_STAR / MYSTIC_ENERGY / MERCENARY`.
- 사용자가 확률과 재료 수량은 **CMS에서 직접 설정**하기로 답했다. 기본값은 모두 `null`이며 자동으로 확률·수량을 만들지 않는다. 확률 합계·재료 수량과 미설정 상태를 CMS에서 표시한다.
- 용병 등급·개별 획득풀·획득 저장 계약은 여전히 승인 전이다. 원화 예시는 베스페라 V-004이며 **보상풀 지정이나 등급 확정이 아니다**. 일반 5장 덱과 별도 용병 1슬롯 계약을 변경하지 않는다.
- 상태: `PREPARATION_ONLY`. 상점 표시와 CMS 초안 저장만 연결한다. 관리자/OWNER도 실제 개봉 불가. 확률 합계가 100%가 되어도 잠금은 유지한다.
- **실제 결제·추첨·보상 지급 기능은 아직 연결하지 않았다.** 승인 후 별도 원자적 지급·중복 요청 검증을 구현·검수해야 한다. `HYPER_PACK_RELEASE_ENABLED=false`만 바꿔 출시할 수 없다.

## 코드 / API

- 상점: `js/app.js`, `css/hyper-pack-v2076.css`.
- 준비 계약·설정: `functions/_hyper_pack.js`.
- `GET /api/hyper-pack/config`: 공개 준비 상태, 5억·최대 10회.
- `POST /api/hyper-pack/open`: 인증/횟수 검증 뒤 항상 409 `HYPER_PACK_NOT_RELEASED`. 사용자 재화·인벤토리·카드·영수증 변경 없음.
- `GET/PATCH /api/admin/hyper-pack`: `CARD_EDIT` 권한, `app_meta.hyper_pack_draft_v2076`에 초안 보관. revision 비교와 DB 조건부 갱신으로 다른 관리자의 변경을 덮어쓰지 않는다. 활성화 우회·외부 출처 요청은 거부한다.
- CMS: 카드 관리 → 카드팩·등급 확률 세부 설정 → 하이퍼팩. 초안 저장·합계 막대·당첨 시 재료 수량·검수 링크를 제공한다.
- 공개 프리뷰에서는 CMS 이동 링크를 제거하고 **로비로 가기**(`/?screen=home`)를 제공한다. 같은 탭에서 게임 로비로 복귀하며 CMS 설정 기능은 유지한다.
- 미스틱 에너지의 실제 인벤토리 식별자는 `STARLIGHT_ARMOR_CORE`다. 가짜 `MYSTIC_ENERGY` 아이템을 만들지 않는다.

## 실제 렌더링 / 타임라인

- `js/hyper-pack-fx-v2076.src.js` → `js/hyper-pack-fx-v2076.bundle.js`.
- 기존 공용 UI 런타임 `js/ui-fx-vendor-v2045.bundle.js` 재사용. 잠금 버전 **PixiJS 8.20.0 / GSAP 3.13.0**. V3 전투 렌더러·카드 프레임·전투 상태는 변경하지 않는다. 일반 게임 진입에 연출 번들을 선로딩하지 않는다.
- PixiJS: 원본 팩 스프라이트, 공간 먼지, 타원형 링, 번개 분기, 섬광 입자, 결과 이미지와 광원. GSAP: 진입·집광·해제·공개·한 칸 밀기 타임라인.
- 개별 타임라인 기준(초): 진입 0–0.35, 집광 0.35–1.05, 봉인 번개 0.8, 해제 충돌 1.04, 결과 나타남 1.12, 결과 공개 콜백 1.40, 다음 칸 이동 3.0(용병은 3.7)–3.4/4.1.
- 꽝은 회색 소멸, 마스터의 별은 금빛 별·파편, 미스틱 에너지는 보라색 코어, 용병은 원화 카드·확장 광원으로 구분한다.
- 최대 10개를 순차 표시한 뒤 전체 결과 목록을 유지한다. 1회는 마지막 결과를 크게 유지한다. 일시정지/재개, ×1/×2, 전체 결과 바로 보기, 재시작을 지원한다. 모바일 재생 시 무대를 화면으로 가져온다.
- 전투 충돌/피해 계산 없음. 소리 추가 없음. CSS는 레이아웃·버튼·결과 목록에만 사용한다.
- 타임라인 중단 시 Promise를 해제하고 generation으로 이전 콜백의 진행을 차단한다. 페이지 이탈 시 타임라인/ResizeObserver/Application을 정리하며 공유 텍스처는 파괴하지 않는다. 이전 표시 객체는 렌더러 분리 후 100ms 뒤 폐기한다.

## 검수 기록

- 원본 SHA-256 일치 및 로컬 PNG 로드 확인.
- `npm run build:hyper-pack`, `npm run test:hyper-pack`: 서버·설정·가격·권한·기존 영수증 보존·가상 연출·로비 복귀 계약 **9개 통과**.
- `npm run test:superstar-pack`: 하이퍼 추가 후 새 순서로 갱신한 회귀 검증 통과. 슈퍼스타 개봉 권한·확률·기존 지급 기능은 유지한다.
- 브라우저: 실제 상점 렌더 함수로 4개 팩 순서·첨부 원본·1회/10회 가격·잠금 버튼 확인. PC 개봉 10칸 누적, 정지 중 진행 05/10 유지, 재개·건너뛰기·재시작 정상. 모바일 390px, 가로 넘침 없음.
- CMS: **별도 로컬 모의 저장소**에서 확률 합계 100%, 재료 수량 저장·재조회와 잠금 유지 확인. 이때 시연 수치는 운영 DB에 저장하지 않았다.
- 프리뷰의 고정 결과 순서는 확률 모델이 아니며 `preview:true / granted:false / quantity:null`이다. 서버 API·결제 호출이 없다.
- 운영 배포 전 전체 `npm run release:gate`를 통과하고 `npm run deploy:production`만 사용한다. 다른 작업 트리의 진행 중인 PVE 개편·리소스 수정은 포함하지 않는다.
