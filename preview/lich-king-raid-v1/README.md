# 리치왕 정벌 — 고난도 기믹 검수판

## 편성·기믹·전체 화면 후속 — 2026-10-01

최신 운영 검수는 공대원 각자의 PvE 카드 5장·용병·배틀슈트를 사용하며 보스 HP와 기믹을 공유한다. 대기방은 기존 레이드 UI, 전투는 PC·모바일 전체 화면이다. 기믹 응답을 즉시 적용하고 서버 시각의 전이/차단 시점을 표시한다. 리치왕 아트 배율은 기존보다 50% 큰 1.65다. PixiJS 8.20.0 객체를 공용 V3 `fxRuntime`에서 가져와 리치왕 번들 안의 중복 라이브러리를 제거했다. 기존 GSAP 3.13.0과 48프레임 감옥·절대영도·말살 자산을 유지한다. 3계정 PC/모바일 조작·표시·종료 검수와 배포 범위는 `docs/lich-raid-loadout-timing-20261001.md`다. 아래 공대장 카드만 사용한다는 설명은 이전 구현 기록이다.

## 운영 레이드 내부 진입 — 2026-09-29

운영의 리치왕 탭은 PVE 레이드 화면 안에서 소개·공대 모집·전장을 표시한다. `/raid/lich-king/`의 마크업과 `live.mjs`를 재사용하고, 독립 페이지 링크는 기존 주소 호환용으로 남긴다. 탭 이탈 시 조회·리스너·전장을 정리하며 공대 상태는 서버에서 다시 조회한다. `battle.src.js`는 `ProjectVBattleV3Live.ensureRuntime()`이 불러온 기존 V3 런타임을 사용하고 엔진을 별도 번들링하거나 게임의 카드 도감을 덮어쓰지 않는다. 공용 PixiJS 8.20.0 / GSAP 3.13.0·진형·카드 프레임·기믹 효과는 유지한다.

PC 1440×1000·모바일 390×844에서 내부 진입·탭 복귀·공대 모집을 확인했고, PC에서는 공용 런타임과 카드 도감 객체 유지·캔버스 1개·공대 출정/나가기를 검증했다. 관련 기록은 `docs/lich-raid-inline-entry-20260929.md`다.

## 운영 TEST 연결 후속 — 2026-09-28

사용자 후속 요청으로 입장권 공대와 OWNER CMS를 추가했다. 운영 입구는 `/raid/lich-king/`, 서버는 `functions/_raid_lich_live.js`다. 초기 TEST에서 OWNER와 지정 계정만 입장하며 보상은 잠겨 있다. 공대장 실제 PvE 덱 5장, 입장권 1장 차감, 공대 목록, 역할 배분, 전원 준비, 강퇴·해산·동시성 검증을 연결했다. 이 폴더의 전투 번들은 기존 V3를 공유하는 운영 전장에서도 사용한다. 아래 LOCAL_REVIEW_ONLY 설명은 별도 `server.mjs` 검수 서버의 경계이며 현재 운영 연결 상태는 `docs/lich-raid-live-test-20260928.md`를 따른다.

2026-09-28. 실제 조작 가능한 독립 검수판. 상태: `LOCAL_REVIEW_ONLY`, 운영 OFF, 보상 잠금. 기존 V3 전장·진형·5장 카드 도크·아트 어댑터를 그대로 사용한다.

## V3 전장 안의 기믹 화면 — 2026-09-28 후속 수정

사용자 지시에 따라 별도 지휘 패널과 모바일 전장/지휘 전환을 제거했다. PC·모바일 모두 V3 전투를 보며 전장 안에서 기믹을 조작한다.

- 역병 숙주의 문양·중첩은 해당 캐릭터의 기존 이름표 위를 따라가며, 발밑에는 Pixi 표적 원이 표시된다. 기존 이름표를 중복하지 않는다.
- 전장에 나타나는 세 구울 문양으로 역병을 전이하고, 세 영혼 문양으로 서리한 내부의 영혼을 구한다. 복합 기믹에서는 두 선택지가 동시에 나타난다.
- 리치왕 시전바가 서리 폭발과 영혼 말살을 구분하며, 말살의 남은 시간과 차단 버튼을 함께 보여준다. 절대영도는 감옥 유지 시간과 대상의 기존 연속 프레임 효과로 표시한다.
- 왕관·순서 봉인은 진행 중인 문양과 입력을 한 줄에 배치한다. 공격 기회는 전장 중앙의 집중 공격·결전 버튼으로 전환하며 서버 공격 간격을 표시한다.
- HP 방벽 목표, 광폭화, 잔재, 영혼과 한정 자원은 같은 화면에서 확인한다. 각 버튼의 역할·자원·시간 제한 판정은 기존 서버가 유지한다.

실제 구현은 `MechanicOverlay.js`, `mechanics.css`, `battle.src.js`다. DOM 기믹 화면은 공용 `.battle-v3-canvas-host`의 자식이고, Pixi 표적 원은 기존 `BattleEngine.effectLayer`의 `LichMechanicTelegraph`다. 숙주 위치는 기존 캐릭터 HUD의 world 좌표를 사용한다. 성공·실패 알림은 기존 `BattleEngine.timeline`의 GSAP으로 재생한다. PixiJS 8.20.0 / GSAP 3.13.0과 기존 48프레임 효과를 재사용하며 새로운 Application·캐릭터 진형·카드 도크·이펙트 이미지·사운드는 추가하지 않았다.

기믹 시계는 서버 스냅샷으로 표시만 한다. 공용 Pixi ticker는 위치·카운트다운 표시를 갱신하고, 화면 크기와 기존 도크 높이를 읽어 조작을 도크 위에 배치한다. 전장 종료 시 observer·ticker·DOM·Pixi 표시 객체를 정리한다. 이번 수정은 독립 검수판에만 반영하며 운영 공개 조건은 유지한다.

## 실행

저장소 루트에서 아래 명령을 실행한다. 기본 주소는 `http://127.0.0.1:8798/preview/lich-king-raid-v1/`다. 포트 변경은 `LICH_PREVIEW_PORT` 환경 변수로 지정한다.

```powershell
node preview/lich-king-raid-v1/server.mjs
```

페이지의 `왕좌에 도전 → 단독 기믹 검수 → 공대 준비`로 시작한다. 12초 집결 후 전투가 시작된다. 단독 모드는 한 사람이 세 역할을 모두 조작한다. 공대 모드는 같은 컴퓨터의 별도 브라우저 탭에서 공대 코드로 참가하여 정벌대·봉인대·구출대를 나눈다. 세 역할이 각각 있어야 출정하며 최대 6명이다. 탭마다 독립 세션을 사용한다. 외부 인터넷 멀티플레이·실계정 공대는 연결하지 않았다.

## 전투 규칙

4단계 / 7개 필수 작전 / 전투 시작 후 210초 광폭화. 모든 기믹을 완료해야 10초 공격 기회가 열리며 마지막 공격 기회는 12초다. 단계별 HP 방벽을 시간 안에 돌파하지 못하면 실패한다.

| 단계 | 작전 | 핵심 판단 |
| --- | --- | --- |
| Ⅰ 저주받은 왕좌 | 역병 2회 | 2~4중첩에 같은 문양의 구울로 전이. 5중첩 전멸. 서리 폭발에 차단을 낭비하지 않고 이후 영혼 말살을 5초 안에 차단한다. |
| Ⅱ 절대영도 | 감옥 2회 | 감옥을 6초간 남겨 절대영도를 흡수한 뒤 역병 전이와 차단. 조기 파괴는 실제 체력 피해와 죽음의 잔재 2중첩을 만든다. |
| Ⅲ 서리한의 내부 | 복합 기믹 2회 | 역병·감옥·말살과 동시에 영혼 구출, 순서 봉인을 처리한다. 올바른 영혼 구출에 2.5초가 걸린다. |
| Ⅳ 왕의 최후 | 왕관 봉인 | 해방된 영혼 3개와 올바른 봉인 순서가 필요하다. 부족한 영혼은 최대 2개 긴급 구출 가능. 마지막 방벽을 돌파해 정벌한다. |

정벌대는 공격·결전·감옥 파괴, 봉인대는 차단·봉인·비상 방벽, 구출대는 전이·정화·구출·회복·부활을 담당한다. 역할 제한은 서버가 검증한다. 죽음의 잔재 3중첩, 전원 사망, 역병 5중첩, 말살 미차단, 기믹/공격 시간 초과는 전멸이다.

초기 공용 자원은 차단 7, 정화 2, 방벽 1, 회복 3, 부활 1, 결전 3이다. 다음 단계에서 초기화하지 않는다. 회복은 살아 있는 카드 최대 체력의 34%, 부활은 영혼 1개를 소모해 최대 체력의 50%로 복귀한다. 전이에 성공하면 해당 공격 기회 피해가 25% 증가한다. 공격은 1.2초 간격이며 결전은 공격력 1.8배를 적용한다. 반격은 공격당 최대 체력의 5.5%에 잔재당 2.5%가 추가된다.

숫자는 검수용 초안이다. 고정 검수 덱으로 정답 공략의 완주와 저전투력 덱의 딜컷 실패를 확인했으며, 운영 붕괴코어와의 정량 난이도 비교·실제 유저 클리어율·최종 보상/입장 조건은 확정하지 않았다.

## 구현 경계

- 서버 권위: `functions/_raid_lich_king.js`. 실제 서버 시각, HP, 차단/구출/공격 창, 자원, 역할, 중복 요청, 전멸·성공을 결정한다. 클라이언트에서 성공 여부·HP·시각을 제출하지 않는다.
- 로컬 HTTP: `server.mjs`. 루프백 전용, 메모리 방/세션, 30분 만료. 서버 재시작 시 세션은 사라진다. 입장권·보상·운영 DB/API는 없다.
- 공격 판정: 기존 `simulateBattleV2Preview`의 짧은 공격 묶음에서 타깃·치명타·명중 이벤트를 사용한다. 공용 PVE 최소 피해량으로 저전투력도 통과하는 문제를 막기 위해 리치왕 방어 규칙으로 실제 공격력에 비례한 피해 상한을 둔다. 각 묶음에서 공용 엔진의 전투 시작 HP/보호막/회복을 다시 부여하지 않는다. 지속되는 공대 HP는 레이드 반격·기믹·유한 회복이 관리한다.
- 시각: 기존 `js/battle-v3-live.js`와 `preview/project-v-v3/source/project-v-pixi-battle.src.js`를 그대로 사용한다. 단일 Pixi Application을 `resetSession`으로 재사용한다. 서버 단계 전환·절대영도는 오래된 공격 연출 대기열보다 우선한다. 복귀 때 서버 HP와 감옥을 복원한다.
- 새 CSS는 입장/결과, 전장 호스트와 리치왕 전용 기믹 오버레이에만 적용한다. 공유 모달을 호스트 내부에 담는 크기/위치 한정 규칙 외에 V3 카드 프레임·로스터·진형을 재구성하지 않는다.
- 카드 5장은 실제 도감 ID와 원화/전투 SD를 분리한 고정 표본이다. ZENITH·SUPERSTAR 프레임 이미지 계층을 유지한다. Faker 전용 공용 구현은 변경하지 않았다.

## 아트·연출

기존 포스터 원화는 `../lich-king-raid-poster-v1/`를 참조한다. 신규 투명 리치왕 전투 PNG와 서리 감옥·절대영도·영혼 말살 각 16프레임(총 48프레임)을 `assets/`에 보존한다. 모든 신규 자산은 사용자 시각 승인 대기이며 검수판에서만 사용한다.

PixiJS 8.20.0 / GSAP 3.13.0. 실제 사용 파일은 `battle.src.js`이며 공용 `BattleEngine.effectLayer`와 `BattleEngine.timeline`을 사용한다. 별도 렌더러·GSAP 인스턴스·독립 프레임 타이머는 없다. 감옥은 약 0.65초 형성 후 9번째 프레임을 유지하고 서버 절대영도 이벤트에 해제된다. 절대영도·말살은 1.25초 동안 16프레임을 진행하고 잔향을 소멸시킨다. 감옥 기준점은 대상 V3 발밑, 광역 효과는 현재 아군 좌표의 중심이다. 격돌 기준은 절대영도 약 750ms, 말살 약 650ms다. 고정 1배속 기믹 시계이며 탭을 가려도 서버 제한 시간은 흐른다.

생성된 시트는 원본 1254×1254 RGBA로 보존했다. 4×4 정규화 텍스처 영역(한 변 313.5px)으로 샘플링한다. 프롬프트의 요청 규격 1024×1024와 실제 산출 규격을 혼동하지 않는다. 각 프레임의 물질·형태가 변하며 한 정지 이미지의 단순 확대/회전 효과가 아니다. 상세 크기·알파·SHA-256은 `assets/manifest.json`, 정확한 생성 프롬프트는 `art-prompts.md`에 있다. 신규 사운드는 제작하지 않았으며 기존 V3 사운드 경로만 상속한다.
