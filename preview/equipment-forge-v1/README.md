# 장비 강화 V2 · Upgrade Lab

상태: **UI_AND_EFFECTS_FINAL_APPROVED / LIVE_UPDATE_PREPARATION** · 2026-09-12.

사용자가 V1의 성공 이펙트와 오래된 UI 디자인·색감·컨셉을 반려한 뒤 교체한 현대적인 SF 강화실이다. **2026-09-12 V2의 해당 UI·연출을 최종 승인하고 라이브 업데이트 준비를 지시했다.** 승인 화면·연출·원본 파일은 그대로 보존한다. 단계별 확률표와 경제는 사용자 답변 `확률표 미정 · 시연 수치로 제작`에 따른 체험 데이터이며, 운영 연결은 하지 않았다.

## 실행과 조작

```powershell
node preview/equipment-forge-v1/serve.mjs
# http://127.0.0.1:8899/preview/equipment-forge-v1/?v=2
node --test preview/equipment-forge-v1/qa.test.mjs
```

서버는 localhost/127.0.0.1에만 바인딩한다. 이 프리뷰와 필요한 장비 이미지·음원·공유 UI 라이브러리만 제공하며 계정 API와 POST는 받지 않는다. 체험 장비·재화·기록은 메모리에서만 유지되고 새로고침 시 초기화된다.

- 상단 **성공 연출 재생**: 재료 차감 없이 현재 장비의 V2 성공 연출을 즉시 재생한다.
- **모든 결과 연출**: 성공·유지·파괴·보호·복구를 개별 재생한다.
- 6개 장비 카드, 종류 필터, 단계별 전투력·비용·3종 확률, 장비보호권 선택.
- **시연 설정**: 확률표, 0.5×/1×/2×, 동작 줄이기, 체험 초기화. 성공률 10% 하한과 합계 100%를 전체 표에 검증한 뒤 적용한다.
- 파괴 기록 → 복구 쿠폰 확인 → 같은 장비·단계 복구 → 재강화. 기록 중복 복구와 중복 차감을 방지한다.
- 일시정지·재개·건너뛰기. 다른 탭으로 이동하면 정지하고 돌아온 뒤 직접 재개한다. 페이지 이탈 시 타임라인·렌더러·오디오를 해제한다.
- 모바일: 연출 무대, 가로 장비 카드 목록, 확률·재료 패널 순서. 강화 시작 시 무대로 이동한다. dialog는 키보드 포커스 제한과 Escape 닫기를 사용한다.

## PixiJS·GSAP 구현과 타임라인

실제 사용 파일은 `source/fx.mjs`, `source/success-v2.mjs`, `source/app.mjs`다. 기존 `js/ui-fx-vendor-v2045.bundle.js`와 `CNineUiFxVendor`를 사용한다. **PixiJS 8.20.0 / GSAP 3.13.0**으로 잠겨 있으며, 별도 렌더러·CDN·라이브러리 사본은 추가하지 않았다. 전투 V3의 진형·원화·SD·전투 계산은 수정하지 않았다.

| 시각 | 성공 연출 |
| --- | --- |
| 0–1.40초 | 나선 코어와 전하 수렴, 에너지 카운트 |
| 1.40–2.25초 | 장면 암전, 빔 압축, 짧은 장비 진동 |
| **2.25초** | 전용 프레임 5부터 플라즈마 폭발, 국소 섬광·충격·장비 확대 |
| 2.41–3.65초 | 파열 껍질과 비산 잔광, 지면 파동, 전격 |
| **3.15초** | 성공 배너와 큰 강화 단계가 0.30초 동안 드러남 |
| 4.25–4.80초 | 폭발 프레임 소멸, 각성 잔광과 결과 유지 |

성공 아틀라스는 **4×4, 실제 1254×1254 RGBA, 16프레임**이다. 프레임마다 수렴·코어·폭발·파열·소멸 형태가 바뀐다. 한 장의 효과를 확대하는 방식으로 대체하지 않았다. 313.5px 셀 UV를 원본 텍스처에서 참조하고 인접 프레임을 짧게 보간한다. 원본을 자르거나 재압축해 저장하지 않는다.

아틀라스의 어두운 알파가 CSS 배경 위에서 검은 사각형을 만들지 않도록, 동일 Pixi 장면에 배경을 먼저 렌더링하고 그 위에 가산 합성한다. 강화실도 같은 캔버스에 포함되며 렌더러는 하나다. 장비·충돌 중심은 무대 `(50%, 44.5%)`. 성공 크기는 무대 너비에 맞추고 원본 무기 비율은 유지한다.

모든 프레임·입자·진동·HUD·배너 진행은 **한 GSAP 경과 시간**에서 계산한다. 일시정지·배속·건너뛰기가 분리된 CSS 타이머로 어긋나지 않는다. Pixi ticker는 최대 60fps이며 대기 시계는 시연 중 정지한다.

다른 결과도 유지한다. 유지는 조용한 잔광 분산, 파괴는 원본 텍스처 40조각의 개별 붕괴, 보호는 균열을 가로막는 장벽, 복구는 조각 역류·재결합이다. 재생 전에 모델이 영수증을 한 번 확정하고 연출은 추첨·차감을 하지 않는다. WebGL 실패 시 원본 HTML 이미지와 즉시 결과를 제공한다. 동작 줄이기에서는 섬광·진동·대기 입자 없이 결과를 바로 표시한다.

## V2 검수

- `node --test preview/equipment-forge-v1/qa.test.mjs`: **20/20**. 기존 18개 모델·단절·원음 검증에 연속 프레임 진행과 V2 원본 해시·규격 검증을 추가했다.
- 360×800, 390×844, 768×1024, 1024×900, 1440×1050에서 가로 넘침·누락 이미지 없음. PC·모바일 실제 화면, 성공 압축·폭발·잔광·결과를 캡처해 확인했다.
- 성공·유지·파괴·보호·복구를 각각 정상 속도로 재생했다. 1초 지점 정지 후 150ms 동안 시각 고정, 재개 후 4.8초 종료와 올바른 배너를 확인했다. 시연 전후 장비·재화·기록은 동일했다.
- 실제 체험 판정: 보호권 선택 후 파괴 → 보호권 1장 소모, +7 유지, 기록 증가 없음. 보호 미선택 파괴 → +7 기록 추가 → 동일 인스턴스 +7 복구, 쿠폰 1장 소모 → 재강화 가능. 연속 확인 클릭도 중복 차감 없음.
- 동작 줄이기에서도 위 처리와 결과 표시가 즉시 완료된다. 건너뛰기로 최종 프레임 전환과 완료 상태를 확인했다.
- 녹음 효과음 켠 2× 성공은 약 2.41초에 종료, 예약 피크 오차 0ms. 배경·아틀라스·무기·녹음만 요청되며 계정 API 요청이 없다.
- 브라우저 오류·경고 없음, 렌더러 하나. 원본 무기·기존 음원·V1 생성 원본의 해시 일치.
- 가려진 검수 브라우저에서는 RAF가 제한되므로 시간 측정 전 브라우저를 전면으로 전환했다. 위 결과를 모든 장치의 성능 보장으로 해석하지 않는다.

## 최종 승인과 라이브 적용 준비

- `release/approval.json`: 사용자 승인 문구·범위, 원본 22개 파일의 SHA-256, PixiJS·GSAP·충돌 시점 고정. UI·연출은 최종 승인 완료다.
- `release/launch-draft.json`: 운영 확률·비용·전투력·보호권·복구 정책은 미정, `liveEnabled=false`. 시연값을 복사하지 않는다.
- `release/policy.mjs`: 3종 판정·성공률 10% 하한·합계 100%·보호권 GAMEPLAY 전용을 검증한다. 운영 설정 저장 API나 확률 추첨 엔진은 아니다.
- `release/server-receipt.mjs`: 인증 요청 함수에 연결할 준비 모듈. 개별 장비·서버 견적·버전·요청 ID만 전송하고 완료된 서버 결과를 기존 5종 연출로 변환한다. 중복 클릭, 응답 유실, 다른 계정·장비·정책 결과를 검증한다.
- `functions/_equipment_forge_preparation.js`: 기존 운영 스키마에 맞는 개별 장비 페이지 조회. 실제 인스턴스를 묶거나 변경하지 않고 강화 상태는 미설정으로 반환한다. 운영 라우트에서 가져오지 않는다.

```powershell
node --test preview/equipment-forge-v1/qa.test.mjs preview/equipment-forge-v1/release/qa.test.mjs
node preview/equipment-forge-v1/release/check.mjs
# 실제 서버 구현·경제 확정 전에는 아래 명령이 실패하는 것이 정상이다.
node preview/equipment-forge-v1/release/check.mjs --require-launch-ready
```

기존 승인 UI·연출 소스와 운영 진입점은 변경하지 않았다. 실제 계정의 강화·파괴·복구, CMS·보상·전투력 연결과 운영 활성화는 준비 기록에 남은 항목이다. 작업 범위는 업데이트 준비이므로 운영 배포를 실행하지 않는다. 다른 콘텐츠의 출시 게이트도 해제하지 않는다. 상세 정책은 `docs/equipment-enhancement-forge-v1.md`, 실제 연결 작업표는 `docs/equipment-forge-live-preparation-v1.md`를 따른다.
