# 아카드 · 카네키 켄 아포칼립스 보스 준비

2026-09-18 사용자 요청과 후속 답변에 따라 두 보스의 투명 SD와 **봉인 / 힐불가 저주 / 궁극기, 각각 3개**를 제작했다. 후속 지시 `전부 승인하고 아카드부터는 쫄몹 나오게 설정해 6마리 정도`로 원화·SD·스킬을 승인받아 공용 V3에 연결한다. 운영 등록·검증 기준은 `docs/apocalypse-legion-v2127-release.md`다.

- 상태: `APPROVED`. `registration-draft.json`은 운영 등록 이전의 OFF 초안 보관 자료이고, 실제 등록은 별도 멱등 스크립트로 처리한다.
- 검수 화면: `/preview/apocalypse-bosses-v1/`
- 실행: `node scripts/serve-apocalypse-boss-drafts.mjs` → `http://127.0.0.1:4243/preview/apocalypse-bosses-v1/`
- 빌드: `node scripts/build-apocalypse-boss-drafts.mjs`
- 테스트: `node --test tests/apocalypse-boss-drafts.test.mjs`

## 전투력 초안

| 보스 | 기본 전투력 | 하시라마 대비 |
| --- | ---: | ---: |
| 센쥬 하시라마 | 5,500,000 | 기준 |
| 아카드 | 7,500,000 | 약 1.36배 |
| 카네키 켄 | 10,000,000 | 약 1.82배 |

기준은 `battle_apocalypse_settings_v1.monsterProfiles[74]`이며 2026-09-18 운영 DB를 읽기 전용으로 재조회해 **하시라마 550만**을 확인했다. 몬스터 테이블의 기본 1,000 값 대신 아포칼립스 개별 프로필을 사용한다.

HP 350%, 공격 475%, 방어 375%, 속도 375%, 보호막 70%, 2회 공격, 강제 행동 주기 4는 하시라마 기준으로 동일하게 두고 기본 전투력만 올린다. 따라서 실제 기존 엔진 환산 HP·공격력·방어력·보호막도 하시라마 < 아카드 < 카네키 순서다. 속도·공격 횟수를 임의로 중첩 상향하지 않는다.

`makeRegistrationDraft(latestHashiramaProfile)`은 최신 하시라마 전투력에 같은 상대 배율을 적용한다. 실제 등록 시 최신 운영 프로필을 읽어 다시 산출하고, 새 DB ID를 할당해야 한다. 샘플 식별자 `DRAFT_ALUCARD` / `DRAFT_KANEKI`는 운영 ID가 아니다. 보상은 `null`로 두었으며 기존 보스의 보상을 자동 승계하지 않는다.

## 스킬

| 보스 | 분류 | 전용기 | 판정 초안 |
| --- | --- | --- | --- |
| 아카드 | 봉인 | 혈계 · 구속의 사슬 | 공격력이 높은 생존 대상 2명, 각자 2행동 동안 스킬 봉인 |
| 아카드 | 힐불가 | 불사의 저주 · 메마른 성혈 | 생존 대상 전체, 각자 2행동 동안 회복 100% 차단 |
| 아카드 | 궁극기 | 구속 해제 · 불사군단 | 생존 대상 전체, 공격력 190%, 피해의 40% 보호막 관통 |
| 카네키 켄 | 봉인 | 린카쿠 · 가시 감옥 | 공격력이 높은 생존 대상 3명, 각자 3행동 동안 스킬 봉인 |
| 카네키 켄 | 힐불가 | 구울의 허기 · 회복 포식 | 생존 대상 전체, 각자 3행동 동안 회복 100% 차단 |
| 카네키 켄 | 궁극기 | 카쿠자 · 백족의 종언 | 생존 대상 전체, 공격력 225%, 피해의 60% 보호막 관통 |

봉인 중에도 일반 공격은 유지한다. 힐불가는 일반 회복·재생·흡혈에 적용하며 정화 후 회복이 가능하다. 부활 자체는 이 초안의 회복 함수가 수행하지 않는다. 상태 지속 시간은 대상 자신의 행동 완료 시에만 감소한다. 일정 초안은 보스 1·2·3번째 행동에 봉인·저주·궁극기를 각각 1회 발동하는 방식이다.

`skill-contract.mjs`는 테스트 가능한 순수 판정 모듈이다. **운영 시뮬레이터에 아직 연결하지 않았다.** 실제 연결 시 스킬 발동 경로에 `canUseSkill`, 모든 회복 경로에 `resolveHealing`, 정화에 `cleanse`, 대상 행동 종료에 `finishAction`을 일관되게 연결하고 전체 전투 회귀 검증을 해야 한다. 검수 화면은 빌드 시 확정한 정적 상태·피해 이벤트를 재생한다. 서버 결과를 브라우저 FX가 다시 계산하지 않는다. 전체 승률·경제 밸런스 검수 완료를 뜻하지 않는다.

## 원화와 SD

- 사용자 원화: `assets/alucard-source.jpg` / `assets/kaneki-source.jpg`. 첨부 `5456252.jpg` / `1231241.jpg`를 무가공 복사했다.
- SD: `assets/alucard-sd-v1.png` / `assets/kaneki-sd-v1.png`, 각 1254×1254 RGBA.
- 두 캐릭터 모두 전신·좌향 3/4 시점·실제 알파. 원화와 SD는 별도 필드이며 카드 도크에는 실제 기존 카드 원화만 표시한다.
- 생성 방식: **내장 image_gen**. 최종 프롬프트 전체는 `prompts.json`, 결과 SHA-256·알파 비율은 `asset-manifest.json`.
- 이미지 픽셀 편집·배경 제거·재압축은 하지 않았다. SD와 FX 원본 PNG를 그대로 보관한다.

## PixiJS / GSAP 구현

- 잠금 버전: PixiJS 8.20.0 / GSAP 3.13.0 (`package-lock.json`). 추가 라이브러리나 CDN 없음.
- 엔진: `preview/project-v-v3/source/project-v-pixi-battle.src.js`, 기존 `BattleEngine`, 아트 어댑터와 `js/battle-v3-live.js`의 카드 도크를 재사용한다. 운영 연결 버전은 양쪽 모두 `2127-apocalypse-legion-20260918`이며 공용 번들 9개를 함께 빌드한다.
- 신규 FX 구현: `DraftSkillFX.js`. 새 Application·렌더러·Ticker를 만들지 않고 기존 엔진의 `effectLayer`에 `AnimatedSprite(autoUpdate:false)`를 배치한다.
- 타임라인 소유자: `BattleEngine.timeline()`. 기준 단위는 초. 같은 GSAP 커서가 실제 프레임 선택과 충돌 콜백을 제어한다.
- 각 스킬은 독립 제작한 4열×3행 **12프레임**. 원본 1448×1086 PNG를 362×362 프레임으로 읽는 atlas JSON을 생성하며 이미지 재가공은 하지 않는다.
- 공통 충돌: 0부터 세는 **6번 프레임**. 봉인·저주 0.80초 / 궁극기 1.15초. 종료 1.80초 / 2.25초.
- 기준점: 대상 발밑 x/y, 텍스처 앵커 `(0.5, 0.9)`. 궁극기는 대상 진형 중앙. 화면 가장자리 여유를 포함해 실제 viewport에 맞춰 크기만 제한한다.
- 단순 정지 이미지 트윈이 아니라 사슬 전개·성배 파괴·마수 돌진·카구네 구속·꽃의 붕괴·백족 강타의 형태가 프레임마다 바뀐다.
- 0.25/0.5/1/2배속, 정지·이어 재생, 프레임 탐색, 충돌 프레임 고정, 취소·보스 전환·화면 이탈 정리 제공.
- 스킬 컷신·카드 사진 팝업·히트스톱 없음. 신규 SFX는 이번 범위에서 제작하지 않았으며 검수판은 무음이다.

## 등록 시 남은 연결 작업

공용 서버 판정과 `ApocalypseLegionFX.js`·`ApocalypseLegionPlayback.js`가 승인 자산의 운영 사본을 사용한다. 보스와 쫄몹 6마리는 각각 독립 체력·행동을 가지며 모두 처치해야 승리한다. 운영 등록은 75·76번 ID의 충돌과 하시라마 기준 변경을 차단하고 로그·수령증을 남기는 `scripts/ops/apocalypse-legion-release-20260918.mjs`로만 처리한다. 보상은 기존 하시라마의 600만 코인을 승리당 한 번 지급하는 정책을 승계하며 쫄몹 수만큼 중복 지급하지 않는다.
