# 독립 스킬 목록과 사용자 배정 검수

2026-09-11 사용자 지시: “스킬 목록을 따로 뽑아놓고 어떤 용병에 적용할지는 내가 정한다”.

## 반영 내용

- `skills.html`: 17개 스킬의 이름·효과·약점·연속 스프라이트를 독립적으로 검토한다. 목록 썸네일은 각 스킬의 충돌 프레임이며 용병 원화가 아니다.
- `skill-assignments.html`: 43개 용병이 모두 미배정으로 시작한다. 용병을 고르고 원하는 스킬만 체크한다. 특정 등급·포지션·용병에 자동 연결하거나 전용 잠금을 두지 않는다.
- 오메가-X의 SSS 등급은 유지한다. MS-021 종언의 사건지평선도 다른 스킬과 같은 독립 목록 항목이다.
- 시연용 용병을 변경해도 배정은 바뀌지 않는다. 배정 화면으로 넘어가는 스킬 링크도 목록 필터만 지정하며 체크하지 않는다.
- 스킬 검토 의견과 용병 배정은 별도 형식·저장소다. 구형 검토본의 이름·의견·수정 번호는 보존하고 당시 제안된 용병 code만 제거한다.
- 배정 초안은 여러 용병에 같은 스킬이나 한 용병에 여러 스킬을 제안할 수 있다. 운영 장착 슬롯 수·무기 적합성·밸런스는 확정하지 않는다.

## 실제 검수

- 관련 자동 검사: `npm run test:mercenary-codex`, 148/148 통과. 알려진 ID·OFF·사용자 권한·중복·누락·수정 충돌, 구형 16/17개 검토본 이동, 검토본/배정본 교차 가져오기 거부를 확인했다.
- 데스크톱 실제 UI: 베스페라에 MS-003/MS-021을 직접 체크해 저장하고 새로고침 후 두 선택과 선택 용병이 유지됐다. 동탄 디임에도 MS-021을 선택할 수 있었고 오메가-X는 미배정이었다.
- 시연 모델을 동탄 디임으로 바꾸고 다른 스킬로 전환해도 시연 모델이 유지됐다. 배정 화면을 다시 읽었을 때 기존 체크가 변경되지 않았다.
- 390px 모바일 화면: 용병·스킬 검색, 체크·해제, 별도 시연 모델 선택, 마지막 충돌과 취소를 확인했다. 문서 가로 넘침이 없고 변경 상태가 체크 해제 후 원래 값으로 돌아왔다.
- 검수 중 만든 배정은 모두 해제하고 저장했다. 사용자 제공 배정이나 운영 데이터는 수정하지 않았다.
- JSON 가져오기/내보내기 데이터 형식은 자동 검사했다. 실제 OS 파일 선택 왕복을 수행한 것으로 보고하지 않는다.

## 연출·출시 범위

- 기존 `source/skills-lab.src.js`, `MercenarySkillFX.js`, `RenderAuthoredSkill.js`, `MercenarySpriteSequence.js`와 V3 공용 렌더러를 유지한다. PixiJS 8.20.0 / GSAP 3.13.0이다.
- 17개 개별 시트, 272개 프레임, 원화와 SD, 충돌 타임라인은 변경하지 않았다. 매니페스트의 `creationReferenceCode`는 과거 제작 출처이며 배정 입력으로 사용하지 않는다.
- MS-021의 접촉 시점 1.05초 / 2.25초와 실제 프레임 재생은 유지한다. 동일 GSAP 시간에서 UV·입자·대상 반응을 제어하고 취소하면 효과를 정리한다.
- 이번 배포는 독립 프리뷰와 브라우저 CMS 초안이다. 실제 계정·획득·덱 저장·전투 API 및 운영 CMS DB를 활성화하지 않는다.
- 전체 스킬 표와 데이터 계약은 [독립 스킬 목록 기준](../../docs/project-v-mercenary-skill-catalog-v1.md)을 따른다. 기술 검수는 사용자의 최종 시각·밸런스 승인과 구분한다.
