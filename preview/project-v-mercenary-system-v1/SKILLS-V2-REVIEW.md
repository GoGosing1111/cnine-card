# 용병 스킬 연속 스프라이트 재제작 V2

최신 2026-09-11 지시로 **17종 모두 독립 스킬 목록으로 분리하고 용병 자동 배정·전용 잠금을 해제했다.** 아래 전용기 표기는 제작 당시 제안 이력이다. 현재 배정 권한·CMS 초안·검증 기록은 [SKILL-LIBRARY-REVIEW.md](./SKILL-LIBRARY-REVIEW.md)를 따른다.

후속 2026-09-11: **오메가-X SSS 전용기 MS-021**을 추가해 현재 17종·272프레임이다. 기존 16종 자산은 변경하지 않았다. 오메가의 두 접촉 시각·프레임·CMS 등급·검수 기록은 [OMEGA-REVIEW.md](./OMEGA-REVIEW.md)를 따른다. 아래 16종 재제작 수치는 최초 V2 검수 이력이다.

2026-09-11 사용자 반려에 따른 재제작. 이전 V1의 정지 이미지 16종에 이동·확대 트윈만 적용한 연출은 품질 기준을 충족하지 못했다. 이전 기술 검증 기록은 동작 안전성 기록으로만 보존하며, 시각 품질 승인으로 해석하지 않는다.

## 한 종씩 확인하는 기준

1. 개별 스킬 전용 원본 시트에 실제로 달라지는 16개 연속 프레임을 제작한다. 형태·접촉·질감·밀도·소멸이 변화해야 한다. 단색 변경·배율 변경·같은 프레임 복제로 수량을 채우지 않는다.
2. 원본 바이트를 보존하고 프레임을 정확한 격자로 추출한다. 실제 RGBA, 셀 경계의 알파, 프레임 중복, 원점과 종료 형상을 확인한다. 경계 번짐이나 잘린 재질은 빌드에서 차단하고 재생성한다.
3. 기존 V3 편성에서 배틀슈트 로켓런처·헬기폭격과 나란히 재생한다. 주 효과의 재질 변화, 접촉 시점, 지면광·파편·먼지·연기의 계층을 확인한다. 큰 크기와 테스트 개수는 품질 승인 근거가 아니다.
4. 원본 프레임 검수와 실제 전장 재생 검수는 각각 기록한다. 사용자 최종 시각 검수는 별도이며, 스킬 수치·등급·실제 계정 전투 연결은 이 작업에 포함하지 않는다.

## 실제 구성

- 주 효과: `skill-assets-v2/source/`의 개별 네 열 × 네 행 원본. 스킬당 16프레임을 `skill-assets-v2/<id>/frames/`에 분리하여 검수 화면에서 직접 확인한다. 런타임은 동일 프레임을 하나의 무손실 WebP 아틀라스에서 읽는다.
- 보조 효과: 배틀슈트 승인 `flash.webp`, `smoke.webp`, `dust.webp`, `cinder.webp`를 수정 없이 사용한다. 주 효과의 스킬별 제작 수량으로 세지 않는다.
- 실제 코드: `source/MercenarySpriteSequence.js`, `source/MercenarySkillFX.js`, `source/RenderAuthoredSkill.js`, `source/skills-lab.src.js`.
- PixiJS 8.20.0 / GSAP 3.13.0, 기존 V3 `effectLayer`·`combatLayer`를 사용한다. 새 Application·Ticker·CDN 사본이 없다.
- 초 단위의 GSAP 시간 하나를 V3 취소 목록에 등록한다. 프레임 UV, 보조 입자, 대상 반응, 카메라 반응이 동일 시각에서 계산된다. `AnimatedSprite`의 독립 자동 재생은 사용하지 않는다.
- 0번 프레임부터 준비하고 접촉 시점에 4번 프레임을 표시한 뒤, 7 → 10 → 13 → 15번으로 잔향을 진행한다. 인접 프레임의 알파를 중첩하며 현재 프레임의 밀도를 유지한다. 정확한 접촉은 이미 확정된 모의 전투 로그의 시점을 따른다.
- 새로 선택할 때 이전 타임라인·표시 객체·프레임 뷰를 정리하고 이전 아틀라스를 해제한다. 비동기 선택은 직렬화하고 선택 토큰이 바뀐 결과를 버린다. 승인 캐릭터 원화·SD와 공유 텍스처 원본은 보존한다.
- 모든 샘플의 기준점은 승인 SD 발 원점과 캐릭터 높이에서 구한 몸통이다. 기존 대기 SD는 유지한다. 새 관절 공격 애니메이션이나 새 사운드를 제작했다고 보고하지 않는다.
- 사운드는 무음 시각 검수다. 실제 녹음 출처·충돌 피크 검증을 거치지 않은 합성음을 추가하지 않는다.

## 제작·검수 기록

원본 파일, 프롬프트, 실제 프레임 수·크기·해시와 재제작 사유는 `skill-assets-v2/generation-inputs.json`과 `skill-assets-v2/manifest.json`에 기록한다. 현재 제작 진행 상태는 해당 매니페스트를 기준으로 한다.

**16종 × 16프레임 = 256프레임**. 실제 원본은 1254×1254 RGBA PNG이며, 313/314px 격자를 그대로 추출하고 최대 1px의 투명 여백만 더해 314px 셀로 정렬했다. 2048px 요청과 실제 반환 규격을 혼동하거나 업스케일 결과로 보고하지 않는다. 선택 원본 16종은 전부 프로젝트에 무가공 보존했다.

## 동작 검수 결과

- 기존 배틀슈트 로켓런처와 헬기폭격을 실제 V3 프리뷰에서 비교했다. 공용 보조 텍스처와 원본, V3 라이브 엔진·카드 도크·기존 원화·SD는 변경하지 않았다.
- CUA에서 16종 각각 1배·0.5배로 끝까지 재생했다(32회). 종료 시 주 효과와 등록 타임라인이 남지 않았다.
- 데스크톱과 390×844 모바일 각각 16종 × 정상·약점·보스 상황을 선택하고 접촉·종료·취소를 검수했다(96상황). Canvas 1개, 효과 계층 1개, 일반 카드 5장·별도 용병 1장을 유지했고, 취소 뒤 효과 0·등록 타임라인 0·위치 오차 0이었다. 모바일 가로 넘침이 없었다.
- 모바일 큰 충돌의 오른쪽 잘림을 발견하여 원본 프레임 전체의 알파 경계로 가로 범위를 구하고, 충돌 원점을 유지한 채 크기를 제한했다. 보정 후 건틀릿 접촉과 회전 검격을 390px 전장에서 다시 확인했다. 같은 경계 검사를 48상황의 자동 샘플 검증에도 포함했다.
- 장막은 크기300/알파0.5, 꽃잎 결계는 크기245/발 위14/알파0.78로 전장 가독성을 조정했다. 화면 전환 시 새 진형 기준점을 반영하고, 체포 조건 미달의 권총 타격에는 구속 고리를 표시하지 않는다.
- 검수 화면에서 원본 16프레임을 각각 열 수 있고 현재 재생 프레임이 강조된다. 이전 스킬의 아틀라스 뷰·타임라인·자체 표시 객체는 선택 교체 시 정리된다.
- `npm run test:mercenary-codex`: 136/136 통과. 마지막 모바일 경계 수정 뒤 `npm run test:mercenary-skills`: 67/67 통과. 배포 소스에서는 전체 `npm run release:gate`를 다시 통과해야 한다.
- 탐색·새로고침 중 브라우저에 `MutationObserver.observe` 오류가 기록되는 현상은 수정하지 않은 배틀슈트 기준 프리뷰의 새로고침에서도 재현됐다. 용병 연출의 로드·재생 실패는 관찰되지 않았다. 해당 공통 탐색 오류를 용병 시각 품질 승인 근거로 숨기거나 새 VFX 오류라고 단정하지 않는다.

재현 명령: `node scripts/build-mercenary-skill-atlases-v2.mjs`, `npm run build:mercenary-skills`, `npm run test:mercenary-skills`. 입력의 선택 원본 경로는 프로젝트 상대 경로이므로 외부 생성 폴더 없이 재현한다. 운영 배포는 깨끗한 운영 작업 트리에서 `npm run release:gate` 후 `npm run deploy:production`만 사용한다. 공개 범위는 이 검수 페이지이며 실제 계정 전투 활성화가 아니다.
