# 마다라 레이드 · 개인 판단·시인성 검수 V3

사용자 지시: **“준비해서 구현 시작해 라이브 올리지말고 준비까지만 해놔”**.

현재 결과는 실제 입력으로 클리어할 수 있는 **로컬 개발판**이다. 정식 출시 후보나 최종 시각 승인본이 아니다. 운영 메뉴·API·CMS·DB·입장권·보상은 연결하지 않았다. `MADARA_RELEASE`는 `OFF`, `runtimeEnabled:false`, `rewardLocked:true`다. 전용 개발 브랜치에서만 보관하며 main 통합·원격 공개·운영 배포를 하지 않는다.

## 실행

저장소 루트에서:

```powershell
node preview/madara-raid-v1/server.mjs
```

주소: <http://127.0.0.1:8806/preview/madara-raid-v1/>

- 단독 지휘: 참가자 3명을 준비하고 전장의 담당자 선택으로 봉인·정벌·구출을 직접 교대한다. 다른 역할의 자동 정답 입력은 없다.
- 공대 플레이: 참가자마다 별도 브라우저 프로필 또는 시크릿 창에서 공대 목록/코드로 참가한다. 같은 프로필의 탭은 동일한 검수 참가자다. 3~6명, 역할별 최소 1명, 전원 준비 후 공대장이 출정한다.
- 각 참가자의 5장 편성을 공용 V3로 표시한다. 검수 편성은 실제 도감 카드의 원화와 SD를 분리한 고정 표본이며 운영 계정 덱이 아니다.
- 새로고침은 같은 브라우저 프로필의 로컬 세션으로 복구한다. 서버 시간이 계속 흐르며 재접속으로 제한 시간을 늘리지 않는다. 방은 생성 후 30분 만료되지만 입장권 잔액은 유지된다. 서버 재시작 시 검수 세션·방·입장권 장부가 초기화된다.
- 로컬 검수 중 명시적 퇴장은 해당 공대 전투를 종료한다. 운영 이탈·재배분 정책은 추후 실계정 연결 단계에서 확정한다.
- 기본 검수 음소거. 외부 인터넷 멀티플레이와 실계정 보상은 없다.

## 공대 생성과 관리

공대장 이름·역할 선택 → 입장권 확인 팝업 → 검수 입장권 1장 차감과 방 생성 → 공대 목록 갱신 → 다른 참가자가 목록/코드로 참가 → 전원 준비 → 공대장 출정 순서다. 초기 3장, 생성자만 차감, 참가 무료, 생성 후 해산·패배 시 반환 없음은 검수 초안이다.

서버는 전체 공대 구성을 먼저 검증한 다음 차감·방 저장·생성 영수증을 동기 구간에서 함께 확정한다. 같은 요청 ID의 중복 클릭·네트워크 재전송은 같은 방/영수증을 반환한다. 잘못된 역할/모드, 입장권 부족, 이미 참가 중인 경우에는 차감하지 않는다. 이 보장은 단일 로컬 프로세스에 한정하며 운영 DB 거래를 대신하지 않는다.

모집 목록은 5초 주기와 수동 갱신을 지원한다. 역할별 인원·정원·모집/출정/종료 상태를 표시한다. 강퇴는 출정 전 공대장만 가능하며, 자신을 강퇴할 수 없다. 강퇴된 동일 검수 참가자는 새로고침/세션 복구 후에도 해당 방에 다시 들어올 수 없고 다른 방은 이용할 수 있다. 공대장이 대기 중 퇴장하면 남은 첫 참가자에게 공대장 권한을 넘기며 추가 입장권을 차감하지 않는다.

**전투 연출 미리보기**는 입장권을 쓰지 않는다. 다섯 기믹을 직접 선택하고 0.25/0.5/1/2배속, 일시정지, 프레임 탐색, 효과 OFF로 볼 수 있다. 실제 공대 시간·HP·보상을 바꾸지 않는다.

## 실제 구현한 기믹

| 단계 | 독립 판단과 협동 |
| --- | --- |
| 환술 | 봉인대 정·역방향 해독 / 정벌대 문양+눈 모양 실체 식별 / 구출대 보호 제외·폭주 우선 정화 |
| 분신 | 봉인대 개인 봉인 해독 / 정벌대 반사 제외·시전 순서 판단 / 구출대 낙인 실체 식별 |
| 화둔 | 보존 결계 해독 / 첫 화염 8초 후 보존·반사 제외·최고 열기 파쇄 / 위험 동료 선택 후 보호 타이밍 입력. 두 번째 화염 26초 |
| 운석 | 봉인 해독 / 핵 예고 2.2초 동안 공격 중단 후 반사 제외·급한 핵 타격 / 대상 선정 후 예고에 맞춰 수동 보호 |
| 완전체 | 환술+운석 개인 과제 동시 처리. 시선 대상자는 결계 유지 후 공격 중단. 모바일에서 과제별 남은 시간과 바로 이동 제공 |

각 역할은 자기 단서를 받아 병행 판단하며, 다른 역할의 정답을 그대로 따르지 않는다. 성공마다 단서·배치가 바뀐다. 오답·대응 시간 초과는 공대 피해와 침식 1회, 1.5초 재정비 뒤 새 패턴을 요구한다. 기믹 전체 제한 시간은 그대로 흐른다. 보호는 자동 완료되지 않으며 예고 중의 핵 타격·보호 전개는 실패한다. [V3 설계·시인성·검수 기록](../../docs/madara-raid-role-decisions-20261011.md)에 상세 규칙과 한계를 기록했다.

3~6인 모두 개인 과제가 있으며 각자의 공격만 자기 편성의 V3 전투 계산을 실행한다. 단계 HP를 출정 인원별 정수 몫으로 고정하고 개인 일반 공격은 해당 몫의 약 1/3까지만 적용한다. 결전은 1.8배 한도, 개인 2회다. 한 명이 다른 사람의 몫까지 소비할 수 없다. 실제 전투 계산이 낮으면 피해 한도까지 올려주지 않는다.

기믹 성공 후 공격 기회는 기본 18초·최종 30초다. 360초 광폭화, 회복 4회(생존 편성 34%), 부활 1회(영혼 1개·쓰러진 카드 50%), 침식 4중첩 실패는 **검수 초안 수치**다. 정식 보스 전투력·경제·주간 한도·입장 정책·보상은 `readiness.json`에서 `null`로 관리한다.

## 구현 경계

- `functions/_raid_madara.js`: 순수 서버 권위 상태 머신. 시간, 개인 과제, 역할, HP, 공격 한도, 공용 자원, 중복 요청과 결과를 관리한다. 기존 리치왕과 공통 전투 계산은 수정하지 않았다.
- `server.mjs`: 루프백 메모리 HTTP. Host·Origin·JSON·Bearer 세션 검증, 제한된 정적 파일 제공, 요청 크기·세션/공대 수·30분 수명 제한. 클라이언트는 시각·HP·성공을 정할 수 없다. 실제 DB 트랜잭션 또는 운영 다중 프로세스 저장소 구현이 아니다.
- `battle.js`: `ProjectVBattleV3Live.ensureRuntime`·`createRenderer`·기존 아트 어댑터 4종을 사용한다. 새 Pixi Application, 진형, 카드 도크, 등급 프레임을 복제하지 않는다. 다른 참가자 공격은 공용 보스 HP로 반영하고 현재 보이는 본인의 편성만 V3로 재생한다.
- `madara.js`: 역할별 정보, 개인 입력 토큰, 눌렀을 때의 토큰 고정, 즉시 응답 반영, 폴링 중 버튼 DOM 유지, 통신 실패 시 같은 요청 ID로 한 번 재시도. 화면 시계는 마지막 서버 시각에서 표시만 진행한다.
- 모바일은 44px 이상 조작 영역, 제한 시간 고정, 전장·임무 이동, 키보드 조작·동작 줄이기를 지원한다. 기존 V3 로스터와 진형은 그대로다.

## 원화·제작 상태

사용자 첨부와 이전 콘셉트 포스터 원본은 `assets/`에 그대로 보존했다. 새 마다라·푸른 거신의 투명 정지 리소스와 작전실 배경은 **내장 `image_gen.imagegen`**으로 제작했다. 정확한 프롬프트는 `art-prompts.json`, 실제 크기·알파·원본 해시는 `assets/manifest.json`에 기록한다. 요청 해상도와 실제 생성 해상도를 구분한다.

게임 UI의 한글은 기존 Noto Sans KR·Black Han Sans와 실제 HTML 텍스트다. 폰트 라이선스는 기존 `assets/fonts/lich-raid/`, `assets/fonts/clan-camp/`의 OFL을 따른다. 이전 콘셉트 포스터는 기획 이력이며, 공개 게시용 포스터 확정 시 한글 별도 조판 기준을 적용한다.

V2는 실제 관절·손·옷자락이 달라지는 마다라 시전 4포즈와 환술·분신·화둔·운석·완전체 강림 각각 12프레임, 총 60효과 프레임을 추가했다. `presentation.js`는 실제 V3 보스 액터와 공용 Pixi 레이어·GSAP 타임라인을 사용한다. 단계·화염·공격 기회·시선·실수·승패에 따른 자막 대사는 서버 이벤트에 연결된다. 거신 본체·검은 기존 원본을 유지하며 추가 본체 동작과 녹음 음성/전용 사운드는 제작하지 않았다.

제작 프롬프트는 `art-prompts-v2.json`, `art-prompts-v3.json`, 원본과 아틀라스·개별 프레임·피벗·방출점·해시는 `assets/presentation-manifest.json`과 `assets/animation/`에 있다. `pack-presentation.mjs`는 균일 축소와 투명 여백 패킹만 수행한다. 원본을 새로 그리거나 무기를 변형하지 않는다. V2 효과 시트는 형태 연구 이력이며, 실제 재생은 V3의 12프레임 시트를 쓴다.

제작 11단계 대응과 시각 수정 이력은 [V2 제작 기록](../../docs/madara-raid-lobby-presentation-20261011.md)에 보존한다. 검수 영상은 `qa-v2/madara-presentation-v2.webm`이다. 기술 검사와 사용자 시각 승인은 구분한다.

## 확인한 범위

```powershell
node preview/madara-raid-v1/pack-presentation.mjs
node preview/madara-raid-v1/prepare.mjs
node --test tests/madara-raid-preparation-20261011.test.mjs tests/madara-raid-lobby-20261011.test.mjs tests/madara-raid-decisions-20261011.test.mjs
# Playwright 설치 또는 PLAYWRIGHT_MODULE에 기존 설치 경로 지정
node tests/madara-raid-preparation-20261011.browser.mjs
node tests/madara-raid-lobby-20261011.browser.mjs
```

- 서버/HTTP/자산 회귀 **28개 통과**: 역할별 개인 판단·권한·응답 마감·수동 보호·이른 타격·판단 속도 6개를 추가했다. 기존 기믹·전투·권한 17개와 생성 중복/동시 요청, 차감 취소·잔액 부족, 강퇴·재입장·공대장 위임, 정원/출정 잠금·대사, 실제 알파·프레임 검증 5개도 통과했다.
- 브라우저 PC 1440×1050·모바일 390×844: 준비·출정, 공용 V3, 실제 문양 클릭, 역할 교대, 화둔·최종전, 모바일 결계 유지, 공략 팝업, 클리어 결과. 캔버스 1개, 가로 넘침 0, 브라우저 예외/로컬 HTTP 오류 0.
- 모바일 시계 고정 검수에서 기존 공통 `overflow-x:hidden`이 로컬 sticky 동작을 막는 문제를 발견해 **이 프리뷰에만** `overflow-x:clip`으로 수정했다. 타이머와 조작 영역의 실제 캡처는 `qa/mobile-controls.png`다.
- 브라우저 전체 단계 진행은 로컬 서버의 제어된 시계와 역할별 공개 응답을 사용하는 테스트 도우미로 검증했다. 실제 공대의 반응 속도, 네트워크 지연, 실전 클리어율 검증은 아니다.
- 최신 개인 판단·시인성 검수는 `qa-v3/browser-result.json`과 같은 폴더의 PC/모바일 PNG다. 이전 전투 검수는 `qa-v2/combat/browser-result.json`, 공대·연출 검수는 `qa-v2/lobby-presentation-result.json`에 보존한다. 신규 PC/모바일 캡처와 1배속 재생 영상도 `qa-v2/`에 있다. `qa/`는 이전 V1 이력이다. 공용 전투/인증/DB 변경이 없어 게임 전체 게이트와 운영 배포 검사는 실행하지 않았다.
