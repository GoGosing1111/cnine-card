# 마다라 레이드 · 로컬 개발 준비 V1

사용자 지시: **“준비해서 구현 시작해 라이브 올리지말고 준비까지만 해놔”**.

현재 결과는 실제 입력으로 클리어할 수 있는 **로컬 개발판**이다. 정식 출시 후보나 최종 시각 승인본이 아니다. 운영 메뉴·API·CMS·DB·입장권·보상은 연결하지 않았다. `MADARA_RELEASE`는 `OFF`, `runtimeEnabled:false`, `rewardLocked:true`다. 전용 개발 브랜치에서만 보관하며 main 통합·원격 공개·운영 배포를 하지 않는다.

## 실행

저장소 루트에서:

```powershell
node preview/madara-raid-v1/server.mjs
```

주소: <http://127.0.0.1:8806/preview/madara-raid-v1/>

- 단독 지휘: 참가자 3명을 준비하고 전장의 담당자 선택으로 봉인·정벌·구출을 직접 교대한다. 다른 역할의 자동 정답 입력은 없다.
- 공대 플레이: 같은 컴퓨터의 별도 브라우저 탭/프로필에서 공대 코드로 참가한다. 3~6명, 역할별 최소 1명, 전원 준비 후 공대장이 출정한다.
- 각 참가자의 5장 편성을 공용 V3로 표시한다. 검수 편성은 실제 도감 카드의 원화와 SD를 분리한 고정 표본이며 운영 계정 덱이 아니다.
- 새로고침은 같은 탭의 로컬 세션으로 복구한다. 서버 시간이 계속 흐르며 재접속으로 제한 시간을 늘리지 않는다. 서버 재시작 또는 공대 생성 후 30분이면 메모리 세션이 사라진다.
- 로컬 검수 중 명시적 퇴장은 해당 공대 전투를 종료한다. 운영 이탈·재배분 정책은 추후 실계정 연결 단계에서 확정한다.
- 기본 검수 음소거. 외부 인터넷 멀티플레이와 실계정 보상은 없다.

## 실제 구현한 기믹

| 단계 | 서버 판정과 협동 |
| --- | --- |
| 1. 환술 판별 | 봉인대마다 다른 개인 단서를 읽고 진실 문양을 공유 → 연결된 정벌대가 동일 환영 파괴 → 구출대가 다음 문양으로 정화. 공유 이전에 다른 역할에게 정답·개인 단서를 보내지 않는다. |
| 2. 분신 대응 | 구출대가 두 낙인을 순서대로 공유 → 봉인대가 첫 문양으로 증식 봉인 → 정벌대가 해당 순서로 분신 격파. 오답은 공대 피해·침식과 추가 분신 과제를 만든다. |
| 3. 화둔 결계 | 봉인대가 남길 결계를 표시 → 8초에 첫 화염 → 정벌대가 나머지 세 결계 파쇄 → 구출대가 보강 → 21초에 두 번째 화염. 엄폐 중 이른 파쇄는 무벌점 차단하며 두 번째 화염까지 보강하지 못하면 실패한다. |
| 4. 운석 저지 | 봉인대 개인 2문양으로 낙하 억제, 정벌대는 연결된 봉인대의 마지막 문양에 해당하는 핵 파괴, 구출대는 개인 단서에 지정된 동료를 2초간 보호. |
| 최종 10%. 완전체 강림 | 환술과 운석 과제를 동시에 부여. 거신의 시선은 첫 5초 예고, 이후 교대마다 4초 예고 후 6초 반사. 지목자는 결계 유지 입력 후 인계까지 공격 중단, 나머지 기믹 입력은 계속 가능하다. |

3~6인 모두 개인 과제가 있으며 각자의 공격만 자기 편성의 V3 전투 계산을 실행한다. 단계 HP를 출정 인원별 정수 몫으로 고정하고 개인 일반 공격은 해당 몫의 약 1/3까지만 적용한다. 결전은 1.8배 한도, 개인 2회다. 한 명이 다른 사람의 몫까지 소비할 수 없다. 실제 전투 계산이 낮으면 피해 한도까지 올려주지 않는다.

기믹 성공 후 공격 기회는 기본 18초·최종 30초다. 360초 광폭화, 회복 4회(생존 편성 34%), 부활 1회(영혼 1개·쓰러진 카드 50%), 침식 4중첩 실패는 **검수 초안 수치**다. 정식 보스 전투력·경제·주간 한도·입장 정책·보상은 `readiness.json`에서 `null`로 관리한다.

## 구현 경계

- `functions/_raid_madara.js`: 순수 서버 권위 상태 머신. 시간, 개인 과제, 역할, HP, 공격 한도, 공용 자원, 중복 요청과 결과를 관리한다. 기존 리치왕과 공통 전투 계산은 수정하지 않았다.
- `server.mjs`: 루프백 메모리 HTTP. Host·Origin·JSON·Bearer 세션 검증, 제한된 정적 파일 제공, 요청 크기·세션/공대 수·30분 수명 제한. 클라이언트는 시각·HP·성공을 정할 수 없다. 실제 DB 트랜잭션 또는 운영 다중 프로세스 저장소 구현이 아니다.
- `battle.js`: `ProjectVBattleV3Live.ensureRuntime`·`createRenderer`·기존 아트 어댑터 4종을 사용한다. 새 Pixi Application, 진형, 카드 도크, 등급 프레임을 복제하지 않는다. 다른 참가자 공격은 공용 보스 HP로 반영하고 현재 보이는 본인의 편성만 V3로 재생한다.
- `madara.js`: 역할별 정보, 개인 입력 토큰, 눌렀을 때의 토큰 고정, 즉시 응답 반영, 폴링 중 버튼 DOM 유지, 통신 실패 시 같은 요청 ID로 한 번 재시도. 화면 시계는 마지막 서버 시각에서 표시만 진행한다.
- 모바일은 44px 이상 조작 영역, 제한 시간 고정, 전장·임무 이동, 키보드 조작·동작 줄이기를 지원한다. 기존 V3 로스터와 진형은 그대로다.

## 원화·제작 상태

사용자 첨부와 이전 콘셉트 포스터 원본은 `assets/`에 그대로 보존했다. 새 마다라·푸른 거신의 투명 정지 리소스와 작전실 배경은 **내장 `image_gen.imagegen`**으로 제작했다. 정확한 프롬프트는 `art-prompts.json`, 실제 크기·알파·원본 해시는 `assets/manifest.json`에 기록한다. 요청 해상도와 실제 생성 해상도를 구분한다.

게임 UI의 한글은 기존 Noto Sans KR·Black Han Sans와 실제 HTML 텍스트다. 폰트 라이선스는 기존 `assets/fonts/lich-raid/`, `assets/fonts/clan-camp/`의 OFL을 따른다. 이전 콘셉트 포스터는 기획 이력이며, 공개 게시용 포스터 확정 시 한글 별도 조판 기준을 적용한다.

현재 보스 원화는 **정지 검수 리소스**다. 본체 연속 작화, 4대 기믹 개별 효과 아틀라스, 최종전 전용 연출, 녹음/라이선스 기반 사운드 및 사용자 시각 검수는 다음 제작 단계다. 공용 V3 기본 공격 재생을 이 신규 연출의 제작 완료로 세지 않는다.

- 서버/HTTP 회귀 **17개 통과**: 3·4·5·6인 각 2시드 완주, 미준비/역할 누락, 비공유 정보 보호, 타인 입력·오래된 토큰·중복 요청, 서버 제한 시간, 화둔 보존/실패, 분신 증식 복구, 시선 교대/반사, 낮은 전투력 실패, 개인 공격 몫, JSON 복구, 회복·부활·결전 소모, 운영 연결 부재, 로컬 출처·Host·파일·세션 보호.
- 브라우저 PC 1440×1050·모바일 390×844: 준비·출정, 공용 V3, 실제 문양 클릭, 역할 교대, 화둔·최종전, 모바일 결계 유지, 공략 팝업, 클리어 결과. 캔버스 1개, 가로 넘침 0, 브라우저 예외/로컬 HTTP 오류 0.
- 모바일 시계 고정 검수에서 기존 공통 `overflow-x:hidden`이 로컬 sticky 동작을 막는 문제를 발견해 **이 프리뷰에만** `overflow-x:clip`으로 수정했다. 타이머와 조작 영역의 실제 캡처는 `qa/mobile-controls.png`다.
- 브라우저 전체 단계 진행은 로컬 서버의 제어된 시계와 역할별 공개 응답을 사용하는 테스트 도우미로 검증했다. 실제 공대의 반응 속도, 네트워크 지연, 실전 클리어율 검증은 아니다.
- `qa/browser-result.json`과 PC/모바일 캡처 9장에 근거를 보존한다. 공용 코드 변경이 없어 게임 전체 게이트와 운영 배포 검사는 실행하지 않았다.
