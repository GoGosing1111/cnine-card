# 몬스터 디펜스 · TEST

운영 진입은 **PVE 메뉴 → 디펜스 (`/defense/`)**다. OWNER CMS의 **디펜스 · TEST**에서 지정한 계정과 OWNER만 입장한다. 아래 Node 실행법은 로컬 검수 서버용이며, 운영은 인증 API와 영속 Durable Object를 사용한다.

- 입문 8W / 보통 10W / 어려움 12W / 악몽 14W / 재앙 16W, 적 13종·최종 보스 5종.
- 계정마다 용병 2명 + 카드 1장, 2인 6기 또는 3인 9기. TEST에서는 제공된 편성을 사용한다.
- CMS에서 난이도 사용 여부·적 HP/공격/속도/등장 수·수호석 HP를 저장한다. 새 방에 설정을 고정하며 계정 보상·비용은 없다.
- 운영 방은 최대 1시간, 전투는 최대 30분이다. 재접속은 같은 계정·방의 상태를 복구한다. 연결 티켓은 2분마다 갱신되며 OFF/테스터 해제는 신규 입장·갱신을 차단한다.
- 색인 `asset-catalog.json`, 해시 `build-report.json`, 규칙 `shared/monster-defense-v1.mjs`, 운영 기록 `docs/monster-defense-test-20261016.md`가 현행 기준이다.

아래는 최초 독립 검수판의 실행법과 이력이다. 기존 10웨이브·라이브 미연결·21개 자산 표기는 위의 TEST 연결로 대체됐다.

# 협동 디펜스 V1 검수판

2~3명이 각자 **용병 2명 + 카드 1장**을 편성하고 하나의 수호석을 방어하는 실행 가능한 검수판이다. 기존 V3/PixiJS/GSAP 전투 엔진을 상속하며, 별도 Node 서버에서 실제 방 상태와 전투를 판정한다.

## 실행

저장소 루트에서 실행한다. 기존에 설치된 의존성을 사용하며 새 의존성은 없다.

```powershell
node scripts/build-coop-defense-v1.mjs
node scripts/serve-coop-defense-v1.mjs
```

브라우저에서 `http://127.0.0.1:8898/preview/coop-defense-v1/`을 연다.

- 혼자 확인: 편성 → 인원 선택 → **혼자 연습하기** → 준비 완료 → 방어 시작. 나머지 자리는 자동 대원이 맡는다.
- 여러 접속 확인: 방장이 협동 방을 만들고, 다른 브라우저/탭에서 같은 서버 주소로 접속해 초대 코드로 참가한다. 전원 준비 후 방장이 시작한다.
- 다른 기기와 같은 네트워크에서 확인하려면 서버를 시작하기 전에 `$env:COOP_DEFENSE_HOST = '0.0.0.0'`으로 설정하고, 모든 참가자가 서버 PC의 실제 내부 IP와 포트 8898로 접속한다. 기본 localhost 링크는 다른 기기의 PC를 가리키지 않는다. 검수 서버를 인터넷 운영 서버로 사용하지 않는다.
- 포트는 `COOP_DEFENSE_PORT`로 바꿀 수 있다.

## 조작과 화면

- PC: 2880×1280의 긴 전장을 전체 보기로 표시하며, A/B/C 탭으로 한 방어선을 확대한다. 하단 유닛과 전술은 같은 줄에 배치해 전장 공간을 확보한다.
- 모바일: 내 방어선 확대가 기본이다. 긴 세로 전장은 대각선 길목을, 작은 세로 화면과 가로 화면은 수평 길목을 표시한다. 전체 보기와 축소 지도로 다른 전선 상황을 확인한다.
- 확대 전장은 드래그·좌우 버튼·방향키로 이동한다. `분대 위치` 버튼 또는 Home 키로 분대에 복귀하며 축소 지도에서 보고 있는 구간을 확인한다.
- 하단 내 유닛 3기 중 하나를 고른 뒤 A/B/C 버튼으로 지원 이동한다. 소유권, 이동 시간, 재사용 대기는 서버가 검사한다.
- 기본 공격은 자동, 전술은 직접 사용한다. 일부 유닛만 쓰러졌다면 다음 정비에 복귀한다.
- **내 3기가 모두 전투불능이면** 전멸 횟수에 따라 **15→30→45→60초(최대 60초)** 후 체력 50%로 담당 방어선에 복귀한다. 웨이브 종료·강화·재접속으로 대기를 줄일 수 없으며, 스킬/지원 쿨다운도 초기화되지 않는다. 전멸 중에도 적은 진격하고 수호석이 파괴되면 전투가 끝난다.
- 웨이브 사이 정비 자원으로 분대를 강화한다. 자원은 이 전투 안에서만 존재한다.
- 나가기 후 **진행 중인 전투로 돌아가기** 또는 같은 탭 새로고침으로 복귀한다. 연결이 끊겨도 서버의 자동 전투는 계속된다.

## 구현 경계

- 2인 6기/2개 진입로, 3인 9기/3개 진입로. 10웨이브, 5·10웨이브 보스, 공동 거점 패배/최종 웨이브 승리.
- 임시 용병 역할, 전술, 체력, 피해, 정비 시간과 강화 수치는 모두 **검수용**이다. 실제 용병 스킬 배정·계정 성장·보상 정책을 확정하지 않는다.
- 라이브 로그인·보유 카드 검증·매칭·CMS·보상 지급은 연결하지 않았다. 새 용병 획득·편성 잠금을 변경하지 않는다.
- 방은 메모리에만 존재한다. 프로세스 재시작, 방 생성 후 2시간 또는 전원 미접속 10분 경과 시 소멸한다. 재접속 토큰은 해당 브라우저 탭의 sessionStorage에 보관한다.
- 검수 서버는 100ms 단위로 전투를 진행하고 클라이언트는 약 250ms마다 상태를 받는다. 클라이언트는 명령만 제출하며 피해·거점 체력·웨이브를 계산하거나 확정하지 않는다.
- 중복 명령은 같은 requestId로 재시도해도 한 번만 반영한다. 같은 ID의 다른 명령은 거절한다. 최대 4,096개 영수증을 보존하고 한도 도달 후 새 명령을 거절한다.
- 단일 Pixi 렌더러, V3 BattleCharacter/SkillEffectFX/오브젝트 풀을 재사용한다. 피해 숫자는 고정 BitmapFont를 사용한다. 숨겨진 화면과 종료 시 연출을 정리하며 동작 줄이기 설정을 따른다.
- 기존 이미지 원본은 변경하지 않았다. 길목과 수호석은 내장 이미지 생성 도구로 제작한 투명 PNG를 사용한다. `assets/manifest-v2.json`과 `assets/prompts-v2.json`에 원본·해시·최종 프롬프트를 기록했다. `build-report.json`은 기존 19개와 신규 2개, 총 21개 자산의 해시와 공용 V3 모듈·버전 기록이다.
