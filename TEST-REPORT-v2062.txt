5. 원안 회귀 재현 및 수정 확인
   작업 파일을 되돌리지 않고 임시 메모리 모듈에 원안의 두 변경을 재현했다.
   - 모듈 전역 publicReleasePromise.
   - requestId가 다른 PENDING 충돌에서 만료 청소/claim 재시도 누락.
   release completion / concurrent release / stale pending / live pending
   4개 시나리오만 선별해 실행했다.
   - 원안 동작 재현: 3 실패 / 1 통과.
   - 수정 코드 동일 시나리오: 4/4 통과.
   운영에서 발생한 사고를 직접 관측한 결과가 아니라 로컬 회귀 재현이다.

   추가 보완:
   - 다른 DB의 공개 마커를 건너뛰지 않고 실패한 마커 조회는 재시도.
   - 동시 요청이 다른 요청의 미완료 DB Promise를 공유하지 않음.
   - 과거 requestId의 만료 PENDING은 정리하되 살아 있는 PENDING은 보호.
   - 완료 재요청 시 1회만 차감; 30억/200억 비용 및 BIGINT 호환 유지.
   - 지급 중 실패하면 차감·카드·로그·영수증을 원자 롤백.
   - 낡은 마법/프라임/차량/블랙미라클/연금술 캐시를 주입해도
     실제 재화 경로는 최신 설정·후보 풀을 조회.
   - 재정금고 배당 예산안은 캐시된 옛 우승 클랜 대신 최신 클랜을 사용.

   check:worker와 연결된 모든 기능 회귀 검사를 통과한 뒤
   마지막 scripts/verify-production-release.mjs가 다음 조건으로 차단했다.
   - 관련/무관 작업 파일이 있는 dirty 작업 트리.
   - 배포 폴더에 node_modules 등 무시 파일 존재.
   - 로컬 HEAD와 origin/main 불일치.

   따라서 전체 명령은 exit 1이며 release:gate 전체 통과가 아니다.
   별도 운영 배포 지시가 없으므로 관련 없는 파일을 지우거나
   원격을 변경하거나 emergency dirty 배포 우회를 하지 않았다.
   로컬 커밋 후에도 무관 파일과 원격 차이가 남을 수 있다.
   향후 배포는 별도 검토 후 깨끗한 배포 후보에서 release:gate를 통과해야 한다.
