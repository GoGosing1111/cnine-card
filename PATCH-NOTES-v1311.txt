숲켓몬 v1311 월드 레이드 SQL 변수 상한·D1 부하 수정

원인
- raid/status가 참가자 전원의 덱 카드 ID와 사용자 ID를 한 SQL의 IN 절에 모두 바인딩했다.
- 30명 × 5장 구성에서는 카드 조회 150개 변수, 돌파 조회 최대 180개 변수가 한 문장에 들어가 D1/SQLite의 문장당 바인딩 변수 상한을 초과했다.
- 화면의 "at offset 293"은 SQL 문자열 안에서 오류가 감지된 위치이며 DB 용량 부족을 뜻하지 않는다.

수정
- 카드 메타데이터 조회를 카드 ID 40개 단위로 분할한다.
- 돌파 수치 조회를 참가자 6명 단위의 사용자-덱카드 쌍 조건으로 분할한다.
- 문장당 최대 바인딩 변수는 40개 이하로 제한한다.
- 참가자 덱 데이터는 서버에서 최대 5장으로 정규화한다.
- 동일 레이드 표시 데이터는 8초 동안 메모리 캐시하고 최대 16건만 보관한다.
- 카드 표시 조회가 일시 실패해도 월드 레이드 화면 전체를 오류 화면으로 교체하지 않는다.
- 레이드 전투 중 보스 HP DB 체크포인트는 최대 5초에 1회만 갱신한다.

DB/용량
- 신규 테이블·컬럼·인덱스·로그 없음.
- 레이드 전투 상세 JSON 추가 저장 없음.
- 메모리 캐시는 Worker 인스턴스 메모리에만 존재하며 D1 용량을 사용하지 않는다.
- HP는 기존 raid_instances 한 행을 갱신할 뿐 새 행을 만들지 않는다.
