CNINE Card 누적 패치 v1307
자동 뽑기 D1 혼잡 복구 및 저장량 제한

기준
- v1306까지 누적 변경 포함
- 기존 DB 테이블 DROP/RENAME/초기화 없음
- 자동 뽑기 전용 신규 테이블 없음

오류 원인
- 자동 뽑기는 요청을 병렬 실행하지 않았지만 20장 묶음을 수백 회 연속 실행하면서 매 회차마다 뽑기 영수증, 코인 로그, 중복 조각 로그, 카드 지급 갱신이 발생함.
- D1 전체 용량이 즉시 가득 찬 문제가 아니라 지속적인 쓰기 요청이 다른 요청과 겹쳐 D1 큐 대기 시간이 초과된 현상임.

수정 사항
1. D1 일시 혼잡 복구
- D1 overloaded, queued too long, SQLITE_BUSY, 429/503 계열 오류를 일시 오류로 구분함.
- 동일 requestId를 유지해 영수증 상태를 확인하고 RETRYABLE 상태에서 안전하게 재시도함.
- 완료된 요청이면 새 결제 없이 저장된 결과를 복구함.
- 원문 D1 오류를 유저 화면에 노출하지 않고 복구 카운트다운과 안전 중지 문구를 표시함.
- 혼잡 후 다음 요청 간격을 자동 증가시키고 정상화되면 서서히 원래 간격으로 복귀함.
- 50회마다 최소 20초 보호 휴식을 적용함.

2. D1 쓰기·행 수 감소
- 20장 묶음의 중복 카드 조각 로그를 카드별 최대 20행에서 묶음당 최대 1행으로 통합함.
- 뽑기 영수증의 user 전체 프로필과 burningEvent 스냅샷을 저장하지 않음.
- 별도 cost 중간 UPDATE를 제거하고 최종 영수증 확정과 함께 저장함.

3. 자동 뽑기 영수증 용량 제한
- 자동 뽑기에서 화면 표시가 끝난 이전 완료 영수증을 10개 단위로 ARCHIVED 처리함.
- ARCHIVED 영수증은 response_json만 비우고 request_id, 유저, 팩, 개봉 수량, 비용, 상태, 시각은 유지함.
- 현재 처리 중이거나 최근 결과는 그대로 보존해 연결 끊김 복구를 유지함.
- 이전 영수증 정리는 다음 뽑기가 성공적으로 원자 커밋될 때만 함께 실행됨.

4. 저장 정리 호환
- 기존 CMS 저장 정리에서 RETRYABLE 및 ARCHIVED 영수증도 보존 기간 이후 정리 가능하도록 확장함.

저장량 참고
- 20장 500회는 500개의 개봉 영수증과 500개의 코인 로그가 필요함.
- v1306 구조는 결과 JSON이 영수증마다 남아 코드 기반 SQLite 모의시험에서 약 3.35MB/500회였음(중복 로그 평균 10행/회 가정).
- v1307 구조는 이전 결과 JSON 아카이브와 조각 로그 통합 후 같은 모의시험에서 약 0.27MB/500회였음.
- 실제 D1 사용량은 카드 중복 분포, 인덱스, 기존 데이터 상태에 따라 달라질 수 있음.
