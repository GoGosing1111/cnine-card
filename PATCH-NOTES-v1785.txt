v1784 에 이어 남아 있던 과제 중 검증 가능한 항목을 적용했다.


[1] battle/fight : 응답 지연 경로 정리
  (1-a) 코인 지급 + coin_logs 기록을 env.DB.batch 1회로 통합
        batch 는 암묵적 트랜잭션 안에서 순차 실행되므로
        coin_logs.balance_after 는 앞선 UPDATE 가 반영된 값을 읽는다(결과 동일).
        D1 왕복 2회 → 1회.

  (1-b) magicSettings(env) 를 기존 Promise.all 로 이동
        evaluateDeckSynergies / userEquipmentBonuses / magicBattleLoadout 과 함께 받는다.
        뒤쪽에서 직렬로 await 하던 왕복 1회 제거.

  (1-c) battle_logs INSERT 를 waitUntil 로 이동
        응답에서 읽지 않는 감사 로그다. 쓰기는 그대로 수행된다.

  (1-d) grantHighGradeRerollDrop 을 waitUntil 로 이동
        기존 코드에서 rerollTicketDrop 변수에 담기만 하고 응답에 포함하지 않았다.
        (= 순수한 지연만 발생시키고 있었다)
        지급 자체는 유지하되 응답이 기다리지 않게 했다.
        receipts 테이블의 INSERT OR IGNORE 로 중복 지급이 막혀 있어 지연 실행이 안전하다.


[2] battle/auto (자동사냥) : 반복 횟수만큼 곱해지던 쓰기 정리
    자동사냥은 남은 전투 횟수만큼(최대 수십 회) 한 요청에서 반복되므로
    회차당 왕복이 그대로 배수로 늘어나던 구간이다.

  (2-a) 회차별 코인 지급 + coin_logs 를 env.DB.batch 1회로 통합
        왕복 2N회 → N회.

  (2-b) 회차별 battle_logs INSERT 를 모았다가 루프 종료 후 50개씩 batch 로 기록
        그마저도 waitUntil 로 넘겨 응답을 기다리게 하지 않는다.
        왕복 N회 → 응답 경로에서 0회.
        resolveAutoBattle 에 options.collectBattleLog 훅을 추가했고,
        훅을 주지 않으면 종전과 동일하게 즉시 실행된다(하위호환).

[4] 클라이언트 : 전투 진입 대기 제거
  (4-a) 아트 매니페스트 4종의 fetch 옵션 cache:'no-cache' → 'default'
        - js/project-v-battle-art-adapter-v1.js
        - js/project-v-monster-battle-art-adapter-v1.js
        - js/project-v-tier-battle-art-adapter-v1.js

        매니페스트 URL 에 이미 ?v= 버전 키가 있고 /assets/* 는 max-age=86400 이다.
        no-cache 는 전투 진입마다 재검증 왕복을 강제하고 있었다.

  (4-b) V3 전투 번들 유휴 프리페치 추가 (js/app.js)
        데스크톱은 nav 호버 시 warmFeatureForTab 으로 미리 받지만
        모바일에는 호버가 없어 '전투' 탭을 누르는 순간

        부팅 후 requestIdleCallback 시점에 rel=prefetch 로 미리 받아둔다.
        - prefetch 는 브라우저 우선순위가 가장 낮아 초기 렌더/로그인을 방해하지 않는다.
        - navigator.connection.saveData 또는 2g 회선에서는 생략한다.

        4) npx wrangler pages dev 로 setup/status·battle/fight 스모크 테스트
        5) 프리뷰 배포에서 먼저 확인 후 프로덕션
