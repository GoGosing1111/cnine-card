# 일일·주간 퀘스트 — 2026-09-24

## 요청과 운영 정책

- 기존 게임의 네이비·라임 UI, 공용 로비/메뉴를 유지하며 퀘스트 화면을 일일·주간 탭으로 개편한다.
- 일일: PLAY DK 글 **15개**, 매일 00:00 KST 초기화. 기존 운영 보상/ON 설정을 보존한다. 운영 DB 읽기 확인 결과 현재 **100억 코인**이다.
- 주간: **월요일 00:00 이상, 다음 월요일 00:00 미만(KST)**. 글 **200개**, 붕괴코어 레이드 **3회**, 영토전 **1회**, 클랜전 **2회**를 각각 독립 퀘스트로 제공한다.
- 붕괴코어는 실제 완료한 공략이 있는 서로 다른 방을 센다. 같은 방의 재공략, 진행 중 공략, `CORE_BATTLE_ABANDONED` 기록은 제외한다.
- 영토전·클랜전은 직접 완료한 공격 전투를 승패와 무관하게 센다. 자동 편성·대기·방어 기록은 제외한다.
- **신규 주간 4종은 보상 0 / 지급 OFF**로 준비한다. CMS `일일·주간 퀘스트`에서 OWNER가 보상 종류·수량·ON/OFF를 직접 저장한다. 보상을 설정하는 것만으로 ON이 되지 않는다.
- 주간 보상은 퀘스트마다 주 1회 메시지함으로 보낸다. 기존 메시지함 수령 거래를 재사용한다. 기존 일일 보상의 즉시 코인 지급은 유지한다.
- 다른 콘텐츠 출시 플래그, 계정 재화, 보상 확률은 바꾸지 않는다.

## 집계·데이터 안전성

- DK 클라이언트의 `/api/v2/ext/board/daily-post-count` 날짜별 `count`를 월요일~오늘까지 합산한다. 응답 게시글 배열이 잘려 있어도 총 `count`를 사용한다. 최대 7일, 동시 요청 2개로 제한한다.
- 응답 UUID·날짜·KST·게시판을 모두 대조한다. 일부 날짜 실패, 날짜 변경, 인증 계정 변경은 합계를 저장하지 않는다. 실패를 0개나 달성으로 표시하지 않는다.
- 새 테이블: `quest_weekly_posts_v1`, `quest_weekly_claims_v1`. 설정 키: `quest_weekly_settings_v20260924`. 기존 데이터를 덮어쓰지 않는 추가형 초기화다. 사용자별 참여 조회 인덱스는 기존 테이블의 소유 권한이 있을 때만 추가하며, 선택적 인덱스 권한 부족이 퀘스트 초기화를 막지 않는다.
- 주간 수령 UNIQUE 키는 `(user_id, week_key, quest_id)`. 설정 원문 비교, 인증 UUID, DB 시각의 주간 경계, 수령 토큰과 사용자 잠금으로 메시지·보상·영수증을 한 트랜잭션으로 저장한다. 보상 행 생성에 실패하면 모두 롤백한다.
- CMS는 revision 비교와 감사 로그를 사용한다. 저장 경쟁으로 이전 보상 설정이 지급되지 않도록 거래 안에서 다시 검증한다.
- 종료된 영토전 완료 기록 자동 정리 기준을 1일에서 **8일**로 늘려 한 주의 참여가 중간에 사라지지 않도록 한다. 기존에 이미 정리된 과거 기록을 복원하는 작업은 포함하지 않는다.
- 운영 DB의 세 참여 테이블/실제 열 타입과 기존 일일 설정을 읽기 전용으로 확인했다.
- **DK의 실제 인증 계정으로 과거 날짜 응답을 조회하는 최종 점검은 미실행**이다. 제공된 클라이언트 계약과 모의 응답으로 집계/실패 처리를 검증했다. 게시글 주간 보상 ON 전 실계정 `작성글 확인` 결과를 확인해야 한다. 실패하면 지급은 차단된다.
