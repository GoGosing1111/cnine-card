# 콘텐츠별 연출 보상 CMS — 2026-10-16

사용자 요청은 클리어 승리 연출이 아닌 **보상 연출**이다. 기존 붕괴코어의 승인된 V2 보관함 3개 중 1개 선택·개봉·무작위 보상 공개를 재사용하고, 별도 OWNER CMS에서 콘텐츠별 후보·수량·확률을 관리한다. 이스겐과 바르센 연결은 후속 요청에 포함된다.

## 설정과 연결

- OWNER CMS → **연출 보상**: 붕괴코어, 이스겐, 바르센, 격전지 일반·격전·극한을 각각 독립 저장한다. 동일 페이지에서 연출 미리보기, 이름·등급 검색, 후보 추가/삭제, 수량·사용 여부·확률 비중을 편집한다. 비중 합계로 계산한 실제 확률(%)을 표시한다.
- 보상 종류는 코인, 마스터의 별, 용병, 장비, 이동수단, 일반 아이템·재료, 카드 조각, 마력 결정이다. 공개·활성 카탈로그를 사용하며 잠긴 리미티드 용병과 별도 획득 경로가 고정된 장비보호권을 임의 편입하지 않는다.
- 최소 보상도 추첨 후보다. 최소 수량은 미입력(null), 신규 콘텐츠 설정은 OFF다. 보상 수량·확률·ON 상태를 자동 설정하거나 운영 계정에 검수 보상을 지급하지 않는다. 붕괴코어는 기존 저장 키와 값을 그대로 사용한다.
- 이동수단은 1대씩 지급한다. 이미 소유했거나 선택 후보가 비활성/비공개로 변경되면 봉인 생성 시 보존한 최소 보상으로 대체한다. 최소 보상까지 지급 불가하면 수령을 완료 처리하지 않고 재시도를 안내한다.
- 기존 콘텐츠 CMS의 기본 보상과 운영 모드, 입장권, 트로피는 유지한다. 연출 보상은 별도 스위치이며 ON인 실제 전투에만 새 봉인을 만든다. OFF/TEST로 시작한 전투에는 생성하지 않는다.

## 서버 거래와 한도

- 이스겐·바르센·격전지는 시작 시 후보 설정을 고정한다. 정산 시 연출 보상 OFF이면 새 봉인을 생성하지 않는다. 이미 획득한 봉인은 이후 CMS 변경/OFF로 재추첨하거나 삭제하지 않는다.
- 격전지는 모든 난이도 합산 KST 하루 3회, 이스겐은 주간 7회, 바르센은 기존 콘텐츠 CMS 주간 한도를 공유한다. 기본 보상·기존 한도·미수령 봉인 발급을 같은 거래로 저장한다. 기본 보상 없이 선택 보상만 ON이어도 획득한 봉인은 한도 1회를 사용한다. 나중에 봉인을 열 때 추가 횟수를 차감하지 않는다.
- 붕괴코어는 기존 주간 3회와 기본/선택 보상 동시 수령 경로를 유지한다. 새 후보 설정은 새 봉인을 만들 때 적용된다.
- 봉인 3개의 후보는 서버에서 독립 추첨해 저장하며 사용자 응답에는 공개하지 않는다. 최초 선택은 별도로 고정하고 실제 지급·원장·완료 영수증·미수령 목록 삭제는 원자 처리한다. 다른 봉인 선택, 동시에 수령, 응답 유실 후 재시도로 중복 지급하거나 재추첨하지 않는다.
- 장비/차량 INSERT가 0행이면 완료 영수증이 남지 않는다. 계정 존재·재화 한도·실제 인스턴스 소유 증명을 확인한다. SQLite와 PostgreSQL을 함께 검증했다.
- 신규 스키마·마이그레이션·의존성 없이 기존 app_meta와 기존 지급 원장을 사용한다. 미수령 목록은 사용자별 키 범위에서 최대 50개씩 조회하며 완료된 봉인은 목록에서 제거한다. 로비에서 한 번 조회하고 더 보기/다시 확인으로 갱신한다.

## 화면과 검수

- 기존 Pixi/GSAP 보관함·배경 자산을 공유한다. 콘텐츠명·기본 보상·일간/주간 한도를 해당 콘텐츠에 맞춰 표시한다. 선택 전 닫기, 재접속, 지급 후 다시 보기, 화면 종료 시 렌더러 정리, 키보드·동작 줄이기·소리 선택을 유지한다.
- PC 1440×960, 모바일 390×844에서 실제 CMS 편집/저장, 미리보기, 봉인 선택→개봉→결과, 미수령 재열기, 중복 수령, 생명주기 종료를 검수했다. 브라우저 오류 0, 가로 넘침 없음, 결과 확인 버튼 화면 안 배치를 확인했다.
- 모바일 CMS의 전역 header 스타일 충돌과 빠른 선택 시 입장 페이드가 중단되어 상자가 사라지는 문제를 검수 중 수정했다.
- 시각 증빙: `docs/qa/reward-reveal-20261016/`의 PC/모바일 CMS·선택·개봉·결과 8장과 checks.json. 모두 격리 SQLite 검수이며 운영 보상 설정/재화 변경은 없다.
- 관련 검사: `tests/reward-reveal-20261016.test.mjs`(15개), `tests/core-raid-rewards-20260925.test.mjs`(16개), `tests/cooperative-rewards-live-20261013.test.mjs`(1개) 최종 합계 32개 통과. 기존 격전지 보상·이스겐 주간 보상·바르센 라이브 회귀도 통과했다. 마지막 OFF 저장 보완은 배포 단계에서 신규 15개 검사에 포함한다.
- UI 재현: `tests/reward-reveal-20261016.browser.mjs`. `PLAYWRIGHT_MODULE`로 설치된 Playwright 모듈, `REWARD_REVEAL_QA_OUTPUT`으로 저장소 밖 출력 폴더를 지정한다.

## 배포

기존 인증·공통 DB/거래 기반을 바꾸지 않고 보상 설정/정산/공개 경로에 한정한 기능 확장이므로 scoped 배포를 사용한다. 전체 게임 검사를 반복하지 않는다. 배포에서 `tests/reward-reveal-20261016.test.mjs`와 `check:worker`, 기존 출시/캐시/Hyperdrive 검사를 수행한다. 이미 통과한 기존 보상 및 PC/모바일 검수는 재사용한다. 실제 직전 Pages 소스는 배포 직전 다시 조회해 SCOPED_DEPLOY_BASE에 기록한다. 운영 배포 결과는 완료 후 아래에 추가한다.
