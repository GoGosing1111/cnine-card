# V3 전체 개편 현황과 운영 전환 준비

> 2026-09-13 후속 구현: 아래 표는 9월 11일 시점의 기록이다. 그 뒤 탑·폐차장·카우방 계정 API/UI, 기존 자동 원정 복구, 용병 개봉/성장/별도 슬롯/서버 스킬, 강화·파괴·보호·복구 거래, 17종 연출·음향 연결을 구현하고 검수했다. 최신 항목별 상태와 검증 원본은 [공동 출시 완료 작업표](v3-joint-completion-20260913.md)를 따른다. 사용자 최종 시각/경제 정책 및 공동 운영 활성화 승인은 별개로 유지한다.

2026-09-11. 사용자 최신 지시는 무한의탑 개편 착수, 전체 V3 현황 보고와 운영 전환 준비다. 앞선 **“라이브는 아직”**을 유지한다. 이번 작업은 운영 메뉴·API·DB/CMS를 전환하거나 배포하지 않는다.

최신 운영 코드와 합친 별도 후보를 준비했다. 전체 회귀 41개 명령·1,193개 테스트, 브라우저 43개 검사가 통과했다. 후보 위치·검증 원본·운영 게이트 보류 사유는 [배포 후보 기록](v3-release-candidate-20260911.md)에 정리했다.

**전체 V3가 현재 즉시 운영 활성화 가능한 상태라고 보고하지 않는다.** 구현·자산·검증 자료와 배포 후보를 준비하되, 위 표의 미확정 정책과 계정 연결을 실제 출시 조건으로 남긴다. 무한의탑은 기존 제외 상태에서 구현 검수 단계로 이동했으며, 과거 PVE 묶음에 자동 편입하거나 별도 먼저 출시하지 않는다.

## 이번에 추가한 무한의탑 구현

- 1~160층의 검수용 고정 곡선. 적 능력치는 계정 전투력을 따라가지 않는다. HP와 공격 성장률이 다르며 수치 초과는 입장 전에 거부한다. 160은 초기 검수 설정의 안전 상한으로, 최고층 클리어를 콘텐츠 종료로 저장하지 않는다.
- 일반 24마리와 정예 3마리의 처치 진행도 100% 및 현재 교전 종료 후 수호자를 소환한다. 같은 개체의 KO는 한 번만 집계한다.
- 공식 시간은 서버 게이지 시계 1단위=60초라는 버전 규약으로 환산한다. 1×/2× 재생·일시정지·탭 속도와 무관하다. 시간 초과·전멸·수호자 생존은 실패다.
- 성공층 +1 해금, 남은 공식 시간 40%/60%에서 +2/+3 시안. 저층 재등반으로 계속 해금층을 늘리지 않으며 건너뛴 층의 최초 보상을 지급하지 않는다.
- 새 진행도·원정·일일 예산·층별 최초 영수증·보상 원장·버전별 기록을 별도 테이블로 준비했다. 기존 최고층을 초기 해금 기준으로 읽고 예전 기록에 가짜 시간을 만들지 않는다.
- 서버가 저장 덱·시드·결과·정산 정책을 고정한다. 입장 날짜가 바뀌거나 CMS/덱을 수정해도 같은 원정은 같은 결과로 복구한다. 보상 지급과 원정 완료가 한 트랜잭션이며 지급 대상/행 검증 실패 시 롤백한다.

## 배포 준비·검증 계약

1. `npm run build:tower-v3`, `npm run build:scrapyard-v3-preview`, 마지막에 `npm run build:v3-grid`로 공통 8개 소비 번들과 해시를 맞춘다.
2. `npm run release:prepare:v3`는 실제 `release:gate`의 전체 회귀 검사를 실행하고 결과를 `tmp/v3-overhaul-ready-20260911/release/`에 저장한다. **운영 게이트 통과 또는 배포 승인과 동일하지 않다.**
3. 운영 계정 연결 패키지는 기존 인증·계정 mutation lock을 사용해야 한다. 새 층/구역/requestId만 받고 브라우저의 카드·시드·피해·보상·시간은 받지 않는다. 기존 탑 경로와 새 경로의 동시 보상 활성화는 금지한다.
4. DB 스키마는 `_tower_v3_runs.js`의 명시적 마이그레이션과 기존 `_scrapyard_v3_runs.js` 스키마를 사용한다. 일반 GET이나 모듈 import로 DDL을 실행하지 않는다. 활성화 전 롤백 시에는 새 플래그를 OFF로 두고 새 영수증을 보존한다.
5. 최신 운영 `origin/main`에서 만든 별도 후보 트리에 범위 커밋만 통합한다. 다른 작업의 dirty 파일을 업로드하지 않는다. 승인 후 원격 main/HEAD/캐시 버전을 일치시키고 **`npm run release:gate` → `npm run deploy:production`** 순서를 따른다.
6. 경제·시각·콘텐츠 연결이 미완료이면 새 기능은 OFF다. 반영 대기 파일을 올리는 것과 실제 입장/보상 ON을 구분한다.

검증 원본은 `tmp/v3-overhaul-ready-20260911/`에 보관한다. 라이브 최초 보상 읽기 전용 조사 helper는 종료하고 임시 비밀키를 삭제했다.
