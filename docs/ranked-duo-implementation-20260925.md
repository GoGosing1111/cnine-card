# 비동기 랭크 듀오 구현·검수 기록

> 2026-09-25 후속 변경: 이 문서는 당시 설계·검수 기록이다. 최신 모집은 **24시간**, 일정은 랭크전 자동 연동, 개인 행동력 규칙은 일반 랭크전 승계, 최종 10팀 트로피 지급이다. 현재 기준은 [자동 시즌 구현 기록](ranked-duo-auto-season-20260925.md)을 따른다.

## 운영 범위

- 첫 모집은 72시간. 모집 종료 후 전력을 평가하고 강자 절반과 약자 절반을 역순으로 묶는다. 홀수면 가장 늦게 신청한 한 명이 대기한다(동일 시각은 계정 ID순). 약한 사람을 항상 대기시키지 않는다.
- 대전 시작 전 추가모집과 편성 재개를 지원한다. 공개한 기존 팀은 유지하고 신규 신청자·대기자만 묶는다. 시즌 도중 중도 합류·팀 해체는 포함하지 않는다.
- 일반 카드 5장과 별도 용병 최대 1장의 기존 편성 계약을 유지한다. 네 소유자의 일반 카드 20장과 용병 최대 4장이 한 시뮬레이션·한 전장에 출전한다.
- 참가자의 현재 선택 공격 프리셋과 방어 프리셋 1을 사용한다. 선택한 공격 프리셋이 없거나 무효하면 공격을 거부한다. 방어 덱으로 대체하지 않는다.
- 전투 개시자가 개인 행동력을 낸다. 오프라인 팀원·행동력 0인 팀원도 출전한다. 팀 점수는 두 사람에게 공통이며 동시 공격 결과를 누적한다.
- 관리자 메뉴 **랭크 듀오**에서 초안 작성 → 72시간 모집 → 팀 편성 → 대전 활성화를 진행한다. 날짜와 행동력 최대치·하루 지급량·공격 비용은 기본 미설정이며 설정 전 대전을 열 수 없다. 점수 초안은 1,000 / 승리 +24 / 패배 -16이고 시작 전 수정 가능하다.
- 새 초안은 비공개다. 배포만으로 시즌 모집·대전·자동 보상을 시작하지 않는다. 시즌 보상은 이번 구현에서 자동 지급하지 않는다.
- 일일 행동력은 한국시간 날짜가 바뀌면 1일분을 최대치까지 충전한다. 미접속일 수만큼 소급하지 않는다.

## 전력 평가와 최신화

현재 편성을 약하게 저장해도 팀 편성 전력이 낮아지지 않도록 **보유한 합법적 최상위 5장**, 슬롯별 최상위 보유 장비의 PVP 전력, 이동수단·유효 칭호, 가장 높은 보유 용병 기여도를 사용한다. 장비 강화·SUPERSTAR 강화와 FUR +13 비교 단위를 반영한다. 미장착 용병도 편성 전력에 포함하지만 실제 전투에는 장착 용병만 출전한다.

용병 평가는 현행 등급 전력, 자기 소유 카드·장비에 연결한 공격력/체력/보호막, 준비된 스킬의 피해·쿨다운 가중치를 사용하는 휴리스틱이다. 용병별 배율은 운영자가 조정할 수 있다. 이 평가가 실제 승률을 보장하지는 않는다. 팀 공개 후 평가 배율과 초기 점수는 잠근다.

팀 편성 시 평가 기록을 남기되 전투 덱은 시즌 동안 고정하지 않는다. 계정의 카드·장비·프리셋·마법·용병·고유특성 변경은 해당 계정 버전을 올리고, 전투 정책 변경은 정책 버전을 올린다. 5분 만료와 칭호 만료도 적용한다. 전투 직전 네 계정의 최신 버전을 확인하고 예약 트랜잭션에서도 버전을 검증한다. 이후 변경은 다음 경기에 반영하며 과거 기록에는 저장된 입력을 사용한다.

## 부하·정합성 제한

- 로비는 시즌에 저장된 인원수를 읽는다. 신청·취소와 인원수 증감을 같은 트랜잭션으로 처리하며 중복 신청·취소·롤백에도 어긋나지 않는다. 참가자 전체 COUNT/SUM을 로비 요청마다 실행하지 않는다.
- PostgreSQL 카탈로그 트리거는 실제 변경 행이 있는 SQL 문장에만 정책 버전을 올린다. 0행 UPDATE나 중복 INSERT 무시 때문에 전 참가자 요약을 무효화하지 않는다.
- 전투 중 API/DB 호출 없음. 결과 계산은 DB 트랜잭션 밖에서 수행한다.
- 최신 요약은 네 계정 일괄 조회. 미스일 때만 변경 계정의 자료를 읽는다. 갱신 임대 30초로 동시 재계산을 제한하고 무제한 재시도를 하지 않는다.
- 편성 평가 12명/요청, 팀 공개 40팀/요청, 시즌 최대 10,000명. 프로필별 전체 보유 스캔은 참가자 전체가 아니라 요청의 최대 12명에 한정하고 자료량 상한을 검사한다.
- 상대 후보는 점수 인덱스의 위/아래 각 12팀, 실제 최신 전력 비교는 최대 3팀. 현재 매칭권은 90초간 재사용한다.
- 기록은 공격·방어 인덱스를 각각 최대 30행 읽어 최근 30건만 반환한다. 목록에 전체 전투 로그를 넣지 않는다. 순위는 상위 100팀.
- 전역 시즌 행을 매 공격 갱신하지 않는다. 예약은 짧은 공유 잠금과 시작자 행동력 행 잠금, 결과는 두 팀 ID순 잠금으로 처리한다.
- 요청 ID·사용자별 미완료 경기 유일성, 행동력/매칭권/경기 예약의 원자성, 팀 점수 증감의 원자성을 검증한다. 결과 응답 유실은 동일 경기 재사용, 확정 불가 입력은 1회 환불한다.
- 마지막 행동력을 쓴 뒤 브라우저를 바꿔도 서버 상태의 미완료 경기 ID로 복구할 수 있다. 자동 무한 폴링은 없다.
- PostgreSQL 인덱스·변경 트리거는 최초 운영자 초안 생성 시 준비한다. 평상시 요청에서 DDL을 반복하지 않는다. 기존 운영 설정·보상은 덮어쓰지 않는다.

## 격리 측정

명령: `node scripts/bench-ranked-duo.mjs`. Node 24.18.0 / Windows / PGlite / 실제 PostgreSQL 호환 어댑터의 pipeline 경로. 네 계정 보유 카드 8,000장, 공격·방어 편성은 각각 5장. 네트워크 지연은 없다. 프로필의 카드 전력·고유특성·시너지는 테스트용 구현이므로 운영 전체 API 지연과 같지 않다.

| 측정 | 표본 | p50 | p95 | DB 어댑터 호출 |
|---|---:|---:|---:|---:|
| 네 계정 프로필 재생성 | 12 | 144.51ms | 164.95ms | 8 (준비 DELETE 1 포함) |
| 네 계정 프로필 캐시 적중 | 50 | 1.17ms | 1.59ms | 1 |
| 상태 조회 | 30 | 2.28ms | 3.53ms | 5 |
| 새 매칭권 생성 | 20 | 6.98ms | 8.30ms | p95 13 (준비 DELETE 1 포함) |
| 캐시 적중 상태의 전투 요청 | 10 | 14.66ms | 23.84ms | 11 |
| 24명 전투 계산 | 64 | 1.98ms | 3.38ms | 0 |

전투 표본은 운영 SS/SSS 용병 13종을 교차 사용했다. 로그 최대 119,905bytes, 이벤트 최대 185개(서버 제한 1.5MB). 10,000명 편성은 5,000팀, 3.93ms. 이 표본의 합산 전력 범위는 평균 대비 0.045%였으며 임의 분포의 보장값이 아니다.

EXPLAIN에서 점수 후보 `ranked_duo_rank_v1`, 기록 `ranked_duo_attack_history_v1`, 소유 카드 `user_cards_pkey` 사용을 확인했다. 작은 테스트 테이블이므로 `enable_seqscan=off`로 인덱스 사용 가능성을 검사했으며 실제 운영 실행 계획·잠금 대기 측정은 아니다. CPU 값은 DB WASM이 포함된 전체 Node 프로세스 기준이다.

로컬 회귀 예산: 캐시 프로필 1회 왕복, 캐시 전투 12회 이하, 24명 시뮬레이션 p95 50ms 미만, 전투 로그 1.5MB 이하. 운영 참가 규모와 네트워크를 반영한 수치·실제 매칭 승률은 첫 시즌 운영 자료로 확인해야 한다. 측정 없이 무병목이나 특정 동시 처리량을 보장하지 않는다.

## 검사·배포

- `npm run test:ranked-duo`: 엔진·서버·DB 일괄 조회 검사 32개. SQLite, PostgreSQL, 실제 pipeline 경로의 중복 요청·팀원 동시 공격·버전 경합·장애 복구·마지막 행동력 복구·참가 인원 원자적 집계·0행 카탈로그 쓰기를 포함한다.
- PC 및 390×844 모바일에서 로비, 참가 신청, 네 소유자 카드 도크, 24명 진형, 결과·랭킹·기록 재생을 확인했다. 운영 폼에서 직접 설정한 최대치 12 / 일일 6 / 비용 1 저장과 72시간 모집 연결을 확인했다. 모든 자료는 로컬 격리 계정이다.
- 듀오 종료 후 기존 1대1(5+1 대 5+1), PVE(5+1 대 몬스터) 진형과 기존 원화 카드 프레임을 확인했다. 공용 렌더러·GSAP/PixiJS·아트 어댑터를 재사용한다.
- 공용 전투·DB·관리자·사용자 화면 변경이므로 전체 검사 대상이다. 지정 명령 `npm run deploy:production`에서 전체 출시 게이트를 한 번 실행한다.
- 배포 기준 확인: 직전 운영 Pages `78a583b7-182c-4baa-af45-72db2b30be91`, 소스 `1a1001376e0b66e083aaef4b8fb5a6c439849f55`. 이후 문서 커밋 f7669082까지 반영했다. 운영 Hyperdrive 쿼리 캐시 OFF를 읽기 전용으로 확인했다.
- 운영 시즌 생성·모집 시작·대전 활성화는 별도 CMS 조작이다. 운영 DB의 새 시즌 자료를 테스트 데이터로 채우지 않는다.

## 롤백

진행 중 장애는 CMS 시즌 종료로 신규 공격을 막고, 이미 예약한 결과는 복구한다. 런타임을 이전 커밋으로 돌리더라도 경기 영수증·행동력·점수를 삭제하지 않는다. 기존 버전의 미완료 입력을 처리할 수 없으면 한 번만 환불한다. 전역 V3·다른 콘텐츠 출시 플래그는 바꾸지 않는다.
