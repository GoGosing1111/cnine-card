# 디펜스 준비·대기실 UI V3와 몬스터 방향 — 2026-10-17

## 적용

사용자 요청으로 실제 `/defense/`의 원정 준비와 분대 대기실을 전용 정비 UI와 맞췄다. 후속 요청의 몬스터 좌우 반전도 같은 변경에 포함한다. 사용자 최종 시각 승인으로 기록하지 않는다.

- 전용 SUIT 서체·흑철/아이보리/청록 색상, `ui-v3/field-service-bay.png`와 기계식 `command-button.png`를 연결한다. 다른 콘텐츠의 버튼과 밀기 입력을 추가하지 않는다.
- 준비 단계 표시, 난이도 5종과 강도 표시, 실제 CMS 웨이브 수, 보스/출현 병단, 용병 2명+카드 1장과 역할, 2/3인 선택, 방 생성/연습/초대 참가를 정리했다.
- 대기실은 실제 참가자별 3기 원화와 이름·내 분대·방장·준비/연결 상태·빈자리를 보여준다. 준비 인원 진행 막대와 실제 출전 가능 상태를 표시한다. 호스트가 변경되면 방장 표시도 갱신한다.
- 모바일은 편성 설정을 보스 정보보다 먼저 보여준다. 대원 카드는 한 열이며 준비/출전 버튼은 하단에 고정한다. 방장이 아닌 참가자는 준비 버튼을 전체 폭으로 사용한다. 가로 화면에서는 하단을 고정하지 않아 좁은 세로 공간을 확보한다.
- 기존 네이티브 select·키보드 포커스·aria-pressed·준비 상태 알림·동작 줄이기를 유지한다. 전장 외 준비/대기실은 별도 `lobby-v3.css`에 한정한다.

## 몬스터 방향

전용 7종 원화는 이미 왼쪽을 바라본다. V3 기본 적군 반전이 오른쪽을 향하게 만들고 있었으므로 빌드 카탈로그에 `artFacing:-1`을 기록하고 디펜스 actor 생성 시 기존 `applyFacing()`을 적용한다. 함수가 중립 포즈의 방향도 함께 갱신하므로 이동·공격·피격·동작 줄이기에서 복원돼도 방향을 유지한다. HUD는 반전되는 view 바깥에 있어 글자와 체력바를 보존한다. PNG 원본 바이트와 공통 V3 엔진 구현은 변경하지 않는다.

## 범위와 검수

서버 전투 규칙·CMS 값·포인트 획득/강화 확률·계정 경제·2~3인 권한을 변경하지 않는다. TEST와 rewardsEnabled=false를 유지한다. 공통 인증·트랜잭션·의존성 변경은 없다.

실제 로컬 Durable Object fixture와 Chrome/Playwright로 다음을 확인했다.

- PC 1440×1000, 모바일 390×844·320×720, 가로 844×390에서 가로 넘침 없음. 모바일 하단 버튼이 뷰포트 안에 있으며 모든 카드로 스크롤 가능.
- 5개 난이도와 실제 30웨이브 표시, 편성 변경 시 원화·역할 갱신, 2인/3인 방 생성·빈자리 표시·대기실 이탈.
- 12자리 코드로 실제 3개 브라우저가 같은 방에 합류, 링크 복사, 9개 원화 표시, 준비 완료/취소에 따른 출전 차단·허용.
- 출전 후 실제 9기·단일 V3 renderer, 모바일 내 전선 기본 선택.
- 전용 몬스터 7종이 x 감소 방향으로 전진하며 왼쪽 원화 유지. 공격 중, 동작 줄이기와 새로고침 재접속 후에도 view/중립 포즈/HUD 방향 유지.
- TEST 비지정 이용자의 방 생성·연습·참가 차단 유지. JS 오류/리소스 HTTP 오류 없음.

검수 중 자동화의 새로고침 전역 준비 대기와 TEST 비지정 계정의 조기 반환 대기 조건을 보정했다. 두 건은 검수 스크립트 문제이며 운영 코드 오류가 아니었다. 최종 통과 기록은 `docs/qa/monster-defense-lobby3-20261017.json`, 주요 화면은 같은 디렉터리의 `monster-defense-lobby3-20261017-*.png`에 보존한다.

배포 게이트는 관련 실제 방 API 검사 `tests/monster-defense-live.test.mjs`와 필수 출시 플래그/캐시/Hyperdrive 검사만 사용한다. 전체 게임 검사를 반복하지 않는다.

## 운영 반영

변경 캐시 태그는 `20261017-defense-lobby3`이다. 새 CSS를 기존 서비스 워커 network-first 목록에 추가하고 메인 셸 캐시 버전은 유지한다. 실제 운영 반영 식별자와 공개 URL 확인은 배포 후 이 문서에 기록한다.
