# 경매장 BGM 입찰 알림·대형 입찰 — 2026-09-26

## 요청과 변경 범위

- BGM 발동표에 없는 1회 입찰은 팝업 없이 누적 입찰 순위·금액만 갱신한다.
- 발동표에 맞는 입찰의 기존 메시지·BGM 재생은 유지한다. 오디오 재생 로직은 변경하지 않는다.
- 1회 입찰 한도를 1,000억 코인으로 올리고 +1억·+100억·+1,000억 입력 버튼을 제공한다.
- 서버가 큰 입력을 10억으로 잘라 받던 처리를 제거했다. 1~1,000억 사이 정수만 허용하며 범위 밖 입력은 오류로 거부한다.
- CMS BGM 금액 구간도 같은 한도를 지원한다. 기존 운영 구간·금액·확률을 변경하는 DB 작업은 없다.

서버는 BGM이 매칭되지 않은 이벤트의 연출 예약을 생략하고, 기존 일반 입찰 메시지도 이벤트 조회에서 제외한다. 클라이언트는 BGM URL이 없는 이벤트를 표시 대기열에 넣지 않는다. 입찰 기록·차감·누적·환불의 기존 트랜잭션은 유지한다.

## 재현 및 검증

- 변경 전 회귀: 7개 중 6개 실패. 100억 입력이 10억으로 잘리고, 일반 입찰에도 3.8초짜리 메시지 연출이 예약되는 현상을 재현했다.
- `node --test tests/auction-bgm-large-bids-20260926.test.mjs`: 변경 후 **8개 통과**. 실제 경매 API 핸들러와 SQLite 및 PostgreSQL/PGlite에서 100억·1,000억의 정확한 차감/누적, 같은 요청 재시도, 잔액 부족, 중간 실패 롤백, 전액 환불을 검증했다. 발동표 경계, 일반 메시지 제외, CMS 큰 금액 구간도 확인했다.
- `node tests/auction-bgm-bids-20260926.browser.mjs`: 로컬 Chromium **1440×1000 / 390×844 통과**. 일반 입찰과 큰 금액 입찰의 팝업 없음, 순위 갱신, 발동표 메시지 표시, 구버전 일반 이벤트 무시, 일반 입찰 중 오디오 호출/소스/재생 상태 유지, 가로 넘침 없음, 브라우저 오류 없음.
- 화면과 거래는 격리된 합성 계정·로컬 DB로 검사했다. 오디오는 호출을 기록하는 테스트 객체로 검사했다. 운영 입찰을 발생시키지 않았다.
- 스크린샷·실행 보고서는 배포 폴더 밖 `../qa-auction-bgm-bids/`에 저장했다.
- 수정한 서버·클라이언트 파일의 `node --check` 및 diff 공백 검사 통과.
