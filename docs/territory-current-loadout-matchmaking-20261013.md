# 영토전 현재 편성 및 상대 다양화 — 2026-10-13

## 요청과 원인

사용자는 **족게이다** 계정에서 과거 카드 덱과 용병 누락을 제보했고, 상대가 더 다양하게 매칭되도록 요청했다.

- 기존 전투는 참가 시점 `deck_snapshot`과 `loadout_bonus_json`을 사용했다. ACTIVE/PREPARING에서는 불완전 덱 또는 휴전일 때만 최신화할 수 있었다.
- 미개막 회차에서 이월된 참가자는 과거 스냅샷을 유지했고, 자동 클랜 편성만 대상으로 한 갱신 조건에서도 제외될 수 있었다.
- 기존 매칭은 전력상 가장 가까운 12명, 기본 5% 범위와 전체 방어 횟수 순서에 치우쳤다. 개인별 최근 상대 이력을 고려하지 않았다.
- 운영 CMS에서 진행 중인 71회차(털), 개인 편성 A/B 각 80명과 제보 계정의 존재를 확인했다. 제보된 10연패의 구체 기록은 새 읽기 전용 조회로 운영 확인한다.

## 변경

1. 입장 및 교전 시작 시 PVP 공격 덱과 현재 용병·펫·장비·마법을 읽는다. 상대도 동일하게 갱신한다. 현재 덱이 5장이 아니면 과거 덱이나 방어 덱으로 대체하지 않는다.
2. 모집 이월 여부와 무관하게 개인 팀 배정 전 현재 편성을 다시 읽는다. 진행 중 수동 최신화도 허용한다. 팀·행동력·기여도·기존 승패는 갱신 대상이 아니다.
3. 후보 조회 상한을 12→48명으로 넓힌다. 전력비 기본 20%, 후보가 6명 미만이면 최대 50%까지 확장한다. 비교 가능한 후보가 아예 없으면 가장 가까운 전력비+10%p를 기준으로 계속 매칭한다. 최근 12경기에서 만나지 않은 후보가 우선이며 전원을 만났으면 가장 오래전에 만난 상대부터 순환한다. 전력 기준은 최신 저장값으로 후보를 좁힌 후, 선택 후보를 현재 전력으로 다시 확인·재선택한다.
4. 확정 전투 입력과 시드를 기존 영수증 거래에 함께 보존한다. 재시도는 당시 입력으로 재생하고 보상·차감을 반복하지 않는다. 입력이 없는 이전 기록 또는 재생 결과가 달라지는 기록은 확정 결과만 표시한다.
5. 내 전투단에 실제 카드 이미지 5장과 PVP 용병 이름을 표시한다. 자동 전체 새로고침 때 열린 전투단 창과 스크롤을 유지한다.
6. CMS 영토전에 정확한 닉네임으로 등록/현재 편성과 최근 10경기를 비교하는 관리자 읽기 전용 조회를 추가한다.

## 검수 및 배포 범위

- 새 매칭/최신 덱/용병/재생 입력/읽기 전용 조회 및 UI 검사 14개 통과.
- 관련 기존 9거점/시설 거래/공성 보상/진영 표시/매칭 회귀를 함께 확인했다. SQLite·PostgreSQL 모두 재시도 중복 차감·지급, 잘못된 거점·불완전 덱 거절과 거래 롤백을 확인했다.
- 실제 V3 엔진에서 현재 선택한 발테르가 양쪽 전투에 포함되는 것을 확인했다.
- 테스트용 계정·회차를 사용하는 실제 게임 UI에서 PC 1280×720 및 모바일 390×844의 카드 이미지 로드, 용병 표시, 수동 최신화, 자동 갱신 후 창 유지, 가로 넘침 없음을 확인했다.
- 화면: [PC](qa/territory-current-loadout-20261013/desktop.png), [모바일](qa/territory-current-loadout-20261013/mobile.png). 모두 로컬 합성 데이터 검수 화면이다.
- 공통 인증·DB 기반·스키마·경제 정책 변경이 없는 영토전 국소 수정이므로 `npm run deploy:production -- --scoped`를 사용한다. 신규 회귀 두 파일과 `check:worker`, 기존 출시·캐시·Hyperdrive 보호 검사를 지정한다.
- 진행 중 회차 초기화, 승패 변경, 보상 소급 지급, ON/OFF 변경은 하지 않는다.
