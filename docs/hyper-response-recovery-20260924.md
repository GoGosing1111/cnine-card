# 하이퍼팩 빈 응답·JSON 파싱 오류 복구

## 재현과 범위

- 사용자 화면: `Failed to execute 'json' on 'Response': Unexpected end of JSON input`가 하이퍼팩 버튼 아래에 노출됐다.
- `joint-account-transport.mjs`가 HTTP 본문을 무조건 `response.json()`으로 파싱하고 실패 시 HTTP 상태를 보존하지 않았다. 하이퍼팩은 이 오류를 그대로 표시하고 중단했다.
- 현재 운영의 상태 조회는 정상이며, 존재하지 않는 영수증 조회는 JSON `JOINT_NOT_FOUND` / HTTP 404였다. 사용자 요청이 비어 버린 상위 네트워크 원인까지 특정한 것은 아니다. 빈 200, 잘린 JSON, HTML 502, 연결 단절을 로컬에서 각각 재현해 수정했다.
- 인증/권한·서버 거래·보상 확률·비용·ON/OFF·DB·다른 개봉 UI는 변경하지 않는다. 공용 통신 변경은 JSON 파싱 실패의 안전한 오류 분류뿐이다. 하이퍼팩의 재시도/영수증 복구는 해당 모듈에만 적용한다.

## 수정

- 잘못된 본문은 HTTP 상태와 `JOINT_RESPONSE_INVALID`로 전달하고, 사용자에게 한국어 연결 안내를 제공한다. HTML/내부 파싱 오류를 화면에 노출하거나 실패한 응답을 성공으로 처리하지 않는다.
- 하이퍼팩 상태·영수증 GET은 일시 오류일 때만 250ms 후 한 번 재확인한다. 반복 실패는 끝없이 재시도하지 않는다.
- 개봉 POST 응답이 불확실하면 **POST는 자동 재전송하지 않고** 같은 요청 ID의 영수증 GET으로 완료 결과를 확인한다. 완료 결과만 수량/최근 결과에 반영한다.
- 영수증을 확정할 수 없으면 자동 개봉을 중지하고 원래 요청 ID를 보관한다. “이전 개봉 처리 확인”을 통한 명시적 복구도 기존 요청 ID를 그대로 쓴다.
- 빈 404는 영수증이 없다는 확정 증거로 취급하지 않는다. 정상 JSON의 404와 구분하여 새 POST로 넘어가지 않도록 한다.
- 자동 결과 전용 표시와 수동 연출은 그대로 유지한다.
