# 2차 인증 입장권 5장 · 붕괴코어/리치왕 주간 보상 초기화

사용자 지시: **2차 인증 전체 유저에게 리치왕 입장권 5장씩 지급하고, 전체 유저의 붕괴코어·리치왕 주간 보상을 초기화한다.**

- 지급 대상은 기존 일괄 지급과 같은 `user_second_verifications`에 연결된 ACTIVE 계정 전체다. 모든 역할과 인증 제공자를 포함하고, 미인증·정지 계정은 지급 대상에서 제외한다. 사전 조회는 541명(OWNER 2 / ADMIN 2 / USER 537), 인증된 정지 계정 1명 제외다.
- `LICH_KING_ENTRY_TICKET`을 인벤토리와 미확인 수량에 각각 5장 더한다. 지급 대상 해시·아이템 활성 상태·지갑 보존·계정별 지급 원장·감사 로그·완료 영수증을 검증한다.
- 주간 초기화는 **2026-10-05 주차**, 인증 여부와 상태에 관계없이 전체 계정이다. 붕괴코어와 리치왕 각각 0/3으로 돌아가며 새 클리어부터 다시 최대 3회 보상받는다. 이미 지급된 보상·잔액·완료 영수증·클리어 기록·과거 주차·CMS 설정은 보존한다.
- 붕괴코어는 지급 영수증에 기존 런타임이 인식하는 `weeklyRewardReset`을 붙이고 주간 카운터를 0으로 변경한다. 해당 코어 보상의 피그 코인 주간 한도도 기존 정책대로 다시 사용할 수 있다. 옛 공대 재수령은 완료 영수증이 계속 차단한다.
- 리치왕은 이번 주 계정별 카운터를 0으로 변경한다. 공대 기록은 삭제하지 않는다. 리치왕 공대 쓰기 잠금 → 전체 사용자 행 잠금 → 주간 기록 잠금 순서로 처리하며, 진행 중 공대가 있으면 내부 version만 갱신해 초기화 전 보상 계산이 재시도되도록 한다. 사전 조회에서 진행 중 공대와 구형 방식 지급 기록은 모두 0건이었다.

## 구현 및 검수

- 지급 작업: `scripts/ops/verified-lich-tickets-five-20261008.mjs`, 키 `ops:verified-lich-tickets-five:20261008:v1`.
- 초기화 작업: `scripts/ops/core-lich-weekly-reset-20261008.mjs`, 키 `ops:core-lich-weekly-reset:20261008:v1`.
- 두 작업은 각각 PostgreSQL 거래와 고유 완료 키로 보호된다. 재실행은 기존 결과만 확인하며 추가 지급이나 재초기화를 하지 않는다.
- 관련 검사 8개: 역할/인증 제공자 및 전체 목록 지급, +5와 다른 상태 보존, 실패/응답 유실/재시도 중복 차단, 양쪽 주간 카운터와 기존 보상 보존, 실제 신규 클리어 3회 및 초과 차단, 옛 공대 재수령 차단, 붕괴코어 피그 코인/선택 보상, 진행 중 공대의 오래된 계산 무효화, 과거 주차·예상 밖 구형 기록 차단.
- 게임 런타임·DB 스키마·CMS·확률은 변경하지 않는다. 일회 운영 스크립트와 해당 검사·기록만 커밋하며 게임 재배포는 하지 않는다.
