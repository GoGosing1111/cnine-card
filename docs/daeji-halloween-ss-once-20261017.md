# 대지 할로윈 SS 리미티드 1회 확정

사용자 요청: “대지 계정에 할로윈팩 개봉할때 SS리미티드 1회 뜨게해”, “아니 자동개봉이던 뭐던 1번뜨게 하라고”.

- 운영 DB의 정확한 닉네임 대지, ID 4479, ACTIVE USER, 현재 PLAYDK 인증 이름 일치를 확인했다. 과거 문서의 인증 식별자를 현재 값으로 가정하지 않는다.
- 할로윈팩 다음 신규 유효 개봉에서 첫 칸 하나를 할로윈 SS 리미티드로 확정한다. 1회·10회·자동 개봉 모두 같은 서버 경로를 사용한다. 개별 캐릭터 지정은 없으므로 판매 설정에 포함된 재고 있는 SS 7종 사이에서 기존 상대 가중치를 사용한다. SSS 리미티드는 확정 대상이 아니다.
- 이후 요청은 원래 CMS 확률이다. 10회 중 나머지 9칸의 자연 당첨은 그대로 유지한다. 기존 완료/미완료 개봉의 확정 난수는 소급 교체하지 않는다.
- 확정 소모, 코인 차감, 카드 보유, 획득·한정 일련번호, 관리자 감사, 완료 영수증을 기존 한 거래에 넣었다. 실패·품절·OFF·잔액 부족에는 확정 기회를 소모하지 않는다. 응답 유실·재시도·동시 요청에 추가 확정이 발생하지 않는다.
- 일반 클라이언트는 확정을 설정할 수 없다. 운영 도구는 정확한 한 계정과 고정 작업 키 `ops:daeji-halloween-ss-once:20261017:v1`만 다루며, 기존 설정을 덮어쓰거나 소모 후 재충전하지 않는다. 설치 단계에서는 재화와 카드, 전역 가격·확률·판매 상태·발행 수량을 바꾸지 않는다.

서버 변경은 `functions/_mercenary_halloween_once.js`, 기존 할로윈 개봉 서비스와 공용 추첨기에 한정한다. 새 UI·공통 DB 스키마·인증 변경은 없다. 관련 회귀는 `tests/mercenary-halloween-once-20261017.test.mjs`와 기존 할로윈 개봉·자동개봉 검사, Worker 컴파일로 한정한다.

운영 절차: scoped 배포 → 계정 USER_LOCK·DB 보조 잠금 아래 dry run 원복 확인 → 1회 설정 → 동일 작업 재실행 무변경 → 별도 연결 검증. 실제 적용 영수증과 배포 결과는 완료 후 아래에 기록한다.
