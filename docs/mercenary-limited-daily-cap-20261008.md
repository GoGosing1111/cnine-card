# 리미티드 용병팩 일일 개봉 제한 — 2026-10-08

사용자 요청: “리미티드팩 개봉 1일 3000개로 제한해”.

- 계정당 하루 **3,000개**, 한국 시간 매일 **00:00** 초기화. 1회·10회 묶음·자동 개봉을 모두 합산한다. 일반/한정 용병, 재료, 꽝 모두 실제 개봉한 수량으로 센다. OWNER도 같은 제한을 따른다.
- 남은 수량보다 큰 10회 묶음은 결제·지급 없이 전체 거절한다. 남은 수량은 1회씩 이용할 수 있다. 자동 개봉 한 번의 기존 최대 1,000회는 유지하며, 여러 번 실행해도 하루 총 3,000개를 넘을 수 없다.
- 현재 1회 10억·10회 100억 코인, CMS 확률·재고·출시 OFF는 보존한다. 이번 변경은 개봉 활성화 승인이 아니다. 기존 멤버 카드 리미티드팩 `pickup`과 일반 하이퍼팩에는 적용하지 않는다.

## 처리 방식

`shared/mercenary-limited-daily-v1.mjs`가 한도와 한국 날짜 계산의 단일 기준이다. 서버가 날짜를 정하며 클라이언트 날짜·사용량을 받지 않는다.

기존 `app_meta`에 `mercenary_limited_daily_v1:<계정 ID>:<한국 날짜>`로 확정 수량을 보관한다. 기존 `runJointOperation`의 계정 행 잠금과 원자적 거래 안에서 한도를 다시 검사하고 수량·코인·보상을 함께 확정한다. 동시 창/기기 요청도 한도를 초과하지 않는다. 별도 스키마·마이그레이션이나 공통 거래 기반 변경은 없다.

실패한 거래는 한도도 함께 롤백한다. 동일 요청 재전송·응답 유실 복구·영수증 재조회는 추가 집계하지 않는다. 미결제 요청을 다음 날 복구하면 실제 결제 처리일의 한도를 사용한다. 완성된 영수증에는 조회 시점의 오늘 잔여량을 포함한다.

운영 출시 OFF이고 적용 전 `MERCENARY_LIMITED_OPEN` 요청 이력은 0건임을 읽기 전용 조회로 확인했다. 따라서 이전 개봉 이력의 이관은 필요하지 않다. 확률·가격·재고·계정 재화를 운영에서 수정하지 않았다.

계약실은 오늘 남은 수량과 초기화 시각을 표시한다. 수량을 초과하는 묶음·자동 시작을 막고 서버의 한도 오류 시 자동 진행을 중지한다. 한국 자정과 백그라운드 복귀 시 사용량을 갱신하며 기존 영수증 확인은 계속 가능하다.
