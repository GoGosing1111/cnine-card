# 전투 길이 단축 (V1812)

실제 엔진(`_battle_v2_preview.js`)을 그대로 뽑아 돌려 측정하고, 수정본으로 다시 돌려
확인한 값입니다. 재구현해서 잰 게 아닙니다.

---

## 무엇이 문제였나

```
실전형 덱 50만 · 나이트메어    231턴 = 130초
그 231턴 중 몬스터가 행동한 건   0~5턴
```

**"서로 공격"이 아니었습니다.** 플레이어 속도는 `70 + 전투력×0.10` 으로 계속 자라는데
몬스터 속도는 **92 고정**입니다. 전투력이 올라갈수록 몬스터는 거의 못 움직이고,
유저는 샌드백을 231번 두들깁니다.

늘어지는 원인은 셋이었습니다.

| | |
|---|---|
| 몬스터 HP = 전투력 × 4.0 (나이트메어 ×2 → **8.4배**) | 깎는 데 100~270턴 |
| 방어 감산 상한 `0.65` 가 실전 구간에서 **항상** 걸림 | 때린 것의 **35%만** 들어감 |
| V3 연출에 길이 압축이 없음 | 턴당 0.56초 고정 |

세 번째는 회귀입니다. 구버전 연출(`js/battle-v2-live.js`)에는 있었습니다.

```js
const base = state.cursor >= 80 ? 260 : state.cursor >= 40 ? 330 : 420;
```

V3(`BattleEngine.js`)로 오면서 이게 빠져서 `timeScale(PLAYBACK_SPEED)` 고정이 됐습니다.

## 조사하다 나온 밸런스 버그 2개

**① 방어형 덱은 나이트메어를 못 깼습니다.** 40판 전부 `MONSTER_SURVIVED` —
진 게 아니라 **4초 시뮬 클럭이 끝난 것**입니다. 아무리 강화해도 안 됩니다.
균형형도 20%만 성공했습니다.

**② 저전투력 구간도 같은 이유로 막혀 있었습니다.** 덱 2만이면 자기 전투력의
30%짜리 몬스터까지만 잡힙니다.

둘 다 이번 수정으로 같이 풀립니다(부수 효과).

## 고친 것

### A. V2 엔진 — 양쪽 최대 HP ×0.55  (`functions/_battle_v2_preview.js`)

```js
// 플레이어
power * profile.hp * 4.25   →   power * profile.hp * 2.34
// 몬스터
power * (isBoss ? 4.6 : 4.0)  →  power * (isBoss ? 2.53 : 2.20)
```

전투 길이 = `HP ÷ 1회 피해량` 입니다. **양쪽을 같은 비율로** 낮추면
"누가 이기는가"는 그대로고 "몇 대 만에 끝나는가"만 줄어듭니다.

피해 상한(최대HP의 46%)·회복량·보호막·보스 궁극기가 **전부 최대HP 비율**이라
함께 축소됩니다. 그래서 상대적 관계가 유지됩니다.

> ⚠ **한쪽만 건드리면 승패가 바뀝니다.** 반드시 두 곳을 같이 봐야 합니다.

### B. V3 연출 — 턴이 쌓이면 재생을 빠르게

`preview/project-v-v3/source/battle/BattleEngine.js` **와**
`preview/project-v-v3/project-v-pixi-battle.bundle.js` **양쪽**에 넣었습니다.

```js
advancePace(type){
  if(type==='DEPLOY'){this.paceActions=0;this.paceScale=1;return}
  if(type!=='TURN'&&type!=='ATTACK'&&type!=='COUNTER')return;
  this.paceActions+=1;
  this.paceScale=this.paceActions>80?1.82:this.paceActions>40?1.28:1;
}
// timeline()
instance.timeScale(this.reducedMotion?8:PLAYBACK_SPEED*(this.paceScale||1));
```

40턴까지 원속도 → 80턴까지 1.28배 → 그 뒤 1.82배. **판정과 타임라인은 그대로고
보여주는 속도만 바뀝니다.** `DEPLOY` 로 매 전투마다 초기화됩니다.

> ⚠ **저장소에 번들러 설정이 없습니다.** 소스만 고치면 반영되지 않습니다.
> `js/app.js` 가 번들을 직접 불러옵니다. 그래서 소스·번들 둘 다 고쳤습니다.
> 나중에 번들을 다시 빌드하면 소스 쪽 수정이 그대로 들어갑니다.

### C. 캐시 버스트 (`js/app.js`)

```
project-v-pixi-battle.bundle.js?v=55-pvp-identity → ?v=56-v1812-pace
```

서비스워커가 `SHELL_CACHE` 에 담아두기 때문에 안 올리면 유저는 옛 번들을 계속 씁니다.

## 결과 (덱 50만 vs 몬스터 50만 · 60판 중앙값)

| | 현재 턴 | 현재 시간 | 수정 후 턴 | 수정 후 시간 | 단축 |
|---|---:|---:|---:|---:|---:|
| 일반 · 공격특화 | 65 | 36초 | 37 | **21초** | 43% |
| 일반 · 실전형 | 97 | 54초 | 54 | **29초** | 47% |
| 일반 · 균형 | 116 | 65초 | 64 | **33초** | 49% |
| 일반 · 방어형 | 153 | 86초 | 84 | **41초** | 52% |
| 나이트메어 · 공격특화 | 155 | 87초 | 87 | **42초** | 52% |
| 나이트메어 · 실전형 | 231 | 130초 | 127 | **55초** | 58% |
| 나이트메어 · 균형 | 270 | 152초 | 155 | **63초** | 58% |
| 나이트메어 · 방어형 | 214 | 120초 | 204 | **78초** | 35% |

**시간초과 패배도 같이 풀렸습니다.**

```
나이트메어 균형형   승률  20% → 100%
나이트메어 방어형   승률   0% →  93%
```

**PVP 공정성은 그대로입니다** (미러전 300판, 선공 승률 · 표준오차 ±2.9%p).

```
공격특화  48% → 48%      실전형  46% → 46%
균형     51% → 49%      방어형  48% → 50%
```

## PVE 난이도 변화

HP는 줄이고 전투 시계 4.0은 유지했기 때문에, 기존 시간초과 패배 일부가 승리로
바뀝니다. 전투 길이를 줄이는 동시에 막혀 있던 PVE 구간을 완화한 결과입니다.

"내 덱 전투력의 몇 %짜리 몬스터까지 잡히나":

| 덱 전투력 | 일반 현재 → 수정 후 | 나이트메어 현재 → 수정 후 |
|---:|---|---|
| 20,000 | 30% → 50% | 10% → 20% |
| 100,000 | 60% → 120% | 30% → 50% |
| 300,000 | 200% → 350% | 80% → 140% |
| 500,000 | 300% → 500% | 120% → 220% |

몬스터 `battle_power`를 일괄 인상하지 않아 CMS 밸런스 값도 그대로 유지됩니다.

## 남은 것 (이번엔 안 건드림)

**몬스터 속도가 92 고정입니다.** 플레이어 속도는 전투력에 비례해 자라므로,
고전투력 구간에서 몬스터는 231턴 중 0~5턴만 행동합니다. 사실상 허수아비입니다.

`buildMonsterFighter` 의 `speed = isBoss ? 104 : 92` 를 전투력 비례로 바꾸면
전투가 "주고받는" 모양이 되지만, **몬스터 행동 횟수가 늘어 난이도가 크게 올라갑니다.**
길이 문제와 별개 사안이라 이번엔 손대지 않았습니다.
