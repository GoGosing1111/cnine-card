S 6명·SS 8명의 컨셉 배정은 `skill-s-ss-plan-v3.json`과 운영 CMS r52를 보존한다. 별도 슬롯의 스냅샷은 저장된 일반 카드 5장과 함께 기존 서버 전투 엔진·V3 Pixi/GSAP 렌더러로 전달된다. 실제 지휘소에서도 배정 스킬의 효과·발동 조건·수치 검수 상태를 표시한다. 원화와 전투 SD를 분리한다.

개봉은 기존 하이퍼팩 5억 코인 × 1~10회이다. 실제 용병 확률 CMS의 C~SSS, 마스터의 별, 미스틱 에너지, 꽝을 사용한다. 이전 하이퍼팩의 별도 4항목 초안 편집 화면은 현재 확률 CMS로 안내한다. 저장된 확률·수량은 변경하지 않는다.

개봉·배치 개봉·구형 Hyper 별칭은 같은 계정 잠금과 원자적 지급 로직을 사용한다. 서버 영수증에 실제 카드 원화·등급·이름·중복 누적 수를 포함하며, 클라이언트는 추첨하지 않는다. 응답 유실 시 계정별 요청 ID로 영수증부터 복구한다. 카드 대신 마스터의 별·미스틱 에너지·꽝이 나와도 같은 확정 결과 표현을 사용한다. 창 닫기·페이지 이동·일시정지·건너뛰기를 처리하고, 연출을 불러오지 못하면 저장된 결과 목록을 표시한다.

폐차장은 실제 티켓·계정 덱·3구역 연속 전투·보상 영수증을 연결한다. 카우방은 실제 PVE 토벌·소탕에서 일반 2%, 아포칼립스 3%로 발견한 포탈을 입장 시 한 번 소비하며, 결과 복구에는 추가로 사용하지 않는다. 기존 클리어 5억·일일 최대 30억·6회·CMS 입력 상한 100억 설정을 보존한다. 서버 자동 원정 진행 방식도 보존한다.

## 개방 상태와 운영 정책

- `shared/v3-joint-release-v1.mjs`의 단일 게이트는 `false`이다. 용병 개봉·편성·폐차장·카우방 API는 인증·계정 쓰기보다 먼저 차단한다. OWNER 우회 경로를 추가하지 않는다.
- 스킬의 미정 피해 계수·재사용·비용 및 검수 상태는 임의 승인하지 않는다. 이 항목은 실제 공동 출시를 ON으로 전환하기 전 확정할 조건이다.
- 운영 변경 계획 `ops:mercenary-pack-connection:2091:20260913`은 `mercenary_runtime_policy_v1`의 미설정 개봉 비용을 기존 상점의 5억 코인으로 연결한다. 정책 revision 0→1, mode OFF, approved false이다. 등급·스킬·확률·유저 계정은 변경 대상에 포함하지 않는다.
- 운영 변경은 사전 해시와 CMS revision을 비교한 뒤 CAS, 감사 로그, 재실행 방지 영수증을 한 트랜잭션에 저장한다. 먼저 롤백하는 드라이런으로 검증한다. 배포 후보와 증빙은 게시 폴더 밖 `../qa/live-connections-2091/`에 보관한다.
- 캐시는 `2091-live-connections`이다. 배포는 깨끗한 범위 커밋에서 `npm run release:gate`를 통과한 뒤 `npm run deploy:production`만 사용한다.

## 검증

- SQLite/PostgreSQL의 실제 트랜잭션 경로: 동일 요청·별칭 개봉의 1회 차감/지급, 실제 원화와 중복 집계, S·SS 14명 모두 저장된 별도 슬롯→실제 전투의 해당 스킬 이벤트, OFF API의 DB 접근 차단.
- 독립 로컬 계정 UI: 실제 10회 개봉 50억 1회 차감, 응답 유실 후 재접속 영수증 복구, 10개 중복 집계, 실제 CMS 스킬과 SS 편성, 폐차장 OUTER/CORE/FURNACE 및 카우방의 일반 카드 5장+용병 1장·일정한 그리드·보상·포탈 1회 소비 후 복구를 확인했다.
- 1440·390·320px 지휘소·개봉 결과, PC/모바일 전투 및 CMS를 렌더링했다. 샘플 계정·검수용 확정 스킬 수치·TEST 모드는 로컬 테스트 서버에만 있다. 운영 계정으로 유료 개봉·입장을 시험하지 않는다.
- 잔액 부족으로 10회 개봉이 거절되면 거래·차감이 생기지 않고, 미완료 요청을 정리한 뒤 1회 개봉으로 변경할 수 있다. 응답 유실·미확정 거래는 기존 요청을 보존한다. 원화 로딩 중 창 닫기와 모바일 결과 목록·CMS 줄바꿈도 별도 검수했다.
- 개봉 표현은 기존 `js/hyper-pack-fx-v2076.src.js`의 PixiJS/GSAP 공용 런타임을 재사용한다. 승인된 스킬 연속 프레임·충돌·사운드 자산은 변경하지 않는다.
