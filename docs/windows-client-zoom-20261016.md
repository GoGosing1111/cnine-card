# Windows 클라이언트 0.1.4 · Ctrl + 휠 화면 크기 — 2026-10-16

사용자 요청: `윈도우클라이언트 컨트롤 마우스휠로 글씨 크기 변경시켜달라고 건의옴`.

게임 창에서 Ctrl + 마우스 휠 위/아래로 글씨와 화면을 확대·축소한다. 범위는 50~200%, 한 단계는 10%p다. Ctrl + ＋/－도 지원하고 Ctrl + 0으로 100%를 복원한다. 일반 휠은 기존 스크롤을 유지하며 런처 배율은 변경하지 않는다. 허용된 게임 새 창에도 같은 크기와 조작이 적용된다.

선택한 배율은 전용 앱 프로필의 `game-display-v1.json`에 작은 JSON으로 원자적으로 저장한다. 게임 창을 다시 열거나 페이지 이동·새로고침·앱 재실행을 해도 복원된다. 설정 파일이 없거나 읽을 수 없으면 100%로 시작한다. 브라우저/PWA 설정·계정 데이터에는 접근하지 않는다.

## 구현

`game-preload.cjs`가 격리된 게임 창에서 신뢰된 Ctrl + 휠/키 입력을 먼저 처리한다. 따라서 페이지나 전장 캔버스의 휠 처리와 중복되지 않는다. 메인 프로세스는 등록된 게임 WebContents의 메인 프레임, 허용된 HTTPS 주소, `in`/`out`/`reset` 명령만 받는다. 원격 페이지에 Node·IPC·런처 브리지를 공개하지 않으며 기존 sandbox/contextIsolation/webSecurity를 유지한다.

`lib/game-zoom.mjs`는 배율 제한·동기화·복원을 담당한다. 글자 CSS만 개별 수정하지 않고 [Electron의 setZoomFactor](https://www.electronjs.org/docs/latest/api/web-contents#contentssetzoomfactorfactor)로 Chromium의 화면 배율을 적용한다. 신규 preload를 외부 스테이징과 app.asar 포장 목록에 포함하고 패키지·정책 버전을 0.1.4로 맞췄다. 런처 이용 안내에도 조작법을 표시했다.

## 검수

- 기존 0.1.3에서 Ctrl + 휠 입력 후 배율이 100%에 머무는 현상을 재현했다.
- `tests/windows-client-zoom-20261016.browser.mjs`: 실제 Electron 44.7.2에서 Playwright 입력으로 21개 확인을 통과했다. 일반 스크롤, Ctrl + 휠 양방향, 키보드 단축키, 상·하한, 100% 복원, 페이지 이동·새로고침·앱 재실행, 허용된 새 창의 배율 공유를 확인했다.
- 확대 후 실제 렌더링 배율(devicePixelRatio) 증가를 확인했다. 페이지가 생성한 가짜 휠 이벤트, 잘못된 IPC 발신 창·프레임·명령은 무시된다. 원격 Node·런처 브리지 미노출, 페이지 오류 0개, 운영 API 요청 0건이다.
- 950×680 런처에서 안내·게임 시작 버튼의 잘림과 가로 넘침이 없었다. 100%/150% 비교와 안내 화면을 `qa/windows-client-zoom-20261016/`에 보존하고 직접 확인했다.
- 기존 `windows-client-20261015.browser.mjs`의 실행·다운로드·캐시 재사용·복구·API/쿠키 전달·원격 권한 제한 회귀가 통과했다. `windows-installer-20261015.test.mjs`의 반복 스테이징·한글 인코딩 검사 1개도 통과했다.
- 완성 app.asar의 main, 양쪽 preload, 배율 모듈, 버전 정책, 안내 HTML 6개 파일이 검수 소스와 바이트 단위로 일치한다. 실제 설치·제거 엔진은 변경하지 않았으며 운영 계정에 접속하거나 기존 설치를 덮어쓰지 않았다.

Electron 배포 서버의 504 응답은 이미 설치된 같은 44.7.2 배포본을 `electron-builder --config.electronDist`에 지정해 해결했다. 기존 스테이징 스크립트와 전용 WPF 설치기 컴파일러를 사용했다. 웹/PWA 실행 파일 변경이 없어 전체 게임 검사·Pages 재배포는 수행하지 않는다.
