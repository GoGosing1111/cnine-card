# 붕괴 코어 보상 V2 연결·이번 주 전체 유저 초기화

2026-09-25 사용자 승인: `승인, 이것도 주간 3회보상 초과해서 받을수 없음 커밋해 내용물은 cms에 반영해뒀다`. 후속 지시: `전체유저 이번주 붕괴코어 보상받은거 리셋해서 0부터 다시 깰수있게 해놔`.

## 구현

- 승인된 전용 배경·8프레임 보관함과 PixiJS/GSAP V2 연출을 본게임 수령 버튼과 레이드 CMS 미리보기에 연결한다. 프리뷰와 게임은 동일한 `js/core-raid-reward-picker-v2.mjs`, `js/core-raid-reward-stage-v2.mjs`, `css/core-raid-reward-picker-v2.css`를 사용한다. 승인 자산은 변형 없이 보존한다.
- 게임에는 실제 주간 사용 횟수와 `기본·선택 보상 함께 주간 최대 3회`를 표시한다. CMS 미리보기에는 실제 지급 없음이 표시되며 저장·지급 요청을 보내지 않는다. 런타임 CSS는 보상 창 내부로 한정하고, 지연 로드·오류 재시도·닫기 시 정리를 유지한다.
- 기본 100억 코인과 선택 보상, 기존 코어 피그 코인을 하나의 서버 거래로 정산한다. 주간 마지막 1회를 동시에 요청해도 한 번만 지급한다. 선택 보상만 별도로 3회 더 받을 수 없다.

## 일회 초기화

- 대상은 KST 2026-09-21 00:00부터 2026-09-28 00:00 전까지의 주차다. 작업 키는 `ops:core-raid-weekly-reset:20260925:v1`이다. `scripts/ops/core-raid-weekly-reset-20260925.mjs`를 별도 인증된 운영 세션에서 한 번 실행하며 게임 API·배포·로그인에서 자동 실행하지 않는다.
- 사용자 행을 순서대로 잠근 다음 같은 트랜잭션에서 이번 주 완료 영수증에 초기화 표식을 남기고 주간 카운터를 0으로 바꾼다. 서버의 영수증 재계산도 표식을 반영하므로 과거 수령 횟수가 다시 복구되지 않는다. 초기화 당시 계정 전체가 0/3에서 다시 시작한다.
- 기존 지급 영수증의 완료 상태·금액·시간과 클리어 기록, 잔액·인벤토리는 보존한다. 이미 지급된 공대는 다시 열어도 결과만 보여준다. 새 클리어 보상부터 최대 3회 받을 수 있다. 해당 코어 영수증에 연결된 피그 코인도 과거 원장은 보존하면서 이번 주 한도 집계에서만 제외한다. 다른 콘텐츠 한도는 변경하지 않는다.
- 변경 전 영수증·카운터를 `admin_logs`에 보관하고 완료 표식을 `app_meta`에 남긴다. 동일 작업 재시도는 완료 결과만 반환하므로 초기화 뒤 새로 획득한 횟수를 다시 지우지 않는다. 현재 주차 불일치·원자성 검증 실패 시 롤백한다.
- CMS 3문서(코어 설정·선택 보상·피그 코인 정책)를 읽기 잠금으로 보호하고 전후 해시를 비교한다. 보상 설정 자체는 쓰지 않는다.
