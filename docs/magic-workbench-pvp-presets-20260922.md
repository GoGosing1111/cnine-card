# 마법카드 UI · PVP 마법 프리셋 개편

2026-09-22 사용자 요청 범위. 기존 네이비·라임 공통 게임 셸을 유지하면서 마법카드의 탐색, 편성, 강화, 소환을 개편한다. 크라이베른 준비 작업과 무관하며 해당 미출시 용병을 포함하지 않는다.

## 사용자 기능

- 첫 화면은 보유 카드. 이름·효과 검색, 공격/생존/제어 유형, 보유/전체 도감/강화 가능 필터를 제공한다.
- PVE와 PVP 프리셋 1·2·3 각각 마법 슬롯 5개를 편집한다. 슬롯 번호는 일반 카드 편성 순서다.
- 카드 상세에서 효과 설명, 발동률, 강화 단계, 보유/재료 수량, 강화 비용과 성공 확률을 확인한다.
- PC는 목록과 상세를 나란히, 모바일은 목록 중심 + 상단 메뉴에 가리지 않는 상세 대화상자로 제공한다.
- 변경은 초안이며 저장 후 적용된다. 되돌리기, 미저장 이동 확인, 저장 실패 시 초안 보존을 지원한다.
- 소환 탭에 현재 서버 설정 기준 보상 종류별 비중과 1회·10회 비용을 표시한다. 기존 강화/소환 API, 영수증, 확률과 재화 정책을 그대로 사용한다.
- 랭크전 덱 화면에서 일반 카드 5장과 마법카드 5슬롯을 한 번에 저장·적용한다. 용병은 기존 별도 슬롯을 유지한다.
- 프리셋 1은 방어용이며 공격에도 선택 가능하다. 프리셋 2·3을 공격에 적용해도 방어 카드와 방어 마법은 1번을 유지한다.
- 마법카드 화면에서 비활성 PVP 프리셋의 마법만 저장해도 현재 공격 프리셋을 임의로 바꾸지 않는다. 공격 전환은 랭크전의 저장 및 적용을 사용한다.

## 저장과 호환성

신규 테이블 `pvp_magic_presets(user_id,preset_no,magic_card_ids,updated_at)`만 추가한다. 키는 사용자 ID + 프리셋 번호이며 빈 슬롯은 0인 길이 5의 JSON 배열이다. 기존 테이블/장착값을 삭제하거나 덮어쓰는 일괄 이관은 없다.

새 프리셋 데이터가 없는 기존 계정은 이전 공통 PVP 마법 편성을 세 프리셋의 초기값으로 읽는다. 첫 명시적 저장 트랜잭션에서 나머지 두 초기값도 함께 보존한 후 선택한 프리셋만 갱신한다. 구버전 클라이언트가 magicCardIds를 보내지 않으면 해당 프리셋 저장값을 보존한다.

- `GET magic/status`: `pvp.magicPresets`, `pvp.activePreset` 추가.
- `GET pvp/config`: `magicPresets` 추가.
- `POST magic/loadout`: `deckType`, `presetNo`, `magicCardIds[5]`. PVP는 해당 프리셋만 갱신.
- `POST pvp/deck`: 기존 `cardIds[5]`, `presetNo`에 `magicCardIds[5]` 추가. 일반 덱·활성 프리셋·방어 덱(1번일 때)·마법 편성을 하나의 DB batch로 저장.
- 기존 `magic/equip` 단일 슬롯 API는 활성 PVP 프리셋과 호환되도록 유지.
- 활성 PVP 프리셋은 기존 `magic_card_loadouts`에도 원자적으로 반영하므로 영토전 등 기존 소비자의 계약을 유지한다. 랭크전 방어에만 명시적으로 프리셋 1을 읽는다.
- 중복 ID, 미보유, 비활성, 모드 불일치, 잘못된 길이·슬롯·프리셋을 서버에서 차단. 수량 0인 마법은 전투에서 적용하지 않는다.

Neon 호환 어댑터는 일반 SQLite CREATE 문을 건너뛰므로 고정 PostgreSQL DDL을 `execSchema`로 실행한다. 트랜잭션 advisory lock으로 최초 생성 경쟁을 막고 독립 app_meta 완료 마커 및 DB 범위 완료값 캐시를 사용한다. 다른 요청의 Promise/연결을 공유하지 않는다. 계정, 비밀번호, Hyperdrive 설정은 변경하지 않는다.

## 검수

- `npm run test:magic-workbench`: SQLite, PostgreSQL(PGlite + 실제 호환 어댑터), 운영용 파이프라인 batch, 실패 롤백, 기존 초기값, 슬롯 순서/공격·방어 분리, 구버전 요청, 인증, 강화/소환 영수증 중복 방지, UI 계약.
- 실제 PostgreSQL CHECK 오류를 batch 중간에 발생시켜 앞선 일반 덱/활성 선택 쓰기가 되돌아가는지 확인했다. 외부 운영 DB에서 쓰기 실험을 한 것은 아니다.
- `tests/navigation-contract-v1.mjs`: 미저장 변경으로 이동 취소 시 새 화면으로 표시되지 않는 계약.
- `scripts/qa-magic-workbench.mjs`: 실제 index/app/공통 셸 + 로컬 전용 계정 API. 1440×1000, 390×844, 320×844.
- 검색/빈 결과/미보유/최대 강화/모드 제한, 실제 강화, 저장 실패 후 재시도, 프리셋 단독·통합 저장, 새로고침 후 복원, 이동 취소, 상세 닫기/Escape, 1회·10회 소환, 가로 넘침을 검수했다. 브라우저 pageerror 0.
- 스크린샷/로컬 SQLite 검수 자료는 배포 경로 밖 `../qa/magic-workbench/`에 둔다.
- 신규 검사 항목은 `release:gate`에 편입한다. 운영 반영은 최신 main 기준 깨끗한 커밋에서 전체 gate 통과 후 `npm run deploy:production`만 사용한다.

## 운영 확인과 롤백

배포 뒤 운영 index의 새 CSS/JS 및 캐시 쿼리, 공개 리소스 HTTP 응답, API 인증 응답을 확인한다. 운영 계정의 덱·재화·소환을 임의로 조작해 검수하지 않는다.

문제 시 이 범위 커밋을 되돌린 후 같은 release gate / production 절차를 따른다. 신규 DB 테이블과 완료 마커는 삭제하지 않는다. 기존 클라이언트는 마지막 활성 프리셋으로 동기화된 기존 PVP 장착값을 읽을 수 있다. 단, 이전 버전으로 되돌리면 프리셋별 편집 및 방어 1번 분리 동작은 제공되지 않는다.

## 공지용 요약

마법카드 화면을 보유 카드 중심으로 개편했습니다. 검색과 필터로 필요한 카드를 빠르게 찾고, 카드 상세에서 효과·발동률·강화 재료와 비용을 확인할 수 있습니다. 편성·강화와 소환 화면을 나눠 모바일에서도 선택과 조작이 편리하도록 개선했습니다.

이제 PVP 프리셋 1~3에 일반 덱뿐 아니라 마법카드까지 함께 저장할 수 있습니다. 프리셋을 불러오면 마법카드도 같이 불러오며, 저장 및 적용 시 해당 편성이 반영됩니다. 방어전은 1번 프리셋을 사용하고, 공격에 2·3번을 선택해도 방어 편성은 유지됩니다.

기존에 장착한 마법카드는 초기값으로 보존됩니다. 강화·소환 비용과 확률, 보유 카드 및 재화는 이번 UI 개편으로 변경되지 않습니다.
