# 핑두의 소원램프 · 소원권 쿠폰

2026-09-10 사용자 요청: 소원램프 소원권을 CMS 쿠폰 생성으로 지급한다.

## 운영 경로

- CMS → 쿠폰관리 → 새 영구 쿠폰 발급 → 보상 종류 **핑두의 소원권 · 소원램프**.
- 쿠폰 코드, 1인 지급 수량, 전체 사용 한도를 운영자가 정한다. 같은 쿠폰은 계정당 1회다.
- CMS 설정의 핑두의 소원램프 패널에 **소원권 쿠폰 만들기** 바로가기를 제공한다. 이 버튼은 생성 화면만 열며 실제 쿠폰을 발급하지 않는다.
- 소원권 선택 기본 수량은 1개이고, 다른 아이템 쿠폰과 동일한 안전 상한 100,000개를 적용한다. 발급 시 자동 지급하지 않고 유저가 쿠폰을 등록해야 적립한다.
- 유저는 출석체크의 쿠폰 코드 입력에서 등록한다. `PINGDU_WISH_TICKET` 인벤토리에 즉시 적립되고, 소원램프 보유량과 동일한 재고를 사용한다.
- 기존 유저관리 개별 지급 기능은 유지한다. 발급 목록의 두 렌더러 모두 소원권 이름과 지급 수량을 표시한다.
- 쿠폰은 삭제·비활성화 전까지 영구 유효하다. 이벤트 운영 기간·비용·확률·공개 및 활성화 설정은 변경하지 않는다. 행사 종료 뒤에는 운영자가 필요에 따라 쿠폰도 비활성화한다.
- `SLD-`는 기존 숲켓랜드 쿠폰 전용 접두어이므로 소원권 쿠폰에 사용하지 못하도록 발급 단계에서 안내한다.

## 지급 보장

- 기존 일반 보상·인증 메시지의 허용 종류나 한도를 확대하지 않는다. 소원권은 쿠폰 전용 타입으로 추가한다.
- 최초 쿠폰 생성 시 소원권 카탈로그를 준비한다. 소원램프 설정을 먼저 열 필요가 없다.
- 운영 Hyperdrive/PostgreSQL 연결과 기존 요청 큐를 재사용한다. 유저·쿠폰 행 잠금 아래 인벤토리 적립, 사용 횟수, 로그, 1인 사용 기록을 한 거래로 저장한다.
- 마지막 사용 한도 경쟁, 같은 요청 재전송, 계정당 중복 사용, 비활성 아이템·쿠폰과 실제 지급 행수 0을 검사한다. 중간 실패 시 쿠폰과 재고 모두 롤백한다.
- 코인 지급·차감, 이벤트 개봉, 다른 보상 지급은 쿠폰 등록에서 수행하지 않는다.

## 검증

- `npm run test:coupon`: 기존 한도 및 실제 신규·호환 CMS 생성 라우트, 소원권 적립, 이벤트 보유량 연결, 재시도·중복·한도, 원자적 롤백, 바로가기, 목록 렌더링 검증.
- `npm run test:wish-lamp`: 기존 소원램프 기간·확률·보상 지급 검증 유지.
- 운영 배포 전 전체 `npm run release:gate`를 통과하고 `npm run deploy:production`만 사용한다.
- 운영 테스트 쿠폰이나 사용자 보상은 임의로 생성하지 않는다.
