# 클랜전 참여형 규칙 V2040

## 점수와 참여

- 공격 승리: 공격한 클랜 +3점. 공격 패배: 공격한 클랜 +1점.
- 해당 공격으로 상대 클랜에는 점수가 생기지 않으며 기존 점수도 차감하지 않는다.
- 방어 성공은 공격자의 획득 점수를 3점에서 1점으로 줄이는 역할이다. 방어 승패 기록은 보존한다.
- 공유 방어 횟수 상한만 해제한다. 개인 행동력, 개인 총 상한(현재 21회), 동일 상대 상한(현재 1회), 서버 무작위 매칭, 최신 랭크전 덱 5장은 유지한다.
- 참여·획득 점수는 도입 이후 실제 완료된 공격만 집계한다. 과거 점수와 시즌 전적을 환산하거나 삭제하지 않는다.

## 경제 설정과 출시

CMS `참여형 점수 · 매 전투 보상` 영역에서 별도로 설정한다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| participationEnabled | false | 참여형 점수·공유 방어 상한 해제 |
| participationEffectiveAt | 빈 값 | ON 저장 시 서버가 다음 대진부터 자동 지정. 클라이언트 백데이트 불가 |
| battleParticipationRewardsEnabled | false | 실제 전투 코인 지급 토글 |
| battleParticipationCoin | 0 | 매 완료 공격 기본 코인, 승패·전투력·피해량 무관 |
| battleWinBonusPercent | 20 | 승리 추가 코인 비율, 소수점 내림 |
| participationMilestoneCoin | 0 | 라운드에서 다섯 번째 완료 공격에 한 번 지급 |

기본 코인과 5회 보너스의 금액은 사용자 확정 전까지 0/OFF로 둔다. 참여형 점수는 별도로 켤 수 있다. 5회 이후에도 개인 상한까지 기본 보상이 지급된다. 경제 ON은 공개 ON, 참여형 ON, 기본 코인 1 이상일 때만 허용한다. TEST/OFF에서는 지급하지 않는다.

기존 시즌 종료 기본·우승·준우승 보상 설정은 수정하지 않는다. 2026-09-05 사전 감사에서 확인된 기존 금액은 기본 5,000,000, 우승 추가 2,500,000,000, 준우승 추가 1,000,000,000 코인이다.

## 라운드 경계

`clan_participation_round_rules`가 시즌·라운드별 규칙을 고정한다. 같은 회차의 네 대진에 동일한 점수·행동력·매칭 상한·경제 설정을 적용한다. 시작 전 미리보기는 설정 변경이 가능하다. 시작된 라운드는 첫 조회 또는 설정 저장 전에 기존 규칙을 고정한다. 이후 CMS 변경은 다음 라운드부터 반영한다. 공개 OFF/TEST의 경제 차단은 즉시 적용된다.

진행 중 라운드를 소급 변경하지 않는다. 이번 시즌 1라운드 결과는 보존하고 아직 시작하지 않은 다음 라운드부터 적용한다.

## 정산 안전성

- 전투 요청 ID UNIQUE 및 전투 ID PK 영수증으로 정확히 한 번만 점수·코인·참여 횟수·전적을 정산한다.
- PostgreSQL은 대진 → 전투 → 참가자(유저 ID 순) → 지갑 행을 잠근 뒤 한 트랜잭션에서 처리한다. SQLite/D1은 원자 배치를 사용한다.
- 실제 RESOLVING 예약, ACTIVE 대진, 양쪽 소속과 공격자 지갑이 모두 존재할 때만 영수증을 생성한다. 이후 모든 쓰기는 이번 처리 토큰의 PENDING 영수증을 조건으로 한다.
- 중간 오류는 모두 롤백한다. 판정 누락을 패배로 간주하지 않는다. FAILED 전투는 공격 횟수에서 제외한다.
- 다섯 번째 공격의 보너스는 누적 행을 잠근 트랜잭션에서 한 번만 선택한다.
- 응답 유실 시 같은 요청 키로 결과를 복구한다. 클라이언트는 계정·대진별 키를 세션 저장소에 유지하며 서버 확정 완료/실패 후에만 해제한다. 복구 응답은 재전투 연출 없이 점수·코인 결과와 현재 지갑을 표시한다.
- 경제 영수증은 전투 상세 보존기간과 독립 보관한다. 코인 지급 완료 시즌의 리셋을 차단하며 새 경제 영수증은 초기화에서 삭제하지 않는다.

## 검증

`npm run test:clan`은 기존 28개 및 신규 18개 테스트를 실행한다. 연패 득점, A/B팀 가산, 승리 보너스, 5·6회 경합, 동일 요청, 다른 계정 요청, 실패 롤백, 0행 조건, 개인/동일 상대 상한, 라운드 고정, CMS 입력과 클라이언트 복구를 확인한다.

별도 PostgreSQL 검증은 Hyperdrive 연결의 단일 외부 트랜잭션 안에서 모든 게임 테이블을 `TEMP`로 만들고 실제 PostgreSQL 어댑터로 정산 SQL을 실행했다. 각 배치는 SAVEPOINT로 격리했고 전체 검증 종료 시 ROLLBACK했다. 운영 유저·점수·지갑 데이터는 수정하지 않았다. 로컬 합성 화면에서 참여 패널, 로스터 상세 및 CMS 입력·콘솔 오류도 확인했다.
