## 원인과 변경

- 첫 입장에서 역할을 배정하는 HMAC 키를 `cacheRuntimeData`에 전달했다. 이 캐시는 `structuredClone`을 사용하는데 Cloudflare Workers는 `CryptoKey` 직렬화를 지원하지 않아 `DataCloneError: Could not serialize object of type "CryptoKey"`가 발생한다.
- 기존 Node/PGlite 검사는 Node가 CryptoKey 복제를 지원하기 때문에 통과했다. 운영 호환일 2026-07-01의 workerd에서 해당 오류를 직접 재현했다. 화면/일반 조회는 역할 키를 만들기 전이라 보이고, 첫 입장은 영수증 저장 전에 503으로 실패했다.
- 족각도시만 비밀 시드 문자열을 캐시하고 각 호출에서 키를 import하도록 수정했다. 저장 시드와 HMAC 입력은 그대로여서 역할을 다시 뽑거나 공개하지 않는다. 공유 캐시·인증·DB 기반·스키마는 변경하지 않는다.
- 미확정 요청을 삭제하거나 성공으로 꾸미지 않는다. 기존 같은 요청 번호 재시도가 정상 입장 영수증을 확정하며, 반복 확인에는 동일 영수증을 돌려준다. 추가 현금 지급은 없다.
- 서버 오류 로그에 오류 이름을 추가한다. 비밀 시드·키·요청 인증정보는 기록하지 않는다.
