# 붕괴 코어 결과 복귀 · 주간 보상 3회

2026-09-14 사용자 지시: 실패 결과는 한 번 확인한 뒤 대기실로 돌아가며, 보상 수령은 계정당 주 3회로 제한한다.

## 결과 복귀

- 기존의 `browse=1`은 최초 이동에만 붙었고, 5초 뒤 자동 조회가 최근 실패 공대를 다시 선택했다.
- `raid/core/acknowledge`는 인증된 본인의 종료 공대에만 `RESULT_SEEN`을 기록한다. 기본 조회는 확인한 마지막 결과를 다시 선택하지 않으며, 더 오래된 실패 공대로 거슬러 올라가지 않는다. 다른 공대원의 확인 상태·기여도·보상은 보존한다.
- 클라이언트는 대기실 조회 상태를 유지하고, 생성·참가 성공 시 해당 공대로 전환한다. 이동 전에 시작된 조회의 늦은 응답·오류는 새 화면을 덮어쓰지 않는다. 처리 중에는 자동 조회를 멈춘다.

## 주간 보상

- 계정당 **보상 지급 완료 3회**, **매주 월요일 00:00 한국 시간 초기화**. 실패·미수령·잠긴 테스트 보상·지급 실패·완료 요청 재전송은 횟수에 포함하지 않는다.
- 보상 소진 후에도 공대 생성·참가·공략이 가능하다. 대기실과 결과 화면에 수령 횟수, 남은 횟수, 초기화 기준을 표시한다.
- 기존 이번 주 `COMPLETED` 보상 영수증도 합산한다. 신규 영수증은 `rewardWeekKey`를 보존하고, 재조회·프로필 갱신이 지급 주차를 바꾸지 않는다.
- `raid_core_weekly_rewards_v2112`는 계정·주차별 누적 횟수와 마지막 지급 요청을 저장한다. PostgreSQL 계정/영수증 행 잠금 및 조건부 upsert로 서로 다른 공대의 동시 요청을 직렬화한다. 주간 횟수·코인·조각·로그·완료 영수증을 하나의 DB 트랜잭션으로 반영한다.
- 커밋 응답이 유실되면 완료 영수증을 확인한다. 미완료 정산은 재시도 가능 상태로 남기며 재지급하지 않는다. 정산 및 재조회 응답 모두 현재 계정 재화를 반환한다.
- 기존 보상 금액·입장권·전투력·TEST/ON 및 보상 잠금 설정은 변경하지 않는다. 운영 DB의 저장 설정을 그대로 따른다.

## 검증

- `tests/core-raid-weekly-return-v2112.test.mjs`: SQLite 및 실제 PostgreSQL 엔진(PGlite)과 운영 D1 호환 어댑터로 결과 확인, 주차 경계, 3회 제한, 계정 분리, 기존 지급 이력, 동시 마지막 보상, 지급 중 예외/롤백, 커밋 응답 유실, 재시도를 검증한다. `npm run test:core-raid` 및 운영 출시 게이트에 포함한다.
- 운영 HTML·CSS·JS를 읽는 브라우저 검수: 1440×1000, 1024×768, 768×1024, 390×844, 320×740, 740×420. 실패 복귀, 실제 5초 자동 조회, 이전 응답 도착, 주간 현황, 수령 완료, 상한 이후 재참가와 버튼 잘림을 확인한다. 태블릿의 공대 목록 최소 너비 초과도 수정했다.
- 검수 도구와 화면 기록은 배포 디렉터리 밖 `../qa/core-raid-weekly-v2112/`에 저장한다. 운영 코어 JS/CSS의 개별 캐시 키에 `weekly=2112`를 추가한다.

## 배포·복구

범위 커밋을 main에 반영한 깨끗한 후보에서 `npm run deploy:production`을 사용한다. 이 명령의 `release:gate`를 우회하지 않는다. 문제가 있으면 이전 검증 커밋으로 같은 게이트를 거쳐 복구한다. 추가 주간 테이블과 영수증은 삭제하지 않는다. 기능 플래그와 계정 재화의 수동 변경은 없다.
