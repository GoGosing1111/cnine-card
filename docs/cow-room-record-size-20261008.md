# 카우방 전투 기록 크기 오류 — 2026-10-08

사용자 첨부의 `전투 기록이 너무 큽니다.`는 `_expedition_v3_runs.js`의 750,000바이트 JSON 저장 제한에서 발생했다. 개편 난도·배틀슈트·스킬칩·용병으로 전투 이벤트가 많아지면 정상 전투도 한도를 초과했다. 체크포인트 인코딩은 입장 거래 전에 실행되므로 이 단계에서 실패한 요청은 포탈·입장 코인·횟수를 소비하지 않는다. 클라이언트에는 복구용 요청 번호가 남아 `전투 결과 다시 확인`으로 같은 요청을 이어갈 수 있다.

## 수정

- `_expedition_v3_record.js`에서 512KB 초과 기록을 gzip으로 무손실 압축하고 `EXPEDITION_GZIP_V1` 형식으로 저장한다. 저장 상한 750KB를 유지하며 해제 원문은 최대 8MiB로 제한한다. 선언한 길이와 실제 해제 길이·UTF-8·JSON을 검사한다.
- 카우방 체크포인트·완료 결과의 모든 저장/조회/재시도 경로가 같은 인코더·디코더를 사용한다. 작은 기록은 기존 JSON 그대로 저장하며 기존 영수증은 변환 없이 읽는다.
- HTTP 응답과 전투 타임라인은 그대로다. 이벤트 삭제·전투 재판정·피해/보상/입장 정책 변경이 없다. UI·공통 전투 엔진·DB 스키마·권한 체계를 변경하지 않았다.
- 입장·정산은 기존 원자적 거래와 요청 번호를 유지한다. 정산 실패 후에는 저장된 전투로 재개하며 변경된 덱·난도 정책이나 새 난수를 적용하지 않는다.
