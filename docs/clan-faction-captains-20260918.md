# 대전 바로가기 · 세력전 행동대장

## 확정된 동작

- 사이드 콘텐츠의 **대전 · PVP**에 **클랜전**, **세력전** 바로가기를 추가한다. 각각 기존 정규 클랜전 탭과 서울 세력전 탭으로 바로 진입한다. PC·모바일 공통 메뉴와 직접 링크를 함께 지원한다.
- 클랜장은 제1·제2 공격대에 **행동대장 1명씩, 최대 2명**을 임명·해제한다. 한 사람이 두 자리를 겸임할 수 없다. 현재 클랜원만 지정하며 최초에는 미지정이다.
- 사용자의 후속 `방어던 공격이던` 지시를 반영해, **어느 행동대장이든 공격대 2개와 방어대 2개의 전체 라인업을 편성**한다. 직책을 맡은 공격대에 본인을 배치할 의무는 없다.
- 직책 임명·해제와 지역 주둔 방어대 지정은 기존 클랜장 권한이다. 행동대장에게 추가되는 권한은 전체 부대 라인업 편성이다.
- **출정 권한은 기존 그대로**다. 해당 공격대의 모든 대원과 클랜장이 출정할 수 있으며 행동대장 전용 출정 조건을 추가하지 않는다. 실제 편성원이 직접 입장·교전한다.
- 부대당 최대 5명, 한 사람 한 부대, 교전 중 라인업 변경 금지는 유지한다. 편성자 간 동시 수정은 편집 시작 시점의 라인업과 비교해 오래된 저장을 거절한다.

## 저장과 검증

- 기존 시즌 JSON에 `captains[clanId] = {attack1, attack2}`를 저장한다. 역할 키가 없는 기존 시즌은 미지정으로 읽는다. DB 마이그레이션과 일괄 임명은 없다.
- `POST clan/faction/captains`는 클랜장만 호출할 수 있다. `formation`은 클랜장 또는 현재 행동대장만 호출한다. 행동대장의 `captains` 동시 변경 요청은 거절한다.
- 현재 소속과 역할, 시즌, 교전 상태를 서버에서 확인한다. 기존 revision 비교와 원자적 영수증 저장을 사용해 권한 해제·이적·클랜장 변경 중 발생한 요청도 다시 검증한다.
- 클라이언트는 편집 시작 당시 `baseFormation`을 보낸다. 충돌 후 새로고침하면 서버 최신 라인업을 다시 편집한다. 전황 기록에 편성자와 행동대장 변경을 표시한다.
- `js/clan-v1.js`와 `js/app.js`가 같은 버전의 세력전 모듈을 불러오며, 변경된 메뉴·스타일·스크립트 URL 및 서비스 워커의 최신 자산 조회 목록을 갱신한다.

## 검수

- `tests/clan-faction-captains.test.mjs`: SQLite·PostgreSQL 각각 임명·해제, 타 클랜/중복 직책 거절, 공격·방어 전체 편성, 역할 주입 차단, 전투 중 잠금, 일반 대원 출정·교전, 역할·소속·클랜장 변경 경합, 동시 편성 충돌, 트랜잭션 롤백, 동일 요청 재처리 검증.
- `tests/navigation-contract-v1.mjs`: 기존 메뉴 계약과 새 바로가기의 실제 클랜 탭 선택 검증.
- `tests/clan-faction-captains.browser.mjs`: 실제 index와 공통 메뉴를 사용해 1440×1000·390×844에서 임명, 편성 이동 저장, 일반 대원의 출정·입장을 검증한다. 320×740 추가 화면 잘림 확인. API 변경은 로컬 합성 DB만 사용한다.
- 범위 커밋과 main 동기화 후 전체 `npm run release:gate`를 포함하는 `npm run deploy:production`으로 운영에 반영한다. 운영 정적 자산과 인증 경계를 추가 확인한다.

## 롤백

해당 변경 커밋을 되돌려 동일 출시 게이트로 배포한다. 저장된 직책 정보는 기존 JSON에 남겨도 이전 런타임에 영향을 주지 않는다. 기존 부대 편성과 전황·징수코인은 보존한다.
