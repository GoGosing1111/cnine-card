# 리미티드 용병팩 준비 · 2026-10-06

요청: 리미티드팩 리소스·연출, 연속 개봉 및 자동 진행, 상점 연결, CMS 가격 설정, **용병별 서버 전체 발행 한도**. 자동 진행은 준비 구간을 반스킵한 기존 공개 연출을 보여준다.

## 출시 상태

- 운영 준비 배포. LIMITED_PACK_RELEASE_ENABLED=false, CMS mode=OFF.
- 가격·발행 한도·재료/꽝 확률 및 수량은 모두 미정으로 시작. 기존 리미티드 확률/가중치 초안 보존.
- 등록된 8종(SS 7종 / SSS 발테르)의 승인 원화·프레임 사용. 이름/코드 미확정 원화는 임의 등록하지 않는다.
- 일반 용병 하이퍼팩, 멤버 카드 리미티드팩(pickup), 일반 합성의 제한을 풀지 않는다.
- 출시 전에 운영자가 경제 설정을 확정하고 별도 출시·전투 연결을 승인해야 한다. 이 배포로 개봉/편성이 자동 활성화되지 않는다.

## 화면과 리소스

- 상점 리미티드 용병팩 → 전용 계약실. 1회/10회 개봉, 1~1,000회 자동 진행, 이전 영수증 복구.
- 자동 진행: 기존 Pixi/GSAP 타임라인의 0.88초 지점부터 봉인 해제·광원·등급·카드 공개를 순서대로 표시. 텍스트 요약으로 자동 결과를 대체하지 않는다.
- 한 영수증의 공개가 끝나야 다음 POST를 보낸다. 화면 옆과 무대 하단에 중지 버튼을 두고, 숨김/닫기/건너뛰기도 다음 결제를 멈춘다.
- 모바일에서 개봉 시작 시 무대 상단으로 복귀. 닫기 헤더 고정, 내부 세로 스크롤, 키보드 포커스·동작 줄이기 지원.
- 기존 승인 팩 PNG와 슬림 V3 프레임 원본 보존. 640px WebP 파생 8종, 팩/프레임/전용 배경 총 11파일, 합계 1,657,352바이트.
- 배경 원본·프롬프트: preview/mercenary-limited-pack-20261006-v1/assets/chamber-source.png 및 prompt-chamber.json.
- 검수 페이지: /preview/mercenary-limited-pack-20261006-v1/ 및 cms.html. 모두 가상 계정/가격이며 운영 API로 지급하지 않는다.

## CMS

관리자 용병 CMS의 리미티드팩 탭. OWNER만 허용.

- 1회·10회 코인 가격 독립 설정. 10회 가격 자동 계산이나 임의 할인 없음.
- SS/SSS 확률, 용병별 등급 내 가중치, 마스터의 별/미스틱 에너지/꽝 확률, 재료 수량.
- 용병별 발행 한도/누적 발행량/잔여량. 발행량 편집/초기화 불가.
- 한도가 발행량보다 작거나 이미 발행한 용병 한도를 미정으로 돌리는 저장 거절.
- 기존 확률 revision과 팩 revision 동시 비교. 동시 OWNER 저장, 감사 로그 실패, 재시도에 대한 원자적 저장.
- 새 용병이 catalog에 추가되면 한도 미정, 기존 정책에 없던 가중치는 0으로 읽는다.

## 추첨 및 거래

- 확률 합계 100%, 선택 등급 잔여 대상 존재, 가격/재료 수량을 모두 확인.
- 개별 용병 소진 시 같은 등급의 잔여 가중치로만 추첨. 해당 등급 전체 소진 시 개봉 중지. 다른 등급/꽝으로 확률을 옮기지 않는다.
- 10회 결과에 필요한 재고가 부족하면 10회 전부 취소. 부분 지급/결제 없음.
- 요청 ID와 가격·확률 revision으로 계획 고정. 발행량 증가, 일련번호, 소유 카드/중복 수량, 코인, 재료, 영수증을 하나의 PostgreSQL 거래로 확정.
- 용병별 재고 행을 코드 순서로 잠그고 조건부 증가. 전 서버 단일 카운터 없음.
- CMS 정책과의 경합도 정책 행 잠금 및 원문 비교로 차단.
- 계정별 기존 Durable Object 잠금 + 클라이언트 Web Locks. 같은 계정의 탭 간 자동 개봉 중복 실행 차단.
- 응답 유실 시 영수증을 확인하고 불확실하면 중지. 복구는 원래 요청 ID/횟수 재사용. 계정 변경/저장 실패 시 새 결제 금지.

## 검수 및 성능

관련 테스트 32개(거래/자동진행/기존 하이퍼 연출) 및 기존 용병·리미티드 회귀 20개 통과. 전체 배포 게이트에도 신규 test:limited-pack 포함.

- 순차 자동 1,000회: 10회 묶음 100번, 최대 동시 POST 1, 각 영수증 공개를 기다림.
- 실제 PostgreSQL: 독립 테스트 스키마에서 8개 연결·64개 동시 요청·마지막 재고 7장. 정확히 7명 지급/57명 무차감, 일련번호 중복 0. 교차 연결 재요청도 추가 지급 없음.
- 운영과 같은 파이프라인 방식: 경합 묶음 3,476ms, P50 2,935ms, P95 3,252ms, 왕복 330회/거래 시도 56회. 노트북→DB 왕복 및 연결별 대기를 포함한 제한된 시험이며 전체 운영 부하 한계 측정은 아니다.
- 비교 중 순차 SQL 전송은 20,631ms였으며 실제 운영 어댑터의 escapeLiteral 파이프라인 보존 시험에서 위 결과 확인. 런타임 어댑터 변경 없음.
- 쿼리는 설정 2종·재고 8행으로 제한. 개봉 중 타이머 폴링이나 프레임별 API 호출 없음. 종료 때만 잔여 수량 갱신.
- Pixi/GSAP 공용 런타임 1개, 계약실당 렌더러 1개. 최대 45FPS/DPR1.5, 입자 수 제한, 결과별 필터·그래픽·타이머 정리, 완성 화면 ticker 정지, 원화 캐시 재사용.
- PC/390px 모바일 실제 UI 및 동작 줄이기, 개봉/자동/영수증 복구/CMS 저장 검수. 상세 결과와 화면: qa/. 브라우저 25개 확인 및 실제 상점 컴포넌트 2개 확인 통과.
- 실제 렌더러 공개 100회(가속 검수): 3,932ms, 마지막 정리 대기 0, 원화 캐시 1개 재사용, 닫기 후 캔버스 0.
