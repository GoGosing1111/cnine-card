# 리미티드 용병팩 준비 · 2026-10-06

요청: 리미티드팩 리소스·연출, 연속 개봉 및 자동 진행, 상점 연결, CMS 가격 설정, **용병별 서버 전체 발행 한도**. 자동 진행은 준비 구간을 반스킵한 기존 공개 연출을 보여준다.

2026-10-06 후속 정정: 일반 용병 C·B·A·S·SS·SSS 전체가 등장하고 SS 리미티드·SSS 리미티드는 별도의 극히 희귀한 확률로 등장한다. 일반 SS/SSS와 한정 SS/SSS의 확률을 혼합하지 않는다. 각각 개봉 1회당 절대 확률로 계산하며 확률 수치는 운영자가 지정한다. 출시 OFF를 유지하는 혼합 풀 준비 배포다.

## 출시 상태

- 운영 준비 배포. LIMITED_PACK_RELEASE_ENABLED=false, CMS mode=OFF.
- 최초 가격·발행 한도·재료/꽝 확률 및 수량은 미정으로 시작했다. 운영자가 이후 저장한 가격·한도·재료 설정과 리미티드 확률/가중치 초안을 보존한다. 새 일반 6등급 확률만 미정으로 읽으며 GET으로 DB 값을 수정하지 않는다.
- 등록된 8종(SS 7종 / SSS 발테르)의 승인 원화·프레임 사용. 이름/코드 미확정 원화는 임의 등록하지 않는다.
- 일반 용병 하이퍼팩, 멤버 카드 리미티드팩(pickup), 일반 합성의 제한을 풀지 않는다.
- 출시 전에 운영자가 경제 설정을 확정하고 별도 출시·전투 연결을 승인해야 한다. 이 배포로 개봉/편성이 자동 활성화되지 않는다.

## 화면과 리소스

- 상점 리미티드 용병팩 → 전용 계약실. 1회/10회 개봉, 1~1,000회 자동 진행, 이전 영수증 복구.
- 자동 진행: 기존 Pixi/GSAP 타임라인의 0.88초 지점부터 봉인 해제·광원·등급·카드 공개를 순서대로 표시. 텍스트 요약으로 자동 결과를 대체하지 않는다.
- 한 영수증의 공개가 끝나야 다음 POST를 보낸다. 화면 옆과 무대 하단에 중지 버튼을 두고, 숨김/닫기/건너뛰기도 다음 결제를 멈춘다.
- 모바일에서 개봉 시작 시 무대 상단으로 복귀. 닫기 헤더 고정, 내부 세로 스크롤, 키보드 포커스·동작 줄이기 지원.
- 기존 승인 팩 PNG와 슬림 V3 프레임 원본 보존. 640px WebP 파생 8종, 팩/프레임/전용 배경 총 11파일, 합계 1,657,352바이트.
- 배경 원본·프롬프트: preview/mercenary-limited-pack-20261006-v1/assets/chamber-source.png 및 prompt-chamber.json.
- 검수 페이지: /preview/mercenary-limited-pack-20261006-v1/ 및 cms.html. 모두 가상 계정/가격이며 운영 API로 지급하지 않는다.

## CMS

관리자 용병 CMS의 리미티드팩 탭. OWNER만 허용.

- 1회·10회 코인 가격 독립 설정. 10회 가격 자동 계산이나 임의 할인 없음.
- 일반 C/B/A/S/SS/SSS 확률과 SS 리미티드·SSS 리미티드 확률 입력 영역 분리. 0.0001% 단위 입력 및 저장/공개 표시에서 정밀도 보존. 일반 6등급 + 한정 2등급 + 마스터의 별/미스틱 에너지/꽝의 합계 100%.
- 일반 용병의 등급·획득 ON·등급 내 가중치는 기존 용병 CMS를 조회한다. 하이퍼팩의 등급 확률을 변경하거나 복사하지 않는다. 리미티드의 등급 내 가중치·발행 한도는 전용 설정을 사용한다.
- 용병별 발행 한도/누적 발행량/잔여량. 발행량 편집/초기화 불가.
- 한도가 발행량보다 작거나 이미 발행한 용병 한도를 미정으로 돌리는 저장 거절.
- 기존 확률 revision과 팩 revision 동시 비교. 동시 OWNER 저장, 감사 로그 실패, 재시도에 대한 원자적 저장.
- 새 용병이 catalog에 추가되면 한도 미정, 기존 정책에 없던 가중치는 0으로 읽는다.

## 추첨 및 거래

- 확률 합계 100%, 선택한 일반 등급의 획득 대상 및 리미티드 등급의 잔여 대상, 가격/재료 수량을 모두 확인.
- 일반 SS/SSS와 SS/SSS 리미티드는 단일 1,000,000구간 추첨의 서로 다른 범위를 사용한다. 일반 등급 확률을 곱하거나 리미티드 두 등급을 먼저 합쳐 정규화하지 않는다.
- 일반 용병은 기존 카드 지급 원장·중복 수량 처리를 재사용하며 발행 한도나 일련번호를 생성하지 않는다. 혼합 10회 결과도 코인·일반 카드·리미티드 재고/일련번호·재료·영수증을 하나의 거래로 처리한다.
- 개별 리미티드 소진 시 같은 한정 등급의 잔여 가중치로만 추첨. 해당 한정 등급 전체 소진 시 개봉 중지. 일반 등급이나 꽝으로 확률을 옮기지 않는다.
- 10회 결과에 필요한 재고가 부족하면 10회 전부 취소. 부분 지급/결제 없음.
- 요청 ID와 가격·확률 revision으로 계획 고정. 발행량 증가, 일련번호, 소유 카드/중복 수량, 코인, 재료, 영수증을 하나의 PostgreSQL 거래로 확정.
- 용병별 재고 행을 코드 순서로 잠그고 조건부 증가. 전 서버 단일 카운터 없음.
- CMS 정책과의 경합도 정책 행 잠금 및 원문 비교로 차단.
- 계정별 기존 Durable Object 잠금 + 클라이언트 Web Locks. 같은 계정의 탭 간 자동 개봉 중복 실행 차단.
- 응답 유실 시 영수증을 확인하고 불확실하면 중지. 복구는 원래 요청 ID/횟수 재사용. 계정 변경/저장 실패 시 새 결제 금지. 확인 팝업 당시 가격 버전을 고정하여 늦은 설정 갱신이 승인 금액을 바꿀 수 없고, 설정 조회 장애 중에도 확정 영수증을 공개한다.

## 배포·복구

최초 재고 테이블 준비는 전체 배포 게이트를 적용했다. 후속 혼합 풀 변경은 기존 테이블과 거래 기반을 재사용하며 스키마·인증·세션을 바꾸지 않는다. 혼합 확률/지급, 기존 리미티드 거래/자동 진행, 공용 개봉 렌더러의 관련 검사와 Worker 검사 후 `npm run deploy:production -- --scoped`로 반영한다. 별도 변경/검수/운영 보존 기록은 `mercenary-limited-mixed-pool-20261006.json`이다.

배포 검사의 과거 고정 버전명(2108) 검사는 캐시 버전 존재 및 앱·서비스워커 버전 일치로 교정했다. 첫 전체 검사 후보 26fb1d80의 완료 단계는 로그 SHA-256으로 보존하며 실패 단계부터 남은 모든 검사를 재개한다. 후속 계약실의 가격 확인·영수증 복구 보완만 전용 브라우저 검사 4건과 소스 해시로 묶어 재개를 허용한다. 공용 세션·추첨 정책·서버·렌더러 변경은 이 예외에 포함하지 않는다. 브라우저 보완 결과는 최종 qa/production.json에 함께 보존한다.

2dc832c6의 후속 전체 검사에서는 변경 없는 전투 어댑터의 옛 playEvents 직접 호출 검사가 발견되어 실제 playEventsChecked 위임과 원래 재생 호출을 함께 검사하도록 수정했다. 원본·후속 로그를 각각 해시로 검증하며 연속된 완료 단계만 이어서 인정한다. 후속 후보 이후 실행 코드 변경은 이 재개 경로에서 허용하지 않는다.

되돌릴 때도 발행 카운터나 지급 영수증을 삭제하지 않는다. 개봉은 서버 게이트를 OFF로 차단하며 확정 영수증 조회는 계속 제공한다.
