# 블랙미라클 신규 보상 수동 편입 — 2026-09-09

사용자 지시: 갓삼족삼의 엠퍼러 레깅스를 미스틱 레깅스로 교환하고, 운영자가 추가하지 않은 새 신화장비가 블랙미라클에 자동 편입되지 않게 한다.

## 운영 교환 및 기존 보상 보존

- 기존 인증된 Hyperdrive 운영 도구에서 실제 PostgreSQL 계정·장비·소유권을 먼저 읽기 전용으로 조회했다.
- 갓삼족삼의 블랙미라클 출처 엠퍼러 레깅스 1개를 미스틱 레깅스 1개로 원자적으로 교환했다. 같은 장비 인스턴스에 새 품목을 연결해 장착 및 획득 시각을 보존하고, 원래 출처와 변경 결과는 관리자 감사 로그에 남겼다.
- 운영 보상 목록은 당시 선택 대상인 장비 22종·이동수단 16종과 기존 개별 확률을 그대로 수동 목록에 고정했다. 명시적으로 제외된 엠퍼러 4종은 제외 상태를 유지했다. 팩 개봉 스위치, 콘텐츠 드롭 확률, 코인·별 보상 설정은 보존했다.
- 구현은 `scripts/ops/black-miracle-manual-pool-20260909.mjs`의 일회성 운영 함수다. 게임 런타임 및 자동 마이그레이션에는 연결하지 않는다.
- 영수증 키는 `ops_black_miracle_manual_pool_20260909_v1`이다. 동일 작업 재실행은 교환·지급·감사 로그를 중복 생성하지 않으며, 이후 운영자가 바꾼 설정을 초기화하지 않는다.
- 운영 결과: 2026-09-09 21:25 KST 완료, 21:30 KST 독립 읽기 전용 재조회에서 엠퍼러 레깅스 0개·미스틱 레깅스 1개·장착 유지 및 보상 목록 보존을 확인했다. 계정별 원본 영수증과 인증 정보는 공개 사이트에 포함하지 않는다.

## 서버 및 CMS 규칙

- `cleanPowerGroup`은 항상 직접 선택 모드를 사용한다. AUTO/HYBRID를 보내는 구형 CMS에도 같은 규칙을 적용한다.
- `buildBlackMiraclePowerPool`은 명시적인 `enabled:true` 항목만 추린 뒤 전투력 범위와 확률을 계산한다. 신화 등급·공개·활성화 또는 개별 확률 입력만으로 자동 승인하지 않는다.
- CMS에는 새 카탈로그 항목이 미체크 상태로 나타난다. 운영자가 체크하고 저장하면 포함되며, 개별 확률을 비워도 체크한 사실은 저장된다.
- LEGACY 카테고리 추첨에도 선택 목록을 적용한다. 후보가 없으면 기존 대체 별 보상 규칙을 사용한다.
- CMS 본체와 중첩 블랙미라클 모듈의 캐시 버전을 함께 갱신한다.

## 검증

- `npm run test:black-miracle`: 16개 통과. PostgreSQL 교환·재실행·0행 롤백, 대상 변경 차단, 기존 목록/확률 보존, 신규 항목 차단, AUTO/HYBRID/LEGACY 우회 차단, 실제 개봉 및 CMS 저장 계약을 확인한다.
- 이 검증 묶음을 `npm run release:gate`에 추가했다. 기존 테스트의 오래된 앱 버전 고정값은 실제 앱 URL과 서비스워커 캐시 버전이 일치하는지 검사하도록 수정했다.
- 운영 배포는 깨끗한 main 기반 체크아웃에서 `npm run deploy:production`으로 실행한다.
