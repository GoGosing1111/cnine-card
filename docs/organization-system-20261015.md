# 조직 입단 심사·균등 배정 준비 — 2026-10-15

## 사용자 지시와 범위

- 가입 방식: “희망하는 조직 설문조사 후 유저 간 밸런스 고려 균등 배정”.
- 후속 정정: 조직 입단에 걸맞은 여러 질문을 종합해 선택하게 한다. 조직 한 곳만 고르는 간단한 설문으로 축소하지 않는다.
- UI: imagegen 스킬을 사용한 실제 자산으로 배경·버튼·추천 카드를 제작한다.
- 15개 조직·조직별 최대 10명으로 새로 시작하며 기존 클랜의 멤버·점수·공동 자산을 승계하지 않는다.
- 최초 입단·배정·아지트는 독립 TEST 검수본으로 제작했다. 후속 “라이브 반영하고 다음 조직 개발할거 작업시작해”에 따라 현재 입단 UI를 공개한다. docs/clan-final-organization-20261012.md의 “모집은 추후 시작”을 유지한다. 운영 DB 설치·실제 모집·배정·OWNER CMS 개방은 별도다.

## 입단 심사

shared/organization-interview-v1.mjs의 7문항, 문항별 4개 선택지를 공통 사용한다.

1. 조직의 문을 두드린 이유
2. 새로운 거점을 여는 방식
3. 불리한 판에서 내리는 결정
4. 불확실한 정보를 다루는 태도
5. 조직에서 자신 있게 맡을 역할
6. 공동 자원의 우선 사용처
7. 입단을 앞둔 마지막 약속

답변을 돌파·결단·정밀·기동·설계·수호·신뢰·야심·통찰·인내·교섭·실리·기반·원칙에 누적하고, 15개 조직의 성향과 대조한다. 상위 3곳에는 성향 일치 점수, 조직 소개, 실제 선택한 답변 2개를 근거로 표시한다. 점수는 배정 확률이나 심리검사 결과가 아니다.

추천 확인 후 희망 조직을 명시적으로 선택한다. 전체 15개 조직도 살펴볼 수 있다. 서버는 정확한 7개 응답과 선택지 ID를 검증하며 클라이언트의 성향 점수·전력 입력을 받지 않는다. 성향은 서버에서 다시 계산해 배정에 사용한다.

진행 중 답변은 계정·회차·심사 버전별로 해당 기기에 임시 저장한다. 제출 후 수정 초안도 기존 제출 버전과 일치할 때 복원한다. 다른 창에서 제출 버전이 바뀌면 서버의 최신 제출본을 따른다. 전체 응답이 없으면 다음 단계·제출을 막는다. 키보드 방향키로 답변을 고를 수 있다.

## 배정·서버 보호

- 인원 차이 최대 1명, 조직별 최대 10명, 중복 소속 금지.
- 서버 평가 전력으로 분배한 뒤 전력 차이를 줄이는 교환을 최대 80번 수행한다.
- 균형이 잡힌 15개 묶음에 조직 이름을 연결하는 2^15 상태 탐색으로 희망을 우선하고, 같은 희망 반영 수에서는 입단 성향을 반영한다.
- 같은 전력끼리의 추가 교환은 인원·전력을 바꾸지 않고 희망·성향 반영을 개선하며 최대 150회 순회로 제한한다.
- 전역 최적 전력 배정을 보장한다는 주장은 하지 않는다. 특정 계정의 전력이 압도적이면 불가피한 편차를 OWNER 결과에 표시한다.
- 150명 초과 시 임의로 탈락시키거나 앞선 150명을 뽑지 않고 배정을 중지한다. 설문은 보존한다.
- 기존 계정 잠재 전력 평가기(보유 카드·강화 장비·탈것·칭호·용병)를 재사용한다. 현재 편성만으로 낮춰 신청하는 방식이 아니다.
- 회당 최대 12명 평가, 최대 5분 유효. 조직 호출에서만 OWNER 평가를 명시적으로 허용하며 기존 듀오의 OWNER 차단 기본값은 유지한다.
- 확정 시 계정 전력 버전·계정 상태·평가 정책·고급 강화 정책을 읽기 잠금으로 확인한다. 오래된 평가와 변경된 설문의 배정안은 거부한다.
- OWNER 관리 권한, TEST 허용 명단, Origin/JSON/필드 검사, 회차·사용자 잠금, 낙관적 버전, 요청 영수증.
- 소속 전체·15개 조직의 점수 0/아지트 1단계·회차 확정·영수증을 한 PostgreSQL 트랜잭션으로 저장한다. 실패 시 전체 롤백한다.
- 철회도 버전을 남겨 이전 창의 오래된 재제출을 막는다.
- 일반 응답에 다른 신청자의 답변·평가 명단·배정 초안을 공개하지 않는다.

functions/_organization_schema.js는 명시적인 설치 함수다. 조회 중 DDL을 실행하거나 클랜 데이터를 가져오지 않는다. 현재 설치는 PGlite 격리 검수 DB에만 수행했다.

## 아지트·미정 정책

낡은 판자촌 → 골목 사무실 → 조직 본거지 → 고급 저택 → 고급 펜트하우스의 5단계를 표시한다. 추후 실제 조직 점수는 정산 시점의 점령 지역 수를 기준으로 한다.

지역당 점수·정산 간격·성장 방식·성장 기준·전용 콘텐츠 해금 단계는 null이다. 초안 저장만으로 모집·점수·콘텐츠가 열리지 않는다. 점수 소모형 성장은 별도 영수증이 구현되기 전 실행하지 않는다. 실제 점령전, 점수 정산, 사냥터·보스 실행 및 보상은 이번 입단·배정 검수 범위에 포함되지 않는다.

ORGANIZATION_RELEASE_ENABLED=false로 LIVE 생성·설문·배정을 차단한다.

## 이미지

- 모드: built-in imagegen.
- 단일 색인: assets/ui/organization/admission-v1/manifest.json
- 전체 프롬프트: 같은 폴더 prompts.json
- 생성 자산: 심사실, 황동 주 버튼, 강철 응답 버튼, 서류 프레임, 본부 인장 5종.
- 생성 원본과 프로젝트 복사본 SHA-256이 일치한다. 원본을 덮어쓰지 않았다.
- 승인된 15개 문양과 기존 아지트 콘셉트는 그대로 사용한다. SVG 표시 영역만 문양 주변의 인쇄 글자가 걸리지 않게 맞췄다.
- 한국어는 이미지에 구워 넣지 않고 HTML 텍스트로 표시한다. 메뉴·문항 이동·응답·조직 선택·제출·아지트·운영 버튼에 이미지 스킨을 사용한다.
- 후속 라이브 반영 지시로 현재 UI를 공개한다. 생성 원본·프롬프트는 그대로 보존한다.

## 공개 화면 연결

- 기존 ClanV1의 조직 메뉴 → 조직 본부에서 동일 출처 /organization/ 화면을 표시한다. 마지막 챔피언스리그 기록은 기존 메뉴로 보존한다.
- iframe으로 조직의 전체 배경·서체·버튼 스타일을 분리한다. 현재 창의 origin과 iframe source가 모두 일치하는 높이 알림만 받아 PC·모바일에 맞춰 확장한다.
- 공개 어댑터는 로그인·가상 계정·TEST 헤더·가상 신청 인원 없이 준비 상태만 제공한다. 7문항·종합 추천·전체 15곳과 최종 희망 선택은 이 기기에 저장된다. 접수 대기 문구와 비활성 버튼, 호출 자체 거부를 함께 적용한다.
- 독립 TEST 화면 및 서버 모듈은 준비 소스로 보존한다. 공개 어댑터는 DB·운영 API를 호출하지 않으며 운영 라우터에 신규 모듈을 등록하지 않는다.
- UI 공개 범위이므로 scoped 검수·배포한다. 조직 스키마는 아직 실행되지 않은 격리 검수 코드이며 공통 DB·인증·마이그레이션·의존성 변경은 없다. 조직 전용 평가의 OWNER 선택지는 기존 듀오의 거부 기본값을 유지한다.
- tests/organization-public-20261015.test.mjs에서 PC 1440·모바일 390, 일곱 질문·추천·15곳 선택·초안 복원·iframe 크기/출처·기존 대회 메뉴·수평 넘침·실제 요청 없음·변조된 제출 차단을 확인한다. 증빙은 docs/qa/organization-live-20261015/.
