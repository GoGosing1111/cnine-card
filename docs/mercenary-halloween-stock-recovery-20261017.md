# 할로윈팩 일부 품절 전체 차단·이전 요청 복구 수정

사용자 제보: 코인이 충분해도 자동뽑기가 활성화되지 않으며 대부분 이용자가 겪는다. 이전 결과 처리 문제로 추정했다.

## 확인한 원인

운영 설정은 revision 12·판매 ON이지만 `userOpeningEnabled: false`였다. `readiness.blockers`는 `V-986의 한정 수량을 확인하세요.` 한 건이다. 남수댕 V-986이 10/10장 소진됐고 나머지 할로윈 SS 및 SSS 리미티드에는 재고가 있었다. 개별 카드 하나의 소진을 전체 팩 준비 실패로 처리하여 일반/자동 개봉 버튼을 모두 잠갔다.

별도로 이전 요청 복구의 GET이 서버 취소(`JOINT_OPERATION_SUPERSEDED`)를 반환할 때 로컬 pending 기록을 정리하지 않는 결함도 확인했다. 서버가 취소를 확정했는데도 새 개봉이 계속 이전 결과 확인을 요구할 수 있었다.

## 변경

- 일부 품절은 다른 재고가 있는 팩 전체를 차단하지 않는다. 미준비 원장, 불완전 설정, 전체 선택 대상 소진, 판매 OFF는 기존대로 차단한다.
- 승인된 가격·1/2단계 확률·개별 발행 한도·기존 발행량은 변경하지 않는다. 품절 확률을 재분배하거나 다른 카드로 재추첨하지 않는다. 기존 확률 구간에서 품절 카드가 선택되면 해당 요청은 코인 차감·부분 지급 없이 종료한다.
- 계약실 진입 시 로컬 pending이 있는 경우에만 기존 영수증을 GET으로 확인한다. 완료된 요청은 결과를 재표시하고, 서버 취소가 확인된 요청은 로컬 pending을 정리한다. 자동 개봉을 재개하거나 새 개봉 POST를 전송하지 않는다.
- PENDING·기록 미확인·네트워크 실패는 같은 requestId를 보존한다. 사용자가 ‘이전 결과 확인’을 눌러야 기존 요청을 재제출한다. 계정 격리·브라우저 잠금·중복 차감 방지는 유지한다.
- 기존 ImageGen 할로윈 계약실과 자동뽑기 패널·버튼을 그대로 사용한다. 새 장식/UI 제작은 없다. 게임·CMS의 관련 모듈 캐시 주소를 갱신했다.

- 기존 `tests/mercenary-halloween-auto-20261017.browser.mjs`에 실제 남수댕 품절 상태, 서버 취소 요청, 완료 요청 및 미확인 요청의 복구 사례를 추가했다. 격리 PostgreSQL 서비스와 실제 UI를 1440px/390px에서 검수했다.
