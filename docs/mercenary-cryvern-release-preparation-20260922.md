# 크라이베른 출시 준비 — 2026-09-22

> 아래는 9월 22일 준비 당시 기록이다. 9월 24일 사용자가 커밋·운영 반영과 SSS 당첨 후 0.1%를 승인했다. 최신 코드 V-049 / MS-049, 출시 범위·비균등 확률·검수 기준은 [9월 24일 출시 기록](mercenary-cryvern-live-20260924.md)을 따른다. 아래의 배포 보류·V-048 예약·균등 편입 계획은 현재 지시가 아니다.

## 최신 사용자 결정

- 이름은 **크라이베른**. 칭호는 빈 문자열이며 `극빙의쌍검`을 붙이지 않는다.
- **SSS**, 라그니엘보다 근소하게 상위. 기존 SSS 기본 전투력 **180,000**과 공통 스탯 환산을 유지한다.
- 승인 원화 V3, 왼손 검이 몸 앞 오른쪽으로 향한 전투 SD V7, 연속 모션·타격/스킬 효과, 진한 실루엣 광원 V2를 사용한다.
- **라이브 반영은 아직 금지**. 운영 DB·유저 재화·계정·확률·기능 스위치 변경, push, 배포를 하지 않았다.

## 작업 위치와 출시 잠금

최신 전투 기준 `89d6aff6bd27c7c2e6af544f7082c5c84ca8a767`에서 분리한 `codex/cryvern-release-prep-20260922`다. 이전 원화/모션 준비본 `8cf5ac019904312e93d2d92c246d57348e3897e0`의 해당 프리뷰만 가져왔다. 원래 작업 폴더의 다른 미완료 변경은 섞지 않았다.

`shared/mercenary-cryvern-v1.mjs`의 `CRYVERN_RELEASE_ENABLED=false`. 운영 로스터/CMS seed에는 여전히 47종, 독립 스킬에는 30종만 있다. V-048 / MS-048은 이 후보의 예약 코드다. 다른 작업이 먼저 같은 코드를 등록하면 충돌을 해결한 뒤 다시 검증한다.

`npm run prepare:cryvern`은 승인 원본의 해시 일치 복사본·도감 파생 이미지와 `preview/mercenary-ice-crystal-dual-sword-v1/release/`의 후보/전투 JSON·로컬 번들만 준비한다. 원본을 덮어쓰지 않으며 DB나 운영 카탈로그를 등록하지 않는다. `--register-local`은 출시 잠금이 켜진 동안 거절한다.

## 구현한 전투

전용 스킬 **극빙 왕관(MS-048 / CRYSTAL_CROWN)**:

1. 적 전열 최대 2명을 고정하고 같은 행동에서 시전한다. 별도의 준비 턴·재장전 턴이 없다.
2. 1.30초 십자참에 전체 피해 예산 40%, 2.62초 결정 왕관 파열에 60%를 나눈다. 최초 대상 수로 각 몫을 나눈다.
3. 첫 타를 피한 대상은 후속 파열이 없다. 첫 타에 쓰러진 대상의 남은 몫은 살아 있는 지정 대상에게만 이전한다. 부활은 전체 시전 뒤 처리한다.
4. 서버의 회피·방어·보호막·피해 억제를 따른다. 0배율/100% 억제를 기본 공격으로 바꾸지 않는다. 빙결, 기절, 즉사, 방어 무시, 최대 HP 비례 추가 피해, 추가 행동은 없다.

준비 수치: 피해 계수 **5.88**, 자원 **35**, 재사용 **본인 행동 5회**. 라그니엘 5.6보다 원 계수 5% 높다. PVP 한 시전 상한 계수는 **1.30**(라그니엘 1.04)으로 비교 검증했다. 상한 계수 차이가 최종 피해량·승률의 같은 비율 증가를 뜻하지 않는다. 공통 SSS 전투력/내구도나 기존 용병 수치는 변경하지 않았다.

기본 공격은 쌍검 연격·십자참·빙선풍의 세 동작을 순환하지만 서버 공격/발동/피해 적용은 **한 번**이다. 대시는 이 동작에 연결된다. 결정벽은 이미 서버가 확정한 보호막 소모에 대한 피격 연출이며 새 방어 판정이나 반격 피해를 만들지 않는다. 광원은 승인 SD/각 포즈 알파를 추종한다.

- `release:gate` 전체와 깨끗한 origin/main 배포 검사도 실제 출시 후보에서 다시 수행한다. 이 분리된 준비 브랜치를 배포 가능한 origin/main이라고 취급하지 않는다.

## 승인 후 출시 순서 — 지금 실행 금지

1. 최신 origin/main과 다른 작업의 로스터/전투 변경을 확인하고 준비 커밋을 통합한다. 승인 이름·원본 해시·V-048 충돌, 기존 CMS 보존을 재확인한다.
2. 명시적인 라이브 승인 후 `CRYVERN_RELEASE_ENABLED=true`로 변경한다. `node scripts/prepare-cryvern-release.mjs --register-local`은 해당 체크아웃의 로스터·포지션·앵커·FX·파생 이미지 목록만 추가한다.
3. `npm run build:mercenary-cms`, `npm run build:mercenary-codex`, `npm run build:v3-grid`, `npm run prepare:cryvern`을 실행한다. 원본/모션을 다시 생성할 필요는 없다.
4. 회귀 검사, 현재 저장된 CMS의 확장, SSS 풀 3종 균등 편입을 확인한다. 등급 전체 확률을 바꾸거나 운영 문서 전체를 seed로 덮어쓰지 않는다. 운영 CMS 반영이 필요하면 기존 revision/영수증/감사 로그 경로를 쓴다.
5. 검수 계정/API로 실제 메인 진입을 PC·모바일에서 확인한다. 첫 로딩/재입장/PVE↔PVP/구버전 갱신/실패 안내와 복귀까지 검사한다. 서비스워커·메인 기능 로더의 배포 캐시 키도 해당 업데이트 회차와 함께 점검한다.
6. 깨끗한 최신 origin/main 후보에서 `npm run release:gate` 통과 후 **`npm run deploy:production`만** 사용한다. 긴급 dirty 우회나 Wrangler 직접 배포를 쓰지 않는다.
7. 운영 파일로 동일 경로를 재검수한 뒤 출시 공지. 하이퍼팩의 기존 등급 확률은 보존한다.

출시 후 문제가 생기면 획득/보유 기록을 삭제하거나 예전 47종 seed로 운영 문서를 덮어쓰지 않는다. 신규 획득 차단/보유 편성 호환을 먼저 점검하고, 지급된 V-048 데이터를 보존하는 수정 또는 명시적인 롤백 계획을 사용한다.
