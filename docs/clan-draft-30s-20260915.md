# 참가 마감 후 1시간 내 드래프트 종료 · 30초 턴 제한

2026-09-15 사용자 최종 요청: 참가 신청 마감 직후 자동 시작하고, **신청 마감 후 1시간 이내 전체 드래프트를 종료**한다. 부재중 클랜이 지명하지 않으면 **30초 뒤 다음 팀**으로 넘긴다.

## 적용

- 기존 신청 마감일과 클랜전 개방 요일·시간은 유지한다. `REGISTRATION` 종료 즉시 시작 대상이며, 전용 Durable Object 알람이 늦어도 매분 확인한다. 클랜 화면 접속 없이도 시작한다.
- 전체 마감은 **신청 마감 + 60분**을 상한으로 한다. 늦게 시작해도 상한을 늦추지 않으며 개별 지명도 전체 마감 뒤로 시간을 늘릴 수 없다. 신규 시즌·테스트 리셋·공식 리셋 생성 모두 같은 60분을 사용한다.
- CMS는 신청 마감 후 종료 시간 60분을 고정 표시한다. 이전 `draftDays` 값은 호환용으로 보존하지만 신규 일정 계산에 사용하지 않는다. 공개 화면에도 전체 종료 시각(KST)과 잔여 후보 자동 편성을 안내한다.
- `workers/clan-draft/`는 운영 ON인 기존 시즌의 신청·드래프트만 처리한다. 신규 시즌을 생성하거나 전투·보상을 정산하지 않는다. 드래프트가 완료되면 기존 대진 생성 코드를 사용한다.
- 알람은 다음 지명 마감 시각에 다시 실행한다. DB 연결은 한 번의 처리 뒤 닫고, 다음 실행 예약은 영속 저장한다. 처리 전에 1분 뒤 재시도를 먼저 예약하므로 DB 장애로 자동 재시도가 소진되어도 타이머가 사라지지 않는다.
- 매분 Cron은 알람이 없을 때 다시 예약하는 보조 장치다. 초기 Cron 전파 지연과 별개로 설치 직후에는 같은 계정의 임시 서비스 바인딩에서 `arm()` RPC를 한 번 호출해 알람을 시작한다. 재배포해도 기존 알람은 보존하며, 재호출은 이미 가까이 예약된 알람을 늦추지 않는다.
- `arm()`은 게임 상태·시간·SQL 입력을 받지 않는다. 공개 HTTP 진입은 404이며 `workers.dev`와 미리보기 URL을 비활성화한다. 알람은 공식 클랜 대회 한 개의 일정만 조정하며 일반 게임 요청은 이 객체를 통과하지 않는다.
- `clan_draft_scheduler_v1` 단일 상태에 마지막 실행·단계·다음 확인 시각을 기록한다. 기록을 계속 추가하는 로그 테이블은 만들지 않는다.
- 개별 턴 만료 시 후보를 자동 지명하지 않는다. 원래 마감 시각을 기준으로 만료한 턴들을 한 번에 반영하므로 늦은 새로고침이 대기 시간을 늘리지 않는다.
- 가득 찬 팀은 건너뛴다. 스네이크 끝에서 부재중인 같은 팀에 연속 차례를 주지 않는다. 정상 지명 시의 스네이크 순서는 유지한다.
- 전체 마감에는 잔여 후보를 기존 점수 순·스네이크 순서에 따라 자동 편성한다. 잠금 하나 아래에서 10명씩 묶은 SQL을 한 트랜잭션으로 확정하여 최대 176명이 있어도 후보별 API 처리를 반복하지 않는다. 처리 실패 시 전체 롤백하고 재시도하며, 신청자나 보유 재화는 삭제하지 않는다.
- 시작·패스·지명은 공통 드래프트 잠금을 사용한다. 시작 편성은 하나의 DB 배치로 확정한다. 지명은 잠금 안에서 단계·차례·남은 시간을 검사하며, 클라이언트는 선택한 차례 번호를 전송한다.
- 클라이언트는 서버 시간을 기준으로 초 단위 카운트다운을 표시하고 만료 시 선택을 잠근 뒤 동기화한다. 일반 팀원도 현재 지명 팀을 볼 수 있고 후보 선택 권한은 마스터에게 유지된다.
- CMS 기본 지명 제한을 30초로 변경했다. 운영 DB의 기존 300초는 별도 원자 작업으로 **이 필드만** 30초로 전환한다. 다른 설정을 기본값으로 덮어쓰지 않는다.

## 확인한 운영 일정

시즌 ID 5 / 시즌 2: 참가 신청은 **2026-09-15 23:00:01 KST** 마감, 전체 드래프트 마감은 **2026-09-16 00:00:01 KST**로 변경한다. 기존 300초 → 30초 작업은 `ops-clan-draft-30s-20260915-01`이다. 후속 1시간 종료 작업 `ops-clan-draft-one-hour-20260915-01`은 설정 `draftMinutes=60`과 이번 시즌 `draft_ends_at`만 변경한다. 첫 정규 클랜전은 기존 운영 요일에 따라 **9월 17일 21:00~22:00 KST** 예정이다.

## 검증 및 배포

- `npm run test:clan`: 119개 통과. SQLite와 PostgreSQL 호환 계층에서 30초 경계·지연된 폴링·중복 호출·실제 지명·가득 찬 팀·1시간 전체 마감·동시 시작을 확인했다. 최대 176명 편성, 늦게 시작해도 마감 유지, 일괄 편성 롤백·재시도, 신규 시즌 마감과 알람의 오류 복구도 검사한다.
- 로컬 Workerd에서 실제 WorkerEntrypoint → Durable Object RPC → 자동 알람 → 다음 30초 예약을 검증했다. 이 검사는 DB만 합성 데이터로 격리하며, 설치된 로컬 런타임의 호환 날짜는 2026-08-27이다. 운영은 2026-09-15를 유지하며 운영 알람 상태를 별도로 확인한다.
- 실제 운영 클랜 UI 모듈/CSS와 격리된 테스트 데이터로 1440px, 390px, 320px 브라우저 확인: 가로 넘침 0, 초 표시, 지명 차례 전송, 만료 후 다음 팀 전환, 타이머 정리, JS 오류 0.
- Wrangler 전용 Worker 빌드 및 타입 생성 완료. 관련 전투 런타임/번들 버전은 변경하지 않았다.
- 배포는 `npm run deploy:production`으로 전체 `release:gate`를 거친 뒤 Pages와 동일 커밋의 드래프트 Worker를 함께 배포한다.
- 배포 후 운영 자산 캐시 버전, 설정 30초, Worker의 실제 실행 상태를 확인한다. 운영 데이터를 앞당겨 드래프트를 강제로 시작하는 테스트는 하지 않는다.

독립 실행 근거: [Durable Object 알람](https://developers.cloudflare.com/durable-objects/api/alarms/), [Cloudflare Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/). 설치 후 `clan_draft_scheduler_v1.source=DURABLE_ALARM`의 `checkedAt`이 접속 없이 두 번 갱신되는지 확인한다. 원상복구 시에는 이 배포 경로에서 복구 코드를 Pages와 Worker에 함께 반영하고 CMS 지명 제한을 기존 값으로 복구한다. 이미 확정된 지명이나 지나간 턴은 되돌리지 않는다.
