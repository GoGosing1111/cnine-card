# 리치왕 정벌 입장권 공대·운영 TEST — 2026-09-28

사용자 요청: 붕괴 코어와 비슷한 입장권 공대, 공대 안 역할 배분, 공대장 강제퇴장, 운영 배포와 ON·TEST·OFF 및 테스트 인원 지정.

## 이용 흐름

- PVE 레이드 영역의 리치왕 정벌 → 운영 전용 `/raid/lich-king/` → 모집 목록 또는 입장권 공대 창설.
- 공대장만 `LICH_KING_ENTRY_TICKET` 1장을 소모하며 참가자에게 추가 차감하지 않는다. 인벤토리 직접 개봉 대상이 아니고 OWNER 유저관리의 기존 아이템 지급 메뉴에서 배포한다.
- 3~6명, 정벌·봉인·구출 역할 모두 필요. 공대장이 배분한 뒤 모든 참가자가 준비 완료를 눌러야 출정한다. 역할이 바뀌면 준비를 초기화한다.
- 대기실과 전장의 공대 관리에서 역할 재배분·강제퇴장 가능. 강퇴자는 같은 공대의 조회·입력·재참가를 차단한다. 자신을 강퇴할 수 없다. 공대장 이탈은 해산이며 입장권은 반환하지 않는다.
- 공용 전장에는 창설 시점 공대장 계정의 실제 PvE 카드 5장을 저장한다. 보유·편성 검증은 기존 `raidDeckPower`를 사용한다. 참가자는 각 역할의 기믹을 조작한다. 운영 화면에는 이름 입력·단독 COMMAND 모드·검수 덱·로컬 세션 발급이 없다.
- 전투는 기존 V3 렌더러·진형·도크·아트 어댑터와 직전 검수된 전장 기믹을 사용한다. 별도 사이드 기믹 패널을 만들지 않았다.

## 운영 제어

OWNER CMS → 레이드 관리 → 리치왕 정벌.

| 모드 | 접근 |
| --- | --- |
| OFF | 모든 계정 입장·조회·전투 입력 차단 |
| TEST | OWNER + CMS에서 지정한 계정 ID만 허용 |
| ON | 로그인한 일반 계정 허용 |

초기 기본값은 TEST, 지정 명단은 빈 목록이다. 다른 콘텐츠의 테스트 명단이나 과거 코인 지급 계정을 자동 편입하지 않는다. 정확한 닉네임/계정번호로 검색하여 최대 100명을 추가·제외하고 저장하면 다음 요청부터 적용한다. 이름 변경 이후에도 계정 ID로 접근을 판정한다. 일반 API에는 지정 명단을 노출하지 않는다. 보스 고정 전투력(초기 320,000)과 모집 시간(초기 15분)은 CMS에서 조정하며 기존 공대의 스냅샷은 유지한다.

모든 모드의 클리어 보상은 잠금이다. 이번 요청에서 보상 정책은 정하지 않았다. 기존 신규 아트의 사용자 시각 검수 기록을 덮어쓰지 않고, 이번 사용자 요청에 따른 운영 TEST 연결 사실을 별도로 기록한다.

## 정합성·복구

- 기존 로그인·OWNER 권한·계정 변경 잠금을 재사용한다. 새 인증 우회나 별도 로그인 토큰은 없다.
- `raid_lich_rooms_v1` 공대 상태, `raid_lich_active_v1` 계정별 단일 참가, `raid_lich_receipts_v1` 요청 영수증을 사용한다.
- 방 생성·입장권 차감·차감 로그·참가·영수증을 같은 DB batch에서 원자적으로 저장한다. 동일 요청 재시도는 기존 결과를 반환한다.
- 서로 다른 계정의 명령은 방 버전 CAS로 경합을 판정한다. 상태 갱신과 멤버 변경·영수증을 한 트랜잭션에 저장하며 CAS 패배 시 전체 롤백하고 최대 3번만 재조회한다. 전투 계산은 트랜잭션 밖에서 수행한다.
- 서버가 시간·기믹·HP·승패를 결정한다. 클라이언트는 성공 여부나 시간을 제출하지 않는다. 클라이언트 지연 응답은 최신 명령 세대와 서버 시간/버전으로 배제한다.
- 일반 전황 조회는 설정과 해당 공대 PK만 읽는다. 기믹 경계·판정이 바뀔 때만 저장하며 매 폴링의 시계 표시를 DB에 쓰지 않는다. 모집 목록은 상태/만료 인덱스와 30개 제한, 참가자는 최대 6명이다.
- 화면 폴링은 전투 650ms, 모집 3초, 소개 15초로 제한하고 숨김 탭에서는 중단한다. 실패 시 최대 10초까지 간격을 늘린다. 생성/참가/행동 요청은 중복 클릭 잠금과 동일 요청 ID 재사용을 적용한다.
- 종료·만료·해산 시 계정의 활성 참가 예약을 해제한다. 새로고침은 실제 공대 스냅샷으로 복구한다.
