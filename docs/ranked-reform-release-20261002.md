## 구현

점수는 기대 승률 `1 / (1 + 10^((상대 점수 - 내 점수) / 400))`, K=48로 계산한다. 승리 변화량은 `48 - round(48 * 기대 승률)`, 패배 감점은 `round(48 * 기대 승률)`이다. 동점 상대는 +24/-24이며 승리와 패배 변화량의 합은 48이다. 정수 반올림 오차 외에 기대 승률을 만족하는 반복 경기의 점수 상승 편향을 제거한다. 0점 하한으로 생기는 이득을 없애기 위해 음수 점수를 허용한다.

공격 경기만 시즌 점수·승패를 바꾸며 방어전은 전투 이력에 보존한다. 매칭은 운영 설정의 점수 차이 및 대칭 편성 전투력 차이 `(큰 전투력 / 작은 전투력 - 1) * 100`를 모두 만족해야 한다. 범위를 벗어나는 상대를 선택하는 대체 경로를 제거한다. 용병은 기존 편성 전투력에 계속 포함되지만 전투 성능은 보정하지 않는다.

경기 티켓, 행동력, 공격자 점수, 이력, 코인, 코인 로그, 전투 감사 기록 및 재요청 영수증을 하나의 트랜잭션으로 반영한다. PostgreSQL 행 잠금과 조건 검증으로 중복·경쟁 요청과 시즌 전환을 처리한다. 기존 선택적 아이템 드롭 처리는 이 핵심 트랜잭션 뒤의 기존 경로를 유지한다. 재요청은 저장된 핵심 결과와 최신 지갑을 반환하며 전투를 다시 실행하지 않는다.

재개 예약은 운영 app_meta의 `ranked_reopen_schedule_v1`에 저장한다. 기존 서버의 분 단위 cron과 개방 이후 첫 PVP 요청이 같은 멱등 재개 함수를 호출한다. 개방 트랜잭션은 시즌 18 정산 완료와 코인·샤드 미전달 0, 일시 중지된 시즌 19의 정확한 식별자, 생명주기 잠금, 예약 시각을 확인한다. 점수 보관·초기화·활성화·5일 일정 설정·예약 완료 표시는 한 번에 커밋한다.

## 검증 및 배포

점수·행동력 거래와 시즌 생명주기 및 신규 보관 테이블을 함께 변경하므로 전체 `npm run deploy:production` 경로를 사용한다. 별도 사전 전체 검사는 중복 실행하지 않는다. 최신 origin/main을 통합해 다른 운영 변경을 보존한다. 직전 확인된 운영은 아바타 릴리스 `ecab6a11617ab1a83f7876591a2c59d39711fbed`이며 이후 신규 유저 선물 릴리스도 최신 main에서 승계한다.

추가 회귀는 SQLite와 실제 운영 호환 PostgreSQL 파이프라인에서 원자성·실패 복구·경쟁 요청·잠금 중 차단·행동력 충전·예약 시각·정산 미완료 차단·단회 초기화를 검증한다. 공용 전투 엔진은 수정하지 않는다.

실제 메인 UI를 이용한 로컬 API fixture 검수는 1440×1000 PC와 390×844 모바일에서 대기 안내, 정상 매칭, 상대 없음, 행동력 부족, 재요청 결과를 확인했다. 브라우저 오류와 가로 넘침은 없었다. 실제 운영 계정으로 경기를 실행한 검수는 아니며 개방 전에는 운영 경기를 만들지 않는다.
