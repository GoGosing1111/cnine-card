# 할로윈 디임 성장 효율·듀오 레벨 연결 · 2026-10-20

씨나인택갓의 최근 PVP를 점검한 뒤 사용자 `수정해`에 따라, 공격·체력·행동 성장이 실제 기여로 이어지지 않던 디임과 별도로 발견한 듀오 성장 누락을 수정한다. 최초 읽기 전용 점검은 [기존 기록](mercenary-halloween-diim-level11-review-20261020.md)에 보존한다.

## 변경

- 출시된 성장 V2가 적용된 할로윈 SS 디임 V-984의 PVP만 보완한다. 기본 능력치·전열 보호 대상·재사용·비용·시작 방벽·성야의 방패 40% 감소는 유지한다.
- 평타 상한에 `min(3, sqrt(1 + 성장 공격% / 100))`를 곱한다. 공격력 증가 전체를 상한에 그대로 곱하지 않고 최대 3배로 제한한다. Lv.11의 공격 +500%에서는 약 2.45배다.
- 받는 타격 상한의 최대 HP 기준을 `min(3, sqrt(1 + 성장 HP% / 100))`로 나눈다. 시작 방벽은 나누지 않는다. 성장 HP가 상대의 타격 상한도 똑같이 키워 생존 이득이 사라지는 문제를 줄이면서, 고레벨에도 피해 상한이 HP와 함께 증가하도록 한다.
- 돌파로 얻는 행동 대응·추가 행동 숙련 합계를 시작 게이지에 반영한다. Lv.6은 20, Lv.11은 50, 상한은 75다. Lv.2 이상 디임의 카드 행동 기반 추가 행동은 자연 행동 게이지를 소모하지 않고, 자연 행동은 여전히 100을 소모한다.
- 듀오는 실제 보유 용병의 성장 스냅샷을 일괄 조회해 전력 평가와 공격·방어 편성에 연결한다. `user_mercenary_levels_v1` 변경과 `mercenary_level_policy_v1` 변경을 기존 듀오 버전 무효화에 추가하며 캐시 형식 키도 갱신한다. 정책 OFF는 성장 테이블을 읽지 않고 기존 무성장 편성을 사용한다.
- 운영 보완은 듀오 전용 계정 트리거 1개와 기존 정책 트리거 3개만 교체하고 듀오 정책 버전을 한 번 올린다. 모의 실행은 DDL까지 롤백한다. 일회 감사·완료 키는 `ops:ranked-duo-growth-tracking:20261020:v1`이며 재실행은 검증만 한다. 성장 행·과거 영수증·점수·보상은 바꾸지 않는다.

특정 이용자나 상대 코드에 따라 승패를 보정하지 않는다. Lv.1·PVE·다른 용병의 전투 계산과 성장 비용/레벨은 유지한다. 기존 도감 설명에 실제 규칙을 보완하며 신규 UI나 미술 자산은 없다.

추가 경계 확인은 동일한 25만 전투력 5인 편성, 같은 용병 레벨, 난수 8개와 양측 교대다. 디임은 강윤 상대로 Lv.1 0/16, Lv.11 1/16, Lv.20 1/16승이고 할로윈 봉순 상대로 0/16·16/16·16/16승이다. 무승부는 0건이며 일반 행동 수는 최대 13이다. 특정 승률을 운영에 강제하지 않는다.

## 검수·배포 범위

새 회귀 10개를 통과했다. 디임의 실제 상한 피해·생존·게이지 소비, Lv.1/PVE/다른 용병·구버전 제외, 성장 중복 적용 방지, 듀오 소유자별 성장, SQLite/PostgreSQL 캐시 갱신, 조회 도중 강화, 출전 직전 강화, 완료 영수증 재시도, 운영 훅 모의 실행·일회 실행을 검사했다.

최종 배포는 직전 운영 소스 `a788d2c66d5d2a2ae7f3148f9f99cfd02cbe83f7`에서 `npm run deploy:production -- --scoped`로 진행한다. 직접 변경된 두 새 회귀, 기존 디임 방벽·성장 V2·듀오 프로필·랜덤·상시 매칭 회귀와 `check:worker`를 선택한다. 공통 DB/인증/세션/의존성 구조는 변경하지 않으며 듀오 전용 훅만 보완한다. 관련 검사와 출시·캐시·Hyperdrive 보호를 통과한 뒤 배포하고, 운영 빌드·공개 도감·듀오 기록을 짧게 확인한다.

운영 `app_meta`와 성장 테이블은 기존 소유자가 다르므로 기존 듀오 스키마 설치 방식대로 각 소유자 연결에서 자기 테이블만 변경한다. 정책 훅을 먼저 반영하고 성장 훅·버전 증가·감사·완료 영수증은 후속 한 거래로 확정한다. 중간 실패는 안전하게 재실행하며 소유권·역할 멤버십·기존 권한을 변경하지 않는다. 두 모의 거래는 모두 롤백한다.

최초 scoped 실행에서 관련 73개·Worker 컴파일·출시 보호·Hyperdrive 캐시 OFF는 통과했지만 정적 파일 수가 20,003개여서 업로드 전에 중단됐다. 이번 점검 문서 2개와 익명 회귀 입력 1개는 브라우저 사용처가 없음을 확인하고 배포 묶음에서만 제외해 20,000개 한도를 지킨다. 원본은 Git에 보존하며 런타임 코드는 그대로다. 재개는 해당 파일 선별 회귀를 추가한 디임 검사와 필수 컴파일·출시 보호만 수행하고 통과한 듀오/성장 검사를 반복하지 않는다.
