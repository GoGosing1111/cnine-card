# PROJECT V V3.5 전투엔진 제작 규정

- 규정 ID: PV-V35-COMBAT-20261101
- 적용일: 2026-11-01
- 사용자 지시: “이펙트 말한 스킬들 spine 작업규정 v3.5 전투엔진으로 규정화 해놔라”, “던전앤파이터급 전투 퀄리티가 나와야함.”
- 적용 대상: V3 기반 신규 용병의 Spine 캐릭터 모션, 기술별 이펙트와 전투 재생 연동.
- **품질 완료 기준: 던전앤파이터급 전투 동작·타격감·효과 밀도·가독성.** 도구 도입이나 파일 생성만으로 이 수준을 달성했다고 판정하지 않는다.

V3.5는 기존 V3 렌더러에 Spine 캐릭터와 보완 작화·연속 이펙트를 결합하는 제작 및 연동 기준이다. 이 규정 등록이 운영 엔진 전체의 Spine 전환이나 V3.5 배포 완료를 뜻하지 않는다. 후속 “새 캐릭터로 처음부터 기준점부터 다시 잡아가라”에 따라 [새 캐릭터 전신 기준안](../preview/v35-character-baseline-20261101/PROJECT.md)부터 다시 시작한다. [진 족로 제작 명세](v35-jin-jokro-pilot-20261101.md)는 반려·보류된 과거 시험 이력이다.

## 1. 기준의 우선순위

최신 사용자 지시와 캐릭터별 승인 원본을 우선한다. [기존 모션·이펙트 11단계 공정](project-v-motion-effects-production-standard-20260927.md)의 원본 고정, 동작 설계, 접점 검증, 실제 재생, 증빙 및 시각 승인 의무를 유지한다. X-BODY V2는 승인된 공정과 비교 자료이며, V3.5가 던전앤파이터급에 도달했다는 증거는 아니다.

V3.5에서는 기존 03단계 몸 작화에 Spine 뼈·메시·IK·교체 attachment·필요한 손그림을, 05단계 효과 작화에 Effekseer 제작 후 연속 이미지 내보내기를 적용할 수 있다. 모든 동작을 ImageGen 전신 시트로 만드는 방식에 한정하지 않는다. 실제 관절·실루엣 변화, 원본 보존, 기술별 고유 연속 작화와 나머지 공정을 생략하는 예외가 아니다.

[스킬 이펙트 규정](project-v-skill-effects-standard.md), [용병 원화 규정](project-v-mercenary-card-art-standard.md)을 함께 따른다. V4의 승인된 쿼터뷰 기준은 별도 범위다. 진 족로의 기존 측면 작화나 다른 캐릭터의 승인 시점을 V3.5 명칭 때문에 일괄 교체하지 않는다.

### 새 캐릭터의 제작 진입 순서

1. **전신 기준안:** 한 사람으로 완성된 정지 그림에서 체형·얼굴·시점·무기 크기·파지·다리 지지를 먼저 비교한다. 이름·등급·수치는 별도로 확정하며, 후보 그림을 승인 원화로 기록하지 않는다.
2. **정지 재조립:** 부품을 분리한 뒤 기준안과 동일한 자세로 다시 조립한다. 실루엣·부품 배율·관절 위치·앞뒤 순서·알파를 원본과 나란히 또는 겹쳐 비교하고 실제 캡처를 남긴다. 이미지 생성기의 격자 지시만 믿고 자동 분할하지 않는다.
3. **네이티브 배율 확인:** Spine import/save/export 이후 region의 width/height 및 scaleX/scaleY와 실제 렌더 크기를 확인한다. 진 족로 실패처럼 import가 PNG 원본 크기로 정규화한 것을 놓치지 않는다. 수치 검사와 조립 모습 확인이 모두 필요하다.
4. **대기 → 기본 공격 → 대표 스킬:** 정지 모습이 유지된 뒤 대기 한 동작부터 검수한다. 접지·파지·준비/적중/회수를 확인하기 전에 여러 동작과 효과를 동시에 제작하지 않는다.

2026-11-01 진 족로의 부품 과대 표시·조립 붕괴는 작업 오류이며 사용자 반려다. 명시적 배율을 넣은 후속 파일은 시각 재검수 전 보류됐으므로 “복구 완료”로 쓰지 않는다. 실패 자료는 보존하고 새 기준의 외형 참고로 재사용하지 않는다. 파일 생성/저장/예제 재생 가능성과 고품질 캐릭터 제작 능력은 별도로 설명한다. 검수 전 조립 프리뷰를 사용자 화면에 자동으로 열지 않는다.

## 2. 도구 역할과 비용

가격은 2026-11-01 확인 기록이다. 구매 시점의 공식 조건을 다시 확인하며, 도구별 설치와 자동화 가능 여부는 실제 작업에서 확인한다.

| --- | --- | --- |
| Spine Professional | 부품 리깅, 관절·IK, 메시 변형, 몸·의상 동작, 교체 작화 연결, 편집 가능한 원본과 런타임 내보내기 | 사용자 구매·설치·활성화 완료. 4.3.26의 파일/CLI 작업 검증 완료 |

기본 조합은 **Spine Professional + Krita + Effekseer**다. Aseprite는 도트 스타일이 정해졌을 때 선택하며, 던전앤파이터급 동작 품질을 이유로 픽셀 스타일이나 추가 구매를 자동 확정하지 않는다. 새 보완 래스터 생성·편집은 해당 환경의 ImageGen 지침도 따른다. Krita/Aseprite는 이를 보완하는 작화·프레임 편집 도구이며, 사용하지 않은 도구를 제작 이력에 적지 않는다.

Spine은 없는 시점의 그림이나 숨겨진 신체를 자동으로 완성하지 않는다. 원화 해상도·재질 묘사·얼굴 품질은 원본과 보완 작화가 결정한다. 강한 원근 변화와 극단 자세는 메시를 과도하게 늘려 해결하지 말고 필요한 교체 작화를 제작한다.

## 3. 기본 작업 방식 — 파일과 명령줄

1. 기존 프로젝트와 의존성을 재사용한다. 사용자가 화면을 비우거나 마우스를 넘겨주는 과정을 기본 공정으로 요구하지 않는다.
2. 승인 이미지·부품·리깅 데이터와 애니메이션을 파일로 준비하고, 설치된 Spine.com의 검증된 import/save/export 경로로 실제 .spine과 런타임 패키지를 만든다.
3. 로컬 프리뷰에서 파일 기반으로 재생·수정·검수한다. **2026-11-01 후속 “내 화면 계속 방해받는데 따로 작업 못함?” 우선:** 사용자 편집기·마우스·키보드·브라우저를 조작하지 않는다. 다시 명시적으로 요청받기 전에는 GUI 검수를 이유로 재개하지 않는다. 숨김 Spine CLI와 화면 없는 브라우저에서 공식 런타임을 실행하고 실제 수행한 검수 방식만 기록한다.
4. 특정 기능에 검증된 파일/CLI 경로가 없으면 그 기능과 한계를 정확히 기록하고 다른 제작·검수를 계속한다. 미검증 GUI 동작을 “자동 제작 가능”이라고 약속하지 않는다.
5. 사용자가 편집한 최신 .spine은 정본이다. 해시·변경 시각을 확인하고 과거 생성 스크립트로 덮어쓰지 않는다. 수정 후 현재 정본에서 런타임을 다시 내보낸다. 저장되지 않은 편집기 작업을 임의 폐기하지 않는다.
6. JSON import의 `-r`은 기존 .spine에 스켈레톤을 추가한다. 새 생성 후보는 입력 해시별 새 .spine으로 만들고, 재열기에서 스켈레톤 수와 애니메이션 이름을 확인한다. 같은 이름의 이전 export를 새 결과로 오인하지 않는다.

현재 검증 환경은 Spine Professional **4.3.26**, 공식 spine-pixi-v8 **4.3.13**, PixiJS **8.20.0**, GSAP **3.13.0**이다. 이는 검증한 조합이며 “항상 최신 버전”이라는 뜻이 아니다. 실제 전투 의존성 추가 시 잠금 파일에 버전을 고정하고, 편집기 내보내기와 런타임의 **major.minor를 일치**시킨다. 환경이나 버전이 바뀐 경우에만 해당 호환성 검증을 갱신한다.

공식 근거: [CLI](https://esotericsoftware.com/spine-command-line-interface), [PixiJS 런타임](https://esotericsoftware.com/spine-pixi), [버전 호환](https://esotericsoftware.com/spine-versioning).

사용자가 지정한 던전앤파이터 참고 영상은 기술별 완성도와 화려함의 기준으로 쓴다. 제작 시 실제 장면의 준비·적중·회수·잔향 시각을 기록하여 비교하며, 제목만으로 동작을 추정하거나 영상의 자산·기술 순서·동선을 그대로 복제하지 않는다.

**이펙트 OFF의 몸·무기 재생과 ON의 최종 연출을 둘 다 제시한다.** 정상 속도 전체 재생이 기준이며 느린 재생과 정지 프레임은 원인 확인을 보조한다. 프레임 개수·파일 생성·수치 검사·높은 FPS만으로 목표 품질 통과를 선언하지 않는다. 사용자 시각 피드백은 기술 검사와 별도로 기록하고, 반려되면 문제 구간을 수정한다.

## 5. 캐릭터 리깅과 원본 보존

- 승인 원화·무기·얼굴·체형·시점을 고정하고 SHA-256, 승인 범위, 이미지별 역할을 기록한다. 카드 sourceArt와 전투 리소스를 분리한다.
- 머리, 몸통, 골반, 팔·손, 다리·발, 천·장식과 필요한 앞뒤 부품을 분리한다. 움직일 때 드러나는 관절 안쪽·몸 뒤쪽·손가락을 보완하고 정지 조립 상태부터 확인한다.
- 피벗은 그림 사각형 중심이 아니라 실제 관절·파지점·발바닥에 둔다. 몸 기준 높이, 바닥 원점, 손 위치, 검날 구간/총구/방출점과 좌표 변환을 기록한다.
- 갑옷·검·총처럼 단단한 부위는 형태를 보존한다. 승인 무기 원본의 전체 이동·회전·균일 배율로 합성하고, 손에 맞추려고 검신만 휘거나 늘리지 않는다.
- **칼 단독 알파 검수:** 캐릭터 합성 전에 칼만 밝은/어두운 배경에 표시한다. 검날의 연속 윤곽·온전한 손잡이·옷 조각 혼입을 확인한다. 원본 픽셀 일치 검사는 선택한 영역의 의미가 올바른지 보장하지 않는다. 가려진 부위는 보완 작화하고 그 영역을 기록한다.
- **무릎 축·굽힘 검수:** 그림의 실제 무릎과 뼈 축을 맞추고 양다리의 굽힘 방향을 큰 자세에서 확인한다. 자동 IK의 방향 추정이나 넓은 y축 가중치만 믿지 않는다. 필요하면 무릎 보조 뼈·보완 작화를 사용하고, 준비/디딤/타격/회수 전체에서 관절 면적과 실루엣을 확인한다.
- **팔 동작 검수:** 어깨 갑옷과 유연한 소매의 움직임을 구분하고 어깨·팔꿈치·손목의 선행/지연, 경로와 구간 속도를 실제 재생에서 판단한다. 모든 관절에 같은 완급을 반복 적용하지 않는다. 사용자 반려는 구조 검사 통과보다 우선하며, 수정안의 시각 승인을 자동으로 기록하지 않는다.
- 양손 무기는 변환 주체 하나와 두 파지점을 정한다. 양손 IK의 순환 제약·이중 변환을 피하고, 전 구간에서 손이 실제 손잡이를 잡는지 확인한다.
- 메시·가중치·IK·draw order·attachment 전환·Physics는 목적에 필요한 것만 사용하고 실제 검수한 기능만 기록한다.
- 먼저 몸과 무기의 주요 자세·속도·접점을 완성한다. 이후 망토·머리카락·장식·잔상과 효과를 붙인다.

완성 용병의 동작 목록은 실제 엔진의 상태 요구에서 정한다. 대기·이동·기본 공격·요청 스킬·피격·사망/퇴장 및 전환을 점검하되, 첫 시험 제작의 3개 동작을 용병 전체 완성으로 보고하지 않는다.

## 6. 기술별 이펙트 공정

효과는 예고/준비 → 방출/무기 궤적 → 접촉 → 최대 파열 → 잔향/소멸로 설계한다. 각 기술의 주 효과는 개별 연속 자산이며 정지 이미지 트윈이나 재색칠로 대체하지 않는다. 공유 연기·먼지·보조광은 보조 계층으로 재사용할 수 있다.

- **검격·근접:** Krita 등으로 필요한 공격 자세와 스미어를 보완하고, 검광은 실제 무기 궤적과 일치시킨다. 과거 포즈 잔상은 공용 시계에서 과거 자세를 샘플링한다. 손그림 스미어와 포즈 잔상을 구분한다.
- **폭발·마법·입자:** Effekseer 등에서 형태·속도·크기·소멸을 제작한다. 기본 전달 방식은 [공식 내보내기](https://effekseer.github.io/Help_Tool/en/ToolReference/record.html)의 투명 이미지 시퀀스/스프라이트 시트다. 별도 Effekseer 실시간 렌더러를 V3에 먼저 추가하지 않는다.
- **합성:** 발광은 additive, 연기·돌·불투명 물질은 normal 등 효과에 맞게 계층을 나눈다. 출력 알파와 Pixi premultiplied alpha 처리를 맞추고 어두운/밝은 배경에서 검은 테두리·빛 번짐을 확인한다.
- **바닥 반응:** 발 디딤·착지·충격의 바닥 좌표를 사용한다. 대상 몸통·검날·총구 접점을 화면 중앙으로 일괄 대체하지 않는다.
- **카메라·타격 정지:** 효과·몸·잔상·예약 사운드가 공용 전투 제어를 따르게 한다. 흔들림과 확대는 타격을 보조하고 진형·카드 도크·배경을 임의 재배치하지 않는다.

출력 시 fps, 프레임 수, 재생 길이, 피벗, 크기/단위, blend/alpha 방식, 효과 소멸 시각, 텍스처 크기와 해시를 기록한다. 고정된 프레임 숫자를 채우기보다 동작의 변화와 전장 크기에서의 가독성으로 판단한다. 이미지 생성·내보내기에 성공한 상태는 최종 타임라인 검수 완료가 아니다.

## 7. V3.5 런타임 연동 계약

- 현재 V3의 BattleEngine, EffectScene, 액터/아트 어댑터, 진형, 카드 도크, 카메라와 효과 레이어를 재사용한다. Spine은 기존 Pixi 트리에 연결한다. 두 번째 Application/캔버스·중복 Pixi·별도 CDN 사본을 추가하지 않는다.
- 전투 재생 컨트롤러와 GSAP 타임라인이 시간의 주체다. Spine의 autoUpdate를 끄고 공용 시각에서 한 번만 진행한다. Spine 내부 애니메이션 시간과 이펙트 프레임을 서로 다른 ticker나 wall clock으로 진행하지 않는다.
- Spine AnimationState의 전환·mixing·Physics가 있는 경우 그 상태를 반영한 진행/초기화/재샘플링을 구현한다. 검증 예제의 단순 trackTime 지정과 update(0)을 모든 전투 상태의 탐색 해법으로 일반화하지 않는다.
- 전역 이동과 Spine root motion 중 이동의 소유자를 하나로 정한다. 발바닥·파지점·검날/총구의 skeleton-local→V3 world 변환과 좌우 반전을 검증한다.
- 서버가 확정한 대상·타수·피해·승패를 재생한다. Spine event는 visual_contact 등 연출 표식으로만 사용하며 피해를 중복 발생시키거나 새 전투 수치를 만들지 않는다.
- 배속·일시정지·히트스톱·시킹·재시작·중단·화면 비활성을 몸·효과·카메라·사운드에 함께 적용한다. 재시킹과 루프 때문에 충돌·사운드가 중복 발화하지 않게 한다.
- 전투 종료·화면 이탈·세션 교체 시 등록한 타임라인·ticker listener·표시 객체·예약 사운드를 해제한다. 다른 액터가 사용하는 공유 텍스처를 파괴하지 않는다.
- 필요한 에셋만 로드하고 인스턴스 수·아틀라스 페이지·텍스처 메모리·동시 효과와 프레임 시간을 기록한다. 첫 용병의 실제 표시 크기와 동시 출전 조건을 기준으로 예산을 정한다. 미측정 실기기 FPS를 보장하지 않는다.

기존 환경 검증은 V3의 공용 effectScene에서 Spine 재생이 가능하다는 근거다. 실제 액터 교체·서버 전투 이벤트·PVE/PVP·모바일 성능까지 통과했다는 뜻으로 확대하지 않는다.

## 10. 기존 V3 업그레이드·다양한 동적 포즈 — 후속 지시

V3.5는 **현재 V3의 업그레이드**다. 구현 전에 현재 V3 리소스의 대기/준비/공격/후속/복귀, 개별 전용 모션과 범용 모션, 신체 높이·발 기준점·좌우 방향·공용 시계·서버 이벤트를 확인한다. 새 Spine은 같은 전장·BattleCharacter·편성·HUD·카드 도크 안에서 기존 용병과 혼합해 검수한다. 별도 프리뷰 통과를 실제 V3 연결로 대체하지 않는다.

사용자 “횡스크롤이라고 칼이 꼭 위아래로 흔들리는게 아니라 … 다양한 포즈 … 역동적으로”를 적용한다. 몸통 비틀기, 낮은 횡베기, 역방향 사선 베기, 찌르기, 몸을 돌린 마무리는 각각 발 지지와 실루엣이 다른 동작으로 설계한다. 큰 시점 변화는 몸통·팔·손의 교체 작화를 사용하고, 원래 그림/검의 회전과 효과 색 변경만으로 완료하지 않는다. 접근·후퇴의 발걸음과 공격의 제자리 디딤도 분리한다.

[현재 V3 점검·로컬 연결 기록](../preview/v35-v3-upgrade-20261101/PROJECT.md): 현재 빌드 소스326개 일치, 대표 기존 용병4종의 기본 공격, Spine 혼합 재생과 실제 TURN 이벤트 연결을 확인했다. 390px 브라우저는 실기기 성능 검수가 아니며 전체 PVP·협동전·모든 용병/스킬 검사도 아니다. 최신7400 native는 그대로 사용했으므로 이번 연결 검사를 새 동적 포즈 제작 완료로 적지 않는다. 사용자 “좀 낫네 그래도 갈길이 되게 먼데”는 최종 승인과 구분한다.
