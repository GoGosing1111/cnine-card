# 족각도시 피격 알림 누락 수정 — 2026-10-11

사용자 신고: “족각도시 공격받는 팝업 안뜨던데 잘뜨냐 이제?”

## 재현한 원인

1. 운영 `apiUserToLocal()`은 `serverUserId`를 저장하는데 알림 루프는 `user.id`만 검사했다. 운영과 같은 `{serverUserId:4,nickname:...}` 계정으로 확인했을 때 알림 조회 0회, 팝업 0개였다. 기존 시연의 `{id:4}` 형태로는 드러나지 않았던 문제다.
2. 기존 알림은 `document.body`에 붙어 인벤토리의 네이티브 모달 뒤에서 클릭 불가 상태가 됐다. 표시 직후 서버 ACK까지 보내므로 실제 확인 전에 읽음 처리됐다. 수정 전 실제 브라우저 재현: 닫기 버튼 중앙의 hit target은 `DIALOG.jc.jc-desk`, `buttonInFront=false`, `read_at>0`.

## 수정 동작

- 알림·사망 상태의 계정 식별에 `serverUserId`를 우선하고 기존 `id` 시연 형태도 지원한다. 로그인/계정 변경, 도시 입장, 화면 복귀 때 알림 조회를 다시 깨운다.
- `mountCityNoticeLayer()`가 알림을 현재 모달 내부에 연결하고 수동 Popover로 위에 표시한다. 모달이 추가·닫힘·제거되거나 내부가 다시 그려져도 같은 알림을 다시 연결한다. 수동 Popover를 지원하지 않으면 모달 안에 배치한다.
- 본문에 붙인 Popover만으로는 모달 밖 요소의 inert 상태가 해결되지 않는 점을 실제 Chrome에서 확인했다. 모달 내부 연결 후 `elementFromPoint()`와 실제 클릭으로 검증했다. API 기본 동작 참고: [MDN Using the Popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using).
- 알림 표시만으로 읽음 처리하지 않는다. 닫기 또는 기록 보기를 누른 경우에만 해당 ID를 로컬에 기록하고 서버에 ACK한다. ACK 실패는 다음 조회에서 재시도한다.
- 응답 도착 시 화면이 숨겨졌으면 새 알림을 표시·ACK하지 않고 복귀 때 보여 준다. 확인 전 새로고침은 같은 미확인 알림을 복구한다. 로그아웃과 요청 도중 계정 변경에는 이전 계정 알림을 표시하지 않는다.
- 알림 자체가 포커스를 가져가거나 게임 전투·타이머를 중단하지 않는다. 도시 체류 중 일반 조회 간격은 기존 8초 + 0~1초 분산/통신 시간이다. OS 푸시나 닫힌 앱 알림을 추가한 작업은 아니다.
