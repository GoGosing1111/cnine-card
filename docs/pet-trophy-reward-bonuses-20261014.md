# 펫 장착 · 트로피 보유 보너스 — 2026-10-14

사용자 요청은 펫 장착 효과와 트로피 보유 효과에 드랍률 증가·레벨업 경험치·코인 보너스를 추가하는 것이다. 후속 답변 **“계정 레벨 경험치”**, **“초기 0%로 두고 CMS에서 직접 설정”**을 적용한다.

## 설정과 표시

- OWNER CMS → **펫 관리 → 장착 보너스**: 펫별 세 항목. 기존 시작 버프·대상·모드는 보존한다. 장착 보너스는 전투 시작 버프의 대상/모드와 별개인 보상 효과이며, `실제 펫 효과 사용` OFF이면 함께 적용하지 않는다.
- OWNER CMS → **트로피 보유 효과**: 기존 트로피 8종별 세 항목. 각각 0~1000%, 소수 둘째 자리까지 입력한다. 빈 값·음수·비수치·알 수 없는 코드/필드는 저장하지 않는다.
- 기존 펫 설정에 필드가 없어도 0%로 읽고, 트로피 설정이 없으면 전체 0% 문서를 읽기 전용으로 제공한다. 최초 조회나 배포로 운영 CMS에 기본값을 쓰지 않는다. 펫 19종의 기존 운영 문서 revision 18, 새 보너스 미설정 상태를 배포 전 읽기 전용으로 확인했다.
- 펫 도감/장착창은 선택한 펫의 수치와 장착 상태를 표시한다. 명함 트로피 진열장은 종류별 효과, 미획득 안내, 보유 트로피 합계를 표시한다.
- `GET /api/collection-bonuses`는 본인의 실제 펫/트로피별 합계를 제공한다. OWNER 전용 `GET/PATCH /api/admin/trophy-bonuses`는 기존 권한과 동일 출처 검사를 사용한다. 개인/관리 응답은 `private, no-store`다.

## 계산과 적용 범위

실제로 보유한 장착 펫 1마리와 획득한 트로피 종류별 보너스를 합산한다. 펫 10마리나 같은 트로피 여러 개를 보유해도 해당 종류의 설정은 한 번만 더한다. 종류가 다른 트로피는 모두 합산한다. 트로피 획득 여부는 기존 공식 시즌·우승·누적 실적 기록으로 확인하며 화면 조회로 트로피를 지급하거나 시즌을 정산하지 않는다.

- **드랍률**: 기존 확률 × (1 + 합산 보너스/100). 기본 10%에 +20%이면 12%이며 30%가 아니다. 최대 100%, 0%는 그대로다. 한 번 선택하는 가중치 풀은 미획득 몫만 줄이고 코인 당첨 확률·아이템 간 상대 비중·선택 횟수를 보존한다.
- **계정 경험치**: 기존 계정 경험치 지급 경로에 합산 보너스를 한 번 적용한다. 기존 틱 단위로 소수점을 버리고 만렙 한도를 유지한다. 용병 재료 경험치·용병 레벨과 무관하며 용병 성장 기능은 계속 OFF다.
- **코인**: 기존 아바타·계급·버닝 계산을 유지한 뒤 합산 보너스를 한 번 적용한다. 정수 보상 계산은 정밀도를 보존한다. 보너스 포함 금액에도 콘텐츠의 기존 일일·주간 횟수, 드랍 수량 한도, 반복 탑 코인 상한을 적용한다.
- 적용 경로: 개인 토벌/연속 토벌·아포칼립스, 원정(폐차장·카우룸·균열·호송), 기존 방치 콘텐츠의 계정 경험치/코인, 일반 PVP·듀오 승리 코인, 레이드 참여/클리어, 공성·봉인전, 탑과 통합 드랍. 군단 사냥의 지역/보스 확률과 카우룸 포탈 최초 판정에도 드랍 보너스를 적용한다. 각 경로에 이미 존재하는 보상만 보강하며 새 보상 종류를 만들지 않는다.
- 제외: 메시지·쿠폰·직접 운영 지급·환급·거래·시즌 순위 보상, 도시 현금, 카드/용병 합성·팩 개봉·강화 확률, 별도 보호권 드랍 정책. 코인 보너스가 조각이나 기타 아이템 수량을 늘리지 않는다.

## 보존과 거래

- 펫의 기존 `pet_cms_preparation_v1`에 선택적인 `rewardBonuses`만 추가한다. 트로피는 기존 `app_meta`의 `trophy_reward_bonuses_v1`에 저장하며 새 테이블/마이그레이션/권한 기반 변경은 없다.
- 트로피 CMS 저장은 버전 비교와 단일 조건부 쓰기, 요청 ID·작성자·내용 해시로 충돌/중복을 처리한다. 동일 요청의 다른 내용은 거부하고 마지막 50개 저장 영수증을 보존한다.
- 서버 요청 안에서는 계정별 보유/장착/설정 조회를 공유한다. 다음 요청에서 장착 해제나 CMS 변경을 다시 읽는다. 전체 트로피 보너스가 0%이면 보상 요청에 트로피 이력 조회를 추가하지 않는다.
- 기존 XP 영수증, 지갑/지급 로그/보상 완료의 거래 단위는 그대로 사용한다. 실패는 함께 롤백하고 완료 영수증 재시도는 추가 지급하지 않는다.
- 듀오는 입장 시 승리 보너스 금액을 고정한다. 코어 추가 보상은 봉인 생성 시 선택지와 최소 보상을 함께 고정한다. 기존 봉인과 일반 레이드/탑/연속 전투의 저장된 보상 계획, 포탈의 저장된 판정은 재가격·재추첨하지 않는다.
- 트로피의 읽기 전용 듀오 조회를 `_ranked_duo_honors.js`로 분리해 보너스→트로피→시즌 스케줄러→전투 정산의 순환 import를 제거했다. 조회 SQL과 시즌 처리 정책은 동일하다.
