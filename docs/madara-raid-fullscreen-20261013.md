# 마다라 레이드 전투 화면 분리 — 2026-10-13

마다라 출정 후에도 전장이 `pveRaidHubView` 내부에 남아 PVE 메뉴와 함께 표시되던 문제를 수정한다. 모집·준비 화면은 원래 작전실에 두고, 전투와 결과 확인은 문서 최상위의 독립된 전체 화면에서 표시한다.

## 변경

- 서버가 보낸 전투 상태를 표시하기 전에 마다라 화면을 `body` 바로 아래로 옮긴다. 공용 V3 렌더러·진형·기믹·서버 판정은 그대로 사용한다.
- PC/PWA와 모바일 화면 전체를 채우고, 배경 메뉴 입력·배경 스크롤을 잠근다. 기믹 조작·공략·퇴장 확인창은 전투 화면 안에서 정상 작동한다.
- 퇴장이나 결과 확인 후 기존 작전실로 돌려놓고 스크롤·포커스·입력 잠금을 복구한다. 다른 콘텐츠로 이동해 작전실 자체가 제거돼도 별도 전장과 타이머가 남지 않는다. 종료된 인스턴스가 늦은 응답으로 화면을 다시 열지 못하게 한다.
- Escape는 기존 퇴장 확인창을 연다. 취소 시 전투를 유지한다. 공대 퇴장과 보상 정책을 변경하지 않는다.
- 메인 진입 스크립트 → inline 모듈 → runtime/CSS → 전투 화면 모듈의 캐시 주소를 `20261013-fullscreen1`로 갱신한다. 생성 파일은 `scripts/build-madara-live.mjs`로 재생성한다.

## 범위 검수

- 실제 메인 HTML과 기존 로컬 서버 fixture를 사용한다. 운영 공대나 재화를 생성하지 않는다.
- 수정 전 브라우저 검수에서 `Combat must leave the nested raid hub and mount directly under body` 단언이 실패해 기존 중첩 화면을 재현했다.
- 최초 수정본은 1440×1000, 390×844에서 화면 크기·배경 입력 잠금·퇴장/결과 복귀·재입장·폴링 종료를 통과했다. 두 화면의 전투/기믹 스크린샷을 직접 확인했다.
- 최종 배포 검사는 `tests/madara-raid-live-20261011.browser.mjs`를 `MADARA_GAME_ONLY=1`로 실행한다. 기믹 실제 클릭, 새로고침 후 복구, 상위 게임 화면 교체 시 정리도 포함한다. 변경 없는 CMS/서버 경제 검사와 전체 게이트는 반복하지 않는다.
