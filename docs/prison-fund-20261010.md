# 감옥 영치금 본인 납부 제한 · 5조 한도

사용자 요청: 본인의 영치금 직접 납부 차단, `100억`·`1조` 단위 표시, 최대 석방금 5조 코인.

- 서버는 인증 계정과 수감자가 같으면 납부 영수증 조회·코인 차감 전에 403을 반환한다. OWNER도 본인 납부 예외가 없다.
- 본인 화면은 납부 입력·버튼 대신 제한 안내를 표시한다. 다른 수감자 선택 시 기존 모금 입력을 표시한다.
- 모금액·석방금·남은 금액·최근 납부·잔액 안내는 만·억·조 단위와 최대 소수점 2자리로 표시한다. 단위 경계에서 금액을 올려 표시하지 않는다. 입력·전송·차감은 기존 정수 단위이며 진행 수치의 title에는 정확한 금액을 보존한다.
- OWNER 설정은 0~5,000,000,000,000 코인 정수만 허용한다. 0은 모금 비활성화다. 저장된 기존 석방금과 모금액은 자동 변경하지 않는다.
- DB 구조·공통 인증·거래 처리·기능 출시 상태는 변경하지 않는다. 캐시 태그는 `20261010-prison-fund`다.

## 검수

- `node --test tests/prison-fund-20261010.test.mjs`: 10개 통과. PostgreSQL 호환 계층/PGlite에서 본인 USER·OWNER 차단, 5조 허용/초과 거부, 방문객·다른 수감자 모금, 중복 요청, 모금 완료 석방, 거래 중 오류 롤백 및 동일 번호 재시도 확인.
- `node --check js/app.js`, `git diff --check` 통과.
- 운영 감옥 함수·CSS를 사용하는 로컬 검수 화면에서 PC 1440×1000, 모바일 390×844 확인. 본인 납부 숨김, 다른 수감자 모금 전환, `100억`·`1조`·`5조` 표시, 5조 입력 한도, 가능 전액 4조 입력, 가로 넘침 없음 확인.

## Scoped 배포

- 직전 운영 배포: `a430795df702f65b0a83b116aae1e01c5813b872` (Cloudflare Pages `67b85f4b-b516-41b0-adb0-7b0c6fc57dcf`). 이후 main 변경은 운영 기록·지급 스크립트이며 추가 게임 런타임 변경은 없다.
