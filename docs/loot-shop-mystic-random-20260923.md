# 고급 전리품 상점 — 미스틱 4종 랜덤 지급

## 승인 범위

- 사용자 승인: 미스틱 슈트·레깅스·슈즈·듀얼디스크 중 각 25%로 장비 1개 지급, 꽝 없음.
- 미스틱의 `확정 지급 장비` 선택을 없애고 CMS에 4종 고정 확률을 표시한다. F바디는 기존 확정 지급을 유지한다.
- 보유 여부와 무관하게 중복 획득 가능. 새 MYTHIC/미스틱 장비는 자동 편입하지 않는다.
- 운영 CMS에서 읽기 전용으로 확인한 기존 설정: r9, 가격 50 피그 코인, 계정당 누적 3회, 미스틱 상품 판매 OFF. 전체 상점 판매와 콘텐츠 지급은 ON. 이 배포는 가격·한도·상품 ID·운영 스위치·기존 구매 이력을 변경하지 않는다.
- 별도 운영 DB 마이그레이션이나 정책 저장이 필요하지 않다. 운영자가 기존 `상품 판매 사용`을 켜서 저장하면 랜덤 상품으로 판매된다.

## 구현 및 호환성

- 단일 후보 목록은 `shared/loot-shop-policy-v1.mjs`의 정확한 4개 이름과 실제 등급 `MYTHIC`이다. 각 이름이 정확히 1개씩 공개·활성 상태여야 구매 가능하다.
- 서버의 Web Crypto 기반 균등 정수 추첨을 사용한다. 브라우저에서 장비 ID나 추첨값을 보내는 요청은 허용하지 않는다.
- `joint_operations_v1.plan_json`에 추첨 결과와 4종의 ID/code/name을 먼저 고정한다. 동일 요청 재시도·응답 유실은 이 기록을 재사용한다.
- 차감 거래 안에서 정책, 전체 4종 구성, 고정된 카탈로그 식별값, 구매 한도와 잔액을 다시 검증한다. 코인 차감·장비 1개 지급·구매 이력·완료 처리를 같은 원자적 배치로 처리한다.
- 일부 장비가 비공개·비활성·삭제·중복 정의·다른 ID/code로 교체되면 확률을 재조정하거나 재추첨하지 않는다. 실패 시 코인·구매 횟수·장비 지급은 전부 롤백한다.
- 이전 버전의 진행 중인 확정지급 요청은 원래 장비로 완료한다. 완료된 과거 영수증은 추가 차감·지급 없이 재조회한다. 새 구매만 랜덤 추첨하며 기존 상품 구매 횟수는 그대로 누적한다.
- 새 구매 영수증 `product_json.equipmentReward`에도 실제 획득 결과를 남긴다. 플레이어 화면은 4종 확률, 중복 가능 여부와 실제 획득 장비명·이미지를 표시한다.
- DB 연결·Hyperdrive·Neon 계정·장비 강화 기능은 변경하지 않았다. 후보 목록은 요청 단위로만 공유하며 전역 계정 상태/DB 클라이언트 캐시를 추가하지 않았다.

## 검증

- `npm run test:loot-shop`: 77개 통과, 실패 0. SQLite와 PostgreSQL(PGlite/운영 호환 계층) 모두 검증했다.
- 네 가지 추첨 구간, 잘못된 추첨값, 1개 지급, 추가 MYTHIC 제외, 누락·중복·잘못된 등급·비공개·비활성 차단, 지급 실패 롤백, 미선택 후보 변경 감지, 고정된 장비 식별값 교체 차단을 확인했다.
- 커밋 후 응답 유실, 같은 요청 동시 실행, 마지막 구매 한도 경합, 타 계정 재사용, 판매 OFF, 미결 요청 중 가격 변경, 과거 확정지급 영수증 호환성을 확인했다.
- 격리 검수 서버: `LOOT_QA_LOSE_ACK=1 node scripts/qa-loot-shop-mystic-cms.mjs`. 로컬 메모리 DB와 검수 토큰만 사용하며 운영 계정 코인은 사용하지 않는다.
- 실제 브라우저에서 CMS의 확정 장비 선택 없이 저장, 데스크톱·390px 모바일 4종 표시, 유저 구성/확률 팝업, 가격·잔여 한도 확인, 구매 성공 뒤 응답 유실을 확인했다.
- 응답 유실 뒤 새로고침 → 결과 확인으로 복구: 잔액 500→475, 미스틱 슈트 1개 결과 표시. 재시도 추가 차감 없음. 모바일 가로 넘침 없음(문서 너비 375px = 스크롤 너비 375px).
- 로컬 QA의 장비 이미지는 명시적인 격리 fixture 이미지다. 운영 화면은 공개 장비 카탈로그의 실제 이미지를 사용한다.
- 캐시 갱신: 플레이어 JS/CSS `20260923.1`, CMS JS/shared `v6`, CMS CSS `v2`.

운영 배포는 깨끗한 범위 커밋을 origin/main에 반영한 후 `npm run deploy:production`을 사용한다. 이 명령의 전체 `release:gate`와 Hyperdrive 캐시 OFF 검사 통과 후 배포하며, 배포 후 CMS 설정 보존과 실제 카탈로그 연결을 읽기 전용으로 확인한다.
