# 대회 펀딩 사은품 메시지 지급

- 사용자 지시: 확인된 후원자에게 대회 사은품을 메시지로 지급하며 내용은 **대회 펀딩 사은품**.
- 같은 SOOP 닉네임의 여러 팀 후원은 합치고, 100개 이상 후원 및 댓글 대응을 확인한 46명에게 계정당 `TOURNAMENT_GIFT_BOX` **1개**를 첨부한다. 제목과 본문 모두 지정 문구를 그대로 사용한다.
- 운영 계정 대조 결과는 `tournament-funding-gift-recipients-20260927.json`에 기록했다. 나머지 미확인 36명은 이번 발송 범위에 포함하지 않는다.
- 사용자 후속 확인: 뚱초환 / 박세라-ㅂ-. `veil`은 운영 표기 `Veil`(4629), `[moo]족쪽이`는 원 댓글 작성자와 일치하는 운영 `[C9]족쪽이`(303)다.
- 커피 계정은 `커피먹는철구`(22)를 후보로 제시한 확인 질문에 사용자가 `커피먹은철구`라고 답했다. 이를 제시된 계정 확인으로 해석했고, 운영의 정확한 표기 `커피먹는철구`로 연결한다고 사용자에게 알렸다.
- 기존 SSS 용병 지급·대회 성황리 기념 코인/별 메시지와 별개다. 이번 캠페인의 메시지·상자 첨부 내역만 중복 검사한다.

## 수령 연결과 범위 검사

- 대회 사은품이 메시지 수령 허용 목록에 없어, 서버 보상 정의 및 클라이언트 표시 목록에 해당 항목만 추가했다. 기존 메시지 수령 트랜잭션과 인벤토리 경로를 재사용하고 수령 전 기존 카탈로그 초기화를 호출한다.
- `messageOnly:true`를 유지해 쿠폰 보상으로 확장하지 않는다. 보상 수치, 개봉 정책, 스키마, 공통 거래 기반은 바꾸지 않는다.
- `scripts/ops/tournament-funding-gift-20260927.mjs`는 운영 런타임에 연결하지 않는 일회 도구다. 최대 82명의 명시적인 대상만 일괄 조회·삽입한다. 수신자 해시와 실제 계정 이름·상태·카탈로그를 검증한다.
- `tournament-funding-gift-20260927-v1` 캠페인의 계정별 고유 제약, 수신자 해시별 완료 영수증 및 감사 로그를 사용한다. 메시지·첨부 보상·감사·완료 기록을 한 REPEATABLE READ 트랜잭션으로 확정한다. 발송 시 지갑이나 인벤토리에 직접 지급하거나 대신 수령하지 않는다.
- 도구 회귀 7개 통과: 정확한 수신자·문구·1개 첨부·재시도, 감사/보상 실패 롤백, dry-run/닉네임 변경/중복 대상 차단, COMMIT 응답 유실, 다른 작업의 중복 지급 차단, 부분 삽입/완료 기록 누락 롤백.
- 운영 `messagesView`·`loadMessages`·메시지 CSS를 사용하는 API fixture에서 PC 1440×980 개별 수령, 모바일 390×844 일괄 수령을 각각 확인했다. 두 화면에 상자 1개와 지정 문구 표시, 수령 요청 각각 1회, 가로 넘침 없음. 실제 계정의 메시지를 대신 수령하지 않았다.
- 관련 초기 검사에서 기존 테스트의 고정 2종 선물 목록을 새 상자 검사와 함께 확장한 오류를 발견했다. 기존 대량 발송 테스트 2종은 유지하고 상자 거래 회귀만 별도로 추가했다.

## 운영 반영 계획

- 직전 운영 배포는 Cloudflare 목록의 `bdf3d2e4-a385-4068-a5af-359d54461182`, 소스 `e7eda1cd8b9da61925e10778d0b90d6826eebd10`으로 확인했다.
- 국소 메시지 수령 지원 추가이므로 `npm run deploy:production -- --scoped`를 사용한다.
- 선택 회귀: `tests/message-gift-rewards-v2044.test.mjs`, `tests/message-reward-client-parity-v1929.test.mjs`, `tests/tournament-gift-20260926.test.mjs`. 도구 7개 검사는 동일한 소스에서 이미 통과해 중복 실행하지 않는다. Worker 문법/컴파일, 출시 조건 및 Hyperdrive 캐시 검사는 지정 배포 도구에서 수행한다.
- 수령 연결의 운영 배포 및 검증 후, 대상 46명의 운영 dry-run 롤백과 별도 조회를 확인한 다음 실제 메시지를 발송한다. 발송 후 개별 수신자·제목·본문·상자 종류·수량·감사·완료 영수증을 별도 READ ONLY 연결에서 검증한다.
