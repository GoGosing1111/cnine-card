## 성능·획득

기본 전투력 297,000, 핏빛 만찬 1,008%, 비용 20, 재사용 1행동. 잃은 체력에 따른 기존 추격 피해 규칙을 사용한다. 자연 행동 속도 2.75배, 아군 카드 4행동당 추가 13행동, 자기 행동 에너지 10, 연계 공격/체력/방벽 1,452%/1,848%/990%다. PVP 스킬/기본 공격 상한은 2.7배/1.5배다. PVE에서는 바토리 프로필에만 기존 스킬 최소 피해 예산을 적용했다. 표시·성장은 SS이며 기존 SS 리미티드의 SSS 전투 보정은 그대로 따른다.

기존 할로윈 SS 7종과 동일 편성·장비·성장·양 진영으로 1,008회 비교했으며 상대별 승률은 약 76.4~95.8%였다. PVE 64회 비교에서도 바토리가 두 측정 조건 모두 가장 빨랐다. 이는 고정 조건 시뮬레이션이며 실제 이용자 승률 보장이 아니다. 기존 7종 및 강윤의 값을 변경하지 않았다.

서버 전체 발행 상한 **10장**을 고정하며 10번째 동시 구매, 11번째 대체 지급, 중복 요청의 재차감 방지를 검증했다. 일반 팩·일반 합성 풀에는 추가하지 않는다. 기존 할로윈 팩의 ON/OFF, 가격, 기존 확률을 보존한다. 바토리 확률은 사용자 미지정이므로 **0%**로 준비하고 OWNER가 지정하기 전 추첨되지 않는다. 자동 지급은 없다. 도감과 OWNER CMS에 10장·남은 수량을 표시한다.

## 배포 준비와 운영 변경 순서

`release-plan.json`이 승인 대기 상태의 단일 출시 기록이다. 검수 완료를 출시 승인으로 바꾸지 않는다. 2026-10-19 15:01 KST 읽기 전용 조회에서는 V-977 재고·보유·발행·CMS 충돌이 없었고 운영 팩은 revision 13 / ON이었다. 저장 당시 해시는 기록용이며 실제 등록 전 반드시 갱신한다.

1. 사용자의 원화/모션·출시 승인을 기록하고 최신 origin/main을 반영한다. 마지막 운영 배포 SHA를 확인한다.
2. `SCOPED_DEPLOY_BASE`, 변경 이유, `release-plan.json`의 관련 테스트 목록, `check:worker`를 설정한다. 깨끗한 커밋을 origin/main에 반영하고 `npm run deploy:production -- --scoped`를 사용한다. 게이트를 우회하지 않는다.
3. **코드를 먼저 배포한 후** `node preview/mercenary-bathory-halloween-20261019-v1/read-live-preflight.mjs`로 현재 팩 해시와 코드 충돌을 재확인한다. 새 필드를 모르는 구버전 서버에 설정부터 쓰지 않는다.
4. `node scripts/ops/run-bathory-registration-20261019.mjs dry-run <최신 문서 SHA-256>` 후, 승인 참조와 동일 해시로 `apply <최신 문서 SHA-256> <사용자 승인 참조>`를 실행한다. `verify`로 재고 10·발행 0·원장·기존 팩 보존을 확인한다. 해시가 달라지면 강행하지 않고 최신 변경을 확인한다.
5. 도감/CMS 및 실제 공용 전투 리소스 URL을 짧게 확인한다. 0%를 임의로 개방하거나 무료 지급하지 않는다.

등록은 기존 스키마를 사용하며 마이그레이션이 없다. 팩 설정 CAS, DB 잠금, 재고·감사·완료 영수증을 한 거래로 저장한다. 중복 키는 `ops:bathory-halloween-registration:20261019:v1`이다. 로컬 격리 DB에서 성공/롤백/부분 실패를 검증했으며 운영에 쓰기는 실행하지 않았다. 발행 이후에는 재고나 보유 원장을 되감지 않는다.
