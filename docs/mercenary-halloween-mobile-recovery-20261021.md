# 할로윈팩 모바일 결과 자동 재확인 — 2026-10-21

사용자 “모바일에서 주로 그런다는거같은데” 제보의 [진단](qa/halloween-load-20261021/mobile/README.md) 후 “고쳐” 요청에 따라 미확인 결과 복구를 수정했다.

## 변경

- 개봉 응답 유실 뒤 첫 영수증 조회가 실패하거나 PENDING이면 같은 요청의 영수증을 1초·3초·8초 간격으로 최대 세 번 추가 조회한다. 정상 완료에는 추가 조회가 없다.
- 온라인·화면 복귀 시 미확인 요청의 첫 조회를 즉시 시작한다. 대기 중이거나 실행 중인 조회는 하나로 합친다. 숨김·오프라인에서는 대기 및 자동 조회를 중단하고, 닫힘·계정 변경·인증/권한 오류·잘못된 저장 상태에도 계속 반복하지 않는다.
- 자동 조회에는 요청별 8초 제한을 전달한다. 공통 전송 계층의 계정 epoch 검사와 한 번의 재조회는 유지한다. 취소된 조회에 늦게 도착한 완료·취소 응답은 저장 기록·결과·잔액에 반영하지 않는다.
- 조회는 GET만 사용한다. 불명확한 404로 pending을 지우지 않으며 자동 POST·새 UUID 구매·자동뽑기 재개를 하지 않는다. 반복 확인 후에도 완료되지 않으면 기존 수동 확인을 사용하고, 명시적인 복구 POST는 저장된 동일 UUID를 사용한다.
- 오프라인 전환도 자동뽑기를 중지한다. 이미 요청한 개봉 결과까지 확인하고 다음 구매는 사용자의 새 동작을 기다린다.

기존 할로윈 화면·이미지·버튼을 유지하고 상태 문구와 복구 동작만 변경했다. 서버 개봉·락·거래·확률·재고·비용·공통 통신 코드는 변경하지 않았다. 메인 앱과 할로윈 모듈 캐시 키를 갱신했다.

## 검증

- 신규 회귀 `tests/mercenary-halloween-mobile-recovery-20261021.test.mjs` 10개 통과: 세 번 제한, 이벤트 합치기, 숨김/오프라인, 다른 작업 종료 대기, 취소와 복귀 경합, 권한 실패 중단, 폐기, 원래 요청 GET만 사용, 늦은 응답·계정 전환 차단, 실제 앱 로더 연결.
- `tests/mercenary-halloween-mobile-recovery-20261021.browser.mjs` 12조건 통과: PC·Pixel 7 Chromium 에뮬레이션에서 실제 연결 중단 후 온라인 복귀, 지연 완료, 연속 epoch 변경, 숨김/복귀, 자동뽑기 중 연결 단절. 모바일에서는 조회 한도 소진 후 수동 복구와 닫힘/재진입도 확인했다.
- 모든 조건에서 완료 결과 10개, 구매 fetch 1회, 요청 ID 1개, 모의 차감 1회, pending 해제, 버튼 활성화, JavaScript 오류 0건이다. missing 사례는 초기 GET+추가 GET 3회 뒤 멈췄고 수동 클릭 후에만 원래 UUID의 POST가 실행됐다. 자동뽑기는 복구 뒤 재시작하지 않았다.
- 브라우저는 실제 전송 계층을 사용하되, 의도적으로 응답을 보류한 POST의 타임아웃만 700ms로 줄였다. 자동 영수증 조회는 실제 8초 옵션이다. 숨김/복귀 이벤트는 격리 주입이며 물리 휴대폰 OS 검수로 표현하지 않는다. 정상 30초 전송 제한은 앞선 진단에서 별도 확인했다.
- PC·모바일 복구 결과 화면을 직접 확인했다. 기존 5열/3열 결과와 고정 버튼에 가로 넘침·새 겹침이 없으며 새 사용자 시각 승인을 뜻하지 않는다.
- 브라우저 최초 검증에서 타이머 함수를 객체 메서드로 호출해 생긴 `Illegal invocation`을 찾아 기본 타이머를 래퍼로 수정했다. 해당 실제 브라우저 검증을 완료했고 무관한 검사로 확대하지 않았다.

기존 저장 공간·재입장/수동 복구 회귀 7개도 scoped 배포 단계에서 통과했다. 관련 회귀는 합계 17개다. 이미 통과한 신규 검사와 브라우저 전체는 배포 과정에서 반복하지 않았다. 결과 자료와 PC/모바일 화면은 `docs/qa/halloween-mobile-recovery-20261021/`에 보존한다.
