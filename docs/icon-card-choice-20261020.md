# 아이콘 카드 선택권 · 시즌패스 보상 연동

사용자 요청에 따라 `ICON_CARD_CHOICE_TICKET`(아이콘 카드 선택권)을 추가한다. 인벤토리에서 카드를 선택한 뒤 확정하면 선택권 1개로 해당 ICON 카드 1장을 받는다. 코인·마스터의 별·재료 카드는 소모하지 않는다. 기존 보유 카드의 강화 단계·실패 누적을 유지하고 수량만 1장 늘린다.

대상은 현재 일반 제작 가능한 디임·하이희야·나무늘봉순·오조은·오리꿍·강구열·아윤·구수댕 8종이다. 제우스 철구와 별도 준비 중인 신규 아이콘은 포함하지 않는다. 이후 추가되는 카드가 자동 편입되지 않도록 공통 정의 `shared/icon-card-choice-v1.mjs`에 8종을 고정한다. 운영 DB에서 카드·멤버가 비활성 또는 비공개로 변경되면 획득을 차단한다.

## 시즌패스 설정

OWNER CMS → 후원 운영 → 시즌패스 보상표에서 날짜를 선택하고 **아이콘 카드 선택권**을 검색한 뒤 수량을 입력해 추가·저장한다. 기존 활성 인벤토리 아이템 카탈로그를 사용하므로 별도 시즌패스 전용 지급 분기를 추가하지 않는다. 현재 운영 보상표·ON/OFF·후원 기간·이미 수령한 날짜는 변경하지 않는다. 이번 등록으로 사용자에게 선택권을 지급하지 않는다.

## 거래와 복구

- 인증·같은 출처 확인·계정 단위 거래 잠금과 기존 `joint_operations_v1` 영수증을 사용한다. DB 스키마·공통 인증·공통 거래 도구는 변경하지 않는다.
- 선택권 차감·인벤토리 로그·카드 수량 증가·완료 영수증을 하나의 원자 거래로 저장한다. 실패 시 모두 취소한다. 요청 번호를 재사용하면 추가 차감·추가 지급하지 않는다.
- 브라우저가 요청 번호를 먼저 보관하며, 지급 후 응답이 끊기거나 창을 닫아도 재입장 시 이전 영수증을 조회한다. 완료 영수증은 재지급 없이 결과만 보여준다. 미완료 요청이 있으면 새 요청을 막는다.
- 마지막 선택권을 사용해 보유 수량이 0개가 되어도 인벤토리의 이전 아이템 사용 결과에서 복구할 수 있다. 결과 확인은 명시적으로 버튼을 눌러 진행하고 인벤토리 진입만으로 자동 사용하지 않는다.
- 운영 등록은 `scripts/ops/icon-card-choice-20261020.mjs`의 일회 거래다. `ops:icon-card-choice:20261020:v1` 영수증·관리자 로그와 함께 아이템 한 종만 등록한다. 재실행은 기존 결과를 돌려주고 운영자의 후속 편집을 덮어쓰지 않는다.

## 이미지와 화면

내장 `image_gen.imagegen`으로 투명 선택권 원본과 남색·백금·금 장식 선택창 프레임을 제작하고 실제 인벤토리 아이템·선택창·확정 버튼·결과 화면에 연결했다. PNG 원본과 프롬프트·SHA-256은 `assets/items/icon-card-choice-20261020/manifest.json` 및 `prompts.json`에 보존한다. 기존 ICON 원화·프레임은 그대로 유지하며, 선택 화면용으로만 비율을 유지한 WebP 8장을 사용한다(합계 268,190바이트). 재현 도구는 `scripts/build-icon-choice-portraits-20261020.mjs`다.

PC 1440×1000, 모바일 390×844·320×740에서 카드 선택·취소·확정·키보드·스크롤·응답 유실 후 결과 복구를 확인한다. 새 리소스의 기술 검수를 사용자 시각 승인으로 기록하지 않는다. 화면과 결과는 `docs/qa/icon-card-choice-20261020/`에 보존한다.

## 검증 및 운영 기록

- 선택권 거래와 실제 시즌패스 카탈로그 → 저장 → 수령 → 사용 경로를 SQLite·PostgreSQL 호환 계층 모두에서 검사했다.
- `tests/icon-card-choice-20261020.test.mjs`, `tests/supporter-season-pass-20261010.test.mjs`, `tests/supporter-pass-catchup-20261017.test.mjs`: 37개 통과.
- `tests/icon-card-choice-20261020.browser.mjs`: 세 화면 크기·CMS 저장 통과. 응답 유실 후 재진입 시 두 번째 POST 없이 카드 1장·선택권 1개 차감만 확인했다.
- 기존 시즌패스 검사 fixture에 현재 카탈로그가 조회하는 장비 `code` 열을 추가했다. 운영 장비 코드·스키마에는 영향이 없다.
- 운영 등록 dry-run: 8종 공개·활성 확인, 아이템 등록 및 감사 영수증을 시뮬레이션한 뒤 ROLLBACK, 시즌패스 설정 해시 동일, 사용자 지급 0개.
