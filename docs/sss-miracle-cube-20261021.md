# SSS 미라클큐브 — 2026-10-21

사용자 요청 `SSS 미라클큐브 만들어 SSS용병~리미티드까지 나오는 구성으로`와 답변 `SSS 일반 + SSS 리미티드만`, `CMS에서 직접 설정하도록 준비`에 따른 독립 큐브다. 준비 기본값은 질문에서 명시한 **확률 미설정·개봉 OFF**다.

## 운영 화면과 정책

- OWNER CMS → **SSS 미라클큐브**: `/admin/sss-miracle-cube.html`.
- 인벤토리 → **SSS 미라클큐브** → `/sss-miracle-cube/`. OWNER는 CMS 링크의 `?admin=1`로 실제 지급 없는 연출을 미리 볼 수 있다. 기존 `카드·용병·펫` 분류를 유지하며 별도 용병 사이드메뉴를 추가하지 않는다.
- 아이템 `SSS_MIRACLE_CUBE`; 설정 키 `sss_miracle_cube_policy_20261021_v1`. 기존 `MIRACLE_CUBE`/용병팩 확률·획득 방식과 분리한다.
- 개별 용병의 **큐브 1개당 최종 확률**을 소수점 8자리까지 저장한다. 합계가 정확히 100%이고 해당 용병이 획득 가능해야 ON 저장이 된다. 빈 값은 미설정(null), 0%도 추첨 제외다. 등급 추첨 후 내부 추첨을 겹치지 않는다.
- SSS 일반 6종은 기존 일반 용병 획득 잠금에 연동한다. SSS 리미티드는 기존 출시된 헬리오스·진무·발테르·족로의 발행 재고를 공유한다. 완판은 획득 불가, 다른 SSS 리미티드의 미공개/전용 획득 잠금은 그대로 보여 준다.
- 기존 한도·발행량을 변경하지 않는다. 설정된 용병이 품절·잠금이면 전체 개봉을 중지한다. 10개 개봉 중 필요한 잔여 수량이 부족해도 전부 무차감 취소한다. 결과를 다른 용병으로 바꾸거나 남은 확률을 재분배하지 않는다.
- 초기 아이템·설정 등록은 자동 지급·가격·판매·드롭을 만들지 않는다. 별도 지급은 기존 OWNER 유저 관리에서 처리할 수 있다. 등록 스크립트 재실행은 이후 OWNER 설정을 보존한다.

## 거래와 접근

`functions/_sss_miracle_cube.js`가 인증, OWNER 설정, 저장 리비전 비교, 1개/10개 개봉과 영수증을 처리한다. `shared/sss-miracle-cube-v1.mjs`가 입력 검증과 100억 정수 단위 확률을 공유한다. 기존 암호학적 40-bit 균일 추첨을 사용한다.

기존 joint operation에 결과를 고정한 뒤 큐브 차감, 용병 보유/중복 수량, 한정 발행, 시리얼, 획득 기록과 완료 영수증을 한 거래로 확정한다. 동시 팩의 마지막 재고 경쟁, 설정 변경, 실패 후 재시도에 중복 지급/재추첨이 없다. 새 테이블이나 공통 거래 엔진 변경은 없다.

진무·족로의 접근 확인에 `SSS_MIRACLE_CUBE_OPEN`을 추가하되 완료 영수증·획득 기록·기존 3장 한도 시리얼의 결합 검증을 유지한다. 일반 계정은 다른 계정 영수증, OWNER 메모에 접근할 수 없다.

브라우저는 계정별 미확인 요청을 보존하고 응답 유실 시 영수증부터 복구한다. 서버 결과 확정 후 봉인 개방/결과를 표시한다. 건너뛰기·줄인 동작·화면 숨김·페이지 이탈은 추가 차감을 일으키지 않는다.
