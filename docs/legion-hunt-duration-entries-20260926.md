# 군단토벌 15분 연속 진행·하루 2회 — 2026-09-26

사용자 지시: “군단토벌 15분동안 계속 진행, 마지막에 보스 스폰 하고 하루에 2번입장 가능하게해”.

## 동작

- 모든 난이도에서 15분 동안 일반 몬스터가 계속 등장한다. 12개 슬롯의 빈 자리를 5초마다 보충한다. 기존 37마리 처치 후 조기 종료와 중간 보스 2종은 이 흐름으로 대체한다.
- 서버 전투 시각 900,000ms에 일반 몬스터가 후퇴하고 태고의 수호자가 한 번 등장한다. 살아 있는 일반 몬스터의 후퇴는 처치·드랍으로 처리하지 않는다. 최종 보스 처치 시 성공한다. 아군 전멸·철수는 조기 종료다.
- 기존 난이도별 전투 제한 150/150/135/120초는 보스전 제한으로 사용한다. 토벌 중 아군 HP·보호막·회복/부활/마법 예산·용병·슈트 상태를 리셋하지 않는다.
- 난이도 전체를 합쳐 계정당 하루 2회, KST 자정 초기화다. 전장 준비 `start`는 무료이며 실제 전투 `begin` 성공과 입장 횟수 증가를 같은 계정별 app_meta CAS 쓰기로 확정한다. 준비 실패·시작 저장 실패는 차감하지 않는다. 철수·패배·세션 만료로 이미 쓴 횟수를 돌려주지 않는다.
- 원정 상태와 `daily.day/used`를 같은 기존 계정 행에 저장하므로 테이블·마이그레이션·공통 거래 기반 변경이 없다. 동일 begin 재요청·응답 유실·동시 요청은 추가 차감하지 않는다. 자정을 넘긴 이전 원정의 begin 재요청도 새 날짜 횟수를 사용하지 않는다.
- 새 화면은 15분/최종 보스/남은 횟수/초기화 기준을 표시한다. 횟수 소진 시 입장과 재도전을 비활성화한다. 구버전 2배속 클라이언트는 start의 `version:2` 검사에서 새로고침 안내를 받고 차감 없이 차단된다.
- OWNER 공개·일반 유저 OFF·실계정 보상 OFF와 운영 CMS 드랍 값은 유지한다.

## 전투 시계·범위

`_sustained_encounter.js`의 제한된 증원 옵션만 공용 시뮬레이터에 추가했다. 기존 PVE/PVP 호출은 이 옵션을 전달하지 않으며 기존 기준판과 12개 seed의 결과가 바이트 수준으로 같다. 처리 중인 적 배열에서 이전 사망 세대를 제거해 매 공격 시 누적 2천여 마리를 훑지 않는다.

실제 UI 검수에서 기존 1배 연출이 밀리면서 약 4분 벽시계에 90초의 전투만 처리하는 문제가 재현됐다. 군단토벌만 공용 GSAP 전투 시계를 `combatClockRate=1`로 고정하고, `HuntBattleEngine`이 연출 지연에 따라 3~8배로 따라잡도록 했다. 일반 PVE/PVP는 기존 paceScale 계약을 그대로 쓴다. 스킬 예고·충돌·잔향은 기존 단일 GSAP 시계이며 피해·대상·KO는 서버 순서를 보존한다. PixiJS 8.20.0·GSAP 3.13.0, 기존 효과 레이어·원화 카드 도크·승인 스프라이트·사운드를 재사용한다.

같은 몬스터에 연속된 100ms 이내의 슈트 사격은 표시용 영수증을 합친다. 합산 피해·마지막 HP/보호막·마지막 충돌 시각을 유지하고 카드 행동·스킬·KO·몬스터 교대 경계를 넘지 않는다. 서버 피해 계산은 변경하지 않는다. 드랍 후보가 없는 원정은 처치마다 불필요한 reveal 요청을 보내지 않는다.

사용자가 광역기 지연을 지적한 뒤 세 원인을 수정했다. Z-BODY 시전 중 들어온 서버 일반 타격은 활성 번개 효과 안에서 즉시 반영해 슈트 동작 잠금과 타격 대기열의 상호 대기를 없앴다. 동일 시각·시전·충돌 번호의 광역 타격은 한 묶음으로 표시하고 KO 소멸을 동시에 시작한다. 각 이벤트의 원래 완료 순서와 다음 몬스터 세대의 대기 장벽은 유지한다. `ZBodyThunderFX.js`는 실제 서버 타격이 없는 후속 번개를 표시하지 않아, 처치된 적 위에 준비 프레임이 남지 않는다. 승인된 24프레임 아틀라스·충돌 시각·피해량·발동 간격은 변경하지 않았다.

## 자원 사용·검증

- 최대 12슬롯, 초기 배치 후 179개 보충 시점, 최초 개체 포함 최대 2,161마리. 전체 적의 과거 상태를 전투 AI에서 반복 조회하지 않는다. 시뮬레이션 중 DB 접근은 없다.
- 로컬 Node 24, SS 용병 포함 고정 계정 fixture/seed 1731의 네 난이도 생성: 약 0.16~0.71초, 6,582~27,478개 표시 이벤트, 저장 상태 약 89~332KB. 실제 운영 서버 지연을 뜻하지 않는다. 전투 전체는 최초 준비 때 한 번 계산하며 기본 후보 없는 전투 진행 중에는 DB 요청이 없다.
- 콘텐츠 계층 입장 소진 거절은 인덱스가 있는 계정별 행 1회 조회로 끝나며 편성 조회·시뮬레이션·쓰기를 실행하지 않는다. begin은 계정 행 조회 1회와 CAS 쓰기 1회다. 기존 계정 잠금과 조회 함수는 재사용한다.
- SQLite와 PostgreSQL 호환 계층에서 시작 저장 실패, 응답 유실, 동시 begin, 난이도 공통 2회, KST 경계, 이전 날짜 재시도, 만료 후 횟수 보존을 검사한다.
- 15분 이전 조기 클리어/보스 등장 금지, 모든 분 구간의 증원, 900초 보스 1회, 몬스터 슬롯 중복 금지, 후퇴 시 드랍 금지, 전멸/시간 초과/철수, 2배속 미래 정산 거절, 저장/복원, 사격 피해 보존을 검사한다.
- 실제 공용 GSAP 재생 테스트에서 연출 속도 3배 중에도 899초에는 보스 이벤트가 실행되지 않고 900초에 실행되는 것을 확인한다. 일반 전투의 기존 배속, Z-BODY 시전 잠금/타격 대기 회귀도 검사한다.
- UI 검수는 실제 핸들러와 로컬 테스트 DB를 사용하는 `serve-legion-hunt-owner-review.mjs`의 PC 1440×960 및 모바일 390×844에서 진행한다. `LEGION_REVIEW_DIAGNOSTICS=1`은 로컬 HTML에만 읽기 전용 진행 표시를 추가한다.
