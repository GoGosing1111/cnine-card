# 고급 전리품 상점 SS 용병 카드팩

2026-09-25 사용자 요청: 고급 전리품 상점에 SS카드팩을 추가하고 구매 횟수는 운영자가 직접 설정한다.

- `MERCENARY_SS_PACK` / `mercenary_ss_pack`: CMS에서 선택한 SS등급 용병 중 균등 추첨으로 1장 지급한다. 기존 A~S 용병팩과 슈퍼스타 선택팩은 별도 상품으로 유지한다.
- 기존 저장 설정을 읽을 때 SS 상품이 없으면 판매 OFF·가격/누적 한도 미설정·지급 후보 미선택 초안만 추가한다. 조회 시 운영 DB를 쓰거나 기존 상품, 구매 이력, 재화 지급 스위치를 초기화하지 않는다. 이미 저장한 SS 상품은 재배포로 덮어쓰지 않는다.
- CMS → 고급 전리품 상점 → SS 용병 카드팩에서 가격, 계정당 누적 구매 횟수, SS 용병 후보, 상품 판매 사용을 저장한다. 누적 구매 횟수는 기본값이 없으며 3회 제한을 적용하지 않는다. 입력 범위 1~2,147,483,647은 정수 처리 상한이다. 기존 상품의 FUR 10회·기타 3회 상한은 유지한다.
- 구매는 기존 피그 코인 거래·보관 팩 경로를 사용한다. 한도 변경은 구매 이력을 초기화하지 않고, 재시도는 같은 요청 영수증과 추첨 결과를 재사용한다. 잘못된 등급 후보나 미설정 가격/횟수로 판매할 수 없다.
- 상품 상세·확률 안내·개봉 확인·결과에 SS등급 100%를 연결했다. 기존 용병팩 원화를 공용 이미지로 표시한다. 큰 한도는 숫자로 표시하며 한도만큼 DOM 장식을 생성하지 않는다.

## 검수 및 배포 범위

- 새 SS팩 관련 회귀 13개를 SQLite/PostgreSQL에서 통과했다. 빈 한도, 기존 정책 업그레이드, OWNER 저장, SS 후보만 지급, 동시 마지막 구매, 한도 증감, 차감/팩/지급 원자성, 실패 재시도와 중복 지급 방지를 포함한다.
- CUA 실제 브라우저 1440×1000 / 390×844에서 실제 CMS·상점 모듈과 격리 DB로 확인했다. CMS 가격·후보·7회 저장, 상점 교환→보관→SS 개봉, 모바일 37회 저장과 가로 넘침 없음을 확인했다. 25코인·7회·37회 및 선택 후보는 검수 계정의 로컬 값이며 운영 설정이 아니다.
- 로컬 재현: `LOOT_QA_SS=1`, `LOOT_QA_PORT=8969` 후 `node scripts/qa-loot-shop-mystic-cms.mjs`.
- 직전 운영 배포: `38c5dfa4-be26-475f-949d-a27cff0ebd55`, 기준 커밋 `5e39f657f4f756359a8a6799549201343f16e20f`. Cloudflare Pages 배포 목록으로 확인했다.
- 기존 거래/DB/권한 기반을 바꾸지 않는 상품 추가이므로 작은 변경으로 분류한다. 최종 배포 과정에서 `test:loot-shop`과 `check:worker`를 실행하고 출시/캐시/Hyperdrive 검사를 유지한다. 배포 명령은 `npm run deploy:production -- --scoped`다.
- 배포 후 운영 파일 반영과 SS 상품의 미설정 초안 경로만 짧게 확인한다. 운영 가격·횟수·후보를 임의 저장하지 않는다.
