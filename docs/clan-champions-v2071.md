# 클랜 챔피언스리그 · v2071

## 개최·경기

- 정규시즌의 기존 보상·트로피를 먼저 정산한 뒤 `SETTLEMENT → CHAMPIONS`로 전환한다. 최종 결승이 끝나야 `COMPLETE`가 되고 다음 시즌을 시작할 수 있다.
- 정규시즌 순위 계약(승점 → 누적 전투점수 → 득실차 → 기존 동률 순서)으로 상위 3개 클랜을 확정한다. 1위는 결승 직행, 2위와 3위의 경기 승자가 결승 진출한다.
- 두 경기 모두 동점이면 정규시즌 상위 시드가 진출/우승한다. 클랜 ID가 작은 팀을 승자로 고르지 않는다.
- 기본 일정: 정규시즌 정산 다음 개방일 21:00 KST에 2·3위전, 그 다음 개방일 21:00에 결승. CMS에서 시간과 각 경기 간격(1~30일)을 설정한다. 개방 요일은 기존 클랜전 설정을 재사용한다.
- 현재 클랜전의 점수/행동력/시간/랜덤 매칭 규칙을 개최 시 고정한다. 대회 중 CMS 조회·설정 저장으로 참가 보상이 덮어써지지 않는다. 덱은 매 전투 최신 랭크전 5장을 사용한다. 서버 판정 및 라이브 V3 재생기를 그대로 사용한다.
- 기존처럼 서버 요청 시 일정 경계를 정산한다. 처리 중인 전투는 최대 120초 회수 기준까지 기다린다. 정산 지연으로 결승 예정 시간을 넘겼으면 다음 개방일로 재배정해 이미 지나간 경기를 만들지 않는다.
- 완료된 과거 시즌을 소급해서 개최하지 않는다. 개최 OFF 또는 3개 미만 클랜일 때는 기존 정규시즌 종료만 진행한다. 개최 후 설정 변경은 진행 중 대회에 소급하지 않는다.

## 기록·원자성

- `clan_championships`: 시즌당 1대회, 시드·규칙·일정·최종 우승·보상 설정 보관.
- `clan_championship_members`: 정규시즌 종료 시 상위 3클랜 참가 명단 고정. 공격자·랜덤 상대 모두 검증한다. 진행 중에는 기존 OWNER 이적/비활동 정리 경로도 단계 검사로 차단된다.
- `clan_wars`의 예약된 `round_no=1001/1002`를 2·3위전/결승으로 사용한다. 1000 이상은 정규시즌 승점·승패·누적 전투점수에서 제외한다. 정규시즌 트로피를 한 번 더 늘리지 않는다. 개인 전투 기록은 기존 시스템대로 누적된다.
- 정산 락 획득 후 시즌 단계를 재조회한다. 오래된 정산 요청이 새로 생성된 대회를 취소할 수 없다.
- PostgreSQL 트랜잭션의 행 잠금, 조건부 상태 변경, 유일키와 요청 토큰으로 재시도를 보호한다. D1 호환 SQL도 별도로 검증한다.
- 대회가 기록된 시즌은 자동 리셋을 차단해 대진/수상 기록을 보존한다.

## 별도 우승 보상

- **v2072 사용자 확정: 최종 우승 클랜의 개최 시 고정 명단 전원에게 챔피언스리그 트로피 1개 + 태양의 선봉대장 아바타 14일.** 기본 보상은 공개 ON 대회에서 자동 지급한다. CMS의 추가 재화 보상 스위치와 구분한다.
- CMS → 클랜전 관리 → `04-C 챔피언스리그 · 최종 우승 보상`에서 1인당 코인, 미스틱 에너지, 마스터의 별, 고등급 재뽑기권을 설정할 수 있다.
- `ON` 모드와 하나 이상의 양수 보상을 지정하고 별도 보상을 활성화한다. 개최 당시 설정된 보상은 최종 우승 후 자동 발송한다.
- 트로피는 `CLAN_CHAMPIONS_TROPHY` 영수증으로 대회·유저당 1개 기록하고 명함에 정규시즌 우승 트로피와 구분하여 표시한다. 클랜 조직의 정규시즌 트로피 카운터를 중복 증가시키지 않는다.
- 아바타는 기존 `SOLAR_VANGUARD` 소유 테이블에 실제 지급 시점부터 14일간 지급한다. 재시도는 기간을 다시 시작하지 않으며 기존 영구 소유권·더 긴 만료일은 보존한다. 자동 장착하지 않는다. 카탈로그가 비공개·비활성이면 지급을 보류한다.
- 트로피·아바타는 직접 지급 후 메시지로 안내하고, 선택 추가 재화만 기존 수령형 메시지로 발송한다. 지원하지 않는 트로피/아바타 코드를 수령형 첨부로 보내지 않는다. 기존 시즌 보상과 별도로 받을 수 있다.
- `clan_championship_rewards` 유일키는 `(season_id,user_id,reward_type)`. 메시지와 보상 첨부, 발송 영수증을 한 트랜잭션으로 처리한다. 수신자별 네트워크 반복 대신 보상 유형별 일괄 INSERT를 사용한다.
- 기본 보상 `SENT`는 소유권 지급과 알림 발송 완료다. 선택 재화 `SENT`는 메시지 발송 완료이며 유저의 수령 완료를 뜻하지 않는다. 실패는 롤백하고 동일 대회에서 재시도한다. 누락 계정은 완료로 오인하지 않고 미발송 상태를 유지한다.
- 미설정 상태로 종료했다면 CMS 설정 저장 후 `미발송 우승 보상 발송`으로 해당 대회의 보상을 처음 확정·발송한다. 이미 설정/발송한 보상을 나중 금액으로 바꿔 이중 지급하지 않는다.
- TEST에서 개최한 대회는 나중에 모드를 ON으로 바꿔도 경제 보상이 생기지 않는다.
- 기존 대회에 동결된 보상을 소급 교체하지 않는다. 이전 버전의 `AWAITING_CONFIG` 대회만 OWNER의 미발송 보상 발송 시 기본 보상과 현재 선택 재화를 처음 동결한다.
- CMS의 `명함 트로피 기록 조회`는 정확한 닉네임으로 기존 읽기 전용 `player-card` API만 호출한다. 보상 지급·회수·정산은 실행하지 않는다. 랭크 1위는 공식 완료 시즌의 최종 1위에게 시즌당 1개이며 현재 1위와 다르다.

## UI·검증

- 유저: 클랜 본부 진입 배너, 전용 챔피언스리그 탭, 1위 부전승, 경기별 상태/점수/일정, 우승 표시, 보상 상태. 비참가자도 관전용 대진표 확인 가능. 참가자는 기존 전투 화면으로 이동한다.
- 다음 시즌에도 직전 대회 결과를 열람한다. PC 2열·모바일 1열 대진표. 모바일 탭은 2행으로 전부 표시한다.
- `preview/clan-champions-v2071/`는 실제 프론트엔드와 클랜 마크를 사용하는 합성 검수 데이터이며 운영 API/지급을 호출하지 않는다.
- `tests/clan-champions-v2071.test.mjs`: 실제 정규시즌 정산 연동, 상위 3시드/부전승/동점/결승, 미완료 전투, 지연 재배정, 명단/규칙 고정, 정규시즌 순위·보상 보존, PostgreSQL 및 SQLite 원자 지급·롤백·재시도, HTML 이스케이프/CMS/캐시 검사.
- v2072 기준 기존 테스트 76개 및 대회 테스트 22개, 총 98개를 `test:clan`과 전체 `release:gate`에 포함한다. 명함 별도 테스트는 15개다.
- 브라우저: 390×844에서 페이지 가로 넘침 없음, 이미지 로드 실패 0, 콘솔 오류 0. 결승/최종 우승 상태 확인. 임시 뷰포트는 복원한다.

운영 배포는 작업 범위 커밋 후 깨끗한 릴리스 작업 트리에서 `npm run deploy:production`만 사용한다.
