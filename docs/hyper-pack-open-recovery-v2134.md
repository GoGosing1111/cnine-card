# 하이퍼팩 개봉·복구 v2134

하이퍼팩 지급이 확정된 뒤에도 연출 종료까지 클라이언트 잠금이 유지되어, 자원 로딩이 멈추면 다음 개봉과 복구가 함께 잠기던 문제를 수정한다. 기준 커밋은 `ed03076b`이며 사용자 제공 인계 패치를 현재 운영 코드에 대조하여 적용했다.

## 변경

- 영수증 저장·지급 완료 이벤트 직후 개봉 잠금을 해제한다. 뒤늦게 끝난 연출이 다음 요청의 잠금을 풀지 않도록 해제는 요청별로 한 번만 수행한다.
- 중복 요청에는 처리 중 안내를 표시한다. 반복 개봉은 결과창을 닫은 다음 실행한다.
- 연출 초기화에는 20초, 재생에는 `20초 + 12초 × 장수` 제한을 둔다. 실패는 콘솔·상태 문구로 알리고 이미 지급된 전체 결과와 다시 개봉 버튼을 제공한다.
- 결과 목록·라이브 연출은 기존 도감 640 WebP를 먼저 사용한다. 로딩 실패 시 원본으로 복구하며 원본 파일은 변경하지 않는다. 라이브에서 사용하지 않는 베스페라 예시 원화를 사전 로드하지 않는다.
- 계정 조회는 계정 변경 이벤트에 맞춰 갱신하고 DOM 변경은 프레임당 한 번만 처리한다. 인계안에 로그인·프로필 저장 이벤트 `cnine:player-updated` 대응을 추가했다.
- 영수증 획득 행을 한 번의 조회로 읽고, 커밋 직전에는 개봉 ON/OFF만 재확인한다. 원자적 개봉 가드와 누락 데이터 처리 방식은 유지한다.
- 복구·비활성 버튼의 표시 및 하이퍼팩 관련 캐시 태그를 갱신한다. 공용 전투·벤더 번들과 기존 확률·가격·운영 ON/OFF 설정은 변경하지 않는다.

## 검증

- 인계 문서의 12개 회귀 파일: 91개 통과. 추가 테스트는 지연된 연출과 다음 결제의 잠금 분리, DOM 변경 시 파싱 횟수, 계정 전환, 획득 행 일괄 조회 및 누락 행 비생성을 검증한다. SQLite와 PostgreSQL 호환 경로를 모두 포함한다.
- Chrome 1440px·390px에서 실제 클라이언트와 서버 핸들러를 PostgreSQL 테스트 DB에 연결했다. 10회 개봉·재개봉·닫기·추가 차감 없는 복구·OFF 버튼 표시·모바일 스크롤을 확인했다. 초기화 시간 초과와 WebP 404도 주입하여 결과 보존과 원본 폴백을 확인했다.
- 운영 DB에서는 기존 OWNER 계정의 완료된 10회 영수증을 읽기 전용으로 조회했다. 결과 10건·용병 2건, 영수증 조회 2쿼리 중 획득 행 조회 1쿼리, 측정 78ms. 준비 정책 5쿼리, 커밋 전 재확인 1쿼리. 운영 계정의 신규 차감이나 보상 생성은 하지 않았다.
- 도감 원화 47종의 WebP 누락 0건. 원본 합계 116,620,045바이트 대비 WebP 6,214,186바이트로 원화 전송 크기는 약 1/18.8이다. 팩·프레임·에너지 공용 PNG는 별도이며, 전체 최초 로딩이 1MB 미만이라는 수치로 해석하지 않는다.
- 생성한 전용 FX 번들은 10,041바이트다. 번들 재생성과 출시 게이트를 거친 동일 커밋을 `npm run deploy:production`으로 배포한다.

개별 운영 영수증과 브라우저 캡처는 배포 디렉터리 밖의 QA 폴더에 보관한다.
