# 붕괴 코어 보상 코인 상한 및 운영 지급액 — 2026-09-23

## 사용자 지시

- `붕괴코어 레이드 코인 상한 300억까지 풀어`: 설정 가능한 상한을 20억에서 **300억(30,000,000,000)**으로 확대한다.
- 후속 `100억으로 니가 바꿔놔`: 운영 클리어 보상은 **1인당 100억(10,000,000,000)**으로 저장한다.
- 주간 수령 3회, 입장권, 카드조각, 피그 코인, 난이도, 공개 모드와 보상 잠금은 변경하지 않는다. 완료된 보상 영수증은 재계산하거나 추가 지급하지 않는다.

## 구현 범위

- `functions/_raid_core_protocol.js`: 설정 정규화 상한 300억. 관리자 저장에서 범위 초과·음수·소수·비숫자 입력은 400으로 거절하며 기존 저장값을 보존한다.
- `admin/core-protocol-raid-admin-v2021.js`: 최대 300억 표기, 숫자 입력 max와 저장 전 검증을 서버와 일치시킨다.
- CMS 진입 및 중첩 로더 캐시 태그를 함께 갱신한다. 일반 월드 레이드의 별도 100억 상한은 변경하지 않는다.
- 기본값(TEST·보상 잠금·코인 0)은 유지하며, 운영 100억은 배포 후 OWNER CMS에서 명시적으로 저장한다.
- 보상 영수증·지갑·코인 로그는 기존 BIGINT 경로와 원자 정산을 유지한다. DB 마이그레이션, 새 쿼리·바인딩·캐시·전투 로직 변경은 없다.

## 검증

- SQLite 및 실제 PostgreSQL 호환 경로(PGlite): 100억/300억 저장·조회·공개 응답·지갑 지급·코인 로그·영수증 확인.
- 주간 3회 상한(300억 설정 시 주간 최대 900억), 네 번째 차단, 재요청 중복 지급 방지, 설정 변경 후 완료 영수증의 과거 금액 보존.
- 300억 정산 도중 로그/영수증 실패 시 롤백, 커밋 응답 유실 시 1회 지급만 복구.
- CMS 100억/300억 입력 허용, 초과·음수·소수 입력의 전송 전 차단과 캐시 연결 검사.
- `npm run test:core-raid`: 80/80 통과. `npm run test:raid-entry`: 34/34 통과.
- 실제 CMS 스크립트 로컬 브라우저 검수: 데스크톱 100억 저장·재조회, 390×844 모바일 300억 저장 및 잘림 없는 입력/저장 버튼 확인. 300억+1 입력 후 저장 시 기존 300억 유지. 검수 서버는 메모리 설정만 사용한다.
- 운영 배포 전 `npm run release:gate`, 배포는 `npm run deploy:production` 경로만 사용한다. Hyperdrive 쿼리 캐시 OFF 및 기존 Neon 연결은 유지한다.
