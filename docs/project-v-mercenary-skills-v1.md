## 특색 검수 기준

1. 이름·색·피해 배율만 바꾼 기술은 별개의 고유 스킬로 세지 않는다.
2. 발동 조건, 표적 정책, 상태 변화, 시간 흐름, 실패 비용, 대응법을 명시한다. 이번 16종은 서로 다른 `mechanic`과 `visual.motion`을 가진다.
3. 강점 하나를 선명하게 둔다. 호위와 회복, 선제 방호와 응수, 즉시 차단과 다음 공격 감쇠를 섞어 만능 스킬로 만들지 않는다.
4. 보호 대상·고정 표적을 잃었을 때 재선정 여부를 명시한다. 처치·추가타·반격에 의한 재귀 발동을 금지한다.
5. 범위 피해·보호막은 전체 예산을 나눈다. 대상 수에 비례해 단일 수치를 무한 복제하지 않는다.
6. 보스의 이동·중단·상태 면역과 고유 기믹을 존중한다. 면역으로 막힌 효과를 임의의 스턴·즉사·고정 피해로 보상하지 않는다.
7. 효과는 방벽·조준탄·금속 균열·명령 전달·독사·장막·봉합·응수·설빙·사선·연화·탄실·건틀릿·구속·두 박자처럼 실루엣과 동작으로 구분한다.

## 구현 및 수치의 범위

- `shared/mercenary-skills-v1.mjs`: 16종의 단일 설계 기준, 배정·발동·효과·약점·보스·연쇄 정책, CMS 초안 검증.
- `preview/project-v-mercenary-system-v1/skill-rehearsal.mjs`: 검수 전용 결정적 시뮬레이션. 기술마다 정상·약점·보스의 3개 상황을 미리 확정된 이벤트로 만든다.
- 100 HP, 검수 피해·회복·보호막 수치는 동작 차이를 확인하기 위한 예시다. 운영 피해 계수·쿨다운·비용은 `null / PENDING_REVIEW`다. 예시 숫자를 운영 정책으로 이관하지 않는다.
- 중첩 상한·지속 턴·모드별 저항·적중·자원·성장 계수는 실제 서버 밸런스 구현 전에 확정해야 한다. 검수 실행기는 이들 전체를 구현한 라이브 전투 엔진이 아니다.
- 지원의 정화·감쇠, 전열 억제, 초탄 조건, 고정 표적과 보스 면역 등의 대표 차이를 48개 시나리오에서 실행한다. 모든 가능한 시간 순서·상태 조합을 검수한 것으로 보고하지 않는다.

## PixiJS·GSAP과 리소스

실제 구현은 `source/skills-lab.src.js`와 `source/MercenarySkillFX.js`다. 기존 `project-v-pixi-battle.src.js`, `BattleEngine`, `BattleCharacter`, `battle-v3-live.js`와 원본 카드 도크·아트 어댑터를 재사용한다. 독립 프리뷰 번들 한 개에 잠금 **PixiJS 8.20.0 / GSAP 3.13.0**을 한 번만 포함한다. 라이브 번들은 수정하지 않는다.

일반 카드 5명은 승인 로스터의 실제 ID·원화·SD로 만든 정적 검수 편성이다. 상대도 같은 승인 카드로 구성한 모의 표적이며 실제 사용자 덱 스냅샷이 아니다. 별도 용병 `BattleCharacter`는 일반 카드 배열 밖에 둔다. 용병 슬롯은 검수용 빈 타일만 사용하며 기존 5인 진형·도크·배틀슈트 타일을 옮기지 않는다. 실제 전투 슬롯 구현·서버 편성 승인을 뜻하지 않는다.

16개 신규 소재는 내장 ImageGen으로 각각 생성했다. 원본 PNG는 `skill-assets/source/`에 무가공 보존한다. 런타임은 균일 512px 무손실 WebP다. 원본·변환본 해시, 알파 검수, 전체 프롬프트와 생성 방식은 `skill-assets/manifest.json`에 남긴다. 생성 후 배경을 임의로 칠하거나 기존 4역할 아틀라스에 색만 입히지 않았다.

이번 방식은 **단일 투명 스프라이트를 GSAP 시간에 따라 이동·회전·확대·소멸시키는 구성**이다. 프레임 아틀라스를 새로 만든 것으로 보고하지 않는다. 각 소재는 서로 다른 경로·개수·박자로 재생하며 실제 V3 `effectLayer`에 붙는다.

- 시간 단위: 초. 각 기술의 `visual.windup`, `visual.impacts`, `visual.duration`이 예고·충돌·완료 기준이다.
- 기준점: 캐릭터 발바닥 원점, 충돌은 캐릭터 높이·실제 스케일을 반영한 몸통 54% 위치. SD 발끝은 승인 `footAnchor`를 사용한다.
- 시간 소유자: V3 `simpleTimelines`에 등록한 GSAP 타임라인 1개. 정지·배속·탐색 모두 이 시계만 변경한다. Pixi 자동 프레임 재생·별도 충돌 타이머는 없다.
- 피해·상태는 사전 확정된 검수 이벤트를 샘플링한다. 이펙트가 피해·승패·발동 횟수를 재계산하지 않는다.
- 취소·화면 이탈·선택 변경은 타임라인 등록을 해제하고 용병을 원래 타일로 되돌린다. 선택 변경·종료는 소유한 표시 객체를 제거한다. 공유 V3 텍스처를 파괴하지 않는다.
- 사운드: **무음 검수**. 새 사운드를 제작·연결하지 않았다. 효과음 완료 또는 음향 ±20ms 검증을 주장하지 않는다.

## CMS 준비 계약

포지션 초안과 별개인 `PROJECT_V_MERCENARY_SKILL_DRAFT_V1`을 사용한다. 브라우저 저장 키는 `cnine.mercenarySkills.draft.v1`이다. 16종의 스킬 이름·검토 상태·의견을 편집, 저장, 재로드, JSON 가져오기·내보내기 할 수 있다.

허용 항목만 받아들이고 배정 코드, 중복·누락, 길이, 스키마 버전, 로스터 버전, 수정 번호와 OFF 상태를 검사한다. 다른 화면의 수정 번호가 바뀌면 덮어쓰지 않는다. `REVIEWED`는 메모용 검토 표시이며 사용자 출시 승인이나 운영 플래그가 아니다.

향후 운영 CMS에서 추가할 항목은 기존 포지션 설계 계약을 따른다. 서버 권한·revision 충돌 검사·감사 로그·검수 전후 차이·이전 버전 복구·사용자 확정 등급·계수·쿨다운·대상 수 상한을 함께 구현한다. 자유 입력 문자열을 실행 코드로 평가하지 않는다.

## 출시 상태

검수 화면 공개만 포함한다. 준비 로스터의 등급 43종은 미정이며, 용병 획득·일반 덱·운영 편성 API·실제 전투·CMS 운영 DB에는 연결하지 않는다. 사용자의 등급 확정과 시스템 연결 지시 뒤 별도 통합 검증을 진행한다.

검증 명령: `npm run build:mercenary-skills`, `npm run test:mercenary-skills`, `npm run test:mercenary-codex`. 운영 프리뷰 공개 전 `npm run release:gate`와 `npm run deploy:production`을 사용한다. 실제 실행 결과는 프리뷰 README에 기록한다.
