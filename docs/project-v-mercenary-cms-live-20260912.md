# 용병 CMS 운영 등록 — 2026-09-12

사용자 지시: **“용병관련 전체 항목 CMS 등록 라이브로 배포해”**.

기존 V3·용병·장비 공동 출시 규칙 안에서 운영 CMS를 먼저 공개한다. CMS의 저장은 준비 설정 등록이며 실제 계정 획득·편성·전투 활성화가 아니다. 기존 읽기 전용 도감과 전투 런타임에는 CMS 초안을 자동 적용하지 않는다.

## CMS와 저장 계약

- 운영 진입: `/admin/#mercenaries`, OWNER 전용 `용병 관리` 메뉴.
- `GET /api/admin/mercenaries`: 고정 카탈로그·현재 설정·리비전·최근 저장 기록.
- `PATCH /api/admin/mercenaries`: 전체 document, expectedRevision, requestId. 최대 512 KiB.
- `mercenary_cms_documents_v1`: `catalog` 고정 원본과 `config` 편집 문서. `ON CONFLICT DO NOTHING` 초기 등록으로 저장된 설정을 보존한다.
- `mercenary_cms_audit_v1`: 등록/저장 관리자·리비전·시각·요청 ID·페이로드 해시. 원자적 트랜잭션으로 설정과 감사 기록을 함께 저장한다.
- 인증은 기존 `requirePermission`과 OWNER 역할 모두 검사한다. 권한 확인 전 스키마/초기 데이터에 접근하지 않는다. 승부예측 ADMIN의 권한은 확장하지 않는다.
- 낡은 리비전은 409. 같은 요청 ID 재시도는 기존 결과를 확인하며 다른 내용·관리자의 ID 재사용은 거절한다. 저장 실패 시 화면의 편집 값을 보존하고 JSON 내보내기를 제공한다.
- 최초 시드의 `sourceHash`는 `scripts/build-mercenary-cms-v1.mjs`에서 원본 로스터/스킬/연출 자료로 결정한다. 다음 카탈로그 버전은 별도 마이그레이션으로 추가하며 운영 초안을 재시드로 초기화하지 않는다.
- CMS 검수 완료 표시는 사용자 최종 전투 연출 승인이나 공동 출시 ON 상태를 뜻하지 않는다.

## 기능 분리와 배포

일반 덱은 기존 5장을 유지하며 용병 1슬롯은 별도 필드다. 이번 변경에는 획득·인벤토리·편성·전투 API, 사용자 보상·재화 수정이 없다. CMS 카탈로그의 `acquisitionEnabled`, `formationEnabled`, `battleEnabled`는 모두 false로 고정하고 UI에 ON 버튼을 만들지 않는다.

전용 배포 후보에서 범위 파일만 커밋한다. `npm run deploy:production`이 먼저 실행하는 `npm run release:gate`를 반드시 통과한 후 배포한다. 운영 DB 등록/검증은 별도 일회성 작업으로 수행하며 개발용 접근 키나 운영 연결 정보를 저장소에 넣지 않는다.
