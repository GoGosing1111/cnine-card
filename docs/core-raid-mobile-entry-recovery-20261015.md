# 붕괴 코어 모바일 전투 초기화 복구 — 2026-10-15

사용자 첨부의 `battleV2 기능 초기화에 실패했습니다`를 전투 리소스 로더에서 재현했다. 운영에 게시된 앱·래퍼·엔진의 현재 버전은 서로 일치했으나, 배포 전부터 열린 앱이 이전 버전을 기대하는 상태에서 새 래퍼·엔진을 받으면 기존의 앱 버전 완전 일치 검사에서 실패했다. 사용자 단말의 실제 캐시 내용은 직접 수집하지 않았으며, 같은 오류를 내는 조건을 코드와 모바일 브라우저에서 검증했다.

## 변경

- 엔진과 래퍼 버전은 계속 정확히 일치해야 한다. 앱이 기대하는 버전에서 접미사만 추가된 새 런타임은 래퍼가 `entryContractVersion:1`로 동일한 진입 API를 보장할 때 허용한다. 이전 버전·다른 계열·다른 진입 계약은 허용하지 않는다. 진입 API의 호환성이 깨지는 변경은 이 계약 번호를 올린다.
- 캐시된 래퍼와 엔진이 서로 맞지 않으면 두 파일에 같은 새 쿼리를 붙여 한 번 함께 갱신한다. 복구 후에도 준비 상태를 검증하고, 실패하면 재시도 안내를 표시한다. 페이지를 자동 새로고침하거나 전투를 임의 생성하지 않는다.
- 완료된 로딩 Promise를 보관하지 않는다. 다른 전장 진입으로 런타임이 교체됐을 때 완료된 과거 Promise로 준비 검사를 건너뛰던 경로도 수정했다. 진행 중 중복 호출은 계속 같은 Promise를 공유한다.
- 붕괴 코어의 기존 순서인 리소스 준비 → 기믹 준비 → 서버 공략 시도 생성을 유지한다. 초기화 실패 경로에서 공략 생성·이탈 판정 API가 호출되지 않는 것을 확인했다. 전투·보상·차감·CMS 및 기존 공대 상태는 변경하지 않는다.
- 메인/SW 캐시 태그는 `20261015-core-battle-recovery-v1`, 래퍼 쿼리는 `entryRecovery=20261015-v1`로 갱신한다. 수정 이전에 열린 화면은 한 번 새로고침해 새 로더를 받아야 한다.

- 기존 캐시 회귀 `tests/overlord-runtime-cache-20261005.test.mjs`와 공통 진입 계약 `tests/pve-battlefield-entry-v2117.test.mjs`를 scoped 배포 검사로 사용한다. 전체 게임 검사는 실행하지 않는다.
