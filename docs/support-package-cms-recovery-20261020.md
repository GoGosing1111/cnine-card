# 후원 관리·패키지 CMS 조회 복구

사용자가 후원 관리의 패키지 항목이 보이지 않는다고 알린 뒤 다시 보인다고 확인하고, 재발 방지 수정을 요청했다.

운영 CMS HTML·후원 모듈·패키지 모듈은 저장소와 일치했다. 코드에서는 첫 후원 관리 조회 실패를 빈 catch로 무시해 메뉴를 숨긴 채 재시도하지 않았고, 같은 관리자 정보 갱신마다 이미 열린 화면과 입력 내용을 제거했다. 사용자의 당시 HTTP 응답은 수집하지 않았으며, 이 두 조건은 별도로 재현·수정했다.

- 최초 조회 실패 시 1·3·10초 간격으로 최대 3회 자동 재시도한다. 재시도가 끝난 뒤에는 온라인 복귀·탭 표시/포커스 복귀 시 다시 확인한다.
- 이미 서버가 허용한 동일 세션에서는 일시 조회 실패나 계정 정보 갱신으로 열려 있는 패키지 화면을 제거하지 않는다. 선택 신청·입금 확인 메모·체크 상태를 보존한다.
- 실제 401/403, 관리자/토큰 변경에서는 기존 화면을 지우고 새 인증 응답을 기다린다. 이전 응답은 epoch와 취소 신호로 폐기한다. ID 1 OWNER 서버 권한 검사는 그대로다.
- 자동 재시도는 후원 관리 조회 GET에만 적용한다. 실제 입금 확인·지급·반려·신규 메시지 발송은 수행하지 않는다.
- CMS HTML의 모듈 버전을 `20261020-package3`으로 올린다. 후원 모듈은 기존 서비스워커 최신 파일 우선 경로에 포함돼 있다. UI 디자인과 전용 이미지·상품 구성·운영 데이터를 바꾸지 않는다.

## 검증

`tests/support-package-cms-recovery-20261020.test.mjs`는 실제 CMS 모듈과 HTTP 서버에서 최초 503, 열린 폼의 재조회 503, 다른 OWNER 전환, 기존 세션의 403을 주입한다.

PC 1440×1000과 모바일 390×844 모두 최초 조회 자동 복귀, 패키지 URL 진입, 동일 DOM 폼·입금 메모·체크 상태 보존, 패키지 목록 불필요 재조회 없음, 계정 전환 시 이전 화면 제거, 403 재시도 없음, 지급 요청 0건을 확인했다. JS 오류·가로 넘침 0건이며 저장된 두 화면을 직접 확인했다. 기술 검수를 사용자 시각 승인으로 기록하지 않는다.

근거는 `docs/qa/support-package-cms-recovery-20261020/`에 보존한다. CMS 한 모듈의 읽기·화면 생명주기 변경으로 공통 인증·서버 권한·DB·결제/보상 거래를 변경하지 않는다. 범위 배포에서는 해당 복구 검사와 Worker 컴파일, 기존 출시·캐시·Hyperdrive 보호만 수행한다.
