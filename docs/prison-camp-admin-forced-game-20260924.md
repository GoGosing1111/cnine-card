# 포로수용소 CMS 수감 · 운영자 강제 경기 지정

## 사용자 범위

- CMS에서 직접 유저를 포로수용소에 넣을 수 있도록 추가한다.
- 후속 지시: 김아윤 수감은 취소. 해당 계정이나 다른 운영 유저를 수감·지정·경기 시작하지 않는다.
- 죽음의 눈치게임은 수용소 안의 인원을 운영자가 지정하는 강제 참가 방식이다. 자율 참가·취소를 제거한다. 기존 정원 4명, 운영자 시작, 입력 동작 동기화와 사망 시 전체 플레이 5분 제한을 유지한다.

## 동작

- CMS → 유저 관리 → 유저 상세 → **포로수용소**. 기존 행정부 감옥과 구분한다.
- 기존 `USER_MANAGE` 인증 + OWNER 전용. 분 단위(1~10,080분), 사유, 닉네임·계정 ID 확인 후 처리한다. 이미 수감 중이거나 이용정지 상태이면 새 형기를 겹쳐 적용하지 않는다.
- 기존 event prison 테이블에 `ADMIN` 출처를 사용한다. 기존 개인 감옥, 클랜·쿠데타 형기, 재화는 덮어쓰지 않는다. 요청 영수증과 관리자 감사 로그·수감/석방을 한 트랜잭션으로 처리한다. 동일 요청 재전송이나 COMMIT 응답 유실은 형기를 연장하거나 재수감하지 않는다.
- CMS는 본 기능으로 만든 수감 건만 석방한다. 게임의 기존 서버 제한·상태 동기화·자동 만료를 재사용한다. 신규 DB 마이그레이션·인증 기반·의존성 변경은 없다.
- 게임 포로수용소 → **운영 / 관전** → **새 경기 준비** → 실제 수감 명단에서 최대 4명 선택 → **선택 인원 강제 참가 지정** → **경기 시작**. 1명 지정 후 추가할 수 있고, 시작에는 2~4명이 필요하다.
- 참가자는 대기·진행 중 자율 취소/닫기를 할 수 없다. 기존 수용소 상태 응답에 지정 정보를 함께 보내며 수용소 접속·새로고침 시 자동 진입한다. 자율 join/leave API도 차단한다. 비참가자는 계속 관전할 수 있다.
- 지정과 시작 시 실제 수용소 형기, 개인 감옥·사망 제한을 서버가 확인한다. 지정 재시도가 이후 명단을 되돌리지 않는다. 기존 4인 식사 스프라이트·스페이스/터치·서버 타임라인은 유지한다.

## 관련 검수·배포 선택

- 직전 운영 배포: `0a54cb09`, 소스 `f529d0800be11ced7d82d4fc4393145683fadb0c`. 그 이후 원격 변경은 기존 운영 작업 스크립트/문서/테스트이며 게임 실행 파일 변경은 없다.
- 포로수용소 내부의 국소 기능 추가다. 공통 인증·DB 어댑터·스키마·의존성은 그대로이며 수용소와 사망 제한 경로에 영향이 한정되어 scoped 배포를 사용한다.
- 선택 검사: `prison-camp-admin-20260924`, `prison-death-game-assignment-20260924`, `prison-death-game-20260924`, `prison-death-game-four-seat-20260924`, `clan-prison-camp-v2083`, `prison-system-v1950` 테스트. 지정 배포 도구의 Worker 컴파일·출시 플래그/캐시·Hyperdrive 확인을 포함한다.
- SQLite·PostgreSQL에서 권한, 대상·시간·사유 검증, 수감/석방 원자성, 중복·동시 요청, 응답 유실, 참가자 상한, 외부 인원 차단, 석방·사망 후 시작 차단, 재접속 자동 진입을 검사한다.
- 개발 중 CMS 10개, 경기 26개 검사 통과. 최초 PostgreSQL fixture는 DDL 호환 계층의 일반 prepare가 스키마 변경을 생략하여 실패했으며, 테스트 환경의 공식 `execSchema` 경로로 수정했다. 운영 스키마는 변경하지 않았다.
- `scripts/prison-camp-admin-preview.mjs`: 127.0.0.1에만 열리는 메모리 DB 검수 환경. 운영 DB·인증·계정과 연결되지 않는다. 실제 CMS 사용자 상세 함수와 새 UI를 사용하며 `/camp?userId=999` 운영자, `/camp?userId=101` 수감자로 같은 서버 경기를 확인할 수 있다.
- PC 1280px, 모바일 390px: CMS 입력·수감 완료/중복 비활성, 선택 명단, 지정된 유저 자동 진입, 운영자 시작 및 참가자 새로고침 복구·닫기 잠금 확인. 승인된 수용소 배경과 실제 식사 모션은 보존했다.

배포 후에는 새 자산 반영과 비인증 API 차단만 짧게 확인하며, 실제 유저 수감이나 강제 경기는 실행하지 않는다.
