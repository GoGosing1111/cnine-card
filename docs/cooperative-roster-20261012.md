# 격전지 무작위 적·편성 공략 개편 — 2026-10-12

사용자 승인 범위: 여러 종류의 몬스터·보스 원화를 제작해 무작위 출현시키고, 현재 SSS 리미티드까지 포함해 난이도를 재측정하여 운영 반영한다. 수동 레이드 기믹 대신 카드·용병 편성으로 공략한다.

## 적용 규칙

- 몬스터 5종 중 서로 다른 3종 → 보스 4종 중 준보스 1종 → 준보스와 다른 최종 보스 1종. 서버의 방 생성 시드로 추첨하며 편성 전 원화·특성을 공개한다. 재접속·선택 변경·이탈 재계산으로 재추첨하지 않는다.
- 새 원화 6점: 철갑 사냥개·맹독 추적자·폭풍 감시자, 철벽 군주 바스티온·역병 여왕 베스페라·폭풍룡 템페스트. 기존 용철 추적자·불씨 감시기·삼핵 거신 아르케를 함께 사용한다. 준보스와 최종 보스는 같은 풀을 사용하되 단계별 예산·크기가 다르다.
- 방벽은 실제 방벽 파괴·방어 약화로 공략한다. 역병의 재생은 기존 회복 억제로 감소하며 총 회복량은 최대 HP 30%로 제한된다. 독·감전 약화는 기존 정화로 제거할 수 있다. 공격은 살아 있는 분대를 순환해 한 분대만 모든 공격을 받지 않는다.
- 3단계 모두 자동 전투. V3 신규 방에서는 수동 차단·엄폐·교란을 생성하지 않는다. 체력·방벽·스킬 사용 한도·대기 시간은 단계 사이에 이어진다. 기존 V2 방은 원래의 기믹·시점·설정으로 끝낸다.
- 용병 자체 능력치·등급·면역·SSS 리미티드 우위는 변경하지 않는다. 적 수치는 파티 전투력·닉네임·특정 보유 캐릭터에 따라 보정하지 않는다. 누구도 특정 캐릭터로 승리를 강제하지 않는다.
- CMS의 기존 5개 몬스터 칸은 출현 위치별 기본 능력치로 사용한다. 보스 특성 탭에서 종별 배율·방벽·공략을 표시한다. 현재 ON·참여자·입장/보상 잠금·경제 초안은 유지한다.

ICON은 +13, 용병 레벨 1, 고유 진급 없음 기준. 최고 성장의 진무·헬리오스·발테르 조합은 여전히 강하다. SSS 리미티드 1명을 일반 SS 간호사로 바꾸면 극한 승률은 1/120로 낮아진다. 모든 조합·장비 수준의 클리어를 보장하지 않으며 진무가 없는 조합의 클리어도 확인했다.

핑크빛유두의 최근 두 편성은 기존 전투를 정확히 20.4초·36.3초 승리로 재현했다. 동일 편성·장비·이탈 조건을 신규 적·난이도에 적용하면 84.32초·113.82초 패배다. 신규 전투에서 동료 분대의 성장과 생존·화력이 필요해진다. 과거 결과나 보유 재산은 수정하지 않는다.

## 배포 범위

단일 격전지 경로와 해당 V3 적 바인딩만 개편한다. 공통 전투 엔진에 추가한 특성 처리는 신규 격전지에만 활성화되며 인증·공통 DB/거래·스키마·의존성은 바꾸지 않았다. scoped 배포를 선택한다. 실제 직전 운영 소스는 `b8653399fbd142a3aa8369bf08c94dfbd26c45d3`, Pages `eb469d1c-1935-4971-9343-1a9bceb99d13`이다. 동시에 배포된 펫 연출을 병합해 유지했다.

- 관련 서버·CMS·구버전 방·재계산 검사 29개 통과. 이후 실제 WebSocket, 공용 전투/번들·메인 로더, Worker 컴파일·출시 플래그·캐시·Hyperdrive 검사로 scoped 배포를 완료한다.
- 새 CMS 기본 예산은 `rebalanceCoopCombat`을 통해 운영 문서에 **한 번만** 적용한다. 설정 버전 비교·행 잠금·백업/적용 영수증을 같은 DB 거래로 저장한다. 이후 CMS 수정은 자동으로 덮어쓰지 않는다. 이미 생성된 방은 저장한 예산을 유지한다.
- 자산과 API 배포를 먼저 마친 후 CMS의 `encounterVersion:3`과 새 예산을 같은 거래에서 활성화한다. 이 값이 없는 동안 운영 API는 V2 방을 생성하므로 업로드 전 새 이미지 경로를 공개하지 않는다. 이후 OWNER CMS 저장은 이 출시 버전을 보존한다.
- 운영 확인은 변경 자산/코드 해시와 비로그인 API 권한, CMS 적용 영수증·설정 버전만 짧게 확인한다.
- 첫 scoped 검사 54개 중 53개 통과. 기존 시간축 비교 테스트가 신규 방의 무작위 적 스냅샷을 기대값에 전달하지 않아 1개 실패했다. 실행 코드는 변경하지 않고 테스트를 V2/V3 및 시간축 1~4 조합으로 수정했다. 재개 검사는 해당 시간축 파일과 배포 도구가 요구하는 로더 검사·Worker 컴파일로 한정한다.
