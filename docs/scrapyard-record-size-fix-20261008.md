# 폐차장 원정 기록 용량 초과 수정 — 2026-10-08

폐차장 V3 입장 시 `원정 기록이 허용 크기를 초과했습니다. 입장권은 사용하지 않았습니다.`가 표시되는 문제를 수정한다. 전투가 길어지면 전체 타임라인을 포함한 일반 JSON이 기존 단일 기록 850,000바이트 또는 예약 묶음 700,000바이트 한도를 넘었다.

## 변경

- 전투·완료 영수증이 512,000바이트를 넘으면 gzip + base64로 손실 없이 저장한다. 전투 계산, HTTP 응답, 타임라인 이벤트는 그대로 유지한다.
- 기존 일반 JSON 기록도 계속 읽는다. 완료 조회·중복 요청·정산 재개·구형 경로의 완료 조회가 같은 디코더를 사용한다.
- 압축 기록 바깥에 엔진 표식과 난이도를 유지한다. 구형 미완료 입장권 환불이 V3 예약을 잘못 환불하지 않으며 복구 상태 조회도 유지된다.
- 저장 기록 최대 850,000바이트, 예약 묶음 최대 700,000바이트를 유지한다. 원문은 8MiB로 제한하고 해제 중 크기·UTF-8·메타데이터를 검증한다.
- DB 구조와 거래 SQL은 변경하지 않는다. 카우방 입장권 초기화와 경제 설정 작업은 다시 실행하지 않는다.

## 검증

- 현재 시즌 31개 덱 × 5개 난이도 × 3개 시드, 총 465회 전투: 전체 JSON 동일 복원. 기존 700,000바이트 초과 표본 10건을 포함한다. 최대 표본 808,144바이트 → 73,512바이트.
- 실제 workerd 환경(운영과 같은 compatibility date/flags): 1,228,976바이트 → 38,847바이트, 전체 JSON 동일 복원.
- 신규 회귀 4건: 일반/압축 기록 호환, 손상·과대 기록 거부, SQLite·PostgreSQL의 850KB 초과 실제 전투에서 정산 실패 롤백/동일 전투 재개/입장권 1회 차감/보상 1회 지급/완료 재조회, 잘못된 입력의 차감 전 거부.
- 기존 폐차장 서버 회귀와 신규 회귀, Worker 컴파일을 scoped 배포에서 실행한다. 공통 전투 엔진·인증·DB 기반 변경이 없는 폐차장 저장 버그 수정이므로 전체 게이트는 반복하지 않는다.
