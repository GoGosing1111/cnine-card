# 프리미엄 큐브 · FUR 첫 습득 보정 삭제

사용자 `프리미엄 큐브 삭제하고 보정습득 관련도 모두 삭제해 아이템도 다 지워`, 후속 `FUR 첫 습득 보정도 삭제`를 따른다. PREMIUM_CUBE, 주간 누적 확률·보장·부족 유저 보정, 카드팩 FUR 첫 습득(기존 2장 보정) 기능을 종료한다. 아이템 삭제는 프리미엄 큐브 전체 보유분과 해당 미수령 보상에 적용한다.

전투·소탕·PVP·무한의탑·대장전의 큐브 지급과 결과/프로필 필드를 제거했다. 레이드·요일 레이드·영토전·봉인전·몬스터 공성전·연금술·퀘스트·쿠폰·메시지·경매의 신규 큐브 보상을 막는다. 서버 초기화의 큐브/보정 시드와 CMS 메뉴·등급 확률·주간 설정·FUR 보정 화면, 전투 획득 연출을 삭제했다. 구형 CMS 설정 저장은 410으로 차단하고 큐브 사용은 기존 영수증 조회보다 먼저 거절한다.

일반 카드팩의 SSR 천장, 10/20/100연 보장, 리미티드 재고·차감·지급 검증과 일반 FUR 추첨 확률을 보존한다. 기존 습득 카드, 코인, 다른 인벤토리, MA/리미티드 확정 아이템과 퇴사 재뽑기권은 유지한다. 확정 아이템이 공유하는 큐브 그림은 해당 아이템의 기존 이미지로 남긴다. 과거 지급/개방/정산 로그와 완료 영수증은 감사 이력으로 보존한다.

운영 정리 모듈은 `scripts/ops/premium-cube-retirement-20261003.mjs`다. 키 `ops:premium-cube-retirement:20261003:v1`의 단일 PostgreSQL 트랜잭션으로 보유 큐브·카탈로그·5개 활성 설정·5개 전용 상태 테이블의 데이터·연금술 보상 풀·미수령 큐브 메시지/영토전 보상을 정리하고, 운영 설정과 미수령 보상 스냅샷에서 큐브만 제거한다. 다른 보상이 같이 있는 메시지는 다른 보상을 유지한다. 완료한 기존 큐브 쿠폰은 재활성/재수령 대상이 아니다. 입찰 중인 큐브 경매가 있으면 환불을 먼저 요구한다. 점검 당시 경매 1건은 이미 SOLD였고 활성 경매는 없다.

적용 직전 원본은 배포 디렉터리 밖 `C:/Users/User/.codex/tmp/premium-cube-retirement-20261003/`에 비공개로 저장한다. 전체 획득 시도 영수증의 원본 덤프 대신 삭제 건수를 기록하고 기존 지급 감사 로그를 유지한다. 백업 실패·중간 실패·감사 로그 실패는 롤백한다. 재실행은 완료 키를 읽어 추가 삭제/로그 없이 같은 결과를 돌려준다.

## 범위 검사와 배포

- 직전 운영 배포: `ad4600e0-4e8e-4f70-8f3e-dd1f45eeb412`, 소스 `15c4d84e88fd72f7d1dffbf794ba78f75573d321`. 원격의 리치왕 후속 수정과 완료 기록 `b2cf6de2`를 먼저 병합했다.
- 국소 기능 폐기다. 공통 인증·세션·DB/트랜잭션 기반·스키마·의존성을 바꾸지 않고, 한 기능의 지급/보정 분기와 UI를 제거한다. 전용 테이블은 비우고 공유 보상 테이블의 과거 컬럼은 감사 이력으로 남긴다. `npm run deploy:production -- --scoped`를 사용한다.
- 관련 검사: 삭제/재시도/롤백 PostgreSQL 회귀, 큐브 없는 FUR 일반 추첨·카드팩 차감/천장 보호, 소탕, 인벤토리/재뽑기, 레이드 보상/CMS, 봉인전 코인 원자성, 쿠폰, 연금술, 영토전 100회 참여 보상과 Worker 컴파일이다. 필요한 검사 후 PC·모바일 변경 화면과 운영 삭제 결과만 짧게 확인한다.
- 삭제 자체는 신규 런타임 배포 후 실행한다. 출시 잠금/펫/용병/아바타/쿠데타 설정은 이번 변경 범위가 아니다.

첫 범위 검사는 92개 중 89개가 통과했고, 배포 전 검사 단계에서 중단됐다. 실패 3개는 재뽑기 검사에 남은 오래된 캐시 버전, 소탕 스크립트의 쿼리 파라미터 순서 고정, PostgreSQL SUM 결과 문자열/숫자 비교였다. 실행 코드를 바꾸지 않고 해당 검사만 수정했다. 통과한 나머지 8개 검사 파일은 반복하지 않고 실패한 3개 파일과 아직 실행하지 않은 Worker 컴파일을 이어서 검사한다.
