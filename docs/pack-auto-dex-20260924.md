# 하이퍼팩·블랙미라클 자동 개봉 / 도감 멈춤 수정

## 범위

- 사용자 요청: 하이퍼팩 반복 클릭 없는 개봉, 블랙미라클 첫 번째 카드 자동 선택, 카드 도감 진입 렉 최적화.
- 서버 확률·상품 풀·재화 단가·기능 ON/OFF·지급 SQL은 변경하지 않았다. 블랙미라클의 현재 CMS 개방 상태도 보존한다.
- 하이퍼팩: 총 1~1,000회와 1회/10회 단위를 직접 선택하고 최대 코인 비용을 확인한 후 시작한다. 마지막 잔여 횟수만 요청하므로 12회 선택은 10+2회다. 후속 지시에 따라 자동 개봉은 완료 영수증 확정 후 연출 없이 결과만 표시한다.
- 블랙미라클: 보유 수량 이내(한 세션 최대 1,000개)로 설정하고 1개씩 개봉한다. 기존 서버 추첨 결과를 첫 번째 카드에서 공개한다. 첫 칸을 고른다고 당첨 확률이나 상품이 달라지지 않는다. 수동 선택은 유지한다.
- 자동 개봉은 화면 진입만으로 시작하지 않는다. 중지·화면 이탈·계정 변경·실패 시 후속 소비를 중단하며, 진행 중인 거래의 결과는 확인한다. 하이퍼팩 미해결 영수증은 먼저 복구하도록 안내한다. 블랙미라클 불확실한 응답 재시도는 동일 요청 ID를 유지한다.
- 자동 개봉을 새로고침 후 자동 재시작하지 않는다. 하이퍼팩 모듈의 HTML/동적 import URL도 통일해 중복 클릭 리스너 설치를 방지한다.

## 도감 원인

- 카탈로그 415행 / 고유 ID 415개. 진입 시 실제 카드 DOM 19개, 멤버 섹션 87개 중 2개만 생성되는 기존 지연 렌더링은 정상이다.
- `high-grade-reroll-v1354.js`가 전체 DOM 변경마다 `injectButton()`을 실행하고, 상태 응답마다 같은 `small.textContent`를 다시 써 자기 자신을 호출했다. 캐시된 Promise와 MutationObserver가 미세 작업 루프를 만들고 모든 전역 observer까지 반복 실행했다.
- 변경 전 5초 idle trace에서 약 1,001.955 / 1,001.316 / 1,000.946ms의 긴 작업 3개를 관측했다. 네트워크에도 `high-grade-reroll/state` 반복 GET이 지속됐다. 이 측정은 실계정 카드를 변경하지 않는 읽기 전용 진입이었다.
- 버튼 인스턴스별 한 번만 연결하고, 진행 중 조회를 공유하며, 문구가 달라질 때만 DOM을 쓴다. 계정 갱신 시만 재조회하고 이전 계정/사라진 버튼에 대한 늦은 응답은 무시한다. 기존 중복 수량·소유권·강화 수치는 전혀 변경하지 않는다.
- 원본 trace: Windows Temp의 `dex-before-20260924.json.gz`, `dex-idle-before-20260924.json.gz` (개인 진단 파일, 저장소 외부).

## 후속 요청 — 자동 개봉은 결과만 빠르게 표시

- 사용자: “연출 말고 자동개봉때 결과값만 보이고 빨리빨리 다음꺼”, “카드 한장씩 보이면서 연출 다 보면 느리니까”.
- 자동 하이퍼팩은 기존 설정 창에서 등급·이름·수량·중복 여부를 한꺼번에 갱신한다. SS/SSS 영상, 카드 뒤집기, Pixi FX, 결과 원화 로딩을 전부 건너뛴다. 수동 개봉과 최근 결과 복구의 기존 연출은 보존한다.
- 자동 블랙미라클은 서버가 확정한 첫 카드 결과의 상품·수량만 표시한다. 봉인 해제 대기, 카드 배열, 선택/뒤집기, 원화 사전 로딩, 진동을 건너뛴다. 수동 5장 중 선택은 보존한다.
