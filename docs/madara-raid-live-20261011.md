# 마다라 레이드 운영 TEST — 2026-10-11

사용자 후속 지시 `마다라 레이드 라이브 올리고 TEST상태로 해놔 내가 ON으로도 하고 설정할수있게 하고`에 따른 운영 연결이다. 과거 준비 문서의 미출시·배포 금지는 당시 이력이다. 기존 개인 판단 V3, 5단계 협동 기믹, 본인 공격 몫, 보스 자막과 전용 효과 자산을 유지한다.

## 운영과 설정

- 게임: 모험(PVE) → 레이드 → 마다라 레이드. 기존 메인 화면 안에서 실행하며 공용 V3 렌더러·아트 어댑터·진형·로스터를 사용한다.
- CMS: 레이드 관리 → 마다라 레이드. OWNER가 OFF/TEST/ON, 정확한 닉네임/계정번호 기반 테스트 참여자, 보스 전투력, 모집/광폭화 시간, 기믹 전체 제한 시간 비율, 생성 입장권 수량, TEST 무료 여부를 저장한다.
- 주간 횟수와 코인·마별·펫 정수 보상 수량, ON 공대 보상 지급 여부를 별도로 설정한다. 기믹 시간 비율은 전체 단계 마감만 바꾸며 개별 반응 구간은 유지한다.
- 최초 기본값: TEST / 테스트 명단 없음 / 보스 440,000 / 모집 15분 / 광폭화 360초 / 기믹 시간 100% / 생성 입장권 1장 / TEST 무료 / 주간 7회 / 보상 OFF·수량 0. 초기 설정은 존재하지 않을 때만 저장하며 후속 CMS 설정을 덮어쓰지 않는다.
- TEST는 OWNER와 지정 계정만 메뉴·API에 접근한다. ON은 일반 계정에도 공개한다. OFF에서는 입장/행동을 차단하되 기존 공대에서 퇴장할 수 있다.

## 실계정 연결

공대 생성·참가·준비는 서버에서 실제 계정과 저장된 RAID 5장 편성을 읽는다. 임의 닉네임·덱·다른 참가자 입력은 받지 않는다. 3~6인, 봉인대·정벌대·구출대가 모두 준비해야 출정한다. 강퇴는 공대장이 출정 전에만 실행하고 해당 방에 재참가할 수 없다. 모집 중 공대장 퇴장 시 다음 참가자에게 위임한다. 전투 중 퇴장은 공대 실패로 종료한다.

공대, 현재 참가 예약, 명령 영수증은 전용 `raid_madara_*_v1` 테이블에 저장한다. 새로고침/다른 워커에서도 복구하며 방 생성의 입장권 차감·인벤토리 로그·예약·방·영수증은 하나의 트랜잭션이다. 계정 잠금, 방 버전 CAS와 요청 서명을 함께 사용한다. 목록 갱신/읽기도 만료된 공대를 정리한다.

보상은 ON에서 생성하고 ON에서 출정하며 보상 지급을 켠 공대만 받는다. TEST 생성 공대는 이후 공개 모드와 무관하게 미지급이다. 난이도는 생성 시, 보상은 출정 시 고정한다. 클리어 상태·전체 참가자 보상·주간 횟수·명령 영수증을 한 번에 저장한다. 실패 시 전부 롤백하고 동일 요청을 재전송해도 한 번만 지급한다. 0개/지급 OFF는 주간 횟수를 소모하지 않는다. 매주 월요일 00:00 KST를 기준으로 집계한다. 별도 트로피 정책은 추가하지 않는다.

입장권은 CMS 유저관리의 기존 인벤토리 지급 경로로 지급한다. 참가자는 무료이며 생성 후 해산·실패·퇴장에 따른 반환은 없다. 신규 입장권은 보유하지 않은 일반 인벤토리 목록에 노출하지 않는다.

## 화면과 검증

준비판의 HTML/CSS·프레젠테이션·전투·기믹 UI를 `scripts/build-madara-live.mjs`로 운영용 `raid/madara/`에 생성한다. DOM과 타이머·이벤트·요청을 인스턴스 범위로 격리하며 다른 콘텐츠로 이동하면 폴링과 렌더러를 종료한다. 로컬 검수 계정/감상용 API는 운영에서 사용하지 않는다.

- 관련 기존 28개와 운영 서버 11개 회귀: TEST/ON/OFF 권한, CMS 충돌, 강퇴/복귀/만료, 6인 동시 참가, 실제 덱/입력 소유권, SQLite·PostgreSQL의 입장권/클리어 재전송·원자성/주간 보상.
- 실제 메인 게임 HTML의 1440×1000, 390×844 브라우저 검증: 공대 생성, 강퇴, 재입장 금지, 준비/출정, V3 전장·기믹 이미지, 안내 팝업, 다른 탭 이동 시 폴링 종료, 복귀, 퇴장. 콘솔 예외·가로 넘침 없음.
- 실제 CMS HTML의 두 화면 크기에서 TEST→ON→OFF→TEST, 계정 검색/추가/제외, 난이도·5천억 코인 값 저장과 새로고침 복원. 운영 DB가 아닌 메모리 검수 계정만 사용한다. 모바일 레이드 관리 화면은 기존 전체 높이 내비게이션이 폼을 덮지 않도록 범위를 한정해 보정한다.
- 명령: `npm run test:madara-raid`, `node tests/madara-raid-live-20261011.browser.mjs`. 브라우저는 `PLAYWRIGHT_MODULE`, 트리 밖 `MADARA_QA_DIR`를 지정한다. `MADARA_CMS_ONLY=1`은 CMS만 재검증한다.
- 새 DB·거래 경로가 포함되므로 `npm run deploy:production`의 전체 출시 게이트를 사용한다. 운영 결과와 배포 식별자는 배포 완료 후 기록한다.

로컬 QA 원본은 기존 작업 폴더의 `tmp/madara-live-20261011/qa` 및 `qa-cms`에 보존한다. 초기 공개는 TEST이며 체감 난이도와 실제 유저 동시 플레이에 따른 수치는 CMS에서 조정할 수 있다.

후속 검증: 서버의 `MADARA_KICKED`를 준비판 클라이언트의 `KICKED` 복귀 코드에 연결했다. 별도 참가자 브라우저에서도 강퇴 후 자동 대기실 복귀를 확인했으며 최종 PC·모바일 게임/CMS 검수는 `qa-final`에 보존한다.
