# 장비 강화·보호·복구 ON 준비 — 2026-09-22

## 범위와 보류

사용자 요청은 CMS에 저장한 장비 강화·보호·복구를 검증하고 ON을 준비하는 것이다. **실제 ON 지시는 아니다.** 운영 계정 재화·장비로 시험하지 않는다. 격리 SQLite/PostgreSQL에서 거래를 실행하고 운영 Neon SQL은 읽기 전용으로 확인했다. 배포 후 OWNER CMS에서 승인된 보호권 제한만 초안 r5로 저장했다.

- 복구는 최신 CMS대로 **핑두 리페어 쿠폰 1장 + 1,000억 코인**, 파괴 직전 단계, 기한 없음. 이전 추가 코인 0 승인보다 이번 명시적 답변을 우선한다.
- 보호권은 **+9 도전 1장 / +10 도전 3장**, 강화 시도마다 소모(`ON_ATTEMPT`). +1~+8 도전은 사용 불가.
- **+1~+6 도전의 파괴확률은 운영 r4에 `null`**이다. 성공+유지=100%여도 빈칸을 승인된 0으로 바꾸지 않았다. 0% 확정 답변 또는 CMS의 명시적 입력이 필요하다.
- 코드 `EQUIPMENT_FORGE_RELEASE_ENABLED=false`, 기존 V3 공동 게이트 false, 공개 설정 `executionMode=OFF`를 유지한다. 서버/화면/획득 경로에 준비 코드를 추가한 것이 기능 활성화는 아니다.

## 보강한 구현

1. 보호권 수량 `0`은 명시적 사용 불가로 검증한다. `null`은 계속 미설정이다. 서버에서 보호권 0장 무료 보호를 거절하고 화면의 해당 단계 선택도 막는다.
2. PostgreSQL 복구는 `INSERT ... RETURNING`을 CTE로 연결하여 새 인스턴스 ID를 단계/파괴 기록에 직접 전달한다. 방대한 장비 테이블에서 요청번호를 재검색하지 않으며 다른 콘텐츠의 같은 요청번호와 혼동하지 않는다. SQLite 대체 경로도 복구 출처·기록을 함께 한정한다.
3. 무한의탑 현재 운영 `tower/fight`의 최초 클리어 거래에 보호권을 연결한다. 별도 재등반 초안은 열지 않는다. 판정은 층/계정별 서버 영수증에 고정하고 진행도·지급·완료 처리를 같이 커밋한다. 폐차장/카우방의 기존 원자 지급 경로도 같은 승인 문서를 사용한다.
4. 강화 전용 출시 게이트를 준비하여 과거 통합 V3 스위치를 켜지 않고 강화 실행·공통 전투력·획득 경로를 함께 연결할 수 있게 했다. 현재 게이트는 false다. 승인 문서가 없거나 불완전/변조됐으면 실행을 거절한다. CMS 초안 저장은 승인이나 ON이 아니다.
5. OWNER 실행 스위치는 코드 최종 게이트와 검증된 승인 문서가 갖춰진 뒤에만 열릴 수 있다. OFF에서는 신규 강화·복구·보호권 추첨을 막고 이미 완료한 거래는 같은 영수증으로 확인한다. 기존 강화 장비의 전투력은 실행 일시중지와 구분한다.
6. 기존 승인 UI/이펙트 자산은 보존한다. 비용은 억 단위, 확률 막대는 실제 견적, 결과 연출 실패 시에도 확정된 계정 상태 갱신, 새로고침 후 같은 요청 복구를 보강했다. 복구 연출은 영수증의 실제 대상 장비를 사용한다.

## 최종 ON 순서 (아직 실행하지 않음)

1. +1~+6 파괴확률을 명시적으로 확정한다. +1~+8 보호권 0은 r5에서 저장 완료다. 최신 CMS를 다시 읽고 revision 충돌 없이 준비한다. 1,000억과 나머지 운영값을 유지한다.
2. 모든 필드·활성 재료·경제 검수를 다시 확인하고 사용자 **최종 ON 지시**를 받는다.
3. 최신 정책과 실제 승인 기록을 포함한 문서를 `scripts/prepare-equipment-forge-release.mjs APPROVED_DOCUMENT.json OUTPUT.sql`로 오프라인 컴파일한다. 미완성/미승인 문서는 생성 거절. 생성 SQL은 현재 CMS 일치·기존 승인 문서 보존·감사 기록을 검증하며 계정 재화, 실행 스위치, V3 스위치를 변경하지 않는다.
4. 검토한 문서를 저장하고 강화 전용 코드 게이트를 최종 승인 범위에서 연다. 현재 준비 전용 테스트의 OFF 고정 검사를 최종 출시 승인·문서 검증 검사로 전환하는 것도 이 승인 작업에 포함한다. 기존 V3 전역 게이트는 바꾸지 않는다. 깨끗한 최신 후보의 `npm run release:gate` 후 **`npm run deploy:production`만** 사용한다. 운영 Hyperdrive SQL 캐시 OFF 검사 유지.
5. OWNER CMS 실행 스위치를 ON으로 저장한 뒤 강화·보호·복구·탑/폐차장/카우방 드롭·전투력·모바일을 재확인한다. 임의 계정으로 재화를 소비하지 않는다.
6. 긴급 중지는 OWNER 실행 OFF. 완료 영수증·장비 상태·감사 기록은 삭제하거나 초기화하지 않는다. 승인 문서는 기존 것을 덮어쓰지 않으며 정책 변경은 새 버전과 별도 검수로 한다.

현재 이 문서는 준비/검증 기록이며 미설정 확률 확정, 최종 ON 승인, 실제 활성화 완료를 대신하지 않는다.
