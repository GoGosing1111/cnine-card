# +10 장비제작 및 실패 누적 천장 — 2026-09-28

## 사용자 확정 사항

- `기타 합성`을 `장비제작`으로 변경한다. 내부 분류 `ITEM_SYNTHESIS`는 기존 데이터 호환을 위해 유지한다.
- +10 장비 1개 + 재료 + 마스터의 별 + 코인을 사용한다. 기본 성공률은 10%다.
- 실패하면 투입 장비 및 +10 강화는 그대로 남고, 나머지 재료·별·코인은 소모된다.
- **실패 N회가 누적된 다음 제작이 100% 성공**한다. N번째 실패 자체를 성공으로 바꾸지 않는다.
- 실패 횟수는 유저·조합식 ID별로 저장한다. 재접속·새로고침·동일 조합식의 투입 장비 변경·레시피 코드 변경으로 초기화하지 않는다. 성공하면 0으로 초기화한다.
- 미스틱 장비와 SKS 조합식의 대상·결과·재료·수량·비용·천장 횟수는 사용자가 직접 CMS에 등록한다. 이번 배포에서 운영 조합식과 임의 비용·천장 수치를 생성하지 않는다.

## CMS / 제작 화면

`제작소 관리 → + 장비제작`에서 새 조합식을 추가한다. 투입 장비, 결과 장비, 재료·수량, 별·코인 비용, 천장 기준 실패 횟수를 입력한다. 10%·결합 결제·결과 장비 1개는 고정이며, 초안은 운영 OFF·유저 비공개·OWNER 테스트로 시작한다.

장착하지 않은 본인 소유 +10 대상 장비만 제작 화면에서 선택할 수 있다. 화면에는 투입/결과 장비, 실패 보존 규칙, 누적 횟수, 기본 10% 또는 이번 확정 성공 100%, 소모 비용이 표시된다. 성공 시 투입 장비는 소비하고 결과 장비는 기존 장비 지급 규칙대로 +0으로 지급한다. 천장 제작도 동일한 비용이 필요하다.

## 거래 / 저장

- 새 API `POST /api/workshop/equipment-craft`는 기존 공용 계정 변경 잠금, `runJointOperation`, 원자적 SQL batch를 재사용한다. 공통 트랜잭션·인증 구현과 DB 스키마는 변경하지 않는다.
- 조합식 설정: `app_meta.WORKSHOP_EQUIPMENT_CRAFT_V1:<recipe code>`. 실패 누적: `app_meta.WORKSHOP_EQUIPMENT_PITY_V1:<user id>:<recipe id>`.
- 확률 결과를 영수증 계획에 고정한 뒤 차감·장비 소비/지급·실패 누적·로그·완료 기록을 함께 커밋한다. 실패 중간 오류는 전부 롤백하고, 같은 요청번호 재시도는 재판정/중복 차감을 하지 않는다.
- PostgreSQL은 결과 장비 INSERT의 실제 지급 행수가 정확히 1개인지 확인한다. 지급이 0행이면 장비·재화·천장 변경 전체가 롤백된다.
- CMS 설정과 누적 상태의 버전 비교, 활성/공개/OWNER 조건, 본인 소유·비장착·정확한 +10·강화 revision을 거래 안에서 검증한다. 기존 `workshop/craft`로 +10 조건을 우회할 수 없다.
- 장비 후보 조회는 강화 상태를 먼저 구체화하고 인스턴스 PK로 조회한다. 일반 장비 전체를 세지 않으며 최대 1,000개와 초과 여부만 반환한다. 새 조합식이 없으면 추가 설정/장비/천장 조회는 실행하지 않는다.
