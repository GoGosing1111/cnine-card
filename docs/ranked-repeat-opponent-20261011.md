# 랭크전 연속 상대 전투 거부 수정 — 2026-10-11

자동 배정 후 `RANKED ERROR`와 ‘같은 상대와는 연속 3회 이상 대전할 수 없습니다’가 표시되는 제보를 수정한다.

- 10월 7일 매칭 완화는 다른 적합 후보를 우선하고, 제한된 검색 범위에 대안이 없을 때 같은 상대를 허용한다. 실제 전투에 남아 있던 과거의 무조건 거부 조건이 발급된 티켓을 폐기하고 있었다.
- `pvp/fight`의 중복된 연속 상대 차단 및 최근 2경기 조회를 제거했다. 상대 선정은 기존 `createRankedMatchTicket`/`selectRankedCandidate` 정책을 따른다.
- 서버 티켓의 소유자·시즌·만료·사용 여부와 현재 점수·편성 재검증, 행동력·점수·보상 원자 처리 및 영수증 재시도는 그대로다. 매칭 범위, CMS 값, 전투 계산, 화면 코드는 바꾸지 않았다.
- 오류는 행동력 차감 이전에 발생했다. 이번 수정은 과거 보상이나 기록을 다시 처리하지 않는다.

## 관련 검증

- 수정 전 새 회귀: 실제 `pvp/fight` 분기에 최근 상대 `[2, 2]`와 유효한 서버 티켓을 넣으면 동일한 `PVP_REPEAT_OPPONENT_LIMIT` / HTTP 409 재현.
- 수정 후 `ranked-matchmaking-20261007`, `ranked-fight-performance-20260929`, `ranked-reform-20261002`의 관련 검사 **29개 통과**. 대안 우선/유일 상대 허용, 티켓 재사용, SQLite·PostgreSQL 거래 원자성, 중복 차감 방지 포함.
- 배포 게이트에서는 추가한 `ranked-ticket-boundary-20261011.test.mjs`로 실제 티켓 조회의 계정·시즌·만료·재사용 경계를 확인하고 `check:worker`를 실행한다. 위 29개 검사는 실행 코드가 그대로이므로 반복하지 않는다.
- UI·전투 연출 변경 없음. 서버 조건 한 곳을 수정한 소규모 범위로 `npm run deploy:production -- --scoped`를 사용한다.
