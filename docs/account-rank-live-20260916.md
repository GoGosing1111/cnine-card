# 계정 레벨·계급 운영 연결

사용자 승인: 실계정 EXP·계급·혜택까지 연결 후 배포. 전원 Lv.1, 최대 Lv.250. 21개 백호 군인 계급장을 사용한다. 선행 시안의 50일 목표 이후 지급량 인하 지시가 우선하며, 곡선은 재조정하지 않았다. 성장 방법·원천별 지급량·전체 성장식은 공개하지 않는다. 후속 경험치 바 요청에 따라 현재 레벨의 EXP·다음 레벨 필요량·진행률은 표시한다.

## 서버 계약

- `functions/_account_rank.js`가 유일한 운영 성장 정책이다. 정수 tick(1 EXP=600 tick)으로 방치형 원정의 소수 EXP를 보존한다.
- `account_rank_progress_v1`, `account_rank_receipts_v1`, `account_rank_presets_v1`, `account_rank_idle_cursor_v1`를 멱등 생성한다. PostgreSQL은 기존 DB 어댑터의 `execSchema`를 사용한다.
- 미기록 계정은 0 EXP/Lv.1로 조회한다. 과거 전투 로그를 재계산하지 않는다. 방치형 원정도 첫 관측을 기준점으로 삼는다.
- `(user_id,source,event_id)` 영수증과 이번 정산 전용 token으로 중복 지급을 차단한다. 기존 콘텐츠 보상 정산 트랜잭션에 EXP를 함께 저장한다. EXP 일일·원천별 상한을 추가하지 않는다.
- 토벌·아포칼립스는 승리, 월드 레이드는 유효 전투 종료, 호송·균열·폐차장은 확정 정산, 공성·봉인전은 유효 전투, 카우방은 클리어, 탑은 기존 최초 층 클리어, 방치형 원정은 실제 정산 시간을 기준으로 연결한다. 운영 입장 제한과 기존 보상 상한은 유지한다. 보상이 잠긴 Core TEST 레이드는 제외한다.
- 후속 지급량: HUNT 8 / APOCALYPSE 24 / RAID 20 / ESCORT 30 / SIEGE 120 / SEAL 160 / TOWER 10 / SCRAPYARD 20 / COW_ROOM 30 / RIFT 30 EXP. IDLE 6 EXP/시간. 기존 균열은 전체 PVE 포함 요청에 따라 원정 1회 30 EXP로 연결했다.
- 최대 누적 EXP 139,440. 인하 후 봉인전·공성 참여량에 따라 도달 기간이 달라진다. 50일을 날짜 잠금이나 보장 기간으로 구현하지 않는다.

## 혜택·공개 화면

- 계급별 최종 공격력 0~10%, HP 0~15%, 개인 PVE 기본 코인 0~5%, 일반 카드 편성 보관함 1~5칸.
- 공격력/HP는 토벌·아포칼립스·호송·폐차장·카우방의 서버 일반 카드 스냅샷에 적용한다. 방치형 원정·기존 균열은 기본 코인 혜택을 적용한다.
- PVP·클랜·영토·월드 레이드·봉인전·공성·탑은 전투 효과를 적용하지 않는다. 전투 버프가 경쟁 순위를 바꾸지 않는다.
- 편성은 인증 계정의 저장된 일반 카드 5장만 보관한다. 적용할 때 현재 소유 여부와 기존 등급 제한을 재검증한다. 용병 전용 슬롯은 일반 카드 배열에 넣지 않는다.
- API에는 레벨·계급·효과·보관함과 현재 레벨의 `progress`만 노출한다. 누적 tick·지급 원천·전체 곡선은 제외한다. 로비 공통 헤더, 내 계정, 실제 명함, 전투 출전 카드 이름에 계급장을 연결했다.
- 공통 헤더의 닉네임·계급은 PC에서 가로 배치하며 계급·레벨을 확대한다. 모바일은 로고·계정·계급·메시지함을 같은 행에 유지한다. 헤더와 계급 상세창에 EXP 바를 표시하고 Lv.250은 MAX로 표시한다.
- 21종 원본 PNG는 보존하고 96px/384px WebP를 서비스한다. 원본 디자인 재생성 없음.
- Pages 미들웨어로 계급 관련 docs/scripts/tests 및 프리뷰 README·프롬프트·매니페스트 접근을 404 처리한다. 공개 모델에는 성장식이 없다.
- 서비스워커는 공통 로비·명함·계급 스크립트의 이전 쿼리 URL도 새 파일로 갱신한다. 전투 엔진 버전과 기존 준비 계약은 유지한다.

## 검수·배포

- SQLite/PostgreSQL에서 전 레벨 경계, 모든 지급 경로 정책, 중복/롤백/계정 격리/최고 레벨, 방치 시간의 소수 누적·중단 시간 제외, 편성 권한·소유·등급 재검증, PVP 능력치 동일성을 검증한다.
- `tests/account-rank-live-v1.test.mjs`를 `test:account-rank` 및 `release:gate`에 포함한다.
- 운영 index.html과 실제 V3 번들, 로컬 인증·정산 DB를 사용하는 `scripts/serve-joint-account-qa.mjs`로 PC 1280px/모바일 390px에서 검수한다. 운영 계정 재화를 소비하지 않는다.
- 2026-09-16 사전 검수: 두 해상도에서 토벌/랭크전 시작 → 결과 → 복귀, 토벌 재입장·PVE→PVP 전환 성공. 로딩 오류 주입 시 두 해상도 모두 오류 안내와 실제 복귀 버튼 확인. 실제 명함 계급장, 21계급 선택, 편성 1번 보관·적용 및 잠금 슬롯 확인. 계급/명함/실제 번들 진입 회귀 39건 통과.
- 배포 후 `JOINT_QA_STATIC_ORIGIN=https://cnine-card.pages.dev`로 실제 운영 정적 파일을 사용해 같은 입장 버튼 경로를 재검수할 수 있다. `JOINT_QA_FAIL_BATTLE=1`은 로컬 렌더러 로딩 오류 검수용이다.
- 깨끗한 범위 커밋을 origin/main에 반영한 뒤 `npm run deploy:production`(내부 `npm run release:gate`)만 사용한다.

롤백 시 코드만 이전 검증 버전으로 되돌린다. 성장·영수증 테이블과 확정된 계정 누적치는 삭제하거나 초기화하지 않는다.
