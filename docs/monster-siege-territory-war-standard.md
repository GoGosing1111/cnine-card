# 몬스터공성 지도형 진영전 설계 기준

상태: `APPROVED / FIXED`

이 문서는 숲켓몬 몬스터공성의 서버 구조, 전황 UI, 몬스터 AI 편성에 적용하는 단일 기준이다.

## 1. 콘텐츠 정체성

- 몬스터공성은 한 마리 보스의 체력을 반복해서 깎는 레이드가 아니다.
- 영토전처럼 지도에서 전선이 전진·후퇴하는 비대칭 진영전이다.
- 유저 진영은 저장된 기존 PVE 덱으로 공략하며 별도 공격·방어 덱을 만들지 않는다.
- 몬스터 진영은 AI가 돌격대와 방어대를 각각 운용한다.

## 2. 지도와 거점

- 지도는 연합 본진 1개와 순차 공략 거점 5개로 구성한다.
- 거점 상태는 `연합 점령`, `현재 교전`, `몬스터 점령` 세 가지다.
- 유저 진영이 현재 전선에서 승리하면 다음 거점으로 전진한다.
- 몬스터 돌격대가 연합 진영 체력을 0으로 만들면 직전 거점을 탈환하고 현재 전선이 한 칸 후퇴한다.
- 첫 전선에서 연합 진영 체력이 0이 되면 공성전은 방어 실패로 종료한다.

## 3. 진영 체력

- 상단 핵심 게이지는 `숲켓몬 연합 진영 체력`과 `몬스터 군단 진영 체력` 두 개다.
- 기존 `phase_hp`는 호환을 위해 DB에 유지할 수 있으나 공개 의미와 UI 표기는 몬스터 개체 HP가 아니라 현재 전선의 몬스터 진영 체력이다.
- 기존 AI 동반 상태의 `alliance_hp`는 현재 전선의 연합 진영 체력으로 사용한다.
- 개별 몬스터 카드나 SD 유닛에 공성용 HP 게이지를 붙이지 않는다.

## 4. 몬스터 방어대

- 각 거점에는 3기의 방어대가 주둔한다.
- 방어대는 탱커, 화력, 지원처럼 역할을 분리하며 지도에서 개별 유닛으로 보인다.
- 유저 출전 시 현재 거점 방어대 중 한 기가 전투 상대로 선택된다.
- 전투 결과로 주는 공성 피해는 선택된 유닛 개인이 아니라 몬스터 진영 체력에 적용한다.

## 5. 몬스터 돌격대

- 각 전선에는 방어대와 별개인 3기의 돌격대가 존재한다.
- 돌격대는 일정 주기마다 연합 진영을 공격하고, 전용 작전 스킬을 사용한다.
- 지도에서 돌격대의 현재 출발 거점, 이동 경로, 다음 공격 목표, 다음 행동 시간을 확인할 수 있어야 한다.
- 돌격대의 공격으로 연합 진영 체력이 소진되면 거점 탈환과 전선 후퇴가 발생한다.

## 6. 원화와 SD 리소스

- `assets/siege/phase-*.webp` 대형 원화는 전선 분위기와 지휘관 정보에만 사용한다.
- 지도·진형의 개별 몬스터는 `assets/ui/project-v/monsters/hunt-tower/`의 승인된 투명 SD 전신 리소스를 사용한다.
- 대형 원화 한 장을 확대해 개별 몬스터 부대처럼 재사용하지 않는다.

## 7. UI 금지·허용 규칙

- 금지: 마름모, 회전된 정사각형, 다이아 아이콘, 다이아 거점, 다이아 장식, 다이아 게이지.
- 허용: 원형 거점, 회전 없는 직사각형 패널, 직선·곡선 이동 경로, 일반 원형 상태등.
- 핵심 화면의 우선순위는 `양 진영 체력 → 지도 전황 → 현재 거점 방어대 → 이동 중 돌격대 → 유저 출전 → 작전 기록` 순서다.
- 단일 몬스터와 유저 성채를 좌우로 세운 VS 구도는 사용하지 않는다.
- PC와 모바일 모두 지도와 양 진영 체력을 첫 화면에서 확인할 수 있어야 한다.

## 8. 구현 검수 조건

- 공개 상태에 지도 노드, 현재 전선, 양 진영 체력, 방어대, 돌격대, 이동 목표가 포함되어야 한다.
- CSS와 HTML에 공성 UI용 `rotate(45deg)` 또는 다이아 `clip-path`를 포함하지 않는다.
- 전투 상대는 현재 방어대에서 선택되어야 한다.
- 몬스터 AI 행동은 돌격대 소속 유닛과 작전명을 기록해야 한다.
- 전선 전진·후퇴 시 양 진영 체력과 방어대·돌격대가 새 거점 기준으로 갱신되어야 한다.
