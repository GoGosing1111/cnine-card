# PVE·PVP 공통 입장 로딩 복구

하이희야 운영 연결 후 엔진과 V3 래퍼는 `2119-battlefield-contract-heeya-2118`을 사용했지만, 메인 앱의 기능 로더는 이전 `2119-battlefield-contract`만 준비 완료로 인정했다. 실제 브라우저에서도 모든 스크립트를 받은 뒤 `battleV2 기능 초기화에 실패했습니다.`가 발생했다. 독립 전투 브리지 검수는 메인 앱의 준비 검사를 지나지 않아 이 누락을 검출하지 못했다.

앱의 중복 버전 비교를 제거하고 V3 래퍼가 보유한 필수 버전으로 준비 상태를 검사한다. 기능 로더는 최종 검사 전에 래퍼의 기존 엔진 갱신 절차를 호출하므로, 이미 열린 세션의 오래된 엔진도 한 번만 갱신한다. 앱과 래퍼 URL에는 `entry=2121` 캐시 키를 추가했다.

PVE·PVP의 오류 처리에는 결과 영역을 드러내는 부모 상태가 빠져 있었다. 실패 문구만 작성하고 실제 투명도는 0으로 유지돼 배경만 보였다. 두 진입 오류에서 `is-result-visible`을 적용하고 로더를 제거해 복귀 조작이 보이도록 수정했다.

원화·SD·스킬·전투 엔진 번들·서버 전투 계산·CMS·확률·보상은 이 수정에서 변경하지 않는다.

검증:
- 배포된 실제 번들의 버전을 읽어 메인 기능 로더와 연결하는 회귀 검사를 추가했다. 수정 전 현재 버전의 준비 판정과 오래된 버전 복구 검사 모두 실패했고, 수정 후 통과했다.
- 관련 일반 PVE/PVP·연속 전투·레이드 복구 검사 17개를 통과했다.
- 실제 메인 앱의 토벌 시작과 랭크전 매칭 버튼을 사용해 1440/390/320px에서 전투 진입·결과·복귀를 확인했다. 검수 덱은 실제 원화/SD가 있는 FUR 2장·PRESTIGE 2장·ZENITH 1장과 별도 하이희야 용병이며, 별도 로컬 계정 API와 서버 전투 계산을 사용한다.
- 390px에서 두 전투 API에 실패를 주입해 안내가 실제로 보이고 복귀 버튼으로 대기 화면에 돌아가는 것을 확인했다. 오류 안내는 하단 진행 표시와 겹치지 않도록 중앙에 표시한다.
- 새 회귀 검사는 기존 `test:live-connections`를 통해 전체 `release:gate`에 포함된다. 운영 배포는 깨끗한 커밋에서 `npm run deploy:production`으로 진행한다.
