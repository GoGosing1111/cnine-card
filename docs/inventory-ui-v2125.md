# 인벤토리 UI V2125

2026-09-16 사용자 요청: “인벤토리 ui 현재 ui 스타일대로 개편해 한눈에 잘 보이게 개편해봐”.

## 구성

- 운영 로비·용병도감·장비강화의 네이비 패널, 라임 선택 상태, Noto Sans KR와 Barlow Condensed 조합을 적용한다. 실제 공통 상단·사이드·모바일 메뉴를 사용한다.
- 목록은 이미지, 등급, 이름, 용도와 수량으로 압축한다. PC는 옆 상세 패널, 700px 이하 화면은 선택 시 열리는 하단 상세창으로 설명과 사용 버튼을 제공한다.
- 팩·상자, 재료, 입장권, 스킬칩, 재뽑기권, 기타를 구분하고 분류별 종류 수를 표시한다. 이름·설명·코드 검색, 기본순·수량순·등급순·이름순, 보유품 필터와 새 아이템 필터를 조합할 수 있다.
- 기본 화면은 보유 아이템만 보여준다. 필터를 해제하면 API가 반환한 미보유 항목도 확인할 수 있다. 큰 수량은 목록에서 만·억 단위로 줄이고 상세·접근성 이름에는 정확한 수량을 유지한다.
- 재료·스킬칩·전용권은 API의 사용 제한과 사용 위치를 안내한다. 선택만으로 소비하지 않으며, 사용 버튼은 기존 팩·재뽑기·입장 화면으로 연결된다. 개봉 후 분류·검색·정렬과 선택을 유지하고 갱신된 수량을 읽는다.
- 로딩, 검색 결과 없음, 빈 계정, 이미지 실패, API 오류·재시도를 제공한다. 갱신 중에는 이전 보유량으로 새 사용 화면을 열지 않으며, 떠난 화면에 늦은 조회 결과를 쓰지 않는다.

## 파일과 범위

- `js/app.js`: 인벤토리 보기·분류·상세·조회 블록.
- `css/inventory-v2125.css`: 인벤토리 전용 스타일. 공통 본문 여백 조정은 이 보관함이 있는 화면에만 적용한다.
- `index.html`: 신규 CSS와 `inventory=2125` 앱 캐시 키. `service-worker.js`도 갱신해 설치된 클라이언트가 최신 셸을 확인한다.
- 인벤토리 API, 계정 재화, 가격·확률·제작 정책, V3 엔진·무기·리소스는 변경하지 않는다. 기존 사용 확인·개봉 연출과 서버 소비 계약을 재사용한다.

## 검증

2026-09-16 로컬 결과: 인벤토리 단위 검사 8개, 실제 브라우저 검사 80개 통과. 공통 메뉴와 기존 재뽑기 회귀 검사도 통과했다.

- `npm run test:inventory`: 보유/검색/분류/정렬, 이벤트권과 입장권 구분, 제한된 아이템, 정확한 큰 수량, HTML 이스케이프, 코어 5·6 등 실제 자산 경로를 검증한다. 전체 `release:gate`에 포함한다.
- `tests/inventory-ui-v2125.browser.mjs`: 실제 `index.html`과 공통 메뉴로 조회, 검색·새 항목, 빈 결과, 정렬, 선택, 제한 안내, 기존 프라임 확인창, 큐브 10개 개봉·결과·복귀·수량 갱신, API 실패·재시도, 늦은 응답, 이미지 실패, 빈 계정과 모바일 상세창을 검증한다.
- 1440×900, 1024×768, 390×844, 320×740, 1440×560에서 가로 잘림, 공통 메뉴, 수량/이름, 스크롤을 검사한다. 모바일에서 Escape 닫기, 선택 항목으로 포커스 복귀, 기존 개봉창 전환을 검사한다. PC·모바일 캡처는 직접 열어 시각 검수한다.
- 검수 서버는 `JOINT_QA_NATIVE=1 JOINT_QA_INVENTORY_UI=1`로 실행한다. API·보유량은 격리된 로컬 자료이며 운영 계정에 소비 요청을 보내지 않는다. `JOINT_QA_STATIC_ORIGIN=https://cnine-card.pages.dev`를 설정하면 실제 운영 정적 파일로 같은 경로를 재검증할 수 있다.
- 브라우저 결과·캡처·배포 로그는 배포 폴더 밖 `../qa/`에 보존한다. 깨끗한 범위 커밋과 `origin/main` 확인 후 `npm run deploy:production`을 사용하며, 명령 안의 전체 `npm run release:gate`를 통과한 뒤 운영에 반영한다.
