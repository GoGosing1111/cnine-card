# 경찰 조은 처치 후 2차 사격 수정 — 2026-09-23

## 재현과 원인

경찰 조은 V-042 / 현행범 체포 MS-042의 서버 사격은 한 번이었다. 하지만 처치 직후에도 `OFFENDER_MARK` 또는 `BASIC_WEAKENED` 상태 이벤트를 생성했고, 클라이언트가 해당 상태의 `skillPhaseIndex: 0`을 사격으로 다시 재생했다. 사라지는 중인 시체는 `root.visible`이 여전히 참이어서 재생 대상에서도 제외되지 않았다.

수정 전 신규 회귀 테스트의 서버 사망 후 표식, 클라이언트 상태의 사격 재생, HIT + 상태의 두 번 FX 로드, 실제 전투의 HP 0 상태 기록이 실패하는 것을 확인했다.

## 수정 범위

- 서버: 명중 후 `living(target)`인 경우에만 표식/약화를 생성한다. 정상 부활로 살아난 대상은 기존 상태 적용을 유지한다.
- 클라이언트: 해당 스킬의 DEBUFF에서 HP·활성·표시 상태를 검사하고, 이전 저장 기록에 남은 사망 후 상태도 건너뛴다. 텍스처/오디오 대기 후에도 생존을 다시 검사한다.
- 표식은 정보 배너만 재생한다. 살아 있는 대상의 `BASIC_WEAKENED`와 과거 `NEXT_BASIC_WEAKENED`는 phase 1 제압 고리만 재생한다. 실제 HIT는 phase 0 사격을 유지한다.
- 피해·확률·비용·쿨타임·타깃·CMS 배정은 변경하지 않는다. 카드 원화·전투 SD·스킬 아틀라스·사운드도 그대로다.
- 런타임 식별자는 `20260923-police-restraint-v1`, main 앱/전장 로더 캐시는 `policeRestraint=20260923`이다. 공용 원본을 쓰는 9개 V3 소비 번들을 재빌드했다.

## 검증

- `npm run build:v3`: 공용 9개 소비자 재빌드 성공.
- `npm run test:v3-joint`: **184/184 통과**, 신규 경찰 조은 회귀 7개 포함.
- `npm run test:live-connections`: **139/139 통과**, 오래된 런타임 교체, 실제 번들 준비, 취소 및 PVE/PVP 연결 회귀 포함.
- PC 1280×720 실제 main UI: 토벌 첫 진입 → 결과 → 복귀 → 재진입 → 결과 → PVP 매칭 → 결과 → 복귀. 경찰 조은의 기존 투명 SD, 일반 5장 도크, 실제 V3 전장을 확인했다.
- 모바일 390×844 실제 main UI: PVP 매칭 → 승리 결과 → 복귀 → 토벌 시작 → 승리 결과 → 복귀. 전장과 카드 도크·결과 버튼의 표시 및 조작을 확인했고 브라우저 오류 로그는 없었다.
- 별도 격리 서버에서 `JOINT_QA_FAIL_BATTLE=1`로 실제 전장 번들 응답을 503 처리했다. 연결 실패 안내와 토벌 화면 복귀 버튼, 복귀 후 다시 보이는 전투 시작 버튼을 확인했다. 운영 장애를 유발하지 않았다.
- 실제 main UI 검수는 `JOINT_QA_NATIVE=1`, `JOINT_QA_MERCENARY_CODE=V-042`, `JOINT_QA_POLICE_RESTRAINT=1`, `JOINT_QA_CARD_POWER=1000000`으로 재현한다. 경찰 조은의 운영 스냅샷 수치·스킬을 **일회용 로컬 DB에만** 적용한다. 운영 계정의 재화·보상·DB는 변경하지 않는다.

출시 절차는 깨끗한 범위 커밋을 `origin/main`에 반영한 뒤 `npm run deploy:production`의 전체 `release:gate`를 통과하는 방식만 사용한다. 배포 후에는 `JOINT_QA_STATIC_ORIGIN=https://cnine-card.pages.dev`로 운영 정적 파일과 격리 API를 연결해 main 토벌/PVP 경로를 다시 확인한다. 출력 로그·로컬 검수 DB는 배포 디렉터리 밖에 보관한다.
