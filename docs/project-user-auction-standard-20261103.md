## 준비본 동작

기존 누적 입찰 방식을 이어간다. 경매 시작가 이상의 누적 입찰액 중 최고액이 낙찰되고, 동액이면 먼저 해당 금액에 도달한 참가자를 우선한다. 비낙찰자의 입찰금은 전액 반환한다. 본인 경매·예약 중 경매·종료된 경매에는 입찰할 수 없다. 1회 추가 입찰 최대 100조, 정수 처리 범위를 벗어난 누적액은 거절한다.

개최 또는 예약 등록 시 실제 물품과 티켓을 함께 보관한다. 티켓 차감·물품 차감·보관 스냅샷·개최 영수증은 같은 DB 거래다. 오류가 나면 전부 원복한다. 같은 요청 번호의 재시도는 기존 결과를 반환하며 내용 변경 재사용은 거절한다.

낙찰 시 보관된 개체를 낙찰자에게 이전하고 판매자에게 80%를 지급한다. 수수료 계산의 1코인 미만은 버림하며 정수 산술로 처리한다. 유찰이면 물품을 판매자에게 반환하고 이미 사용한 티켓은 반환하지 않는다. 시작 전 예약 취소는 물품과 미사용 개최 티켓을 함께 반환한다. 예약 취소 규칙은 준비본 구현 기본값이며 사용자 별도 확정 문구와 구분한다.

카드는 수량 0행을 남겨 기존 강화·실패 횟수를 유지한다. 용병은 마지막 보유행만 삭제하고 성장·돌파 천장·경험치 이전 이력은 유지한다. 구매자에게 이미 해당 종류의 성장 이력이 있으면 그대로 사용한다. 펫은 영구 보유 수량만 변경하고 잠재력과 기간제 기록은 변경하지 않는다. 기간제 펫, 편성 중인 마지막 카드/용병/펫, 장착 중인 물품은 판매하지 않는다.

장비 준비 어댑터는 강화 상태행·연마 이력이 없는 미장착 기본 인스턴스를 같은 고유 ID로 이전한다. 강화/연마 장비 거래 정책은 이 준비본의 완성 범위가 아니다. 이동수단은 이미 보유한 계정의 입찰을 거절하고, 종료 전에 다른 경로로 취득했으면 다음 유효 입찰자를 판정하며 해당 입찰금은 환불한다.

판매자가 보관 중인 이동수단을 다시 획득하여 유찰·취소 반환이 충돌하면, 원본은 반환 대기 보관함에 남기고 경매 정산·다음 예약은 계속 진행한다. 기존 보유분과 충돌하지 않을 때 원본을 한 번 수령할 수 있다. 삭제 또는 강제 병합으로 해결하지 않는다. `enabled:false`는 신규 개최를 잠그는 준비/종료 모드이며, 이미 진행 중인 경매의 입찰·정산과 기존 예약 처리는 계속한다.

## 운영 연결 전 남은 작업

이 목록은 추가 사용자 승인을 요구하는 절차가 아니라, **준비본을 운영 출시본으로 연결할 때 필요한 구현·검증 범위**다.

1. 운영 카탈로그의 소유권/거래 가능 판정 연결. 귀속·기간제·영수증에 묶인 아이템 제외, 실제 모든 편성/프리셋 확인. 현재 검수 카탈로그는 가상 계정 데이터다.
2. 진무·족로 등 원발행 권한 검사에 완료 경매 소유권 증거 추가. 리미티드의 기존 발행량·serial·최초 획득 영수증을 변경하지 않고 거래 계보 연결. 현재 서비스의 provenance 필드만으로 이 운영 접근권한 문제가 해결된 것은 아니다.
3. 패키지 코인의 예약·환불·판매 정산에서 사용 제한 출처를 보존하는 회계 연결. 현재 신규 `U<경매ID>` 원장 사유는 기존 패키지 회계 파서에 연결하지 않았으므로 **운영 입찰을 활성화할 수 없다**.
4. 기존 공통 사용자 잠금·실제 계정 동기화·장비 수량/랭크 갱신 트리거·기존 경매 종료 확인 연결. 주기 종료 처리의 기존 Worker 호출점 연결. 조회가 없는 동안에도 종료/다음 경매가 진행되는 운영 검증 필요.
5. 새 API 라우터와 로비/경매 진입점·캐시/원스토어 파생본 연결. 현재 운영 경매 코드·입찰 기록·정산을 그대로 보존하고 진행 중 경매가 끝난 뒤 새 예약을 시작하도록 전환 검증.
6. 티켓 `AUCTION_HOST_TICKET / ENTRY_TICKET / SPECIAL` 카탈로그 등록 준비. 인벤토리에서 단독 사용을 막고 “경매장 → 경매 개최 시 자동 사용” 안내. 두 상점 상품 가격은 확정했으나 기존 CMS가 요구하는 구매 한도는 미정이므로 초안은 숨김/OFF. 다른 상품과 상점 전체 판매 설정은 보존.
7. 콘텐츠 보상 지급처·수량·확률은 아직 미정이다. 임의 보상을 추가하지 않는다.

## 검증 범위

SQLite 실제 보유 구조를 본뜬 격리 DB와 PostgreSQL(PGlite)+현재 PostgreSQL 호환 어댑터에서 거래·원복·재시도를 검사했다. 실제 운영 DB/다중 서버 부하/전체 소비 경로 검증이 아니다. Chromium 1440·390·320 및 WebKit390에서 화면·개최·100조 입찰·예약 취소·팝업 중복 차단을 확인했다. 실기기 검수 또는 최종 시각 승인으로 주장하지 않는다.

최종 관련 서버 검사 22개 통과. PostgreSQL은 경매 전역 행을 `FOR UPDATE`로 잠근 뒤 버전을 검증하고 변경 대상 계정의 지갑을 ID 순서대로 잠근다. 자산 보관과 펫 메타에는 대상 행 잠금/CAS를 적용한다. 최초 리뷰에서 찾은 경합 순서 및 이동수단 반환 충돌을 수정했다. 단일 연결 PGlite 결과를 실제 PostgreSQL 다중 세션 경합 검증으로 확대하지 않는다.

검수 실행: `node --test tests/auction-user-20261103.test.mjs tests/auction-user-postgres-20261103.test.mjs`, `node tests/auction-user-20261103.browser.mjs`.

로컬 검토 서버: `node tests/helpers/auction-user-preview-server-20261103.mjs --serve`. 출력된 localhost 주소를 사용한다. 운영 API 호출은 차단되며 서버 종료 시 가상 계정 데이터가 사라진다.
