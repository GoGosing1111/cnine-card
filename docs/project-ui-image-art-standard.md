# 전체 콘텐츠 UI 이미지 제작 기준

2026-10-17 사용자 지시: “분대 박스랑 나머지 박스들도 CSS로하지말고 스킬로 만들어서 넣어놔”, “대충 네모박스하지말라는뜻임 이미지넣어서 해놔라”, “전부 싹 다 몬스터디펜스에 일반 박스 뱃지 넣지말것”, “모든 컨텐츠 및 프로젝트 규정에 적어놔”.

## 적용 범위

프로젝트의 모든 콘텐츠와 하위 프로젝트에 적용한다. 신규 UI와 기존 화면 개편에서 반복 요청 없이 먼저 적용한다. 현재 몬스터 디펜스의 대기·준비·전투·정비·결과 화면은 전체 대상이다.

## 범위 해석 — 2026-10-18 후속

전투 동작·스킬·이펙트 리소스를 요청받았다는 이유만으로 프리뷰 패널·버튼 등 UI 자산을 추가 제작하지 않는다. 사용자가 요청한 실제 UI 신규 제작·개편에만 이 기준을 적용한다. 기존 프리뷰를 유지하면서 연출 명칭·설명만 바꾸는 작업은 별도 UI 생성 대상이 아니다.

## 제작 방식

- 버튼, 패널, 분대 탭, 이름판, 초대 코드판, 난이도/상태 배지, HUD, 보상·강화·선택 카드는 해당 콘텐츠 콘셉트에 맞는 이미지 리소스로 만든다. 단순 색상 사각형·그라디언트 박스·둥근 모서리·CSS 테두리만으로 마감하지 않는다.
- ImageGen 스킬로 독자적인 실루엣·소재·장식이 있는 원본을 생성한다. 원본과 프롬프트, 사용 참조, 해시, 실제 연결 경로를 자산 색인에 보존한다. 투명 cutout은 알파를 유지한다.
- 만든 이미지를 실제 소비 화면에 연결한다. 검수 페이지에만 추가하거나 배경 그림 한 장을 넣고 기존 일반 박스/배지를 남기지 않는다.
- CSS/HTML은 배치, 9-slice, 반응형, 실시간 텍스트·진행률, 선택/호버·초점과 접근성을 담당한다. 글자와 서버 수치를 이미지에 굽지 않는다. 클릭·터치·키보드 조작은 실제 DOM 제어로 유지한다.
- 다른 콘텐츠 리소스를 의미 없이 가져오지 않는다. 해당 콘텐츠 전용으로 제작한 일관된 세트는 여러 상태/크기에 재사용하고 늘릴 때 모서리·장식 비율을 지킨다.

## 완료 조건

PC와 모바일 실제 화면에서 이미지가 로딩되고 장식과 글자가 겹치지 않으며 배지/선택 상태가 구분되는지 직접 확인한다. 작은 화면, 비활성·선택·취소 상태, 필요한 터치/키보드 경로를 검수한다. 이미지를 제작했다는 사실이나 테스트 통과를 사용자 시각 승인으로 간주하지 않는다. 승인된 다른 원화와 실제 확률·비용·서버 조건은 UI 수정으로 변경하지 않는다.
