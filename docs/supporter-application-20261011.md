# 후원 신청 계좌 메시지 · 2026-10-11

- 사용자 요청: 보상 이용 안내 옆 신청하기 → 안내 팝업과 즉시 개인 메시지 발급 → 발급 5분 뒤 해당 메시지 삭제 → 한국시간 하루 3회 제한.
- 최종 후속 지시: CMS ON/OFF 제공, **첫 배포는 OFF**. CMS `후원 관리 → 후원 신청 버튼`에서 설정을 저장한다. 설정 미등록 시 OFF이며 운영에서 ON 전환·실계정 메시지 발송은 하지 않는다.

## 동작

- `server_support_application_config_v1`은 기본 `enabled:false`다. OFF이면 신청 버튼을 숨기고 `server-support/apply`도 차단한다. ON 시 가입 72시간 경과·2차 인증 완료 계정만 발급할 수 있다. 미인증 OWNER 미리보기도 발급은 불가하다.
- CMS 설정은 기존 후원 관리와 동일하게 ID 1 OWNER만 변경한다. 리비전 비교, 요청 영수증, 관리자 변경 기록을 저장한다. 재시도로 설정을 중복 변경하지 않는다.
- 안내 팝업을 먼저 그린 뒤 추가 확인 없이 요청한다. 5분 삭제·하루 3회·운영자 확인 후 혜택 적용을 안내하고 메시지함으로 연결한다. 기존 생성 원화 `sanctum-hero.webp`와 `supporter-crest.webp`를 재사용한다. 팝업에서도 기존 화면 보호를 유지한다.
- 은행·계좌·예금주 본문은 서버에서 생성해 인증된 신청자 개인 `user_messages`에만 저장한다. 공개 화면·신청 응답·발급 횟수 및 영수증에는 계좌 본문을 넣지 않는다. 신청만으로 후원 혜택을 부여하지 않는다.
- 하루 기준은 KST 자정이다. 계정별 발급 횟수, 메시지 생성, 요청 영수증을 같은 원자적 배치로 저장한다. 원본 비교와 요청별 값을 포함한 저장 후 검증으로 경쟁 요청·누락된 메시지 INSERT를 검출한다. 서버와 브라우저 모두 같은 요청 번호를 재사용한다. 삭제·만료·재시도는 횟수를 돌려주지 않는다.

## 5분 만료

- 만료 시각은 읽은 시각이 아닌 발급 시각 + 300초다. 본문 없는 발급 영수증은 중복 방지용으로 남는다. 만료/수동 삭제된 메시지는 같은 요청 재시도로 복구하지 않는다.
- 받은 편지함 조회 및 두 미읽음 집계 경로에서 서버 시계로 만료 메시지를 제외한다. 메시지함 API는 private/no-store이며, 메시지 클라이언트 캐시를 끈다.
- 열린 편지함은 서버 시계와 단조 시계를 사용해 남은 시간을 표시하고 만료 시 본문 DOM을 삭제한다. 탭 복귀 시 즉시 재확인한다. 기존 일반·쿠폰·보상 메시지는 보존한다.
- 기존 Durable Alarm 작업에서 신청 메시지만 물리 DELETE한다. 다음 메시지 만료 시각이 빠르면 그 시각에 알람을 예약하며 기존 클랜 마감 시각을 이동하지 않는다. 클랜 처리 실패와 별개로 삭제 작업을 시도한다. 플랫폼 알람 지연·DB 장애가 생겨도 API 조회와 클라이언트의 5분 만료 판정은 별도로 유지된다.
- DB 스키마, 인증 기반, 공용 트랜잭션 구현, Wrangler 바인딩/마이그레이션 변경은 없다.
