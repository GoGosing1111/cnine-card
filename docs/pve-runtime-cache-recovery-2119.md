# 무한의탑·카우방 전투 엔진 재사용 복구

2026-09-15 사용자가 무한의탑의 `this.battlefieldAsset is not a function` 오류를 재차 제보했고 카우방도 함께 확인하도록 지시했다.

운영 CDN의 V2117 파일은 현재 소스와 일치하지만, 브라우저에 이미 로드된 구버전 엔진은 기존 `ready()` 조건을 충족했다. 서비스 워커도 과거 `?v=` 전투 스크립트를 캐시 우선으로 반환했다. 따라서 소스 수정 및 일부 진입 URL 변경만으로 모든 기존 클라이언트의 구버전 재사용을 막을 수 없었다.

## 수정

- 공용 전장 선택에 `resolveBattlefieldAsset()`을 두어 현재 함수와 구형 문자열 getter를 모두 처리한다. 생성자·페이로드·전장 전환·텍스처 로드가 같은 해석기를 사용한다.
- 번들에 `2119-battlefield-contract` 런타임 버전을 제공하고, 공용 기능 로더가 이 버전을 확인한다.
- 실제 렌더러 생성 직전에도 버전을 확인한다. 오래된 런타임이면 기존 인스턴스를 정리하고 현재 번들을 한 번만 다시 불러온 뒤 동일한 서버 페이로드로 전투 화면을 구성한다. 입장 API를 다시 호출하지 않는다.
- 서비스 워커 활성화 시 앱·전투 엔진의 예전 스크립트 캐시만 비운다. 이 경로들은 과거 버전 쿼리에서도 네트워크 우선으로 받는다. 미디어 및 계정 저장 정보는 유지한다.
- 관련 앱·전투 진입 URL을 V2119로 갱신하고 공용 엔진을 사용하는 모든 기존 번들을 다시 빌드했다.

## 확인

구형 getter 재현, 현재/구형 런타임 교체·동시 요청, 과거 URL의 서비스 워커 캐시 재현 검사를 추가했다. 기존 실제 생성자와 일반 PVE/PVP/레이드/호송/공성 배경 선택 검사도 유지한다.

실제 운영 UI 코드와 독립 로컬 계정 API를 사용해 CUA 브라우저에서 무한의탑 69층의 캐릭터·몬스터·연속 전투, 결과 표시와 다음 층 복귀를 확인했다. 카우방은 같은 페이지에서 이어서 입장해 공용 렌더러의 콘텐츠 전환 및 두 번째 입장의 몬스터와 타격 연출 표시를 확인했다. 운영 계정의 입장권·코인은 검수에 사용하지 않는다.

기존 페이지에서 이미 실행 중인 오래된 JavaScript까지 서버 배포가 교체할 수는 없다. 설치된 서비스 워커는 갱신되며, 배포 후 일반 새로고침 한 번으로 새 앱과 전투 코드가 적용된다. 이후 엔진 버전 검증은 클라이언트가 수행한다.
