# 일반 랭크전 상대 다양성 개선 — 2026-10-13

사용자 요청: 이전 패치부터 반복 상대 원인을 조사한 뒤 제안한 개선안을 적용하고 유저 공지문을 작성한다. 외부 공지 발송은 요청 범위에 포함하지 않는다.

## 조사 근거

- 10월 2일 개편 이후 195,703경기를 읽기 전용으로 확인했다. 직전 10경기 상대와의 재대전 비율은 10/2 이후 55.74%, 10/7 이후 59.78%, 10/11 이후 66.16%, 최근 24시간 70.06%였다. 각 구간에서 계정별 이전 10경기가 있는 대전을 비교했으며 시즌·참여자 차이까지 패치의 인과 효과로 해석하지 않는다.
- 10/7은 후보 부족 완화, 10/11은 발급된 재대전 티켓의 전투 거부 오류를 수정했다. 당시 실제 운영 코드도 최근 4경기와 고정 정렬 1위를 사용했다.
- 2026-10-13 03:46 KST 최신 편성 스냅샷에서 최근 활동 정상 편성 135명 중 113명은 기본 범위 후보가 20명 이상이었다. 일부 계정은 최대 확장 범위에서도 상대가 적어 무조건적인 재대전 차단은 적합하지 않다.

## 반영 정책

- 기존 CMS 기본 범위와 단계별 상한을 유지한다. 현재 250점·대칭 전투력 차 20% → 350점·30% → 500점·40%이며 무제한 매칭을 추가하지 않는다.
- 후보 메타데이터 최대 768명, 편성 96명씩 최대 8묶음을 유지한다. 기본 범위에서 적합한 후보 8명을 확보하면 조회를 끝내고 한 번 추첨한다. 후보가 부족하면 제한 내 검색을 마친 뒤 이용 가능한 후보를 사용한다.
- 최근 공격 경기 20건을 기존 `(attacker_id,id DESC)` 인덱스로 조회한다. 가장 가까운 허용 단계에서 최근 5경기 상대를 우선 제외한다. 후보가 모두 최근 상대라면 최근 2경기 → 직전 1경기 순으로 회피 조건을 완화한다.
- 남은 후보는 점수·전투력 차가 작을수록, 최근 20경기의 대전 횟수가 적을수록 높은 가중치로 추첨한다. 현재 기본 설정에서 가중치는 `exp(-점수차/200 - 전투력차%/20) / (1 + 대전횟수)^2`다. 척도는 CMS 기본 범위에 비례한다.
- 서버 `crypto.getRandomValues`로 추첨하며 계정 ID로 정렬 1위를 고르는 방식을 제거한다. 같은 상대를 두 번 연속 만났으면 기존과 같이 허용된 다른 단계의 대안을 우선하고, 유일한 상대라면 재대전을 허용한다.
- 기존 90초 티켓을 재사용한다. 새로고침으로 재추첨하지 않으며 동시 요청도 하나의 미사용 티켓으로 수렴한다. 티켓 계정·시즌·만료·사용 검증, 현재 편성 재검증, 점수·행동력·보상 거래와 영수증은 유지한다.
- 듀오, CMS 저장값, 전투 계산, 점수·행동력·보상, 클라이언트 UI는 변경하지 않는다. 이미 발급된 티켓은 기존 수명 동안 유지된다.

## 관련 검수와 성능

- 개발 중 매칭 관련 17개 통과: SQLite·PostgreSQL 실제 후보 SQL, 96명 이후 최소 후보 확보, 20건 이력, 가중 선택·대전 빈도·최근 상대 회피, 희소 후보, 단계 상한, 티켓 재사용 및 동시 요청.
- `ranked-matchmaking-20261007.test.mjs` 12개와 `ranked-matchmaking-variety-20261013.test.mjs` 5개다. 같은 실행 코드의 이 검사는 배포 때 반복하지 않는다.
- 배포 단계는 아직 실행하지 않은 `ranked-reform-20261002.test.mjs`, `ranked-fight-performance-20260929.test.mjs`, `ranked-ticket-boundary-20261011.test.mjs`와 `check:worker`로 전투 정산·티켓 경계를 확인한다.
- 실제 이전/새 선택 함수를 사용한 고정 스냅샷 135명 × 60회 비교: 최근 20경기 상대 종류 평균 4.83 → 15.30명, 평균 전투력 차 3.99% → 5.65%, 편성 조회 묶음 평균 1.22 → 1.33(각 최대 7)이었다. 이는 점수·성장·후보 변동을 고정한 모의 결과이며 운영 개선율·HTTP 지연 예측값이 아니다.
- 최근 20건 SQL은 운영 읽기 전용 EXPLAIN ANALYZE 3건 모두 기존 인덱스로 20행만 반환했다. DB 실행 시간 4.868/11.914/4.337ms. 추가 스키마·전 서버 집계·계정별 N+1 조회는 없다. 상세 측정은 같은 이름 `-measurements.json`에 보존한다.
- UI·전투 연출 수정이 없어 별도 PC/모바일 화면 검수를 확대하지 않는다.
