## 동작 계약

### 개방 시간

- KST 날짜별로 3시간짜리 창 두 개를 분 단위로 추첨하고 DB에 한 번 저장한다.
- 두 창은 서로 겹치지 않고 당일 24:00을 넘지 않는다. 연속한 두 회차는 가능하다.
- 가능한 모든 비중첩 시간 쌍 중 무작위로 선택한다. 재조회·재접속·동시 요청이 일정을 재추첨하지 않는다.
- 당일 두 시간과 진행/예정/정산/미진행 상태를 기존 세력전 화면에 표시한다. 자정 종료는 `24:00`으로 표시한다.
- 정규 클랜 시즌이 ACTIVE일 때만 진행한다. 세력전 대기 시간에도 부대 편성은 가능하다.
- 적용 시각 이전에 시작한 창, 시즌 종료를 넘어가는 창, 장애로 완전히 지나간 **순연과 무관한** 미개방 창은 소급 개최·소급 보상하지 않는다.
- 진행 중인 회차가 없는 상태에서 영토전과 겹치는 신규 개방은 미진행 처리한다. 이미 진행 중인 회차의 중단/재개로 밀린 후속 회차는 아래 순연 정책으로 보존한다.
- 일반 서버 지연 자체로 마감을 늘리지 않는다. 영토전 중단 시간만 실제 진행 시간에서 제외한다.
- 중단 중에는 승패·점령을 임의 확정하거나 메시지 보상을 보내지 않는다. 종료된 영토전 기록을 읽어 멈췄던 만큼 제한 시각을 연장하며 반복 조회해도 한 번만 연장한다.
- 순연 회차는 대기열에서 순서대로 진행하며, 시작될 때 참여 명단을 새로 만든다. 앞 회차 종료와 다음 회차 개방은 같은 상태 저장 트랜잭션이다.
- 자정을 넘어도 원래 날짜·회차 키를 유지한다. 하루 두 개라는 것은 **해당 KST 날짜의 신규 추첨 수**이며, 이월된 기존 회차를 새 회차로 재추첨하지 않는다. 순연 때문에 실제 진행이 다음 날짜로 이어질 수 있다.
- 같은 시각 두 회차를 열지 않는다. 남은 시즌 길이가 3시간 미만이면 새 순연 회차를 부분 개방하지 않는다.

### 전투와 영토전 배제

- 기존 서울 25개 영토 지도, 공격대/방어대, 행동대장, 공용 V3 전투 계산·연출을 유지한다.
- 출정·입장·교전 API가 회차 개방 여부를 확인한다. 닫힌 회차에서는 직접 API를 호출해도 진행되지 않는다.
- 전투 계산 후 상태를 다시 읽으며 마감 이후 결과를 뒤늦게 반영하지 않는다.
- ACTIVE 영토전과, 시작 시각이 도래한 PREPARING 영토전을 차단한다. 미래 PREPARING은 실제 시작 전까지 현재 세력전을 막지 않는다.
- 전투 저장 직전 SQL 조건에도 영토전 차단을 넣어 조회와 쓰기 사이에 영토전이 시작되는 경합을 방어한다.
- 장애 중 영토전이 시작되고 끝난 경우에도 FINISHED 기록과 실제 `settled_at`을 조회하여 겹침을 판정한다.
- 정상 회차 종료 또는 시즌 종료 때 남은 교전은 방어 유지로 종료한다. **영토전 일시중단 때는 교전 상태·HP를 보존**하고 재개한다.

### 보상과 원자성

- 마지막 확정 점령 상태에서 4개 이상을 세며, 8개를 점령했다고 보상을 두 배로 지급하지 않는다.
- 금액은 **30,000,000,000 일반 코인**이다. 기존 징수코인 전용 지갑으로 지급하지 않는다.
- 종료 집계 시 실제 명단과 회차 출정/입장 기록을 대조해 스냅샷으로 저장한다. 명단이 동시 변경되면 전체를 다시 읽어 집계한다. 다른 클랜에서의 참여만 가지고 새 소속 클랜의 보상을 받지 못한다.
- 회차 종료 상태, 대상자 스냅샷, 메시지, 보상 행을 동일 DB 트랜잭션으로 저장한다.
- 전역 회차 키와 시즌별 상태 revision으로 중복 종료·동시 요청을 막는다.
- 일부 INSERT가 예외 없이 0행 처리되는 경우에도 지급 수 CHECK 제약으로 전체를 되돌린다.
- 메시지의 `campaign_key`는 `faction-session:YYYY-MM-DD:1` 또는 `:2`다.
- 지급 시점에는 지갑을 직접 올리지 않는다. 기존 메시지 수령 경로에서 1회만 수령한다.
- PostgreSQL 금액 열이 BIGINT인지 미리 검사하며, 스키마가 맞지 않으면 지급을 거부한다. 자동 대규모 ALTER는 없다.
- API가 다른 유저의 보상 대상자 명단을 내보내지 않으며 개인 화면에는 본인의 지급 금액만 보여 준다.

### 징수세 전환

- 적용 시각 이후 시간당 징수세 적립과 새 수동 분배 요청을 중단한다.
- 기존 징수코인 잔액·누적액·미분배 세금 풀은 삭제하지 않는다. 일반 코인으로 자동 환전하거나 임의로 지급하지 않는다.
- 과거에 성공한 요청 키를 재전송하면 보존된 영수증만 반환하며 새 재화가 생기지 않는다.
- 세력전 화면의 기존 징수세 탭은 회차 종료 보상 안내와 최근 결과로 바뀐다.

### 예약 작업과 성능

- 기존 `workers/clan-draft` 알람 안에서 정산을 **await**한다. 신규 공개 cron API나 별도 바인딩은 만들지 않았다.
- 무접속 상태에서도 다음 알람(기존 60초 간격)이 종료를 집계한다. DB 장애 동안에는 지급이 지연될 수 있으며 다음 실행이 같은 회차를 재시도한다.
- 새 시즌이 만들어져도 이전 시즌의 미정산 회차를 먼저 확인한다.
- 연결은 성공·실패 모두 기존 finally에서 닫힌다.
- 개편 OFF는 추가 세력전 스키마/일정/보상 조회를 수행하지 않는다.
- ON 상태의 변동 없는 동기화는 warm 기준 SELECT 6개이며 쓰기·스키마 검색·일정 재추첨이 없다. 캐시하는 것은 불변 일일 일정뿐이며 점령/지갑/전투 상태는 캐시하지 않는다.
- 세력전이 화면에 열린 동안에는 overview에 포함된 알림을 재사용하여 alerts API의 중복 회차 집계를 생략한다.
- Cloudflare/Workers 스킬의 요청 수명·비동기 작업·연결 정리 기준으로 검토했다. [Workers 운영 모범 사례](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/)와 [Scheduled Handler 문서](https://developers.cloudflare.com/workers/runtime-apis/handlers/scheduled/)를 참고했으며 외부 계정이나 Hyperdrive 설정은 변경하지 않았다.

## 다음 대화/운영 반영 담당자 절차

1. 다른 대화의 변경을 보존한 통합 후보에서 위 브랜치의 준비 커밋을 cherry-pick한다. Downloads dirty 디렉터리를 그대로 운영 배포하지 않는다.
2. 이 문서의 최종 승인 정책 네 가지와 실제 적용 지시를 확인한다. 정책을 RESET/CANCEL/전체 클랜원 지급 등으로 되돌리지 않는다.
3. 운영 DB에 읽기 전용으로 아래 열의 BIGINT 여부를 확인한다. 누락/다른 형식이면 활성화를 멈추고 별도 마이그레이션 계획을 검토한다.
   - `users.coin`
   - `user_message_rewards.reward_amount`
   - `user_message_reward_claim_receipts_v1222.reward_amount`, `balance_before`, `balance_after`
   - `coin_logs.change_amount`, `balance_after`
   - 기존 `user_messages`의 `campaign_key`와 `(user_id,campaign_key)` 유일 인덱스 및 보상 테이블의 기존 생성 상태도 확인한다.
4. `FACTION_SESSION_RELEASE`의 네 가지 승인 정책은 유지하고 `effectiveAt`, `enabled`만 실제 적용 지시에 맞춰 확정한다. 적용일은 임의로 추정하지 않는다. 온전한 첫날 2회 추첨을 원하면 KST 자정부터 적용하는 것이 가장 명확하다.
5. 현재 활성 세력전·영토전·시즌 종료 시각, 사용자 공지 시각을 확인한다. Pages와 예약 Worker가 모두 반영될 시간을 확보한다.
6. 적용 후 UI 버전을 한 번 더 갱신한다. 준비본 토큰은 `20260922-sessions-prep`이며 연결 파일은 `index.html`, `js/clan-v1.js`, `js/app.js`, `preview/clan-faction-v1/preview.mjs`다. 새 일정 UI 모듈은 service-worker의 network-first 목록에도 추가되어 있다.
7. 관련 검증 후 범위 커밋을 만들고 승인된 통합 후보를 origin/main에 반영한다. 깨끗한 후보에서 **`npm run release:gate` 통과 후 `npm run deploy:production`만 사용**한다. 이 명령이 Pages와 clan-draft Worker를 함께 배포한다. assets-only 경로 및 직접 Wrangler 배포를 사용하지 않는다.
8. 배포 후 실제 페이지/API를 읽기 전용으로 확인하고, 당일 일정 2개, 지도 보존, 영토전 차단, 다음 알람 기록을 확인한다. 실제 운영 코인을 테스트 목적으로 임의 지급하지 않는다.
9. 첫 실제 종료 때 `clan_faction_sessions_v1`의 `recipient_count=reward_count`, 해당 campaign 메시지 수, 반복 조회 후 개수 불변을 확인한다.

### 롤백 주의

- 초기 준비본의 OFF는 기존 운영을 유지하기 위한 값이다. 이미 개편을 켠 뒤 OFF만 바꾸면 이전 24시간 전투 경로로 돌아갈 수 있으므로 이를 긴급 정지 스위치처럼 사용하지 않는다.
- 활성화 후 문제가 발생하면 먼저 승인된 점검/콘텐츠 차단 절차로 신규 전투를 멈추고 미정산 회차·원장 상태를 확인한다. 해결 후 같은 키로 재처리한다.
- `taxDisabledAt`, 일정, 전역 회차 키, 종료 원장, 메시지·수령 영수증을 삭제하거나 초기화하지 않는다. 구버전 코드로 단순 회귀하면 중단 기간 세금이 잘못 적립될 수 있다.
- 이미 수령한 보상을 자동 회수하거나 유저 잔액을 되돌리지 않는다. 필요한 경우 별도 승인된 복구 계획으로 처리한다.
