# V3 용병 공격 누락 수정 · 2026-09-13

사용자 지시: “용병 왜 공격모션 없냐?”, “왜 v3에서 공격안함?” 실제 전투에서 공격 턴이 생성되지 않는 문제를 수정한다.

## 원인과 재현

서버의 속도 게이지는 전투력에 비례하지만, 용병은 승인된 등급별 고정 전투력을 쓴다. 일반 카드 전투력이 커지면 용병이 자신의 첫 행동 게이지를 채우기 전에 전투가 끝났다. 여기에 최소 시계 진행량 0.001이 고속 카드의 게이지를 매번 상한 130까지 채워, 가장 빠른 카드가 계속 같은 동률 비교에서 이기는 문제가 겹쳤다.

카드당 전투력 2천만, ATTACK·DEFENSE·SPEED·HP·ATTACK 5장, SS 베스페라, seed 12로 재현했다. 수정 전에는 PVE와 PVP 모두 아군 용병 공격 이벤트가 0개였다. 기존 용병 연결 검사는 일반 카드 전투력 1천~1만을 사용해 이 차이를 잡지 못했다.

## 서버 처리

- `functions/_battle_v2_preview.js`: 한 번의 기존 최소 시간 간격으로 게이지 100 전체를 다시 채울 만큼 빠른 전투에서는 정확한 게이지 도달 시각을 사용한다. 이미 준비된 배우를 처리하기 전 시간을 추가로 진행해 게이지를 포화시키지 않는다. 그 속도 미만에서는 기존 계산과 전투 결과를 보존한다.
- `functions/_mercenary_combat.js`: 살아 있는 용병은 아군 일반 카드 5행동 뒤 다음 아군 행동 기회를 받는다. 자연적으로 용병 차례가 먼저 오면 이 대기 횟수를 초기화한다. 일반 행동 한도를 소비하며 준비·발동·재사용·기절·침묵·사망 처리를 그대로 거친다.
- 상대 행동, 배틀슈트 사격, 몬스터 연속 공격과 추가 피해는 용병 대기 횟수에 포함하지 않는다. 죽은 용병을 행동시키거나 사망한 스킬 대상을 다른 몬스터로 바꾸지 않는다.
- C·B·A·S·SS·SSS의 고정 전투력과 HP·공격력·방어력·속도 값, CMS 스킬 수치, 일반 카드 5장과 별도 용병 1장 계약은 유지한다. CMS·지갑·개봉 설정을 수정하는 운영 데이터 작업은 없다.

## 검증과 재생 기준

`tests/mercenary-turn-cadence-v2099.test.mjs`를 공동 출시 검사에 추가했다. 카드당 전투력 100만·2천만·1억의 PVE/PVP 양쪽, 스킬 없는 6등급 기본 공격, 사망 배제, 아포칼립스 배틀슈트 공통 시계, 연속 몬스터 교체를 검사한다. 기존 배틀슈트 피해 검사에서는 저속 구간의 과거 운영 전투 결과 전체와 동일함을 대조한다.

브라우저는 운영과 같은 V3 번들에서 PVE(1440px), 양쪽 용병 PVP(390px), 배틀슈트 스킬 동시 재생, 폐차장 연속 몬스터 전투를 완료했다. 서버가 생성한 실제 공격·스킬 이벤트를 재생해 IDLE→MOVE→ATTACK, 준비·충돌 프레임과 완료 후 효과 정리를 확인했다. 별도 전투 UI나 가짜 공격 이벤트를 배포하지 않는다. 기존 PixiJS 8.20.0·GSAP 3.13.0 렌더러와 승인된 16프레임 스킬 자산을 재사용한다. 이번 수정은 새로운 캐릭터 공격 원화를 제작한 작업이 아니다.

재현 자료와 화면 캡처는 배포 디렉터리 밖 `../qa/mercenary-attacks-2099/`에 보존한다. 운영 반영은 범위 커밋과 전체 `npm run release:gate` 통과 후 `npm run deploy:production`으로 진행한다.
