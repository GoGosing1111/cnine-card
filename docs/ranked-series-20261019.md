# 랭크전 용병 삼연전 · 2026-10-19

사용자 확정: 기존 일반 랭크전을 삼연전으로 교체하고 이름은 `랭크전`으로 유지한다. 화면 변경은 매칭·출전 순서에 집중한다. 서로 다른 용병 3종을 보유해야 참가하며 같은 용병의 여러 장은 1종이다.

## 규칙과 저장

- 카드 5장·마법·펫·장비는 매 차전 동일하고, 저장한 용병은 1→2→3차전에 한 번씩 출전한다. 매 차전 독립된 V3 전투를 생성해 체력·보호막·기력·재사용 상태를 초기화한다. 먼저 2승하면 종료한다.
- 랭크전 전용 편성은 직접 저장해야 한다. 기존 PVE/PVP 공용 단일 용병 슬롯이나 보유 카드를 자동 변경하지 않는다. 저장을 마친 상대만 매칭한다.
- `app_meta`의 `ranked_series_roster_v1:<userId>`에 코드 3개와 revision을 저장한다. UI는 보유·출전 가능한 용병만 선택하게 하고 서버는 실제 보유권·전용 계정 제한·배정된 등급을 다시 확인한다. 획득 경로가 잠긴 용병도 실제 지급받은 보유분은 기존 배치 정책을 따른다.
- 90초 매칭권과 `ranked_series_ticket_v1:<attackerId>`를 한 거래로 저장한다. 계정별 마지막 매칭 정보 1개만 유지한다. 양측 순서는 매칭 시 고정한다. 상대 목록은 코드순으로 공개하고 상대 순서는 공개하지 않는다. 매칭 중 자신의 순서 저장은 거부한다.
- 이전 단판의 미사용 매칭권은 새로 발급한다. 이미 처리한 경기의 영수증은 보존한다.
- 새 테이블·마이그레이션·시즌 초기화는 없다. 기존 점수, 행동력 잔액, 충전 주기, 코인 금액과 획득 정책을 보존한다.

## 정산과 동시성

세트당 행동력 1회 비용, 점수 승/패 1회, 코인·확률 드롭 1회를 처리한다. 기존 `commitRankedFight`의 시즌/점수/행동력/매칭권 CAS와 영수증 거래를 사용한다. 양측 용병 3종의 실제 보유권도 커밋 직전 같은 거래에서 다시 확인하고 PostgreSQL 공유 락으로 회수와 경합을 보호한다. 첫 편성 저장은 단순 INSERT로 경쟁 요청이 덮어쓰지 못하게 하고, 기존 편성은 revision 원문 비교와 행 락을 사용한다.

일치하지 않는 매칭권, 보유권 회수, 불완전한 카드 덱, 점수/카드 전력 변경은 차감 전에 중단한다. 동일 요청 재시도는 세트 점수와 각 차전 결과를 포함한 기존 영수증을 반환한다. 방어자의 점수와 승패 집계, 보상은 종전대로 변경하지 않는다. 후보 검색의 점수·카드/장비 전력 범위와 최근 상대 분산은 유지하며 용병 전력으로 불리한 추가 매칭 조건을 만들지 않는다.

## 화면과 리소스

`js/ranked-series-ui-v1.js`와 `css/ranked-series-v1.css`가 매칭 화면만 구성한다. 세 용병의 원화, 차전별 선택, 앞/뒤 순서 변경, 명시적 저장, 카드 덱 요약, 행동력과 세트 규칙을 표시한다. 매칭 후 상대 용병 3종을 공개하고 시작 버튼 또는 4초 후 전투로 연결한다. V3 차전 전환마다 이전 렌더러를 정리하고 최종 결과에 세트 점수와 승패 내역을 표시한다.

전용 ImageGen 배경·프레임·버튼 재질의 원본, 프롬프트, 파생 파일과 해시는 `assets/ui/ranked/series-20261019/manifest.json`에 보존한다. 기존 캐릭터 원화는 재생성하지 않는다. 기술 검수 결과는 사용자 시각 승인으로 기록하지 않는다.
