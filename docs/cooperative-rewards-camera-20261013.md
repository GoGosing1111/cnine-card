# 격전지 일일 보상 · CMS · 고정 카메라 — 2026-10-13

사용자 요청: 격전지 보상을 하루 3회로 제한하고 다양한 보상을 CMS에서 설정하며, 격전지 궁극기 줌아웃을 제거한다.

## 운영 정책

- 계정별 **전체 난이도 통합 하루 3회**, KST 자정 초기화. 종료 시각의 날짜에 실제 지급 성공한 클리어만 집계한다. 실패·이탈·TEST·보상 OFF·빈 보상은 횟수를 소모하지 않는다. 한도 이후 전투는 계속 가능하다.
- OWNER CMS → 격전지(협동) → **클리어 보상**. 지급 ON/OFF, 일반/격전/극한별 코인·마스터의 별·인벤토리 아이템 최대 20종과 수량을 설정한다. 코드 임의 입력 대신 활성 지급 카탈로그에서 선택하며, 강화 보호권 등 기존 지급 제한을 유지한다.
- 신규 기본값은 OFF·코인/마별 0·아이템 없음. 2026-10-13 읽기 전용 확인에서 운영 설정은 r6 / ON / encounterVersion 3 / rewardLocked true, 이전 경제 초안도 전부 0이었다. 이전 초안을 자동 활성화하거나 실제 계정에 검수 보상을 주지 않는다.
- 보상 수량은 새 방 생성 시 고정한다. 기존 방·기존 TEST 방에 소급하지 않는다. 운영 OFF 또는 보상 OFF는 미정산 방에도 적용한다. 입장 차감은 이전대로 잠금이며 무료 입장을 유지한다.

## 지급과 재시도

전투 결과는 서버 Durable Object가 확정한다. 별도 클라이언트 승리 신고나 임의 보상 요청 API는 없다. 승리 종료 시 서버가 자동으로 지급하고 결과창에 실제 영수증을 표시한다.

기존 app_meta에 `coop_reward_receipt_v1:<roomId>` 영수증과 `coop_reward_day_v1:<KST 날짜>:<userId>` 횟수를 저장한다. 영수증, 3명 각각의 횟수 CAS, 코인/아이템 잔액, 경제 로그는 기존 PostgreSQL/D1 batch와 joint atomic guard를 이용해 한 거래로 처리한다. 타 참여자 지급 실패 시 앞 참여자 지급까지 모두 취소한다. 수량 정수·활성 아이템·잔액 상한·중복 영수증을 검증한다.

DO가 DB 커밋 응답을 받지 못해도 영수증을 다시 읽어 중복 지급을 막는다. 실패한 정산은 방을 삭제하지 않고 15초부터 최대 5분 간격으로 재시도한다. 클라이언트가 나가도 서버 처리는 유지한다. 정산 완료 방은 기존 한 시간 정리 정책을 따른다. 공통 DB/인증/배포 기반이나 마이그레이션은 변경하지 않았다.

## 격전지 화면

진무 대사가 줄바꿈될 때 ResizeObserver가 캔버스 높이를 바꾸고 전장 전체를 다시 축소할 수 있었다. 격전지 대사창에서 다섯 문장의 최대 높이를 처음부터 확보해 문장 교체가 전장 크기에 영향을 주지 않게 했다. 얼굴 초상·SSS 테두리·대사는 유지한다.

COOP_THREE_SQUADS에만 카메라 focus/zoom을 비활성화하고 전용 궁극기 프레이밍도 차단한다. 다른 PVE/PVP로 재사용 시 기본 카메라 정책을 복구한다. 피해량, 스킬 시간, 공격 연출, 난이도와 보상 확률을 변경하지 않는다.
