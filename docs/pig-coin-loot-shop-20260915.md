# 피그 코인 · 고급 전리품 상점

## 사용자 지시와 출시 상태

- 영토전·클랜전·신규 레이드에서 별도 피그 코인을 얻고 고급 전리품으로 확정 교환한다. 상품별 계정당 누적 구매 한도는 1~3회다.
- 품목: 슈퍼스타 선택팩, FUR 선택팩, F바디, 미스틱 장비, A~S등급 용병 카드팩.
- 최초 경제 정책 질문의 답변은 **“미정 — CMS 설정 후 활성화”**였다. 아래 후속 확정 지급량을 적용하며, 가격·구매 한도·카드 목록·장비·A/S 가중치는 계속 미정이다. 상품 판매는 OFF를 유지한다.
- 후속 “영토전,클랜전,신규레이드 CMS에 피그코인 지급 기능도 추가해놓을것”을 반영하여 각 기존 CMS 보상 영역에도 같은 정책의 지급 설정을 추가했다.
- UI 고정 기준은 현재 로비·용병도감·장비강화다. `docs/ui-fixed-reference-20260915.md`를 따른다.

## 후속 확정 지급 기준 · 2026-09-15

사용자가 **“합산 지급 (영토전 150·클랜전 60)”**을 확정했다. 승리 조건과 참여 조건은 독립이며 둘 다 충족하면 합산한다.

| 콘텐츠 | 승리 / 격파 | 참여 조건 | 참여 보상 | 한도 |
| --- | --- | --- | --- | --- |
| 영토전 | 승리 진영 100개 | 해당 회차 정산에 저장된 CMS 최소 공격 횟수 이상 | 승패·무승부 관계없이 50개 | 회차당 최대 150개 |
| 클랜전 | 기존 시즌 정산 WINNER 클랜 30개 | 시즌 완료 공격 30회 이상 | 승패 관계없이 30개 | 시즌당 최대 60개 |
| 붕괴 코어 | 최종 보스 격파 후 클리어 보상 수령 30개 | 기존 클리어 보상 자격 | 별도 없음 | 계정당 주간 90개 |

- 운영 CMS 조회 시 영토전 최소 공격 횟수는 **50회**였다. 이 값을 별도 피그 코인 설정으로 복제하지 않고 기존 `settlementMinAttacks`와 정산 시 저장한 `required_attacks`를 따른다. 상점에는 현재 CMS 횟수를 표시한다.
- 승리 보상에는 참여 보상의 최소 공격 횟수를 다시 요구하지 않는다. 영토전 기본 보상이 `INELIGIBLE`이어도 승리 진영의 피그 코인 100개는 수령할 수 있으며 버튼·수령 안내에 반영한다.
- 클랜전은 기존 시즌 종료 보상과 함께 지급한다. 매 개인 전투·정규전 대진마다 30개를 지급하지 않는다. 완료 공격 진행 기록과 구형 완료 공격 영수증 중 큰 값을 대진별로 합산한다. 방어, PENDING/FAILED 공격, 포스트시즌은 제외한다.
- 붕괴 코어 주간은 **한국 시간 월요일 00:00**부터 다음 월요일 직전까지다. 지급 원장 합계로 90개를 별도로 제한하고, 기존 주간 3회 수령·보상 잠금도 유지한다. 지난주에 받은 같은 공대의 보상을 다시 지급하지 않는다.
- 구형 단일 지급량 정책은 승리·참여·한도가 없으므로 새 필드로 명시적으로 저장하기 전 지급 OFF로 읽는다. 기존 상품과 구매 이력은 보존한다.

## UI와 CMS

- `/loot-shop/`: 공통 왼쪽/모바일 메뉴, 상품 선택 목록, 강화소 원본 무대, 교환 상세, 보관 팩, 콘텐츠별 지급 상태.
- 실제 `soop-adventure-lobby` 상단 재화 UI에 돼지 문양 코인을 표시한다. 계정 API에서 잔액을 읽고 상점으로 연결한다. 구형 셸도 같은 잔액을 사용한다.
- 선택팩 후보, 용병 후보·등급 확률을 결제 전에 확인할 수 있다. 개봉 시 선택 카드 또는 용병 카드 1장을 지급한다.
- OWNER 상점 CMS: 가격, 한도, 지급 장비, 직접 선택한 카드/용병 후보, A/S 가중치, 개별 판매·전체 판매, 콘텐츠 지급량·스위치.
- 영토전 회차 정산 보상 영역, 클랜전 시즌 보상 영역, 신규 레이드 붕괴 코어 설정 하단: 전체·콘텐츠별 지급 스위치, 승리/참여 지급량, 클랜 최소 공격 횟수 또는 코어 주간 한도, 별도 저장 버튼을 제공한다. 상점 CMS에서도 동일 필드를 편집한다.
- 세 콘텐츠 CMS와 상점 CMS는 `app_meta.loot_shop_policy_v1` 한 건을 공유한다. 수정 버전을 검사하여 다른 창의 변경을 덮어쓰지 않는다. 콘텐츠 저장은 다른 콘텐츠와 모든 상품을 보존한다.
- 신규 카드·장비·용병은 자동으로 상품 풀에 들어가지 않는다. 기존 상품 ID·종류를 삭제/변경하지 않고 판매 중지로 관리하므로 이름 변경·재개가 누적 한도를 초기화하지 않는다.

## 지급 및 거래 계약

| 콘텐츠 | 실제 지급 시점 | 중복 방지 기준 |
| --- | --- | --- |
| 영토전 | 승리 진영 및 최소 공격 조건을 각각 판정한 V3 회차 보상 수령 | 사용자 + 버전/회차 |
| 클랜전 | 시즌 종료 기존 보상 정산 | 사용자 + 시즌 |
| 신규 레이드 | 붕괴 코어 클리어 보상 수령, 기존 보상 잠금·주간 조건 충족 | 사용자 + 공대 |

보상은 기존 정산 거래 안에서 원장과 잔액을 함께 변경한다. 이미 수령한 보상에는 소급하지 않는다. 콘텐츠 자체 공개·보상 잠금·공동 출시 정책을 피그 코인 스위치가 우회하지 않는다.

PostgreSQL에서는 지갑 행을 잠근 뒤 보상 자격과 주간 합계를 SQL로 판정한다. 수령 완료 표시까지 같은 거래에서 반영한다. 동시 공대 수령, 지급 실패, 네트워크 응답 유실과 재시도는 중복 지급 또는 주간 한도 초과를 만들지 않는다. 신규 기준 이전 LEGACY 영토전에는 소급 적용하지 않는다.

구매는 공통 계정 변경 잠금·PostgreSQL 계정 행 잠금·CHECK 가드를 사용한다. 잔액 차감, 계정 구매 횟수, 지급, 원장, 완료 영수증을 하나의 원자적 거래로 처리한다. 장애 후 같은 requestId로 재시도하며 용병 추첨 결과는 준비 영수증에 고정된다. 한정 카드의 마지막 수량도 잠금과 발급 수량 가드로 보호한다.

선택팩·용병 팩 소유권은 `loot_shop_packs_v1`에 보관하며 상점의 **내 보관 팩**에서 개봉한다. F바디·미스틱 장비는 `user_equipment_instances`로 직접 지급한다. 선택 카드와 용병 지급은 기존 카드/용병 소유권 테이블을 사용한다.

## 저장소 준비 및 OFF 배포

처음 정책이 없는 상태의 조회는 0코인·OFF·미설정 상품을 반환하며 신규 테이블을 생성하지 않는다. OWNER가 CMS 저장을 명시적으로 실행할 때 신규 지갑·원장·구매 이력·팩 테이블을 준비한 뒤 정책을 저장한다. 준비 실패 시 정책은 게시되지 않는다. 별도 기존 데이터 이전이나 운영 계정 코인 지급은 필요하지 않다.

신규 테이블: `pig_coin_wallets_v1`, `pig_coin_ledger_v1`, `loot_shop_purchases_v1`, `loot_shop_packs_v1`. 기존 공통 `joint_operations_v1`과 감사 로그를 사용한다.

확정 지급량 운영 반영은 `scripts/ops/pig-coin-rewards-20260915.mjs`의 일회성 작업으로 수행한다. 배포 후 조회한 기존 정책 해시를 검사하고, 세 콘텐츠 지급을 ON으로 저장하며 상품 설정을 보존한다. 감사 로그와 `ops_pig_coin_rewards_20260915_v2` 완료 기록을 같은 거래에 남긴다. dry-run은 롤백하며 재시도는 이후 CMS 수정값을 초기화하지 않는다. 이 스크립트는 런타임 자동 마이그레이션에서 호출하지 않는다.

## 검증

- `npm run test:loot-shop`: SQLite·실제 PostgreSQL 호환 계층(PGlite) 35개 검사. 기존 24개 거래·CMS 검증에 승패·횟수 경계, 합산, 방어 제외, 주간 경계·90개 상한, 재시도·롤백, 일회성 정책 게시 검증을 추가했다.
- `tests/core-raid-weekly-return-v2112.test.mjs`: 실제 클리어 수령 API에 피그 코인을 ON으로 설정해 30개 지급·실패 복구·90개 제한을 SQLite와 PostgreSQL 양쪽에서 확인한다.
- 브라우저: 1440·1100·980·800·600·390·360·320px에서 상점 가로 넘침 없음. 상품 선택, 결제 전 후보, 실제 로컬 거래·선택 개봉·용병 개봉, 실패 후 새로고침 복구, 공통 메뉴, 실제 로비 컴포넌트 지갑 링크를 확인했다.
- 기존 세 CMS 스크립트를 로드한 검수 화면에서 각 패널 저장·동기화·모바일 배치·OWNER 제한을 확인했다. 모든 검수 수치(500 코인, 가격 25, 지급량 11/12/13 등)는 격리된 로컬 DB에만 사용했다.
- 후속 검수는 확정된 100/50, 30/30/30회, 30/90 설정으로 실행했다. 320~1440px 상점 획득 조건, 중앙 CMS와 세 콘텐츠 CMS, 피그 코인만 남은 영토전 수령 버튼·완료 안내를 확인했다. 보상 버튼의 기존 닫힘 태그 누락도 수정해 아래 모집 화면이 버튼 안으로 들어가지 않게 했다.
- 전체 출시 게이트와 운영 배포는 `npm run release:gate`, `npm run deploy:production`만 사용한다. 운영 활성화와 검수 DB의 ON 시나리오는 별개다.

## 자산

`assets/items/pig-coin-v1.png`는 사용자 요청에 따라 생성한 돼지 문양 금화 원본이다. 상점 무대와 팩·F바디는 기존 게임 리소스를 사용한다. 미스틱 장비 미설정 시 공용 보급 상자를 품목 안내용으로 표시하고 안내 문구를 붙인다. 용병 팩 외형 역시 공용 이미지임을 표시한다. 용병 원화·앵커·배틀슈트 원본은 수정하지 않았다.
