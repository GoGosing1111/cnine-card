# SSS 재뽑기권 · 재계약 연출 · 독립 CMS — 2026-10-14

사용자 확정: **보유 SSS 1장과 아이템 1개를 소모해 다른 일반 SSS로 교체**한다. 전용 아이템 원화와 연출을 만들고 확률은 별도 OWNER CMS에서 관리한다.

## 이용과 운영

- 아이템 `MERCENARY_SSS_REROLL_TICKET` / SSS 재뽑기권. 인벤토리 사용 및 용병도감의 SSS 재뽑기에서 `/mercenary-codex/sss-reroll/`로 이동한다.
- 입력은 보유한 일반 SSS 1장이다. 동일 용병과 모든 리미티드를 결과에서 제외하고 일반 SSS 1장을 지급한다. 이미 보유한 다른 용병이면 보유·중복 수량에 합산한다.
- 마지막 1장도 소모할 수 있지만 PVE 또는 PVP에 편성된 마지막 1장은 해제 후 사용한다. 중복이 남으면 기존 편성을 유지한다. 성장 기록은 기존 용병에 남으며 새 용병으로 이전하지 않는다.
- **OWNER CMS → SSS 재뽑기 관리** (`/admin/sss-reroll.html`). 운영 ON/OFF·용병별 기준 확률·운영 메모·투입 용병별 실제 확률을 제공한다. 하이퍼팩·미라클 큐브 설정을 변경하지 않는다. 공통 획득 OFF는 계속 적용한다.
- 최초 **OFF, 확률 미입력, 지급 0**. 0%·미입력은 추첨 제외다. ON 저장은 기준 확률 합계 100%, 현재 획득 가능한 서로 다른 일반 SSS 최소 2종이 필요하다. 임의 확률·상점·드롭·일괄 지급은 넣지 않았다.
- 1억 정수 단위로 소수점 6자리 %를 정확히 저장한다. 입력 용병 확률을 제거한 후 남은 가중치로 추첨한다. 예: 20/30/50%에서 첫 용병 투입 시 37.5/62.5%. 고객·CMS 모두 같은 모델로 표시한다.

## 리소스와 연출

- 새 원화: 투명 흑요석·금장·청록 수정 재뽑기권, 별빛 계약실. built-in image_gen으로 만들었다. 원본과 256/768px 투명 WebP, 배경 WebP, 해시는 `preview/sss-reroll-v1/manifest.json`, 전체 프롬프트는 `prompts.json`에 보존한다.
- 전용 계약실 → 투입 계약 흡수 → 봉인 충전 → 밀어서 개방 → 새 SSS 카드 공개. 실제 서버 영수증이 확정된 후 연출한다. PC 마우스·모바일 터치, 미완료 슬라이드 복귀, 바로 결과 보기, 키보드 End/Enter, 동작 줄이기에 대응한다. 자동 재생 음향은 없다.
- `/mercenary-codex/sss-reroll/?preview=1`은 고정 시연 데이터만 사용하며 API 재뽑기 요청을 보내지 않는다. 시연 확률·보유량은 운영 설정과 무관하다. 원화 기술 검수 완료를 사용자의 최종 시각 승인으로 간주하지 않는다.

## 거래 보호

- 기존 계정 잠금·공동 영수증·원자 거래를 재사용한다. 신규 테이블·마이그레이션·의존성·인증 기반 변경이 없다.
- 선택 용병·설정 버전·난수 결과를 영구 요청 계획에 고정한다. 아이템 차감·입력 소모·결과 보유량·획득 원장·아이템 로그·완료 영수증이 한 거래다. 마지막 1장 소모는 수량 0행을 남기지 않고 해당 보유행을 삭제한다.
- CMS 설정·등급·공통 획득 잠금·보유량·편성이 바뀐 미완료 요청은 취소한다. 이미 완료된 영수증은 재추첨하지 않는다. 정책 저장도 버전과 이전 값 비교 후 갱신한다.
- 클라이언트는 요청 ID를 계정별로 먼저 저장하고, 연결 오류·새로고침 시 영수증을 먼저 확인한다. 결과 다시 보기·닫기·밀기·건너뛰기는 추가 차감과 재판정이 없다.

## 검수

- 서버 SQLite/PostgreSQL: 기본 OFF·OWNER·교차 출처 차단·확률 정밀도·동일/리미티드 제외·마지막 1장·중복 합산·성장 보존·편성 보호·부족 재료·실패 전체 롤백·고정 결과 재시도·설정 변경 취소·타 계정 영수증 차단.
- 클라이언트: 응답 유실 후 복구·동시 클릭·계정 전환·저장 공간 실패·잘못된 영수증·취소 처리.
- 운영 준비: OFF 생성·dry run·감사 실패 롤백·재실행 시 기존 설정 보존·지급 없음.
- PC 1440×1000 / 모바일 390×844: 실제 테스트 API 거래, 잘린 응답 후 새로고침 복구, 터치/마우스 슬라이드 및 중간 복귀, 결과 재생, CMS 확률 저장, 동작 줄이기·키보드. 콘솔 오류 0. 모바일 장식 궤도로 인한 가로 넘침을 수정했다. 캡처와 측정은 `docs/qa/sss-reroll-20261014/`에 보존했다.
- 각 화면의 원화·결과 카드·버튼·모바일 가독성을 직접 확인했다. 시연 계정만 차감했으며 운영 재화는 사용하지 않았다.

## 배포 범위

신규 기능 한 개가 기존 등록·인증·거래 기반을 재사용하며 일반 뽑기/전투를 변경하지 않는다. 관련 거래·클라이언트·운영 준비 검사와 Worker 문법 검사를 지정하고 `npm run deploy:production -- --scoped`를 사용한다. 직전 실제 운영은 Pages `d6513b36`, 소스 `eec4dbff621ea3b1df547f86c2c7a8a2fddc6525`로 조회했다. 다른 작업의 최신 주작 대기 연출을 보존한다. 출시 플래그·캐시 일치·Hyperdrive 캐시 OFF 조건을 유지한다. PC/모바일 검수는 통과한 범위를 불필요하게 반복하지 않는다.
