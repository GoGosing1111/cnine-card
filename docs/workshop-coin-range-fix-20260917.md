# 제작소 고액 코인 차감 오류 수정

## 장애와 원인

- 솔라리스 조립의 5,000,000,000 코인 비용에서 `value "5000000000" is out of range for type integer` 발생.
- 운영 DB 읽기 전용 확인: `users.coin`, `coin_logs.change_amount/balance_after`, 제작 레시피 비용과 제작 로그 금액은 이미 `bigint`다.
- PostgreSQL 호환 계층이 단항 바인딩 `-?`를 `(0-$n)`으로 바꿨다. 리터럴 `0` 때문에 매개변수가 `int4`로 추론되어, 차감 기록을 `bigint` 컬럼에 넣기 전에 실패했다.
- 같은 경로를 쓰는 배틀슈트 04의 10,000,000,000 코인 비용도 영향을 받는다.

## 수정

- 단항 매개변수를 `(-CAST($n AS NUMERIC))`으로 변환한다. 큰 정수와 소수를 정확히 계산하며 이항 뺄셈, SQL 문자열과 주석의 기존 처리는 유지한다.
- 금액 컬럼 변경이나 운영 데이터 마이그레이션은 필요하지 않다.
- 코인/별 비용, 성공 확률, 재료 수량, 활성화 설정은 변경하지 않는다. 실패한 제작 요청은 기존 정책대로 새 요청 번호로 재시도한다.
- 실제 제작 함수와 PostgreSQL 호환 계층을 함께 실행하는 회귀 검사를 `test:workshop`에 추가하고, 기존 `test:postgres-compat`도 전체 출시 검사에 포함한다.

## 검증

- 수정 전 PostgreSQL WASM에서 실제 제작 함수가 50억 차량 조립 성공/실패와 100억 장비 제작 모두 같은 `22003` 오류를 재현했다.
- 수정 후 동일 경로에서 정확한 코인·별·재료 차감, 결과에 따른 지급, 요청 재전송 시 중복 차감 방지 검증 통과.
- 차감 기록 단계에 오류를 주입해 코인·별·재료·지급·로그가 모두 롤백되고 요청만 `FAILED`로 남는 것을 확인했다.
- 단항 값 0, int4 경계, 50억, 100억, JavaScript 최대 안전 정수, 음수, 소수와 NULL 검증 통과.
- 2026-09-17 03:11 KST 운영 DB 읽기 전용 트랜잭션에서 배포 후보의 실제 호환 계층으로 2,147,483,648 / 5,000,000,000 / 10,000,000,000 / 9,007,199,254,740,991의 음수 변환과 bigint 저장 타입 변환을 확인했다. 실제 계정 제작이나 재화 변경은 수행하지 않았다.
- 운영 레시피 읽기 결과: 솔라리스 50억·별 250,000·성공 10%, 배틀슈트 04 100억·별 300,000·성공 10%.

## 운영 반영

전체 `release:gate`를 포함하는 `npm run deploy:production`으로 반영한다. 롤백은 이 수정의 코드 커밋을 되돌리는 방식이며 DB 복구 작업은 필요하지 않다.
