# 격전지(협동) — 2026-10-01

**현재 상태: 기존 용병 검사 5건과 후속 도감 실패 10건 수정 완료, 남은 출시 검사 진행.** 도감 관련 3개 파일 159/159 및 실제 미리보기 PC·모바일 검수가 통과했다. 완료된 전체 게이트 31개 단계 중 직접 영향받는 계약만 다시 검사하고 남은 단계를 재개한다. 운영 배포는 아직 완료하지 않았다.

사용자 요청: 세 명이 같은 대기방에서 각자 용병 1명·보유 카드 2장을 골라, 같은 전장의 9명과 동일한 전투 진행을 함께 본다. SS·SSS 용병과 ZENITH·FUR·SUPERSTAR의 실제 고유효과로 난이도를 검증하고 기존 게임에 맞는 UI를 구현한다.

## 이용 흐름과 운영 범위

- 모험 → 레이드 → **격전지(협동)** → 일반/격전/극한 선택 → 10자리 대기방 코드 공유 → 3인 편성 → 출전 준비 → 전원 로딩 완료 → 공통 3초 카운트다운.
- 각 계정이 소유한 서로 다른 카드 2장과 용병 1명만 허용한다. 슈퍼스타는 1인 1장까지다. 서로 다른 참가자가 같은 카드를 소유했다면 함께 사용할 수 있다.
- 일반 덱 저장 계약은 계속 5장이다. 협동 전용 편성은 별도 저장하며 일반 덱이나 용병 슬롯을 변경하지 않는다. 각 용병은 소유자의 카드 2장과 능력치를 연동하고, 아군 대상 회복/보호는 기존 팀 스킬 규칙을 사용한다.
- 준비할 때 실제 카드 강화·고유특성 진화·PVE 장비 보너스와 현재 승인 용병 등급/배정 스킬을 서버에서 다시 읽고 편성을 잠근다. 배틀슈트 보너스는 제외하며 배틀슈트/별도 마법카드를 추가 출전시키지 않는다. 총 아군은 항상 9명이다.
- 기본 운영값은 **TEST, 참여자 빈 목록, OWNER 허용**이다. OWNER는 화면의 운영 테스트 설정에서 OFF/TEST/ON과 최대 100명 계정 ID를 관리한다. OFF에서도 OWNER에게 설정 진입을 유지한다. 이번 배포로 ON을 저장하거나 테스트 계정을 임의 등록하지 않는다.
- 입장 차감과 보상 지급은 구현하지 않았다. 모든 상태에서 보상 잠금을 표시한다. 기존 리치왕 입장권 공대와 별개 콘텐츠다.

## 같은 전장·이탈 판정

- 기존 private API runtime에 SQLite Durable Object `CooperativeRoom`, `CooperativePlayer`를 추가한다. 방마다 편성, 시드, 상태, 서버 전투 시간, 결과, 명령 영수증을 저장한다. 한 계정은 한 활성 방에만 참가한다.
- 기존 계정 인증·동일 출처 검증·사용자 잠금을 재사용한다. WebSocket 접속은 인증된 API가 발급하는 60초 일회용 티켓을 사용한다. 로그인 토큰을 WebSocket URL에 노출하지 않는다.
- `LOBBY → LOADING → ACTIVE → VICTORY/DEFEAT`. 세 명의 준비와 로딩 완료가 각각 장벽이며 시작 시각은 서버가 한 번 확정한다. 피해·공격·처치·승패 계산은 기존 서버 전투 엔진을 사용한다.
- 각 화면은 같은 이벤트와 서버 시각을 재생한다. 지연이 커지면 지난 연출을 취소하고 서버 HP/보호막 상태로 맞춘다. 기기별 프레임 동시성까지 보장하지 않으며 전투 상태와 결과를 공유한다.
- 전장 로딩부터 새 화면으로 재접속하거나 명시적으로 나가면 **본인만 패배**, 본인의 카드 2장과 용병 1명을 제거한다. 나머지는 계속 싸운다. 동일 시드와 이탈 시각으로 재계산하여 이탈 이전 결과를 보존한다.
- 1초 heartbeat, 15초 무응답 패배. 같은 화면의 짧은 연결 복구는 허용한다. 브라우저 종료는 WebSocket/keepalive와 서버 만료 판정으로 처리한다. 만료와 승리가 동시에 밀려 도착해도 실제 만료 시각을 먼저 처리하여 이탈자가 승리로 바뀌지 않는다.
- 새로고침 패배는 다음 화면에서 확인할 수 있게 남기고, 결과의 목록 복귀 버튼으로 방 연결을 해제한다. 대기방 이탈은 패배가 아니며 방장을 다음 참가자에게 넘긴다.
