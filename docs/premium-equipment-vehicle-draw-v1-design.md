# 프라임 장비·이동수단 상품 분리 설계 v1

## 현재 상태

- 상태: `PREPARED_ONLY`
- 이미지 리소스와 도입 설계만 준비한다.
- 운영 상점, 인벤토리, API, 확률, 가격, DB에는 아직 연결하지 않는다.
- 기존 `EQUIPMENT_SUPPLY_BOX`, `VEHICLE_DRAW_TICKET`의 판매 및 개봉 상태도 변경하지 않는다.

## 신규 상품

| 구분 | 임시 상품명 | 신규 아이템 코드 | 이미지 |
| --- | --- | --- | --- |
| 장비 | 프라임 아머리 상자 | `PRIME_EQUIPMENT_SUPPLY_BOX` | `assets/ui/packs/prime-armory-equipment-box-v1.png` |
| 이동수단 | 프라임 하이퍼드라이브 팩 | `PRIME_VEHICLE_DRAW_TICKET` | `assets/items/prime-hyperdrive-vehicle-pack-v1.png` |

상품명은 출시 전 CMS에서 교체할 수 있다. 아이템 코드는 기존 상품과 재고가 절대 합쳐지지 않도록 별도 코드로 고정한다.

## 기존 상품 보존 규칙

1. 기존 재고는 신규 아이템으로 변환하거나 이름을 바꾸지 않는다.
2. 기존 상품의 상점 구매만 중단하고, 인벤토리 개봉은 계속 허용한다.
3. 기존 장비상자는 현재처럼 `enabled=true`, `shopEnabled=false`로 두어 개봉과 판매를 분리한다.
4. 기존 이동수단은 현재 `settings.enabled`가 판매와 개봉을 함께 막는 구조이므로 그대로 끄면 안 된다. 출시 구현 때 `openEnabled`와 `shopEnabled`를 분리하고, 기존 재고는 `openEnabled=true`, `shopEnabled=false`로 유지한다.
5. 기존 개봉 영수증, 중복 보상, 보유 수량, 메시지 지급 내역은 그대로 보존한다.

## 권장 가격안

가격은 아직 적용하지 않는 검토 기준이다.

| 상품 | 권장 단가 | 판매 묶음 | 할인 |
| --- | ---: | --- | --- |
| 프라임 아머리 상자 | 30,000,000 코인 | 1개 / 10개 | 없음 |
| 프라임 하이퍼드라이브 팩 | 100,000,000 코인 | 1개 / 10개 | 없음 |

- 100개 구매는 고액 오조작 방지를 위해 기본적으로 숨긴다.
- 구매 직전 서버가 현재 가격을 다시 검증하고, 가격이 바뀌면 결제를 중단한다.
- CMS 가격 상한은 최소 2,000,000,000 코인까지 허용하되 총액은 안전 정수 범위와 보유 코인을 함께 검사한다.

## 보상 풀 초안

### 프라임 아머리 상자

- 코인·카드 조각 같은 대체 보상은 제외하고 장비 1개를 확정 지급한다.
- 활성·공개 상태인 장비만 후보로 사용한다.
- 장비 전투력 백분위로 자동 구간을 만들되 CMS에서 개별 장비 확률을 덮어쓸 수 있게 한다.
- 권장 자동 배분:
  - 상위 1% 장비: 합산 0.10%
  - 상위 1~5%: 합산 2.90%
  - 상위 5~20%: 합산 17.00%
  - 상위 20~50%: 합산 35.00%
  - 나머지 프라임 풀: 합산 45.00%
- 같은 장비가 다시 나와도 장비 인스턴스를 새로 지급하는 현행 장비 소유 모델을 유지한다.

### 프라임 하이퍼드라이브 팩

- 기존 저가 이동수단 풀과 분리된 프라임 전용 풀을 사용한다.
- 신규 하이퍼카와 고전투력 이동수단을 중심으로 구성한다.
- 전투력 백분위에 따라 기본 가중치를 자동 계산하고, CMS에서 `자동 / 개별 고정`을 항목별로 선택할 수 있게 한다.
- 최고 전투력 개별 차량은 0.01~0.10% 범위에서 세부 설정할 수 있게 한다.
- 중복 차량 보상은 차량별 카드 조각과 마스터의 별을 각각 설정한다.
- 비싼 상품의 체감 보호안으로 10회 안에 상위 30%, 50회 안에 상위 10% 차량을 보장하는 천장을 별도 옵션으로 둔다. 기본 OFF 상태로 검수한다.

## API·DB 분리안

- 설정 키:
  - `prime_equipment_supply_box_settings_v1`
  - `prime_vehicle_draw_settings_v1`
- API:
  - `equipment/prime-supply-box/config|purchase|open`
  - `vehicle-draw/prime/config|purchase|open`
- 구매·개봉 영수증에는 반드시 `item_code`와 풀 버전을 기록한다.
- 구매 시 신규 아이템 코드만 증가시키고, 개봉 시 동일 코드만 차감한다.
- 확률표 수정 뒤에도 이미 구매한 팩의 적용 기준을 감사할 수 있도록 개봉 결과에 `poolVersion`을 남긴다.
- 한 요청에서 차감·보상·영수증 완료를 원자적으로 처리하며, 보상 INSERT가 0행이면 아이템을 차감하지 않는다.

## 상점 전환 순서

1. 신규 아이템·API·CMS를 기능 OFF로 배포한다.
2. 기존 두 상품과 신규 두 상품의 인벤토리 개봉 회귀 테스트를 각각 통과시킨다.
3. 신규 확률표와 가격을 최종 승인한다.
4. 기존 상품은 `shopEnabled=false`, `openEnabled=true`로 전환한다.
5. 신규 상품만 `shopEnabled=true`, `openEnabled=true`로 전환한다.
6. 문제 발생 시 신규 판매만 OFF하고 기존 재고 개봉 기능은 그대로 유지한다.

## 출시 전 필수 검증

- 기존 장비상자 보유자가 판매중단 후에도 정상 개봉 가능
- 기존 이동수단 뽑기권 보유자가 판매중단 후에도 정상 개봉 가능
- 신규 상품 구매가 기존 재고를 증가시키지 않음
- 신규 상품 개봉이 기존 재고를 차감하지 않음
- 가격 변경 중 중복 결제 및 구가격 결제 차단
- 동시 개봉·재시도 시 이중 차감 및 이중 지급 차단
- 비활성·비공개 보상 제외
- 확률 합계 100% 및 CMS 시뮬레이션 결과 허용 오차 확인
