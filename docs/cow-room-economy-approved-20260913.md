# 카우방 보상·입장 횟수 확정

2026-09-13 사용자 지시: “카우방 보상 상한선 풀어놔라 100억까지 클리어 5억 최대 상한 30억 입장회수 6회”.

| 항목 | 확정값 |
| --- | --- |
| 카우 킹 클리어 보상 | 500,000,000 코인 (5억) |
| 일일 코인 보상 상한 | 3,000,000,000 코인 (30억) |
| 일일 입장 횟수 | 6회 |
| CMS 클리어 보상·일일 상한 입력 허용치 | 각각 10,000,000,000 코인 (100억)까지 |

100억은 CMS와 서버의 입력 한도다. 현재 지급 설정은 클리어 5억·일일 30억이며, 6회 모두 클리어하면 보상 합계가 30억이다. 기존 실패 보상 없음·포탈 1개 사용·일일 집계의 한국 시간 기준은 유지한다. 입장 코인 250,000은 이번 지시의 변경·승인 범위에 포함하지 않는다.

`shared/cow-room-economy-v1.mjs`의 한도를 CMS와 서버가 같이 사용한다. 기존 클리어 2천만·일일 2억의 서버 검증 제한을 모두 100억으로 늘렸다. 새 설정 기본값도 위 수치로 변경했으며, 이미 저장된 다른 설정은 자동으로 덮어쓰지 않는다. 공동 출시 시 이 확정 수치를 승인 정책 문서의 COW_ROOM 구성에 반영한다.

현재 검수 서버의 OWNER CMS에서 실제 저장한 값은 5억·30억·6회다. 기존 계정·다른 CMS 설정을 보존해 서버를 다시 시작했으며, 이전 SQLite 파일은 그대로 남겨 두었다. 60개 테이블을 비교해 `expedition_v3_cow_room`의 보상·횟수 및 저장 이력 필드만 변경된 것을 확인했다.

## 검증

- `tests/cow-room-economy-v2.test.mjs`: SQLite·PostgreSQL에서 100억 저장·실제 지급, 초과/음수/소수 거절, 5억×6회=30억 누적, 7회차 차단, 동일 결과 재조회 무중복, 날짜 변경 시 일일 집계 초기화.
- 기존 계정 원정·포탈·공동 승인 문서 테스트와 함께 32개 통과. PostgreSQL의 BIGINT 준비 스키마와 SQLite에서 32비트 범위를 넘는 누적 금액·잔액을 실제 정산했다.
- 기존 카우방 전투·V3 개편 준비 회귀 9개와 `npm run check:worker`도 통과했다.
- `scripts/qa-cow-economy-v2.mjs`: 실제 CMS 저장 후 재조회, 100억 입력 한도, 1440·390·320px 가독성·입력 칸 경계·화면 넘침 검수. 브라우저 오류 0건.
- 검수 서버 재시작 시 `JOINT_QA_RESTORE_DATABASE`로 이전 로컬 QA DB를 새 파일에 복사할 수 있다. 기존 DB 경로는 QA 디렉터리의 `joint-account-숫자.sqlite`로 제한한다. 원본 파일은 수정하지 않는다.

보상 수치 확정은 공동 기능 활성화 지시가 아니다. `V3_JOINT_RELEASE_ENABLED=false`를 유지하며 운영 배포는 기존 공동 출시 절차를 따른다.
