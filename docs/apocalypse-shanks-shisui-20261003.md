# 샹크스 · 우치하 시스이 아포칼립스 확장

사용자 요청에 따라 카네키 켄의 군단 전투를 두 보스에 연결하고 별도 배틀슈트 스킬 방어를 추가한다. 실제 운영 카네키 켄의 CMS 기본 전투력 80,000,000·궁극기 20%를 기준으로 정했다. 과거 프리뷰의 10,000,000·225%는 현재 운영 기준이 아니다.

| 보스 | ID | 기본 전투력 | 궁극기 공격 배율 | 보호막 관통 | 슈트 스킬 피해 감소 |
| --- | --- | ---: | ---: | ---: | ---: |
| 샹크스 | 77 | 120,000,000 | 45% | 50% | 35% |
| 우치하 시스이 | 78 | 180,000,000 | 70% | 65% | 50% |

첫 3행동에 봉인·회복 차단·궁극기를 1회씩 사용한다. 샹크스 봉인은 고공격 3명·3행동, 시스이는 4명·4행동이며 정화로 해제한다. 회복·재생·흡혈 차단은 전체에 각각 3·4행동 적용한다. 보스와 독립 HP·행동·사망을 가진 쫄몹 6마리를 모두 처치해야 승리한다. 기존 뱀파이어·타락한 성기사·달빛 악령을 각 2마리 사용하며 기본 전투력은 보스의 8%다. 개막 궁극기는 중복 발동하지 않는다.

카네키의 HP·공격·방어·속도·보호막·강제 행동 및 보상 설정을 복제한다. 기존 HARD 샹크스 #13, 아카드 #75, 카네키 #76과 다른 CMS 설정은 변경하지 않는다.

## 별도 방어 스탯

`battleSuitSkillDefensePercent`는 일반 방어력과 독립된 0~100% 피해 감소다. 스킬칩과 X·Z 슈트 고유기의 보호막 피해·관통 피해를 모두 감소시킨 후 각 타격에 분배한다. 일반 슈트 사격과 카드 피해는 기존 계산을 유지한다. 100%면 스킬 피해와 관통 피해 모두 0이다. 쫄몹에는 부여하지 않는다.

CMS의 군단 보스별 입력으로 조절하며 토벌 화면에도 표시한다. 기존 보스의 기본값은 0이고, 필드가 없는 구형 CMS 요청은 저장된 값을 보존한다. 명시적 0은 유효하다. 진행 중 전투는 시작 시 저장한 값을 유지한다.

## 리소스

`assets/ui/project-v/monsters/apocalypse-shanks-shisui-v1/`에 사용자 원본 2장, 투명 전신 SD 2장, 보스별 3종 스킬 시트·아틀라스 6쌍을 보존한다. 각 시트는 4×3, 서로 다른 12프레임이며 7번째가 충돌 프레임이다. 총 72프레임이다.

내장 image_gen으로 제작했으며 알파·실제 프레임·가장자리·전신·자연 비율·머릿결·무기 축을 확인했다. 시스이 궁극기는 셀 여백을 보완한 최종본을 사용한다. 원본 및 파생 이미지를 코드로 재채색·배경 제거·재압축하지 않았다. 생성 프롬프트는 `prompts.json`, 해시·프레임·알파 검수는 `manifest.json`이다. 승인된 기존 쫄몹 리소스는 보존한다.

## 관련 검증과 범위 배포

새 보스의 실제 서버 7마리 전투·세 스킬·OFF·방어 0/35/50/100·관통·X/Z 광역기·상태 스냅샷·CMS 구버전 보존·PostgreSQL 원자 등록/롤백/재시도/ID 자동 증가를 검증했다. 기존 군단/궁극기 12건, 슈트 피해·스킬칩·X/Z·공용 로더 관련 경로도 통과했다. PC에서는 샹크스의 실제 전투와 상태 표시를, 390×844 모바일에서는 시스이의 7마리 진형과 전용 이펙트·피해 감소 표시를 확인했다.

`tests/pve-apocalypse-v1952.test.mjs`의 기존 URL 문자열 순서 고정 assertion은 실패했다. 기준 커밋에서도 `coop=...`가 `v=2110-combat-lobby` 앞에 있어 같은 실패이며 전투 실행과 무관하다. 이미 통과한 관련 검사는 무효화하거나 전체 게임 검사로 확장하지 않는다.

직전 실제 운영 배포는 Pages `50774bf0-dc8d-461d-bed3-546a6cc3c1fb`, 소스 `dd706edc46e14c97b874588b65f2fecb0ecb65c1`이다. 최신 원격의 펫 작업은 통합 보존한다. 신규 몬스터 두 종과 국소 피해 분기·CMS·진입 표시·공용 번들만 바꾸며 인증·스키마·트랜잭션 기반·의존성은 변경하지 않는다.

지정 명령은 `npm run deploy:production -- --scoped`다. 이미 실행한 서버 검사를 반복하지 않고 남은 기존 보스/SD/공용 진형 검사를 선택한다: `tests/apocalypse-signature-v2048.test.mjs`, `tests/project-v-apocalypse-boss-sd-v1958.test.mjs`, `tests/v3-common-grid-v1.test.mjs`. 배포 도구가 요구하는 `tests/pve-battlefield-entry-v2117.test.mjs`, `check:worker`, 출시 플래그·캐시·Hyperdrive·깨끗한 커밋 검사는 유지한다.

배포된 16개 리소스의 SHA-256을 확인한 뒤 고정 키 `ops:apocalypse-shanks-shisui-release:20261003:v1`로 두 행·CMS 설정·감사 로그·영수증을 한 트랜잭션에 등록한다. 사전 실행은 롤백했으며 실제 등록에서만 기존 PostgreSQL identity sequence를 nextval로 필요한 만큼 앞으로 진행한다. setval로 되감지 않는다. 이후 독립 읽기 전용 연결로 새 보스·기존 설정 보존·감사 로그 1건을 확인한다.

## 운영 반영

소스 `14237d04d9764dfdaae88dabc03f52c3b5922cda`를 지정 scoped 명령으로 배포했다. 추가 범위 검사 25/25, Worker 컴파일·출시 보호·Hyperdrive 캐시 OFF 검사가 통과했다. Pages는 `https://ac3a24ec.cnine-card.pages.dev`, API 런타임은 `5b327e99-e1e4-404e-b9cd-eed88a64bfca`, 클랜 워커는 `4c0dabdf-427e-471b-9f77-7962c03b548e`다.

운영 리소스 16개와 진입/CMS/공용 런타임 9개 파일은 로컬과 SHA-256이 일치했다. 두 보스를 한 번 등록했고 감사 로그는 **40163**이다. 독립 읽기 전용 연결에서 전투력·궁극기·슈트 방어 및 기존 설정 보존을 확인했다. 실제 CMS에서도 샹크스 35%·시스이 50% 입력을 확인했다.

모바일 CMS 검수에서는 기존 `aside{height:100vh}`가 상단 메뉴의 배경으로 화면 전체를 가렸다. 새 입력의 값과 너비는 정상이었다. 전투관리 화면이 열려 있고 800px 이하일 때에 한해 메뉴 높이를 auto로 보정한다. 다른 CMS 화면과 데스크톱에는 적용하지 않는다. 이 CSS·캐시 수정은 위 소스를 기준으로 최소 scoped 후속 배포하며 이미 통과한 전투/자산 검사는 반복하지 않는다.
