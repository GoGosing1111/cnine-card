# 용병 실전 성능 상향 · 2026-09-13

사용자 요청: “확실히 쌔지게 만들으라고 스킬도 알아서 조정”. 고전투력 일반 카드에 비해 용병의 고정 공격력이 너무 작아 기본 공격·피해·회복·보호의 기여도가 사라지는 문제를 수정한다. 앞서 긴급 배포한 하이퍼팩 수량 수정 `da3698d5`를 포함한 후속 배포다.

## 전력 연계

등급별 기본 전투력 C 1만 / B 2만 / A 4만 / S 7만 / SS 12만 / SSS 18만과 기본 능력치는 유지한다. 별도 능력인 전력 연계는 전투 시작 시 **자기 편 일반 카드 5명**의 평균 공격력·최대 체력으로 한 번 결정된다. 배틀슈트·상대·다른 용병은 산정에 포함하지 않으며, 전투 중 사망이나 강화로 다시 계산하지 않는다.

| 등급 | 평균 공격력 대비 최소 공격력 | 평균 최대 체력 대비 전용 방벽 |
| --- | ---: | ---: |
| C | 35% | 60% |
| B | 45% | 70% |
| A | 55% | 80% |
| S | 65% | 90% |
| SS | 85% | 120% |
| SSS | 115% | 150% |

- 기본 공격과 피해·회복·방벽·보호·독·반격의 공격력 예산에 같은 연계 공격력을 사용한다. 실제 공격력이 하한보다 높으면 기존 공격력을 사용한다.
- 전용 방벽은 기존 일반 카드의 수호형 방벽을 나누어 가져오지 않는다. 소진 가능한 방벽이며, 피격 상한에도 최초 방벽 크기를 포함하여 낮은 기본 HP로 방벽이 사실상 무적이 되는 것을 막는다. 사망 상태로 시작하는 용병은 방벽을 받지 않는다.
- 아군 일반 카드 3회 행동마다 용병이 추가 행동한다. 자연 행동 시 주기를 다시 센다. 상대 행동·배틀슈트 사격은 주기에 포함하지 않으며, 일반 카드 행동 예산·순서·난수는 유지한다.
- 위협도 기반 스킬은 상대의 전력 연계 공격력도 확인한다. 이미 사라진 대상에게 후속 피해를 적용하지 않는 기존 취소 규칙은 유지한다.
- 도감과 CMS 용병 상세에 등급별 연계 기준을 공개한다. 개별 스킬 배율·재사용·비용은 기존 운영 CMS에서 계속 편집한다.

## 스킬 수치

26개 스킬을 `shared/mercenary-skill-balance-v2103.mjs`의 초안으로 **한 번만** 운영 CMS에 저장한다. 런타임·시드가 이 초안을 자동 덮어쓰지 않으며 이후 운영자 수정을 그대로 읽는다. 등급·배정·원화·SD·효과 설명·핵심 기믹·개봉 확률·재화는 변경하지 않는다.

| 스킬 | 효과 배율 | 재사용 | 에너지 |
| --- | --- | --- | --- |
| 루비 최후통첩 | 210% → 380% | 5 → 3 | 30 → 20 |
| 종언의 사건지평선 | 240% → 560% | 7 → 5 | 45 → 35 |
| 탄착 교정 | 210% → 420% | 6 → 5 | 30 → 25 |

광역·다단 배율은 기존처럼 전체 예산이다. 준비·타격·소멸 프레임, PixiJS·GSAP 재생, 승인된 7개 역할의 기본 공격 자산과 사운드는 그대로 사용한다.

## 검증

- 기존·변경 후 각각 43종 × 일반 카드 전투력 4구간(10만·100만·2천만·1억) × 공격/수비 × 512시드 = 176,128회 비교. 최종안 172조건 모두 기존 버전 대비 표본 승률 하락이 없었다.
- 베스페라, 일반 카드 각 1억인 동일 덱: 기존 승률 51.37% → 74.02%, 팀 피해 기여 0.0106% → 15.71%. 이는 동일 덱으로 진행한 재현 가능한 비교 실험이며 개별 PVP 승리를 보장하는 값이 아니다.
- 방벽·기본 능력치·일반 카드 난수/행동 예산 보존, 방벽 소진·사망, 회복/보호 예산, 에너지/재사용, 취소/대상 소실, PVE·아포칼립스·연속 몬스터 전투 회귀를 확인한다.
- 실제 V3에서 7역할 기본 공격 및 PVP·PVE+스킬칩·연속 전투 전체 재생이 완료됐고 남은 효과 노드와 활성 스킬이 없었다. 브라우저 오류·누락 자산도 없었다.
- 도감·CMS 실제 모듈의 PC 1440×1000 / 모바일 390×844에서 기본 전투력, 전력 연계, 변경 스킬 수치와 가로 잘림을 확인했다.
- 기록: 배포 폴더 밖 `../qa/mercenary-strength-2102/`의 `comparison-release.json`, `live-connection-report.json`, `catalog-browser-report.json` 및 CMS 변경 전·후 영수증.

## 배포와 운영 적용

코드는 범위 커밋 후 `npm run deploy:production`만 사용한다. 전체 `release:gate` 통과와 운영 배포 확인 후 CMS r53을 기준으로 해시·버전 조건부 갱신을 수행한다. 26개 스킬 밸런스와 검수 필드만 갱신하며 운영 감사·멱등 영수증을 같은 트랜잭션에 기록한다. 임시 운영 도구는 시간 제한·인증키·Hyperdrive를 사용하고 완료 후 종료 및 키 삭제한다.

롤백은 배포된 코드 버전과 감사 기록의 CMS 변경 전 수치를 함께 사용한다. 이후 운영자가 편집했다면 현재 버전과 차이를 먼저 비교한다. 하이퍼팩 수량 수정은 되돌리지 않는다.
