# 리버스콜 초기 로딩 화면 — 2026-10-18

사용자 요청: 첨부된 초기 로딩 화면을 실제 게임에 어울리도록 개편한다.

## 적용

- `index.html`의 기존 초기 로딩 영역을 전용 성채·차원문 배경, 공식 투명 심벌, 게임 타이틀, 얇은 금속 로딩 레일로 교체했다. 내부 버전·리뉴얼 안내는 제거했다.
- 배경과 레일은 built-in ImageGen으로 신규 제작했다. 원본·전체 프롬프트·SHA-256·파생 규격은 `assets/ui/loading/reverse-call-20261018/manifest.json`, 재현 스크립트는 `scripts/build-loading-art-20261018.mjs`에 보존한다. 배경 원본을 비율대로 WebP 인코딩하고 레일의 투명 바깥 여백만 제거했다.
- 실제 사용 이미지는 PC 배경 183,098바이트, 모바일 배경 88,668바이트, 공용 투명 레일 160,854바이트다. 화면 폭에 맞는 배경 한 장만 우선 로드한다.
- 문구는 DOM이며 로딩 레일은 불확정 상태다. 임의 퍼센트·최소 대기시간·새 시작 스크립트를 추가하지 않았다. 기존 `v21-ui-ready` 전환과 로그인·대기실·수감 화면의 준비 판정은 유지한다.
- 모바일 구도, 낮은 가로 화면, 안전 여백, 웹폰트 실패 시 제목 폭, 동작 줄이기를 대응했다. 기술 검수를 사용자 시각 승인으로 기록하지 않는다.

## 검수

- 실제 `index.html`을 로컬 읽기 전용 서버에서 실행하고 앱 번들 응답만 잠시 보류하여 초기 화면을 확인했다. 번들을 해제한 뒤 기존 로그인 화면으로 정상 전환하는지 확인했다. 운영 계정이나 DB를 변경하지 않았다.
- 1440×900, 첨부 화면에 가까운 963×588, 390×844, 320×568, 가로 844×390에서 배경·레일·텍스트·하단 잘림과 겹침을 확인했다. 좁은 화면 폰트 대체 검수 후 320px 제목 폭을 추가 조정했으며 최종 좁은 화면 결과는 `docs/qa/loading-screen-20261018/narrow-final/`이다.
- 모든 확인 화면에서 스크롤 넘침 없음, 로딩 종료 후 앱 표시·로그인 전환 정상, JavaScript 예외 없음. 390px에서 동작 줄이기 설정 시 스캔 애니메이션이 정지한다.
- 브라우저 실행 기록·스크린샷·재현 코드: `docs/qa/loading-screen-20261018/`.
- 배포 시 선택 회귀: `tests/prison-system-v1950.test.mjs`(기존 부트 해제 계약), `tests/image-delivery-20261015.test.mjs`(이미지 전달·스테이징).

## 배포 패키지

배포 기준은 Pages `29a5becd-7bb9-4100-a218-985e779272ea`, 소스 `f62e75db9aef6bcd27a0ddbf6233e3e6a5dfd3e2`다. 작업 중 확인한 세계관 운영본 `1ddc975af`가 이미 19,999개 파일이므로 새 로딩 자산을 추가하면 Pages의 20,000개 한도를 넘는다. 기존 테스트 실행기 제외 규칙을 `scripts/qa-*.mjs`·`scripts/qa-*.js` 37개에도 적용했다. 이들은 Node/Playwright 검수 실행기이며 게임·프리뷰 실행 코드에서 참조하지 않음을 확인했다. 저장소에는 그대로 보존하고 실제 원화·전투 자산·프리뷰는 제외하지 않는다. 스테이징 회귀에는 실행기 제외와 원본 보존, 일반 빌드 스크립트·이미지 유지 검사를 추가했다.

최신 계엄령 운영본과 병합한 뒤 PC·모바일에서 부트 → 로그인 전환을 다시 확인했다(`integrated/`). 배포 결과와 운영 확인은 완료 후 이 문서에 기록한다.
