# 리치왕 정벌 차단·역할 배정 요청 충돌 — 2026-10-13

## 신고와 재현

차단 연타 및 포지션 배정 중 `같은 계정의 요청을 처리 중입니다. 잠시 후 다시 확인하세요.`가 나타난다는 문의를 받았다. 해당 문구는 공통 계정 변경 잠금의 `JOINT_LOCK_BUSY`(HTTP 409)다. 특정 신고 계정의 운영 요청 로그를 확보한 것은 아니며 아래 결과는 운영 잠금 구현을 사용한 재현이다.

리치왕 API는 잠금 충돌을 `retryable:false`로 응답했고 클라이언트는 바로 오류를 표시하면서 요청 번호를 버렸다. 차단·역할 배정 모두 같은 계정 잠금을 사용하므로 앞선 요청이 끝나기 전에는 동일 현상이 발생한다. 기존 리치왕 검수 fixture는 요청을 큐에 넣어 처리하므로 운영의 즉시 거절 동작이 가려져 있었다. 실제 `UserMutationLock`으로 거절을 재현했으며 수정 전 새 회귀검사는 `false !== true`로 실패했다.

## 수정 범위

- 리치왕 API의 계정 잠금·공대 CAS 충돌만 재시도 가능한 응답으로 표시한다.
- 리치왕 클라이언트는 확정된 충돌 코드에 한해 동일 요청 번호·본문으로 최대 4회 재시도한다. 간격은 120/240/400/640ms이며 무한 반복하지 않는다. 잠금이 계속 유지되면 오류를 표시하고 기존 요청 번호를 보존한다.
- 기존 같은 행동 중복 입력 방지와 독립 기믹 동시 입력은 유지한다. 처리 완료·담당 변경·마감·화면 이탈을 확인하면 오래된 기믹의 대기 재시도를 중단한다. 권한·자원·마감 오류 및 결과가 불명확한 통신 오류는 자동 재전송하지 않는다.
- 계정 잠금, 공대 CAS, 영수증·입장권·보상 거래는 그대로 유지한다. 경제 값·출시 모드·공대 상태를 운영 DB에서 변경하지 않는다.
- 메인 진입·인라인·단독 페이지와 서비스워커 버전을 `20261013-lock-retry`로 갱신한다.
