## 추가로 발견한 오류

점검·로그인·연결 복구 화면은 렌더링됐지만 V21 셸 준비 플래그가 설정되지 않아 로딩 덮개 뒤에 가려질 수 있었다. 독립 시스템 화면을 확인한 뒤 준비 상태를 표시하도록 수정했다. 점검 우회나 게임 기능 활성화는 하지 않는다.

## 검증 및 제한

- Node 회귀: 기존 출시 게이트 전체, 추가 성능/캐시/지급 재시도 검사, PostgreSQL SQL 변환 검사.
- 실제 PostgreSQL: 임시 테이블에서 BIGINT 잠금, 만료 잠금 재획득, 이전 소유자의 해제 차단, 일괄 조회 바인딩·100억 값·타 계정 차단, 사용자 한정 Core 정리 확인 후 전부 ROLLBACK. 운영 사용자 지급/차감 없음.
- 브라우저: 초기 화면에서 프라임/공통 엔진 요청 0개, 세 기능 동시 준비 시 공통 엔진 요청 1개, 챌린저 WebGL 정상, 숲켓랜드 프리뷰 개봉, 프라임 잠금 해제/특별 보상 표시 확인.
- 서비스워커 모의 런타임: 동일 버전 재요청 없음, 버전 변경 재취득, 버전 없는 파일 재검증, 관리자 제외, HTML 오응답 미캐시 확인.
- 운영 DB는 Hyperdrive/PostgreSQL이다. 기존 `x-cnine-d1-*` 계측 이름을 실제 D1 백엔드라고 해석하지 않는다. 옛 D1의 쿼리당 지연을 현재 성능 수치로 사용하지 않았다.
- 점검 중 측정된 로더 LCP는 정상 게임 초기 화면의 LCP가 아니다. 동시 사용자 p95 개선률·실제 운영 부하 감소율은 이 검사만으로 확정하지 않는다.
- Workers의 요청 경계를 넘는 DB 연결이나 진행 중 Promise는 신규 캐시에 보관하지 않는다. DB 단위 완료값만 TTL/항목 수 제한과 함께 저장한다.
- 기능 공개 상태·게임 보상/확률·전투/입장 규칙·점검 설정은 변경하지 않는다.
