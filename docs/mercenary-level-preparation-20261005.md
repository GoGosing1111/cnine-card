# 용병 레벨 활성화 준비 — 2026-10-05

사용자는 만렙 20의 용병 성장을 준비하도록 지시했고, 추가 답변으로 재료를 **같은 등급의 용병 카드**, 돌파 구간을 **5·10·15·20레벨**로 확정했다. 준비본은 OFF로 배포하며 실제 카드 소모·레벨 변경을 시작하지 않는다.

## 성장 계약

| 항목 | 준비된 동작 |
|---|---|
| 대상/재료 | 보유한 용병 / 같은 등급 용병의 중복 카드. 기본 보유 1장 보호 |
| 일반 재료 | 해당 등급의 카드당 경험치 |
| 동일 용병 | 카드당 경험치 × 동일 카드 배수, 정수 내림 |
| 일반 레벨 | 경험치를 채우면 다음 레벨로 상승, 잔여 경험치 이월 |
| 돌파 준비 | Lv.5·10·15·20의 해당 레벨 경험치 100%에서 정지 |
| 돌파 초과 경험치 | 미리 표시하고 명시적으로 동의해야 소멸. 동의 없이는 차감 거절 |
| 돌파 실패 | 레벨 유지, 해당 레벨 경험치 0%, 이전 돌파 효과 유지 |
| 돌파 성공 | 효과 1회 해금, 경험치 0%, 다음 레벨. Lv.20 성공은 20 유지·최종 완료 |
| 추가 비용 | 코인·마스터의 별 없음. 돌파 버튼에는 별도 재료 비용 없음 |
| 만렙 | 레벨 20 + 최종 돌파 완료 시 추가 훈련/돌파 차단 |

보너스 초안 종류는 최대 HP%, 공격%, 방어%, 배정 스킬 계수%, 배정 스킬 재사용 감소 턴이다. 같은 종류는 합산한다. 스탯은 전력 연계 계산 이후 적용하고 부상 비율을 유지한다. 스킬 계수는 기존 상한 10,000, 재사용은 원래 0턴인 경우를 제외하고 최소 1턴이다. 고정 등급 기본 전투력과 간호사 최대 HP 15% 회복 상한은 변경하지 않는다.

## 정책과 실행 잠금

- `shared/mercenary-level-v1.mjs`: `MERCENARY_LEVEL_RELEASE_ENABLED=false`, 만렙/돌파/재료 계약 및 공통 계산.
- `app_meta.mercenary_level_policy_v1`: 별도 OWNER 초안. 기본 `mode=OFF`, 경험치 26개·배수 1개·돌파 확률 4개·효과 4개의 **35개 설정 그룹 미정**. 다른 용병 CMS 초안을 덮어쓰지 않는다.
- `admin/mercenaries/leveling` GET/PATCH: OWNER 전용, 동일 출처, 수정 버전 충돌 검사, 저장 응답 유실 재확인. 현재 ON 저장은 423으로 거절한다.
- `mercenaries/v3/leveling/feature`: 읽기 전용 출시 상태. `state`: 내 보유 카드와 설정/성장 상태. OFF에서는 새 테이블을 읽지 않고 시작 레벨만 표시한다.
- `preview`, `train`, `breakthrough`: 정적 출시 잠금이 열리기 전에는 OWNER도 423, DB 소모 작업 없음. 실제 실행에는 정책 ON과 모든 수치 설정도 필요하다.
- `receipt`: 계정과 요청 ID가 일치하는 기록만 조회. 미완료 기록은 판정/결과를 노출하지 않는다.
- 공개 도감의 성장 진입은 `account.leveling.enabled`일 때만 표시한다. 준비본에서는 숨김이다.

새 테이블 `user_mercenary_levels_v1`의 설치 함수는 `_mercenary_level_policy.js`에 준비했으나 **이번 운영 배포에서는 실행하지 않는다**. HTTP 자동 DDL도 없다. 기존 성장 테이블의 과거 QA 레벨은 이관하지 않는다. 운영 계정의 카드/레벨/재화 변경은 이번 작업 범위에 없다.

## 거래와 전투

기존 계정 잠금과 `joint_operations_v1`을 사용한다. 새 공통 DB/트랜잭션 기반은 도입하지 않는다. 같은 요청 ID는 결과를 재사용하고, 돌파 난수는 소모 전에 영구 계획으로 고정한다. 재시도·새로고침·재접속으로 재차감/재추첨하지 않는다.

정책, CMS 등급 수정 버전, 대상 소유권, 성장 수정 버전, 중복 수량을 같은 트랜잭션에서 재확인한다. PostgreSQL은 정책/CMS 공유 잠금과 카드/성장 행 잠금도 적용한다. 재료 차감과 성장 저장은 함께 커밋하거나 함께 롤백한다. 합성과 같은 계정 재료를 공유하므로 낡은 수량의 요청은 취소된다.

승인 후 새로 시작하는 전투만 서버가 확정한 성장/보너스를 스냅샷으로 기록한다. 이미 저장된 전투 및 성장 필드 없는 스냅샷은 이전 동작을 유지한다. 현재 OFF에서는 새 성장 쿼리나 효과를 추가하지 않는다. PVE/PVP/소유자별 협동 전력 연계 뒤에 1회 적용한다.

## 배포 범위

실제 직전 운영 배포는 `c1bf20f7f2d0114d903e6f4e9849ed934ae642b7`, Pages `133da1b9-220e-4965-9f03-e43303881e60`이다. 이번 변경은 용병 성장 준비 기능으로 한정되며 운영 마이그레이션·공통 인증/거래 기반·의존성 변경이 없어 scoped 배포를 사용한다. 성장 테스트, 기존 계정/전투/연계/간호사 회귀, 도감/CMS 연결, 실제 전장 번들/메인 로더 및 Worker 컴파일을 선택한다. 전체 게임 검사를 반복하지 않는다.
