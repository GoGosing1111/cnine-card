# S-BODY 제작 결제 오류 및 정책 정정 — 2026-09-30

## 정책과 원인

- 사용자가 확정한 S-BODY 제작 비용은 슈트 코어 5 ×10, 코인 100,000,000,000, 마스터의 별 1,000,000을 **모두 차감**하는 것이다. 성공 확률 10%와 결과물 S-BODY는 그대로다.
- 운영 CMS의 `배틀슈트 05 제작`(recipe 521, `WORKSHOP_NEW_1790584013750`, 결과 장비 47)이 잘못 `COIN_OR_MASTER_STAR`로 저장돼 있었다. 초기 오류는 구 클라이언트가 `BOTH`를 요청해 서버가 거부한 것이었다.
- `d00b5bd75bdc05a149fbf1dd70ece86ec05bdad7` 배포는 CMS 값을 정답으로 오인해 선택 결제 화면을 표시했다. 이후 사용자가 동시 차감 정책을 명확히 바로잡았다. 초기 배포와 선택 결제 안내는 정정 대상이다.

## 후속 수정

- 운영 CMS에서 해당 레시피의 결제 방식만 `BOTH`로 변경한다. 코인·별 금액, 슈트 코어, 성공 확률, 결과물, 공개 상태는 바꾸지 않는다. 제작소 클라이언트는 이미 CMS 모드에 따라 `BOTH`일 때 두 비용을 표시·검사·전송한다.
- 서버는 S-BODY 결과 장비의 레시피가 `BOTH`가 아니면 제작을 거부한다. `BOTH` 레시피에 구 화면이 명시적으로 `COIN` 또는 `MASTER_STAR`만 보낸 경우도 영수증 예약과 차감 전에 거부한다. 결제 방식이 없는 기존 호출은 유지한다.
- 기존 제작 트랜잭션은 코인·별·재료 차감과 결과 지급을 원자적으로 처리하고 같은 요청번호를 재사용한다. 차감·지급 SQL은 변경하지 않는다.

## 범위 검사와 배포 기준

- 직전 운영 배포 소스는 `d00b5bd75bdc05a149fbf1dd70ece86ec05bdad7`이고, 이후 `9a5c0594`는 문서만 반영했다. 이번 변경은 제작소 결제 검증의 국소 수정으로 `npm run deploy:production -- --scoped`를 사용한다.
- 관련 검사: `tests/battle-suit-workshop-v2004.test.mjs`, `tests/workshop-battle-suit-payment-20260930.test.mjs`, `tests/workshop-coin-postgres.test.mjs`. PC·모바일 동시 비용·요청, 구 선택 요청 거부, 코인·별·코어 원자 차감, 동일 요청 재생, 실패 시 롤백을 확인한다. Worker 컴파일은 scoped 배포 검사에 포함한다.
- 실제 운영 계정의 재화를 소모하는 제작 버튼은 누르지 않는다. 배포 후 CMS 값과 운영 화면의 두 비용, 새 서버 배포 상태를 짧게 확인한다.
