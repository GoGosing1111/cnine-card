# 동방무기 실패 리페어와 장비제작 마별 상한

사용자 요청: 동방무기 제작 실패로 소모된 +10 무기를 리페어권으로 복구 가능하게 하고, 잘못된 ‘실패 시 보존’ 안내를 교정한다. 장비제작 마스터의 별 비용 설정 상한은 100만에서 2,000만으로 확대한다.

## 구현

- `failureInputPolicy=CONSUME`와 `failureRepairable=true`인 실패만 기존 `equipment_forge_destroyed_v1` 기록을 생성한다. 소모 대상의 실제 소유 인스턴스·장비·이름·이미지·전투력·+10·revision과 제작 원인을 보존한다. 입력 삭제·코인/별/재료 차감·천장 누적·영수증과 같은 트랜잭션으로 기록하며 기록 생성이 누락되면 전체를 롤백한다.
- 기존 강화 센터의 복구 거래를 그대로 사용한다. 현재 운영 정책은 `PINGDU_REPAIR_COUPON` 1장 + 100,000,000,000 코인, 이전 단계(+10) 복구, 기간 제한 없음이다. 제작 재화와 실패 누적은 환급/초기화하지 않는다. 성공 변환·일반 보존 실패·복구 비허용 소모는 복구 기록을 만들지 않는다.
- 실패 연출에 해당 기록으로 가는 링크를 제공한다. 강화 센터는 ‘제작 실패 · 리페어 복구’, ‘소모 당시 +10’으로 표시한다. 다른 계정이나 이미 사용한 기록의 링크는 임의의 다른 장비를 선택하지 않는다.
- CMS 동방무기 새 초안은 소모+리페어 설정으로 시작한다. 보존 정책에서는 리페어 설정을 사용할 수 없다. 기존 일반 조합식의 누락 필드 기본값은 보존·복구 비대상이다.
- 장비제작 비용 상한은 서버와 CMS 모두 마별 20,000,000개다. 초과 저장은 거부하며 조용히 수량을 줄이지 않는다. 현재 레시피 비용, 다른 제작 종류의 정책은 자동 변경하지 않는다.
- 유저 화면의 상단 안내는 저장된 자유 설명 대신 실제 실패 처리/리페어 정책으로 생성한다.

## 운영 설정 교정

읽기 전용 조회에서 기존 동방무기상 레시피 526(`WORKSHOP_ITEM_SYNTHESIS_1790598488947`, 결과 장비 40 / `EQ_1788486888336`)을 확인했다. 실패 처리는 이미 `CONSUME`인데 설명만 보존으로 남아 있었다. 조회 당시 운영 OFF, 공개 ON, OWNER 제한 OFF, 마별 1,000,000, 정책 revision 3이었다.

`scripts/ops/eastern-craft-repair-policy-20261004.mjs`는 두 승인 동방무기 코드만 대상으로 현재 스냅샷을 비교한 뒤 `failureRepairable=true`와 설명만 교정한다. 비용·운영/공개 상태·천장을 보존하며 감사 로그와 멱등 완료 기록을 함께 저장한다. 동시 CMS 변경은 거부한다. 원격 예행/적용 결과는 배포 후 별도 기록한다.

## 검수·배포 범위

- PC 1440×1000 및 모바일 390×844: 실제 격리 SQL API와 운영 클라이언트로 실패 → 기록 링크 → +10 복구, 복구 비용, 사용된 기록 재접근, CMS 2,000만 저장/재조회, 초안 OFF, 호환 설정 제어 **37개 확인 통과**. 페이지 오류와 가로 넘침 없음, 사운드 OFF.
