# 실제 펫 전투 및 자석 잠재력

사용자 요청: 보유 펫을 전투 화면에 구현하고 군단토벌 자동 흡수 잠재력을 추가한다. 잠재력은 물약 1개로 확률 도전하며 확률과 획득처는 사용자가 CMS에서 직접 설정한다.

## 사용 흐름

- PVE/PVP 덱의 펫 슬롯 또는 `/pets/`에서 실제 보유 펫 1마리를 장착한다. 기존 OWNER 검수 보유·장착 키와 분리한다.
- 실제 V3의 등록된 카드 SD를 유지하면서 펫을 별도 지원 레이어에 표시한다. 서버가 전투 시작에 CMS 대상·모드·버프를 한 번 적용한다. 펫은 타격 대상·행동 슬롯·승패 인원에 포함하지 않는다.
- 일반 PVE/PVP, 탑·폐차장·카우룸·공성·클랜전·세력전·듀오·협동전·호송·코어·리치왕에 서버 펫 스냅샷을 연결한다. 저장된 전투의 재입장은 원래 펫 설정을 유지하며 지속 전투 HP를 다시 회복시키지 않는다.
- 잠재력 물약(`PET_POTENTIAL_POTION`) 1개로 자석 잠재력에 도전한다. 성공·실패 모두 1개 소모, 성공 후 영구 유지, 이미 자석이면 추가 도전 차단. 기존 보유 모델에 맞춰 계정의 같은 펫 종류가 잠재력을 공유하며 화면에 명시한다.
- 장착한 자석 펫은 군단토벌 서버 드랍을 원정 가방으로 자동 수집한다. 실제 지급은 기존 클리어·패배·시간 종료·명시적 철수 정산에서 한 번만 처리한다. 중단 입장 복구는 가방을 지급하지 않으며 TEST는 계정 보상 미지급이다.

## CMS

- **펫·동료 준비 → 펫 잠재력**에서 도전 ON/OFF 및 성공확률을 설정한다. 0.0001% 단위, 0~100%이며 ON은 확률 지정 후 가능하다.
- 초기 정책은 `enabled:false`, `successPpm:null`이다. 배포로 수치·획득 풀·가중치·계정 물약을 채우지 않는다. 이후 사용자가 저장한 설정도 보존한다.
- 기존 통합 드랍 관리에서 **잠재력 물약**을 재료 아이템으로 선택해 획득처·가중치·수량을 지정한다. CMS 유저 인벤토리 지급에도 같은 아이템 코드를 연결한다.
- 기존 펫별 버프 설정과 획득 정책을 보존한다. 용병 2슬롯과 다른 콘텐츠의 미출시 플래그는 이번 펫 연결로 변경하지 않는다.

## 거래 및 표시

보유 펫·물약·CMS/잠재력 버전을 서버에서 검증한다. 잠재력 상태·차감·로그·요청 영수증을 기존 원자 트랜잭션 안에서 저장한다. 영수증은 별도 키로 보존하며 응답 유실·동시 클릭·재접속 때 같은 요청을 재확인한다. 같은 요청 번호로 대상이나 버전을 바꾸면 거부한다. 클라이언트는 서버 영수증과 전투 이벤트만 표시한다.

펫 미장착 계정은 장착 키 1회 조회 후 종료하고 장착 계정만 보유·잠재력·CMS를 추가 조회한다. 이번 변경은 기존 app_meta, 인벤토리와 트랜잭션 체계를 사용하며 인증 기반·스키마 마이그레이션·의존성은 변경하지 않는다.

## 배포 범위

기존 펫 준비 계약을 실제 장착·공통 전투 소비 경로에 연결하고 물약 거래와 군단 자동 수집을 추가한다. 전투/보상 경로의 직접 회귀와 실제 메인 로더 검사를 선택하며 무관한 전체 콘텐츠 검사를 반복하지 않는다. 공통 인증·DB 기반·의존성은 그대로다.

- 공식 명령: `npm run deploy:production -- --scoped`.
- 관련 펫/전투/군단/소유자별 전투 회귀, Worker 컴파일, 메인 로더, 출시 플래그·캐시·Hyperdrive 검사를 수행한다.
- 배포 결과와 운영 확인은 완료 후 별도 JSON에 기록한다.
