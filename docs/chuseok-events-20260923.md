# 추석 달빛 잔치 — 2026-09-23

## 확정 범위와 출시 상태

사용자 지시: 도끼 이벤트 및 낡은도끼 제거, 송편 고르기와 추석 떡값(봉투) 이벤트 신설. 경제 정책 질문에 대한 답변은 **“CMS에서 직접 설정하도록 준비, 실제 도전은 OFF”**다.

- 공개 페이지: `/events/chuseok/`, 봉투 바로가기 `?event=envelope`.
- 공통 로비의 보상 메뉴와 독립 페이지 내비게이션에 **추석 달빛 잔치**를 연결한다.
- 두 실제 도전은 각각 OFF. 비용·일일 횟수·기간은 null, 상품 배열은 빈 값으로 초기화한다.
- 미리보기는 빚기·고르기·개봉 연출만 재생하며 API 도전 요청, 재화 차감, 상품 지급을 하지 않는다. 화면에도 실제 상품이 아닌 연출 예시임을 명시한다.
- 추석 코인 자동 지급, 기존 도끼의 코인 전환, 다른 재화 가격 설정은 하지 않는다.
- 다른 콘텐츠의 운영 설정이나 출시 상태를 변경하지 않는다.

## CMS 사용법

관리자 **설정 → 추석 달빛 잔치**에서 송편·봉투를 따로 설정한다.

1. 시작·종료 일시(KST), 1회 추석 코인 소모량, 이벤트별 일일 횟수를 입력한다. 0회 제한은 무제한을 뜻한다.
2. 상품 행을 추가하고 일반 코인·아이템·장비·용병·꽝 중 종류를 선택한다. 카탈로그 상품은 운영자가 직접 선택한다.
3. 수량과 최종 확률을 입력한다. 확률은 소수점 4자리, 합계 정확히 100%여야 실제 도전을 ON으로 저장할 수 있다. 꽝도 직접 추가하며 꽝에 당첨되어도 참가 비용은 소모된다.
4. 준비 중에는 ON 체크를 끈 채 저장한다. 실제 ON 저장에는 별도 확인창이 뜬다. 이번 출시는 두 이벤트 모두 OFF로 유지한다.
5. **추석 코인 쿠폰 만들기** 또는 유저관리 아이템 지급에서 `CHUSEOK_COIN`을 직접 지급한다. 쿠폰 수량 상한은 100,000개, 유저관리 개별 지급 상한은 기존 9,999개다.

메뉴 공개 체크는 도전 ON/OFF와 별개다. 각 이벤트의 일일 횟수는 00:00 KST 기준이다. 색·위치 선택은 당첨 확률에 영향을 주지 않는다. 장비·용병은 1개/1장씩 지급하고 기존 용병 중복 장부를 그대로 사용한다. 차량의 중복 보상 정책은 임의로 만들지 않으므로 차량 자체는 신규 보상 종류에 포함하지 않는다.

## 연출·UI 구현

- 기존 로비·용병도감·장비강화 기준: 공통 내비게이션, 네이비/라임 색상, Noto Sans KR와 Barlow Condensed.
- 전용 원화는 `assets/ui/events/chuseok-v1/`. 내장 ImageGen으로 배경·송편·봉투·손동작 아틀라스를 생성했다. 실제 프롬프트는 같은 폴더의 `generation.json`에 기록했다. 달 무늬 추석 코인은 코드 기반 SVG이며 일반 보상 코인에는 기존 별 무늬 코인 아이콘을 재사용한다.
- `js/chuseok-fx-v1.src.js`를 `npm run build:chuseok`으로 빌드한다. 기존 `ui-fx-vendor-v2045.bundle.js`의 PixiJS 8.20.0 / GSAP 3.13.0을 재사용하고 별도 엔진을 로드하지 않는다.
- Pixi 투명 무대: 1000×700. 선택 소품 기준점은 (210,568), (500,568), (790,568).
- 송편 빚기는 서로 다른 손·반죽 형태의 8개 프레임을 0.48초 간격으로 보여준다. 반죽 → 누르기 → 오목하게 만들기 → 깨소 → 접기 → 여미기 → 다듬기 → 완성 후 세 접시가 놓인다. 총 준비 연출 약 5.4초.
- 송편 결과는 온전한 송편에서 깨소가 드러나는 별도 잘린 송편 프레임으로 바뀐다.
- 봉투는 세 색상이 펼쳐진 뒤 선택 봉투가 중앙으로 모이고, 접힌 상태에서 펼쳐진 봉투와 증서 프레임으로 바뀐다. 열린 봉투 아틀라스의 실제 상단은 y=410으로 보정했다.
- 결과 연출은 약 3초. 서버가 이미 확정한 결과만 표현한다. 건너뛰기, 탭 숨김, reduced-motion, WebGL 실패 시 단순 화면, 9초 안전 종료와 페이지 이탈 정리를 지원한다. 합성 알림음·전투 사운드는 추가하지 않았다.

## 지급·복구 안전성

`functions/_chuseok.js`의 PostgreSQL 트랜잭션 안에서 설정·카탈로그·사용자·추석 코인 보유량을 확인하고, 상품 지급·비용 차감·로그·영수증을 함께 확정한다. 일반 코인은 bigint로 처리한다.

- 이벤트 종류, 선택 번호, 사용자에 귀속된 requestId를 사용한다.
- 설정 revision과 실제 카탈로그를 포함한 quote가 바뀌면 결제하지 않고 갱신을 요구한다.
- 영수증 날짜는 트랜잭션 시작 시각이 아닌 완료 시각을 명시해 KST 자정 경계에서 일일 횟수와 기록 날짜를 일치시킨다.
- 중복 클릭·동시 요청·재접속은 저장된 결과를 반환하며 중복 차감·지급하지 않는다. OFF 전환 뒤에도 이미 완료된 요청은 복구할 수 있다.
- 지급 SQL이 0행이거나 로그·차감·영수증 저장이 실패하면 전부 롤백한다.
- API 도전은 로그인·활성 계정·동일 출처 요청을 검증한다. CMS는 기존 USER_MANAGE 권한과 변경 기록을 사용한다.
- 브라우저는 요청 직전 계정별 복구 키를 저장하고, 연출 중 재접속해도 **이전 도전 결과 확인**으로 같은 요청을 복구한다.

## 도끼 이벤트 종료와 데이터 정리

- 도끼 신규 도전과 CMS API는 `EVENT_RETIRED`로 영구 차단한다. 낡은도끼 쿠폰 신규 발급·재발급·사용과 관리자 직접 지급을 막는다.
- 과거 도전 영수증과 지급된 장비·용병·코인은 삭제하지 않는다. +13 강화권과 차량부품 150개 선택권도 계속 사용 가능하다.
- `/events/golden-axe/`와 소원램프의 과거 주소는 추석 페이지로 이동한다. 선택권 use 쿼리를 보존한다.
- 실행 모듈: `scripts/ops/chuseok-retirement-20260923.mjs`.
- 처리 마커: `ops:chuseok-retirement:20260923:v1`. 중복 실행은 기록만 반환한다.
- `preview`는 실제 정리와 같은 트랜잭션을 실행한 뒤 ROLLBACK한다. `apply`는 기존 설정·카탈로그·전체 보유량·쿠폰을 관리자 감사 로그에 백업하고, 낡은도끼만 회수한다. 양수 보유자는 음수 재고 로그를 남긴다. 기존 쿠폰은 soft-delete하고 카탈로그는 비활성화한다.
- 다른 지급 풀·제작법·미수령 메시지에서 낡은도끼를 참조하면 중단한다. 추석 도전이 이미 ON이면 역시 중단한다.
- 2026-09-23 16:28 KST 운영 dry-run: 낡은도끼 보유 행 201개(양수 16계정, 총 29개), 도끼 쿠폰 14개(활성 1개), 전 과정 검증 뒤 롤백. 개인별 백업은 저장소·공개 자산에 포함하지 않고 별도 운영 작업 폴더에 보관했다.
- 실제 정리는 새 코드 배포 후 `apply → verify`로 마무리한다. 최종 수량·감사 ID는 DB의 위 마커와 운영 작업 결과 파일이 기준이며 dry-run 수치로 실행 결과를 대신하지 않는다. 복구가 필요하면 감사 로그의 before_data를 검토해 별도 승인된 복구 작업을 수행한다. 자동 복구/도끼 재활성화는 하지 않는다.
