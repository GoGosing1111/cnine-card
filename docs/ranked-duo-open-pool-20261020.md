# 랭크 듀오 모집 폐지 · 랭크전 저장 덱 전체 매칭

사용자 최종 정정: `모집없이 언제나 가능하게 하라니까 랭크전 기반의 덱 다 모아서`.
시즌 5를 24시간 모집으로 연 기존 해석을 수정한다. 랜덤 비동기 2대2와 요청자만 점수·행동력·승리 보상을 반영하는 정책은 유지한다.

## 동작

- `RANDOM_ASYNC` + `entryMode:RANKED_POOL`. 별도 신청 없이 매칭 버튼으로 바로 출전한다.
- 랭크전 공격 프리셋과 방어 프리셋 1이 저장된 전체 ACTIVE 이용자를 조회한다. OWNER·제재 계정은 제외하며 동시 접속과 듀오 참가 기록을 요구하지 않는다. 기존 카드 5장·장착 용병 전투를 사용한다.
- 전체 후보를 임의 정렬하거나 모든 인벤토리를 읽지 않는다. 저장 덱 ID 집계 후 무작위 위치에서 순환 구간을 읽어 최대 23명을 추출하고, 요청자를 포함해 최대 12명씩 최신 프로필을 검증한다. 저장 덱 변경·보유권·계정 제한은 실제 출전 거래에서도 다시 검사한다.
- 첫 매칭에서 요청자의 개인 기록만 생성한다. 동료·상대는 캐시 버전 추적과 해당 경기의 다시보기 기록만 남으며 개인 참가·점수·행동력·보상은 변하지 않는다. 과거 모집 정원 제한을 상시 매칭에 적용하지 않는다.
- 7일마다 개인 순위를 정산한다. 다음 시즌은 즉시 ACTIVE이며 이전 시즌 정산과 분리한다. 스케줄러가 늦더라도 종료 후 첫 상태 조회·매칭이 같은 보호 거래로 다음 시즌을 연다. 동시 요청은 같은 시즌을 사용한다. 자동 운영 OFF일 때는 재개하지 않는다.
- 모집 버튼·마감·24시간 대기 안내를 유저 화면과 CMS에서 제거했다. 기존 랭크 듀오 전용 ImageGen 패널·버튼을 그대로 연결하고 문구와 상태만 수정했다. 신규 장식 이미지를 만들지 않았다.

## 검증

- 기존 듀오 회귀 101개 통과. 신규 상시 매칭·운영 전환 검사는 별도 파일로 관리한다.
- SQLite / PostgreSQL / PostgreSQL pipeline에서 무신청 출전, 다른 세 명의 기록·재화 보존, 재시도, 덱 변경, 제재·OWNER 제외, 동시 첫 매칭과 시즌 교체, 이전 시즌 보상 분리, OFF 유지와 모집 정원 제거를 검증한다.
- 실제 로컬 API·V3 런타임으로 1440px PC와 390px 터치 화면의 로비→매칭→전투→결과→개인 순위를 확인했다. 참가 API 없이 match/fight만 요청, 요청자 행동력 1 감소, 개인 순위 1명, JS/HTTP 오류 0건이다.
- 두 화면의 기존 전용 이미지 로딩·44px 이상 버튼·가로 넘침 없음과 모집 없는 CMS를 확인했다. 기술 검수이며 사용자 시각 승인으로 기록하지 않는다.
- 2026-10-20 14:25 KST 운영 DB 읽기 전용 조회에서 기본 저장 덱 조건에 맞는 후보 694명, 서로 다른 표본 23명을 확인했다. 실제 출전 가능 여부는 최신 보유권과 덱 검증 결과에 따른다.
- 기존 공통 DB·인증·거래 어댑터·전투 엔진을 변경하거나 새 스키마를 만들지 않는다. 관련 듀오 검수 후 scoped 배포하며 전체 게임 검사는 반복하지 않는다.

## 운영 전환

`scripts/ops/ranked-duo-open-pool-20261020.mjs`로 현재 시즌 5와 정책 revision 3, 미시작·모집 상태·전투 0건·ACTIVE OWNER를 확인한다. 기존 참가 행·일반 랭크전·경제 설정을 보존하고 정책 revision 4, 상시 매칭, 즉시 ACTIVE, 전환 시각부터 7일 일정으로 변경한다.

정책·시즌·감사·일회 영수증은 같은 거래다. 예행은 끝까지 실행 후 롤백하며 적용 후 같은 키로 재실행하면 쓰기 없이 영수증만 반환한다. 운영 계정의 참가·전투·재화 지급을 검수로 실행하지 않는다. 배포와 실제 적용 결과는 `docs/qa/ranked-duo-open-pool-20261020/`에 기록한다.
