# 프라임 장착 PVE 진입 지연 수정

사용자가 프라임만 보이고 `V3 WebGL 전장 구성 중`에서 진행하지 않는 화면을 제보했다.

## 원인과 수정

프라임 초기화가 승인된 12개 PNG 시트(약 23 MB)의 다운로드/디코드를 모두 기다렸다. 실제 운영 정적 파일을 처음 받는 브라우저 검사에서 공통 전장 초기화 제한 14초를 넘기고 재시도도 시간 초과로 끝나는 현상을 재현했다. 로컬 파일을 즉시 읽는 기존 검사는 이 조건을 포함하지 않았다.

- 본체와 전장을 먼저 초기화하고 프라임 효과는 백그라운드에서 준비한다. 공통 전장과 연속 사냥의 용병 생성 경로에 동일하게 적용한다.
- 준비 중/로드 실패 시 기본 공격은 기존 V3 공격 경로를 사용한다. 광역기는 서버 HP·보호막·피해 표시를 고유 대상마다 한 번 반영한다. 이미지 대기로 전투/피해를 누락하지 않는다.
- 다운로드가 끝날 때 진행 중인 기본 공격과 복귀 동작을 기다려 본체를 교체한다. 이전 전장이 끝났으면 해당 텍스처 뷰를 정리한다.
- 승인된 2배속 광역기 중 최장 2.475초짜리 연출이 일반 이벤트 2초 제한으로 중단되지 않도록 다른 장시간 용병 광역기와 같은 9초 상한을 적용한다. 실제 모션 속도/길이는 바꾸지 않는다.
- 런타임·로비·서비스 워커 캐시를 `prime-requiem-20261021-v2`로 갱신한다.

밸런스·획득 잠금·승인 이미지·지급·계정 DB는 변경하지 않았다.

## 검증

`tests/prime-requiem-pve-entry-20261021.test.mjs` 4개와 기존 `tests/pve-battlefield-entry-v2117.test.mjs` 9개 통과.

`tests/prime-requiem-pve-entry-20261021.browser.mjs`는 실제 서버 `createPveBattleV2` 결과와 공통 운영 번들을 사용한다. PC/모바일 각각 백호 시트 요청을 의도적으로 계속 보류해도 첫 입장·배치·기본 공격·광역 피해가 완료됨을 확인했다. 요청을 풀면 승인 네온/적월 효과가 붙는다. 다음 전투에서는 실제 라이브 래퍼를 통해 적월 무간참이 약 2.47초 동안 끝까지 재생되고 HP가 한 번만 반영됐다. 이전 FX 폐기, 대기 복귀와 페이지 예외 0건도 확인했다. 결과/화면은 `docs/qa/prime-requiem-pve-entry-20261021/`이다.

앞선 출시 문서의 “단일 보스” 검사는 다수 적 사냥 데이터의 타격 대상만 하나로 제한한 경우였다. 이번 검사는 일반 PVE의 한 몬스터와 비활성 적 슬롯, 첫 로딩·재입장 경로를 별도로 검증한다.
