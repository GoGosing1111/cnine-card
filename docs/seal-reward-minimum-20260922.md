# 봉인전 보상 최소 공격 횟수 · 2026-09-22

## 승인과 적용 범위

- 사용자 확정: 완료·공헌도 순위 보상의 최소 공격 횟수 **25회 이상**.
- 파괴·수호·정화의 서버 처리 완료된 전투를 회차별로 합산한다. 승패와 무관하며 일일 횟수·충전 횟수와 구분한다. 실패한 요청·재전송은 추가 집계하지 않는다.
- 전투 1회 참여 보상, 전투력, 충전 시간, 순위 산정 순서와 기존 지급액은 변경하지 않는다.
- 클리어 100억(10,000,000,000) 설정·저장·지급이 이미 지원된다. 종전 코인 무제한 정책을 다시 축소하지 않는다. 운영 설정의 현재 20억을 100억으로 자동 변경하지 않는다.
- 운영 점검 시 최신 #45 회차는 CLEARED이고 활성 회차가 없었다. 종료된 회차의 1회 기준과 기지급 보상은 유지하며 다음 시작 회차에 25회를 고정한다.

## 구현

- CMS `minRewardAttempts` 기본값 25. 1~1,000,000 정수 입력·검증·저장·재조회. 구형 CMS가 이 필드를 생략해도 기존 설정을 보존한다.
- 회차 `min_reward_attempts` 스냅샷. 기본 설정 저장으로 기존 회차 조건/금액을 소급 변경하지 않는다.
- 과거 회차의 새 컬럼 기본값은 기존 정책인 1이다. 독립 `seal_reward_attempts_schema_20260922_v1` 게이트로 구형 초기화 마커 유무에 관계없이 추가한다. PostgreSQL은 prepare()의 DDL 무시 경로 대신 execSchema()를 사용한다.
- 현재/지난 회차 안내, 직접 eventId 청구, 완료·순위 보상을 모두 동일한 `total_attempts >= min_reward_attempts` 조건으로 검증한다.
- 미달 시 403 / `SEAL_REWARD_MIN_ATTEMPTS`. 화면에는 현재 횟수·필요 횟수·부족 횟수를 표시한다.
- 새 쿼리에는 기존 회차/유저 PK 조인과 숫자 비교만 추가한다. 전투 로그 전체 재조회나 새 폴링은 없다.

## 운영 설정 작업

- 연결 대상을 cnine DB / cnine_migrator / 기존 운영 endpoint로 검증한다.
- 기존 설정과 활성 회차만 `seal_reward_minimum25_backup_20260922`에 보존한 뒤, 설정의 minRewardAttempts만 25로 지정한다. 활성 회차가 있다면 최소 횟수만 변경하며 완료·실패 회차는 제외한다.
- `seal_reward_minimum25_applied_20260922` 작업 마커로 재실행 중복을 차단한다. 다른 설정·잔액·보상 이력은 변경하지 않는다.
- 되돌릴 때는 백업의 최소 횟수만 복원한다. 이후 운영자가 변경한 다른 필드를 전체 백업으로 덮어쓰지 않는다.

## 검증

- `npm run test:seal`: 0·24·25·26회, 고공헌도 우회 차단, 승패·세 역할 누적, 재전송, 직접 청구·이전 회차 보상, 실패 회차 정책, CMS 권한/경계값/구형 저장, 레거시 초기화, 중복 지급·롤백.
- PGlite PostgreSQL + 실제 D1 호환 어댑터로 신규 컬럼 초기화와 25회 100억 지갑·로그 지급 및 중복 차단 검증.
- 실제 봉인전/CMS 렌더링 모듈과 스타일, 모의 API로 1440px·390px 저장·재조회·24/25/26회 버튼·줄바꿈·가로 넘침 검수. 운영 계정 전투·재화는 사용하지 않는다.
- 전체 release:gate 통과 후 지정 deploy:production 배포, 운영 정적 자산 일치와 읽기 전용 DB 결과를 재확인한다.
