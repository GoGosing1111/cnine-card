# 시즌패스 패키지 · 구매 접수 팝업

사용자 지정: 서버 안내에 기존 서버 운영 후원 버튼과 같은 크기의 **패키지 구매** 버튼. **시즌패스 활성화 유저만 표시**. 금액 **49,800원**, 구성 **50조 코인 + 엠퍼러 에너지 200개 + SSS 리미티드 조각 5개**. 추가 요청: 구매 신청 접수 시 핑크빛유두에게 게임/CMS **팝업** 알림.

## 이용과 운영

- 표시·신청 조건은 기존 페이지 자격(활성 계정, 가입 72시간 경과, 2차 인증), 유효한 후원 기간, 시즌패스 CMS ON을 모두 충족하는 것이다. OWNER 미리보기로 구매할 수 없다. 신청 API에서 조건을 다시 검증한다.
- 구매 버튼과 후원 버튼은 PC 680×132px, 모바일 328×112px 검수 환경에서 동일하다. 기존 서버 안내 배치와 계열을 유지한다. 신규 조각은 built-in ImageGen으로 제작하고 동일 후원/시즌패스 콘텐츠의 승인 이미지 프레임·배경·버튼을 사용한다.
- 구매 신청 시 고정 구성의 PENDING 주문과 5분짜리 비공개 계좌 안내 메시지, 핑크빛유두(ID 1) 접수 메시지를 같은 거래로 저장한다. 기존 후원과 같은 입금처를 사용하며 자동 결제/차감/지급하지 않는다.
- 계정별 미처리 신청은 하나를 유지한다. 계좌 안내 재발급은 같은 주문이며 구매 수량이나 접수 알림을 늘리지 않는다. 처리 후 새 구매 신청이 가능하다. 별도 구매 횟수 제한을 임의 추가하지 않았다.
- 핑크빛유두 게임·CMS에서 접수 팝업을 표시한다. 접속 중 화면이 보일 때 20초 간격으로 확인하고, 다음 접속에서도 미확인 접수를 표시한다. 다른 유저는 조회하지 않는다. 팝업은 신청자·ID·금액·구성·시각·신청 번호 및 CMS 이동 버튼을 제공한다. 같은 브라우저에서 확인한 팝업은 다시 표시하지 않으며 대기 건수와 접수 목록은 계속 유지한다.
- OWNER CMS → 후원 관리 → 패키지 구매 접수에서 신청자를 선택하고, 실제 49,800원 입금 확인 체크와 확인 메모를 입력한 뒤 **입금 확인 · 패키지 지급**을 누른다. 반려도 메모를 남긴다. ID 1 OWNER만 처리한다.
- 기존 주문이 정상 접수된 후 시즌패스가 만료되어도, 그 주문의 실제 입금 확인·지급 처리는 가능하다. 신규 신청은 불가하다. 시즌패스 기간은 연장하지 않는다.
- 코인·두 재료·각 지급 로그·주문 상태·접수 포인터·감사·영수증을 하나의 DB 거래로 저장한다. 기존 사용자 잠금과 CAS를 사용하며 요청 재시도/동시 확인은 한 번만 지급한다. 잔액/재료 안전 정수 한도·활성 아이템·계정 상태를 검사한다.

## 새 재료와 원본

- `MERCENARY_SSS_LIMITED_SHARD` / **SSS 리미티드 조각** / MATERIAL / SSS.
- 기존 `MERCENARY_SSS_CARD_SHARD`(일반 SSS 용병 카드 조각)를 교체하지 않는다. 보관용으로 등록하며 교환 수량·제작식·드롭·합성 풀을 임의 추가하지 않는다.
- 원본 PNG, 512px 알파 WebP, 생성 도구·전체 프롬프트·SHA-256: `assets/items/sss-limited-shard-20261020/manifest.json`. 원본 바이트를 보존한다.
- 인벤토리 진입/패키지 정보/CMS의 카탈로그 초기화로 등록한다. 별도 운영 등록은 `scripts/ops/support-package-catalog-20261020.mjs register`이며 재료 마스터와 초기화 마커만 쓴다. 보유 수량 지급은 없다.

## 검증과 배포

- 신규 기능 6개 테스트: SQLite/PostgreSQL 구매 자격·고정 구성·입금 확인·동시 처리·재시도·원자적 롤백·잔액 한도·메시지 만료·타 계정 주문 비공개·일반 조각 보존·ID 1 알림 권한.
- 기존 후원 17개, 계좌 신청/만료 10개 회귀 검사 통과. 메시지 테스트 fixture에 이미 운영 중인 시라누이 후원 보상 초기화와 브랜드 표시 의존성을 맞췄다. 그 운영 로직은 변경하지 않았다.
- 실제 모듈+격리 PostgreSQL API를 사용하는 PC 1440×1000, 모바일 390×844 UI 검수 통과: 버튼 크기, 비활성 숨김, 이미지 로딩, 응답 유실 재시도, 게임 팝업 1회 표시, CMS 팝업→지급, JS 오류·가로 넘침 없음. 증거 `docs/qa/support-package-20261020/`.
- 기능/시각 기술 검사는 사용자 시각 승인으로 기록하지 않는다. 실제 사용자 구매/입금/보상 지급을 테스트하지 않는다.
- 운영 배포와 카탈로그 등록은 완료 후 아래 기록을 추가한다.
