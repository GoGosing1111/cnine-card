## 화면과 조작

- 카드 상점의 기존 프라임 아머리 아래에 전용 상자와 네 코어의 실제 설정 확률을 표시한다.
- 1 / 10 / 100 / 1,000개 구매 및 직접 수량 입력을 제공한다. 비용은 억·조 단위, 잔액으로 살 수 있는 최대 수량도 표시한다.
- 상점·인벤토리에서 보유분 전체까지 선택해 일괄 개봉한다. 서버는 최대 500개 단위로 기존 원자 영수증을 발급하고 클라이언트는 전체 결과를 합쳐 한 번만 보여준다.
- 프라임의 밀기 조작을 재사용하되 정적인 상자·청색 링과 약 0.33초 페이드만 사용한다. 화면 흔들림·플래시·대형 입자·희귀 개별 컷인·추가 사운드는 없다. `바로 결과 보기`, Escape, 동작 줄이기를 지원한다.
- 결과창에서 같은 수량을 다시 개봉한다. 남은 수량이 적으면 그 수량으로 줄인다. 미완료 밀기는 복귀하고 다시 밀 때 이전 복귀 트윈을 정리한다.
- 구매 완료 토스트가 개봉 화면의 결과 버튼을 덮지 않도록 개봉 시작 시 정리한다.
- 전용 PNG는 ImageGen으로 신규 제작했다. `assets/ui/packs/suit-core-supply-box-20261008.json`에 도구·최종 프롬프트·규격·원본 해시를 기록하고 생성 원본 바이트를 보존한다.

## 서버·CMS

- `suit-core-box/config`, `purchase`, `open`을 기존 프라임 처리기에 추가한다. 기존 영수증 테이블의 `item_code`와 추가 풀의 `product_kind=suit_core`로 구분한다. 스키마 변경은 없다.
- 신규 설정이 없으면 구매·개봉 OFF다. 유효한 코어 네 종류와 합계 100%를 확인한 뒤에만 구매·개봉 가능하다. 코어 하나가 비활성화되면 남은 등급으로 몰아주지 않고 중단한다.
- 코인 차감·상자 지급·상자 소모·코어 지급·로그·영수증은 기존 트랜잭션 안에서 처리한다. 차감/지급 SQL이 0행이면 롤백하며 동일 요청을 재시도해도 중복 지급하지 않는다.
- 정수/안전 정수 금액 범위를 확인한다. 개당 10억 기준 요청당 최대 구매 수량은 9,007,199개이며 실제 잔액이 우선한다. 클라이언트의 개봉 재시도는 같은 요청 ID를 유지한다.
- OWNER 프라임 CMS에 전용 탭을 제공한다. 네 코어 확률과 구매·개봉 스위치를 편집하고, 다른 보상 추가·코어 삭제·과한 특별 연출은 허용하지 않는다.
