# 카우방 포탈 발견과 입장

2026-09-13 사용자 지시: PVE 소탕·토벌 완료 시 아포칼립스 3%, 일반 PVE 2% 확률로 “미지의 젖소방 포탈이 열렸습니다. 입장하시겠습니까?” 안내 후 입장한다.

## 확정한 발견 방식

- 일반 PVE 토벌·소탕은 2%, 아포칼립스 토벌은 3%다. 난이도는 서버가 조회한 몬스터 설정으로 구분한다. 아포칼립스가 아닌 일반·보스·나이트메어는 2%를 사용한다.
- 사용자가 승리 조건을 별도로 지정하지 않았으므로 실제 처리 완료한 전투를 기준으로 승리·패배 모두 1회 판정한다. 실패한 요청, 미처리 소탕 횟수, PVP·레이드·탑·카우방 전투에는 판정하지 않는다.
- 소탕은 첫 연출 전투 1회와 후속 묶음 안의 각 처리 전투를 각각 판정한다. 소탕 요청 하나당 한 번으로 축소하지 않는다. 아포칼립스 소탕 금지 규칙은 그대로 유지한다.
- 서버 난수는 0~999,999의 균등 정수이며 20,000 미만/30,000 미만이 당첨이다. 사용자 ID·실행 종류·실행 참조가 같은 요청은 저장된 결과를 사용한다. 미당첨도 저장해 재요청으로 다시 추첨할 수 없다.

## 사용자 흐름

1. 토벌 전투 연출 또는 전체 소탕 결과가 완료되면 발견 팝업을 연다. 여러 포탈이 생기면 모두 계정에 보관하고 하나의 팝업으로 안내한다.
2. **입장하기**는 카우방 계정 화면으로 이동한 뒤 공통 V3 전투를 시작한다. 서버가 보관 포탈을 오래된 순서로 1개 사용한다. 브라우저가 입장 허가·포탈 개수·확률·승패를 제출하지 않는다.
3. **나중에** 또는 Esc는 포탈을 보관한다. 계정에 보관한 포탈이 있으면 PVE의 `카우방 · 포탈 N개`에서 다시 열 수 있고 새로 접속해도 확인한다. 임의 만료 시간은 추가하지 않았다.
4. 포탈 없는 직접 URL/API 입장은 거절한다. 입장 비용·일일 예산·전투 체크포인트와 포탈 사용은 같은 트랜잭션으로 저장한다. 입장 실패 시 모두 롤백하고, 정산 재시도·결과 복구에서는 추가 포탈을 사용하지 않는다.
5. 카우방의 반복 입장 선택은 숨겼다. 팝업에서 입장하기 한 번은 포탈 한 개의 전투만 시작한다.

포탈 지시 당시에는 기존 카우방 경제 초안을 보존했다. 2026-09-13 후속 지시로 클리어 보상 5억 코인·일일 보상 상한 30억 코인·일일 입장 6회, CMS 보상 입력 한도 100억이 확정됐다. 최신 수치는 [카우방 보상·입장 횟수 확정](cow-room-economy-approved-20260913.md)을 따른다. 입장 코인 등 나머지 정책을 자동 승인하지 않는다. CMS에는 포탈 2%·3%와 개별 전투 판정 기준을 고정 안내한다.

## 구현과 검증

- `functions/_cow_room_portal.js`: 서버 추첨·포탈 저장·조회. `cow_room_portal_rolls_v1` 및 인덱스는 명시적 공동 출시 스키마 준비에 포함한다. HTTP 요청에서 테이블을 임의 생성하지 않는다.
- `functions/api/[[path]].js`: 직접 토벌과 소탕의 서버 확정 결과에 발견 포탈을 연결한다.
- `functions/_expedition_v3_runs.js`: 포탈 1개 사용과 기존 계정 원정 입장을 원자적으로 묶는다.
- `js/cow-room-portal.mjs`, `css/cow-room-portal.css`: 실제 팝업. 기존 목초지 배경을 사용하며 전투 렌더러·진형·카드 프레임은 수정하지 않는다.
- `preview/cow-portal-v1/`: 동일 팝업·동일 계정 입장 경로의 로컬 검수 화면. 강제 당첨 재현은 localhost QA 서버만 제공한다.
- `tests/cow-room-portal-v1.test.mjs`와 기존 PVE 소탕·계정 원정 회귀 **38개 통과**. SQLite·PostgreSQL 확률 경계, 중복 추첨, 계정 격리, 동시 요청, 입장 롤백, 정산 복구를 확인했다.
- `scripts/qa-cow-portal-v1.mjs`: 1440·390·320px에서 팝업 문구·잘림·가로 넘침·나중에·Esc·새로고침·실제 V3 입장·CMS를 확인했다. 브라우저 오류/실패 요청 0건. 애니메이션 종료 상태의 PC·모바일 캡처를 직접 검수했다.
- 앱/전투 어댑터 캐시에는 `cowPortal=20260913`을 추가했다. 기존 서비스워커의 기본 출시 태그는 유지하고, 검증기는 v 파라미터 값과 서비스워커 태그를 비교한다. 깨끗한 작업 트리·origin/main 일치 등 배포 조건은 그대로 유지한다.
- 전체 후보의 출시 회귀 명령 45개·테스트 1,400개 통과. 최초 실행에서 추가 쿼리 파라미터를 버전 값으로 읽던 기존 Black Miracle 검사를 수정하고, 해당 검사부터 나머지 명령을 이어 검증했다. 최종 운영 배포 게이트 통과로 보고하지 않으며, 공동 출시 시 깨끗한 main 후보에서 전체 게이트를 다시 실행한다.

## 출시 상태

`V3_JOINT_RELEASE_ENABLED=false`를 유지한다. 공개 경로는 DB 접근 전에 발견/입장을 차단하며, 로컬 계정 검수만 준비용 핸들러를 사용한다. V3·용병·장비 강화 공동 출시 전에는 카우방을 단독 활성화하거나 운영 DB에 포탈을 지급하지 않는다.
