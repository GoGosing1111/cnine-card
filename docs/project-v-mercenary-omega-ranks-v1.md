# 오메가 전용 스킬과 용병 등급 · 2026-09-11

사용자 지시: “오메가 최상위용병카드인데 스킬 별도로 있어야할거같은데 등급은 C,B,A,S,SS,SSS 이렇게 가야할듯”.

등급은 **C → B → A → S → SS → SSS**, 오메가-X(V-021)는 **SSS**로 배정한다. 나머지 42명의 등급은 미정이다. 준비 로스터 v11과 읽기 전용 도감에 표시하며 원화·SD는 변경하지 않는다. 승인 근거와 변경 전 카드 데이터 해시는 `assets/ui/project-v/mercenaries/mercenary-rank-approval-20260911.json`에 보존한다.

## 전용기 초안: 종언의 사건지평선 · MS-021

오메가의 성좌·중력·대검을 두 단계 검격으로 구성한다. 오메가에게만 배정하며, 다른 용병이나 스킬칩으로 이전하지 않는다. SSS라는 이유로 다른 모든 역할을 겸하거나 무조건 승리하지 않는다.

1. 살아 있는 적 전열 최대 2명을 고정한다. 전열 부재 시 기존 전열 우선 규칙으로 단일 표적을 고른다.
2. 첫 검격이 맞은 생존 표적에 해제 가능한 성좌 균열 1개를 새긴다.
3. 두 번째 검격에서 남은 균열만 한 번 폭발시키고 소모한다. 첫 타격과 마지막 타격 각각의 전체 예산을 최초 표적 수로 나눈다. 표적이 죽거나 정화되면 해당 몫은 사라지며 다른 대상에게 넘기지 않는다.
4. 사용 뒤에는 성공·실패와 무관하게 과부하가 남아 다음 기본 공격 준비가 지연된다. 추가타·반격은 재귀 발동이나 처치 초기화를 만들지 않는다.

대응 수단은 두 검격 사이의 정화·오메가 제압·보호막이다. 보스는 동일한 단일 대상 예산을 사용하며, 최대 HP 비례·즉사·강제 이동·방어 무시·대체 스턴을 주지 않는다. 실제 서버에서 명중·표적 상실·시전자 제압/사망·상태 면역·과부하 소비·쿨다운을 확정해야 한다. 현재 오프라인 검수는 정상·첫 표적 정화·단일 보스의 대표 세 상황을 실행하며 서버 구현을 대체하지 않는다.

100 HP 검수에서는 첫 타격 총량 18, 마지막 타격 총량 48을 사용한다. 이 값은 동작 비교용이며 운영 피해 계수·비용·쿨다운·과부하 지연량은 확정하지 않는다. 기술 이름과 메커니즘은 사용자 검수 대기다.

## 연속 스프라이트와 재생

- 검수: `/preview/project-v-mercenary-system-v1/skills?skill=MS-021`
- 내장 ImageGen으로 오메가 전용 금빛·보라색 중력 균열 시트 한 종을 개별 제작했다. 최초 인력 실 → 금빛 균열 → 압축된 핵 → 대검 절단 → 파열 → 소멸이 실제 16프레임에서 변한다. 기존 이펙트 색만 바꾼 자산이 아니다.
- 원본 `skill-assets-v2/source/omega-event-horizon-sequence-v2.png`는 무가공 보존한다. 원본은 1254×1254 RGBA이며 4×4 셀을 그대로 분리하고 최대 1px 투명 여백만 추가한 314px 프레임 16개와 1256×1256 무손실 WebP를 만든다. 셀 경계 알파 5 이하, 개별 프레임 해시·프롬프트는 매니페스트에 기록한다.
- PixiJS 8.20.0, GSAP 3.13.0. 기존 `source/MercenarySkillFX.js`·`source/RenderAuthoredSkill.js`·`source/MercenarySpriteSequence.js`와 V3 `effectLayer`·`combatLayer`를 사용한다.
- 기준 시각은 한 GSAP 시계의 초 단위다. **1.05초의 05번 프레임**이 첫 접촉, **2.25초의 09번 프레임**이 종언 접촉이다. 총 4.2초. 첫 타격으로 소멸하거나 정화된 표적에는 마지막 파열이 재생되지 않는다.
- 기준점은 승인 SD의 발 원점에서 캐릭터 높이·스케일을 반영한 몸통이다. 승인 대기 SD를 변경하지 않으며 관절별 대검 공격 포즈를 새로 제작한 것으로 보고하지 않는다. 배틀슈트 승인 flash/smoke/dust/cinder는 보조 계층으로만 사용한다. 사운드는 무음 검수다.
- 최종 시각 승인은 사용자 검수 대기다. 검수 결과는 `preview/project-v-mercenary-system-v1/OMEGA-REVIEW.md`에 남긴다.

## CMS 등급 초안

`positions.html`에서 6단계 등급 또는 미정을 선택하고 역할·위치와 함께 검토한다. 공식 SSS인 오메가는 등급 편집이 잠긴다. 저장은 브라우저에만 적용하며 도감 로스터나 운영 DB를 갱신하지 않는다. JSON 검증도 허용 등급·사용자 확정 등급·코드별 누락/중복·수정 충돌·OFF 상태를 확인한다.

포지션 형식은 `PROJECT_V_MERCENARY_POSITION_DRAFT_V2 / schemaVersion=2 / rosterVersion=11`이다. 기존 저장 키는 유지한다. 정확히 알려진 V1/로스터10 → V2/로스터11 변환만 허용하고 과거의 역할·메모·수정 번호를 보존하면서 등급 필드만 추가한다. 다른 오래된 버전이나 임의 필드는 자동 수리하지 않는다.

스킬 초안은 같은 저장 키·형식을 사용하되 `version=2 / rosterVersion=11`이다. 정상인 이전 16종 저장본의 이름·의견·검토 표시·수정 번호를 보존하며 MS-021만 검토 대기로 추가한다. 운영 CMS 연결 시에는 서버 권한·수정 번호·감사 기록·복구 계약이 별도로 필요하다.

이번 반영은 등급 표시와 독립 검수 화면까지다. 일반 덱 5장 + 별도 용병 1장 계약을 유지하며, 용병 획득·편성 저장·실제 전투는 활성화하지 않는다.
