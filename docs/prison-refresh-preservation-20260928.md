# 수용소·눈치게임 반복 화면 초기화 수정

## 원인과 범위

- 사용자 제보: 수용소 눈치게임 이용 중 새로고침처럼 화면이 반복 갱신되어 조작을 방해함.
- 기존 배경 조회(버닝 상태, 족장 상태 등)는 수감 중 서버에서 `423 USER_INCARCERATED`를 받는다. 공통 API 처리기가 매번 `renderLockedPrison()`을 호출하고, 이 함수가 동일한 수감 상태에도 전체 `app.innerHTML`을 교체했다. 수용소 타이머·눈치게임·포커스·채팅 초안이 초기화되고 다시 상태를 요청하는 경로를 실제 클라이언트 함수로 재현했다. 브라우저 문서 자체의 `location.reload()`가 아니라 화면 전체 재생성이 확인된 원인이다.
- 수용소 자체 상태 조회도 동일한 명부·안내·석방 버튼을 1.5초/5초 주기마다 다시 만들었다.

## 수정

- 계정, 시설, 수감 시작·종료 시각이 같은 잠금 화면은 유지한다. ISO/SQL UTC 시각 표현 차이는 같은 시각으로 비교한다.
- 다른 시설로 이동, 사망 제한 시작, 형기 변경, 석방은 기존 서버 상태에 따라 전환한다.
- 수용소 안내·명부·석방 버튼은 출력 내용이 달라질 때만 교체한다. 기존 채팅 메시지 변경 감지와 운영자 강제 참가 규칙은 유지한다.
- 운영 `index.html`의 두 변경 스크립트 캐시 쿼리를 갱신한다. 서버·제재·계정·재화·DB·게임 규칙은 변경하지 않는다.

## 관련 검수와 배포 선택

- 직전 운영 소스: `936e3b5b802f453f655b3ee28ef84846ade05f85`, Pages `aa9bc5e5-015a-407f-85ad-31ff6626d497` (Wrangler production 목록 확인).
- 그 이후 원격 변경은 운영 작업/검수 기록이며 다른 게임 실행 변경은 없음. 국소 프런트엔드 수정으로 scoped 배포한다.
- 선택: `tests/prison-refresh-preservation-20260928.test.mjs`, `tests/prison-death-game-assignment-20260924.test.mjs`. 배포에 포함된 검사만 최종 실행하며 전체 게이트를 반복하지 않는다.
- 새 브라우저 회귀는 실제 `apiRequest`, 잠금 렌더러, 수용소 및 눈치게임 스크립트를 사용하고 응답만 로컬 fixture로 대체한다. 운영 계정/API/제재는 사용하지 않는다. 검수 사운드는 시작 전 OFF.
- 수정 전 PC·모바일에서 반복 423으로 채팅 초안 소실, 포커스 이탈, 게임 노드 교체, 후속 입력 누락을 재현했다. 수정 후 초안·포커스·명부·게임 노드와 연속 입력 유지 확인. 같은 시각의 사망 상태 재수신, 형기 변경, 사망 제한 종료 후 수용소 복귀·석방도 확인했다.
- PC 1440×1000, 모바일 390×844. 실제 마우스/터치 입력과 화면 확인 자료: `C:/Users/User/.codex/tmp/prison-refresh-20260928/`.
