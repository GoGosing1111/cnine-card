## 후속 V3 — 긴 진입로와 전장 화면 확장

사용자 `조금 더 길목하고 화면 활용도를 높여봐 너무 짧아`를 반영했다.

- 논리 전장을 1920×1080에서 **2880×1280**으로 확장했다. 적 진입점부터 수호석까지의 수평 거리는 1,610에서 2,560으로 약 **1.59배** 늘었고, 분대 배치·2/3개 방어선 간격·위험 표식·자동 대원의 지원 기준·축소 지도도 새 좌표에 맞췄다. 접근 시간도 실제로 늘어나는 검수 지형 변경이다. 피해·공격 주기·이동 명령 대기·부활 규칙은 유지했다.
- 생성된 길목 PNG의 석재 비율을 유지해 반복 배치하고, 원본 중앙 석재의 텍스처 영역으로 불규칙한 연결 틈을 덮었다. 원본 PNG·프롬프트·수호석을 변경하거나 재생성하지 않았다.
- 전체 보기는 실제 방어선 범위에 맞춰 카메라를 잡는다. PC의 하단 유닛과 전술 조작을 같은 줄에 놓고 상단 상태 영역도 낮췄다. 1920×1080 실측에서 전장 높이 **707.4→851.2px**, 하단 조작부 **223.6→114.8px**다.
- 모바일은 조작부를 압축하고 충분히 긴 세로 전장에서 길목을 대각선으로 표시한다. 캐릭터·이름·피해 숫자는 똑바로 표시한다. 작은 세로 화면과 가로 화면은 공간에 맞는 수평 구도를 사용한다.
- 확대 화면에서 전장을 드래그하거나 좌우 버튼/방향키로 살펴볼 수 있다. `분대 위치`와 Home 키로 돌아오며 카메라는 전장 범위 안에 제한된다. 축소 지도에 현재 보고 있는 구간을 표시한다. 전멸 패널을 가리지 않도록 전멸 중에는 하단 카메라 버튼을 숨긴다.

관련 모델·방·HTTP 회귀 **13개 통과**. PC 1920×1080의 3인 전장, 1366×768의 2인 전장과 모바일 에뮬레이션 390×844·320×568·844×390을 직접 확인했다. 390px 전장에서 실제 포인터 드래그로 카메라 중심이 1340→2066으로 이동하고 `분대 위치`로 1340에 복귀했다. 방향키 이동·Home 복귀, 화면 회전 후 원래 캐릭터 방향과 전체 보기 복구, 가로 넘침 없음, 콘솔 오류·경고 없음도 확인했다. 검수 서버를 새 좌표 모델로 재시작했다.

상태는 계속 REVIEW_ONLY다. 이 절의 전장 크기·배치가 아래 최초 V1 기록보다 우선한다. 지정 운영 배포 스크립트가 없는 상태는 동일하다.

## 후속 V2 — 생성 원화와 누적 전멸 대기

사용자 `길목하고 수호석 CSS효과 말고 이미지 생성스킬로 꾸며`와 `전멸할 때마다 부활 대기시간 증가`를 반영했다.

- 내장 **image_gen** 도구로 투명 길목과 수호석 PNG 2종을 생성하고 원본 바이트 그대로 `preview/coop-defense-v1/assets/`에 보관했다. 회색 성채 석재·청록 룬 길목, 금속 장식과 원형 받침대가 있는 수정 수호석이다.
- 전장의 선·화살표·원형 표식·다면체 수호석을 제거하고 생성 이미지 Sprite로 교체했다. 합류로는 같은 길목 이미지를 사용하며, 축소 지도의 수호석도 같은 이미지다. 원본 배경·용병·카드·몬스터 자산은 유지했다.
- 생성 방식·원본 경로·SHA-256·투명도·크기는 `assets/manifest-v2.json`, 최종 프롬프트 전문은 `assets/prompts-v2.json`에 기록했다. 빌드 색인에는 기존 19개와 신규 2개, 총 21개 자산을 포함한다.
- 전멸 판정은 **소유한 3기 전부 전투불능**인 분대별로 한다. 첫 전멸 15초, 두 번째 30초, 세 번째 45초, 이후 60초다. 복귀는 담당 방어선에서 최대 체력의 50%로 하며, 수치는 검수용이다.
- 대기·횟수·부활·체력은 서버가 판정한다. 같은 전멸을 매 틱 다시 세지 않으며, 다음 웨이브 정비 회복과 강화·이동·전술·재접속으로 대기를 우회할 수 없다. 전멸 상태의 자동 대원도 동일하게 처리한다. 기존 스킬/이동 쿨다운은 유지한다.
- 전원이 전멸해도 적과 수호석 판정은 계속된다. 수호석 파괴나 최종 승리 시 예약 부활을 중단한다. 일부 유닛만 쓰러진 경우의 다음 정비 복귀는 유지한다.
- 전선 탭, 내 3기, 전술 버튼, 전장 패널에 남은 시간을 표시한다. 패널에는 이번 전멸 차수·대기시간·복귀 체력·다음 전멸 대기를 함께 표시하고 결과 화면에도 전멸 횟수를 기록한다.

관련 검사 **13개 통과**: 기존 10개에 누적 전멸/상한/중복 방지/50% 복귀/스킬 쿨다운 유지, 정비·강화 우회 차단, 재접속 유지 및 전원 전멸 후 거점 패배를 추가했다. 실제 브라우저 검수에는 별도 로컬 서버의 통제된 전멸 상태를 사용했으며 운영 API에 전멸 조작용 경로를 추가하지 않았다.

후속 화면 검수는 PC 1920×1080, 모바일 에뮬레이션 세로 390×844·320×568와 가로 844×390에서 진행했다. 생성 길목·수호석, 첫 전멸 15초, 두 번째 전멸 30초와 다음 전멸 45초 안내를 확인했다. 320px 화면에서도 패널이 화면 안에 들어오고 가로 넘침이 없었으며, 대기 중 조작 잠금과 새로고침 후 동일 부활 시각 유지, 부활 후 패널 해제를 확인했다. 관련 화면의 콘솔 오류·경고는 없었다.

이 후속 작업도 검수판 범위다. 운영 계정·획득·보상·배포 상태는 변경하지 않는다. 아래 V1의 19개 자산·10개 검사·정비 복귀 설명은 최초 구현 당시 기록이며, 현행 부활/원화 기준은 이 절이 우선한다.

## 요청과 이번 결과

사용자 최종 편성은 플레이어마다 **용병 2명 + 카드 1장**이다. 5장 덱이라는 이전 해석은 적용하지 않는다. 2~3인 협동 디펜스와 PC 전장 확장, 모바일 대응을 검토한 뒤 `시작해` 지시에 따라 실제 다중 접속이 가능한 독립 검수판을 구현했다.

기존 V3 전투를 상속하는 전장과 HTML 조작부, 서버가 판정하는 방·전투 모델, 초대 코드 대기실, 자동 대원이 참가하는 연습 모드가 동작한다. 라이브 전투·API·재화 파일은 수정하지 않았다.

## 운영 상태와 남은 연결

상태는 **REVIEW_ONLY / 계정 보상 없음**이다. 검수용 수치와 임시 역할·전술을 운영 정책이나 고유 스킬로 확정하지 않았다. 현재 서버는 메모리 기반이며 프로세스 재시작 시 방을 잃는다.

운영화에는 실제 계정 인증 및 소유 편성 확인, 지속 가능한 권위 방 호스트, 저장·재시작 복구, 운영 밸런스/CMS 및 보상 정책의 연결이 필요하다. 검수판의 모델과 프로토콜을 그 단계에 재사용할 수 있다. 정적 Pages 배포만으로 실시간 방 서버가 실행되지는 않는다.

`package.json`의 지정 배포 명령은 `node scripts/deploy-production.mjs`이나 **현재 체크아웃에 그 파일이 없다**. 직접 Wrangler 배포나 dirty 배포 우회를 하지 않았다. 로컬 검수 서버 주소는 `http://127.0.0.1:8898/preview/coop-defense-v1/`이며 운영 반영 완료로 보고하지 않는다.
