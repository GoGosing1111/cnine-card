# 인벤토리 사은품 팝업 반복 수정 — 2026-10-01

사용자 제보: 인벤토리 진입 때 보유 0개의 펀딩 사은품 팝업과 `이전 개봉 결과 확인`이 계속 표시된다.

원인은 `loadInventory()`가 브라우저의 계정별 미확인 개봉 요청 ID를 발견하면 사은품 창을 자동으로 열던 코드다. 닫기는 ID를 보존하므로 인벤토리 재진입·새로고침마다 반복됐다. 실제 운영 소스와 같은 index를 사용하는 로컬 브라우저에서 보유 0개, 미확인 요청 1개로 재현했다.

인벤토리 로딩의 자동 개봉 창 호출을 제거했다. 미확인 요청이 있을 때만 인벤토리 안에 `사은품 개봉 결과`와 사은품별 확인 버튼을 표시한다. 펀딩·영입전·대회 사은품은 버튼을 직접 눌러 기존 확인창에 들어간다. 로딩 중이나 이미 창이 열린 동안에는 추가 진입을 막는다.

기존 계정별 요청 ID와 재시도 흐름을 보존한다. 보유량이 0이어도 같은 ID의 완료 영수증을 명시적으로 재확인할 수 있고, 성공한 뒤 안내가 사라진다. 조회·재진입만으로 `inventory/use` 요청을 보내지 않는다. 서버 지급·차감·보상 수치와 영수증 코드는 수정하지 않았다.

## 검사 및 배포 범위

- 수정 전 실제 index 브라우저 재현: 보유 0개 팝업 표시 → 닫기 → 인벤토리 갱신에서 다시 표시. 개봉 API 호출은 0건이었다.
- PC 1440×1000, 모바일 390×844: 자동 팝업 없음, 확인 버튼으로 진입, 닫기 후 재진입, 응답 오류 후 재진입, 같은 요청 ID 재사용, 보유 0개 완료 영수증 재확인, 완료 후 안내 제거, 영입전·대회 수동 확인을 검증했다. 가로 넘침과 JavaScript 오류는 모두 0건이다.
- 실제 앱은 진입 후 `screen` URL을 소비하므로 브라우저 검수의 새 문서 진입은 `?screen=inventory`로 다시 이동한다. 최초 검수에서 로비를 인벤토리로 기다리던 테스트만 교정했다.
- 화면·결과 증빙은 작업 트리 밖 `../inventory-gift-before-20261001/`, `../inventory-gift-after-20261001/`에 보존한다. PC·모바일 실제 화면을 직접 확인했다.
- 국소 프런트엔드 수정이며 공통 인증·서버 거래·DB·의존성 변경은 없다. `npm run deploy:production -- --scoped`의 관련 검사로 `tests/inventory-ui-v2125.test.mjs`만 선택한다. 실제 로더·클릭 처리의 팝업 미자동실행, 계정 구분, 요청 ID 보존과 보유량 0개 수동 복구를 추가했다. 전체 게임 검사는 반복하지 않는다.
- 직전 운영 기준: Pages `00a6e115-1a3f-435f-a606-fdd564a05395`, 소스 `5b50dbb031b706da4b0bd17d0d1727e121dee6e0`. 그 이후 원격 커밋은 랭크전·종료 콘텐츠의 운영 결과 문서뿐이다.

최종 배포와 운영 파일 확인은 반영 후 기록한다.
