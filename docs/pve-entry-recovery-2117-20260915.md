# 카우방·폐차장·무한의탑 전투 초기화 복구

2026-09-15 카우방과 폐차장 몬스터가 나타나지 않고 입장이 멈춘다는 제보를 운영 후보와 동일한 코드, 별도 로컬 계정 DB로 재현했다.

## 원인

황궁 전장 지원 때 공용 V3 엔진의 배경 선택이 `battlefieldAsset(mode)` 메서드로 변경됐다. 연속 전투용 폐차장·카우방·무한의탑 및 `pve-v3` 엔진은 같은 이름의 문자열 getter를 유지했다. 공용 생성자에서 `this.battlefieldAsset(...)`를 호출하는 순간 `TypeError: this.battlefieldAsset is not a function`이 발생했다. WebGL과 몬스터 텍스처를 만들기 전의 오류다.

운영 이미지 9개는 HTTP 200과 올바른 이미지 형식으로 응답했다. 읽기 전용 운영 조회에서 카우방·폐차장 CMS는 ON이고, 저장된 전투는 정산 완료 상태였다. 입장 API의 실패가 아닌 전투 화면 초기화 실패인데도 폐차장은 불확실한 입장 요청으로 안내했고, 카우방은 생성되지 않은 렌더러의 숨겨진 결과 영역에 복구 결과를 넣었다.

## 수정

- 모든 연속 전투 엔진의 배경 선택을 공용 메서드 계약에 맞췄다. 생성·전투 데이터 연결·전장 전환·진단 모두 같은 함수를 호출하고 기존 배경 로더를 재사용한다.
- 카우방 렌더러 생성 실패 시 별도 결과 모달을 표시한다. 결과 확인으로 요청을 마무리하고 카우방에 복귀한다.
- 폐차장은 확정 응답 이후의 화면 오류를 통신 오류와 구분하고 기존 결과창을 표시한다. 복귀 버튼을 누를 때 보존한 요청번호를 해제한다.
- 기존 V3 소비자 번들을 다시 빌드하고, 운영 앱·진입 모듈·변경 번들에 `pveEntry=2117` 캐시 키를 추가했다. 공용 셸 버전과 서비스 워커의 네트워크 우선 정책은 유지한다.
- 몬스터 원화·SD, 일반 5장+별도 용병 슬롯, 진형, 보상·입장료·입장권·일일 제한·CMS·서버 계산은 변경하지 않는다.

## 검증

- 수정 전 실제 엔진 생성자 테스트 및 운영 진입 UI에서 동일한 TypeError를 재현했다.
- 실제 생성자·페이로드 연결·텍스처 선택을 폐차장·카우방·무한의탑의 프리뷰와 공용 운영 엔진으로 검증한다. 일반 PVE/PVP·레이드·호송·공성·황궁 배경도 함께 확인한다.
- 신규 검사를 `test:live-connections`에 추가해 운영 `release:gate`에 포함했다.
- 관련 서버·입장 복구·요청 중복·공용 진형 검사 71개 통과. SQLite와 PostgreSQL 호환 계층을 포함한다.
- 실제 운영 진입 UI와 검수 계정 API에서 카우방 22체(280개 서버 이벤트), 폐차장 외곽 10체(87개)·압축 설비 13체(147개)·용광로 16체(260개), 기존 무한의탑 28체(211개)가 보스까지 전부 나타나고 종료됐다. 완료 콜백 순서가 서버 타임라인과 동일하다.
- 1440px 데스크톱·390px·320px 모바일에서 원화 카드 도크와 몬스터·전투 조작을 확인했다. 일시정지 중 이벤트 수가 유지됐고 재개 후 정상 종료됐다.
- 폐차장 용광로는 새로고침 후 같은 요청번호의 확정 기록을 복구했다. 입장권은 추가로 차감되지 않았다.
- 카우방·폐차장 렌더러에 생성 실패를 주입해도 저장된 결과 및 복귀 버튼이 실제로 보인다. 확인 후 대기실로 돌아가며 입장 오류 경고나 반복 재시도가 없다. 정상 재생 중 콘솔 오류·HTTP 실패는 0건이다.
- 브라우저 검수는 운영 계정의 재화를 사용하지 않는 별도 로컬 DB로 진행하며, 배포 후에도 CDN 코드·자산을 검수 계정 API와 결합해 확인한다.

배포는 범위 커밋과 `npm run deploy:production`의 전체 출시 검사를 통과한 후보로만 진행한다.
