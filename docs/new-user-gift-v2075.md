# 신규유저 기프트 박스 V2075

## 확정 정책 — 2026-09-09

- 숲켓몬 `users.created_at`으로 가입 후 **7일(168시간) 이내**인지 판정한다. UTC 저장값을 명시적으로 해석하고 CMS에는 KST로 표시한다. 정확히 168시간은 포함한다. 가입일 누락·잘못된 날짜·미래 날짜는 차단한다.
- 사용자 승인: **“숲켓몬 가입일로 하되 2차인증 안되면 지급 불가.”** 서버의 `user_second_verifications`에 WAGO 또는 PLAYDK 인증이 있어야 한다. 요청에서 보낸 가입일·인증 여부는 사용하지 않는다.
- CMS → 유저관리 → 대상 유저 → **신규유저 기프트 박스**에서 수동 지급한다. `USER_MANAGE` 권한 필요. 이 기능 추가만으로 기존/신규 유저에게 자동 지급하지 않는다.
- 계정당 1회 및 동일 인증 제공자·인증 계정당 1회. 인증 계정 식별자는 SHA-256으로 기록한다. 수령 원장에는 계정 삭제 FK를 걸지 않아 탈퇴·재가입·인증 해제·계정 초기화 후에도 중복 지급을 막는다. 서로 다른 제공자의 계정이 같은 사람인지 추론하지는 않는다.
- 7일 제한은 **CMS 박스 지급 시점**에 검사한다. 정상 지급된 박스는 개봉 기한이 없지만, 개봉 시에도 지급 당시와 동일한 2차 인증 계정을 유지해야 한다.

## 원자성·재시도

- `new_user_gift_receipts_v1`: `user_id` PK, `(provider,identity_hash)` UNIQUE, 상태 `ISSUED → OPENED`.
- CMS 지급: 계정 행 잠금, 인증 행 잠금, 인증 해시 기준 트랜잭션 잠금, 조건 재검증, 보상 명세·해시·박스 1개·관리자/인벤토리 로그를 한 트랜잭션으로 저장한다.
- 개봉: 동일 계정/원장/인증을 다시 잠그고 박스 1개 차감, 코인·카드·마법·장비 지급, 지급 행 수 검증, 로그·완료 원장 저장을 한 트랜잭션에서 수행한다. 중간 실패·0행 지급·감사 로그 실패는 모두 롤백한다.
- 최대 안전 정수 범위 밖 코인 잔액은 차단한다. 100억 금액은 BIGINT로 저장한다.
- 동일 계정 재요청은 기존 완료 결과를 반환한다. 네트워크 응답 유실·더블 클릭·다른 요청 ID를 써도 중복 지급하지 않는다.
- 보상 목록은 지급할 때 스냅샷으로 고정한다. 이후 신규 카드 추가는 기존 박스에 소급하지 않는다. 개봉 전 대상 보상이 삭제/비공개되거나 한정 카드 재고가 소진되면 박스를 유지하고 관리자 확인을 요구한다. 다른 보상으로 몰래 대체하거나 부분 지급하지 않는다.
- 일반 CMS `INVENTORY` 지급에서는 `NEW_USER_GIFT_BOX`를 차단한다. 다른 경로에서 수량만 생겨도 정식 원장이 없으면 개봉할 수 없다. 운영 중 수령 원장을 삭제하거나 초기화하지 않는다.
- `inventory_items.is_active=0`이면 추가 지급·개봉 모두 차단한다. 카탈로그 초기화는 `ON CONFLICT DO NOTHING`이므로 운영자의 OFF 설정을 덮어쓰지 않는다.

## API·화면

- `GET /api/admin/users/new-user-gift?userId=…`: 가입·인증·기지급 상태와 실제 보상 목록.
- `POST /api/admin/users/new-user-gift`: `{ userId, requestId, reason }`. 수량·강화·기한·보상 항목은 클라이언트에서 변경 불가.
- `GET /api/new-user-gift`: 로그인 유저 본인의 원장/박스 상태.
- `POST /api/new-user-gift/open`: 로그인 유저 본인만 개봉. 요청 본문의 다른 유저 ID는 사용하지 않는다.
- CMS 스크립트: `admin/new-user-gift-v2075.js`.
- 클라이언트: `js/new-user-gift-v2075.js`, `css/new-user-gift-v2075.css`. 기존 보급 상자 리소스를 사용한다. 새 그림 제작/이미지 재생성은 포함하지 않는다.

## PLAY DK 가입일 조사 결과

현재 서버 클라이언트 `functions/_playdk_client.js`는 HMAC 인증된 `GET /api/v2/ext/game/user?token=…`에서 UUID·닉네임만 반환한다. 현재 연동 문서와 운영 인증 테이블에는 PLAY DK 가입일 계약/저장이 없다. 실제 성공 응답의 모든 필드를 확보하지 못했으므로 **PLAY DK API 자체가 가입일을 제공하지 않는다고 단정하지 않는다.** 확인되지 않은 필드명/엔드포인트를 만들지 않았으며, 인증 완료 시각이나 게시글 작성 시각을 가입일로 대체하지 않는다. 사용자가 승인한 숲켓몬 가입일 기준을 사용하므로 PLAY DK 가입일 API에는 의존하지 않는다.
