# 제작소 대량 장비 조회 지연 수정 — 2026-09-27

## 재현과 원인

- 사용자 제보: 제작소 `MASTER WORKS` 로딩이 길고, `연결할 운영 화면을 찾지 못했습니다.`가 함께 표시됨. 장비 보유량이 많은 계정에서 악화된다는 후속 제보.
- 기존 `synthesisRecipeRows`는 계정의 **모든 장비 인스턴스**를 집계한 뒤 합성 레시피에 결합했다. 합성에 사용할 수 없는 다른 종류의 장비까지 읽었다. 운영 PostgreSQL 실행 계획에서 대량 계정의 수백만 행 스캔을 확인했다.
- 해당 계정의 기존 운영 쿼리는 읽기 전용 트랜잭션의 8초 제한에 걸렸다. 진단은 운영 재화/장비 수정 없이 수행했다. 전체 계정 집계 대신 DB 통계의 빈도 상위 계정 두 곳을 골라 제한된 조회로 확인했다.
- 별도로 라우터가 API 응답 뒤 생기는 탭 버튼을 15초 동안 찾았다. 로컬에서 API 응답을 18초 지연시키면 **15,020ms에 제보와 같은 오류가 발생하고 로딩 화면이 남았다**. 화면 연결 자체의 문제가 아니라 데이터 대기를 잘못 보고한 것이다.
- 기존 접속 OWNER 계정은 제작소 API 284ms, 화면 진입 약 409ms로 정상적이었다. 이 계정만 검사하면 대량 보유 계정의 문제가 드러나지 않는다.

## 변경

- 합성 레시피별 해당 장비만 기존 `(user_id, equipment_id, id)` 인덱스로 읽고, 사용 가능한 장비 **최대 2,001개**에서 집계를 종료한다. 전체 인벤토리 집계, 새 스키마, 보유 수량 캐시는 추가하지 않았다.
- 기존 일괄 합성 상한 100회 × 레시피당 최대 20개 = 2,000개를 판단하는 데 충분한 범위다. 조회 상한에 도달하면 `quantity_capped`를 반환하고 UI는 **2,001개 이상**, 합성 후 남는 수량도 **이상**으로 표시한다. 실제 인벤토리 수량을 변경하지 않는다. 상한 미만은 정확한 수량이다.
- 장비 제외 조건이 과거 `V3_JOINT_RELEASE_ENABLED=false`를 참조하던 것을 실제 운영 강화 출시 조건 `FORGE_RUNTIME_RELEASE_ENABLED`로 고쳤다. 보유 수량, 소비 대상 선택, 트랜잭션 검증 모두 장착·강화 장비를 제외한다. 강화 0단계는 사용할 수 있다. 출시 플래그 값이나 CMS 정책은 변경하지 않았다.
- `fusion`/`vehicle`은 기존 `workshopSection` 초기 렌더 계약으로 바로 연결한다. 불필요한 탭 버튼 폴링/클릭을 제거해 늦은 API 응답을 잘못된 경로 오류로 표시하지 않는다.
- 제작소 GET에 12초 전체 대기 제한을 적용했다. 읽기 요청 대기열·본문 수신까지 포함하고 만료 시 요청을 취소하여 화면 내 재시도 안내를 제공한다. 합성/제작 POST의 처리 시간이나 영수증 계약은 바꾸지 않았다.
- 오류 버튼은 기존 제작소 디자인과 맞추고 모바일에서 문구·버튼을 확인했다. 메인 로더, 라우터, 제작소 JS/CSS 캐시를 갱신했다.

## 측정과 검증

- 운영 DB에서 수정 쿼리 실행: **811ms / 531ms**. 두 번의 측정 모두 같은 대량 계정이며 운영 부하·캐시 상태에 따라 달라질 수 있다.
- 실제 수정 `userWorkshopState`를 운영 DB의 대량 계정 두 곳에 읽기 전용 실행: **1,019ms / 1,020ms**, 각 8개 조회, 합성 16개 레시피 반환. 인스턴스 목록을 클라이언트로 보내지 않는다. 이 수치는 인증·네트워크·화면 렌더를 포함한 사용자 전체 진입 시간은 아니다.
- 로컬 PostgreSQL 회귀: 관련 없는 장비 10만 개와 대상/다른 계정 장비를 함께 두고 제한 조회, 0개/정확 수량/상한 표시, 비공개·OWNER 제한, 장착·강화 제외를 확인했다.
- 실제 합성 함수로 최대 100회 × 20개 차감, 결과 100개 지급, 같은 요청 동시 실행·완료 재시도 1회 처리, 영수증 오류 시 차감·지급 롤백을 검증했다.
- 브라우저: PC 1440px 및 모바일 390px·DPR 2·CPU 4배 조건. 한 번의 진입 조회, 첫 화면 장비 탭, 분류 전환/검색, 즉시 셸 재렌더, 직접 주소 진입, 새로고침 오류/재시도, 이탈 후 늦은 응답 무시, 재진입을 검수했다. 가로 넘침 0, JS 오류 0.
- 1.6초 파일 지연 + 0.4초 API 지연을 주입한 격리 환경에서 실제 목록 준비까지 PC 1,696ms / 모바일 1,942ms. 이는 운영 성능 수치가 아닌 재현 가능한 로컬 지연 시험이다.
- 응답을 멈춘 경우 12초 제한 뒤 화면 안에서 다시 시도할 수 있고, 오래된 응답이 성공한 재시도 결과를 덮어쓰지 않는다. 실계정 합성/차감은 실행하지 않았다.
- 재현 스크립트: `tests/workshop-slow-read-20260927.browser.mjs`, 기존 전체 제작소 진입 검사 `tests/workshop-entry-20260926.browser.mjs`.
