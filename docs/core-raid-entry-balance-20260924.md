# 붕괴 코어 입장 안전 판정 보호 — 2026-09-24

사용자 승인: 입장 당시 안전했던 공략이 다른 공대원의 진행 때문에 과부하 실패로 뒤집히지 않게 수정·배포한다. 처음부터 위험한 선택, 기존 허용 편차·과충전 피해·전투/기믹 실패는 유지한다.

## 원인과 재현

- 기존 입장 화면은 현재 공대 진척을 표시한다. 서버의 개인 공략 스냅샷에는 덱·CMS 설정만 저장했고, `resolveAttempt`는 종료 시 재조회한 공대 전황만으로 공명 판정을 했다.
- SQLite와 PostgreSQL 호환 경로의 실제 `raid/core/battle` → `raid/core/resolve` 핸들러로 재현했다. 세 코어 100/100/100, 목표 360, 허용 편차 123에서 두 명이 파쇄에 입장하면 모두 권장·안전 상태다. 동료가 먼저 +100~120을 완료한 뒤 내 +100~120이 정산될 때 편차가 200 이상으로 바뀌어, 전투·기믹을 모두 성공해도 `CORE_OVERLOAD`, 개인 진척 0, 공대 HP -100으로 처리됐다.

## 변경

- 새 CORE 공략의 서버 `deck_snapshot.coreRaidEntryBalance`에 버전·목표·세 코어 진척을 보존한다. 이미 저장하는 `coreRaidCombatSettings`와 함께 사용하며 클라이언트가 보내는 같은 이름의 값은 받지 않는다.
- 기존 종료 판정을 우선 적용한다. 과부하일 때만 저장된 입장 상태에 본인의 실제 진척을 더해 같은 판정 함수를 실행한다. 입장 당시 판정이 안전하면 기본 성공 결과를 유지하고 `balanceProtectedAtEntry:true` 및 `entryProjectedBalance`를 감사용 결과에 남긴다.
- 최저 코어/동률 최저 코어의 기존 균형 복구 예외도 동일하게 보호한다. 단순히 입장 당시의 현재 편차만 작았다는 이유로 보호하지 않고, 본인 진척까지 포함해 판정한다.
- 실제 누적은 기존 원자 정산의 `score + progress`와 목표 상한을 그대로 사용한다. 다른 사람의 진척을 입장 값으로 덮지 않는다. 전투·기믹 실패, 이탈·유효시간, 보스 단계, 중복 정산 방지는 변경하지 않는다.
- 구형/누락/불완전한 입장 스냅샷은 기존 판정을 유지한다. 완료된 과거 결과나 운영 계정 재화·보상을 소급 변경하지 않는다.
- UI·클라이언트 캐시·CMS·기능 공개 상태·보상·난이도·DB 스키마·공통 트랜잭션 기반은 변경하지 않는다. 배포 후 새로 시작한 개인 코어 공략부터 보호가 적용된다.
