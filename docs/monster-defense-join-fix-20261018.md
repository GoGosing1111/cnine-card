# 몬스터 디펜스 참가 버튼 복구 — 2026-10-18

## 원인과 수정

사용자 화면의 대기방은 1/3명으로 참가 가능했지만, 저장된 분대가 없으면 `DefenseRoomBrowser`가 참가 버튼을 `disabled`로 만들었다. 하단 안내만 있고 클릭으로 편성에 진입할 수 없어 무반응처럼 보였다.

- 참가 가능한 방의 버튼은 빈 편성에서도 누를 수 있다. 용병 2명과 카드 1장 편성을 열고, **분대 배치**가 완료되면 처음 선택한 방에 한 번 참가한다.
- 취소·닫기·Escape는 편성 초안을 버리고 방 목록으로 돌아온다. 참가 요청을 보내지 않으며 선택한 방 버튼에 초점을 돌린다.
- 이미 유효한 분대가 있으면 즉시 참가한다. 편성 중 방이 가득 차거나 시작되면 서버 거절 사유를 목록에 표시하고 다시 선택할 수 있다. 마감된 방은 계속 비활성화한다.
- 기존 ImageGen 디펜스 UI를 유지했다. 서버 보유·중복·정원 검증, 운영 접근 설정, TEST 및 계정 보상 정책은 변경하지 않았다.
- 편성 창은 적용/취소 결과를 반환한다. 일반 편성·대기방 편성은 기존 동작을 유지하며, 이전 참가 동작이 나중의 편성 완료에 다시 실행되지 않는다.
- 배포 번들 쿼리를 `20261018-defense-join1`로 갱신했다. 현재 main의 승인된 공용 소스로 재빌드하며 공용 전투 소스는 수정하지 않았다.

## 검수

`tests/monster-defense-join.browser.mjs`는 운영 계정 대신 격리 Miniflare/SQLite 계정과 실제 `/defense/` 번들을 사용한다. PC 1440px, 모바일 터치 390px, 좁은 화면 320px에서 참가·편성·취소·Escape·Enter·재참가·정원 오류·정원 마감·화면 넘침을 검사한다. 같은 번들의 3분대 준비와 V3 전투 진입도 확인한다. 별도 신규 UI 자산이나 운영 방을 만들지 않는다.

첫 검수에서 방장 계정을 관찰자로 열자 기존 방 자동 재접속이 정상 작동해 방 목록을 열 수 없었다. 검수용 별도 계정으로 관찰자를 분리했다. 운영 코드 문제로 처리하지 않았다.

화면과 결과는 `docs/qa/monster-defense-join-20261018/`에 보존한다. 배포 과정은 `tests/monster-defense-loadout.test.mjs`로 보유·편성·준비의 서버 계약만 추가 검사하며, 이미 완료한 브라우저 시나리오를 다시 실행하지 않는다.
