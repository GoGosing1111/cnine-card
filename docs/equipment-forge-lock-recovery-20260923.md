# 장비 강화 잠금·응답 유실 복구 (2026-09-23)

## 신고와 원인

- 신고 화면: 미스틱 듀얼디스크 #407509213 선택 후 확률·비용이 비고 `같은 계정의 요청을 처리 중입니다` 버튼이 비활성화됨.
- 기존 견적 POST도 실제 강화와 같은 계정 작업 잠금을 잡았다. 연속 장비 선택은 서로 다른 견적 ID로 여러 요청을 보내므로 읽기 성격의 견적끼리 또는 실제 게임 작업과 경합할 수 있었다.
- 견적 실패를 비활성화된 강화 버튼에만 표시하고 재시도 경로를 제공하지 않았다. 네트워크 타임아웃도 없었다.
- 강화 결과를 받지 못하면 브라우저에 pending 요청을 유지한다. 기존 화면은 이를 발견하면 확률·비용을 비운 뒤 반환했고, 결과 확인 버튼은 장비 목록 아래에 작게 있었다. 완료 여부를 자동 조회하지 않아 서버 처리가 끝나도 화면이 잠긴 것처럼 남을 수 있었다.

## 운영 읽기 전용 근거

- 신고 개체의 소유 계정은 3011이다. 점검 시 계정 잠금 행은 없었고 최근 강화 12건은 모두 COMPLETED였다.
- 확인된 최근 작업의 생성~완료 기록 간격은 약 29~42ms였다. HTTP/API 전체 지연시간을 의미하지 않는다.
- 같은 시점 Neon DB는 idle client 149개, active client 1개, Lock 대기 0개였다. 이는 순간 상태이며 과거/모든 시간대의 과부하가 없었다는 증거는 아니다.
- 운영 장비·장착·재화·강화 기록·CMS 정책·계정 잠금 행은 수정하지 않았다.

## 수정 경계

- 인증·소유권·origin·요청 검증을 그대로 유지하며 **견적만 계정 작업 잠금에서 분리**한다. 실제 강화/복구는 기존 공유 잠금, 원자적 차감, 강화 단계·revision 재검증, 동일 요청 멱등성을 유지한다.
- 같은 견적 ID의 병렬/네트워크 재시도는 `ON CONFLICT DO NOTHING` 후 단일 저장 스냅샷을 반환한다. 다른 계정·다른 입력은 계속 충돌 오류다.
- 장비 선택은 180ms 모으기, 화면당 동시 견적 1개, 대기 중 최신 선택 1개만 유지한다. 동일 상태의 견적은 만료 직전까지 최대 8초/12개만 재사용한다. 상태 갱신 시 폐기한다.
- 견적 재시도는 같은 ID로 최대 2회, 500/1500ms + 짧은 분산 지연이다. 요청/응답 본문 모두 15초 타임아웃을 적용하며 무한 폴링하지 않는다.
- 실제 강화는 서버의 명확한 계정 잠금 거절만 최대 2회 자동 재시도한다. 통신 유실처럼 성공 여부가 모호한 POST는 자동으로 다시 실행하지 않는다.
- pending이 있으면 진입 시 기존 영수증 GET을 1회 수행한다. COMPLETED면 pending을 정리하고 상태를 갱신한다. 미완료/없음이면 사용자에게 같은 요청을 이어서 확인하는 버튼을 제공한다. 새 요청 ID를 만들지 않는다.
- 네트워크/알 수 없는 오류에서는 pending을 지우지 않는다. 손상된 pending도 자동 삭제하지 않고 운영 확인을 안내한다. 서버에서 확정한 재시도 불가능 오류만 새 견적을 받을 수 있게 해제한다.
- 오류와 복구 버튼을 강화 정보 상단에 표시하고 견적 실패 시 기본 버튼도 `견적 다시 확인`으로 동작한다. OFF 안내로 오해하는 문구를 현재 상태로 바꾼다.
- 로그인 상태의 진입 요청은 status→state 2회에서 state 1회로 줄였다. 목록 갱신 중 중복 refresh/필터 요청을 막고, 이미지·FX 초기화를 데이터 조회와 분리했다. 정상 결과 연출에는 8.5초 상한, 초기화에는 10초 상한을 두며 영수증 복구는 연출 재생을 기다리지 않는다. 기존 승인 자산/연출 자체는 변경하지 않았다.
- 오류 안내가 추가되어도 모바일 버튼이 다음 복구 섹션을 덮지 않도록 공개 화면의 옵션 영역 높이를 내용 기준으로 조정했다.
