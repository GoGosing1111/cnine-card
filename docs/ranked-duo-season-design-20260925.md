# 비동기 랭크 듀오 시즌 설계

2026-09-25 · 요구사항 및 구현 전 설계. 런타임·DB·운영 설정 변경 없음.

## 확정 요구사항

- 시즌 참가자는 기본 3일(72시간) 모집하며 추가모집이 가능해야 한다.
- 시스템이 강한 참가자와 약한 참가자를 묶어 2인 팀을 만든다. 팀 간 전력 격차도 줄인다.
- 1덱 대 1덱 결과만 보여주지 않고 네 사람의 2덱 대 2덱 전투 전체를 보여준다.
- 각 팀원에게 행동력을 각각 부여한다. 기존 랭크전처럼 비동기로 진행한다.
- 덱은 최신화되어야 한다. 시즌 동안 카드·강화·장비·용병 능력치를 동결하지 않는다.
- 편성 기준에는 용병 보유 현황, SUPERSTAR, FUR +13을 기준으로 한 카드 전력, 장비 전투력을 포함한다.
- 모든 구현에서 병목·과한 DB 조회·과부하를 방지한다. 이 원칙은 듀오 외의 작업에도 적용한다.

아래 계산식, 추가모집 세부 운영, 공격 시 행동력 차감 주체와 구현 구조는 이 요구사항을 만족시키기 위한 제안이다. 실제 운영 계수·수량·보상을 확정하거나 구현했다고 해석하지 않는다.

## 전력 평가와 최신 덱의 구분

| 구분 | 목적 | 갱신 시점 |
| --- | --- | --- |
| 보유 전력 요약 | 참가자의 실제로 사용 가능한 전력을 평가 | 카드 획득/강화/퇴사, 장비 획득/강화/파괴, 용병·스킬 등 관련 변경 |
| 팀 편성 평가 기록 | 어떤 기준으로 강자+약자를 묶었는지 재현 | 해당 모집 차수의 편성 확정 시 기록 |
| 현재 팀 전력 | 성장한 팀에 맞는 상대 후보 탐색 | 팀원 전력 요약 변경 시 |
| 경기 입력 스냅샷 | 한 경기의 네 덱·능력치·승패를 일관되게 재생 | 각 경기 접수 시 최신 서버 상태로 생성 |

팀 구성은 시즌 동안 유지하는 것을 기본 제안으로 하되, 출전 전력은 계속 갱신한다. 덱 저장·강화 등 변경이 완료된 뒤 접수한 경기에는 해당 변경을 반영한다. 이미 접수된 경기의 도중에는 입력을 바꾸지 않으며, 과거 전적 재생은 그 경기의 저장된 입력과 결과를 사용한다.

현재 선택 덱만 낮추거나 장비·용병을 잠시 해제해도 보유 전력 평가가 낮아지지 않게 한다. 실제 출전은 사용자가 선택한 유효한 덱이며, 새 카드를 얻었다고 시스템이 임의로 덱을 교체하지 않는다. 소유권을 잃어 덱이 무효가 됐다면 전투 전에 편성 수정을 안내하고 행동력을 차감하지 않는다.

## 기준점과 점수 산정 제안

### 기준 단위

동일한 전투 설정 버전에서 **일반 FUR +13 한 장의 기본 카드 전투력을 100점**으로 환산한다. 카드별 특수 추가 전력·고유특성은 기준 단위에 섞지 않고 해당 카드 평가에 반영한다. 이는 비교 단위이며, 모든 보유 카드를 +13으로 취급하거나 실제 전투 수치를 보정하는 규칙이 아니다.

코드 기본값의 일반 FUR +13은 83,200, SUPERSTAR +13은 93,200이다. `cardBattlePower`와 전투 설정에서 도출되는 값이며 현재 운영 CMS를 조회한 결과가 아니다. 실제 구현은 숫자를 복제하지 않고 같은 서버 계산과 설정 버전을 사용한다. SUPERSTAR는 현재 강화 단계에 해당하는 값으로 평가한다.

### 평가 구성

| 요소 | 평가 방식 | 과대·과소 평가 방지 |
| --- | --- | --- |
| 일반 카드 | 보유 카드 중 실제 편성 제한을 만족하는 상위 5장의 기본 전력 | 동일 카드 중복 수량을 출전 인원처럼 합산하지 않음. 현재 SUPERSTAR 최대 1장 등 라이브 덱 규칙 적용 |
| FUR +13 | 상위 5장 평가와 함께 보유한 서로 다른 +13 카드 수를 설명 지표로 표시 | 기본 전력에 들어간 +13에 별도 고정 보너스를 다시 더하지 않음 |
| SUPERSTAR | 보유 여부·최고 강화 단계·실제 카드 전력 및 고유효과 | 여러 장 보유해도 동시에 사용할 수 있는 수만 평가. 낮은 강화와 +13을 같은 점수로 취급하지 않음 |
| 용병 | 보유한 사용 가능한 용병의 등급·개별 능력·스킬·전력 연계를 비교해 한 슬롯의 전력을 추정 | 보유한 모든 용병 전투력을 합산하지 않음. 같은 SSS라도 개별 성능을 구분. 중복 수량은 실제 성장에 반영되는 경우에만 고려 |
| 장비 | 보유한 장비 중 슬롯별 사용 가능한 조합의 강화 포함 PVP 기여분 | 전체 장비 창고를 합산하지 않음. 기본 장비 전력과 강화 증가분을 각각 한 번만 반영 |
| 차량·호칭 등 | 현행 PVP에서 실제 적용되는 항목을 같은 서버 규칙으로 반영 | 만료·비활성·파괴 항목 제외. PVE 전용 배틀슈트 전력 제외 |
| 고유특성·조합 | 기본 전력에 포함되지 않는 전투 기여만 별도로 검증 | 모든 덱 조합을 완전 탐색하지 않으며 기존 수치와 중복 가산하지 않음 |

설명 가능한 초기 모델은 `100 × (카드 전력 + 장비 등 PVP 전력 + 용병 평가 전력) / FUR13 기준 전력`이다. 고유특성과 용병 스킬의 전투 기여를 보정할 계수는 미정이다. 계수는 버전이 있는 공통 정책으로 관리하고 운영자의 최신 설정을 재배포로 초기화하지 않는다.

용병은 고정 등급 전력만으로 실전 영향력을 설명할 수 없다. 기존 전력 연계는 소유자 일반 카드 5장의 공격력·체력과 상호작용하므로 해당 소유자의 덱을 기준으로 평가한다. 팀원 카드까지 합친 10장으로 용병 능력치를 부풀리지 않는다. 강자·약자 구분은 이 추정 전력에 따른 분류이며 매 경기 승리를 예측한다는 뜻이 아니다.

보정은 FUR +13 중심 덱, SUPERSTAR 강화 단계별 덱, 용병 없음/SS/SSS, 장비 약함/강함 등 제한된 대표 조합을 고정 난수와 공격·방어 양쪽에서 비교하여 잡는다. 이 비교는 개발·편성 검수 작업에서 한정된 예산으로 수행하며 실시간 매칭 API에서 모든 참가자 조합을 시뮬레이션하지 않는다.

### 편성 절차

1. 모집 종료 시 동일한 평가 정책 버전으로 참가자 요약의 최신 여부를 확인한다. 모집 중 기록한 최고 유효 전력은 약한 편성으로 신청하는 문제를 검토하는 보조 지표로만 사용하며 이를 자동 제재 사유로 삼지 않는다.
2. 점수순 상위·하위 그룹에서 한 명씩 조합한다. 상위 1명+하위 1명 형태는 초기 해다.
3. 메모리의 요약 자료로 제한된 횟수의 교환을 수행하여 팀 간 추정 전력 격차를 줄인다. 정렬은 O(N log N), 후속 교환은 정해진 후보 수와 반복 횟수 내에서 수행한다. 전체 조합 탐색·전원 상호 대전은 금지한다.
4. 관리자 검수 화면에 카드·용병·장비별 점수, 팀 합산 점수, 팀 간 최대 격차, 강자 편중을 표시한다. 최고 참가자가 압도적인 경우 알고리즘이 균형을 보장했다고 표시하지 않는다.
5. 시즌·모집 차수·정책 버전·입력 버전·난수/동점 처리 기준과 최종 팀을 기록하여 재실행 시 중복 팀 편성을 막는다. 홀수 인원은 추가모집 대기자로 관리한다.

시즌 중 성장은 그대로 허용한다. 상대 후보를 찾을 때 팀 랭크 점수와 현재 팀 전력을 사용하되, 현재 장착만 낮춰 유리한 상대를 얻지 않도록 보유 전력 요약도 참고한다. 상대 탐색의 정확한 가중치와 전력 허용 범위는 검수 후 확정한다.

## 개인 행동력과 비동기 전투

권장 동작은 다음과 같다.

- A와 B가 한 팀이면 A와 B는 자신의 행동력을 각각 사용해 공격을 시작할 수 있다. A가 시작하면 A의 행동력만 차감하고 A+B 두 덱이 함께 출전한다. B가 시작하면 B만 차감한다.
- 다른 팀원의 접속·동의·남은 행동력은 공격 시작 조건으로 요구하지 않는다. 방어 중인 상대 두 명의 행동력도 차감하지 않는다.
- 네 사람의 최신 유효 덱과 능력치를 서버가 확정하고 한 번의 2덱 대 2덱 전투로 계산한다. 한 명의 덱이 전멸해도 팀원의 덱이 남아 있으면 이어진다.
- 일반 카드 계약은 사람마다 정확히 5장, 용병은 사람마다 별도 최대 1장이다. 팀은 최대 12명, 전체 최대 24명이며 각 유닛의 팀과 소유자를 별도로 보존한다. 일반 카드 배열 하나를 임의로 10장으로 바꾸지 않는다.
- 기존 V3 렌더러·카드 프레임·원화/SD 분리·배속과 재생 시계를 확장해 네 덱의 전투를 표시한다. 소유자 한정 효과와 팀 전체 효과의 범위를 명시한다. 팀 단위 지원 범위 등 변경되는 밸런스는 별도 검증한다.
- 서버 결과를 전투 로그로 반환하고 클라이언트가 재생한다. 영상 재생 완료나 브라우저 생존 여부를 점수 확정 조건으로 삼지 않는다. 재접속 시 같은 경기 결과를 가져온다.
- 팀 점수의 변화와 경기 기록은 공동으로 관리하되 개인 행동력·공격 이력은 별도로 남긴다. 개인/방어 보상 정책은 아직 확정하지 않는다.

행동력 최대치·충전 방식·회당 비용, 기존 1인 랭크전 행동력과의 공유 여부는 미정이다. 구현 시 기존 랭크전의 행동력 수량·충전 규칙을 자동 승계하지 않는다.

## 최신화와 부하 제어 구조

### 변경 시 요약 갱신

- 계정별 전투 원본 버전을 카드·장비·용병·스킬·편성 등 관련 변경과 같은 원자적 쓰기에서 갱신한다. 서버 설정에는 별도의 전투 정책 버전을 둔다.
- 보유 전력 요약과 출전 덱 요약을 이 버전에 연결한다. 변경된 계정과 항목만 갱신하고, 짧은 시간에 연속 변경된 동일 계정의 재계산은 마지막 버전으로 합친다. 변경된 상위 항목 제거 시 해당 계정의 후보만 제한해서 재선정한다.
- 초기 요약 생성과 정책 변경 후 재평가는 제한된 묶음과 동시 실행 수로 처리한다. 일반 상태 조회 요청이 전체 참가자 요약 재생성을 수행하게 하지 않는다.
- 갱신 큐의 지연이나 캐시 누락이 생겨도 경기에는 오래된 덱을 사용하지 않는다. 필요한 네 계정의 원본 버전을 먼저 일괄 확인하고, 불일치한 계정만 재구성하거나 준비 중으로 응답한다. 이 단계에서 거절된 요청은 행동력을 쓰지 않는다.
- 캐시 키에 계정·편성·원본 버전·정책 버전을 포함하고 TTL은 호칭 등 가장 빠른 만료 시각을 넘기지 않는다. 권한·금지 상태·소유권·행동력은 경기 접수 시 권위 있는 서버 상태로 검사한다. Hyperdrive SQL 쿼리 캐시는 OFF를 유지한다.
- 같은 버전을 동시에 재구성하지 않도록 중복 작업을 합치고, 실패한 작업에는 유한 재시도·만료·복구 기준을 둔다. 단순히 응답 후 실행될 것이라는 가정만으로 필수 최신화를 보장하지 않는다.

### 경기 요청의 제한된 작업

1. 상대 탐색은 시즌·상태·점수/전력 구간의 인덱스로 제한된 후보 요약을 가져온다. 전 참가자 덱을 읽거나 전체를 무작위 정렬하지 않는다. 후보 확대 횟수에도 상한을 둔다.
2. 선택된 네 계정의 편성과 필요한 장비·용병만 종류별 일괄 조회한다. 카드 20장을 20개 쿼리로 조회하거나 카드마다 보유 목록을 다시 읽지 않는다.
3. 일관된 입력 버전을 검증해 한 경기 스냅샷을 확정한다. 동시에 덱이 바뀌는 경우에도 서로 다른 버전의 카드와 장비가 섞이지 않게 한다. 재검증 횟수에 상한을 두며 확정 후 변경은 다음 경기에 반영한다.
4. `(시즌, 시작자, 요청 ID)`에 고유한 경기 접수 기록과 입력·난수·계산 버전을 저장한다. 시작자 행동력 확보 및 경기 접수는 같은 원자적 처리에 포함한다. 동일 사용자 중복 클릭은 같은 경기로 합치고 동시 진행 수를 제한한다.
5. 전투 계산과 로그 생성은 DB 잠금 밖에서 수행한다. 계산 중 DB를 조회하지 않으며 행동 수·시간·로그 크기를 제한한다. 상한 도달 시 결과 규칙은 구현 전에 확정한다.
6. 짧은 정산 트랜잭션으로 결과 영수증·행동력 확정·팀 점수·이력을 반영한다. 예약 후 실패 시 복구 또는 반환 상태를 영속 기록해 정확히 한 번 처리한다. 응답 유실과 재시도는 기존 경기 결과를 반환하며 새 난수로 재추첨하지 않는다.
7. 팀원 두 명이 동시에 공격해도 각자 행동력과 경기 ID를 분리하고 팀 점수 갱신 손실을 막는다. 갱신 행은 일관된 ID 순서로 짧게 잠그며 전역 시즌 집계 행을 매 경기 갱신하지 않는다. 시즌 마감과 지연 정산의 판정 기준도 경기 접수 기록에 둔다.

소유자별 요약은 참가자가 늘어도 한 경기 조회량이 전체 참가자 수에 비례하지 않도록 설계한다. `Promise.all` 호출 자체를 DB 왕복 감소의 증거로 취급하지 않고 실제 어댑터·쿼리·왕복 수를 계측한다.

### 조회·순위·재생

- 모집 화면은 카운트와 내 신청 상태 중심의 가벼운 응답을 사용한다. 전체 명단은 페이지 단위로 제공한다.
- 개인 행동력과 내 경기 결과는 최신 상태를 제공하며, 공개 순위는 명시한 갱신 시각과 짧은 캐시를 사용할 수 있다. 캐시 무효화 시 전 참가자 순위를 동시 재계산하지 않는다.
- 상태를 매초 DB에서 다시 읽지 않는다. 화면 진입·사용자 조작·필요한 상태 변화에 맞춰 갱신하고 비활성 탭의 폴링은 중단한다. 대기 작업을 조회할 때는 백오프와 횟수/시간 상한을 적용한다.
- 전투 영상 재생 중 프레임·공격 이벤트마다 API/DB 호출을 하지 않는다. 서버가 저장한 전투 결과와 로그를 재사용한다. 로그 목록에는 본문을 붙이지 않고 필요한 경기만 읽는다.
- 정산·캐시 재생성·추가모집 편성은 요청 하나가 전부 처리하지 않고 재개 가능한 묶음으로 처리한다. 작업이 겹쳐도 같은 차수·경기를 중복 적용하지 않는다.

## 모집과 추가모집

모집 기간과 시즌 경기 기간은 별도로 저장한다. 기본 모집은 시작 시각부터 72시간이며 화면에 KST 종료 시각과 남은 시간을 표시한다. 운영자가 추가모집 차수와 기간을 지정할 수 있게 한다.

팀 발표 전 추가모집은 합쳐서 최종 편성할 수 있다. 발표된 기존 팀을 임의로 해체하지 않는다. 시즌 중 추가 참가까지 허용할 경우에는 신규 참가자/대기자끼리의 편성, 경기 수·점수·보상 자격의 차이, 중도 이탈 대체 기준을 먼저 확정한다. 추가모집 기능을 지원한다는 지시만으로 이 세칙을 자동 확정하지 않는다.

## 구현 시 검증할 조건

- FUR +13 기준 단위, SUPERSTAR 편성 제한·강화 차이, 용병 보유/미장착·개별 스킬, 장비 강화/파괴·만료·슬롯별 한도, 장비/용병 중복 합산 방지.
- 최신 덱 저장 직후 시작, 오프라인 팀원 성장 반영, 보유 카드 제거, 정책 변경, 캐시 지연/누락/만료, 동시 변경 중 일관된 경기 입력, 과거 전적 재생 보존.
- 네 덱 전체 출전·전멸 판정·소유자별 용병 전력 연계·효과 범위, PC와 모바일에서 전체 전투와 네 소유자 구분 확인. 공용 V3 수정 시 관련 서버 회귀와 실제 번들/메인 로더 연결, PVE·PVP 핵심 흐름 검증.
- 한 팀원만 접속하거나 다른 팀원 행동력이 0인 경우, 팀원 동시 공격, 시작자 중복 요청, 마지막 행동력 경합, 예약 후 장애, 결과 응답 유실, 시즌 종료 경합에서 중복 차감/점수/보상 방지.
- 예상 참가자 수·피크 공격량을 정한 격리 환경에서 쿼리 수·DB 왕복·읽은 행/실행 계획·p50/p95/p99 응답·CPU·메모리·잠금 대기·로그 크기를 기록한다. 캐시 적중/미스·동시 요약 갱신·추가모집을 포함한다. 실제 측정 전에 구체적 처리량이나 무병목을 보장하지 않는다.
- 정상 경기의 조회량이 참가자 수에 비례해 늘지 않고 정해진 후보/네 계정에 한정되는지 확인한다. 허용 지연·CPU·왕복 예산을 구현 착수 시 현재 기준선과 예상 피크에 맞춰 수치화하고, 초과 경로를 수정한 뒤 공개한다.

실제 듀오 구현은 공용 전투·행동력/점수 거래·DB를 함께 바꾸는 큰 변경에 해당할 수 있으므로 그 구현 범위에서 전체 출시 게이트를 적용한다. 현재 문서와 고정 지침 수정에는 문서 확인·범위 커밋·원격 반영만 수행한다.
