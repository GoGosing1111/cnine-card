# 마다라 개인 판단·기믹 시인성 V3 — 2026-10-11

사용자 지적: 리치왕은 특정 역할을 제외하면 너무 쉽다. 마다라도 공유된 정답을 따라 누르는 구간과 자동 보호가 남아 있었다. 후속 지시 `개선해봐`, `그리고 기믹연출이나 시인성도 신경쓰길바람`에 따라 역할별 개인 판단과 대응 표현을 개편했다. 앞선 **라이브에 올리지 말고 준비까지만** 지시는 유지한다.

## 변경한 플레이

| 단계 | 봉인대 | 정벌대 | 구출대 |
| --- | --- | --- | --- |
| 환술 | 개인 기준 문양에서 정·역방향 이동을 두 번 해독 | 문양과 눈 모양이 모두 맞는 실체를 두 번 식별 | 보호 중인 동료를 제외하고 가장 급한 폭주 위험을 두 번 정화 |
| 분신 | 바뀌는 봉인 방향·칸 수를 해독 | 반사 분신을 제외하고 시전이 가장 빠른 표적을 세 번 끊음 | 문양과 눈 모양으로 낙인의 근원을 두 번 식별 |
| 화둔 | 보존 결계의 봉인을 두 번 해독 | 첫 화염 후 보존·반사를 제외하고 최고 열기 결계를 세 번 파쇄 | 보호되지 않은 급한 동료 선정 → 예고 후 직접 보호 전개 |

| 완전체 | 환술과 운석 개인 과제 동시 처리 | 환술 식별과 핵 노출 대응 동시 처리 | 위험 정화와 대상 선정·보호 타이밍 동시 처리 |

최종 시선 교대, 본인 공격 몫, 공대 회복·부활, 기믹 전원 완료 조건은 유지한다. 같은 역할도 개인 기준·표적 배치를 받는다. 다른 사람의 입력은 서버에서 거절한다. 보존 결계와 완료된 봉인 기록은 공유하지만 개인 선택의 정답/후속 패턴은 공유하지 않는다. 이전의 역할 간 순차 잠금을 제거해 각자 기믹을 병행할 수 있다. 화둔 파쇄만 첫 화염 이후에 열린다.

정상 3인 완주 기준 판단 성공 입력은 봉인대 12 / 정벌대 14 / 구출대 12회다. 입력 횟수 자체를 난도나 재미의 증거로 삼지 않는다. 정벌대의 식별·금지 표적 제외·우선순위·공격 보류, 구출대의 위협 비교·대상 선택·보호 시점 판단을 실제로 요구하는 것이 변경의 목적이다.

## 시간·실수·서버 판정

- 일반 판단은 0.6초 예고 뒤 입력한다. 분신 위협은 최우선 유효 표적까지 8초, 구출 위협은 9초, 식별·봉인·열기는 14초의 대응 시간을 준다.
- 핵 타격·보호 전개는 2.2초 예고 후 6.5초 대응 구간을 사용한다. 예고 중에도 버튼 입력 자체는 가능하고 이른 입력은 실패로 판정한다. 보호는 시간이 지나도 자동 완료되지 않는다.
- 성공할 때마다 새 단서·표적 배치를 발급한다. 잘못 선택하거나 응답 시간이 지나면 공대 피해와 침식 1회가 발생하며, 1.5초 재정비 후 현재 단계에서 새 패턴으로 재시도한다. 전체 단계 제한 시간은 늘어나지 않는다. 침식 4회 전멸을 유지한다.
- 첫 화염은 8초, 두 번째 화염은 **26초**, 화둔 단계는 36초로 로컬 초안을 조정했다. V1/V2의 두 번째 화염 21초보다 이 기준이 우선한다. 운영 경제나 출시 수치는 아니다.
- 정답은 `_raid_madara_decisions.js` 내부 `expected`에만 남는다. 공개 응답은 해당 참가자의 현재 단서·선택지·예고/마감·자기 피드백만 포함한다. 이벤트에 정답이나 개인 선택지를 싣지 않는다.
- 서버 시각, 과제 버전, 요청 영수증으로 검증한다. 늦은 입력/길게 누른 포인터/동일 요청 재전송은 다음 패턴을 처리하거나 이중 실패를 만들지 않는다. JSON 복구 시 예고·마감·복구 시간이 유지된다. 로컬 단일 프로세스 경계는 이전과 같다.

## 화면·연출

- 전장 위에 현재 목적, 우선 과제, 행동 조건, 남은 시간, 개인/공대 완료 수를 표시한다. 원화는 기존 생성된 5종 아틀라스 프레임을 사용하며 새 이미지 생성이나 원본 수정은 하지 않았다.
- 대상 버튼은 눈 모양 SVG·문양·반사/보호 배지·숫자 카운트다운·열기를 함께 쓴다. 색만으로 정답이나 위험을 구분하지 않는다. 정답을 자동 강조하지 않는다.
- 과제별 예고/대응 구간은 사선 영역과 밝은 영역, 이동 표시, 큰 남은 시간, `핵 노출 · 지금 타격` / `지금 보호 전개` 문구로 구분한다. 예고는 단서를 읽는 시간이므로 비활성 대상도 높은 대비를 유지한다.
- 실수는 해당 과제에 원인과 복구 안내를 남긴다. 성공 시 어떤 판단이 맞았는지 표시한다. 같은 DOM 버튼을 유지하며 포인터를 누를 당시의 입력 토큰을 고정한다.
- 전장 보스 발밑에는 예고 점선/대응 실선 고리와 마감 막대를 표시한다. 이는 서버 상태의 HUD이며 피해/판정을 만들지 않는다. 실제 판단 피드백은 기존 아틀라스 후반 프레임을 공용 GSAP 타임라인 0.75초로 재생한다. 기존 Pixi `fxRuntime.Graphics/Sprite`·효과 레이어를 사용하고 두 번째 렌더러를 만들지 않는다.
- 기존 시전 4포즈·효과 60프레임·보스 자막은 유지한다. 이번 작업은 새 주력 스킬 작화나 성우 음성 제작이 아니다. 예고 표시가 조작 버튼이나 로스터를 덮지 않는다.
- 모바일 봉인 문양은 4개를 한 줄에 표시한다. 최종전에는 환술/운석 이동 버튼에 각 마감 시간을 표시하고 해당 과제로 바로 이동한다. 시선 안내는 소형 카드로 정리했다. 키보드 Enter 보호 전개와 동작 줄이기를 확인했다.

## 검증

관련 서버·HTTP·자산 검사 **28개 통과**: 기존 17개를 새 개인 과제로 갱신했고, 공대/자산 5개를 유지했으며, 독립 행동·권한·개인 정보·이른 타격·재시도·수동 보호·마감·복구·판단 속도 6개를 추가했다.

3/4/5/6인 2시드의 모든 단계 완주, 약한 덱의 피해량 실패, 개인 공격 몫, 회복/부활 재시도를 확인했다. 별도 3인·6인 모의에서는 각 참가자가 2.0~2.6초 간격으로 판단하는 조건으로 완주했다. 이 수치는 1.8~2.4초 판단 간격과 200ms 전달 여유를 합친 것이다. 모의 시선 대응/회복은 도우미가 처리한다. 실제 유저의 동시 판단·통신 지연·체감 난이도나 클리어율을 측정한 결과는 아니다.

브라우저 검수는 `preview/madara-raid-v1/qa-v3/browser-result.json`과 PNG에 보존한다. PC 1440×1050, 모바일 390×844에서 실제 UI 입력, 개인 표적, 보호 대상 선택 → 이른 전개 실패 → 재정비 → 키보드 전개 성공, 최종 중첩·시선·격파를 확인했다. API 도우미는 공개 단서로만 진행한다. 캔버스 1개, 기믹 표시 레이어 1개, 가로 넘침 0, 브라우저 예외/HTTP 실패 0을 확인했다.

실제 3~6인 플레이 난도와 시각 최종 채택은 사용자 검수 대상으로 남긴다. `MADARA_RELEASE`는 OFF, 운영 메뉴/API/DB/실계정 입장권·보상 연결 없음. 커밋은 개발 브랜치에만 보관하고 원격 업로드·main 반영·운영 배포는 하지 않는다.
