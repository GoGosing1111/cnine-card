# 붕괴 코어: 미완료 전투 이탈 패배

2026-09-22 사용자 지시: 기믹을 수행하지 않고 스킵하거나 새로고침으로 전투를 이탈하면 해당 개인 전투를 패배 처리한다.

## 판정

- 새로고침, 화면/탭 닫기, 전투 화면 제거, 기믹 취소·누락·비정상 입력은 `CORE_BATTLE_ABANDONED`다. 같은 전투를 처음부터 재생하는 복구는 제거한다.
- 실패 1회, 코어 진척 0, 보스 피해 0, 기여 점수 0이다. 시작 당시 저장된 CMS의 기존 기믹 실패 피해를 사용한다. 공대 전체를 즉시 패배로 바꾸는 정책은 아니다. 공대 HP가 0이 되면 기존 전멸 규칙이 적용된다.
- 정상 완료 결과는 새로고침·중복 이탈·늦은 성공 제출로 덮어쓰지 않는다. 공대 보상 자격·주 3회·입장권·난이도·공개 모드·보상 잠금은 변경하지 않는다.
- 배포 전 이미 진행 중이던 구형 시도의 정상 입력은 계속 정산할 수 있지만, 이탈 후 재개와 입력 누락 면제는 허용하지 않는다.

## 서버 보장

- `raid_core_attempt_flights_v20260922`: 페이지별 임시 ID, 최초 요청 ID, 서버 접속 유효시간을 보관한다. 이전 foundation 마커와 독립된 추가 테이블이며 기존 데이터를 초기화하지 않는다.
- 페이지 ID는 브라우저 저장소에 남기지 않는다. 재접속 상태 조회에서 이전 페이지의 미완료 시도를 실패로 정산한다. `pagehide`의 인증된 keepalive 요청도 같은 정산 함수를 사용한다.
- 전투 중 20초 간격 접속 확인, 서버 유효시간 120초. 창 강제 종료 등 이탈 알림 누락은 다음 전황 조회/재접속/결과 정산에서 만료를 확인한다. 별도 크론 없이 만료 시점 이후 첫 서버 접근에서 확정된다. 만료된 접속 확인은 전투를 되살리지 않는다.
- 같은 페이지·동일 시작 요청의 통신 재시도만 진행 중 스냅샷을 받을 수 있다. GET 재개나 다른 페이지의 재요청은 실패 처리한다. 구형 클라이언트의 신규 출전은 갱신 안내로 차단한다.
- 시도 상태 변경·개인 기록·공대 HP는 하나의 DB 트랜잭션이다. 매 정산 실행의 고유한 소유권 토큰으로 중복/동시 요청의 부수 효과를 막는다. 정산 응답 유실 시 저장된 시도 결과를 반환한다.

## UI와 검증

- 라이브 V3 렌더러·진형·카드 원화/SD·하단 카드 프레임을 변경하지 않는다. 기믹 라이브러리와 일반 PVE/PVP 스킵 동작도 유지한다.
- 전투 시작 안내·규칙·이탈 결과·재접속 직전 결과에 실패 규칙을 표시한다. 재개 버튼은 제거한다.
- `tests/core-raid-abandon-20260922.test.mjs`: SQLite 및 PostgreSQL 호환 어댑터/PGlite로 새로고침, 알림 누락/만료, 정상 완료 보존, 타 계정/페이지, 롤백, 커밋 응답 유실, 중복/동시 정산, CMS 스냅샷, 기존 foundation 마커 검증.
- 기존 고정 전투력·랜덤 두 기믹·보상 회귀 테스트를 유지하고, 종전의 미완료 입력 무벌점 재개 테스트는 새 승인 정책으로 교체한다.
- `tests/serve-core-raid-abandon-qa.mjs`: 127.0.0.1:8962 전용 인메모리 SQL 검수. 실제 index → 모험 메뉴 → 월드 레이드 → 붕괴 코어 → 공용 V3 → 결과/복귀를 사용한다. 운영 계정과 DB는 사용하지 않는다.
- 실제 브라우저 1280×720 및 390×844: 새로고침마다 실패/HP 차감 1회, 진척 0, 정상 기믹 시간 만료 결과와 복귀 버튼을 확인했다. 공개 모드와 보상 잠금은 검수 fixture 값이며 운영 설정 변경이 아니다.

## 배포

- 런타임 캐시: `core-protocol-raid-v1924.js?v=20260922-abandon-defeat`.
- `npm run test:core-raid`에 신규 회귀를 포함하고 `npm run release:gate`로 전체 검사한다.
- 범위 커밋을 origin/main에 통합한 깨끗한 후보에서 `npm run deploy:production`만 사용한다. Hyperdrive 캐시 OFF와 기존 Neon 운영 계정을 유지한다.
- 롤백하더라도 추가 테이블과 이미 확정된 실패 기록을 삭제하지 않는다. 이탈 무벌점 재개 코드를 되살리는 롤백은 사용자 정책을 위반하므로 회귀 검증 없이 수행하지 않는다.
