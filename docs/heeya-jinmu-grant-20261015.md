# 하이희야♡ 진무 지급·편성 허용

사용자 `하이희야 계정에 진무 지급하고 편성 가능하게 해` 후 닉네임을 `하이희야♡`로 확정했다. 운영 조회에서 정확한 닉네임·ID 4977·USER·ACTIVE 및 PLAY DK ID를 확인했다. 인증명이 유사한 헬로희야(ID 4824)는 대상이 아니다.

## 변경 범위

- 진무 V-989 지정 계정 판정을 ID 1 및 ID 4977로 확장한다. 실제 소유 조건은 유지하고 일반 보유 조회·PVE/PVP 저장·단건/일괄 전투 스냅샷에서 동일한 판정을 사용한다.
- 하이희야♡에 영구 1장을 직접 지급한다. 작업 키 `ops:heeya-jinmu-grant:20261015:v1`로 중복을 막으며, 보유·획득 원장·감사 기록·완료 영수증을 같은 거래에 저장한다.
- 운영 USER_LOCK과 DB 대체 잠금을 사용하고 정확한 ID·닉네임·인증 ID를 대조한다. dry-run은 되돌리고 실제 지급 후 같은 키 재시도 및 새 연결로 검증한다.
- PVE/PVP 현재 선택·재화·다른 카드·기존 진무 소유자·성장·리미티드 정책/재고를 보존한다. 자동 편성하지 않는다. 진무의 수량 제외·일반 획득 불가·성능·원화는 유지한다.
- 기존 핑크빛유두 지급 영수증 검증은 그 계정의 보유분만 확인하도록 좁혀, 추가 지정 지급 후에도 원래 영수증을 재시도할 수 있다.

## 검수·배포 계획

- 지정 두 계정의 미보유 차단, 보유 후 PVE/PVP 편성·재시도·단건/일괄 스냅샷, 비지정 계정 차단, 기존 지급 영수증 재시도 검증을 통과했다.
- 새 지급 테스트는 dry-run·각 쓰기 실패·잘못된 닉네임/인증 ID·기존 보유 보존·커밋 응답 유실 후 재시도·기존 소유자 보존을 확인한다.
- 정식 V3 빌더 실행 후 실제 전투 JavaScript 출력은 동일했다. 정책 소스 해시를 담은 빌드 기록만 갱신한다. 시각/게임 밸런스 변경이 없어 브라우저 전투 검사를 반복하지 않는다.
- 인증/DB 기반을 바꾸지 않는 특정 용병 허용 대상 추가이므로 scoped 배포한다. 이미 통과한 편성 회귀를 반복하지 않고 마지막으로 보강한 지급 테스트와 Worker 문법 검사만 배포 게이트에서 수행한다.
