# 최고사령부 퀘스트 · 사용자 승인 기준 (2026-11-03)

사용자는 `preview/weekly-command-20261103/index.html`의 첫 시안을 보고 “좋은데 … 니 시안 승인하고 규정으로 저장 그렇게 만들어”라고 승인했다. 아래는 같은 메시지에서 확정한 변경 사항이다. 최초 시안의 예시 목표·보상을 실제 정책으로 사용하지 않는다.

## 디자인

- NPC 이름은 **최고사령부 - 서린**. 승인된 성인 여성 지휘관의 얼굴·남색 제복·청록 안감과 사령부 배경을 유지한다.
- 현재 로비의 남색 `#152b3d`, 청록 `#46dcff`, 실제 패널·아이콘, 본문 Pretendard Variable, 제목 Black Han Sans를 사용한다.
- 일일/주간 탭 → 임무 선택 → NPC 설명·목표·진행도·보상 확인 → 출전 또는 보상 수령. 모바일에서도 얼굴·이름·대사·선택지가 읽히고 겹치지 않아야 한다.
- “임무를 확인했습니다”는 설명을 읽었다는 대화 선택이다. 전투는 별도의 수락 요청 없이 자동 집계하며, 확인 버튼을 누르기 전 완료한 전투도 해당 기간에 포함한다.
- 원화/배경은 `assets/quest-command-20261103/`에 원본 그대로 있다. 승인 해시는 `docs/qa/quest-command-20261103/approval.json`에 저장한다. 생성 프롬프트·원본·첨부·첫 시안은 프로젝트 루트의 기존 preview 폴더에 보존한다.

## 전투 집계와 보존

- 주간 레이드는 붕괴코어·리치왕 정벌·바르센·흑익의 맹약 합계. 월드레이드는 제외한다. 같은 종류의 같은 방은 1회만 계산한다.
- 붕괴코어는 기존 완료 시도 증거와 방 단위 중복 방지·이탈 제외를 유지한다. 나머지 공대 레이드는 실제 출전 후 CLEAR/FAILED로 종료된 공개 방을 집계하며, 테스트·모집 취소·중도 이탈 실패는 제외한다. 결과 이후 퇴장으로 출전 기록을 잃지 않도록 동결 명단 또는 기존 정산 증거를 사용한다. 과거 리치왕 실패 방에서 이미 전원이 나가 명단 증거가 없는 경우 출전을 추정해 만들지 않는다.
- 영토전·클랜전은 직접 완료한 공격 참여이며 방어전은 제외한다. 승패와 무관하다.
- 랭크전은 직접 완료한 전체 경기 영수증 1건을 1회로 센다. 여러 차전·방어·재요청을 추가로 세지 않는다. 듀오랭크는 직접 시작해 완료한 경기이며 자동 선정된 동료·상대 출전은 제외한다.
- 월드레이드는 출전 전투력이 있는 활성 참가자가 공개 방의 종료까지 참여한 서로 다른 방을 센다. 대기·중도 이탈·테스트 방을 제외한다.
- 기존 `CORE_RAID` 영수증 식별자를 유지한다. 목표/보상을 변경해도 이번 주 이미 수령한 보상을 재지급하지 않는다. 기존 계정·전투·성장·재화·PLAY DK 이력과 정상 수령을 덮어쓰지 않는다.
- 일일 보상은 계정/날짜/퀘스트 단위 고유 영수증과 사용자 잠금, 정책·인증·날짜 재확인, 코인/별/원장 원자 처리로 중복과 부분 지급을 막는다. 지급 완료 후 응답이 끊겨도 저장된 영수증으로 확인한다.

## NPC 대사

“왔군요”, “어떤 임무부터 확인하겠습니까” 같은 공통 인사만으로 끝내지 않는다. 각 임무의 전장·전술·참여 조건을 구체적으로 묘사한다. 최초 브리핑, 진행 중(현재/목표/남은 횟수), 달성, 수령 완료, 인증 필요, 지급 중지, 조회 실패를 실제 상태에 맞춰 구분한다.

예: 랭크전은 선봉과 후속 차전의 편성을 읽는 전술 보고, 듀오는 동료의 공격과 방어를 맞추는 공조, 월드레이드는 출전 편성 유지와 공동 전선의 전투 종료를 설명한다. 영토전은 공격 지점 선택, 클랜전은 동료와 공격 대상 조율을 설명한다. 실제 게임에 없는 필수 기믹이나 완료되지 않은 전투 결과를 사실처럼 말하지 않는다.

정본 대사는 `shared/quest-command-v1.mjs`, UI는 `js/quest-command-ui.mjs`, 서버 집계·지급은 `functions/_quest_hub.js`와 `functions/_quest_combat.js`다. 동일 내용의 별도 가짜 운영 보상 로직을 미리보기에 만들지 않는다.
