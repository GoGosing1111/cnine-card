# 펫 봉인구 · 펫 정수

사용자 지정 기본값은 봉인구 1개당 정수 10개, 리치왕 최종 클리어 참가자별 정수 5개다. 두 수량 모두 OWNER CMS에서 수정한다.

- 개봉 비용·최대 일괄 개봉·획득 풀과 가중치·개봉 ON/OFF: 관리자 → 펫 개봉·아이템.
- 클리어 지급 수량·지급 ON/OFF: 관리자 → 정벌 → 리치왕 정벌.
- 아이템 지급: 기존 유저관리 인벤토리 지급 흐름에 PET_SEAL_ORB, PET_ESSENCE 추가.
- 실제 화면: /pets/opening/, OWNER 연출 검수: /pets/opening/?review=1.

획득할 펫과 운영 확률은 아직 사용자 지정이 없다. 초기 획득 풀은 비어 있고 실제 개봉은 OFF다. OWNER 검수에서 빈 풀은 등록 원화 후보를 사용한 시각 검수만 제공하며 운영 확률·보유 아이템·획득으로 취급하지 않는다. CMS에서 풀과 가중치를 설정한 뒤 실제 개봉을 켤 수 있다. 펫 전투 편성·버프 출시 잠금은 유지한다.

개봉은 봉인구와 정수 차감, 펫 수량 누적, 아이템 로그, 영구 요청 영수증을 하나의 기존 DB batch 거래로 처리한다. 서버 RNG만 사용하며 설정 버전과 보유 잔액을 검증한다. 같은 요청 ID는 결과를 재사용하고 수량이 달라지면 거부한다. UI는 응답 단절 시 계정별 원래 요청을 보존해 재시도한다. 중복 펫은 보유 수량에 누적한다.

리치왕은 ON 모드에서 생성하고 출정한 공대의 최종 CLEAR 전환에만 지급한다. 출정 당시 CMS 수량과 지급 상태를 고정하며 중간 설정 변경은 다음 출정부터 적용한다. 실패·해산·TEST·기존 클리어·이탈·강퇴 계정은 지급하지 않는다. CLEAR, 참가자별 인벤토리·로그와 행동 영수증을 동일 room CAS 거래에 저장해 중복 지급과 부분 지급을 막는다. 기존 다른 클리어 보상 잠금은 유지한다.

전용 투명 아이템 원화 2종과 성소 배경을 image_gen으로 제작했다. PNG 원본은 보존하고 WebP 파생본만 실행 화면에서 사용한다. 생성 프롬프트와 SHA-256은 assets/ui/pets/opening-v1에 기록했다. 기존 펫 원화는 수정하지 않았다.

검증 범위: SQLite·PostgreSQL 실제 호환 거래, 비용 변경, 잔액 부족, 재시도·동시 요청, 지급 중 오류의 전체 rollback, 풀 가중치/제외, 기존 리치왕 라이브 회귀와 인벤토리 회귀. PC 1440px·모바일 390px 실제 Chrome에서 성소·CMS·수량 입력·확률·결과·응답 단절 재시도를 확인했다. JS 오류와 가로 넘침 없음.

배포는 기존 인증·DB 기반·마이그레이션·의존성 변경 없이 기존 거래 도구와 app_meta/인벤토리를 사용하는 국소 기능 추가이므로 scoped 경로를 사용한다. 실제 직전 Pages 운영 배포 확인 기준 fead53fa5af3d445587e00b080969dbb4f5db585(배포 6e025aaf-30ea-4c23-9672-32aa34007e3e). 더 최근 배포가 있으면 실행 시 새 실제 기준을 사용한다.
