# 무한의탑 121~150층 · 배포 전 준비

> 후속 배포 승인 및 2용병 출시 작업: [2026-11-02 출시 기록](../tower-coop-live-20261102/README.md). 아래 내용은 배포 전 준비 단계의 이력이다.

상태: **구현·격리 검수·배포 사전 검사 완료. 운영 배포·운영 설정 변경 없음.** 사용자 요청은 용병 2명, 각 21레벨을 고려한 120층 이후 확장과 보상 상향이다. 후속 답변으로 **121~150층**, **신규 구간만 30% 상향·기존 1~120층 보상 유지**가 모두 확정됐다. 준비 분기는 `codex/tower-121-150-prepare-20261102`다.

## 구성과 보상

일반 카드 5장과 SSS 1명 + SS 1명까지의 기존 2슬롯 편성 규칙, 각 용병 Lv.21·최종 돌파 완료를 기준으로 검수했다. 레벨·편성은 난이도 설계 가정이며 새 입장 제한이 아니다. 일반 24마리 → 정예 3마리 → 수호자 1마리, 180초 공식 시간, 서버 완료 확인, 한 층씩 진행하는 운영 방식을 유지한다.

2026-11-02 읽기 전용 조회에서 운영 최대층 120, 119층 일반 보상 600억, 120층 수호자 보상 4조, 120층 전투력 18억을 확인했다. 승인된 탑 전용 몬스터 리소스를 재사용한다. 신규 전투력은 유저 전투력에 연동하지 않는 고정 기하 보간이며, 기존 120층 18억에서 130층 30억 → 140층 52억 → 150층 90억으로 이어진다.

| 구간 | 기본 클리어 코인 | 비고 |
|---|---:|---|
| 121~129층 | 780억 → 967.2억 | 층마다 증가 |
| 130층 | 5조 2,000억 | 120층 수호자 대비 +30% |

| 150층 | 8조 7,880억 | 140층 수호자 대비 +30% |

기존처럼 일반층과 10층 단위 수호자 보상 곡선을 구분한다. 수호자 다음 일반층은 수호자 특별 보상보다 작다. 일반층은 `600억 × 1.3^구간 × (1 + 구간 내 순번 × 0.03)`이며 순번은 0~8, 구간은 1~3이다. 정수 계산으로 원 단위 오차 없이 결정한다. 신규 30층 기본 코인 합계는 **23,885,097,600,000**이다. 기존 수집 보너스와 부가 드롭 정책은 그대로 적용하며, 희귀 드롭 확률·수량을 30% 올리는 변경은 없다.

## 보존과 적용

- 기존 120개 층을 수정·비활성화하지 않고 30개 행만 추가한다. 계정 보유·재화·성장·편성·최고층·미완료 전투·기존 수령 이력을 쓰지 않는다. 120층 완료자는 기존 도전층 121에서 이어간다.
- 일회 키 `ops:tower-121-150:20261102:v1`. 설정/몬스터 원본 해시와 준비 계획 해시가 모두 일치할 때만 적용한다. CMS가 바뀌면 다시 검토한다.
- 30개 층, 최고층 150, 감사, 완료 영수증은 한 PostgreSQL 거래다. 실패하면 원복한다. 완료 뒤 재실행은 SELECT만 수행하며 이후 CMS 편집을 덮지 않는다.
- 준비 분기의 **dualMercenaries=false**와 재등반 개편 **OFF**를 유지했다. 실제 출시 시 2용병 기능의 별도 출시 승인·배포·확인이 선행되어야 한다. 이 작업이 다른 콘텐츠의 2슬롯 개방 승인으로 확대되지 않는다.
- 도전 안내에 하드코딩된 120층을 제거하고 서버의 현재 최대층을 표시하도록 수정했다. 운영이 아직 120층이면 안내도 120층이다. 메인·배포판 스크립트 버전과 서비스워커의 해당 파일 갱신 경로를 준비했다.

## 검증과 한계

서버/거래 13검사, 인접 탑 UI/자동 다음 층 13검사, 배포 파일 경계 1검사로 **총 27검사**가 통과했다. 신규 구간의 실제 운영 API 블록을 격리 PostgreSQL에서 실행해 120→121 연결, 2명의 Lv.21 전투원, 121/130/140/150층 승리·정확한 지급·재시도·150층 완료·151층 거부를 확인했다. 일회 설정의 모든 쓰기 단계에 실패를 주입해 원복과 계정/진행/미완료 전투 불변을 확인했다. 실제 PostgreSQL 다중 연결 부하 검사는 아니다.

총 **1,520판**의 고정 모의 전투: 4개 SSS+SS 조합, 일반 카드 개별 전투력 25만/100만, Lv.16/21, 용병 1명/2명, 경계층 8개 시드와 신규 30층 전수 구조 확인. 세부 결과는 [balance.json](balance.json)이다. 아이템·펫·마법·계정 버프가 없는 고정 덱이며 실제 유저 승률이나 모든 21레벨 조합의 클리어를 보장하지 않는다.

25만 카드 + Lv.21 헬리오스/바토리는 130층 8/8승 → 140층 2/8승 → 150층 0/8승, 같은 조합의 100만 카드는 150층 8/8승이었다. 신궁 강윤/경찰 조은 및 발테르/블랙크라운 조은은 150층까지 8/8승, 오메가-X/련화는 기존 120층부터 0/8승이었다. 이는 현재 용병별 스킬 편차를 반영한 결과이며, 이번 층 추가를 이유로 기존 용병 수치를 조정하지 않았다.

별도 headless Chromium과 로컬 격리 API에서 **PC 1440px·모바일 390px**의 121층/150층 진입 → 전투 → 일시정지/재개 → 정확한 보상 → 복귀를 확인했다. 150층 이후 전체 완료, 캔버스 1개, 가로 넘침·콘솔 오류·누락 리소스 0을 확인했다. 실제 설치 앱/실기기 검수는 포함하지 않는다. [화면 검수 결과](browser/verification.json), [모바일 121층](browser/390-121-entry.png), [모바일 150층 결과](browser/390-150-result.png).

배포 대상은 생성될 클라이언트 매니페스트까지 포함해 **20,000개**로 한도 검사를 통과했다. 직전 운영 소스에 없던 미출시 V3.5 제작 자료 609개와 신규 검수 데이터는 공개 포장에서만 제외했으며 원본·Git 이력·기존 운영 리소스를 보존했다. 전체 자산 복사 없이 실제 포장 필터와 Git 목록을 대조했다. 파생 배포판 생성 검사와 JS 문법 검사도 통과했다. [배포 사전 검사](delivery-preflight.json).

사용자 브라우저/편집기·마우스·키보드 조작, 운영 계정 전투·보상 수령, 운영 설정 쓰기, 메시지 발송, 저장공간 유지관리, 예약은 수행하지 않았다.

## 최종 반영 순서

1. 준비 분기 검토 후 최신 main과 운영 CMS를 다시 대조한다. 2용병 출시가 별도 승인·검증된 상태인지 확인한다.
2. UI 변경과 파생물만 지정 scoped 배포 절차로 반영한다. 공통 전투 엔진을 다시 빌드하거나 기존 재등반 개편을 켜지 않는다. 아래 보상/층 적용은 아직 실행하지 않는다.
3. 운영 READ ONLY에서 `inspectTowerExpansion`으로 설정과 몬스터를 재조회한다. 준비 시의 `activation-plan.json` 해시와 다르면 중단하고 표를 다시 검토한다. 적용 직전의 운영 소스 커밋과 2용병 출시 상태를 확인한다.
4. 별도 라이브 승인 후 `applyTowerExpansion`에 검증된 `sourceCommit`, 두 해시, `authorization`에 정확한 일회 키, `dualMercenariesReleased:true`, `dryRun:false`를 전달한다. **이번 준비에서는 호출하지 않았다.** `dryRun:true`도 이번에는 로컬 DB에서만 실행했다.
5. 독립 READ ONLY 연결에서 기존 120층 불변, 신규 30층, 최고층 150, 완료 키/감사를 확인한다. 실제 계정 직접 지급이나 완료 층 재정산은 하지 않는다.

문제 발생 시 추가 30층 입장을 차단하는 별도 승인 대응을 사용한다. 이미 시작된 원정/정산 영수증·획득 코인·진행도를 삭제하거나 120층으로 되감는 자동 롤백을 하지 않는다.
