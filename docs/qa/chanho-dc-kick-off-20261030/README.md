# 찬호 DC 복귀 · 원로 추방 OFF

사용자 지시: `찬호 다시 DC 가입시키고 원로 추방기능 OFF시켜`.

찬호 ID4597의 실제 추방 감사53073은 DC(ID8) 소속과 기존 기여81·30승30패를 보존하고 있다. 조회 당시에는 추방 이후 원로 심사를 거쳐 FM(ID7)에 가입된 상태였다. 요청한 DC로 현재 클랜 본부·정규전 명부를 함께 변경하고, 기존 DC 전적에 복귀 전 신규 전적을 더해 보존한다. 현재 전력·재화·다른 계정·설문·과거 전투·원로·클랜 점수는 유지하고 자동 부대 편성은 하지 않는다.

원로 추방은 전체 클랜에서 OFF. 두 경로 `clan/member/kick`, `organization/member/kick`를 인증 뒤 본문 해석·영수증 재처리·거래·라이프사이클 진입 전에 차단한다. 기존 화면은 서버의 `memberKickEnabled`를 확인하고, 클랜 본부는 기존 `canKick`을 false로 내려 추방 버튼을 숨긴다. 가입 심사 및 원로의 다른 권한은 유지한다. 명시적인 재개 지시 전 다시 활성화하지 않는다.

검수는 변경 경로와 기존 클랜 거래·복구 제한에 한정한다. 실제 메인과 본부 PC1440/모바일390 화면, 격리 계정으로 두 API409·버튼0·명부 유지·감사쓰기0 확인. 브라우저 검수는 PGlite 합성 계정이며 실제 계정 조작이 아니다. 실제 DB 복귀 거래는 이중잠금 충돌·명부 변경 직후 실패·감사 뒤 영수증 직전 실패·정상 예행연습을 원복하여 검증했다.

운영 반영은 지정 scoped 배포 명령과 해당 테스트를 사용한다. 복귀 완료 키는 `ops:chanho-dc-restore:20261030:v1`이며 동일 요청은 재변경하지 않는다. 이번 복귀의 원본/거래/예행연습/배포/브라우저 증거는 기존 작업 폴더 `operations/chanho-dc-kick-off-20261030/`에 보존한다. 기존 체크아웃과 의존성을 재사용했고 저장공간 유지관리·캐시 정리·예약은 실행하지 않았다.

현재 단계: 구현 및 화면/거래 예행연습 완료. 운영 배포와 실제 복귀 결과는 후속 완료 기록으로 추가한다.
