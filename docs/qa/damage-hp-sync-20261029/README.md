# 레오넬 피해 숫자·체력바 동기화

사용자 제보: “때렸는데 딜값까지 나왔는데 피는 안달았어요.” 첨부 화면과 후속 닉네임 학벌을 기준으로 사현 토벌의 레오넬 궁극기와 Z-BODY 후속 공격을 확인했다.

학벌 ID4627의 최근 사현 토벌 기록을 PostgreSQL READ ONLY로 확인했다. 운영 저장 기록은 타임라인을 비워 보관하므로 제보 순간의 완전한 과거 재생은 불가능하다. 보관된 편성·시드·설정으로 로컬 전투를 구성했으며 초기 능력치 차이 27개를 기록했다. 이를 동일 과거 경기라고 보고하지 않는다.

로컬 서버 이벤트 160개에서 레오넬 타격 23개의 실제 HP 감소량이 damage와 모두 일치했다. 기존 운영 번들에서 궁극기 seq133의 985,738,600 피해를 포함한 다음 슈트 이벤트 seq136의 누적 HP가 궁극기 접촉 전에 먼저 표시됐다. 궁극기 숫자 표시 시 실제 표시 HP는 이미 36.6169407%여서 그대로였다. 의도한 궁극기 접촉 HP는 36.7049039%다. HP 요청/표시 불일치 2건, 실제 HP 피해가 있는데 체력바가 움직이지 않은 궁극기 1건을 재현했다. 보호막에만 흡수된 피해는 이 오류 집계에 포함하지 않았다.

## 변경

공통 BattleSuitSkillChipPlayback에서 기존에 긴 연출로 분류하던 행동의 앞뒤 순서를 모두 보장한다. 먼저 발사한 슈트 공격은 착탄을 기다리고, 궁극기가 끝나기 전 후속 슈트·스킬칩 누적 HP가 앞서 반영되지 않게 했다. 이미 날아가는 유도탄의 탐색 경로도 미처리 궁극기를 건너뛰지 않는다. 비행·연기 시계는 계속 움직이며 서버 이벤트를 추가하거나 피해를 재계산하지 않는다.

직접 재생된 슈트 공격도 연사 루프가 없다는 이유만으로 착탄 대기를 즉시 완료하지 않는다. 일반 전장과 사냥 전장에서 실제 진행 중인 사격이 끝나거나 세션이 바뀌면 해제한다. 새 세션·취소·회복·오래된 HP 갱신 방지 및 기존 미사일 연속 비행을 유지한다.

PixiJS 8.20.0 / GSAP 3.13.0의 기존 렌더러·충돌 콜백·시계를 사용했다. 원화·아틀라스·스킬 모션·사운드 원본, 서버 피해·밸런스·승패·보상·보유·설정은 변경하지 않았다. 공통 11개 소비 번들과 메인/스토어 로더·캐시를 갱신했다.

## 검증과 배포

행동 순서, 선행 탄착, 연사 없는 직접 사격, 후속 슈트·유도탄, 아직 시작하지 않은 궁극기, 기존 유도탄 지속, 보호막·회복·취소를 회귀 검사한다. 서버 PVE/PVP 피해 원장과 현재 번들 전체 해시/메인 로더를 검증한다. 기존 스킬칩 런타임·첫 궁극기 컷신·배포 도구가 지정하는 실제 전장 입장 검사를 함께 선택했다.

Chrome 실제 메인 로더에서 PC1440/모바일390 사현 전투와 모바일 PVP 양측 레오넬을 확인한다. API는 격리 응답이며 운영 계정/재화 쓰기는 0건이다. 최종 수치와 운영 배포 식별자는 completion.json을 따른다.

첫 배포 게이트는 신규 전달 검사 두 곳의 잘못된 가정으로 중단됐다. 협동 디펜스는 공유 BattleEngine을 직접 포함하므로 라이브 브리지의 runtimeVersion 문자열 대신 번들 해시·순서 수정·진입 URL 캐시를 검사한다. PVP 서버 원장은 개시 버프가 모두 적용된 팀 스냅샷에서 시작하며, 그 이전 at=0 힐러 오라 수치로 용병 연계가 반영된 HP를 덮지 않게 검사기를 수정했다. 두 실패는 수정 후 통과했고 게임 실행 코드는 추가 변경하지 않았다. 재배포는 이미 통과한 순서/스킬칩/컷신 검사를 보존하고 수정한 전달 검사 및 도구가 요구하는 전장 입장 검사만 수행한다.

두 번째 시도는 관련 검사 12개와 출시/Hyperdrive 검사까지 통과했으나 동시 작업에서 추가된 운영 기록 14파일 때문에 공개 파일 수가 20,014로 계산되어 배포 전에 중단됐다. `operations/`의 Node 운영 실행기/영수증은 게임·프리뷰에서 참조하지 않음을 확인하고 공개 포장에서 제외했다. Git/로컬 원본을 유지하며 삭제나 유지관리를 수행하지 않는다. 포장 검증과 기존 release-policy 검사를 추가하고 이전 게임 검사 결과를 유지한다.
