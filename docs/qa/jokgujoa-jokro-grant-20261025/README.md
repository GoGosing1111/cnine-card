# 족구조아 족로 1장 · 한도 예외 지급

사용자 요청: `족구조아 계정에 족로 지급해 한도 예외로`.

운영에서 정확한 닉네임으로 유일한 ACTIVE 계정 족구조아(ID 525)를 확인했다. 족로 V-979 / SSS LIMITED 보유는 0장이다. 1장을 영구 직접 지급하고, 팩/일반 제작/SSS 리미티드 조각 제작 한도·발행 원장은 변경하지 않는다. 기존 재화·다른 카드·성장·장비·PVE/PVP 편성도 보존한다.

족로는 보유 외에 직접 지급 계정 허용도 필요하므로 `jokroAccountAllowed`에 정확한 ID 525만 추가한다. 실제 보유 1장 이상이 필요하며, 다른 지정 계정과 대여 만료·정상 팩/제작 영수증 규칙을 유지한다. 자동 편성이나 메시지 발송은 없다.

일회 키는 `ops:jokgujoa-jokro-exempt-grant:20261025:v1`이다. 계정 ID·닉네임·ACTIVE·인증 식별값 해시를 다시 검증하고 운영 USER_LOCK 및 DB 보조 lease 아래 보유·획득·감사·영수증을 원자적으로 저장한다. 기존 계정 동기화 트리거로 collection revision이 증가하는지 확인한다. 같은 키의 재실행은 읽기만 한다.

검증은 대상 계정의 보유 필수·PVE/PVP 선택·전투 단건/일괄 스냅샷과 인접 비허용 계정, 기존 티머니 접근과 족로 대여 만료 회귀로 제한한다. 거래는 실제 DB에서 실패 주입 원복·정상 dry-run 원복·읽기 전용 재호출을 확인한다. 실제 지급 뒤 별도 DB 연결과 현재 계정 서비스로 보유·사용 가능을 확인한다.

현재 작업 폴더와 공용 의존성을 재사용하며 원화·프로젝트·node_modules 복사본을 만들지 않는다. 공식 범위 배포 후 실제 지급과 독립 검증 결과를 이 폴더에 보존한다.
