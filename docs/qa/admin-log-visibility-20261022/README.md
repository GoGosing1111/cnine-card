# 게임 운영 로그 제외 범위 수정 — 2026-10-22

사용자 최종 범위는 **게임 운영 로그에서 제외**다. Codex 대화/명령 기록 자체를 삭제하라는 요청이 아니다.

## 원인과 변경

기존 `admin/logs`는 지정 운영 계정의 지급 action 11종만 제외했다. 설정·기타 명령과 새로운 Codex 운영 action은 목록에 나타날 수 있었다.

- 지정 운영 계정의 모든 action을 고정 ID로 제외한다. 이후 닉네임 변경/사용자 join 부재도 제외 정책을 해제하지 않는다.
- 과거 닉네임 기준과 앞뒤 공백 처리는 호환한다.
- `OPS_`/`CODEX_` action 접두사와 구조화된 before/after의 최상위 `actor`, `source` (`CODEX`, `CODEX_OPERATIONS`, `SYSTEM_OPS`), `operationKey` (`ops:`)를 제외한다.
- 값 비교는 대소문자/앞뒤 공백을 정규화한다. 일반 설명 문자열에 Codex가 들어간 것만으로 제외하지 않는다.
- 잘못된 JSON/NULL 값은 조회를 실패시키지 않는다.
- SQL에서 필터링한 뒤 최신 300건을 가져오므로 제외된 최신 행이 목록을 비우지 않는다.
- API 응답부터 제외하므로 관리자 화면에 숨겨진 작업의 명령/결과가 전달되지 않는다.
- 다른 OWNER/ADMIN의 일반 운영 기록, 기존 인증/권한, 원장/영수증/계정 잔액은 유지한다. 로그 행의 물리 삭제와 쓰기 중단은 하지 않는다. 기존 지급 검증과 중복 방지 코드가 내부 영수증/감사 ID를 참조한다.

## 검수

`node --test tests/owner-user-grant-admin-log-visibility-v1806.mjs` 5개 통과:
- SQLite/PostgreSQL에서 계정 전체 작업·Codex 작업·새 action 제외.
- 이름 변경, 공백, NULL, 깨진 JSON, 평문 언급, 다른 OWNER/ADMIN 구분.
- 700건의 최신 제외 행이 있어도 정상 운영 기록 300건 반환.
- 조회 전후 저장된 감사 행 불변.
- 실제 `admin/logs`의 기존 권한 검사와 서버 필터 연결.

`verify-live.mjs`는 운영 DB를 REPEATABLE READ / READ ONLY 거래로 조회하고 원시 기록 없이 집계만 저장한다. preflight에서 저장 행 30,017건 중 지정 계정 9,629건 제외, 일반 표시 대상 20,388건, 반환 300건에 제외 대상 0건. 계정/재화/로그 쓰기 0건.

이 변경은 국소적인 로그 조회 정책이며 인증·공통 권한·DB 스키마 변경이 없다. scoped 배포에서 관련 검사와 worker 컴파일을 수행한다. UI 레이아웃/이미지는 변경하지 않는다.

## 배포

배포 완료 후 소스/Worker/Pages와 운영 재확인 결과를 기록한다.
