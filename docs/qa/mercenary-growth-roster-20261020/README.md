# 전체 용병 PVP 성장 효율 · 2026-10-20

사용자 `다른용병도 이런현상 없는거임?`에 대한 운영 설정 점검에서 디임 외 용병도 평타 상한·HP 기반 피격 상한·추가 행동의 게이지 소모 때문에 강화 효율이 상쇄됨을 확인했다. 후속 `수정해`에 따라 디임에 적용했던 제한 있는 보정을 모든 성장 V2 용병의 PVP 공통 규칙으로 옮긴다.

## 변경과 범위

- `shared/mercenary-growth-review-v2.mjs`가 공통 정책을 담당한다. 캐릭터 코드나 이용자·상대·승패를 조회하지 않는다.
- 평타 상한은 **기존 고유 배율의 4배 한도 적용 후** `min(3, sqrt(1 + 성장 공격% / 100))`를 곱한다. 성장과 고유 배율을 먼저 합치면 발테르·헬리오스 등의 Lv.10→11 상승이 다시 4배 한도에 잘리므로 두 단계를 분리했다. 실제 피해는 공격력·방어·치명타·회피 계산과 상한 중 작은 쪽을 사용한다. 스킬·반격의 고유 상한 배율은 그대로다.
- 피격 상한의 HP 기준은 `min(3, sqrt(1 + 성장 HP% / 100))`로 나눈다. 최대 HP 자체를 줄이지 않으며 시작 방벽은 나누지 않는다. 장비·연계·후속 HP 버프는 피격 상한에 계속 반영된다.
- 돌파의 행동 대응·추가 행동 숙련 합계를 시작 게이지에 반영한다(최대 75). Lv.2부터 카드 행동으로 예약된 추가 행동은 자연 게이지를 소모하지 않는다. 자연 행동은 100을 소모하고, 추가 행동 획득량·스킬 비용·재사용·듀오 소유자별 시계는 기존 규칙을 사용한다.
- Lv.1·PVE·성장 미적용·V1 성장·일반 카드 계산을 유지한다. 디임의 PVP 방벽 40% 감소도 유지한다. CMS 수치·실제 레벨·보유 카드·성장 비용·획득 경로·과거 저장 전투·점수·재화를 수정하지 않는다.
- 전투 가능한 용병 도감의 기존 설명에 공통 규칙을 표시한다. 새 UI·레이아웃·이미지 제작은 없다.

## 재현과 결과

운영 CMS revision 61, 성장 정책 revision 1의 79종을 읽기 전용으로 구성했다. 각 이용자의 획득·계급별 착용 제한과는 별개인 전투 스냅샷 구성 가능 목록이다. 개인 식별·소유자 정보·CMS 내부 메모를 제거한 입력은 `tests/helpers/mercenary-growth-roster-20261020.json`에 보존했다.

동일한 25만 전투력 기본 카드 5장, 장비·마법·펫 없음, 동일한 방어형 표적에 고정 난수 0.5를 적용했다. 단일 평타 패킷은 고유 평타 피해 배율까지 포함하고 별도 후속타는 제외한다.

|대상|Lv.1 피해|수정 전 Lv.11|수정 후 Lv.10|수정 후 Lv.11|
|---|---:|---:|---:|---:|
|할로윈 조은|156,000|156,000|330,926|382,120|
|발테르|312,000|312,000|661,852|764,241|
|헬리오스|312,000|312,000|661,852|764,241|

- 79종 모두 Lv.1→10→11에서 해당 평타 피해가 증가한다. Lv.1→11 피해가 동일했던 용병은 27→0종이다.
- Lv.11 최대 HP 증가가 피격 상한의 HP 성분을 동일 비율로 키우던 용병은 78→0종이다.
- 각 용병 Lv.1/10/11을 강윤 Lv.4·할로윈 아윤 Lv.4와 비교했다. 각 조건 난수 4개와 양측 교대, 총 3,792회다. Lv.11 추가 행동에서 부분 자연 게이지가 지워지는 용병은 78→0종이며 무승부는 0건이다.
- 이는 고정 조건의 비교이며 실제 이용자 승률, 과거 경기의 완전한 재생, 모든 상대에 대한 승리 보장이 아니다. 공격 상한 성장 보정은 최대 3배이므로 최대 레벨에서도 무제한 증가하지 않는다.

`before.json`은 앞선 읽기 전용 감사 결과, `after.json`은 수정 후 동일 조건 결과다. `unchanged-baseline.json`의 수정 전 전체 반환값 해시 163개(79종 Lv.1 PVP + 79종 Lv.11 PVE + 4개 V1 성장 + Lv.1 듀오)는 수정 후 모두 일치한다.

`scripts/measure-mercenary-growth-roster-20261020.mjs`는 정식 엔진을 메모리에서 읽어 전용 관찰 콜백과 비공개 타격 함수 export만 추가한다. 6개 전투의 전체 반환값을 원본 엔진과 비교해 계측의 무영향을 검사한다. 측정은 `node scripts/measure-mercenary-growth-roster-20261020.mjs`로 재현한다. 운영 엔진에 진단 코드나 별도 전투 경로는 추가하지 않는다.

## 검사·배포

- 직접 회귀 12개 통과: 전체 로스터의 실제 타격, HP 상한, 게이지, 최대 레벨/최종 돌파, 중복 적용 방지, 스킬/반격 경계, 예약/자연 행동 및 듀오 소유자별 경로, 기존 디임 회귀, 공개 설명.
- 기존 디임 회귀의 `Lv.1 디임 vs Lv.4 강윤` 정확한 행동 수 단정은 제거했다. Lv.4 강윤도 새 공통 보정을 받기 때문이다. Lv.1 자체 계산 보존은 양측 Lv.1 전체 결과 해시로 검사한다.
- 직전 운영 소스는 Pages 배포 목록에서 확인한 `8d25020835097dc2ea8e37a372e357f69a626b73`이다. 공통 전투의 해당 계산만 수정하며 인증·DB·거래·의존성 구조를 바꾸지 않는다.
- `npm run deploy:production -- --scoped`에서 기존 성장 V2, 할로윈 역할/스킬, 디임 방벽, 봉순 고유 방어, 실제 PVE/PVP 번들/로더 연결 및 Worker 컴파일을 검사한다. 이미 통과한 직접 12개를 배포 과정에서 반복하지 않는다. 기존 출시·캐시·Hyperdrive 보호는 유지한다.
- 익명 입력은 `tests/helpers/`, 측정 명령은 `scripts/measure-*`, 증빙은 `docs/qa/`의 기존 비배포 규칙을 사용한다. 정적 자산을 추가하거나 이미지 원본을 삭제하지 않는다.
- 배포 후 운영 API 공통 설명과 변경 공유 모듈 해시, 실제 배포 소스·Worker 버전을 짧게 확인한다. 완료 증빙만 후속 커밋하고 재배포하지 않는다.

배포 완료 상태와 식별자는 후속 검증 시 이 문서 및 `release.json`에 기록한다.
