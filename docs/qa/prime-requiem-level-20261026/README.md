# 프라임 레퀴엠 용병 레벨업 복구

사용자 요청: `프라임 레퀴엠 용병레벨 렙업 안된대 풀어`.

운영 읽기 전용 조회에서 프라임 레퀴엠 V-975 보유자 **2명 모두** 성장 목록에 표시되지 않고, 전수 예상 요청이 **409 MERCENARY_LEVEL_RANK**로 실패하는 문제를 확인했다. 성장 정책은 ON이고 CMS는 r61이었다. 신규 회귀 5개가 변경 전 동일한 목록 누락·등급 오류로 실패했다.

`functions/_mercenary_level.js`의 별도 성장 카탈로그에 `PRIME_CODE`를 연결한다. 정상 SSS LIMITED 정의·요구 경험치 5배·돌파/천장·최대 21레벨·재료/원본 1장 보호·기존 물약 이전·중복 요청 거래를 그대로 사용한다. 제작 ON·현재 비용/재료·전투 밸런스·스킬·획득·계정 보유/성장은 변경하지 않는다. 실제 계정의 레벨을 직접 올리는 작업이 아니다.

수정 후 실제 성장실과 서버 핸들러를 격리 DB에 연결해 PC 1440/모바일 390에서 프라임 레퀴엠의 원화/이름/SSS·요구 경험치 5배 표시, 정상 중복 재료 소모로 Lv.1→2, 새로고침 유지, 원본 소모 제한, 가로 넘침/스크립트 오류/누락 리소스 없음을 확인했다. 1,500 EXP와 재료 15장은 격리 검사 설정이다.

운영 스냅샷을 사용하는 읽기 전용 전수 예상에서는 보유자 2명 모두 카드 표시·SSS 등급·정상 100 XP 예상·요구량 5배를 확인했다. 운영 계정에 전수/돌파/이전을 실행하지 않았다. 변경 전후 보유·성장 해시는 `339364fb9eeaddc017d31500857703a0b44482cfe68969d27f5f7bb2c58751d1`, 성장 정책 해시는 `6e60255c851ff333322e23e10a35f8856c3181d11fa842d56c382aaa45cffb85`로 동일했다.

배포 준비 중 이전에 추가된 독립 APK 패키징 파일 10개가 웹 업로드 대상에 포함되어 Pages 한도 20,000개를 초과한 20,010개임을 확인했다. `packaging/onestore/`, `scripts/onestore/`, 새 네이티브 테스트 `tests/android-native/StoreDistributionTest.java`만 웹 배포에서 제외한다. 원본·패키징 기능·기존 웹 파일을 보존하고 배포 파일 수/스테이징/원본 해시를 검증한다. 실제 게임 런타임에서 해당 파일을 참조하지 않음을 확인했다.
