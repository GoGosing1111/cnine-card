# 무한의탑 도전 버튼 계정 연결 수정 · 2026-10-22

실제 로그인 객체는 `apiUserToLocal()`에서 서버 ID를 `serverUserId`에 저장한다. 기존 도전 코드는 존재하지 않는 `user.id`를 숫자로 변환해 NaN끼리 비교했고, 리소스 로딩 직후 전투 요청을 보내기 전에 중단했다. busy 상태도 남아 후속 클릭이 무반응이었다. 기존 격리 화면은 `{id:7}`을 사용해 이 불일치를 재현하지 못했다.

## 변경

- 도전 시 계정 확인, 전투 복구 세션 키, 성장 기록, 내 순위 표시를 동일한 유효 서버 ID로 통일한다. 기존 숫자 `id` 형식은 호환한다.
- 리소스 로딩 중 계정이 바뀌면 시작 요청을 보내지 않고 잠금을 해제한다. 중복 클릭·화면 전환 가드는 유지한다.
- 과거 공용 0번 키를 자동으로 가져오거나 다른 계정 기록과 합치지 않는다. 운영 서버의 본인 미완료 전투를 읽어 현재 계정 키에 복구한다.
- 클릭 직후 기존 전용 ImageGen 버튼에 “전투 준비 중…”과 안내 문구를 DOM으로 표시한다. 새 박스나 이미지 대체 도형을 추가하지 않는다.
- `index.html`의 탑 UI·컨트롤러 캐시 값을 함께 갱신한다. 서버 판정·보상·진행도·이미지 원본은 변경하지 않는다.

## 재현과 검증

- 수정 전 실제 로더 + `{serverUserId:7}` 조건에서 리소스 준비 완료 후 버튼을 두 번 눌러도 `tower/start` 0회, 모달 미표시를 재현했다. `reproduction.json`, `390-before.png`에 보존했다.
- 신규 회귀 4개: 실제 `apiUserToLocal` 출력으로 진입, 계정별 복구/기록, 로딩 중 계정 전환/중복 클릭, 유효하지 않은 로그인 안내.
- PC 1440px / 모바일 390px에서 실제 게임 로더·컨트롤러·V3 전투 번들과 격리 DB의 실제 Tower API를 연결했다. 1층 버튼 클릭/터치→즉시 준비 표시→시작 요청 1회(200)→전장과 일시정지 조작을 확인했다.
- 모바일 새로고침 후 동일 영수증 복구, 추가 시작 요청 0회, 계정 7 전용 세션 키, JS 오류 0·가로 넘침 없음·음소거를 확인했다. 운영 계정 사용과 운영 DB 쓰기는 없다. 기술 검수는 사용자 시각 승인이 아니다.
