# 시즌패스 최초 판매일 기준 일괄 수령

사용자 최종 지시 `패스 첫 개방 시점부터 현재까지 수령`, `패스판매일 기준`을 적용한다. 앞선 매월 1일 선택과 구매일부터 계산하던 기존 정책을 대체한다.

## 기준과 동작

- 최초 판매 신청 ON 감사 **44138**: `SERVER_SUPPORT_APPLICATION_SETTINGS`, `processedAt=1791647946414`, **2026-10-11 00:59:06.414 KST**. 보상표를 먼저 켠 10월 10일 밤이 아니라 실제 판매 신청을 개방한 날을 1일차로 삼는다.
- `supporter_season_pass_v1.salesStartsAt`에 고정한다. 10월 20일은 10일차이며 늦게 구매한 활성 후원자도 1~10일차 미수령분을 기존 **미수령 보상 모두 받기** 버튼으로 받는다.
- 기존 개인 구매일 달력에서 받은 보상은 받은 **일차**를 판매일 달력에 대응시킨다. 예: 10월 17일 구매 후 DAY 1을 받았다면 판매일 기준 DAY 1은 수령 완료이고, DAY 7을 막지 않는다. 이전 영수증과 지급 내역은 수정하거나 삭제하지 않는다.
- 기존 날짜 영수증과 판매일 달력의 날짜 영수증은 구분한다. 같은 보상 일차·같은 판매 달력 날짜의 중복 지급은 계속 막는다. 확정된 이전 요청은 결과만 복구하고, 확정되지 않은 구매일 기준 요청은 새 기준을 다시 불러오게 한다.
- 구매 후 30일 이용 기간과 연장 기간을 줄이지 않는다. 구매 전 지난 날짜를 추가로 열되, 기존 유료 기간 마지막 유효 KST 날짜는 보존한다. 30일 보상표는 판매일 기준으로 이어지며 기존 마지막 부분 날짜의 추가 31일차 지급 제한을 유지한다.
- 만료·중지·패스 OFF에서는 새 보상을 지급하지 않는다. 보상표, 수량, 계정 가입/인증 조건, CMS 권한, 계정 잠금과 보상 거래 보호는 유지한다. 운영 변경 자체로 계정에 보상을 자동 지급하지 않는다.

## 변경과 검수

- 날짜 공통 계산, 패스 조회·단건·일괄 수령을 동일한 판매 기준으로 연결한다. CMS 저장은 서버가 고정한 `salesStartsAt`을 보존한다.
- 기존 시즌패스 전용 이미지 버튼과 프레임을 유지하고 실제 판매 시작일과 수령 기준만 DOM 안내로 표시한다.
- SQLite/PostgreSQL 관련 API 회귀 **47개 통과**: 늦은 구매, 기수령 일차 보존, 미래 차단, 연장/재등록, 만료/OFF, 구버전 요청, 단건/일괄 경쟁, 보상 실패 롤백과 복구.
- 운영 설정 작업 회귀 **2개 통과**: 감사·영수증 원자 저장, 반복 실행 무변경, 잘못된 개방 증거 차단, 감사 실패 롤백, 실제 dry-run 롤백 보존.
- PC 1440 / 모바일 390에서 실제 클라이언트와 PostgreSQL 테스트 서버로 확인: 10월 17일 구매·DAY 1 기수령 → 10월 20일 미수령 9일, 응답 유실 후 복구, 재접속 자동 지급 없음, 중복 클릭 차단, 장비 보상 여러 거래 자동 연결. 화면·브라우저 기록은 `docs/qa/supporter-pass-sales-start-20261020/`.
- 화면 검사는 기술 검수이며 사용자 시각 승인으로 기록하지 않는다.

1. 설정이 없는 동안 기존 동작을 유지하는 호환 코드를 관련 검사만 포함한 scoped 배포로 반영한다.
