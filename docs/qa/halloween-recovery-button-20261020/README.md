# 할로윈팩 복구 버튼 응답 대기 수정

사용자 보고는 족게이다 계정의 할로윈팩 개봉 정지이며, 추가 확인에서 ‘이전 개봉 결과 확인 또는 복구 안내’가 보이고 복구 버튼도 눌리지 않는다고 답했다.

## 운영 기록 확인

- 2026-10-20 13:26~13:30 KST 읽기 전용으로 ID 4111 / 족게이다를 확인했다. 마지막 할로윈 개봉은 13:09:21, 10회이며 완료 상태다.
- 최근 12건 모두 실제 운영의 영수증 조회 함수로 재구성했고, 획득 원장과 개봉별 100억 코인 차감 12건이 일치했다. 마지막 요청의 지급 용병은 홍련·로젤이다.
- 미완료 공동 거래와 계정 변경 잠금은 0건이다. 운영 계정·잔액·카드·추첨 결과·발행량을 수정하지 않았다.
- 계정 단위 코인 로그 전체 조회는 20초 제한으로 중지하고, 개봉 시각의 2분 범위와 요청 번호로 좁혀 검증했다. 운영 쿼리 제한을 해제하지 않았다.
- 이용자의 브라우저 내부 저장소·네트워크 장애 원인 자체를 직접 확인한 것은 아니다. 서버 기록 정상과 사용자가 알려준 비활성 버튼 현상을 기준으로 클라이언트 복구 경로를 재현했다.

## 수정

- 미확정 요청이 있으면 새로운 1회/10회·자동 개봉은 잠그되 **개봉 결과 다시 확인**은 조회/개봉 응답 대기 중에도 누를 수 있게 한다. 자동 개봉 중에도 같은 복구 버튼을 표시한다.
- 복구를 누르면 기존 화면의 대기만 종료하고 동일 요청 번호를 보존한 채 계약실을 다시 연다. 재진입은 영수증 GET만 수행하며 새 추첨·자동 개봉을 시작하지 않는다.
- 이전 화면은 AbortSignal과 로컬 대기 취소를 함께 사용한다. 취소 신호를 무시한 통신의 뒤늦은 응답도 새 화면의 저장 결과·잔액 알림·대기 요청을 변경할 수 없다.
- 서버가 여전히 미확정이라고 응답하면 대기 기록을 유지한다. 그 후 명시적으로 ‘이전 결과 확인’을 눌렀을 때만 기존 요청을 재전송한다. 기존 계정/브라우저 잠금과 서버의 중복 지급 방지를 유지한다.
- 할로윈 전용 승인 이미지와 레이아웃을 유지한다. 가격·확률·재고·서버 거래 코드는 변경하지 않는다.

## 검증

- 새 세션 회귀 3개: 네트워크 전 대기 기록/복구 알림, 종료된 화면의 지연 응답 차단, 재진입 읽기와 명시적 동일 요청 재전송.
- 자동 개봉 기존 검사 10개 통과: 순차 개봉·중지·응답 유실·계정/탭 잠금·실제 격리 PostgreSQL 거래.
- Chrome 1440px/390px에서 최초 복구 조회 정지, 개봉 응답 정지, 자동 개봉 응답 정지 및 여전히 PENDING인 경우를 확인한다. 복구 버튼 실제 클릭, 추가 POST 없음, 자동 개봉 재시작 없음, 늦은 응답 무시, 가로 넘침/스크립트 오류 없음. 상세는 `report.json`이다.
- 이전 2026-10-17 서버 확률/소진 검사 5개는 바토리 추가와 재고 10→11 변경 전의 고정 표본/수량을 사용해 실패했다. 해당 서버 정책·추첨 구현·검사는 이번 변경 전과 동일하다. 무관한 확률/재고 테스트를 수정하거나 전체 검사를 반복하지 않는다. 관련 클라이언트 및 자동 개봉 사례는 통과했다.
- 기술 검증을 사용자 시각 승인으로 기록하지 않는다.

## 배포

직전 운영 소스 `f33ada9e8c68d6164bc63d6119db16878e478e18` 기준의 작은 클라이언트 수정이다. 지정 scoped 배포에서 새 세션 3개와 자동 개봉 10개, 출시 정책 및 Worker 검사를 실행한다. 운영 반영 결과는 후속 기록에 추가한다.
