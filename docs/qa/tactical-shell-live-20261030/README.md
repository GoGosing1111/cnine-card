# 로비·사이드메뉴·전체메뉴·아이콘·콘텐츠 현황 한정 배포

최신 사용자 지시: “로비,사이드메뉴,전체메뉴만 개편하고 나머지 페이지는 기존대로 냅둬 일단”, “내가 말한거만 라이브 배포”, “아이콘까지”. 앞선 전체 페이지 개편 지시보다 이 범위가 우선한다.

배포 준비 중 후속 “콘텐츠 현황도 개편해”에 따라 로비의 콘텐츠 현황과 해당 전체 보기 창을 포함했다.

후속 “화면 폭 너무 큰데 세로가”, “콘텐츠현황 폭 말하는거임”에 따라 콘텐츠 현황의 세로 높이를 축소했다. 큰 목록형 초안은 최종안이 아니다.

## 포함 범위

- 로비 오른쪽 창: 사용자가 표시한 참조의 반투명 프레임, 상단 아이콘 탭, 구분선 제목, 출전 버튼.
- 공유 상단의 양끝 배경 채움, 사이드메뉴와 모바일 하단 메뉴, 전체 메뉴 검색·분류 창.
- 기존 작업의 은색 메뉴 아이콘 64종을 원본 WebP 바이트 그대로 연결. 재생성하지 않음.
- 콘텐츠 현황은 같은 프레임과 아이콘으로 PC 3개/태블릿 2개/모바일 1개 요약. 나머지는 전체 보기 창에서 기존 목록 그대로 확인. 프레임 포함 높이 PC·태블릿 94.8px, 모바일·320px 122.8px. 가로 스크롤 없음.
- PC 1440×900, 태블릿 768×1024, 모바일 390×844, 작은 모바일 320×740 반응형.

## 보존 범위

운영 기준은 Wrangler 조회로 확인한 Pages `e3f20234-42f2-4796-b6e7-ca5594256379`, 소스 `834d3f2c9ef6876d6da7cdadfcf28cd05409e935`다. 그 이후 origin/main `f3578c740`의 문서·운영 영수증을 보존한다. 해당 작업들을 재실행하지 않는다.

페이지 내부 CSS, PVE·기존 아이콘·쉘 어댑터·도시 코드와 functions/workers는 운영 기준 그대로다. `js/app.js`는 로비에서 연 콘텐츠 창 표시 및 상태 재렌더 뒤 표현 갱신 2줄만 추가했고, 원본 데이터/시간/이동/갱신 로직은 그대로다. 다른 진입 파일의 변경은 공유 로비 번들의 캐시 URL뿐이다. 전역 `tactical-ui-20261030.css` 및 `commandInteriors` 주입을 배포하지 않는다. 콘텐츠 현황 CSS는 로비 소유 목록과 로비에서 연 창에만 적용한다.

앞선 페이지 내부 개편은 브랜치 `codex/tactical-ui-20261030`, 커밋 `9785fcaed`에 보존했다. 해당 커밋과 이전 내부 화면 스크린샷은 이번 배포 결과가 아니다.

## 검수

- 실제 메인 로더와 격리 API fixture로 PC·모바일 메뉴 열기/닫기, 사이드 분류, 검색→기존 토벌 화면 이동을 확인.
- 1440/768/390/320px에서 문서 가로 넘침 0. 열린 메뉴 내부 scrollWidth와 clientWidth 동일. 관측된 메뉴 아이콘 깨짐 0.
- PC 상단 좌표 0→1440px, 배경 `rgb(21, 43, 61)`. 모바일/태블릿 상단은 세로 스크롤바를 제외한 가용 폭 전체를 채움.
- 토벌 내부는 기존 스타일과 기본 아이콘을 유지하고 새 메뉴만 함께 표시.
- 콘텐츠 현황 4크기에서 요약/전체 목록 가로 넘침 0·이미지 누락 0. 카운트다운 갱신, 전체 보기 열기/닫기, 경매장 이동·로비 복귀 확인. 최종 수치는 `operations-qa.json`에 기록.
- 초기 fixture 재수화 중 320px 메뉴 열림 확인 1건은 실패 후 실제 로비 복귀 및 열림 재검증. 최종 `menu-small-confirmed`와 스크린샷이 통과 기록.
- 소스 범위 감사: 15개 진입 파일의 캐시 외 변경 없음, 기존 페이지 CSS 및 서버 변경 없음, 전역 내부 테마 없음.
- 관련 자동 검사는 공식 scoped 배포에서 한 번 실행: 아이콘 64종 해시/배포 용량, `test:lobby`, `test:navigation`, `test:release-policy`. 기존 복구된 클랜전 메뉴 및 로비 독립 캐시를 반영해 오래된 검수 단언 두 곳만 현재 계약에 맞춤.

증거: 프로젝트 루트 `operations/tactical-ui-20261030/scoped-*`. 로컬 검수용 계정과 고정 fixture를 사용했으며 운영 계정·재화 직접 쓰기, 메시지 전송 없음. 별도 유지관리·정리·예약 없음.

## 배포 계획

`SCOPED_DEPLOY_BASE=834d3f2c9ef6876d6da7cdadfcf28cd05409e935`, `npm run deploy:production -- --scoped`. 소스 커밋/푸시 후 공식 절차로 배포한다. 실제 배포 완료와 공개 파일 검증 결과는 별도 결과 기록에 추가한다.
