# SSS 리미티드 조각 전용 제작 · 독립 발행 수량

사용자 요청: SSS 리미티드 조각으로 제작하는 용병의 발행 수량을 분리하고 5장씩 추가할 수 있게 한다. 후속 답변으로 전체 SSS 리미티드에 별도 제작식을 준비하고, 조각 수량·코인·마스터의 별·성공률은 CMS에서 직접 입력하며 입력 전 제작 잠금을 확정했다.

## 적용 범위

- 발테르·헬리오스·천룡검황 진무·카이론·시라누이·족로·레오넬·제로·프라임 레퀴엠·제너럴 족·은설·각성 오메가 12종. 명시한 목록만 등록하며 미래 신규 용병을 자동 추가하지 않는다.
- 용병마다 `WORKSHOP_SSS_LIMITED_SHARD_V_*` 제작식과 `mercenary_limited_shard_craft_v1:V-*` 정책을 사용한다. 초기 전용 발행 한도 5장, 발행 0장. 최초 정책 저장 전에도 CMS에 미입력 초안으로 표시한다.
- OWNER CMS → 제작소 관리 → **SSS 리미티드 조각 발행수량**. 용병 선택 후 **발행 한도 +5장**으로 증가한다. 발행·잔여·한도를 별도로 표시하며, 조건 저장과 한도 추가는 독립 작업이다. 한도 증가는 비용·확률·운영/공개 상태를 바꾸지 않는다.
- 전용 필수 재료는 `MERCENARY_SSS_LIMITED_SHARD`. 수량·코인·마스터의 별·성공률은 모두 `null`, 운영/공개는 OFF다. 모든 값을 직접 입력한 뒤 운영·유저 공개를 별도로 켜야 제작 가능하다. 원가 0도 직접 입력해야 한다.
- 일반 SSS 조각 자동 대체·합산은 금지한다. 기존 일반 조각 제작식에 리미티드 조각을 새로 지정할 수 없으며 전용 제작식을 사용한다. 기존 카이론/족로의 일반 제작 비용·성공률·발행 기록·한도 8/2장은 보존한다.
- 팩·큐브·직접 지급과 분리해 **해당 제작식의 성공 원장만** 집계한다. 실패·재시도는 발행량을 늘리지 않으며 성공/실패 시 기존 제작 정책대로 재료와 비용을 한 거래로 차감한다.
- 기존 승인 원화·전투·성장과 은설 PVE 전용, 시라누이 중장 편성 조건을 유지한다. 진무/족로 제작 획득자는 성공 원장·완료 영수증·일치하는 획득 기록을 모두 검증한 뒤 편성/랭크 접근을 허용한다.

## 정합성과 검증

- +5 저장은 OWNER 권한, 현재 수정 버전, 요청 ID를 검사한다. 정책·감사 로그·완료 영수증은 한 거래다. 중복 요청은 동일 결과를 복구하며 다른 탭의 오래된 버전은 거부한다. 제작과 한도 변경은 같은 정책 행을 잠근다.
- 제작 직전 한도와 정책을 거래 안에서 다시 검증한다. 마지막 수량 경합의 패자는 재료/코인을 차감하지 않는다. 지급/감사 실패는 원복한다.
- 제작식 조회는 전체 정책·레시피·성공 수량을 3회 묶음 조회한다. 14개 제작식을 건별 조회하지 않는다. 기존 테이블을 사용하며 DB 기반/마이그레이션/의존성 변경은 없다.
- 새 전용 제작/발행 검사와 기존 족로·카이론·조각 재료 검사 26개. SQLite와 PostgreSQL 호환 계층에서 분리·5장 소진·+5·동시 요청·재시도·원복·권한·보유자 접근을 검증한다.
- 실제 CMS와 제작소 컴포넌트를 격리 SQLite에 연결해 PC 1440, 모바일 390/320에서 확인했다. 미입력 잠금 → +5 → 초안 저장 → 공개/OFF → ON → 제작 성공·결과명·차감 1회, 폼 미저장 값 보존·필수 재료 잠금·화면 넘침 0을 확인했다. 승인 남색 패널·연두 버튼과 짙은 글씨를 사용한다. `browser.json` 및 PNG 참조. 예시의 100%와 저가 비용은 격리 검수 값이며 운영에 저장하지 않는다.
- 운영 DB는 READ ONLY 거래로 사전 확인했다. 카이론 일반 제작 revision 3·성공 4장, 족로 revision 2·성공 0장. 기존 재료/비용/확률은 `production-before.json`에 기록했다. 운영 계정·설정 쓰기 없음.
