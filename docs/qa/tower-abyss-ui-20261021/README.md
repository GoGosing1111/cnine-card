# 무한의탑 UI 전면 개편 — 나락의 시련 (2026-10-21)

사용자 요청: “무한의탑 스킵 불가능하게하고 자신의 성장을 한계를 태스트하게끔 나락 느낌으로 리뉴얼 구상해”에 이어 **“UI부터 싹 다 뜯어고쳐 모든걸”**.

## 이번 반영 범위

- 기존 네이티브 PVE 무한의탑 진입 경로를 유지하고 내부 화면을 전면 교체했다. 이전 무한의탑 입구 UI 유지 지시는 이번 명시적 전면 개편 지시로 대체한다.
- 입구/현재 도전층/수호자/개인 최고층/출전 전투력, 출전 편성 확인, 성장 기록, 순위, 안내, 로딩, 미개방, 잠금, 완료, 연결 오류 화면을 새로 구성했다.
- 내장 ImageGen으로 검은 석재 성소, 전용 프레임, 버튼, 봉인 문장을 각각 생성했다. 모든 타워 패널·조작부·층 표식·전투 HUD·결과에 실제 이미지를 연결한다. 숫자와 문구는 DOM이며 9-slice로 모서리 비율을 보존한다.
- 실제 연속 전투 엔진의 Tower 배경도 새 성소를 사용한다. 공통 격자/SD 배치/승인 캐릭터 리소스/전투 카드 도크는 유지한다. 다른 전투 모드의 배경·전투 정책을 변경하지 않는다.
- 무한의탑 자동진행과 `결과 보기` 버튼을 제거했다. 한 층의 전체 타임라인을 재생한 다음 결과와 다음 층 확인을 제공한다. 일시정지/재개와 백그라운드 일시정지는 유지한다. 폐차장의 기존 결과 보기 동작은 유지한다.
- 전투 HUD는 현재 층, 서버 이벤트에 기록된 남은 공식 시간, 수호자 소환 진행도를 표시한다.
- 결과는 공식 공략 시간, 수호자 잔여 체력, 첫 전투 불능 시점, 최종 생존 인원, 실제 보상을 표시한다. 같은 층·규칙 버전·제한 시간·수호자 전투력이 같은 이전 기록만 비교한다.
- 이 기기의 계정별 localStorage에 최근 40회 요약만 저장한다. 다른 계정/기기와 섞거나 서버 전체 기록처럼 표현하지 않는다. 중복 영수증/복구 재생을 중복 기록하지 않으며 저장소 오류가 결과 표시를 막지 않는다.
- 기존 sessionStorage 전투 복구 키를 유지한다. 중복 클릭과 화면 이탈 중 늦게 끝난 로딩/API 응답으로 새 전투가 열리지 않게 한다. 전투 중 배경 스크롤과 Escape 종료를 막고 Tab 초점을 전투 안에 유지한다.
- 장비 획득 연출은 기존 경로를 유지하고 별도 보상창의 키보드 초점을 방해하지 않는다.

## 운영 정책과 한계

이번은 UI 단계다. 서버 보상·입장·층 수·전투력·제한 시간·현재 진행도·운영 ON/OFF를 바꾸지 않았다. 승리 시 한 층 진행, 완료층 재진입/최고층 완료 정책은 현재 API 기준이다.

기존 `tower/fight` API가 응답 전에 전투 결과와 보상을 정산하는 구조도 유지된다. UI의 결과 버튼/자동 진행 제거를 **서버 차원의 우회 불가능한 완전 스킵 방지**로 주장하지 않는다. 새 층 구조·전투 시간·성장 한계 밸런스·서버 정산 시점 개편은 아직 반영하지 않았다.

## 이미지 원본과 제작 근거

- 생성 도구: 내장 `image_gen.imagegen`.
- 최종 프롬프트: `prompts.json`.
- 원본: `sources/{sanctum,frame,button,seal}.png` (생성 원본 바이트 보존).
- 파생 이미지: `assets/ui/tower-abyss-20261021/{sanctum,frame,button,seal}.webp`.
- `art-manifest.json`: 원본/파생 SHA-256, 해상도, alpha, 용량.
- 기계적 파생 작업: 투명 여백 trim, WebP 인코딩. 승인 캐릭터 원본은 수정하지 않는다.
- 사용자 시각 승인 상태: **PENDING_USER_REVIEW**. 아래 검사는 기능/기술 검수이며 사용자 승인으로 기록하지 않는다.

## 검수

- `npm run build:v3`: 공통 소스의 canonical 빌드 성공. 배경/런타임 버전과 10개 소비자의 생성 번들/해시 동기화.
- `tests/tower-abyss-ui-20261021.test.mjs`: 실제 수치/누락값, 다른 계정 분리, 40회 한도, 영수증 중복, 비교 조건 분리, 저장소 차단, Tower만 결과 버튼 제거, 이중 클릭/늦은 입장 취소.
- `tests/pve-combat-only-v2094.test.mjs`: SQLite/PostgreSQL 실제 운영 route의 한 층 진행·최고층 완료·실패 무보상·재요청 무중복·승인 몬스터/네이티브 진입.
- `tests/pve-battlefield-entry-v2117.test.mjs`: 실제 빌드 버전/로더/재연결, Tower 연속 전투 배경과 다른 콘텐츠 배경 보존.
- 관련 기능 검사 총 20개와 Tower 배포 자산 검사 1개. 최종 scoped 배포에서 UI·엔진 연결·Tower/봉인전 파일 수 제한 검사를 실행한다.
- Chrome 검사 도구의 기존 프로필 충돌로 내장 브라우저로 전환했다.
- PC 기본 뷰포트 1264×720, 모바일 390×844·320×740에서 직접 확인했다.
- 격리 SQLite에서 실제 `tower/status`와 `tower/fight` route로 만든 승/패 응답을 shipping UI/controller/V3 renderer에 연결했다. 운영 계정/재화를 변경하지 않았다.
- PC 입구·편성·승리 결과, 모바일 입구·기록 필터·순위·전투 일시정지/재개·패배 결과·연결 오류·미개방·잠금·완료·미편성을 확인했다.
- Tower 실제 재생에서 결과 보기 버튼 0개, 일시정지/재개 정상. 새로고침 시 저장된 동일 전투 복구 후 결과 표시를 확인했다.
- 생성 이미지 로드/가로 넘침 없음, 터치 대상 높이 최소 44px. 모바일 전체 UI는 스크롤 가능하고 전투 중 배경 스크롤은 잠근다.
- 발견해 수정한 문제: 공통 결과창의 bottom/height 규칙으로 인한 잘림, 연속 전투 CSS의 늦은 로딩으로 인한 일시정지 버튼/HUD 겹침, 320px 상단 버튼 줄바꿈.
- 실제 승/패 전투에서 JS 오류 없음. 기존 공통 Pixi의 미사용 apocalypse impact atlas cache 경고 1건은 다른 콘텐츠 자산의 사전 조회 경고이며 현재 전투 완료에 영향을 주지 않았다.
- 화면 증빙: 이 폴더의 `desktop-*.png`, `mobile-*.png`. `build-fixture.mjs`, `fixture.json`, `runtime-scripts.json`, `index.html`, `serve.mjs`는 격리 검수 전용이며 운영 Pages에서 제외한다.

## 배포

준비 시 운영 소스 `99120149ff676e033c2fffb748ed9c1cb2bc390c` / Pages `ad516cc9`를 재확인했다. 작업 중 먼저 반영된 봉인전 소스 `ea0affd78` / Pages `48e30697` 위로 재배치하고 봉인전의 코드·이미지·운영 정책을 보존했다.

두 작업을 합친 운영 파일이 20,005개가 되어 Pages 제한을 초과했다. 런타임에서 참조하지 않는 Tower 작성용 문서 4개와 이미 번들된 `source/app.mjs` 1개만 배포 대상에서 제외해 정확히 20,000개로 맞췄다. 다섯 원본은 Git에 보존한다. 실제 연결된 기획 문서, 기존 프리뷰의 HTML/번들, 새 이미지 4개는 계속 배포한다. `tests/tower-abyss-delivery-20261021.test.mjs`가 원본·파생 해시, 런타임 포함, 작성 파일 보존, 스크립트 순서와 전체 파일 수를 확인한다.

무한의탑의 국소 UI 개편이고 공통 엔진 변경은 Tower 배경 연결/캐시 버전뿐이다. DB·인증·정산 정책·의존성 변경 없이 `npm run deploy:production -- --scoped`를 사용한다. 원본/QA는 docs/qa 아래에 보존하고 운영 파일은 새 WebP 4개와 JS/CSS 2개만 추가한다. 배포 완료 후 실제 소스·파일 해시를 아래에 기록한다.
