# iPhone 전투 중 검은 화면·페이지 종료 제보 — 2026-11-02

첨부 33.93초 영상의 21초 부근에서 전장/용병이 검게 사라지고, 30초에는 iOS의 반복 페이지 오류가 보인다. 하단 카드/DOM 대사가 남아 있는 동안 렌더링이 먼저 손상된다. 문의는 격전지·군단토벌·랭크전에서 10판 중 8판이며, 기종/OS/기기 종료 로그는 제공되지 않았다. 실제 재현 빈도나 원인을 확정한 수치로 취급하지 않는다.

10월31일의 종료 후 자원 반환과 별도로 진행 중의 큰 원본 아틀라스가 메모리를 점유하는 것을 확인했다. 진무 14개 동작/효과 이미지가 RGBA 추정 178.5MiB였다. 아이폰 조건의 공통 이미지 로더에서 직접 사용하는 전투 이미지만 축소하여 44.625MiB로 줄였다. 원본 파일을 수정하지 않으며 Pixi 논리 좌표/UV/프레임 수/앵커/배우 크기는 유지한다. 미세한 픽셀 해상도는 줄어든다. JSON 스프라이트 시트는 별도 scale 규칙 때문에 제외한다.

아이폰/iPad는 디코딩과 축소를 최대 두 장 동시에 처리한다. 한 장 제한의 초기안은 격전지의 14초 로딩 제한에 걸려 두 장으로 조정하고 재검수했다. Android/데스크톱의 동시수와 원본 이미지 해상도는 유지한다. 축소 옵션 미지원·실패는 원본을 보존하며, 성공 시 원본 ImageBitmap은 즉시 반환하고 축소본은 마지막 소유 종료 시 반환한다. 원본 원화·동작·스킬 타격·서버 수치·보상·입장·계정 데이터는 수정하지 않는다.

동일 Chromium 아이폰 UA PVE에서 고유 캐시 이미지 RGBA 추정 256.56→122.69MiB(약52.2% 감소). 이는 전체 RAM/GPU/프로세스 최고 메모리 또는 실제 아이폰 측정이 아니다. WebKit 모바일 PVE/PVP 결과와 복귀, Chromium 데스크톱 PVE/PVP를 확인했다. 실제 iPhone 모든 기종/OS 또는 문의자의 80% 빈도 해결을 보장하지 않는다.

검수 원본/전후 스크린샷/프레임/스크립트는 프로젝트 본체 operations/iphone-battle-report-20261102/에 보존한다. 동시에 다른 UI 작업이 기존 release-checkout에 진입해 버전을 변경하여, 이 변경은 기존 tmp/cardgu-live-20261027 체크아웃으로 분리했다. 의존성 전체 복사나 용량 유지관리·예약·운영 계정 쓰기·메시지는 없다.

브라우저 전투/재입장·배포 검수 최종 결과는 browser.json과 completion.json을 따른다.

최종 동시수 2에서 WebKit 390px 토벌/랭크의 실제 시작 버튼→전투→결과→복귀, 군단토벌 iframe 3회 진입→종료 후 캔버스/이미지 0을 확인했다. 격전지는 실제 서버의 3인 payload로 진무 스킬/프레임/대사/종료를 확인했다. Windows WebKit의 격전지 포털 스크린샷은 변경 전후 모두 캔버스가 빠지는 현상이 있어 시각 통과로 세지 않는다. 같은 실행의 WebGL 캔버스 추출은 전장/12배우가 정상이며 Chromium 포털 화면도 정상이다. 문의 영상의 실제 iPhone 종료와 이 검수 환경의 캡처 문제를 같은 원인으로 단정하지 않는다.
