# 무한의탑 + 격전지 초월 · 함께 배포할 준비본

**상태: 준비 완료, 라이브 미반영.** `codex/tower-coop-prepare-20261102`는 무한의탑 준비 커밋 `f1cdcaa0c` 위에 격전지 변경을 더한 분기다. main 병합, 게임/Worker 배포, 운영 설정 변경, 운영 계정 전투·보상 수령은 하지 않았다. 사용자 지시대로 일어난 뒤 무한의탑과 함께 반영할 때 사용할 준비본이다.

## 반영 내용

- 무한의탑 **121~150층**, 신규 구간만 **30% 상향**, 기존 1~120층 유지. [기존 탑 준비 기록](../tower-121-150-20261102/README.md)을 그대로 포함한다.
- 격전지 기존 일반·격전·극한 위에 **초월**을 추가한다. 각 참가자 카드 2장 + 용병 2명(SSS 1명·SS 1명), 각 용병 Lv.21·최종 돌파를 난이도 검수 가정으로 삼았다. 새 레벨 입장 제한은 없다.
- 격전지 편성 화면에서 용병과 카드에 **별표 즐겨찾기**를 저장한다. 종류별 즐겨찾기만 보기·우선 정렬·검색/등급 필터로 바로 선택한다. 별표는 편성 선택과 별도 버튼이며, 계정별 서버 저장으로 재진입 시 유지된다. 각 종류 최대 100개, 보유·출전 가능한 대상만 추가할 수 있고 보유하지 않게 된 항목도 해제할 수 있다. 다른 콘텐츠의 도감/전체 편성 즐겨찾기로 확장한 변경은 아니다.
- 신규 대기방은 **2명 전원 준비 → 방장 ‘2인 출발’**, **3명 전원 준비 → 자동 출발**이다. 1인/비방장/미준비 출발, 출전 후 합류를 거부한다. 기존 저장 대기방은 기존 3인 조건을 유지한다. 현재 1용병 구성에서도 2인 출발이 작동하고, 2용병 출시 후에는 분대당 2용병이 연결된다.
- 행동력은 출발한 참여자만 각 1회 차감한다. 두 사람 중 한 명이라도 부족하면 전원 차감하지 않는다. 미참가 세 번째 계정에 차감·보상을 만들지 않는다. 기존 보상 횟수·재충전·이탈 규칙을 유지한다. 전장 명단도 실제 2/3분대 수대로 표시하도록 수정했다.

## 극한의 정확히 2배 보상

2026-11-02 KST 읽기 전용 운영 설정 r13을 기준으로 한다. 기존 3난이도 수치·보상 행은 그대로 보존한다.

| 보상 | 기존 극한 | 신규 초월 |
|---|---:|---:|
| 기본 코인 | 2,000억 | **4,000억** |
| 마스터의 별 | 200만 | **400만** |
| 엠퍼러 에너지 | 1개 | **2개** |
| 펫 봉인구 | 3개 | **6개** |
| 펫 잠재력 물약 | 1개 | **2개** |
| 추가 선택 최소 코인 | 300억 | **600억** |
| 추가 선택 용병/재료 | 기존 수량 | **2배 수량** |

추가 선택 후보와 가중치는 극한과 같다. 신규 `COOP_TRANSCEND` 콘텐츠에만 서버 수량 배율 2를 적용해 당첨 수량과 대체 최소 보상 모두 2배다. 예를 들어 용병은 당첨 시 2장이다. 기존 극한·다른 콘텐츠의 보상이나 추첨 확률을 변경하지 않는다. CMS에는 배율을 안내하고, 중복 보유가 불가능한 이동수단은 초월 선택 보상에 등록할 수 없게 했다. 기존 선택 정책의 일반 수량 상한을 전체적으로 올리지 않았다.

## 난이도와 검수 결과

초월 적 능력치는 인원·아군 전투력에 따라 바뀌지 않는 고정값이다. 기본 전투력은 일반 적 **12.96억**, 준보스 **102.48억**, 최종 보스 **162억**이다. 설정 HP 배율은 48/48/48/60/72배, 공격 3배·방어 1.5배, 연속 공격 3/3/3/4/4회, 강제 행동 주기 2다. 종별 고유 보정과 기존 2용병 보정(HP 1.6배·공격 1.15배)이 추가로 적용된다. 초월에만 1,200%를 넘는 HP 설정을 실제 전투원에 반영하며 다른 난이도의 상한과 수치는 그대로다. 기존 랜덤 3단계·자동 보스 기술·180초 제한을 유지한다.

[최종 모의전투 1,024판](balance-final.json): 4개 조합/장비 조건, 2종 카드 덱, 2/3인, Lv.16/21, 극한/초월, 각 16개 시드. ICON +13 카드 메타데이터는 2026-10-12 검수 자료이고 용병 스킬·성장은 2026-11-02 조회 자료다. 펫·아바타·마법·실제 유저 전체 계정 효과를 포함한 운영 승률이 아니다. 아래는 Lv.21 균형 덱 표본이다.

| 용병 조합 · 분대 장비 보너스 | 초월 2인 | 초월 3인 |
|---|---:|---:|
| 발테르 + 블랙크라운 조은 · 2,000만 | 0/16 | 0/16 |
| 신궁 강윤 + 경찰 조은 · 5,000만 | 4/16 | 1/16 |
| 헬리오스 + 바토리 · 5,000만 | 0/16 | 0/16 |
| 발테르 + 블랙크라운 조은 · 1억 | 15/16 | 16/16 |

같은 조건의 극한은 모두 16/16승, 평균 7초 미만이었다. 초월 통과 표본은 강윤 조합 약 172~174초, 최고 장비 발테르 조합 약 89~98초였다. 인원이 늘면 행동 순서·공용 효과가 달라져 모든 조합에서 3인이 반드시 우세하지는 않다. 모든 Lv.21 조합의 클리어를 보장하지 않으며 기존 용병 능력치를 이 작업에서 재조정하지 않았다. `balance-power-*.json`은 조정 중 비교 기록이고 최종값은 `balance-final.json`이다.

관련 **고유 검사 83개 통과**: [검증 색인](verification.json). 신규 9검사는 기존 수치 불변·출발 권한·2/3인·즐겨찾기·실제 SQLite/PostgreSQL 행동력과 지급·선택 보상·원자 적용·재실행을 검증한다. 운영 인벤토리 두 수량 열이 BIGINT임을 읽기 전용 확인하고 PostgreSQL 검수도 동일 형식을 사용했다. 기존 CMS 검수의 누락된 `users.role/status` 열을 보완했으며 검증 조건은 그대로다.

기존 HEAD에서도 실패하는 군단 행동력 복구 2검사·과거 조합 승률 부등식 1검사·sparse 체크아웃에 없는 원화 파일 검사 1개는 신규 성공 수에 포함하지 않는다. 원본 HEAD 모듈을 별도 로컬 번들로 실행한 `baseline-*.log`에 같은 실패를 기록했다. 배포 원화는 Git에 보존되어 있고 브라우저 검수는 원본 Git 바이트를 로컬에서 읽었다.

별도 headless Chromium **PC 1440px / 모바일 390px**, 실제 격리 API·Durable Object·WebSocket으로 즐겨찾기 저장/재진입 복원/계정 분리, 2인 준비/출발, 분대별 Lv.21 용병 2명, 단일 캔버스, 전장 4용병, 결과·복귀를 확인했다. PC는 실제 준비된 초월 실패 결과, 모바일은 시간을 줄인 일반 몬스터 설정으로 승리·기존 보상 수령을 확인했다. [화면 검수](browser/report.json). 실기기·설치 앱·모든 용병 조합 검수는 아니다. `browser/failure.png`는 수정 전 실패를 보존한 자료이며 최종 결과는 `report.json`과 폭별 파일이다. 미출시 2용병 플래그는 격리 Worker 번들 메모리에서만 켰다.

## 이후 함께 반영할 때

현재 **`dualMercenaries=false`**, 탑 재등반 개편 OFF다. 새 초월 CMS가 없거나 2용병 출시 플래그가 꺼져 있으면 초월을 개방하지 않는다. 이 준비가 전체 콘텐츠 2용병 출시나 라이브 배포를 실행한 것은 아니다.

1. 최신 main 및 운영 CMS와 대조하고, 별도 준비된 2용병 출시 검증·승인을 확인한다. 탑과 초월의 해시를 둘 다 먼저 확인한다. 운영 CMS가 바뀌면 해당 계획을 재산출·검토해야 한다.
2. 이 준비 분기에 포함된 클라이언트·Worker 변경을 같은 배포본에 반영한다. 메인/원스토어 파생본·캐시 갱신을 준비했고, Worker 문법/메모리 번들·실제 전투 로더 검사를 통과했다. [공개 자산 사전 검사](delivery-preflight.json)는 **20,000/20,000개**다. 대규모 자산 복사나 원화 삭제는 하지 않았다.
3. 나중에 라이브 반영을 요청받았을 때 탑의 기존 적용 함수와 `scripts/ops/coop-transcend-20261102.mjs`의 `applyCoopExpansion`을 사용한다. 각 설정 작업은 각각 단일 원자 거래이며 두 작업 전체를 하나의 거래로 묶었다고 설명하지 않는다. 일회 키는 탑 `ops:tower-121-150:20261102:v1`, 격전지 `ops:coop-transcend:20261102:v1`이다. 지금은 둘 다 운영 완료 키가 아니다.
4. 초월 함수의 기본값은 `dryRun:true`다. 실제 반영에는 `sourceCommit`, `expectedHash`, `expectedPlanHash`, 정확한 일회 키 `authorization`, `dualMercenariesReleased:true`, `dryRun:false`가 모두 필요하다. 준비된 값은 [activation-plan.json](activation-plan.json)에 있다. 이번에는 운영에서 dry run조차 실행하지 않았다.
5. 독립 읽기 전용 연결로 두 적용 영수증, 기존 120층/3난이도 불변, 신규 30층/초월 보상을 확인한다. 과거 완료 보상을 소급 지급하거나 계정 재화·성장·진행·미완료 방을 덮어쓰지 않는다. 재실행은 이미 완료된 작업의 SELECT만 수행한다.

운영 설정 쓰기·운영 배포·main 병합·사용자 화면 조작·메시지·저장공간 유지관리·예약 없음. 현재 설정 불변 및 두 완료 키 없음은 `final-readonly.json`에 기록했다. 문제가 생기면 이미 지급한 보상이나 진행을 되감지 않고 신규 입장 중단 등 별도 대응을 검토한다.
