# 리버스랜드 코인·마별 확률 및 리페어 보상

사용자: “리버스랜드 코인을 60프로로 맞추고 마별 낮춰 그리고 핑두의 리페어 쿠폰 1개도 추가해 10%정도로 해서”.

| 보상 | 변경 확률 | 당첨 수량 |
| --- | ---: | --- |
| 코인 | 60% | 5억~2,500억, 5억 단위 유지 |
| 엠퍼러 에너지 | 5% 유지 | 5~25개, 5개 단위 유지 |
| 마스터의 별 | 14% | 5,000~5,000,000개, 5,000개 단위 유지 |
| 미스틱 에너지 | 10% 유지 | 5~5,000개, 5개 단위 유지 |
| 핑두의 감사 선물 | 1% 유지 | 5개 유지 |
| 핑두 리페어 쿠폰 | 10% 신규 | **1개 고정** |

가중치 합은 30,000이며 `18000/1500/4200/3000/300/3000`이다. 리페어는 기존 복구용 아이템 `PINGDU_REPAIR_COUPON`이다. 인벤토리 지급만 하며 자동 장비 복구나 복구 비용·강화 정책 변경은 없다.

## 보존·거래

- 일일 이용권 10장, 발급 쿠폰 150명, 등록 스트리머 및 OWNER 권한을 유지한다.
- 기존 쿠폰은 저장된 보상 그대로 사용한다. 리페어만 과거 5배 수량 호환 변환에서 제외하여 0.2개·2개·5개를 거부한다.
- 기존 다섯 종류 저장 설정은 리페어 가중치 0으로 읽는다. 화면 조회/배포만으로 OWNER 설정을 재작성하지 않는다.
- 운영 변경은 `scripts/ops/reverse-land-repair-20261020.mjs`의 단일 거래다. 기존 42/5/42/10/1 확률과 활성 아이템을 확인한 뒤 설정·감사·완료 영수증을 함께 저장한다.
- 일회 키 `ops:reverse-land-repair:20261020:v1`. 재시도는 완료 영수증을 반환하고 후속 OWNER 설정을 덮어쓰지 않는다.
- 과거 감사선물 운영 도구도 신규 설정 키를 0으로 보완하여 기존 확률 검증을 유지한다. 과거 운영 도구를 재실행하지 않는다.

## 검수

- 지급 실패 롤백, 영수증 재시도·계정 중복·쿠폰 사용 인원 한도, 실제 PostgreSQL 호환 어댑터의 인벤토리·로그 지급.
- 새 운영 거래의 드라이런/감사 실패 롤백/재실행/OWNER 편집 보존과 기존 쿠폰·재고·일일 정책 보존.
- 관련 테스트: `tests/soopketland-v2039.test.mjs`, `tests/reverse-land-repair-policy-20261020.test.mjs`, `tests/soopketland-thanks-gift-policy-20261006.test.mjs`, `tests/reverse-land-daily-reset-20261020.test.mjs`.

## 배포

리버스랜드 관련 검사와 `deploy:production -- --scoped`를 사용한다. 변경 후 운영 설정은 코드 배포 확인 다음 적용한다. 이전 배포 후 추가된 장비 전투력 감사 문서 2개는 Git에 보존하고 Pages 배포 대상에서만 제외한다. 브라우저 참조가 없으며 기존 20,000개 자산 한도를 유지한다.

배포 및 운영 적용 영수증은 완료 후 이 문서에 기록한다.
