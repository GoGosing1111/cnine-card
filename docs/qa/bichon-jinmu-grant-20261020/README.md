# 비숑 관리자 진무 직접 지급

요청: `연두 관리자 계정에 차감없이 진무 지급`
계정 확인 답변: `비숑에다 지급해`

- 대상은 비숑(ID 5663), ACTIVE OWNER다. PLAYDK 연결이 없는 관리자 계정이며 ID·닉네임·역할·상태·연결 상태를 지급 직전에 재확인한다.
- 일반 유저 ε연두з(ID 3), 연두(ID 3353)는 제외한다.
- 보상은 SSS 천룡검황 진무(V-989) 영구 1장이다. 사전 보유는 0장이다.
- 코인·구매/개봉 횟수·팩 재고·다른 보유 카드·아이템·성장·저장 덱·팩 설정은 그대로 보존한다. 자동 편성하지 않는다.

## 구현과 검증

공용 접근 판정에 ID 5663만 추가했다. 실제 소유권은 계속 필요하며 ID 1·Inception ID 2·정상 할로윈팩 당첨자의 기존 접근은 유지한다. 일반 연두 계정·다른 관리자·회수된 하이희야 계정의 접근 제한은 유지한다.

`scripts/ops/bichon-jinmu-grant-20261020.mjs`는 기존 Inception 지급 방식을 사용한다. PLAYDK 연결이 없는 이번 관리자도 LEFT JOIN으로 정확하게 조회하고 null 연결 상태까지 검증한다. USER_LOCK·3초 간격 잠금 유지 확인·DB 보조 잠금·행 잠금 아래 보유, 획득, 감사, 완료 영수증을 한 거래로 저장한다.

일회 키는 `ops:bichon-jinmu-grant:20261020:v1`다. 잘못된 계획 거부, 영수증 저장 직전 실패의 전체 롤백, 재실행 시 쓰기 없음, 보호 상태의 거래 전후 일치와 최종 원상복구를 운영 DB dry-run으로 확인했다. 상세는 `dry-run.json`이며 해당 테스트 지급은 커밋하지 않았다.

관련 검사만 실행한다: `tests/bichon-jinmu-grant-20261020.test.mjs`의 허용/차단·미보유 차단·도감·PVE/PVP 편성·단건/일괄 스냅샷·랭크 선택·성장·팩 재고 보존, 기존 Inception 회귀 2개, Worker 컴파일이다. 공용 인증·스키마·경제/전투 수치는 변경하지 않는다.

V3 빌드 후 전투 실행 번들이 동일함을 확인했다. 빌드 보고서의 공용 원본 해시만 갱신했으며 이번 접근 판정과 무관한 프리뷰/빌드 메타데이터 재생성 차이는 제외했다.

## 운영 반영

계정 정책을 scoped 배포한 뒤 실제 지급하고 독립된 읽기 전용 연결로 보유 수량·영수증·팩 재고·공개 운영 접근 정책을 확인한다. 실제 지급 결과와 배포 ID는 후속 기록으로 확정한다.
