## 운영 반영 절차

일회 키 `ops:prime-requiem-blueprint:20261026:v1`. `register.mjs`는 코드·이름·이미지 충돌을 확인하고 카탈로그 한 행·감사·완료 영수증을 SERIALIZABLE 거래로 저장한다. 기존 카탈로그·용병 제작 정책·제작 레시피 및 재료 행을 비교하며, 재실행은 후속 OWNER 편집을 덮어쓰지 않는다. 시작/로그인/재배포 자동 초기화에 연결하지 않는다.

이번 변경은 새 소비 이미지 1개와 배포하지 않는 원본/QA/일회 운영 도구뿐이다. 실제 직전 운영 소스를 기준으로 지정 `npm run deploy:production -- --assets-only`를 사용한다. 게임/Worker/메인 캐시 코드는 바뀌지 않으므로 Worker 재배포 및 무관한 게임 전체 검사는 하지 않는다. 기존 작업 폴더와 의존성을 재사용하며 새 작업 복사본을 만들지 않는다.

공개 WebP 해시 확인 → 운영 예행연습 전체 원복 → 일회 등록 → 별도 READ ONLY 연결의 카탈로그/감사/영수증 확인 → 중복 등록 추가 카탈로그 쓰기 0 확인 순서다. 실행기: `run.mjs read|dry-run|apply|verify`. 연결 문자열과 토큰은 메모리에만 유지한다.
