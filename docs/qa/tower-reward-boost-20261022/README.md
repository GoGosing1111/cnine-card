사용자 지시: “59층까지는 10배 61층부터는 5배씩 늘려”. 최신 정정: “아니 100층 이후는 안늘려도됨”.

## 적용과 보존

- 운영 CMS의 `reward_coin`과 해당 99개 행의 수정 시각만 변경한다. 난도·몬스터·시즌·운영 스위치와 다른 보상은 유지한다.
- 기존 진행도·완료 이력·계정 코인을 수정하거나 소급 지급하지 않는다. 진행 중 전투는 시작 당시 확정한 보상으로 정산하며 새 전투부터 상향된 CMS를 읽는다.
- 변경 전 `before.json`과 120층 `floor-plan.json`을 보존한다. 검토 해시가 다르면 중단하고 설정·감사·일회 영수증을 같은 SERIALIZABLE 거래에 저장한다.
- 고정 작업 키: `ops:tower-rewards:20261022:low10-high5-through100-v1`. 재실행은 영수증만 반환하므로 재곱셈하지 않는다.

## 검증

`node --test tests/tower-reward-boost-20261022.test.mjs` 관련 검사 3개 통과:
- 59/60/61/100/101 경계와 99개 변경, 누락·중복 층 및 정수 한도 검사.
- PostgreSQL에서 CMS 충돌 차단·원복 예행연습·영수증 저장 실패 시 감사와 설정 전체 롤백·반복 실행·기존 진행도/수령/미완료 기록 보존.
- 실제 배포 API 경로를 격리 PostgreSQL로 실행해 100층 2조의 시작 시 고정·미리 지급하지 않음·완료 정산·재시도 중복 지급 방지·101층 진행 확인.

운영 설정 적용 후 독립 연결 재조회 결과는 `live-verification.json`에 기록한다. 게임 실행 코드와 UI 변경이 없어 런타임 재배포는 하지 않는다.
