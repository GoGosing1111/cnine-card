사용자 제보는 27/30공세 정비실의 `결과 확인 중… / 반응로 가동 중 / 다음 공세 0초` 고착이다. 당시 브라우저 로그는 제공되지 않았으므로 최초 연출 중단의 기기별 계기는 확정하지 않는다.

## 원인과 변경

- 기존 `DefenseWorkshop`은 GSAP 완료 콜백만으로 강화 대기를 해제하고, `busy`일 때 서버가 WAVE/VICTORY/DEFEAT로 바뀌어도 정비창을 닫지 않았다. 중단/정지된 연출, 공세 전환 뒤 처음 도착한 강화 영수증, 최신 영수증이 없는 성공 응답에서 잠금이 유지되는 경로를 재현했다.
- 서버가 정비 단계를 벗어나면 진행 중인 결과 표시를 끝내고 정비창을 즉시 닫는다. 전투 중 도착한 저장 영수증은 안내로 한 번 표시한다.
- 연출 정상 완료·중단·3초 실제 시간 제한·탭 복귀가 같은 일회 완료 함수를 사용한다. 결과는 서버 영수증만 읽으며 새 강화 요청을 만들지 않는다. 수동 닫기/폐기 시 타이머와 리스너를 제거하고 이전 콜백이 다시 열린 창을 덮지 못하게 한다.
- 명령 실패나 최신 상태가 아직 없는 응답도 무한 대기를 남기지 않는다. 이미 도착한 영수증의 결과 연출은 늦은 실패 응답으로 취소하지 않는다.
- 원화·레이아웃·강화 확률/비용·공세 규칙·일일 횟수·보상·운영 설정과 서버 처리 코드는 변경하지 않았다. 운영 계정/재화/설정 직접쓰기 0건.
