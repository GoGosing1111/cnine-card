# 봉인구 전용 이미지 3종

사용자 요청: `봉인구도 새롭게 꾸며`.

내장 **image_gen**으로 파괴·수호·정화 봉인구를 각각 새로 생성했다. 흑요석과 낡은 청동 재질을 봉인룡과 맞추고 파괴는 붉은 균열/날카로운 구속 장치, 수호는 청색 수정/두꺼운 용 비늘 갑각, 정화는 보랏빛 마력/곡선형 봉인 고리로 구분했다.

- 원본: `sources/{attack,guard,purify}.png`. 생성 PNG를 바이트 그대로 보존한다.
- 실제 자산: `assets/ui/seal-battle/orbs-20261022/{attack,guard,purify}.{webp,png}`. 비율 유지 축소·투명 여백·포맷 변환만 수행하고 원본 알파를 보존한다.
- `prompts.json`, `manifest.json`에 프롬프트·해시·파생 경로를 보존한다. 사용자 시각 승인 상태는 `USER_REVIEW_PENDING`이다.

## 적용

역할 선택 탭·선택한 봉인 상세·출전 대기·CMS 역할 이미지·실제 V3 전투 몬스터에 동일한 역할 리소스를 연결했다. 큰 상세 원화는 모바일에서 112px, 320px 화면에서 92px로 조절한다. 기존 전용 봉인전 프레임과 버튼을 유지한다.

봉인구 WebP와 대응 PNG를 전투 요청 전에 준비한다. 중복 준비는 한 작업을 공유하고 둘 다 실패하면 참여 POST 없이 복귀하며, 재시도 때 다시 로드한다. 새 원화를 `approved:true`로 표시하지 않는다.

서버 전투·승패·공헌도·회차·계급 EXP·보상은 변경하지 않는다. 프리뷰의 예시 완료 코인은 이미 승인·운영 반영된 5천억에 맞추고 기본 진입을 세 봉인 단계로 변경했다. 기존 단일 봉인구 원본/파생본은 보존한다.

## 검수

- `check-ui.mjs`: 1440×1000, 390×844에서 각 3종의 선택 → 실제 V3 전투 → 결과 → 복귀, CMS 이미지, 320px 가로 넘침, 키보드 선택, 이미지 전체 실패 시 POST 0회 확인. `browser-check.json`에 오류/실패 요청 0건 기록.
- `capture-idle.mjs`: 같은 실제 renderer/payload에 DEPLOY를 재생한 배치 화면. 공격 효과 전 3종의 원형과 투명 여백을 확인했다. 전투 전체는 앞선 실제 버튼 검사에서 별도 확인했다.
- PC/모바일의 선택·전투·배치 스크린샷을 직접 보고 본체/체력바/텍스트가 잘리지 않는지 확인했다. 기술 검수와 사용자 시각 승인은 구분한다.
- `tests/seal-orbs-20261022.test.mjs` **3개 통과**: 역할별 실제 payload, 로딩 공유/PNG 대체/실패 후 재시도, 원본·알파·해시·배포 파일 수.

## 배포 범위

직전 운영 소스는 `ab12ecbd67000be091802d59122c710c004763fa`. 작은 자산 연결/UI 변경으로 `deploy:production -- --scoped`를 사용한다. 공용 엔진 원본·번들은 변경하지 않으며 실제 번들/메인 로더 연결, 전투 파일 복구, 기존 봉인 연결, 봉인전 파일 패키징 검사만 추가 실행한다.
