# 격전지 선택 보상 큰 코인 잔액 오류 — 2026-11-06

요청: 격전지에서 코인이 많을 때 보상 오류가 나는지 확인하고 복구.

## 확인한 원인

기본 격전지 클리어 지급은 앞선 10경 수정에 포함됐지만, 이후 봉인 3개 중 하나를 고르는 공용 선택 보상 함수 `prepareCoreChoiceGrant`의 코인 지급 조건이 `Number.MAX_SAFE_INTEGER - 보상량`으로 남아 있었다. PostgreSQL BIGINT 지갑이 정상이어도 약 9,007조 이상에서 원자성 보호 조건을 통과하지 못해 HTTP 503이 발생했다.

2026-11-06 21:27:21 KST 운영 READ ONLY 조회에서 선택 완료·지급 미완료 상태의 격전지 극한 COIN 보상 1건이 같은 조건에 해당했다. 동일 공용 함수의 LICH 선택 보상에도 1건이 남아 있었다. 미선택 봉인은 변경하지 않았다. 세부 계정/영수증 증거는 공개 배송에서 제외되는 `operations/coop-large-coin-20261106/before-inspection.json`에 보존한다.

## 수정

- 코인에만 기존 공용 `coinCreditLimit`의 정확한 signed 64-bit 저장 한도를 사용한다.
- 코인 가산 매개변수를 BIGINT로 명시해 SQLite와 PostgreSQL 모두 10경+1 및 홀수 보상을 정확히 처리한다. 원장은 실제 DB 잔액을 기록한다.
- 카드 조각·마력 결정·아이템 수량 한도, 보상 설정/확률, 에너지/주간 횟수, 선택 슬롯/기존 영수증과 트랜잭션은 보존한다.
- 실패한 선택은 기존 미수령 목록에서 같은 슬롯으로 재시도한다. 완료된 선택은 기존 결과를 돌려주므로 중복 지급하지 않는다. 운영 계정 직접 지급·재추첨·기존 영수증 초기화 없음.

## 검증

수정 전 실제 선택 보상 API + 격리 PostgreSQL에서 HTTP 503/guard check 위반 재현. `reproduction.log` 보존.

수정 후 신규 12검사 통과: SQLite/PostgreSQL의 2^53 경계·10경-1/10경/10경+1·DB 최대값 정확 가산, 코인 원장, 재조회 중복 방지, 원장 실패 원복, 선택 슬롯 보존, 응답 유실 복구, 저장상한 초과 거절, 중복 차량 최소 코인 전환, 다른 재화 한도 보존, 격전지 기본 지급→선택 보상 연속 처리. 같은 함수의 LICH/MADARA/BLACKWING 목적지도 포함한다.
