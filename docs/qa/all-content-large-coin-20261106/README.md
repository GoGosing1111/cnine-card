# 큰 코인 잔액 콘텐츠 점검 — 2026-11-06

사용자 요청: 격전지에 이어 다른 콘텐츠도 전부 점검. 큰 코인 보유 시 발생하는 지급·차감·원장·영수증 문제에 범위를 맞췄다.

## 결과와 수정

- `functions/shared/workers/js`의 추적 코드 1,014개에서 코인 관련 250개 파일을 검색했다. 잔액 한도, Number 변환, SQL 지급·차감, 원장·영수증, 재시도 비교를 검토했다. 신규 정산 도우미 1개가 추가됐다.
- PostgreSQL 어댑터가 BIGINT를 Number로 읽으므로, 정확성이 필요한 잔액은 SQL TEXT로 읽거나 DB의 실제 coin을 원장에 직접 기록하도록 수정했다. 전역 어댑터와 스키마는 변경하지 않았다.
- 메시지 수령의 지급 전 잔액을 DB에서 직접 기록하고, 실패 복구 판정에서 10경+1과 10경+2가 같은 수로 취급되던 비교를 BigInt로 바꿨다.
- 출석 지급·출석 기록·원장을 한 거래로 묶었다. 광물 교환은 반올림된 절대 잔액 덮어쓰기를 없애고, 신청 상태·일일 한도·현재 잔액을 잠금과 조건으로 검증해 정확히 가산한다.
- 대장전·마법 뽑기·쿠폰·균열·단일 진화·관리자 지급 원장과 일반 팩 지급 증명의 큰 잔액 처리를 수정했다. 관리자 조정의 이미 부정확한 Number 금액 입력은 거부한다.
- 마법 뽑기는 완료 영수증이 존재하면 응답 유실 뒤 비용을 잘못 환불하지 않는다. 금도끼의 유지된 교환권 조회도 정확한 잔액을 읽으며, 종료된 이벤트는 계속 종료 상태다.
- 29개 파일의 코인 증감식 45개를 명시적 정수 바인딩으로 바꿨다. 이 중 별도 의미 변경이 없는 27개 파일은 변경 전과 정규식 치환 결과가 완전히 동일함을 검증했다. SQLite에서 10경+1 단일 진화 시 마지막 1코인이 사라지는 문제도 재현 후 해결했다.

## 검증

- 변경 전 소스 `dfa2cddba`를 사용하는 독립 재현 6건 모두 실패했고 수정 코드에서 통과했다.
- 관련 41개 검사 파일 최초 516건 중 505 통과. 희소 체크아웃의 누락된 검사 자료를 복원해 18건 추가 통과(금도끼 쿠폰의 파일 로드 실패 1건은 실제 10개 검사로 대체). 정수 SQL을 검증하는 호송 상태 가드 검사도 통과했다.
- 호송 PostgreSQL 스키마 검사 1건, 관리자 정확 정수 조정 검사 1건 추가. 합계 **고유 검사 526건 통과**. 구형 호송 로더의 고정 버전 `106-combat-flow`/`3.36.0-combat-flow`를 요구하는 기존 검사 1건은 직전 소스와 동일한 파일에서 실패한다. 실제 게임 로더나 버전을 그 검사에 맞춰 되돌리지 않았다.
- 경계: JS 안전정수 전후, 10경−1/10경/10경+1, ±1/7코인, BIGINT 상한·하한. 원장 실패 전체 원복, 수령/구매 재시도, 응답 유실, 중복 방지, X-BODY 제작, 강화·복구, 100조 경매 정산, 단일/일괄 진화 등을 격리 DB에서 확인했다.
