# 이스겐 체력 표시·직접 진입 수정 · 2026-11-17

[제보 및 댓글 13개](https://www.playdk.kr/board/skm/1538245)를 읽었다. 댓글의 “3인으로 진행하면 된다”는 경험담은 보장된 조건이 아니다. 읽기 전용 운영 조회에서 작성자가 참가한 3인·4인 전투 모두 마지막 12초 공격 구간에서 각각 57,139·85,716 HP가 남고 시간 초과된 것을 확인했다. 서버 확정 HP는 단조 감소했고, 마지막 성공 공격 이후 약 6초간 추가 성공 공격 영수증은 없었다. 실패한 요청은 이 영수증 테이블에 저장되지 않으므로 사용자의 당시 입력·통신 실패까지 단정하지 않는다.

## 원인과 변경

- 리치왕의 각 공격은 공용 전투 시뮬레이션을 실행한 뒤 레이드 피해 한도를 적용한다. 기존 코드는 최상위 damage/targetHpAfter만 보정하고 hits 배열의 시뮬레이션 피해·HP는 남겨 두었다. 운영 기록에서 레오넬·블러드문 남수댕·블랙크라운 공격의 값이 불일치했고, 보스에게 체력이 남았는데 하위 타격에는 0이거나 훨씬 높은 값이 있었다.
- 최상위와 하위 타격에 같은 정수 피해 예산·실제 남은 HP·최대 HP를 적용한다. 연속 타격은 누적 반올림으로 합계를 보존한다. 이미 생성된 전투의 이전 이벤트도 화면에서 같은 방식으로 보정한다.
- 이스겐 전투에만 늦은 연출의 HP 역행·조기 사망을 막는 보호를 연결하고 퇴장 때 원래 메서드로 복원한다. 공용 전투 엔진과 다른 콘텐츠의 회복은 바꾸지 않는다.
- 새 클라이언트의 로비→이스겐 직접 진입은 공용 전투 런타임이 없어 ensureRuntime 오류로 열리지 않았다. 기존 공용 리소스 로더와 이스겐 번들을 병렬 준비하고 완료 뒤 전투를 연다. Promise 캐시·실패 재시도는 유지한다.
- 피해 한도·3~6인 배율·기믹·제한시간·보상·과거 CLEAR/FAILED 결과는 그대로다. 계정 변경·시험 운영 공격·보상 보정·메시지/댓글 발송은 없다.

## 재현·검증

신규 회귀는 실제 리미티드 용병 편성으로 3~6인 막타·남은 1/57,139/85,716 HP·중복 요청·다중 타격 합계·이전 이벤트 보정·늦은 연출·퇴장 원복을 검사한다. 원본에서 하위 타격 피해 983,178과 상위 확정 피해 19,663의 불일치로 실패했고 수정 후 통과했다. 실제 DB 거래·동시 클리어·주간 횟수·부분 지급 실패 롤백은 기존 관련 PostgreSQL/SQLite 회귀를 배포 검사에 포함한다.

브라우저는 실제 로비 메뉴→레이드→이스겐, 재입장, 남은 HP에서 두 번의 직접 공격→CLEAR·보상 1회, 컴포넌트 퇴장을 검증했다. PC/Android·iOS(WebKit)/Windows 런처 URL/H5 iframe의 원본·수정본 각 1회다. 변경 전 직접 진입은 실패하므로 원본 체력 비교에서는 공용 런타임을 미리 불러오는 우회가 필요했다. 실제 휴대기기·설치된 Windows 렌더러·원스토어 호스트 측정은 아니다.

측정 조건·첫 실행/진입/재진입·프레임·SQL·퇴장 뒤 갱신은 [performance.json](performance.json)에 있다. API의 SQL 수를 늘리지 않고 기존 번들/런타임 요청을 병렬화했다. 네트워크는 localhost이며 실제 인터넷 지연을 대표하지 않는다. 기존 WebKit ResizeObserver 경고와 긴 프레임은 변경 전후를 그대로 기록했다. 운영 계정 전투 스냅샷은 저장소에 넣지 않았다.

## 배포

관련 기능만 수정하는 scoped 배포다. [배포 계획](deployment-plan.json)의 실제 직전 운영 SHA·선정 검사·이유를 사용했다. 13:39:39 KST 배포 완료, 배포 커밋 f8882d201 · Pages 306c460b · 두 Worker 100%다. 관련 60개 고유 검사와 공개 파일 9개(스토어 HTML은 실제 변환 결과) 해시를 확인했다. 상세 버전·원본 결과/설정 보존·한계는 [completion.json](completion.json)에 기록했다.

Pages의 파일 수 제한에 맞춰 이스겐 자체 build-report.json만 공개 포장에서 제외했다. 원본·검수 기록은 Git에 보존했고 런타임 파일은 모두 전달했다. 배포 직후 관찰한 공대에는 새 용병 공격이 없어 실제 사용자 클리어 재발 여부까지 확인한 것은 아니다. 운영 수정본 전달 및 격리된 실제 코드 경로의 전투/보상 검증을 완료했다.
