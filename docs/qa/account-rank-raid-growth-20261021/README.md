# 봉인전·주간 레이드 계급 경험치와 중령 이후 성장

2026-10-21 사용자 지시: 봉인전 기본 경험치를 40으로 낮추고, 붕괴 코어·바르센·이스겐은 주간 보상 수령에만 계급 경험치를 분배한다. 후속 답변 `레이드 경험치량 너무많음 1/3로 줄여 그리고 강한증가`에 따라 제안했던 1,000/500/500 EXP의 정확히 ⅓과 중령 이후 레벨마다 +5%p 증가를 적용한다.

## 확정 지급량

| 콘텐츠 | 기본 EXP | 실제 저장 ticks | 보상 한도 |
| --- | ---: | ---: | --- |
| 봉인전 정상 전투 | 40 | 24,000 | 기존 행동력·정산 조건 |
| 붕괴 코어 주간 보상 | 333⅓ | 200,000 | 주 3회 |
| 이스겐 정벌 주간 보상 | 166⅔ | 100,000 | 주 7회 |
| 바르센 레이드 주간 보상 | 166⅔ | 100,000 | CMS 설정, 확인 시 주 5회 |

1 EXP는 600 ticks다. ⅓을 333/167로 반올림하지 않는다. 현재 운영 한도를 모두 채우면 주간 기본 합계는 **3,000 EXP**이며, 기존 펫·트로피 경험치 보너스와 사용 중인 경험치 물약은 공통 정산 규칙대로 적용한다. 주간 한도를 별도로 늘리거나 초기화하지 않는다. 바르센 기본 설정 7회로 계산한 3,333⅓ EXP는 실제 운영 한도에 해당하지 않는다.

붕괴 코어는 기존 수령 거래에서 주간 횟수 예약과 PENDING 영수증 소유 조건을 함께 확인한다. 이스겐·바르센은 현재 구조의 클리어 시 주간 보상 자동 지급 거래에 합친다. 단순 클리어마다 주는 방식이 아니며, 기존 주간 보상이 실제 지급되는 경우에만 지급한다. 추가 선택 보상 설정 OFF여도 유효한 기본 보상 수령에는 적용한다.

완료된 과거 보상, 보상 선택·공개·재조회, 같은 방/요청 재시도, 실패, TEST, 주간 한도 초과에는 새 경험치가 없다. 이스겐·바르센의 동결된 지급 정책과 탈퇴 등 기존 자격 조건을 유지한다. 경험치·코인·아이템·주간 횟수·완료 영수증은 같은 거래에 저장된다.

## 증가 곡선

Lv.184까지 다음 레벨 필요량은 기존과 같다. Lv.185→186부터 기존 필요량에 5%를 추가하고, 레벨마다 **5%p씩** 추가한다. 필요 EXP는 정수 올림하며, 1.05를 반복 곱하는 복리는 아니다.

`ceil(기존 다음 레벨 필요 EXP × (1 + max(0,현재 레벨-184)×0.05))`

| 현재 레벨 | 기존 다음 필요 EXP | 새 다음 필요 EXP | 기존 대비 |
| --- | ---: | ---: | ---: |
| 185 중령 | 6,400 | 6,720 | 1.05배 |
| 200 대령 | 6,880 | 12,384 | 1.80배 |
| 215 준장 | 7,360 | 18,768 | 2.55배 |
| 225 소장 | 7,680 | 23,424 | 3.05배 |
| 235 중장 | 8,000 | 28,400 | 3.55배 |
| 249 대장 구간 | 8,448 | 35,904 | 4.25배 |

신규 누적 중장 도달량은 1,466,820 EXP, Lv.250 상한은 1,948,378 EXP다. 새 성장 규칙은 서버 전용이며 공개 응답은 기존처럼 현재 레벨의 경험치·진행률만 반환한다. 계급별 보너스·시라누이 Lv.235 조건·보상 중복 방지는 그대로다.

## 기존 계정 전환과 배포

현재 레벨과 해당 레벨 진행 비율을 보존한다. 새 필요량에 비례한 잔여 ticks를 올림해 기존보다 진행이 줄지 않게 하며, 오차는 1 tick(1/600 EXP) 미만이다. Lv.250은 새 상한으로 전환한다. 과거 경험치 지급 원장·계정 재화·메시지는 수정하지 않는다.

운영 사전 조회에서 중령 이상은 OWNER 1계정(Lv.250)이다. 일반 계정은 변경 구간에 도달하지 않았다.

운영 절차는 `scripts/ops/account-rank-raid-growth-20261021.mjs`다. 먼저 CHECK 상한만 확장하고 기존 수치는 유지한다. 새 런타임 배포 확인과 이전 요청 정리 뒤 계급 데이터를 일회 전환한다. 전환은 테이블 잠금 안에서 현재 값을 읽고 갱신해 동시 경험치 누락을 방지한다. 사전 상한 확장은 배포 실패 시에도 기존 성장에 영향을 주지 않는다.

- 상한 키: `ops:account-rank-raid-growth:20261021:cap-v1`
- 전환 키: `ops:account-rank-raid-growth:20261021:v1`
- 새 상한: 1,169,026,800 ticks
- 감사 종류: `ACCOUNT_RANK_RAID_GROWTH`
- 재실행은 저장된 완료 영수증만 반환한다. 새로 쌓인 경험치를 다시 환산하지 않는다.

## 검증

250레벨 경계·중령 이전 동일성·단계별 증가폭·중장 시라누이 기준·모든 레벨의 진행률 전환을 검사한다. PostgreSQL 전환 dry-run/실패 전체 원복·재시도·지급 원장 보존을 검증한다. 레이드는 SQLite/PostgreSQL에서 실제 수령·주간 마지막 횟수 경쟁·저장 실패·응답 유실·선택 보상 재조회·TEST/실패/과거 영수증·정확한 ⅓ 정산을 확인한다.

첫 관련 검사 129개 중 기존 PostgreSQL 레이드 검수 DB에 새 정산이 사용하는 메시지/용병 테이블이 없어 24개 실패했다. 검수용 DB 스키마 생성 경로를 보완하고 영향받은 레이드 검사 81개를 다시 실행해 모두 통과했다. 계급·물약·시라누이·협력 계급 검사 48개도 통과했다. 운영 테이블을 회피하거나 보상 예외를 무시하는 변경은 없다.

최종 배포·운영 전환 결과는 완료 후 이 디렉터리에 기록한다.

운영 DB의 기존 테이블 소유자 `cnine_migrator`로 사전 전환 거래를 실제 실행 후 ROLLBACK했다. 462개 진행 행 중 1개만 환산 대상이며 462개 계급 모두 보존됐다. 기본 조회 계정 `neondb_owner`에는 해당 테이블 DDL/역할 전환 권한이 없어 기존에 구성된 테이블 소유자 연결을 사용했다. 권한이나 역할 멤버십은 변경하지 않았다. Core TEST·실패 방·과거 완료 영수증의 경험치 제외 검사 2개도 추가 통과했다.

전체 출시 게이트는 `test:live-connections`의 기존 배너 호출 수 검사(59/58 불일치)에서 한 차례 중단됐다. 앞선 운영 소스 `b0fd3bfa6`와 해당 테스트·원본·번들은 동일하며, 기존 `ZeroCombatPlayback.js`의 배너 호출 1개가 검사 목록에서 누락된 상태였다. 목록에 Zero만 추가해 해당 검사를 통과시켰다. 게임 코드나 번들은 변경하지 않았다. 원본 로그 SHA-256 `2d9c57850bf2c294a9a0c98eb9791c66e6715241a5e732e1ac49218c415722c0`, 검사 시작 소스 `f039e8dadfa502e40369b503e6c4633a7b14748b`에 묶인 기존 재개 기능으로 통과한 단계를 재사용한다.
