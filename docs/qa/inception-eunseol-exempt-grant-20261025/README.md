## 검증 및 적용 절차

- 기존 검증된 단일 계정 지급 실행기를 재사용했다. 운영 USER_LOCK과 DB 보조 임대, 계정/보유 행 잠금, 발행 수량 읽기 잠금, 단일 트랜잭션을 사용한다. 임대 키·연결 비밀은 파일이나 출력에 기록하지 않는다.
- `run.mjs read`: 독립 READ ONLY 연결로 대상·보유·팩/제작 수량 확인.
- `run.mjs dry-run`: 감사 기록 작성 뒤 영수증 저장 직전 실패를 주입해 전체 원복, 정상 예행 지급 후 전체 원복, SELECT 전용 재실행의 추가 쓰기 0, 양쪽 계정 잠금 회수를 검증했다. `dry-run.json`의 지급/감사 결과는 원복된 예행연습이며 실제 지급 영수증이 아니다.
- 예행연습과 실제 실행 코드 SHA-256: `15380709a30a5df5330817e9e8361c33f7a0a3099443e1c640e9064eeb735803`.
- `run.mjs apply`: 동일 코드 해시의 통과한 예행연습을 요구한 뒤 1회 커밋한다. `run.mjs verify`로 새 연결에서 보유·획득·감사·수량 보존을 확인한다.
- 이 문서 및 운영 스크립트는 배포 자산에서 제외된다. 데이터 직접 지급만 요청됐으므로 웹/워커를 재배포하지 않는다.
