## 처리 구조

- `shared/mercenary-bloodmoon-bulk-v1.mjs`: BigInt 한도/가격 계산, 최대 100,000회, 기존 2단계 정수 확률 추첨, 카드별 수량 집계, 압축 영수증 합계 검증.
- `functions/_mercenary_bloodmoon_bulk.js`: 버퍼 방식 암호학적 난수와 일반 카드별 합산 지급. 기존 획득 원장에 묶음 지급 이벤트 하나와 지급 후 잔고를 남기고, 정확한 수량은 기존 `joint_operations_v1` 계획의 `normalDraws`에 보존한다. DB 스키마 변경은 없다.
- 기존 개봉 서비스에 `budget`이 있는 요청만 대량 경로로 연결한다. 서버가 저장 가격으로 횟수·비용을 재계산한다. 기존 1/10회 요청·영수증도 계속 읽는다.
- 동일 거래에서 한정 발행·일반 보유 수량·코인·완료 영수증을 확정한다. 한정 발행 번호는 개별 원장에 유지한다. 소진된 구간은 일반 SSS로만 대체하고, 확정된 결과를 다시 추첨하지 않는다.
- 브라우저에는 결과 전체 대신 요청 ID/한도만 저장한다. 재접속·응답 유실 복구는 같은 요청을 사용하고 자동으로 새 구매를 시작하지 않는다.
- 작업량은 일반 카드 종류 수에 비례해 저장한다. 한정 원장은 요청당 최대 256건, 계획은 기존 250,000자 제한, 보유 수량은 기존 INTEGER 상한을 넘기지 않는다. 미래에 한정 재고가 크게 증가해 이 경계에 도달하면 결제 전에 더 작은 한도를 요청한다.
