# 트로피 새 디자인 4종 · 2026-11-01

사용자 확정: 흑익의 맹약 15회 클리어, 랭크전 3시즌 연속 챌린저, 클랜전 챔피언스리그 우승, 클랜전 정규시즌 우승 트로피를 새로 제작한다. 새 디자인은 앞에, 기존 디자인은 뒤에 보존한다. 추가 이후 기록으로 새 트로피를 지급하고 기존 획득자에게 소급 교체·지급하지 않는다. 이전 세 이름 앞에는 `(구)`를 붙인다.

## 적용

- 새 코드: `BLACKWING_CLEAR_15`, `CHALLENGER_STREAK_3_V2`, `CLAN_CHAMPIONS_TROPHY_V2`, `CLAN_CHAMPION_V2`.
- 기존 세 코드와 원화·수동 지급 기록·CMS 보너스 값은 보존한다. 이전 세 트로피는 추가 시각 전 완료 기록으로 고정한다.
- 새 랭크전 트로피는 추가 시각 이후 정산된 공식 시즌 3회 연속 챌린저 조건이다. 이전 시즌을 새 연속 기록에 합치지 않는다. 미참가·챌린저 미달은 연속 기록을 끊는다.
- 흑익은 추가 이후 공식 ON 성공 방의 고정 `clearRewards` 참가 증거로 집계한다. 주간 보상 한도 및 성공 후 퇴장은 횟수를 바꾸지 않는다. TEST·실패·클리어 전 이탈·다른 계정은 제외한다.
- 클랜 우승은 기존 공식 정산·우승 당시 소속, 챔피언스리그는 우승 참가 명단·실제 트로피 지급 완료 조건을 유지한다.
- 시작 시각은 운영 배포 검증 후 `trophy_renewal_20261101_v1`에 DB 시각 기준으로 한 번만 기록한다. 작업 키 `ops:trophy-renewal:20261101:v1`. 재실행은 기존 시각을 반환하며 새 키로 시작 시점을 재설정하지 않는다.
- 명함 및 공통 보유 효과 조회는 SELECT 전용이다. 신규 효과 기본값은 0%, 기존 설정 읽기 호환과 과거 수동 지급 8종의 범위를 유지한다.

## 자산 및 화면

내장 ImageGen으로 개별 생성한 투명 PNG 4종과 프롬프트·해시는 `assets/ui/player-card/renewal-20261101/`에 보존한다. 실제 게임은 각 512px WebP를 사용한다. 기술 검수와 사용자 시각 승인은 구분한다.

새 4종을 첫 페이지에 표시하고 기존 12종을 보존한다. 구 3종은 마지막 페이지에서 `(구)` 이름으로 표시한다. 진열장 4개씩 페이지 이동·상세 조건·미획득 표시를 유지한다. PC 1440, Chromium 모바일 390, WebKit 320에서 실제 명함 컴포넌트를 검증했다. 실기기나 설치앱 검증으로 기록하지 않는다.

## 검증 범위

SQLite와 PostgreSQL 호환 계층에서 적용 전/정각/이후, 14→15회, 연속 기록 단절·유지, 다른 계정·TEST·실패 제외, 기존 소유 보존, 구 설정 8/9/12종 호환, 조회 중 쓰기 금지, 실제 명함 API와 공통 honors 일치, 기존 원화 해시를 확인한다.

기존 `current LIVE clan excludes...` 테스트 하나는 6클랜 전제에서 FM(7번)을 미등록으로 기대한다. 현재 운영은 8클랜이며 해당 테스트와 소속 판정 코드는 본 작업 이전부터 같은 상태다. 이번 트로피와 무관한 소속 정책을 변경하지 않고 이 검사만 scoped 명령에서 제외한다.

원본 PNG 및 과거 트로피 구현 문서 4개는 Git에 보존하고 공개 Pages 포장에서만 제외한다. 원화·문서 삭제나 저장공간 유지관리는 하지 않는다. 기존 희소 체크아웃 및 의존성을 재사용한다.

운영 결과 및 정확한 시작 시각은 배포 후 completion.json에 기록한다. 공지·메시지 발송 및 계정 재화 직접 지급은 없다.
