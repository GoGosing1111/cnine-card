## 구현

- 기존 DK `GET /api/v2/ext/game/user`가 반환한 선택 필드 `soopUserId`를 최초 2차 인증 및 같은 DK 계정 재인증 성공 뒤 서버의 `app_meta`에 저장한다. 브라우저 입력의 ID나 동의 주장은 사용하지 않는다.
- 기존 계정 바인딩을 SQL에서 다시 확인한다. 오래된 응답이 새 응답을 덮지 않으며, 새 정상 응답에 ID가 없으면 기존 ID를 비워 집계에서 제외한다. ID 부재를 미동의로 단정하지 않는다. 인증/기프트/지갑/메시지 정책은 유지한다.
- `GET /api/admin/soop-watch/ranking?month=2026-10`은 기존 인증을 통과한 OWNER만 허용한다. 현재 ACTIVE PLAYDK 바인딩과 일치하는 저장 ID 전체(중복 SOOP ID는 1회)를 DK 랭킹 API에 전달해 1페이지 100명을 받는다. 기존 API의 1,000명 한도 초과 시 임의로 일부를 제외하지 않고 명시적으로 실패한다.
- 달력상 2026-10-01 이상 2026-11-01 미만 KST. 진행 중인 월은 오늘의 누적을 포함하는 다음날00:00을 실제 조회 종료일로 사용한다(10/28에는10/29). 달력 월 끝은 calendarDateLt로 별도 반환한다. 지난 월은 전체 기간이다. 동시 방송 시청은 API 계약대로 각각 합산한다. generatedAt은 산출 시각이지 최신성 보장 시각이 아니다.
- DK가 현재 동의/권한/연결을 검사한다. 403 전체 실패에서 사용자 제거 탐색·자동 재시도·0초 변환을 하지 않는다. 저장되지 않은 이용자 수와 실제 집계 대상 수를 구분하며 일부 확보 목록을 전체 TOP100이라고 표시하지 않는다.
