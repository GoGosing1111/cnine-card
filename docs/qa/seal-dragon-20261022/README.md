# 봉인룡 개편 · 고난도 운영 준비

사용자 요청: `세 봉인 해제 → 보스 본체전 → 공동 완료 보상 작업해. 보스는 새로 리소스 만들고 용으로 하나 만들어`, 후속 `난이도 높게해놔`.

## 최종 규칙

- 새 회차는 파괴·수호·정화 봉인을 모두 해제한 다음 봉인룡 네르가온의 서버 공용 HP를 소진해야 성공한다. 각 봉인 목표는 운영의 150억을 유지한다.
- 본체 HP **150억**, 전투력 **1,800만**. 미달 덱은 기존 패배 기여율 **10%**. 최소 공격 수 **20회**는 봉인·본체전, 승패와 관계없이 합산한다.
- 기존 최대 5회/30분 충전, 참여 보상 1억 코인, 공동 보상 1,000억 코인/마스터의 별 100만, EXP 40을 유지한다. 순위 보상은 계속 폐지 상태다.
- 이미 종료된 64회차는 기존 규칙과 정산을 유지한다. 새 회차를 자동 시작하거나 날짜를 새로 정하지 않는다. 운영 CMS의 다음 회차 설정만 일회 감사 거래로 변경한다.
- 보스 수치 미입력, 지난 종료 시각으로 새 회차 시작은 서버에서 차단한다. 시작된 회차는 이름·HP·전투력·보상 스냅샷을 사용한다.

## 난이도 근거

운영의 최근 완료 영수증 5,000개에서 각 참여자의 마지막 덱만 사용했다. 149명, 중간 전투력 12,809,530, 75백분위 14,328,936, 90백분위 19,190,120. 1,800만 이상은 30명(약 20%). 이 집단이 균등 참여한다고 단순 가정하면 본체 평균 피해 5,781,554, 약 2,594회 공격이 필요하다. 실제 고전투력 참여 빈도·성장에 따라 달라지며 완료를 보장하는 모델이 아니다. 원본 조회는 `difficulty-inspection.json`에 보존한다(닉네임/계정 식별자 없음).

## 구현과 거래 보호

독립 스키마 마커와 event_id/request_id PK의 두 부속 테이블로 기존 회차를 보존한다. 서버 계산 후 해당 회차 한 행을 잠그고 현재 단계·시간·남은 HP·횟수를 재검증한다. 실제 남은 HP로 피해를 제한하며 횟수/공헌/단계 변경/보상/EXP/영수증을 같은 거래로 확정한다. 마지막 봉인 동시 공격, 마지막 본체 동시 공격, 실패 롤백, COMMIT 응답 유실, 동일 요청 재시도를 검증했다. 생존한 본체는 시간 만료/관리자 종료에도 클리어가 되지 않는다.

`configureSealDragonHard`는 기본 dry-run, 설정 CAS, 감사 로그 및 일회 영수증을 사용한다. 재실행은 이후 운영자 CMS 편집을 덮어쓰지 않는다.

## 자산 및 화면

ImageGen 원본 6종(용 원화, 대기, 브레스 동작, 피격/사망, 청염 FX, 성소 배경)을 `sources/`에 무가공 보존한다. 프롬프트·SHA-256·변환 결과는 `prompts.json`, `motion-prompts.json`, `manifest.json`이다. 측정한 스프라이트 경계로 추출하고 동일 캔버스/바닥 기준으로 패딩하여 이웃 프레임의 발톱이 섞이지 않게 했다. 생성된 알파를 유지하며 신체를 휘거나 다시 칠하지 않는다.

기존 전용 봉인전 패널/버튼/문장을 같은 콘텐츠에서 재사용하고, 새 용 원화·배경·16프레임 atlas를 화면에 연결한다. 공용 V3 격자·카드 도크는 유지한다. 브레스 본체/청염/타격은 기존 GSAP 전투 시계에 연결한다. 본체 HP가 남았으면 쓰러뜨리지 않고 처치 영수증에서만 사망 동작을 재생한다.

PC 1440×1000, 모바일 390×844의 실제 번들 재생·CMS·일반/마지막 타격을 확인했다. 320px, 동작 줄이기, 마지막 봉인→등장→본체 진입, 자산 실패 시 POST 전 차단도 확인했다. `browser-check.json`, `edge-check.json`, 스크린샷/영상이 근거다. 기능/시각 기술 검수는 사용자 이미지 승인으로 기록하지 않는다: **USER_REVIEW_PENDING**.

## 배포 검사 범위

회차 단계와 전투 거래를 새로 추가하는 개편이므로 전체 `npm run deploy:production` 게이트를 사용한다. `test:seal`에 SQLite/PostgreSQL 신규 회귀를 등록했다. 원본/검수/운영 스크립트와 Node 전용 구형 V3 테스트 4개, 번들에 포함되는 용 모듈 원문은 Git에 보존하고 Pages에서는 제외해 파일 수 제한을 지킨다.

배포 결과와 운영 설정 확정 기록은 후속 검증 후 이 폴더에 추가한다.
