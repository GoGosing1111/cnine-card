# 고급 전리품 상점 여러 개 구매 — 2026-10-23

사용자 요청: 한 번씩 눌러 사던 고급 전리품을 여러 개 한 번에 구매할 수 있도록 추가.

- 상품 상세에서 수량 직접 입력, −/+, 최대 버튼으로 선택하고 총 피그 코인 비용을 확인한다. 한 거래는 최대 100개이며 현재 잔액과 계정의 남은 구매 한도 내에서만 선택한다.
- 확인창에 수량·총 비용·구매 후 남은 한도를 표시한다. 기존 상점용 승인 이미지 패널을 사용했으며 별도 프리뷰 UI를 만들지 않았다.
- 한 요청의 전체 차감·구매 기록·지급을 같은 거래로 처리한다. 구매 기록은 수량별로 유지해 기존 일/주/월/누적 한도가 그대로 적용된다. 묶음 아이템은 구성 수량을 곱해 합산하고, 장비와 보관팩은 개별 인스턴스로 생성한다.
- 미스틱은 구매 개수별로 독립 추첨하며 확률을 바꾸지 않는다. 영수증에 전체 결과를 고정해 실패·재시도로 다시 추첨하지 않는다. 수량이 바뀐 동일 요청 번호는 거부한다.
- 기존 수량 미포함 단일 구매의 영수증과 미결제 요청은 수량 1과 동일하게 복구한다. 가격·확률·판매 상태·계정 한도·보유분은 배포로 변경하지 않는다.

## 검증

- 신규 회귀 25개 SQLite/PostgreSQL 통과: 최대 100개, 모든 팩 종류, 아이템 합산, 2번째 장비 지급 실패 전체 복구, 전체 추첨 결과 고정, 중복/동시 요청, 금액·기간 한도 경쟁, 삭제 상품, 구 영수증 호환, 요청 필드 검증.
- PC 실제 화면: 3개(75코인) 구매 직후 응답 유실 주입 → 새로고침 → 결과 확인 시 잔액 425/보관팩 3개, 추가 차감 없음.
- 최대 버튼 17개/425코인, 0 입력 시 차단, 10 입력 시 250코인 실시간 표시 확인.
- 390×844 모바일: −/+ 조작과 10개 확인창, 가로 넘침 없음(문서 375px/뷰포트 390px), 수량 조작 버튼 높이 모두 44px.
- 신규 25개가 통과한 실행 코드 그대로 배포하며 공식 scoped 경로에서 기존 상점 127개와 Worker 문법/출시 보호 검사를 실행한다. 검사 결과와 운영 버전·공개 해시는 deployment.json에 보존한다.

운영 계정 구매·코인 차감·설정 변경: 0건. 거래 검수는 격리 SQLite 계정에서 수행했다.
