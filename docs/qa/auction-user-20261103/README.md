# 유저 경매장 개편 준비 검수

사용자 확정 규칙은 `docs/project-user-auction-standard-20261103.md`에 기록했다. 현재 운영 API/로비 연결·운영 스키마 적용·상점 판매 활성화·계정 지급·배포·메시지 발송은 모두 0건이다. 유지관리·삭제·새 예약 작업도 실행하지 않았다.

## 결과

- SQLite 관련 21검사 + 실제 PostgreSQL 호환 어댑터/PGlite 1검사 = 22개 통과.
- Chromium PC1440·모바일390·320 및 WebKit390: 개최·예약·예약 취소·퀵 버튼 5종·100조 입찰·20% 수령 안내·로비 최초 알림/재진입/새로고침 검증.
- 브라우저 가로 넘침 0, 페이지 오류 0, 리소스/API 실패 0. 시안은 가상 계정과 SQLite에만 연결된다.
- 원본 스크린샷·실행 보고서: 프로젝트 루트 `operations/auction-user-20261103/browser/`.
- 티켓은 내장 ImageGen으로 생성했으며 무가공 PNG를 보존한다. 원본 위치·프롬프트·SHA-256은 `assets-manifest.json`, `ticket-prompt.txt` 참조.

## 확인한 거래

티켓·물품·개최 영수증 원자성, 마지막 티켓 경합, 요청 재사용/내용 충돌, 1건 진행/FIFO, 실제 시작부터 2시간, 기존 경매 종료 대기, 자기 입찰 금지, 정수/상한/잔액 부족, 100조 차감/80조 정산, 비낙찰 환불, 유찰 반환, 예약 취소 반환, 실패 주입과 재시도, 7개 물품 종류의 보유 이전 및 성장 원문 보존, 장착/기간제 차단, 동일 이동수단 재획득 시 반환 보관, 계정별 경매 알림 영수증.

## 기존 입찰 BGM 유지 후속 — 2026-11-03

사용자 “좋네 경매 코인에 맞춰서 노래나오는건 그대로 유지하고”를 반영했다. 기존 공통 발동표를 읽으며 운영 금액 구간·음원·곡별 볼륨·CMS 쓰기 경로는 변경하지 않는다. 이번 추가 입찰액 기준으로 음악을 선택하고 일반 입찰/화면 갱신 때 재생을 유지한다. 발동표 안내·40자 메시지·재생 순서·늦은 입장 재생 위치·자동 재생 차단 안내를 준비본에 연결했다.

- 기존 거래 22개 + BGM 관련 8개 = **30개 통과**. 80개 발동표 보존, 누적 합계와 1회 추가액 구분, 양끝/겹침/무상한/빈 URL, 100조 정밀도, 음악 이벤트 실패 시 코인·입찰·영수증 전체 원복, 재시도 1회 처리, 공유 재생 순서·조회 커서·종료 제외를 검증했다.
- 실제 PostgreSQL 호환 어댑터/PGlite 검사에도 BGM 삽입 실패와 정상 재시도·100조 매칭을 포함했다. 단일 연결 시험이며 운영 다중 서버 검증은 아니다.
- Chromium1440·320, WebKit390에서 같은 실행의 관전자 2화면을 사용해 곡별 볼륨·일반 입찰 중 무중단·동일 순서·늦은 입장 위치·자동 재생 차단 후 버튼·이탈 정지를 확인했다. 재생 객체를 계측했으며 **실제 음원 청취/실기기 재생 검증은 아니다**.
- 기존 UI 전체 흐름도 Chromium1440·390·320/WebKit390에서 재검증했다. 가로 넘침·페이지 오류·리소스/API 실패 0.
- 원본 후속 증거: 프로젝트 루트 `operations/auction-user-20261103/bgm/`. 보고서 사본은 `bgm-tests.json`, `bgm-browser-report.json`, `bgm-layout-report.json`. 기존 스크린샷·보고서·원화·`assets-manifest.json`은 최초 준비본 증거로 보존하고, 후속 파일 해시는 `bgm-manifest.json`에 별도 기록한다.
- 기본 OFF·운영 라우터 미연결·운영 쓰기/배포/메시지/유지관리/예약 0 유지.

사용자 추가 지시로 입찰 BGM 알림을 **화면 중앙·PC너비560px·모바일 좌우16px 여백/높이210px 이상**으로 키웠다. 닉네임·금액·망치 아이콘도 함께 확대했다. 처음 중앙 검토에서 발견한 배경 글자 겹침은 불투명 패널 바탕으로 수정했다. 최종 Chromium1440·320/WebKit390에서 중앙 좌표 오차 1px 미만, 확대 크기, 알림 중 일반 입찰, 음악·수동 재생 동작을 재검증했다. 최종 보고 `bgm-centered-report.json`, 원본 증거 `operations/auction-user-20261103/bgm/centered-final/`. 앞선 하단 알림 화면과 초기 중앙 캡처는 검수 이력으로 보존했다.

## 준비 한계

최종 운영 라우팅·실제 카탈로그/접근권한·리미티드 거래 계보·패키지 코인 제한 회계·계정 잠금/동기화·Worker 주기 종료·현재 관리자 경매의 전환 연결은 후속 출시 작업이다. 준비 서비스만 검증했으며 운영 준비가 모두 끝났다고 주장하지 않는다. 콘텐츠 티켓 보상 대상/수량/확률과 두 상점 구매 한도도 미정이다. 이 상태에서 운영 정책을 ON으로 바꾸는 실행기는 제공하지 않는다.

다중 세션 PostgreSQL 부하/경합, 실제 설치앱·iPhone 기기 검수, 전체 기존 콘텐츠 회귀는 수행하지 않았다. 기존 구현 파일을 바꾸지 않은 독립 준비본이므로 전체 release:gate와 배포를 실행하지 않았다.
