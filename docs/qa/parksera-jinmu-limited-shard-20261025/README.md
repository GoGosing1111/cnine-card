# 박세라-ㅂ- 진무 1장 · 한도 외 직접 지급

사용자 최초 요청은 진무 리미티드 조각 전용 발행 수량 1장을 차감하여 박세라-ㅂ-에게 지급하는 것이었다. 조회 시 잔여 1장이었지만 실제 지급 전 재확인에서 5/5장 소진을 확인했다. 최초 지급은 수행되지 않았다. 사용자 후속 **`한도상관없이 1장 지급`**에 따라 전용 발행 한도를 추가하거나 차감하지 않는 직접 지급으로 확정한다.

- 정확한 계정: **박세라-ㅂ- / ID 45 / ACTIVE USER**. 천룡검황 진무 `V-989` 1장, 자동 편성 없음.
- 전용 조각 발행 5/5장, 팩 발행 수량과 정책, 재료 조각·코인·마스터의 별, 다른 카드·용병 성장·편성을 유지한다. 제작 성공 원장과 팩 발행번호에 이 직접 지급을 넣지 않는다.
- 일회 키: `ops:parksera-jinmu-limited-shard:20261025:v1`. 최초 요청에서 정한 중복 방지 키를 유지하되 완료 기록의 `stockPolicy`는 `EXEMPT_NO_COUNTER_CHANGE`다. 키를 바꿔 추가 지급하지 않는다.
- `shared/mercenary-jinmu-v1.mjs`의 기존 직접 지급 허용에 ID 45만 추가한다. 실제 보유 전에는 편성할 수 없으며 비대상 계정은 유지한다.
- 진무 직접 지급 접근 검사 3개 통과: 실제 보유 전 차단, 보유 후 도감·PVE·PVP·랭크·성장 접근, 인접 ID 46 차단, 발행 수량 불변.
- 운영 USER_LOCK·DB 계정 잠금 아래 영수증 실패 주입 원복, 실제 지급 거래 전체 ROLLBACK, 같은 키의 재실행 추가 쓰기 0을 검증했다. `dry-run.json`의 보유 1장·감사 ID는 롤백된 검수 값이다. 계정 실지급 완료는 `apply.json`과 독립 `verify.json`으로 확인한다.
- `run.mjs`는 비밀을 메모리에서만 읽고 파일에 저장하지 않는다. 운영 계정 잠금을 해제하고 검수 결과만 보존한다. 새 프로젝트·의존성 복사본은 만들지 않았다.

진무 직접 지급 접근에 한정한 정식 scoped 배포 후 동일 검증 소스로 적용한다. 배포·지급 완료 결과는 후속 기록한다.
