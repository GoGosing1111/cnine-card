# 이스겐 6인전 0.3% 잔여 · 입력 잠금 조사와 복구

사용자 제보: 6인 공대가 이스겐 HP 0.3%를 남기고 실패하며 “입력 중입니다” 상태로 버튼을 누를 수 없다는 문의를 확인한다.

## 운영 근거

운영 PostgreSQL에 `BEGIN READ ONLY`와 15초 쿼리 제한을 적용해 최근 24시간 공대 33개를 조회했다. 블랙캐슬 공대 `LK-e1482ced-8d15-4188-adc9-5a5402100d32`는 6인, 마지막 7작전 EXPOSED에서 **85,710 / 25,714,920 HP = 0.333308%**를 남기고 `DPS_CHECK`로 끝났다. 다른 6인 공대에도 0.111~0.556% 잔여 실패가 있었으며, 6인 정상 클리어도 존재한다.

이 HP는 서버에 남은 실제 값이다. 0.3% 불사/강제 잔여 HP 코드는 없다. 마지막 공격 단계는 12초, 개인 공격은 1.4초 재사용과 기존 공대원별 피해 상한을 사용한다. 제보 공대의 기믹은 완료됐고 마지막 공격이 부족한 상태에서 제한 시간이 종료됐다. 실패 기록만으로 당시 개별 브라우저의 패킷 지연을 단정하지 않는다. 아래 두 오류는 실제 코드/격리 API에서 별도로 재현했다.

원본 방 상태·설정·조회 결과는 저장소 밖 `C:/Users/User/.codex/visualizations/2026/10/26/01a177dd-7092-7920-b797-b6ed09d6f5df/isgen-investigation/`에 보존한다. 운영 계정/방/설정/보상 쓰기는 수행하지 않았다.

## 원인과 수정

1. 전투 입력의 응답 대기 15초가 마지막 공격 기회 12초보다 길다. 요청이 서버 도착 전에 지연되면 해당 버튼이 전투 종료까지 잠길 수 있다. 전체 입력과 잠금 재시도에 **2.5초**의 응답 대기 제한을 적용하고, 실패로 단정하지 않은 채 동일 요청 번호/본문으로 수동 재시도할 수 있게 한다. 늦은 응답은 적용하지 않으며 서버의 기존 영수증/소모된 토큰 검증을 그대로 사용한다. 자동 통신 재전송은 추가하지 않는다.
2. 처리 중인 공격과 전황 조회가 겹치면, 조회 응답에 **더 늦은 시간과 더 오래된 공격 토큰/HP**가 함께 올 수 있다. 기존 UI는 시간만 먼저 비교해 이를 받아들였다. 실제 API의 커밋을 잠시 지연한 회귀검사에서 재현했다. 방 revision과 사건 번호가 감소하는 응답을 거절하고, 같은 상태에서만 시계가 전진하도록 한다.
3. 전투가 이미 표시된 동안 전황 조회 제한을 30초에서 3초로 줄인다. 기존 단일 조회·실패 시 간격 증가를 유지하고 초기 전장/로비 로딩은 그대로 둔다. 새 쿼리·서버 잠금·자동 공격은 추가하지 않는다.

서버 전투·12초 제한·1.4초 재사용·피해 상한·기믹·입장권·보상은 변경하지 않는다. 실패한 운영 방을 소급 클리어하거나 보상을 지급하지 않는다. 메인/단독/인라인 진입·서비스워커 캐시를 갱신하고, 기존 원스토어 생성물도 원본에 맞춰 갱신한다.
