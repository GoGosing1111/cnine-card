# 아이폰 경매 BGM 입찰 알림 축소·세로 이동

사용자 첨부 화면의 큰 중앙 BGM 입찰 알림을 축소하고 위아래로 이동하도록 요청했다. 기존 운영 소스 699b6a64b 및 문서 후속 c40749021이 있는 체크아웃을 재사용했다.

## 변경

- 모바일 너비 최대 300px, 320px 화면에서는 296px. 메시지가 없는 390px 화면에서 높이 210px → 119.53px로 감소했다. 기존 경매 아이콘과 이미지 패널을 유지하고 글자·아이콘·여백을 축소했다.
- 알림 본문을 손가락/마우스로 위아래로 드래그한다. ‘↕ 이동’ 안내 및 키보드 방향키/Home/End도 지원한다. 음악 듣기 버튼은 드래그에서 제외한다.
- 위치를 기기의 localStorage에 비율로 저장한다. 다음 음악 알림, 새로고침, 경매장 재진입에 사용하며 visualViewport/화면 크기/알림 높이 변경 때 화면 안으로 제한한다. safe-area 여백과 이벤트/관찰자 정리를 포함한다.
- 기존 BGM 금액 조건·음원·음량·순서·일반 입찰·자동재생 실패 시 듣기 버튼을 유지한다. 웹/스토어 진입 모듈·동적 로더·서비스 워커 캐시를 갱신한다. 경매/계정/보상 정책과 DB는 변경하지 않는다.

## 검수

- 기존 입찰/음악/운영 라우트 단위 검사 38개 및 웹/스토어 실제 로더·서비스 워커 검사 17개 통과.
- 실제 메인 화면 WebKit 390/430px, Chromium 터치 320px/PC 1440px: 축소, 위/아래 이동, 화면 끝 제한, 음악 유지, 다음 알림 위치, 긴 닉네임/40자 메시지, 844×390 가로 화면, 높이 360px로 줄어든 뷰포트, 새로고침, 듣기 버튼, 방향키, 경매장 퇴장 확인. 런타임 오류/로컬 자산 실패 0.
- 기존 음악 UI 검수 Chromium 1440/320px·WebKit390px: 일반 입찰/탭 전환에 재생 유지, 서버 큐 순서, 늦은 입장 재생 위치, 자동재생 제한과 듣기 버튼, 퇴장 시 중지 통과.
- Chromium 모바일은 CDP 터치 입력, WebKit은 실제 포인터 드래그와 합성 touch PointerEvent 경로를 검사했다. 오디오 호출 계측이며 실기기 아이폰/실제 소리 청취/설치 앱 직접검수는 아니다. 키보드는 실제 iOS 키보드 대신 뷰포트 축소로 검증했다.

원본 증거: 프로젝트 본체 operations/auction-bgm-mobile-20261106/. 전체 메인 화면 검수 재실행: node tests/auction-bgm-mobile-20261106.browser.mjs. 공개 코드 검수는 --public으로 실행하며 모든 API를 격리 fixture로 가로챈다.
