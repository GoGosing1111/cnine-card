# 고급 전리품 상점 품목 삭제·저장 안내 — 2026-10-23

사용자 요청: 고급 전리품 상점 품목 삭제 기능과 ‘변경사항 저장’ 버튼 무반응 수정.

## 동작
- OWNER CMS → 전리품 상점 → 품목 선택 → 품목 삭제 → 확인 → 변경사항 저장.
- 저장 전에는 삭제 예정이며 새로 불러오기로 취소할 수 있다. 마지막 판매 품목을 제거하면 전체 판매도 OFF로 저장한다.
- 서버가 삭제한 상품 코드를 누적 보존한다. 클라이언트가 삭제 이력을 제거하거나 같은 코드를 재등록해도 복구되지 않는다. SS팩의 구형 자동 추가도 삭제 이력을 존중한다.
- 기존 구매 영수증·원장·보관팩 스냅샷은 유지한다. 보관팩 개봉과 완료 구매 영수증 재시도는 정상이며 미결제 삭제상품 요청은 취소한다.
- 가격 범위 오류 등 브라우저 기본 검증이 submit 이벤트를 막고 이전 완료 문구를 남기는 현상을 격리 CMS에서 재현했다.
- 명시적 입력 검증으로 오류 항목에 초점을 옮기며 저장 버튼 옆에 오류·저장 중·완료를 표시한다. 구성 검증 및 서버 실패 메시지도 같은 위치에 표시하고 작성 중 값은 유지한다.
- 기존 승인된 CMS 이미지 버튼·패널을 그대로 사용한다. 운영 상점 품목·가격·확률·지급 설정 및 계정 데이터는 이 코드 배포로 변경하지 않는다.

## 검증
- 삭제 관련 신규 SQLite/PostgreSQL 회귀 17개 + 기존 상점 회귀 110개 통과.
- 실제 CMS 모듈·서버 핸들러와 격리 SQLite fixture로 PC/390px 모바일 검수.
- 정상 저장, 가격 0 입력 오류, 후보 누락 오류, 수정 후 저장, 저장품 삭제, 저장 후 재접속에서 삭제 유지 확인.
- 모바일 가로 넘침 없음. 오류 문구·저장 버튼이 함께 보이며 44px 이상의 버튼 유지.
- 공식 배포 검사와 배포 ID·공개 파일 해시는 deployment.json에 기록한다.

운영 DB 수동 쓰기·품목 삭제·계정 지급: 0건. 시각 검수는 기술 검증이며 사용자 디자인 승인으로 기록하지 않는다.
