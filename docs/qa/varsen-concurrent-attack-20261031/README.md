# 바르센 4인 개인 공격 피해 누락 수정

사용자 문의: ShowMaker(문의 표기 showmaer), x수댕, 현하루, 응맨의 4인 파티에서 전원이 공격을 반복했으나 개인 공격 실패 및 단계 진행 실패. 즉시 확인·수정·운영 반영 요청.

## 확인한 원인

운영 DB는 READ ONLY로 조회했다. 2026-10-31 11:37~11:42 KST의 4인 공대 `9D39CDDC71`, `877883E05C`, `26A46A5056`는 첫 단계 공격 시간 초과로 종료됐다. ShowMaker의 공격 영수증이 있지만 피해가 0 또는 개인 몫의 일부에 멈췄다.

신궁 강윤의 `MERCENARY_IMPERIAL_ARROW_VOLLEY` / `MERCENARY_IMPERIAL_ARROW_RAIN`은 `hits[]`에 실제 피해를 기록한다. 바르센의 기존 수집기는 이벤트 최상위 `damage`만 읽었다. 강윤이 내부 시뮬레이션의 보스를 먼저 처치하는 편성에서는 일반 카드·장비 타격 없이 계산이 끝나며, 정상 접수된 개인 공격과 결전 피해가 0이 된다. 4인 인원수나 동시 클릭 자체가 직접 원인은 아니었다.

## 수정

- 바르센 공격 수집기에 본인 출전 편성의 보스 대상 `hits[]` 피해를 포함한다. 부모 요약과 개별 타격의 중복 합산을 막는다.
- 기존 공격력 상한, 개인 몫, 단계 HP 하한, 1.2초 쿨다운, 결전 횟수를 유지한다.
- 화면으로 전달하는 타격별 피해·잔여 HP도 실제 확정한 개인 피해 예산으로 배분해 원래 시뮬레이션의 과다 수치가 표시되지 않도록 한다.
- 공통 전투 엔진, 편성·성장·CMS·입장·보상 정책·기믹·DB 저장 방식은 변경하지 않는다. 운영 계정 직접쓰기·보상 지급·메시지 발송은 없다.

## 검증

- 신규 5검사 통과: 그룹/단일 피해, 중복·타인·다른 대상 제외, 표시 피해와 실제 HP 일치, 쿨다운·몫 상한·같은 요청 재전송, 4인 동시 공격+상태 조회 12회, SQLite/PostgreSQL 최종 타격 보상 실패 전체 원복·재시도 1회 정산.
- 신고 공대 3개의 저장 편성을 로컬 메모리에서 전후 비교했다. 기존 코드는 ShowMaker의 개인 피해 0으로 정지했다. 수정 코드는 각 3회·총 12회 공격으로 4명 모두 몫을 채우고 다음 단계로 진행했다. 일반 공격/결전 모두 확인. 운영 기록을 수정하거나 실패를 성공으로 소급하지 않았다.
- 기존 바르센 실제 API·보상 거래 및 개인 판단 3/6인 회귀, Worker 컴파일을 scoped 배포에 지정한다. 신규 검사 결과는 같은 실행 소스로 보존한다.
- PC/모바일 실제 메인·V3 화면 검수와 배포 결과는 완료 기록에 추가한다.
