# 장비 PvE 방어와 동일 단계 세트 — 최종 상향안 2026-11-15

사용자가 초기안의 약 20초 생존 증가를 반려하여 상향폭을 크게 늘렸다. 초기안은 운영 배포되지 않았다. 최종 운영 상태는 completion.json을 확인한다. 아르덴 4부위, 신화 용병 1~10단계와 유니크 1~3단계 각각의 같은 세트 5부위에 적용한다. 기존 소유권·아이템 코드·강화·연마·개별 옵션·획득·보상·PvP 정책은 보존한다.

## 원인과 적용 방식

기존 장비 전투력은 기본 방어 수치를 올렸지만 PvE 방어 공식 defense/(defense+600)이 65%에 일찍 도달했다. 장비 효과에 방어력 증가 항목이 없었고 지역 특수 공격은 일반 공격의 방어 계산을 거치지 않았다. 실제 방어 수치를 증가시키면서 PvE 추가 피해감소를 최종 피해에 한 번 적용하여 두 경로 모두 장비 성장을 반영한다. 기존 방어 공식을 교체하지 않는다.

캐릭터 장비와 용병 장비의 추가 피해감소는 곱해서 적용한다. 아르덴 60%와 유니크 1단계 65%를 함께 받는 용병은 추가 피해감소 86%다. 유니크 3단계와의 조합은 92%이며, 방어력 증가 정규화 한도는 1000%, 추가 피해감소 한도는 95%다. 기존 유니크 개별 피해감소와도 곱해 적용한다. 일반 공격, 지역 특수 공격, 피해 하한이 있는 공격의 최종 피해에서 처리한다.

|---|---:|---:|---:|
| 아르덴 | 4 | 200% | 60% |

아르덴은 부위당 방어력 25%·추가 피해감소 5%, 4부위 완성 시 100%·40%를 추가한다. 신화 용병 장비는 부위당 5%·2%, 완성 시 방어력 (25+15×단계)%·피해감소 (10+4×단계)%를 추가한다. 유니크는 부위당 30/40/50%·5/6/7%, 완성 시 200/250/350%·40/42/45%를 추가한다. 표는 부위 효과와 완성 보너스의 합계다. +0부터 적용되며 아르덴 +10 외형과 독립이다.

9단계 2개·10단계 2개·5단계 1개는 각각 독립된 그룹이며 완성 보너스가 없다. 같은 부위 중복·다른 부위 위장·실물 ID 재사용으로 세트를 완성할 수 없다. 기존 2/4/5세트 옵션과 유니크 개별 옵션은 유지한다. 유니크 영구 코드·개별 옵션을 바꾸지 않고 방어 세트 판정을 추가했다. 장비창은 단계별 진행·합계·교체 전후 방어 효과를 표시한다.

## 검증과 한계

- 최종안과 원본 각 180회, 총 360회 고정 시드 모의 토벌. 같은 카드·지원 전투력·용병·+0 장비, 해안/사막/천공 재앙 난이도. 실제 계정 승률이 아니다. 반려된 초기안 결과 180회는 rejected-v1.json에 별도로 보존했다.
- 아르덴만 비교한 동일 편성 평균 전투 지속 시간 99.1→360.4초, 3.64배. 아르덴+신화 10단계 172.1→420.0초.
- 아르덴+유니크 1단계는 양쪽 모두 420초 제한에 도달하며 평균 생존 인원 1→5명. 방어 강화가 보스 처치를 보장하지 않으며 공격력 요구는 그대로다. 장비 없는 대조군과 고정 PvP 재생 결과는 동일하다.
- 실제 SQLite/PostgreSQL 장착, 완성/해제/혼합/위조 슬롯·ID, 캐릭터·용병 중첩, 연마·성장·랭크·듀오, PvP와 지역 전투 검사. 최종 검사 수는 배포 기록에 남긴다.
- 일반 몬스터 공격과 지역 특수 공격에서 30/60/65/80/92% 추가 피해감소를 정확히 한 번 적용하는지 검증했다. 아르덴 UI 계약에는 실제 승인 장비 코드·이름·이미지를 넣었다.

## 로딩·프레임

Windows 헤드리스 Chrome PC 1440px·Android 390px 에뮬레이션, WebKit iPhone 390px 에뮬레이션. 로컬 실제 API와 격리 DB이며 실기기·설치 앱·운영 회선 측정이 아니다. 첫 진입은 새 컨텍스트, 재진입은 같은 컨텍스트 캐시. 단회 비교의 작은 차이를 성능 개선으로 단정하지 않는다.

최종 토벌 동작 프레임 95백분위: Chrome 약 4.3ms, WebKit 31~33ms. 관측 구간 50ms 초과 프레임 없음. PC 장비 첫 화면에는 원본 58.3ms·최종안 70.8ms의 긴 프레임이 각각 1건 있었다. 최종 세 조건 모두 퇴장 후 재생 취소·캔버스 0·엔진 해제를 확인했다. 최초 PC 원본 측정에는 퇴장 전 엔진 진단을 기록했다.

신규 효과는 기존 장비 조회 결과를 사용하여 SQL·네트워크 왕복을 추가하지 않는다. 코드→정책 인덱스를 모듈 로딩 시 한 번 만들고 실제 착용 슬롯만 순회하며, 타격마다 계산된 비율을 한 번 읽는다. 별도 갱신 루프를 추가하지 않았다.
