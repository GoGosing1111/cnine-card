# 장비 PvE 방어와 동일 단계 세트 — 2026-11-15

아르덴 4부위, 신화 용병 장비 1~10단계 및 유니크 1~3단계의 같은 세트 5부위에 방어 성장과 완성 보너스를 연결했다. 기존 아이템 코드·소유권·강화·연마·개별 옵션·획득·보상 정책을 보존하며 신규 효과는 PvE에 적용한다. 운영 완료 여부는 completion.json을 확인한다.

## 확인한 원인과 변경

기존 장비 전투력은 기본 방어 수치를 올렸지만, PvE의 방어 공식 `defense/(defense+600)`가 65%에 일찍 도달했다. 장비 효과에는 방어력 증가 항목이 없었고 지역 보스 특수 공격은 일반 공격의 방어 계산을 거치지 않았다. 따라서 방어 수치만 올리면 군단토벌에서 성장 효과가 다시 사라진다.

이번에는 실제 방어 수치를 증가시키고, 별도의 PvE 추가 피해감소를 최종 피해에 한 번 적용한다. 일반 공격·지역 특수 공격·피해 하한이 있는 공격을 모두 처리한다. 기존 방어 공식을 바꿔 낮은 장비 이용자가 더 많이 맞게 하지 않는다. 캐릭터 장비와 용병 장비의 추가 피해감소는 곱해서 적용하며 총 60% 상한을 둔다. 아르덴 20%와 유니크 1단계 30%는 합산 50%가 아닌 44%다. 기존 개별 피해감소와도 곱해 적용한다.

| 완성 세트 | 부위 수 | 방어력 증가 합계 | PvE 추가 피해감소 합계 |
|---|---:|---:|---:|
| 아르덴 | 4 | 60% | 20% |
| 신화 1 / 2 / 3 / 4단계 | 각각 5 | 24 / 28 / 32 / 36% | 11 / 12 / 13 / 14% |
| 신화 5 / 6 / 7 / 8단계 | 각각 5 | 40 / 44 / 48 / 52% | 15 / 16 / 17 / 18% |
| 신화 9 / 10단계 | 각각 5 | 56 / 60% | 19 / 20% |
| 유니크 1 / 2 / 3단계 | 각각 5 | 100 / 130 / 160% | 30 / 35 / 40% |

아르덴은 부위당 방어력 8%·추가 피해감소 2%, 완성 시 28%·12%를 추가한다. 신화 용병 장비는 부위당 2%·1%, 완성 시 방어력 `10+4×단계`%·피해감소 `5+단계`%를 추가한다. 유니크는 부위당 8/10/12%·3/4/5%, 완성 시 60/80/100%·15%를 추가한다. 표는 부위별 효과와 완성 효과를 포함한 수치다. 아르덴 +10 외형 효과와 무관하게 +0부터 적용한다.

9단계 2개·10단계 2개·5단계 1개는 독립된 세 그룹이며 완성 보너스가 없다. 같은 부위 중복·다른 부위로 위장·같은 실물 ID 재사용을 제외한다. 2/4부위의 기존 옵션은 유지한다. 유니크의 영구 아이템 코드와 개별 옵션은 바꾸지 않고 별도 방어 세트 판정을 추가했다.

## 검증

- 관련 자동 검사 39개 통과: 실제 SQLite/PostgreSQL 장착 경로, 완성/해제/혼합/잘못된 슬롯·ID, 캐릭터와 용병 중첩, 연마, 성장·랭크·듀오, PvP 보존, 지역 군단토벌.
- 일반 몬스터 공격과 지역 특수 공격의 실제 서버 판정에서 추가 피해감소 30%가 각각 정확히 한 번 적용된다.
- 변경 전후 각 180회, 총 360회 고정 시드 모의 토벌. 같은 카드·지원 전투력·용병·+0 장비, 해안/사막/천공 재앙 난이도. 실제 계정 승률 자료가 아니다.
- 아르덴만 비교한 동일 편성의 평균 전투 지속 시간 99.1→118.0초(+19.1%). 아르덴+신화 10단계 172.1→311.1초. 아르덴+유니크 1단계는 420초 제한을 양쪽 모두 채웠으며 평균 생존 인원이 1→2.33명으로 증가했다. 공격력이 같은 상태라 처치 수·클리어 시간까지 모든 시드에서 단조 증가하지는 않는다.
- 장비 없는 대조군 결과와 고정 PvP 재생 결과는 동일하다. `before.json`, `after.json`은 당시 코드 결과를 보존한다.
- 장비창에서 단계별 진행, 총 방어 효과, 교체 전후 효과를 표시한다. 아르덴 UI는 실제 승인 장비 코드·이름·이미지를 넣은 격리 계약으로 확인했다.

## 로딩·프레임

Windows 헤드리스 Chrome(PC 1440px, Android 390px 에뮬레이션)·WebKit(iPhone 390px 에뮬레이션), 로컬 실제 API 핸들러와 격리 DB를 사용했다. 실제 스마트폰·설치 앱·운영 회선 측정이 아니다. 첫 진입은 새 브라우저 컨텍스트, 재진입은 같은 컨텍스트의 캐시를 사용했다. 숫자는 단회 비교이며 작은 차이를 성능 개선으로 단정하지 않는다.

| 조건 | 장비 첫 진입 전→후 | 장비 재진입 전→후 | 토벌 첫 진입 전→후 | 토벌 재진입 전→후 |
|---|---:|---:|---:|---:|
| PC | 249→259ms | 72→70ms | 1493→1546ms | 641→712ms |
| Android 에뮬레이션 | 278→212ms | 68→81ms | 1414→1245ms | 652→747ms |
| WebKit 에뮬레이션 | 351→288ms | 160→185ms | 2303→1939ms | 1558→1419ms |

토벌 동작의 프레임 95백분위는 Chrome 약 4.3ms, WebKit 30~32ms였고 관측 구간의 50ms 초과 프레임은 없었다. PC 장비 첫 화면에는 변경 전 58.3ms·후 66.7ms 긴 프레임이 각각 1건 있었다. 퇴장 후 재생 취소·캔버스 0·엔진 해제를 확인했다. 최초 PC 기준 측정에는 퇴장 전 엔진 진단을 기록했고 이후 다섯 조건에는 pagehide 후 파괴까지 기록했다.

신규 효과는 기존 장비 조회 결과로 계산해 SQL·네트워크 왕복을 추가하지 않는다. 코드→정책 인덱스는 모듈 로딩 때 한 번 만들고 실제 착용 슬롯만 순회한다. 전투 중에는 이미 계산된 비율 한 번만 읽는다. 장비창 데이터와 공용 모듈은 재사용하며 별도 전투 갱신 루프를 만들지 않았다.
