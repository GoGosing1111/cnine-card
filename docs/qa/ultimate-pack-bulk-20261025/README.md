# 얼티메이트팩 100,000장 빠른 개봉

2026-10-25 07:53 KST 운영 반영 및 확인 완료. 소스 `88615e2b2be29e161f5954e99dbcc9dad5c8ab8c`, Pages `016a9f1e-34dd-4e28-b116-f743f3c1a71f`, API Runtime `0a2985ec-de60-418c-b4d1-c84f153adbcb`.

## 사용자 범위

`한번에 10만장 구매가능하게 만들어`, `개봉도 빠르게`. 얼티메이트에만 1,000/10,000/100,000장 선택과 1,000~100,000장(100장 단위) 입력을 제공한다. 20/100장 수동 개봉과 다른 팩은 유지한다. 새 이미지 생성 없이 기존 얼티메이트팩과 승인 공통 도감 패널/버튼을 사용한다. 블러드문 판매 잠금·할로윈은 변경하지 않는다.

현재 운영 조회 결과 단가 3,000코인, 100,000장 300,000,000코인이다. 서버는 현재 CMS 가격과 고객이 확인한 총액이 일치할 때만 결제한다. 가격·확률·판매 상태·재고 설정에 쓰지 않는다.

## 처리와 복구

- `draw/ultimate-bulk` 한 요청으로 실제 100장 규칙을 1,000번 판정한다. 기존 `drawOneFromContext`를 재사용하며 10장마다 보장 등급, 100장마다 크리티컬 판정, 100장당 LIMITED 최대 1장, 유한 재고 품절 대체를 보존한다. 20장 개봉 보장은 별도 기존 경로다.
- 낱장 100,000개 응답/DOM/HTTP 큐 대신 종류별 수량을 합친다. C~UR 등급 합계와 전체 이름/수량 상세는 50종씩, SSR 이상 이미지는 24종씩 표시한다. 연출·영상·이미지 완료를 기다리지 않는다.
- 기존 사용자 락과 브라우저 리스를 사용한다. 같은 계정의 일반 개봉 진행 중에는 새 일괄 개봉을 차단한다. 코인·조각·별·보유 수량·유한 재고·영수증을 원자 거래로 확정한다. 직전 스냅샷 및 지급 후 실제 수량 검증에 실패하면 거래 전체를 취소한다. 마지막 재고 경쟁은 최신 상태를 읽어 최대 세 번 시도한다.
- 기존 영수증 테이블에 `pack_id=ultimate-bulk`, `ULTIMATE_BULK_V1` 결과를 저장한다. 정상 완료만 저장하므로 서버 요청 중단으로 별도 PENDING 예약이 남지 않는다. 기존 일반 개봉 경로는 `ult-` 요청을 거부한다. 같은 요청의 다른 계정·수량·금액 재사용을 막는다.
- 통신 실패/새로고침은 저장된 요청 번호로 GET 복구 후 동일 POST만 재시도한다. 영수증이 없는 24시간 초과 요청은 재결제하지 않는다(영수증 청소보다 짧은 유효 기간). 결과 검증·현재 잔액/보유 반영·렌더링 후에만 로컬 미확인 요청을 지운다.
- 유한 LIMITED는 개별 재고 감사, 모든 LIMITED는 개별 기존 `draw_logs`를 유지한다. 중복 MA/LIMITED 별, 카드 조각도 기존 계산을 따른다. 재생 응답은 과거 스냅샷 대신 최신 잔액과 보유량을 별도로 전달한다.

- 관련 회귀 45개: 신규 15개 + 기존 카드팩/가드/최적화 30개 통과. `ultimate-pack-bulk-20261025.test.mjs`, `iyejun-fur-card-pack-eligibility.test.mjs`, `draw-territory-perf-20260919.test.mjs`, `treasury-draw-alchemy-perf-v2062.test.mjs`.

## 서버 성능

실제 운영 팩·후보 풀·가중치·크리티컬을 READ ONLY로 읽고 운영 추첨 함수와 신규 서비스, 운영 PostgreSQL 어댑터를 사용했다. Cloudflare 임시 원격 프리뷰(HKG) → 운영 Hyperdrive → Neon 연결에서 **임시 테이블만** 사용했다. 모든 DML은 DB가 강제하는 READ ONLY 상태였고 영구 테이블 쓰기는 불가능했다. 외부 거래를 유지하기 위해 내부 BEGIN/COMMIT은 SAVEPOINT/RELEASE로 치환했다. 마지막 ROLLBACK 후 임시 테이블 0개, 임시 프리뷰 종료를 확인했다.

| 100,000장 조건 | 횟수 | 평균 | 최소~최대 |
|---|---:|---:|---:|
| 현재 운영 풀·확률·크리티컬 | 5 | 392ms | 340~555ms |
| 시험용 유한 재고 각 10장 | 5 | 474ms | 387~776ms |

현재 운영 LIMITED 후보는 `limited_total=null`이며, 기존 경로와 동일하게 100장당 한 장 판정과 개별 개봉 로그를 따른다. 나머지 세 조건의 유한 재고/100% 확률은 **임시 검증 전용**이며 실제 설정에 적용하지 않았다. 현재 설정 결과는 약 43KB, 약 154종으로 100,000개 결과 배열이 아니다.

이 수치는 인증·Durable Object 대기·다른 실제 이용자와의 락 경쟁·운영 테이블 규모·실제 COMMIT 영속화 비용을 포함하지 않는다. 운영 전체 응답시간 보장이나 실제 고객 계정 개봉 실측으로 해석하지 않는다. PC/모바일 브라우저 측정은 별도의 로컬 임시 PostgreSQL을 사용했다.

## 운영 확인

- `npm run deploy:production -- --scoped`로 관련 검사 45개·Worker 검사·릴리스 캐시 일치·Hyperdrive 캐시 OFF 검사를 통과한 뒤 배포했다. 앞선 캐시 버전 불일치 검사는 업로드 전 실패했으며 앱과 서비스워커 버전을 맞춰 재검사했다. 실패/성공 원시 로그는 위 보존 경로에 있다.
- 공개 `index.html`, `service-worker.js`, 앱/상점 어댑터, 신규 일괄 모듈/CSS/공유 규칙 총 7개 파일이 로컬 SHA-256과 일치한다. 운영 API 번들의 실제 신규 경로와 미인증 구매 401 차단을 확인했다.
- 배포 전후 READ ONLY 조회에서 얼티메이트 가격·판매 상태·확률·크리티컬 및 블러드문/할로윈 설정 해시가 일치했다. 블러드문 공개 API는 `releaseEnabled=false`, `userOpeningEnabled=false`를 유지한다.
- 임시 성능 Worker는 상시 배포되지 않았으며 조회 404를 확인했다. 검증을 위한 실제 계정 구매·차감·지급·운영 설정 쓰기는 없다.
- `live-verification.json`, `settings-verification.json`, `deployment-result.json`에 운영 확인 결과를 보존한다. 검수용 거래·성능 테스트 결과와 실제 운영 계정 거래를 구분한다.

이 작업은 기존 보호된 작업 폴더와 의존성 junction을 재사용했다. 이전 작업에서 자동 승인 검토가 차단한 삭제는 재시도하지 않았다. 2,035바이트의 `.wrangler/cache/cf.json`은 원시 증빙 경로에 비파괴 이동하고 전후 SHA-256 일치를 확인했다(`cache-preservation.json`). 공유 의존성과 보호된 작업 폴더는 유지하며, 배포 후 작업 폴더에 새 ignored 산출물이 없음을 확인했다.
