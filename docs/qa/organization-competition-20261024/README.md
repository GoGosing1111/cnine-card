# 세력전 피그코인 · 주간 승점 · 4주 시즌

상태: 구현·격리 검수 완료. 운영 배포와 운영 DB 변경은 하지 않았다.

사용자 요청은 “8개 이상 점령 시 피그코인 200개 지급, 설정 가능, 1주일마다 지역 1개당 1승점, 주간·시즌 각각 정산, 순위표”다. 후속 답변으로 4주 시즌을 확정했다. 주간 기준은 한국시간 월요일 00:00이다.

## 지급·정산 규칙

- 기존 회차 보상(8개 점령, 코인 3천억·마스터의 별 30만·미스틱 에너지 300)은 유지한다. 피그코인은 추가 보상이며 기본 ON / 8개 이상 / 참여자 1인당 200개다.
- 피그코인은 회차 시작 시 설정을 고정하고 종료 시 판정한다. 같은 클랜으로 참여한 현재 활성 구성원만 지급하며 기존 메시지함의 PIG_COIN 수령 경로를 사용한다. TEST에서는 계정 재화를 지급하지 않는다.
- CMS → 클랜 → **보상·승점·순위**에서 ON/OFF, 점령 조건(1~25개), 수량(1~10만 개), 시즌 기간(기본 4주)을 설정한다. 기존 브라우저가 새 필드를 생략해 저장해도 저장된 새 설정을 보존한다. 보상 설정은 다음 회차, 시즌 기간은 다음 시즌부터 적용한다.
- 매주 월요일 00:00 보유 지역 1개당 1승점을 확정한다. 회차별 점령 수나 재점령 횟수를 누적하지 않는다. 8개 미만도 보유 수만큼 승점을 얻는다. 점령 보상과 주간 승점은 별도다.
- 첫 집계가 시작된 한국시간 주부터 시즌을 시작하므로 첫 주는 부분 주일 수 있다. 시작 이전의 주간 결과나 과거 피그코인을 소급하지 않는다. 초기화일과 첫 정산일을 화면에 표시한다.
- 4번째 주간 승점을 먼저 합산한 뒤 시즌 최종 순위를 한 번 확정한다. 다음 시즌의 승점만 0으로 시작하고 지도·소속·편성·아지트·공동 자금을 초기화하지 않는다. 동점은 공동 순위(1·1·3위)다. 별도 시즌 순위 재화 보상은 추가하지 않았다.
- OFF 중 도래한 주간 경계는 승점 없이 SKIPPED로 기록한다. 설정 변경 직전에 기존 모드로 이미 도래한 정산부터 확정하므로 나중에 ON으로 바꿔도 OFF 기간 승점이 생기지 않는다.

## 구현

`shared/organization-competition-v1.mjs`는 정책·한국시간 경계·공동 순위·피그코인 참여자 판정을 담당한다. `functions/_organization_competition.js`는 주간·시즌 진행과 조회를 담당한다.

현재 `organization_faction_state_v1` 행 잠금과 동일 트랜잭션 안에서 승점·상태·정산 기록을 저장한다. 기존 `organization_faction_settlements_v1`에 `competition:v1:week:<시각>` / `competition:v1:season:<번호>` 키로 정산을 남긴다. 스키마 변경은 없다. 보상 메시지·아이템 첨부·회차 정산도 같은 기존 트랜잭션이다. 단계 중 실패하면 전체 롤백하고 동일 요청으로 재시도할 수 있다.

기존 1분 주기 클랜 스케줄러와 실제 세력전 조회/행동 경로에 연결했다. 기한 전 정산 요청은 승점을 만들지 않는다. OWNER의 `admin/organization/faction/settle`은 기한이 지난 누락 정산 확인만 수행한다. `organization/faction/rankings`는 순위, `?seasonNo=N`은 보존된 과거 시즌 결과를 조회한다. 최근 12주·12시즌은 화면에서 바로 조회하며 더 오래된 시즌도 영수증/API에 보존된다.

세력전 → **순위표**와 CMS에 시즌 누적 / 이번 주 예상 / 주간 정산 / 시즌 결과를 제공한다. 기존 해당 콘텐츠의 ImageGen `interface-v2`와 승인 클랜 마크를 재사용한다. 신규 장식 프리뷰는 만들지 않았다. 큰 순위 패널은 9-slice로 장식이 수치와 겹치지 않게 표시하며 글자·수치는 DOM이다. 자산 해시와 연결 경로는 `verification.json`에 있다.

## 검증

- 서버·회귀 53건 통과: 신규 14건, 고정 일정 5건, 기존 세력전 7건, 공개 알림 4건, 원로 4건, 자율참여 7건, 실제 피그코인 수령 12건.
- 실제 PostgreSQL 호환 엔진에서 7/8개 경계, 8개 미만 주간 승점, 참여자·소속·활성 조건, 금액 고정, OFF/TEST, KST/월·연도 경계, 지연 정산, 중복 호출, 기존 클라이언트, 정산 실패 롤백, 마지막 주와 시즌의 원자성, 과거 결과 보존을 검증했다.
- 실제 UI/로컬 API로 1440×1000, 390×844, 320×740 화면을 검사했다. 6개 클랜 순위·키보드 탭·주간 4회/시즌 1회 결과·보상 안내·CMS 입력→저장→재조회→복원을 확인했다. JS 오류·실패 응답·가로 넘침·누락 이미지 0.
- API 런타임과 클랜 스케줄러 Wrangler dry-run 빌드 통과. 업로드·배포는 수행하지 않았다.
- `npm run test:organization`에 새 회귀검사를 포함했다. 기능·화면 검증은 사용자 시각 승인으로 기록하지 않는다.
