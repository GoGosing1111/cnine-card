# 전리품 상점 리뉴얼 · 2026-10-23

사용자 요청: 전리품 상점 전체 UI를 용병도감 UI 리소스로 교체하고, 원하는 판매 상품을 다양하게 구성할 수 있도록 확장한다.

## 화면과 관리

- `/loot-shop/`: 승인된 용병도감 `command-20261021/panel-v3.webp`, `action-user-approved.webp`를 원본 그대로 사용. 검색·분류·가격 정렬·교환 가능 필터, 선택 상품 상세, 별도 보관 팩 탭, 구성/확률과 결과 창을 제공한다.
- OWNER CMS → 전리품 상점: 상품 추가·복제, 이름·설명·이미지·분류·표식·추천·진열 순서, 노출과 판매 스위치를 편집한다. 기존 상품은 삭제/종류 변경 대신 판매 중지 또는 숨김으로 관리한다. 저장 전 초안만 삭제할 수 있다.
- 신규 유형: 아이템/재료 묶음(20종, 종류별 1~1,000,000개), 공개·활성 지정 장비 1개, 공개·활성 카드 자유 선택팩, 일반 용병 C~SSS 등급 가중치/후보 지정 팩. 기존 6개 유형과 미스틱 고정 4종 각 25%를 보존한다.
- 상품 최대 100개. 계정 한도 1~1,000회; 누적·일일·주간·월간 선택. 일일 00:00, 주간 월요일 00:00, 월간 1일 00:00 한국 시간에 갱신한다. 판매 시작·종료는 한국 시간 입력, UTC 저장이다.
- 일반 용병 후보로 리미티드/미출시 잠금을 우회하지 않는다. 획득 OFF 후보도 서버에서 거절한다. 등급 내 등록 후보는 균등 추첨이며 등급 확률을 표시한다.

## 거래 보존

운영 설정·가격·한도·판매 스위치·재화 지급 설정을 자동 변경하거나 샘플 상품을 추가하지 않는다. 기존 상품의 ID/종류, 구매 기록, 보관 팩의 구매 시점 구성과 진행 중 영수증을 유지한다. v1 필드만 있는 설정은 같은 모양으로 정규화한다.

기존 공통 거래와 사용자 잠금, OWNER 권한/설정 버전 충돌 검사를 사용한다. 결제·구매 횟수·모든 묶음 구성품 지급을 한 거래로 처리한다. 동일 요청은 재지급하지 않는다. 기간별 한도·판매 기간을 결제 거래 안에서 다시 확인하고, 지급 불가/재고 초과 시 모두 롤백한다. DB 마이그레이션은 없다.

## 전체 게이트에서 발견한 기존 문제

최초 후보 `44391dbce`의 상점 검사 110건은 통과했다. 이후 공통 전투 검사에서 4건이 실패했다.

- 실제 복구 경로: `js/app.js`의 엔진 선택 문자열에 `?&generalJok=...`가 들어 있어 현재 URL과 일치하지 않았다. 공통 엔진 경로+`?`까지만 매칭하도록 한 줄 수정하고 메인 앱 캐시 쿼리를 갱신했다. 엔진·브리지 두 요청과 제한된 재시도라는 기존 검증을 완화하지 않는다.
- 탑 렌더 검수: 현재 `currentUserId`/`autoNextEnabled` 실제 함수를 함께 실행하고 `serverUserId` 계정 형태로 맞춘다.
- 비차단 배너 검수: 이미 배포된 제너럴 족의 소스를 비교 목록에 포함한다. 번들/소스 호출 수의 정확한 일치 검사는 유지한다.

실제 로더 수정이 포함되므로 앞선 게이트를 재사용하지 않고 수정 후보의 전체 게이트를 다시 실행한다.
