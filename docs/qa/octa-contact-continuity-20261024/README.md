# 8방향 유도탄 도착 지점 정지 수정

사용자 신고: 8방향 유도탄이 대상 앞에서 멈춘 뒤 뒤늦게 폭발함.

## 원인과 수정

- 기존 공용 재생기는 8발의 타격 시간을 각각의 HIT를 처리할 때 예약했다. 오디오 출력 지연이 매번 추가됐고, 다른 슬롯의 처치/카드 복귀 대기열에 뒤쪽 HIT가 막히면 비행 시간이 종점 직전으로 고정됐다.
- 실제 운영 `index.html` → 토벌 시작 버튼 → V3 전투에서 같은 문제를 재현했다. 첫 1발 후 나머지 7발이 대상 앞에 정지했다. `before/browser-report.json`과 `before/before-1.7.png` 참고.
- 발사 시 확정된 서버 영수증의 8개 접촉 시간을 함께 예약한다. 이미 발사된 유도탄은 기존 광역 접촉 처리 경로와 같은 공용 시계에서 정확한 대상 인스턴스에 명중하며, 무관한 처치 애니메이션의 완료를 기다리지 않는다.
- 서버 영수증 이외의 피해/폭발을 추가하지 않는다. 후속 콜백 순서·슬롯 교체 대기·치명 타격 전 탄착 대기·QTE·사용자 일시정지·취소를 유지한다.
- 첫 명중 1,020ms, 이후 60ms 간격으로 8발, 마지막 1,440ms. 피해·10초 주기·대상·원화·승인 아틀라스·전투 UI는 변경하지 않았다.

## 검증

- 회귀: 출력 지연 + 다른 대상의 KO 대기로도 8발 연속 명중, 뒤늦은 콜백에서 중복 타격 없음, QTE/일시정지/배속/취소, 치명 타격과 대상 재사용, 기존 광역 스킬/로켓/헬기 재생.
- 변경 전 재현 테스트는 `1 !== 8`로 실패했다. 변경 후 동일 시나리오의 일반/연속 전투 두 모드가 통과했다.
- PC 1440×1000 / 모바일 390×844에서 실제 토벌 시작 → 유도탄 비행·명중 → 결과 → 복귀, 이어서 PVP 매칭 → 전투 → 결과 → 복귀를 확인했다. 전용 프리뷰 UI를 만들지 않았고 테스트는 음소거했다.
- API는 격리된 검수 영수증만 사용한다. 운영 계정·재화·설정 쓰기 없음. 로컬 기록: `local/browser-report.json`.
- 동일 공용 소스로 기존 V3 소비자 10개를 재빌드하고 런타임/로더 캐시를 갱신했다. 운영 반영 및 공개 파일 재검증 결과는 배포 후 아래에 기록한다.
