# 하이퍼팩 연속 개봉 · CMS 저장 · 운영 도감 (2026-09-13)

사용자 지시: 연속 개봉 버튼 추가, CMS 확률·재화 수량 저장 문제 수정, 도감에 CMS의 현재 스킬까지 표시, 장비 강화 화면을 참고한 도감 디자인 개편.

## 반영 내용

- 하이퍼팩 결과 화면에 같은 수량의 `1회 더 개봉` / `10회 더 개봉`과 코인 비용을 표시한다. 연출 완료 또는 건너뛰기 후 활성화한다. 이전 확정 결과를 확인 처리한 다음 새 요청 ID로 다음 개봉을 시작하며, 연타·진행 중 중복 호출을 차단한다. ON/OFF·잔액·지급·복구 검사는 기존 서버 경로를 계속 사용한다.
- `확률 초안 저장`을 `운영 확률·수량 저장`으로 변경한다. 비어 있는 저장 사유가 숨은 필수 조건으로 저장을 막던 부분을 없애고, 변경 전후 확률·수량을 자동 감사 사유로 보낸다. 직접 작성한 사유도 보존한다. 합계·정수·권한·revision·요청 재시도 검증은 유지한다. 오류와 성공 결과를 저장 버튼 옆에도 표시하며, 실패 시 입력은 보존한다.
- `GET /api/mercenary-codex`는 운영 CMS 행을 매번 읽어 용병 이름·칭호·등급·포지션·역할·고정 전투력·직접 배정된 스킬의 효과·조건·배율·재사용·에너지를 반환한다. 관리자 메모·감사 로그·계정 보유·미정 획득 비용은 공개하지 않는다. 전투 정보만 조회하는 도감은 정적 원화 페이지처럼 점검 중에도 열람할 수 있다. 개봉·편성·전투의 점검 게이트는 유지한다.
- 도감은 독립 아트 검수 프리뷰와 분리된 운영 화면이다. 승인된 장비 강화의 남색 패널·연두색 강조·Barlow Condensed/Noto Sans KR·연구실 배경을 사용하고, 용병 목록 / 원화·SD / 전투·스킬 정보로 구성한다. 공식 원화와 카드 프레임은 별도 계층이며 원본을 수정하지 않는다. 검색·등급/위치 필터·즐겨찾기·딥링크·원본 확대를 제공한다.
- 사용자에게 새 확률·수량을 받지 않았으므로 운영 확률·지급량은 수정하지 않는다. 기존 하이퍼팩 ON도 유지한다.

## 검증

- 실제 운영 모듈과 격리 SQLite 계정으로 PC 1440px / 모바일 390px 화면을 검수했다. 원화·SD 전환, 스킬명 검색, 등급별 전투력, 스킬 수치, 가로 넘침, 하단 버튼을 확인했다.
- 격리 CMS에서 마스터의 별 2,000개·미스틱에너지 50개로 변경, 사유 공란 저장, 재조회, 자동 감사 기록을 확인했다. 해당 값은 로컬 검증값이며 운영에 저장하지 않았다.
- 총 확률 110%의 실패를 재현하고 입력 보존과 저장 버튼 옆 오류를 확인했다.
- 실제 로컬 개봉 1회 → 연속 1회, 10회 → 연속 10회, 버튼 연타, 고유 영수증과 총 110억 코인 차감(600억 → 490억)을 확인했다. CMS OFF 전환 후 추가 개봉 없이 반복 버튼이 비활성화됐다. 운영 계정 재화는 검증에 쓰지 않았다.
- SQLite·PostgreSQL에서 CMS 변경 후 공개 도감 조회, 스킬 배정 해제, 공개 필드 제한, 읽기 전용 메서드, 검색·필터·HTML 이스케이프를 검증한다. 기존 프리뷰 로스터는 보존한다.
- 실제 브라우저 기록과 화면: 배포 디렉터리 외부 `../qa/hyper-cms-codex-2098/browser-report.json` 및 PNG. 운영은 범위 커밋과 전체 `release:gate` 후 `npm run deploy:production`으로 반영한다.
- 운영 검수에서 이미지 로드 후 SD의 원본 높이가 전환 버튼을 덮는 현상을 확인했다. SD를 표시 영역 안에 절대 배치하고 원화·SD 버튼 영역을 분리했다. PC 43종 전체, 태블릿·모바일 각 4종의 이미지 로드 완료 후 영역 경계와 실제 전환 클릭 51건을 통과했다. 증빙은 `sd-bounds-report.json`이며 CSS 버전은 `2098.1`이다.
