# 배틀슈트 스킬칩 V2046 — 장착 기반 준비

상태: **장착 UI/API와 아이콘 검증 완료, 전투 계산·발동 연결 미완료, 운영 미배포.**

## 확정 범위

- 로켓런처 ×2.5, 헬기폭격 ×5의 독립 배율 함수.
- 아바타 바로 오른쪽의 스킬칩 탭, 계정별 최대 3슬롯, 같은 칩 중복 불가.
- 실제 `cnine_user_inventory` 보유 수량과 `inventory_items.is_active`를 확인하는 장착/해제 API.
- 칩은 장착·해제로 소모되지 않는다. 신규 지급, 획득처, 상점 가격, 확률은 추가하지 않았다.
- 512×512 실제 알파 PNG/무손실 WebP 2종. 생성 원본과 프롬프트·해시를 보존했다.

## 사용자 확인 및 후속 구현 필요

요청에 로켓런처 이름이 두 번 쓰였다. **로켓런처 3초 / 헬기폭격 15초**는 제안 해석이지 확정값이 아니다. 피해 배율의 기준도 기존 배틀슈트 1발 피해인지 PVE 전투력인지 확인하지 못했다. 비동기 질문을 보냈으며 아직 답변이 없다.

`shared/battle-suit-skill-chips.mjs`의 `SKILL_CHIP_RUNTIME_ENABLED=false`와 `TIMING_AND_DAMAGE_BASE_CONFIRMATION_PENDING`을 유지한다. 현재 배율 함수는 전투 엔진에서 호출하지 않으며, 실제 전투 이벤트·보상·전투력은 바뀌지 않는다. 확정 후 다음을 함께 마무리해야 한다.

1. 서버 권한으로 칩별 독립 피해 이벤트와 한 게임마다 초기화되는 발동 스케줄을 만든다. 중복·미보유·비활성 칩은 전투 시작 스냅샷에서도 제외한다.
2. 기존 서버의 `BATTLE_SUIT_REFERENCE_CYCLE`/시뮬레이션 `clock`은 실제 초 단위가 아니다. 3 또는 15를 그대로 대입하지 않는다. 기존 V3는 서버 시간 값을 그대로 재생하지 않으므로 일시정지·배속·재시작에도 일치하는 공통 전투시간 계약이 필요하다.
3. 승인 프리뷰의 Pixi/GSAP 이펙트를 기존 V3 렌더러에 연결한다. 로켓 투사체는 기존 몸통 목표점을 보존하고, 폭발 접지는 `root.y` 발끝을 유지한다. 일반 덱/카드 도크/아트 어댑터를 복제하지 않는다.
4. 기본 사격과 칩 피해 집계를 분리하고, 미장착 회귀·반복 주기·15초 이전 종료·동시 발동·전투 종료 후 취소·다음 게임 초기화를 검증한다.
5. 기능을 활성화할 때 앱/서비스워커 캐시 버전을 함께 갱신하고, `test:skill-chips`를 운영 출시 게이트에 포함한다. 확인 전 준비 커밋을 운영에 배포하지 않는다.

## 데이터와 확장

단일 카탈로그: `shared/battle-suit-skill-chips.mjs`. 안정된 코드·이름·이미지·효과 키·배율을 관리한다. 신규 스킬은 레지스트리와 이펙트 구현, 회귀 테스트를 추가한다. 이미 적용된 카탈로그에 추가할 때에는 기초 마이그레이션 키도 갱신해야 한다.

장착 테이블: `user_skill_chip_loadout_v2046`. `(user_id,slot_no)` 기본 키, `(user_id,item_code)` 유일성, 1~3 슬롯 CHECK를 DB가 보장한다. 장착은 보유 확인을 같은 INSERT 문 안에서 수행한다. 해제는 사용자·슬롯·기존 코드가 모두 일치해야 삭제되어 오래된 화면이 새 장착을 지우지 못한다. PostgreSQL에서는 기존 어댑터가 prepared DDL을 무시하므로 고정 DDL을 `execSchema`로 적용한다.

엔드포인트: `GET character/skill-chips`, `POST character/skill-chips/equip`, `POST character/skill-chips/unequip`. 장착/해제 본문은 `{slot:1,code:'SKILL_CHIP_ROCKET_LAUNCHER'}`. 클라이언트는 성공 응답의 최종 상태를 사용한다.
