# 하이퍼팩 개봉 수량 긴급 수정 · 2026-09-13

10회(50억) 개봉 결과에서 닫기를 누르지 않고 용병 지휘소로 이동하면 이전 요청이 localStorage에 남았다. 이후 1회 버튼이 선택한 수량 대신 이전 요청의 10회를 사용했다. 완료된 요청은 이전 결과 10장을 다시 표시했으며, 미완료 요청은 이전 10회 요청을 재전송할 수 있었다. 특정 신고 계정의 추가 차감 여부는 이 재현만으로 확정하지 않는다.

완료된 영수증은 표시·화면 이동 전에 미완료 요청에서 제거하고 최근 결과 포인터로 분리한다. 기존 버전에서 남은 완료 요청도 정리한 뒤 새로 선택한 수량으로 요청한다. 미완료 요청의 수량이 새 선택과 다르면 결제를 실행하지 않고 이전 처리 확인을 안내한다. 네트워크 오류 후 재시도는 원래 요청 ID를 보존하여 중복 차감을 방지한다. 최근 결과 확인은 조회만 수행한다.

지휘소 버튼에 선택 횟수를 표시하고 개봉 복구를 실제 팩 복구 경로로 연결했다. 서버의 단일 개봉 경로 `mercenary-cards/open`은 정확히 count 1만 허용한다. 일괄 개봉과 기존 공용 경로는 검증된 1~10회 계약을 유지한다. 상점·지휘소 모듈 및 앱 진입 캐시 키는 `2102-open-count`로 갱신했다.

검증:
- SQLite·PostgreSQL에서 단일/10회 개봉, 정확한 차감과 지급, 중복 요청 재사용, 단일 경로 count 10 거부 및 OFF 동작을 확인했다.
- 실제 개봉 모듈의 회귀 테스트로 화면 이동, 기존 완료 요청 복구, 미완료 수량 불일치 차단, 응답 유실 후 무차감 복구, 연속 클릭 잠금, 요청·결과 불일치를 확인했다.
- 실제 상점 개봉 모듈과 지휘소 화면을 사용하는 격리 브라우저 API 검수에서 PC 1440×1000·모바일 390×844 모두 10회 → 지휘소 이동 → 1회 요청, 총 11개 결과·55억 차감을 확인했다. 최근 결과 확인은 추가 요청·차감이 없다. 연출 모듈은 거래·탐색 검증용 스텁이며 시각 연출의 신규 승인 검사가 아니다.
- 브라우저 증거와 보고서는 배포 폴더 밖 `../qa/hyper-pack-count-2102/`에 보존한다.

운영 반영은 범위 커밋 후 `npm run deploy:production`의 전체 `release:gate`를 통과해야 한다. 기존 확률·지급 수량·개봉 ON 정책은 변경하지 않는다.
