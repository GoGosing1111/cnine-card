# 변경 규모별 검수·배포 — 2026-09-23

사용자 승인: 작은 수정은 관련 회귀와 핵심 경로만 확인하고, 큰 변경만 전체 검사를 한다. 과거의 일률적인 전체 검사·중복 화면 검수 요구보다 이 기준이 우선한다. 기능 출시 승인, OFF 상태, 권한·재화 보호를 생략하는 규칙은 아니다.

## 선택 기준

- **작은 수정**: 한 버그·동작·화면에 영향이 제한되고 호출 경로와 회귀검사를 특정할 수 있다. 재현과 관련 테스트, 영향받는 핵심 경로만 확인한다. 일반 서버 코드나 생성 번들이 변경됐다는 사실만으로 큰 변경으로 분류하지 않는다.
- **큰 변경**: 여러 시스템의 구조 개편, 인증/권한 기반, 공통 DB/트랜잭션 기반, 마이그레이션, 런타임 의존성·인프라 변경, 영향 범위를 한정할 수 없는 변경. 기존 전체 `release:gate`를 사용한다.
- **문서/규칙/배포 도구만 변경**: 관련 도구 테스트 후 범위 커밋·원격 반영으로 끝낸다. 게임 파일이 같으면 운영을 재배포하지 않는다.
- **자산 전용**: 기존 `--assets-only` 자격과 검증을 유지한다.

## 작은 수정 배포

PowerShell 예시(실제 배포 직전 커밋과 해당 작업 테스트로 설정):

```powershell
$env:SCOPED_DEPLOY_BASE = '<실제 직전 운영 배포의 40자리 SHA>'
$env:SCOPED_DEPLOY_REASON = '경찰 조은 처치 후 표식 연출 수정; 해당 회귀와 공통 전장 입장만 검사'
$env:SCOPED_DEPLOY_TESTS = '["tests/mercenary-police-restraint-20260923.test.mjs"]'
$env:SCOPED_DEPLOY_CHECKS = '[]'
npm run deploy:production -- --scoped
```

- `SCOPED_DEPLOY_TESTS`: 정확한 저장소 상대 경로의 테스트 파일 JSON 배열. glob, 상위 경로, 미추적 파일은 거부한다.
- `SCOPED_DEPLOY_CHECKS`: 필요한 기존 `test:*` 또는 `check:worker` npm 스크립트 이름 JSON 배열. 파일 단위 선택으로 충분하면 광범위한 묶음을 중복 선택하지 않는다.
- 최소 하나의 관련 검사를 선택하고, 변경 범위와 선정 이유를 20자 이상 기록한다. 직전 운영 SHA를 추측하거나 단순히 HEAD의 부모로 대체하지 않는다. 그 기준부터의 전체 diff가 이번 배포 범위다.
- `functions/`·`workers/` 변경은 Worker 컴파일 검사를 추가한다. 공용 V3 원본·라이브 번들·래퍼 변경은 실제 번들/메인 로더 연결 회귀를 추가한다.
- DB 기반·인증 모듈·마이그레이션·Wrangler 설정·의존성 변경은 경량 경로에서 차단한다. 자동 차단 목록은 최소 장치이며 나머지 큰 변경을 작은 수정으로 취급해도 된다는 뜻은 아니다.
- 선택 검사가 실패하면 배포하지 않는다. 깨끗한 커밋·미추적/ignored 파일·origin/main·출시 플래그·캐시 호환·운영 Hyperdrive 조건은 기존대로 검사한다.
- 인자가 없는 `npm run deploy:production`은 전체 게이트 경로를 보존한다. 작은 수정에 습관적으로 이 기본 경로를 사용하지 않는다.

## 중복 검수 방지

코드를 고치는 동안 필요한 재현 테스트는 실행하되, 최종 빌드가 같고 배포 과정에서 다시 실행할 검사를 별도 “사전 전체 검사”로 반복하지 않는다. 관련 서버 거래는 원자성/중복 지급/재시도 등 그 변경의 위험을 직접 확인한다.

UI 변경은 해당 화면의 PC·모바일 핵심 조작 한 번씩, 전투 변경은 PVE·PVP 핵심 흐름을 확인한다. 구버전·재입장·장애 주입은 그 경로가 변경됐거나 문제가 관측된 경우에만 추가한다. 배포 후에는 변경 파일과 바뀐 대표 경로를 짧게 확인하고 전체 시나리오를 다시 수행하지 않는다.

이 정책 자체의 검증: `npm run test:release-policy`. 게임 UI나 서버 동작 변경은 없으므로 이번 정책 반영은 게임 전체 검사·운영 재배포 대상이 아니다.
