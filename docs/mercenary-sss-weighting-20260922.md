# 하이퍼팩 SSS 용병별 가중치

2026-09-22 사용자 요청: **라그니엘이 오메가-X보다 적게 나오도록 하고 동일 등급 균등 추첨을 해제한다.**

## 기존 상태와 변경

운영 확률 r9의 SSS 전체 확률은 `1 / 1,000,000 = 0.0001%`다. SSS 풀은 오메가-X(V-021), 라그니엘(V-046) 두 종이고, 등급이 선택되면 두 카드가 각각 50%로 추첨됐다. 흑월 추가가 SSS 전체 확률을 올린 것은 아니다.

사용자에게 전체 확률 유지와 9:1 가중치를 기본안으로 알렸다. 이번 반영은 **SSS 전체 0.0001%를 유지하면서 오메가-X 가중치 9, 라그니엘 가중치 1**로 변경한다.

| 용병 | SSS 안에서의 비율 | 개봉 1회 기준 확률 | 종전 대비 |
|---|---:|---:|---:|
| 오메가-X | 90% | 0.00009% | 1.8배 |
| 라그니엘 | 10% | 0.00001% | 1/5 |

확률은 독립 추첨이며 특정 횟수 안의 획득을 보장하지 않는다. 최근 완료된 2,000개 개봉 요청의 읽기 전용 조사에서는 SSS 결과 2개 중 1개가 별도 운영 지정 지급이었다. 자연 추첨과 지정 지급을 혼합해 확률 오류라고 판정하지 않는다. 이 표본만으로 무작위 분포의 정확성을 증명하는 것도 아니다.

## 구현

- `shared/mercenary-draw-policy-v1.mjs`: `WEIGHTED`와 `cardWeights`를 지원한다. 미설정 카드는 가중치 1이다. 기존 `UNIFORM` 및 규칙 없는 초안은 동일 확률인 빈 가중치로 호환한다. 양의 정수 1~1,000,000만 허용하며 CMS 저장과 추첨에서 미등록 코드를 거부한다.
- `functions/_mercenary_draw_accounting.js`: 기존 1,000,000단위 등급 추첨 후 해당 등급의 가중치 합을 상한으로 한 정수 누적 추첨을 수행한다. 기존 암호학적 난수 및 나머지 편향 제거를 재사용한다. 등급 확률, 보유 여부 미반영, 재추첨 없음, 중복 수량 집계는 유지한다.
- OWNER CMS에 등급별 용병 가중치 편집, 등급 내부 비율, 전체 개봉 기준 개별 확률을 표시한다. 기존 버전 충돌 방지·감사 기록·같은 요청 재시도를 재사용한다.
- 상점과 관리자 화면의 균등 추첨 안내를 수정하고 해당 코드의 캐시 키만 갱신한다. V3 전투 번들·로더·이미지·SD·전투 버전은 변경하지 않는다.
- 가격, 등급별 확률·수량, 계정의 보유품·코인과 기존 운영 지정 지급은 변경하지 않는다. 이미 저장된 개봉 결과와 재시도 영수증은 새 가중치로 다시 추첨하지 않는다.

## 검증

- 확률/CMS/회계 검사 **29개 통과**. 정확한 9:1 경계, 전체 1ppm 유지, 레거시 호환, 잘못된 가중치 거부, OWNER CMS 감사/충돌/재시도, SQLite·PostgreSQL에서 10회 개봉의 지급·중복·실패 복구·기존 영수증 보존을 확인했다.
- 기존 개봉 버튼·1회 운영 지정 지급 검사 **36개 통과**.
- 실제 Chrome과 로컬 PostgreSQL 호환 DB/실제 CMS 핸들러로 **1440·1024·390·360px**를 검사했다. 가중치 입력 시 90%/10%와 개별 확률 갱신, 저장·새로고침·버전 충돌·응답 유실 재시도·JSON 내보내기·다른 CMS 초안 보존을 확인했다. JavaScript 오류와 가로 넘침이 없고 PC/모바일 캡처를 직접 검수했다. 운영 계정 개봉은 실행하지 않았다.

## 운영 적용 순서

1. 깨끗한 후보를 커밋·푸시하고 `npm run deploy:production`으로 필수 `release:gate`를 통과한 서버와 CMS를 함께 배포한다.
2. 새 서버가 반영되기 전에는 운영 정책을 WEIGHTED로 바꾸지 않는다. 구버전 서버는 새 정책을 알지 못하므로 순서를 지킨다.
3. 운영 r9의 전체 정책 해시와 SSS 구성원을 비교하고, 기존 OWNER CMS 저장 핸들러로 r10을 기록한다. 요청 ID는 `sss-weights-20260922-omega9-ragniel1`이다. 다른 변경이 선행했으면 덮어쓰지 않고 중단한다.
4. 실제 운영 정책과 감사 기록, 전체 확률·수량 불변, 개봉 ON 상태, 준비 상태를 읽기 전용으로 확인한다. 운영 정책을 입력으로 10개 결정적 가중치 티켓이 9:1로 나뉘는지 검사하되 계정 재화나 획득 API는 호출하지 않는다.

회귀 시에는 먼저 새 서버에서 감사 기록의 이전 정책을 OWNER CMS로 복원한 뒤 서버를 되돌린다. 구버전 서버에 새 WEIGHTED 정책을 남기지 않는다.
