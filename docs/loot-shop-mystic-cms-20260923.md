# 고급 전리품 상점 미스틱 장비 선택 복구

- 원인: 운영 미스틱 장비는 `MYTHIC` 등급인데 상점 카탈로그, CMS 선택 필터, 저장 검증, 구매 지급 가드가 `MYSTIC` 등급을 요구했다. 기존 테스트도 존재하지 않는 등급을 사용해 누락을 발견하지 못했다.
- 수정: 공개·활성 상태의 `MYTHIC` 중 이름이 `미스틱 `으로 시작하는 장비를 상품 후보로 사용한다. CMS와 서버가 공용 판정 함수를 사용하며, 카탈로그 SQL과 원자적 지급 가드도 같은 조건을 사용한다. 다른 신화 장비와 F바디는 미스틱 상품에 포함하지 않는다.
- 미스틱 레깅스·슈즈·슈트·듀얼디스크를 확정 지급 장비에서 선택하고 가격·구매 한도·상품 판매 사용을 저장할 수 있다. 기존 상품 설정·구매 기록·피그 코인 지급 정책·판매 스위치는 배포로 변경하지 않는다.
- 관리자 모듈과 공용 정책 모듈의 CMS 참조 버전을 v5로 갱신했다. DB 변경이나 운영 정책 자동 저장은 없다.

## 검증

- `npm run test:loot-shop`: 57개 통과. SQLite와 PostgreSQL 호환 계층에서 실제 등급의 후보 조회, 명시적 선택 저장, 다른 신화/비공개/비활성/잘못된 등급 거절, 구매 지급·실패 롤백·동일 요청 재시도를 확인했다.
- `node scripts/qa-loot-shop-mystic-cms.mjs`: 격리 SQLite DB와 실제 CMS 모듈/API로 검수한다. 검수용 계정·가격·ON 저장은 로컬에만 적용된다.
- 데스크톱과 390px 모바일에서 4종 선택 목록, 미스틱 슈트 선택·판매 ON 저장·재조회, 듀얼디스크 변경 저장·브라우저 새로고침 후 유지, 가로 넘침 없음을 확인했다.
- 운영 배포는 깨끗한 범위 커밋에서 `npm run deploy:production`을 사용하며 내부 `npm run release:gate`와 Hyperdrive 캐시 OFF 검사를 통과해야 한다.
