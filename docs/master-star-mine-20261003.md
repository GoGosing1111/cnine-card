# 마스터의 별 광산 — 2026-10-03

사용자 요청: 전동드릴·태양광드릴·황금드릴 원본, 광산 이미지, 현 메타에 맞춘 실제 운영 UI 및 4시간 방치 채굴.

## 확정한 운영 기준

- 사용자 `그렇게 하고 수정도 가능하게 해놔` 승인: **4시간당 전동 5,000개 / 태양광 15,000개 / 황금 30,000개**. OWNER CMS에서 드릴별 보상을 수정한다.
- 계정당 채굴 1건. 드릴은 영구 장비로 사용하며 채굴 시작 때 소모하지 않는다. 접속 종료 후에도 서버 시각으로 진행한다.
- 4시간 후 직접 수령하며, 이후 새로 시작한다. 미수령 보상은 1회분만 유지되고 추가 회차가 자동 누적되지 않는다.
- **드릴 획득 방식은 미정**이다. 초기 `mode: OFF`, `acquisition: PENDING`, 검수 계정 없음. 자동 지급·판매·가격은 설정하지 않는다.
- CMS에는 OFF/TEST/ON, 검수 계정, 획득 안내, 획득 방식 미정/CMS 지급, 계정 확인 후 개별 영구 드릴 지급·회수를 준비한다. 실제 계정 지급은 이번 작업에서 하지 않는다.
- 보상 미설정 또는 획득 방식 미정이면 TEST/ON 저장을 거부한다. CMS 변경은 다음 채굴부터 적용한다. 기존 채굴은 시작 당시 보상량으로 수령 가능하고 OFF 전환도 이미 확정된 수령 권리를 없애지 않는다.

## 경제 근거

2026-10-03 운영 PostgreSQL 읽기에서 FUR +14/+15 시도당 마스터의 별 1,000,000/2,000,000개, 현재 봉인전 성공 보상 300,000개를 확인했다. 추천값은 아래와 같고 사용자 승인으로 초기값을 확정했다.

| 드릴 | 4시간 | 하루 3회 | 하루 이론상 6회 |
|---|---:|---:|---:|
| 전동드릴 | 5,000 | 15,000 | 30,000 |
| 태양광드릴 | 15,000 | 45,000 | 90,000 |
| 황금드릴 | 30,000 | 90,000 | 180,000 |

하루 수령 횟수 제한이 아닌 비교 수치다. 실제로는 수령 후 재시작 시점에 따라 횟수가 줄어든다. 드릴의 최종 획득 난이도에 맞춰 OWNER가 보상량을 조절할 수 있다.

## 라이브 연결

- 운영 화면: `/master-star-mine/`. 공통 모험·PVE 메뉴와 전체 메뉴에서 진입한다.
- 동일한 네이비·라임 내비게이션, 광산 작업대, 실제 드릴 3종 선택, 보유 마스터의 별, 서버 시간 타이머, 진행률, 수령, 최근 5회 기록.
- `GET master-star-mine/state`, `POST master-star-mine/start`, `POST master-star-mine/claim`.
- OWNER CMS: `admin/master-star-mine`, `admin/master-star-mine/user`, `admin/master-star-mine/drill`.
- 기존 인증·계정 mutation lock·joint transaction·인벤토리 지급을 재사용한다. 브라우저가 보상 수량이나 완료 시점을 제출하지 않는다.
- 신규 독립 테이블 `master_star_mine_runs_v1`: 사용자당 미수령 채굴 한 건을 부분 UNIQUE 인덱스로 보장한다. 시작 보상·설정 버전·시각·수령 영수증을 보존한다.
- 채굴 시작의 PENDING 재시도는 실제 커밋 시각에 4시간을 시작한다. 실패한 요청을 오래 보관해 미리 시간을 쌓을 수 없다.
- 수령 상태 변경·MASTER_STAR 인벤토리·감사 지급 로그·완료 영수증은 원자 처리한다. 동일 요청, 새 요청으로 중복 수령, 동시 요청, 응답 유실을 방어한다.
- 드릴 지급/회수는 대상 계정 잠금, 보유량 검증, 감사 로그로 처리한다. 이미 보유한 드릴을 중복 지급하지 않으며 채굴 중인 드릴은 회수할 수 없다.
- 스키마는 HTTP 요청에서 만들지 않는다. `scripts/ops/master-star-mine-prepare-20261003.mjs`가 명시적으로 준비하며 기존 CMS 수치를 덮어쓰지 않는다.
