# 랭크 듀오 자동 시즌 · 24시간 모집

> 이 문서는 최초 연동 구현 기록이다. 후속 승인된 독립 24시간 모집 + 전투 7일, 행동력·승리·티어 보상 CMS의 최신 정책은 [주간 듀오 운영](ranked-duo-weekly-rewards-20260925.md)을 따른다. 아래 동시 종료·경제 보상 없음·읽기 전용 CMS는 과거 기록이다.

사용자 최종 정정: 듀오 챌린저와 트로피는 **상위 10팀**이다. 일반 랭크전의 20위 기준은 별개로 유지한다.

사용자 후속 승인: 랭크전 시즌에 맞춰 자동 모집·종료, 같은 티어 명칭에 전용 이미지, 듀오 챌린저 전용 트로피. 모집은 3일에서 **24시간**으로 정정했다. 행동력은 일반 랭크전과 같은 최대치·충전 간격·소모량을 사용하되 개인별 듀오 잔액을 따로 관리한다.

## 운영 동작

- 공식 랭크전의 이름·시작·종료를 읽어 자동 시즌을 만든다. 이름과 UTC 시작 시각으로 같은 시즌을 식별하므로 종료일 수정이나 날짜 표기 차이로 중복 모집하지 않는다.
- 신규 시즌 감지 후 24시간 참가 모집, 강자+약자 자동 팀 편성, 최소 2팀이 준비되면 자동 대전한다. 첫 배포가 시즌 도중이어도 24시간을 보장한다. 종료까지 24시간 이하만 남았다면 다음 공식 시즌을 기다린다.
- 모집 마감 뒤에는 12명씩 전력을 평가하고 40팀씩 공개한다. 참가자가 많으면 순차 편성이 끝난 뒤 대전이 열린다. 홀수 인원은 마지막 신청자가 대기하고, 무효 덱·정지 계정은 대기로 남겨 다른 팀의 편성을 막지 않는다.
- 추가모집은 경기 시작 전 CMS에서 가능하다. 기존 팀은 유지하고 새 참가자·대기자를 편성하며 공식 시즌 종료를 넘는 모집은 거부한다. 최소 2팀이 안 되면 준비 상태로 기다리며 트로피는 발생하지 않는다.
- 일반 랭크전 종료 시각부터 신규 경기를 받지 않는다. 접수된 미완료 경기는 회당 최대 4건씩 복구하고 전부 완료된 뒤 최종 순위를 고정한다. 완료 순위·두 팀원의 트로피·시즌 종료는 같은 트랜잭션이다.
- 랭크전 종료일 연장은 같은 듀오 시즌에 반영한다. 종료일 단축으로 모집 뒤의 대전 기간이 사라지면 미개시 시즌을 종료하며 트로피를 만들지 않는다. 종료된 동일 시즌은 다시 모집하지 않는다.
- 자동 시즌의 수치·티어는 생성 시 일반 랭크전 설정을 복사한다. 행동력 충전 시각의 나머지를 보존하며 최대치를 넘지 않는다. 팀원 또는 일반 랭크전의 잔액을 차감하지 않는다.
- 기존 수동 시즌이 있다면 먼저 해당 시즌을 유지하고 종료 후 자동 연동한다. 기존 경기 계산 버전은 유지해 이미 예약한 전투를 복구할 수 있다.

## 티어와 트로피

브론즈 → 실버 → 골드 → 플래티넘 → 다이아 → 마스터 → 그랜드마스터 → 챌린저. 점수 구간은 공식 랭크전 설정을 사용하며 챌린저는 상위 10팀이다. 동점은 기존 팀 순위의 `score DESC, id DESC`를 사용한다.

최종 1~10위 팀원 각각에게 `DUO_CHALLENGER` 트로피를 시즌당 1회 영구 기록한다. 같은 시즌의 중복 실행·응답 유실은 중복 지급하지 않는다. 다음 시즌에도 명함의 획득 수와 첫 획득일이 남는다. 능력치·코인·별 보상은 없다.

최종 문장은 서로 반대 방향을 바라보는 검투사 투구 두 개다. 최초 양쪽 하트 디자인은 사용자 반려로 제외했다.

전용 문장 8종과 트로피 1종은 built-in `image_gen`으로 각각 생성했다. 원본 투명 PNG와 런타임용 WebP를 `assets/ui/ranked-duo/`에 보존한다. 전체 프롬프트·수정 지시·원본 경로·해시는 `manifest-v2.json`에 기록했다. 로비·팀 랭킹·티어 안내·명함에 연결하며 384px 문장, 512px 트로피만 실제 화면에서 로드한다.

추가 요청한 공지용 포스터는 `assets/ui/ranked-duo/announcement-poster-v3.png`(1024×1536)다. 최종 투구 트로피와 대표 문장 3종을 재활용하고 24시간 모집, 자동 팀 편성, 네 덱 동시 전투, 덱 최신화, 개인 행동력, 자동 종료와 **상위 10팀** 트로피 지급을 설명한다. 상단 `숲켓몬`의 획을 또렷한 한글로 수정했다. 수정 프롬프트·참조 이미지·원본 해시는 같은 이름의 JSON에 보존한다. 외부 공지 게시 자체는 수행하지 않는다.

## DB·스케줄러 범위

- 기존 클랜 워커에 별도의 `RankedDuoAlarm` 객체를 둔다. 클랜과 다른 객체·연결로 처리해 듀오 편성이 클랜 드래프트를 지연시키지 않는다. 매분 Cron은 알람만 준비한다.
- 알람은 다음 재시도를 먼저 저장하고 DB 연결을 열어 한 단계만 진행한 뒤 반드시 닫는다. 접속 중인 유저가 없어도 동작한다. 활성 단계는 1초 간격, 평상시 최대 1분 간격이다.
- 스케줄러 전용 60초 임대와 시즌 리비전 가드가 중복 실행을 막는다. 일반 게임 요청은 이 임대 행을 사용하지 않는다. 평상시 전체 참가자 재계산과 전체 순위 COUNT가 없다.
- 10,000명 상한에서 편성 정렬은 한 번 수행한다. 공개 계획은 40팀 단위 별도 행에 저장하고 한 번에 한 묶음만 읽고 삭제한다. 로비 상위 10팀·랭킹 상위 100팀은 기존 시즌/점수 인덱스를 사용한다.
- 운영 스키마는 기존 테이블 소유자별로 최초 1회 준비하고 독립 영속 마커를 남긴다. 스케줄러는 이 마커를 확인하며 유저 요청에서 DDL을 실행하지 않는다. 명함은 마커와 해당 사용자 트로피 인덱스만 추가 조회한다.
- Hyperdrive SQL 캐시 OFF 유지. 다른 콘텐츠 출시 플래그와 일반 랭크전의 재화·정산 정책은 변경하지 않는다.

## 검수와 측정

`tests/ranked-duo-seasons.test.mjs`에서 SQLite·PostgreSQL·pipeline 경로로 자동 모집/시작/종료, AP 충전과 개인 분리, 마지막 경기 복구, 트로피 트랜잭션 실패/재시도, 동시 스케줄러, 추가모집, 무효 참가자, 인원 부족, 일정 변경, 10/11위 경계와 알람 장애 복구를 검사한다. 기존 명함 검사에 영구 획득 기록과 중복 방지를 추가했다.

격리된 실제 API·공용 V3 연결 QA 서버에서 PC 1440×1000 및 모바일 390×844로 로비, 24시간 모집·신청, 팀 랭킹, 8종 티어·트로피 안내, 자동 CMS 읽기 전용 설정, 기존 명함의 트로피와 상세 설명을 확인했다. 최종 투구 문장으로 교체한 뒤 두 화면 크기에서 티어 안내·소형 랭킹 문장·명함 트로피를 다시 확인했다. 운영 계정은 사용하지 않았다. 명함 시각 검수는 예시 데이터이며 실제 지급 계약은 서버 테스트로 확인했다.

`scripts/bench-ranked-duo-seasons.mjs`의 10,000명/5,000팀 로컬 PGlite pipeline 측정 원본은 `docs/benchmarks/ranked-duo-seasons-20260925.json`이다.

## 출시 범위

직전 게임 운영 커밋: `aab04e9e272ae2f14d1ff9e9d4db827c2073abf0` (Pages `6e238fed`). 이후 원격의 인증 유저 보상 운영 스크립트·기록은 보존한다.

이번 변경은 자동 시즌 DB 스키마, Durable Object 마이그레이션, 명함 지급과 UI가 함께 바뀌므로 **큰 변경**이다. 관련 개발 검사를 마친 뒤 깨끗한 범위 커밋을 원격에 반영하고 `npm run deploy:production`의 전체 출시 게이트를 한 번 실행한다. 별도 사전 `release:gate`는 반복하지 않는다. 배포 후 새 코드·자산과 자동 시즌 상태만 짧게 확인한다.

롤백 시 시즌·전투 영수증·트로피 테이블을 삭제하지 않는다. 필요하면 CMS 종료로 신규 공격을 막고 접수된 경기를 처리한다. 기존 클랜 알람 객체와 마이그레이션은 보존한다.
