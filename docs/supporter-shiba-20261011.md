# 시즌패스 활성화 헤드셋 시바견 — 2026-10-11

사용자 요청: 시즌패스 활성화 시 헤드셋 시바견 지급. 이미 후원 기능이 활성화된 계정 중 미보유자에게도 지급.

시즌패스 이용 권한을 부여하는 기존 `admin/server-support`의 GRANT(신규·연장·재가입)에 `PET-HEADSET-SHIBA` 미보유 시 1마리 지급을 연결한다. 기존 소유자는 추가 지급하지 않는다. 펫은 영구 보유하며 후원 만료·중지로 회수하지 않는다. 기존 펫 수량·장착·잠재력·기간제 자석 선택·지갑·시즌패스 일일 수령은 보존한다. 전역 보상표 ON/OFF 저장은 계정 활성화와 별도이므로 지급을 유발하지 않는다.

후원 기간, 펫 보유권, PET_GRANT/후원 감사, 후원 영수증은 하나의 기존 원자적 batch로 반영한다. 보유 기록은 CAS와 저장 후 검증으로 동시 변경을 덮어쓰지 않으며, 동일 요청 재시도는 확정 영수증을 반환한다. 펫 설정이 없거나 지급 저장이 실패하면 후원 활성화도 롤백한다.

소급 지급은 `scripts/ops/supporter-shiba-20261011.mjs`를 사용한다. 각 계정 처리 직전에 후원 유효 기간/중지 여부와 실제 보유량을 재확인하고 운영 USER_LOCK 및 DB 보조 lease를 함께 확보한다. 보유권·감사·계정별 고정 영수증을 원자적으로 저장하며 지급 중 중단돼도 완료 계정은 재지급하지 않는다. 초기 읽기 확인: 43명 활성, 40명 미보유, 3명 기존 보유.

국소 서버 보상 변경으로 `tests/supporter-shiba-20261011.test.mjs`(SQLite/PostgreSQL 활성화·소급·재시도·원자성·동시 변경), 기존 후원·시즌패스 회귀 및 `check:worker`를 scoped 배포에서 실행한다. 공통 인증/거래 기반, DB 스키마, UI는 변경하지 않는다. 다른 작업에서 완료된 비밀경찰 칭호 배포와 기록을 보존하고 최신 운영 커밋 `89114e97846fefa866cc17044468f8ebb02b0c26`을 배포 기준으로 사용한다. 운영 지급/배포 최종 결과는 같은 이름 JSON에 기록한다.

첫 검사에서 기존 후원/시즌패스 32개는 통과했다. 신규 검사 중 SQLite 결과 객체의 프로토타입 차이를 없애고 PostgreSQL SQL 변환 후에도 실패 주입이 작동하도록 검사 문자열을 수정했다. 서버 활성화 실행 코드는 동일하므로 최종 배포에서 수정 영향 범위인 신규 검사 14개와 Worker 확인만 다시 실행하며 기존 32개를 반복하지 않는다.
