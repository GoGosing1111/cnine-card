기존 승인 H/S/Z 자산은 보존한다. 과거의 정지 조준 프레임 반복 승인, 로켓런처·헬기폭격 비교 이력은 그대로 남기되, 이후 새로 만드는 모션·효과의 전체 제작 과정과 완료 기준은 이 규정을 우선한다.

## 3. 필수 제작 공정

### 01 — 승인 원본과 작업 범위 고정

승인 원화, 전투 기본자세, 무기 원본, 캐릭터 식별 요소와 수정 범위를 먼저 확인한다. 기준 원본을 별도 경로에 무가공 보존하고 SHA-256을 기록한다. 기존 승인본을 덮어쓰거나 요청하지 않은 다른 슈트·무기·용병을 재생성하지 않는다. 원본이 현재 체크아웃에 없으면 기존 보존 작업 트리와 승인 기록을 확인한다.

증빙: 원본 경로·해시, 승인 문구·대상 버전, 수정 범위, 입력 이미지별 역할.

### 02 — 동작과 타격 흐름 설계

이동/가속, 준비, 무기 휘두르기·발사, 실제 적중, 타격 정지, 후속 동작, 착지·회복, 잔향·소멸을 시간순으로 설계한다. 몸통·어깨·팔·손목·골반·무릎·발·망토의 변화가 동작을 설명해야 한다. 강한 마무리는 앞선 공격과 구도·속도·타격 정지·반동·지면 반응에서 구별한다.

시각적 타수와 서버 피해 이벤트를 분리한다. 빠른 연속 검술은 X의 교차 돌진과 올려베기·공중 마무리 수준의 연결성과 읽히는 동작을 기준으로 삼는다. 모든 스킬을 같은 연격으로 만들거나 이펙트 크기·광량만 올려 화려함을 대신하지 않는다.

증빙: 단계별 시간·포즈 순서·타격 구간·회복 구간·지상/공중 구분.

### 03 — 몸 전용 연속 동작 작화

현재 승인 공정처럼 built-in image_gen으로 고품질 몸 동작을 제작한다. 기준 캐릭터와 몸 동작 스타일을 입력 역할별로 구분한다. 한 번에 2×2의 네 자세를 분리 제작하고, 동일 카메라·신체 기준 크기·캐릭터 정체성·전체 실루엣과 투명 여백을 유지한다. 각 자세에서 관절과 천의 형태가 실제로 달라져야 한다.

고정 무기가 있는 경우 생성 입력은 몸·팔·손·망토 보정에 사용하며 새 칼날·가드·총기 외장을 그리지 않는다. X처럼 짧은 손잡이만 쥔 몸을 제작하거나, 기존 승인 총기 공정의 고정 원본 실루엣 프록시를 사용한 뒤 제거한다. 생성 모델이 그린 대체 무기와 잔여 프록시는 최종 자산에서 제외한다.

생성 결과를 즉시 확인해 팔다리 수, 손·손잡이 접점, 무기 없는 영역, 몸 비율, 카메라, 잘림·시트 간 겹침을 검수한다. 반려 원인을 보정한 뒤 다음 단계로 간다.

증빙: 개별 원본 시트, 실제 사용 프롬프트·입력 파일, 선택/반려 구분과 이유.

### 04 — 승인 무기 원본 합성

원화에 무기가 포함됐으면 승인 원본의 보이는 무기 픽셀을 선택해 별도 RGBA로 분리한다. X의 sword-lock.json, extract-approved-blade.mjs, blade-provenance.json처럼 선택 영역·원본 오프셋·파지점·검끝/총구와 해시를 보존한다. 선택한 불투명 픽셀이 원본 위치의 RGBA와 일치하는지 검사한다.

무기는 단일 승인 래스터만 사용한다. 전체 균일 배율·이동·회전·필요한 좌우 반전만 허용한다. 칼끝을 뭉뚝하게 만들기, 길이·날 폭만 수정하기, 비균일 변형, 메시 변형, 프레임마다 다른 형상 생성은 금지한다. 몸 대비 무기 길이를 먼저 확정하고 그 크기에 맞춰 손·팔 자세를 구성한다. 시트 폭이나 기존 손 위치에 맞춰 무기를 줄이지 않는다.

기술 합성은 승인된 프로젝트 스크립트로 수행한다. 시트의 실제 알파에서 몸을 분리하고, 손·발 좌표와 같은 무기 원본을 합성한다. 원화나 무기를 다시 그리는 작업을 “후처리”로 숨기지 않는다.

증빙: 원본 선택 설정, 픽셀 동일성 결과, 프레임별 파지점·회전·균일 배율·무기 출처 해시.

### 05 — 단계별 개별 효과 연속 작화

대시의 가속·공기 흔적, 무기 궤적, 적중 파열, 강한 마무리, 지면 충격, 파편·먼지·잔향을 필요한 계층으로 분리해 제작한다. X는 각각 4×3의 12프레임 시트를 사용했다. 효과의 실루엣·방출 방향·파편·밀도·소멸 형태가 프레임마다 실제로 바뀌어야 한다.

주 효과를 정지 그림의 이동·확대·회전·투명도 변경으로 대체하지 않는다. 같은 효과의 색만 바꾸거나 아이콘 여러 개를 한 장에 모아 개별 스킬이라고 세지 않는다. 실제 원화/몸 동작 프레임의 과거 시각을 샘플링한 잔상은 보조 계층으로 사용할 수 있다.

검기에는 방향과 날카로운 경계·빈 공간이 읽히게 하고, 마무리에는 무게가 느껴지는 충격과 물질의 반응을 연결한다. 화면 전체를 흰 빛이나 불투명 안개로 덮어 몸·무기·적중 위치를 감추지 않는다. 돌·먼지처럼 질량을 읽어야 하는 계층을 전부 가산 합성으로 태우지 않는다.

증빙: 효과별 원본 시트·프롬프트·프레임 범위·계층·출처 해시.

### 06 — 알파·피벗·아틀라스 패킹

발바닥 기준점, 손/파지점, 검날 구간 또는 총구, 무기 변환을 pose-registration에 기록한다. 웅크린 자세의 보이는 높이를 기준으로 몸을 확대하지 않고, 같은 캐릭터의 기준 신체 높이와 원본 무기 비율을 유지한다. 전신과 무기가 잘리지 않는 캔버스를 확보한 뒤 전체를 균일 패킹한다.

X의 pack-assets.mjs처럼 실제 알파를 보존해 개별 프레임·아틀라스·썸네일과 매니페스트를 만든다. X 재현 규격은 몸 768×768 RGBA 셀·4×2 아틀라스다. 다른 런타임 규격이 필요하면 같은 피벗·균일 비율·투명 여백·전체 무기 보존 조건을 만족하는 규격과 변환값을 기록한다. 원본 시트·선택한 프레임·합성 결과·표시용 썸네일을 구분한다.

증빙: 각 프레임 좌표·알파·여백·해시, 아틀라스 레이아웃, 소스/무기 출처와 패킹 설정.

### 07 — 타격 접점과 지면 검증

검격은 칼날이 적의 몸을 가로질러 베고 검끝은 통과하도록 구성한다. 검끝을 적의 중심에 억지로 맞추기 위해 캐릭터를 띄우거나 칼날을 변형하지 않는다. 칼날 구간과 몸통의 교차를 확인하며, 지상 동작은 발바닥 기준 지면을 유지한다. 도약은 명시적으로 설계한 높이 곡선과 착지 구간만 사용한다.

원거리 무기는 총구/방출점 → 비행 궤적 → 대상 접점을 연결하고, 격투·둔기·마법은 손발·타격면·방출점과 효과 중심을 역할에 맞춰 등록한다. 타격 지점은 화면 중앙이나 무기 끝으로 일괄 고정하지 않는다.

X의 실제 검수에서는 6회 모두 칼날 길이의 약 51~61% 구간이 적 몸통과 가장 가깝고, 지상 기준 오차는 1e-8 이하였다. 이 값은 검증 예시이며 다른 무기의 기하를 억지로 같은 수치에 맞추지 않는다.

증빙: 적중 시각별 몸통/타격면 교차, 지면 오차, 도약 여부, 이펙트 OFF 상태의 실제 몸·무기 확인.

### 08 — 공용 V3·PixiJS·GSAP 실제 재생

기존 V3 BattleEngine, 지원 액터/용병 액터, 진형, 효과 레이어, 카메라, 아트 어댑터와 카드 도크를 재사용한다. 별도 렌더러·중복 라이브러리·임의 전투 프레임을 만들지 않는다. PixiJS는 실제 렌더링을, 공용 GSAP 시계는 몸·효과 프레임·이동·접점·잔상·반동을 함께 제어한다.

과거 포즈 잔상도 같은 시각을 샘플링한다. 시간 기반 효과가 배속·일시정지·탐색·취소에서 서로 어긋나면 미완료다. 서버 피해·대상·승패·보상은 연출에서 재계산하지 않는다.

카메라는 검기와 몸·망토·칼끝을 PC·모바일 화면 안에서 읽을 수 있도록 구성한다. X에서 고친 것처럼 CameraController 기본 위치를 유지하고 피벗으로 초점을 옮겨 공용 배경의 패럴랙스 구간이 갈라지지 않게 한다. 공유 전장·카드 도크의 배치 자체를 바꾸지 않는다.

증빙: 실제 구현 파일·잠금 라이브러리 버전·단일 시계 소유자·번들 내 사본 수·라이브 연결 여부.

### 09 — 실제 전장 시각·제어 검수

PC와 모바일에서 각각 실제 V3 전장에 올려 한 번씩 검수한다. 1배속으로 전체 흐름을 보고 0.25/0.5배속과 프레임 탐색으로 준비·각 적중·최대 효과·착지·회복·소멸을 확인한다. 이펙트를 끈 몸·무기 동작도 확인한다. 정지 스크린샷이나 테스트 성공만으로 시각 검수를 대신하지 않는다.

2배속, 일시정지, 재시작, 중단, 페이지 이탈 시 잔여 타임라인·효과·잔상이 정리되는지 확인한다. 화면 잘림·가로 넘침·배경 분리·불필요한 원본 자산 중복 로드·누락·콘솔 오류를 확인한다. 한 번 통과한 동일 빌드를 이유 없이 반복 검수하지 않고 변경한 경로와 실제 발견된 문제에 집중한다.

증빙: 수행한 화면/속도/시각과 결과, PC·모바일 캡처, 실제 재생 영상, 제어·정리 결과.

### 10 — 재현 가능한 결과물과 검증 보존

README, 실제 프롬프트, 승인 원본, 고정 무기와 출처 기록, 등록 좌표, 몸/효과 원본 시트, 개별 프레임, 아틀라스, 매니페스트, 합성·빌드·검수 스크립트, 결과 보고서, PC·모바일 캡처, 실제 재생 영상을 프로젝트 안에 보존한다. 프로젝트에서 사용하는 결과를 생성 도구의 임시/개인 출력 경로에만 두지 않는다.

현재 X의 재현 진입점은 extract-approved-blade.mjs → pack-assets.mjs → build.mjs → qa.test.mjs → serve.mjs 및 qa-browser.mjs → record-review.mjs다. 다른 캐릭터도 같은 공정을 재현할 수 있는 대응 파일을 기록한다. 이미지 편집은 이미지 생성 도구, 승인 무기 합성·알파/피벗·패킹은 프로젝트의 승인된 기술 스크립트로 역할을 구분한다.

원본 해시/선택 픽셀, 무기 출처·균일 비율, 실제 서로 다른 프레임, 접점과 소멸, 공용 런타임 연결을 관련 검사로 확인한다. 프레임 해시가 다르다는 사실만으로 동작 품질을 통과시키지 않는다.

증빙: 실행 명령·결과, 누락 파일 0, 원본/산출물 해시, 미완료 항목과 최종 산출물 위치.

### 11 — 사용자 시각 승인과 보존

검수 영상을 포함한 실제 재생 결과를 사용자에게 제시한다. 기술 검증 결과와 사용자 시각 승인 상태를 각각 기록한다. 반려된 결과는 다음 제작의 품질 앵커로 쓰지 않는다. 승인된 버전과 파일 해시를 고정하고 후속 작업은 별도 후보로 만든다. 승인본을 재생성해 자동으로 승인 상태를 승계하지 않는다.

이번 사용자 메시지로 X-BODY V2의 모션·이펙트는 시각 승인되었고 슈트·용병 공통 제작 기준으로 채택됐다. 이 승인은 제작 규정과 시각 품질에 관한 것이다. 계정 지급, CMS 등록, 등급·전투 수치·제작 비용·획득 경로 또는 운영 전투 활성화를 추가로 정하는 지시는 아니다.

증빙: 승인 날짜·사용자 문구·버전·해시·범위, 후속 변경 여부와 운영 상태.

## 4. 매 작업 완료 기록

작업 README에 위 01~11 단계 각각의 대응 파일과 검수 결과를 연결한다. 파일 개수만 체크한 표나 “X 수준으로 제작”이라는 선언으로 대체하지 않는다. 한 단계라도 증빙이 없으면 제작 완료라고 보고하지 않는다. 수정된 구간은 다시 확인하고 승인 원본·비대상 자산은 해시로 보존을 확인한다.

사운드가 포함되면 기존 실제 녹음/폴리·라이선스·충돌 ±20ms 규칙도 적용한다. X 검수판은 무음이므로 임의 합성음을 새 기준으로 추가하지 않는다.

커밋·배포 검사는 [변경 규모별 정책](scoped-release-policy-20260923.md)을 따른다. 이번처럼 규정·승인 메타데이터만 바뀌면 문서·경로·해시 확인과 범위 커밋·원격 반영으로 끝낸다. 게임 전체 검사나 운영 재배포를 추가하지 않는다.
