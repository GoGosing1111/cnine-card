# 붕괴 코어 신규 기믹 검수·모바일 입력 수정 V2085

## 범위와 승인

2026-09-12 사용자가 중앙 타이밍을 포함한 화면 기믹 1~3종 준비와 모바일 방향 입력 불량 점검을 요청했다. 코어 동조·회로 복원·차폐 구역 이동 세 종류를 `preview/core-raid-mechanics-v1/`에 준비한다. 운영 배틀 타임라인·경제·입장권·CMS 기능 플래그는 변경하지 않는다. 신규 기믹 배정·난이도·서버 판정 연결은 후속 사용자 검수 대상이다.

기존 방향 QTE 입력 수정은 공용 `js/project-v-raid-qte-v1924.js`에 반영한다. 기존 레이드가 이미 노출되는 조건에서 입력만 개선되며 신규 레이드 공개 범위를 넓히지 않는다.

## 기존 모바일 문제와 수정

기존 버전은 터치 방향 버튼 없이 36px 이상 스와이프한 뒤 손을 뗄 때 입력했다. 짧은 스와이프는 입력되지 않았고, 다른 손가락의 pointerdown이 시작 좌표를 바꿀 수 있었다. 기존 CSS에도 `touch-action:none`은 있었으므로 해당 속성 누락을 원인으로 보지 않는다.

- 60px 이상(가로 화면 54px 이상) 방향 버튼을 추가하고 `pointerdown` 시점에 판정한다.
- 스와이프는 주 손가락 ID를 캡처한다. 이동 중 우세 축이 22px 이상이면 즉시 한 번 입력한다. 1.2배 미만의 대각선과 작은 떨림은 보류한다.
- 버튼에서 손을 떼며 생기는 호환 click은 중복 입력하지 않는다. 키보드/보조 기술의 detail=0 click은 지원한다.
- 두 번째 손가락이 스와이프 시작점을 교체하지 않는다. 취소·캡처 상실 후 새 제스처를 시작할 수 있다.
- 애니메이션 프레임이 늦어져도 제한시간이 지난 입력은 SEQUENCE/MASH 양쪽에서 거절한다.
- 기존 방향 순서·실수당 450ms 차감·연타 간격·서버 입력 기록 형식과 판정 정책은 유지한다.

입력 처리 참고: [MDN Pointer events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events), [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action).

## 통합·캐시

- 메인 및 기존 Core 프리뷰에서 QTE JS를 `?v=2085-mobile-input`으로 참조한다.
- `css/raid-qte-mobile-v2085.css?v=2085`는 QTE 하위 요소만 변경한다.
- 메인 앱 로직/서비스워커는 그대로다. 문서 탐색은 기존 network-first 경로이며 수정 리소스의 새로운 URL이 이전 스크립트 캐시를 우회한다.
- 새 검수 페이지는 기존 V3 renderer와 어댑터 체인을 사용한다. 카드 원화/SD 구분 및 ZENITH/SUPERSTAR 프레임을 유지한다. 별도 Pixi 렌더러·복제 카드 UI·새 전투 음원은 없다.
- 신규 세 기믹은 로컬 결과만 만든다. 서버 피해/승패/보상을 바꾸지 않는다.

## 검증

2026-09-12 로컬 검수: `npm run test:core-raid` 36개 통과, 브라우저 입력·화면 검사 46개 통과. 런타임 오류와 계정 API 요청은 0건이었다. 가로 화면 타이머/닫기 겹침과 회로 단자 간격을 시각 검수 후 보정했다.

- Core 단위/회귀 검사: 기존 서버 기록 재판정, 방 전투 흐름, 고정 전투력, 부족한 설정 차단, 사용자 접근 제한을 포함한다.
- 새 모델 검사: 중앙 판정 양쪽 경계·속도, 중복/오연결, 타깃 범위, 세 번의 차폐 조건, 라이브 연결 단절을 확인한다.
- `scripts/qa-core-mechanics-browser.mjs`: 실제 CDP 터치로 즉시 방향 입력·24px 스와이프·중복 방지·두 손가락 간섭·취소·대각선/떨림 무시·기한 경계·키 반복·연타를 확인한다. 수집한 입력 기록을 실제 `evaluateCoreRaidQte`에 전달해 판정 일치를 검사한다.
- 신규 기믹의 성공/실패, 드래그/두 번 터치, 닫기·빠른 재시작, 프레임/원화 유지와 계정 API 무호출을 검수한다.
- 360×740, 390×844, 844×390, 1440×1000 화면의 조작부 위치 및 타이머/닫기 겹침을 확인한다. 이는 Chrome 브라우저 에뮬레이션 결과이며 모든 실물 모바일 기기에서의 완전한 해결을 의미하지 않는다.

운영 배포는 깨끗한 범위 커밋을 origin/main에 반영한 뒤 `npm run deploy:production`으로만 진행한다. 이 명령의 `npm run release:gate`가 실패하면 배포하지 않는다. 롤백 시 메인 QTE 참조와 공용 스크립트를 함께 되돌리며 DB 롤백은 필요 없다.
