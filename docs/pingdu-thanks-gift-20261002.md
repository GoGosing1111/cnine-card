# 핑두의 감사 선물 — 2026-10-02

사용자 요청에 따라 기존 사은품과 다른 `PINGDU_THANKS_GIFT_BOX`를 추가한다. 상자 1개를 사용하면 아래 네 보상이 함께 확정 지급된다.

| 보상 | 실제 코드 | 수량 |
| --- | --- | ---: |
| 코인 | COIN | 300,000,000,000 (3,000억) |
| 마스터의 별 | MASTER_STAR | 5,000,000 (500만) |
| 미스틱 에너지 | STARLIGHT_ARMOR_CORE | 1,000 |
| 핑두 리페어쿠폰 | PINGDU_REPAIR_COUPON | 1 |

## 구현

- `functions/_pingdu_thanks_gift.js`: 독립 카탈로그, 개봉, 관리자 지급. 기존 사용자 잠금·공동 거래를 사용하며 상자 차감, 네 보상, 로그와 영수증을 한 거래로 처리한다. 같은 요청 재시도는 기존 결과를 반환한다.
- 인벤토리의 팩·상자 분류에 표시하고 명시적인 개봉 버튼으로 사용한다. 응답 유실 후 보유 상자가 0개여도 인벤토리의 이전 결과 확인 버튼으로 복구한다. 진입 시 자동 개봉하지 않는다.
- CMS 유저관리 직접 지급과 2차 인증자 메시지 보상 종류에 추가한다. 메시지 수령은 상자만 보관함에 추가하며 내용물은 사용자가 개봉할 때 받는다.
- 남청색 패널, 핑크색 상자·보상 강조, 기존 라임색 주요 버튼을 사용한다. 닫기 버튼은 44px이며 모바일 높이에 따라 내용이 스크롤된다.
- 등록은 상품 메타데이터만 추가한다. 계정 지급·메시지 발송은 이번 요청에 포함되지 않는다. 기존 영입전·펀딩·대회 사은품의 코드·이미지·보상은 그대로다. 재등록은 CMS에서 편집한 이름·사용 중지 상태를 덮어쓰지 않는다.

## 이미지

내장 imagegen으로 새 핑크색 상자를 생성했다. 코인, 황금 별, 보라색 에너지와 리페어쿠폰 1장 기호를 넣었다. 생성 PNG를 수정·재압축 없이 `assets/ui/packs/pingdu-thanks-gift-box-v1.png`에 복사했다. 원본 SHA-256 및 최종 프롬프트는 `pingdu-thanks-gift-20261002-art.json`에 보존한다.

## 검사와 배포 범위

단일 선물 상품과 기존 개봉·지급·메시지 연결 변경으로 한정한다. 인증·거래 기반·스키마·의존성은 바꾸지 않으므로 scoped 배포를 사용한다.

- 새 선물 거래 검사 8건 통과: 네 보상 정확한 수량, 마지막 상자 경쟁, 요청 재시도, SQL/완료 실패의 전체 롤백, 응답 유실, 비활성 아이템, 수량 오류·정수 상한, 관리자 권한·로그·동일 지급 요청 복구.
- 실제 로비·인벤토리, CMS 유저관리 마크업, 서버 거래를 로컬 격리 계정으로 연결해 1440×1000과 390×844에서 확인했다. 네 보상 개봉, CMS 직접 지급, 모바일 응답 유실 후 0개 상태 복구, 가로 잘림 0px, 닫기 44px, JavaScript 오류 0건을 확인했다.
- 배포 단계에서 기존 영입전 선물, 메시지 보상, 인벤토리와 사용자 잠금 관련 회귀만 실행하고 `check:worker`를 포함한다. 이미 완료한 동일 UI 검수는 반복하지 않는다.
- 실제 직전 운영 커밋은 Cloudflare Pages 메타데이터에서 배포 직전에 조회해 `SCOPED_DEPLOY_BASE`에 지정한다. `npm run deploy:production -- --scoped` 한 번으로 반영하고 새 파일·캐시·운영 서버 보상·카탈로그만 짧게 확인한다.

운영 완료 정보는 실제 배포 결과 확인 후 이 문서에 기록한다.
