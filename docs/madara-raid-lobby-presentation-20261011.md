# 마다라 공대·입장권·전투 연출 V2 — 2026-10-11

사용자 요청: 공대 생성자 → 입장권 → 방 생성 → 목록 갱신 → 강퇴, 보스 멘트와 개선된 전투 연출. 앞선 “라이브 올리지말고 준비까지만” 지시는 유지한다. `codex/madara-raid-preparation-20261011`의 로컬 범위 커밋만 준비하며 운영 메뉴/API/CMS/DB·실계정·main·원격 공개·배포에는 연결하지 않았다.

## 실제 동작

- 이름·역할과 공대/단독 지휘 선택 후 입장권 팝업에서 현재/차감 후 잔량을 확인하고 방을 생성한다. 로컬 초기 3장, 생성자 1장 차감, 참가 무료, 생성 후 미환급은 검수 초안이다. 운영 아이템 코드/수량/입장 정책은 미확정이다.
- `server.mjs`의 검수 참가자 ID와 입장권 장부는 방 세션과 분리된다. 같은 브라우저 프로필에서 새로고침해도 잔량/소속/강퇴 기록이 유지된다. 생성 영수증으로 중복/동시 요청을 한 번 처리하고, 전체 방 검증 후 동기 구간에서 방 저장·차감·영수증을 함께 반영한다. 서버 프로세스를 재시작하면 모두 초기화된다.
- 모집 목록은 공대장 이름, 코드, 역할별 인원, 6인 정원, 모집/전투/종료 상태를 표시한다. 5초 자동 갱신과 수동 갱신을 제공한다. 참가 요청 시에도 서버가 정원·출정·소속·강퇴 조건을 재검증한다.
- 강퇴 확인창은 공대장에게만 표시되고 서버도 공대장/대기 상태/자기 자신 제외를 검증한다. 대상의 입력/조회 권한을 즉시 해제하며 같은 검수 ID의 해당 방 재입장을 금지한다. 공대장 퇴장 시 남은 첫 대원에게 무료 위임한다. 실서비스 계정 인증이나 다중 프로세스 DB 잠금 구현으로 간주하지 않는다.
- 실제 전투는 기존 4대 기믹·최종전·서버 시간·개인 공격 몫·유한 공용 자원을 유지한다. 보스 대사는 단계 진입, 화염, 방벽 해제, 시선 교대, 오답, 승패에 연결된 서버 이벤트에서 나온다. 대사는 자막이며 성우 음성은 없다.
- 입장권 없는 연출 감상에서 다섯 장면 선택, 0.25/0.5/1/2배속, 일시정지/계속, 시점 탐색, 효과 OFF, 재시작·퇴장을 제공한다. 감상은 공대·입장권·HP·보상 상태를 만들거나 바꾸지 않는다.

## 제작 기준 11단계의 대응

1. **원본 보존:** 사용자 첨부, 마다라, 거신, 배경은 `assets/manifest.json`의 기존 SHA-256을 유지한다. X-BODY V2 제작 문서와 `review-v2.webm`의 실재생 프레임을 확인했다. 검수 참고 캡처는 `qa-v2/x-reference-motion.png`다.
2. **동작 계획:** 3.6초 공용 시계. 0–0.38초 준비, 0.38–0.9초 인 맺기, 0.9–1.7초 손바닥 방출, 1.7–3.3초 회복·소멸, 3.3–3.6초 정리. 효과는 0.45–3.15초에 원본 12프레임을 순서대로 읽고 3.3초까지 사라진다. 서버 HP/판정을 이 시각으로 재계산하지 않는다.
3. **실제 몸 작화:** 내장 `image_gen.imagegen`의 `madara-cast-poses-v2.png` 2×2 시트. 팔·손·몸통·다리/옷자락이 달라지는 네 포즈. `art-prompts-v2.json`에 원본 입력과 정확한 프롬프트를 기록했다. 자연스러운 연속 머릿결·성인 비율·동일 카메라를 요청했다.
4. **무기 보존:** 마다라 시전은 맨손이므로 무기 재생성/합성은 없다. 거신은 기존 검을 포함한 원본 PNG를 그대로 사용하며 새 거신 검격을 제작했다고 주장하지 않는다.
5. **개별 효과:** 환술의 붉은 회오리/파열, 분신의 청색 연무/분열, 화둔의 방출/결계 충돌, 운석의 낙하/암석 파열, 거신의 봉인/푸른 불꽃/소멸을 각각 12프레임으로 생성했다. `art-prompts-v3.json`이 실제 사용 프롬프트다. 첫 4프레임 V2 시트는 형태 연구 이력이며 실제 재생에서 제외한다.
6. **알파·패킹:** `pack-presentation.mjs`는 원본을 고정 셀로 추출하고 같은 배율로 축소해 투명 여백을 더한다. 몸 640×640×4, 효과 384×384×60. 몸의 발 피벗/방출점·원본 셀·균일 배율·알파 경계·개별 해시는 `assets/presentation-manifest.json`에 있다. 원본 작화를 후처리로 다시 그리지 않는다.
7. **접점·지면:** 발 피벗을 실제 보스 root의 지면에 연결하고, 손 방출점·살아 있는 아군의 몸통·발 위치에서 효과 위치를 계산한다. 지상 원점 오차를 실제 좌표 변환으로 측정했다. 전장 상단에 잘리던 운석/거신 효과는 셀 전체 높이를 기준으로 제한했다. 준비·충돌·소멸·효과 OFF 캡처를 확인했다.
8. **공용 런타임:** 기존 `ProjectVBattleV3Live.createRenderer`와 설치된 `ProjectVPixiBattle.fxRuntime`만 쓴다. 새 Pixi Application/라이브러리/진형/로스터는 없다. `presentation.js`의 몸·효과·카메라·자막 배너는 `engine.timeline` 한 시계에 올라간다. 실제 액터는 `engine.boss/currentEnemyTarget`으로 찾으며 예비 적 슬롯 사용을 회귀 검사한다.
9. **실재생 검수:** PC 1440×1100, 모바일 390×844에서 정상 재생·저속·2배속·정지·탐색·재시작·퇴장·재진입·동작 줄이기를 확인했다. 1캔버스, 사라지는 효과/배너, 44px 이상 조작, 모바일 가로 넘침 0, 브라우저 예외 0. `qa-v2/madara-presentation-v2.webm`과 장면별 PNG에 보존했다. 전투 서버 시계는 이 UI 재생에 종속되지 않는다.
10. **재현 산출물:** 원본 시트, 두 프롬프트 JSON, 패킹 스크립트, 개별 프레임/아틀라스, 두 자산 매니페스트, 구현 JS/CSS/HTML, 서버/브라우저 검사, 영상·캡처를 모두 개발 브랜치에 보관한다. 개인 generated_images 경로만 참조하지 않는다.
11. **승인 상태:** 기술 검사/내부 시각 점검과 사용자 시각 승인은 별개다. 현재 `PENDING_USER_VISUAL_REVIEW`. 신규 성우 음성·녹음 사운드, 거신의 추가 본체 동작, 운영 경제·입장 정책·실계정 저장소·출시는 미확정이다.

## 검증과 발견한 문제

관련 검사 22개 통과. 생성 동시 요청/재시도 중복 차감 방지, 유효성 실패 무차감, 입장권 부족, 종료된 영수증 재사용, 무료 참가·위임, 강퇴 권한/재입장/출정 잠금, 정원, 서버 대사, 아틀라스 알파/프레임 차이를 포함한다. 기존 기믹 3/4/5/6인 각 2시드 완주와 오류 경로 검사를 유지했다.

실제 브라우저에서 공대장·정벌·구출 세 프로필로 생성 확인 → 목록 참가 → 코드 참가 → 강퇴 확인 → 새로고침 후 재입장 잠금 → 공대장 위임을 수행했다. `qa-v2/lobby-presentation-result.json`에 기록했다. 이후 시각 수정만 재검사할 때는 `MADARA_MOTION_ONLY=1`로 해당 장면/제어 범위만 실행했다. 관련 없는 전체 게임 검사는 실행하지 않았다.

처음 프레임 검사에서는 숨겨진 예비 적의 속성만 바뀌고 실제 보스는 정지 상태로 남는 문제가 있었다. 시각 검수로 발견해 실제 `engine.boss`에 연결하고 활성 액터 검사를 추가했다. 모바일 감상 중 불필요한 고정 제목이 전장을 덮는 현상은 감상 모드에서 고정을 풀었다. 운석/완전체 최대 효과는 상단 여백을 확보했다.

기존 전투 UI/API 전체 단계 검증은 `qa-v2/combat/browser-result.json`에 있다. 기존 테스트의 모바일 세션 주입을 방 토큰에서 새 검수 참가자 토큰에 맞춰 수정했다. 로컬 제어 시계·공개 역할 단서를 이용한 자동 검증이며 실제 인터넷 3~6인 공대의 지연/난도/클리어율 검증은 아니다.
