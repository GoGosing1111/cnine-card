# 족각도시 PVP — 2026-10-09

## 사용자 확정 범위

새 콘텐츠 이름은 족각도시다. 현대 도시의 장소를 골라 체류자를 약 10명씩 보고 공격한다. 기존 PVP 편성의 카드·용병으로 싸우며 역할은 한국시간 00·06·12·18시에 서버 공통으로 무작위 배정한다. 경찰은 체포·검문, 간호사·의사는 치료할 수 있다. 상대가 다른 콘텐츠를 이용하는 동안에도 피격 팝업을 받는다.

최신 게임의 네이비/라임 UI, 한글 타이포그래피, 공용 메뉴를 사용했다. 야간 해안 도시 지도 위 건물의 실제 영역과 표지를 선택하며 PC는 지도/장소 정보와 인원 목록을 나란히, 모바일은 지도와 인원 목록을 순서대로 표시한다. 모바일 지도는 좌우 이동·확대를 지원한다. 일반 정보 카드만 배경 위에 나열하지 않는다.

## 진행 방식과 구현 기본값

1. PVP 카드 5장을 편성하고 도시 입장. 집에서 시작하며 입장 시 다른 콘텐츠에서도 교전 대상임을 안내한다.
2. 장소 선택 → 체류자 확인 → 이동 → 상대 선택 → 공격/검문/체포/치료.
3. 기존 서버 PVP 엔진으로 양쪽의 현재 편성·고유 능력·시너지·장비·마법·공개된 용병·펫을 반영한다. 방어는 기존 PVP 방어 편성과 방어 마법 프리셋을 사용한다.
4. 도시 전용 거리 배경에서 기존 V3 전투를 재생하고 저장된 결과를 확인한 뒤 지도로 돌아온다.
5. 다른 콘텐츠 화면에서는 비차단 피격 팝업과 결과 확인을 제공한다. 진행 중 전투의 타이머·정산·라우트를 바꾸지 않는다.

역할 7종은 시민·거지·경찰·간호사·의사·갱단·반달이다. 장소 8종은 경찰서·병원·백화점·우체국·시장·집·항구 창고·뒷골목이다. 목록은 접속자 수가 아닌 **도시 체류자**이며 오프라인이어도 명시적 퇴장 전에는 대상이 된다.

아래 수치는 플레이 가능한 첫 구현을 위한 기본값이다. 사용자에게 개별 승인받은 숫자로 간주하지 않는다.

| --- | --- |

도시 체력은 도시 교전 가능 상태를 뜻한다. 카드의 기존 전투 능력치를 도시 체력 비율로 줄이지 않는다. 별도 코인 보상·강탈·입장권 차감·랭크 점수 변동은 없다.

## 서버 저장과 알림

- `jokgak_city_players_v1`: 참여·위치·도시 체력·수배·대기시간과 revision.
- `jokgak_city_actions_v1`: 요청 ID에 묶인 확정 결과. 요청자/대상자만 자신의 기록 열람 가능.
- `jokgak_city_notifications_v1`: 상대 계정의 미확인 알림. 계정/미확인/시간 인덱스.
- `jokgak_city_guards_v1`: transaction 내부 CAS 실패 시 전체 rollback을 강제하는 CHECK guard. 처리 후 행 제거.

동일 행동은 기존 계정 mutation lock, 요청 본문 fingerprint와 immutable receipt를 사용한다. 양쪽 revision을 계정 ID 순서로 갱신하며 체력·수배·영수증·알림은 한 transaction으로 저장한다. 상대 이동이나 다른 교전이 먼저 반영되면 결과를 덮어쓰지 않는다. 전투 계산을 SQL transaction 밖에서 수행하고 교대 경계를 재검사한다. 응답 유실 시 같은 요청 번호로 확정 결과를 복구하며 다시 판정하지 않는다.

역할은 비공개 서버 seed + 교대 ID + 계정 ID의 HMAC으로 배정된다. 별도 6시간 대량 UPDATE나 클라이언트 시계 의존 없이 공통 경계에 반영된다. seed는 클라이언트에 노출하지 않는다.

목록은 장소 인덱스와 keyset으로 최대 11행 조회 후 10명만 반환한다. 전 계정 조회나 총원 재집계를 하지 않는다. 활성 화면의 알림 조회는 약 8~9초 간격, 미입장 계정은 약 60초 간격이며 숨겨진 탭은 멈춘다. 여러 탭은 Web Locks와 공유 polling lease/확인 기록을 사용한다. 즉시 WebSocket 전달은 아니다.

초기 스키마는 첫 인증 요청에서 additive `IF NOT EXISTS`로 준비하고 durable marker와 runtime cache를 사용한다. 운영 긴급 중지는 `app_meta.jokgak_city_settings_v1 = {"enabled":false}`로 가능하며 이미 저장된 결과 조회·알림은 보존한다. 기존 콘텐츠 출시 플래그를 변경하지 않는다.
