# 엠퍼러 장비 제작 봉인 개방 · 동방무기 실패 정책 준비

사용자 요청: 엠퍼러 장비 제작의 즉시 결과 창을 화려한 ‘밀어서 확인하기’ 연출로 바꾸고, 이후 동방무기 제작에서 실패하면 투입 +10 무기를 소모할 수 있게 준비한다.

## 적용

- `ITEM_SYNTHESIS / EQUIPMENT` 제작에 전용 제작실, 금속 봉인, 터치/마우스 슬라이드, 충전 반응, 양쪽 문 개방·입자 확산과 성공/실패 결과를 연결했다. 엠퍼러 에너지 같은 재료 제작과 차량/슈트 조립 연출은 기존 경로다.
- 성공 시 기존 카탈로그 장비 원본과 +0 획득을 표시한다. 실패 시 깨진 봉인과 실제 영수증의 +10 장비 보존/소모 및 천장을 표시한다. 불완전한 밀기는 시작점으로 돌아오며, 키보드·바로 결과 보기·동작 줄이기·이미지 로딩 실패 대체 표시를 지원한다.
- 결과는 서버에서 확정 후 표시한다. 연출에는 API 호출이 없으며, 실패한 연출은 거래 재시도로 취급하지 않는다. 닫기·페이지 이탈 시 타이머/애니메이션/리스너/스크롤 잠금을 정리한다. 사운드는 사용자가 연출 화면에서 켰을 때만 재생한다. 모든 검수는 음소거했다.

## CMS·거래

- `WORKSHOP_EQUIPMENT_CRAFT_V1:<code>` 안에 `failureInputPolicy`를 추가했다. `PRESERVE`는 기존 실패 보존, `CONSUME`는 실패 시 선택한 +10 장비와 강화 상태를 소모한다. 필드가 없는 운영 레시피는 계속 보존이다. 이름이나 ‘동방’ 문자열로 정책을 추정하지 않는다.
- 실패 소모도 기존 사용자 잠금·설정/강화 상태 버전 확인·원자적 배치 안에서 수행한다. 출력 장비는 성공 시에만 지급한다. 커밋 후 응답 유실은 저장 영수증을 반환하므로 소모된 장비를 다시 요구하거나 차감하지 않는다. 이전 영수증도 당시 정책으로 재생한다.
- CMS에서 조합식별 실패 처리를 선택한다. `+ 동방무기 준비`는 소모 정책이 선택된 **미저장 초안**을 연다. 운영 OFF·유저 비공개·OWNER 테스트이며, 투입/결과 장비·비용·재료·천장은 운영자가 입력한다. 실제 운영 DB에 불완전한 레시피를 생성하거나 개방하지 않았다. 장비제작 기존 10% 계약을 유지하며 새로운 동방무기 확률/비용 정책을 임의로 확정하지 않았다.
- 스키마·마이그레이션·의존성 및 기존 레시피 값/확률/천장 변경 없음.

## 자산·검수

- `preview/workshop-equipment-reveal-v1/`에 imagegen 원본·생성 명세·최종 화면 증빙을 보존한다. 런타임은 `assets/ui/workshop/emperor-forge-sanctum-v1.webp`와 `emperor-seal-v1.webp`로 약 700KB. 기존 장비 원본은 변경하지 않는다.
- 실제 격리 SQLite API와 PC 1440×1000 / 모바일 390×844에서 77개 항목 통과: 터치/마우스 슬라이드, 중간 취소, 실패 누적, 확정 제작, 응답 유실 후 같은 요청 복구, CMS 저장·재조회, 실패 소모/보존 안내, 키보드·동작 줄이기·페이지 이탈.
- 최종 입체 봉인 교체 후 별도 화면 검사 22개 통과 및 시각 검수로 시작·충전·개방·성공·실패를 직접 확인한다. 데스크톱 Grid의 이미지 최소 크기 때문에 장비 원화가 결과 문구를 덮던 문제를 Flex 정렬로 수정하고 이미지가 무대 안에 남는 회귀 항목을 추가했다.
- 관련 거래 검사: `tests/workshop-equipment-craft-20260928.test.mjs`. SQLite/PostgreSQL의 실패 보존/소모, 실패 롤백, 중복 요청/동시 요청, 성공 출력 원자성, CMS 정책 버전과 비공개 초안을 검사한다.

## 배포 범위

직전 운영 배포는 `22044f1a-b303-4ef3-8576-36b199508684`, 소스 `d39ba94bc8a9ee3925646e2be5e0e527ed24f19c`다. 변경은 장비 제작 프레젠터와 해당 조합식의 실패 처리에 한정되어 `npm run deploy:production -- --scoped`를 사용한다. 위 거래 테스트와 `check:worker`를 배포 게이트에서 한 번 실행하며 기존 출시·캐시·Hyperdrive 보호 검사를 유지한다.
