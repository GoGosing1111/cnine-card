# 용병 여러 번 합성 — 2026-10-19

사용자 요청: “용병합성 한번에 여러마리 하고싶다고 건의들어옴”. 용병도감의 기존 중복 합성 화면에 횟수 입력과 1회·10회·최대 선택을 추가한다. 한 번에 최대 100회이며, 현재 선택한 등급의 기존 중복 카드 수량으로 가능한 횟수까지만 선택한다.

## 동작

- 1회당 같은 등급 중복 8장, 독립 승급 확률 10%, 나머지 90%는 같은 등급 무작위 1장이다. 추가 비용·CMS 카드별 비중·획득 OFF·기본 보유 1장 보존 정책은 유지한다. SSS는 재료로 사용할 수 없다.
- 횟수 선택 시 재료를 자동 선택하고, 카드별 소모량과 전체 소모량을 실행 전에 표시한다. 같은 등급의 다른 용병을 함께 쓸 수 있다. 결과 카드를 같은 요청의 재료로 다시 쓰지 않는다.
- 기존 성소·카드 프레임·효과를 유지하고 대표 카드 8장으로 연출을 한 번 재생한다. 여러 회의 결과는 용병별 수량으로 모아 보여주며 승급·동일 등급 합계를 표시한다. `전체 결과 보기`는 이미 확정된 결과를 바로 표시한다. 연출 다시 보기·닫기·건너뛰기는 추가 합성이 아니다.
- 기존 디자인 우선 지시에 따라 기존 합성 콘텐츠의 이미지와 도감 제어 스타일을 사용했다. 새 패널 원화나 타 콘텐츠 프레임을 추가하지 않았다.

## 거래와 호환

- 기존 API의 재료 배열을 8~800장(8의 배수)으로 확장한다. 서버가 횟수를 계산하고 같은 등급 및 각 카드의 중복 수량을 확인한다. 계정 잠금, 원래 보유 수량의 DB 재검사, 원본 1장 보존을 유지한다.
- 요청 1개·준비 기록 1개에 모든 추첨을 저장하고, 재료 전체 차감과 결과별 획득 원장 및 완료 처리를 한 DB 거래로 실행한다. 중간 지급 실패는 전부 롤백하며 재시도는 저장된 결과를 사용한다.
- 다회 결과는 `attempts`, `results`를 추가하고 기존 `result`는 첫 결과로 유지한다. 기존 1회 영수증 및 미완료 준비 기록의 `:fusion` 획득 키는 유지한다. 다회만 `:fusion:0` 등의 개별 키를 쓴다. DB 스키마·공용 거래·인증 코드는 변경하지 않았다.
- 브라우저는 요청을 먼저 저장하고 응답 유실 시 같은 영수증을 조회한다. 재료 80장을 보낸 요청에 1회 영수증 등 일부 결과만 돌아오면 완료로 처리하지 않는다. 자동 복구는 GET만 수행한다.
- `/fusion/feature`의 `maxBatch`가 없는 이전 서버와 만날 경우 화면은 1회까지만 허용한다. 진입 모듈·스타일·정책 캐시 태그는 `20261019-bulk`다.
