# 장비 강화 · 보호권 · 파괴 이력 복구 기준 V1

2026-09-11 사용자 지시와 후속 `확률표 미정 · 시연 수치로 제작` 답변을 기준으로 한다.

## 사용자 확정 사항

- 강화 판정은 **성공 · 유지(무반응) · 파괴**의 세 가지다.
- 모든 단계의 **성공률 하한은 10%**다. 세 확률의 합은 정확히 100%다.
- **장비보호권을 출시할 예정**이며 게임 플레이로 극히 어렵게 획득한다. 상자·뽑기 획득은 제외한다.
- 파괴된 장비의 기록에서 **복구 쿠폰으로 장비를 되살리는 방식**을 사용할 예정이다. TJ는 사용자 설명의 비유이며 UI의 상품명이나 제휴 표시로 사용하지 않는다.
- 단계별 확률표는 미정이다. 이번 결과물은 조절 가능한 시연 수치로 제작하는 UI다.

## 이번 시연에서만 사용하는 가정

| 항목 | 체험 동작 | 운영 확정 여부 |
| --- | --- | --- |
| 강화 단계 | +0 → +15, 단계별 임시 확률표 | 미정 |
| 보호권 | 파괴 판정만 유지로 전환, 그때만 1장 소모 | 최종 소모 시점 미정 |
| 성공·유지 시 보호권 | 미소모 | 미정 |
| 강화 비용 | 모든 결과에서 단계별 시연 코인·결정 소모 | 재료 종류·수량·증가 규칙 미정 |
| 전투력 | 화면 비교를 위한 가상 기본값과 6% 단계 증가 | 미정, 운영 계산에 사용하지 않음 |
| 쿠폰 복구 | 파괴 직전 강화 단계·동일 장비 인스턴스 복구 | 실제 대상 기간·등급·단계·지급 정책 미정 |
| 복구 중복 | 파괴 기록 1개당 1회, 쿠폰 1장 소모 | 시연의 중복 방지 규칙 |
| 복구 시 재료 | 강화에 이미 소비한 재료 미반환 | 미정 |
| 획득처 | 보호권은 GAMEPLAY만 허용하는 준비 정책 | 구체 콘텐츠·수량·드롭률 미정 |

보호권을 체크해도 기본 판정의 세 확률을 숨기지 않는다. 기본값과 별도로 `보호 후 결과: 성공 S · 유지 M+D · 파괴 0%`를 보여 주며 성공률은 그대로다. 보호 발동은 네 번째 추첨 확률이 아니라 파괴 결과의 보존 처리다.

## 검수 진입점

2026-09-11 후속 피드백에서 V1의 성공 이펙트와 오래된 디자인·색감·컨셉이 반려됐다. 현재 같은 진입점은 **V2 Upgrade Lab**이다. 2026-09-12 사용자의 **`장비 프리뷰 해당 UI,연출 최종 승인 라이브 업데이트 준비할것`** 지시로 네이비·코발트·라임 UI와 성공·유지·파괴·보호·복구 연출을 최종 승인했다. V1 배경·보호권 원본은 반려 보존 상태를 유지한다. 확률과 경제는 기존 시연 모델이며 이번 UI·연출 승인이 운영 수치 확정을 뜻하지 않는다.

- `preview/equipment-forge-v1/index.html`: 장비 6종, 강화소/복구소, 확률표 편집, 보호권, 확인 창, 기록, 결과별 연출 시연.
- `preview/equipment-forge-v1/source/model.mjs`: 검수 전용 메모리 모델. 실제 계정·API·DB·브라우저 보유 자산 저장과 연결하지 않는다.
- `preview/equipment-forge-v1/source/fx.mjs`: 공유 PixiJS·GSAP UI 런타임으로 구현한 장비 강화 연출.
- `preview/equipment-forge-v1/source/success-v2.mjs`: 전용 연속 프레임, 에너지 압축·폭발·각성 연출.
- `preview/equipment-forge-v1/README.md`: 재생/검수 결과와 미확정 범위.

## 운영 연결 전에 남는 일

1. **UI·연출 최종 승인 완료.** 강화/보호/복구 상세 운영 정책은 미정 항목을 확정한다.
2. 확정 규칙에 맞춘 서버 권한·확률 추첨, 장비 인스턴스 잠금, 재료 차감, 파괴 기록과 복구 지급의 원자적 처리를 별도로 구현한다. 클라이언트 체험 모델을 운영 판정으로 사용하지 않는다.
3. 보호권은 상자·상점 자동 풀에 들어가지 않게 하며, 사용자가 확정한 게임 내 경로에만 명시적으로 연결한다. 이번 작업에서 획득 확률은 만들지 않았다.
4. 장비 파괴 시 실제 장착 해제·중복 요청·거래 상태, 복구 시 동일 기록 재사용·지급 0행·응답 유실을 서버와 실제 계정 구조로 검수한다.
5. 운영 연결 지시 이후 승인된 결과물만 출시한다. 깨끗한 배포 대상에서 `npm run release:gate` 통과 후 `npm run deploy:production`을 사용한다. 이번 시연 제작은 다른 PVE·레이드·블랙미라클의 기존 출시 대기를 해제하지 않는다.

현재 상태는 **UI_AND_EFFECTS_FINAL_APPROVED / LIVE_UPDATE_PREPARATION**다. 승인 원본 22개 파일의 SHA-256은 `preview/equipment-forge-v1/release/approval.json`에 고정했다. 현재 UI·연출을 다시 검수 대기로 취급하거나 V1으로 되돌리지 않는다.

라이브 적용 준비 기록은 `docs/equipment-forge-live-preparation-v1.md`다. 개별 장비 조회, 서버 결과 수신 계약, 중복 요청·응답 유실 처리, 고정 규칙·승인본 검증을 준비했다. 확률·소모·전투력·획득·복구 정책은 `release/launch-draft.json`에서 미정으로 유지한다. 실제 강화·파괴·복구 트랜잭션과 운영 진입점은 아직 구현·연결하지 않았다. 이번 요청은 업데이트 준비이며 운영 활성화 완료를 뜻하지 않는다.
