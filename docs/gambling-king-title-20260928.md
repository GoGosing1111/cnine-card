# 도박왕 — 승부예측 적중 업적

- 사용자 요청: 도박왕, 승부예측 적중 1,000회. 후속 지시를 반영한 최종 장착 전투력은 **60,000**이다.
- 기존 참여/정산 기록을 매칭해 누적 적중을 계산한다. 무효·환불·미정산과 오답은 제외하며, 같은 경기 추가 베팅은 기존 계정별 단일 참여 행이므로 횟수가 늘지 않는다. 기록을 삭제하거나 새 카운터로 초기화하지 않는다.
- 장비 화면의 기존 비동기 칭호 동기화에서 조건 달성 시 영구 칭호를 지급한다. 서버에서 현재 기록을 계산하며 타 계정 값/클라이언트 횟수를 사용하지 않는다. 중복 호출은 기존 소유권 고유 키로 보호하고, 지급 직전 CMS 조건·활성/공개 설정을 재확인한다.
- 신규 카탈로그와 전용 완료 marker를 한 배치로 등록한다. 기존 칭호·소유·장착·승부예측 정산/지갑은 변경하지 않으며, 이후 CMS에서 변경한 조건·전투력은 재배포로 덮어쓰지 않는다.
- `GAMBLING_KING`, `PREDICTION_HITS`, `{"count":1000}`, 장착 시 기존 공용 칭호 보너스에 따라 PVE/PVP 각각 +60,000. 한 개만 장착되므로 여러 칭호의 수치를 합산하지 않는다.
- 전용 투명 문장, 에메랄드/금색 배지, 획득 전 현재 적중 수와 진행 막대를 공용 칭호 화면에 연결했다. 기존 명함·공개 닉네임 배지 스타일 및 CMS 선택/편집을 재사용한다.
- 원화·프리뷰·생성 기록: `preview/gambling-king-title-v1/README.md`.

## 범위 배포 계획

- 직전 운영 확인: Pages `97702760-c1cc-4b82-806f-351975e39134`, 소스 `7726e19b`(배포 목록 확인).
- 기존 칭호 시스템에 조건/카탈로그 한 종을 추가한 국소 변경이며, 스키마·인증·공통 거래 기반·의존성 변경은 없다. `npm run deploy:production -- --scoped`를 사용한다.
- 선택 검사: `tests/prediction-title-20260928.test.mjs`(SQLite/PostgreSQL 누적 집계·999/1000 경계·원자적 등록·재시도·CMS 보존/재확인), `tests/equipment-loading.test.mjs`(장착·해제/60,000 보너스·진행도 표시), `tests/achievement-titles-20260927.test.mjs`(기존 업적과 공용 연결 보존).
- Worker 구문 검사와 지정 운영 검증은 배포 명령에서 함께 실행한다. 이미 끝난 PC/모바일 시각 검수와 무관한 전체 게임 검사를 반복하지 않는다.
- 고정 슈트 fixture 두 곳은 신규 카탈로그 marker를 포함하도록 갱신해 기존 고정 칭호 데이터를 유지한다.
