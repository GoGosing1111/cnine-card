## 정책을 임의로 확정하지 않는 항목

- 입장권 1장, 기존 일일 횟수·완주 코인·통합 드롭 풀을 우선 유지한다. 전투 프리뷰의 샘플 전투력은 운영 CMS 값이 아니다.
- 부품 목표 회수·추가 진격/철수·누적 확정 보상은 전투 검수 뒤 정책 확정이 필요한 후속 항목이다. 앞선 초안의 ‘컨테이너 확정’을 현재 운영 지급 정책으로 오인하지 않는다.
- 제한시간은 서버 시뮬레이션 한도와 화면 재생 시간을 구분한다. 배속·백그라운드 탭·기기 성능으로 승패/보상/순위가 달라지지 않아야 한다.
- 접속 중 제한된 원정과 오프라인 무한 파밍은 별개다. 무제한/오프라인 정산은 이번 1차에 추가하지 않는다.

## 기존 기반과 보호 대상

- `functions/_battle_v2_preview.js`: 실제 카드별 판정; 기존 인자만 전달하는 호출의 결과를 보존한다.
- `functions/_scrapyard.js`: 현재 운영 원정, 입장권 예약, 결과 기록. 신규 경로가 완성되기 전까지 그대로 사용한다.
- `functions/_drop_pool.js`: 구역별 `SCRAPYARD_PARTS_OUTER/CORE/FURNACE`, 클리어당 1회 드롭 영수증을 재사용한다.
- `preview/scrapyard-v3-v1/`: 승인 방향 확인용 외곽 전투. 브라우저 샘플 시뮬레이션이지 실계정 결과가 아니다.
- 실제 계정 전투 결과는 서버에서만 계산한다. 클라이언트는 서버 타임라인을 재생할 뿐 덱·피해·승패·보상 값을 제출하지 않는다.
- 기존 V3 진형·카드 도크·등급별 원화 프레임·배틀슈트 승인 외형을 유지한다. 카드 원화와 SD를 분리한다.

## 검증 기록

### 2026-09-09 — 서버·복구 기반

- 작업 브랜치: `codex/pve-continuous-overhaul`. 기준은 `425a0043`이며 원격 푸시·배포·운영 DB/CMS 변경은 하지 않았다.
- `functions/_battle_v2_preview.js`: `createPveBattleV2`에 명시적으로 전달하는 `encounter`만 처리한다. 기존 단일 몬스터 호출의 전체 JSON을 수정 전 커밋의 시드 1/17/7123과 SHA-256으로 비교해 일치를 확인했다. 프리뷰의 기존 시뮬레이션 골든 해시도 유지했다.
- `functions/_scrapyard_v3.js`: 기존 `raidDeckPower`의 저장 덱 ID 순서를 복원하고 기본 강화 전투력에 고유효과가 중복 적용되지 않게 분리한다. 마법·궁극기·슈트·전직은 기존 서버 의존성으로 읽는다. 클라이언트가 보낸 카드/피해/승패/시드는 읽지 않는다.
- `functions/_scrapyard_v3_runs.js`: 입장권 예약과 전투/추첨 스냅샷을 함께 저장한다. 보상, 지급 행 검증, 기존 드롭/원정 영수증과 최종 완료는 한 DB 트랜잭션으로 처리한다. 빈 추첨도 저장해 CMS 수정 후 재시도가 새로운 추첨이 되지 않게 한다. 아직 실제 운영 HTTP 경로에 연결하지 않았다.
- `functions/_drop_pool.js`: 기존 추첨/지급 함수를 재사용하는 읽기 전용 계획기와 지급 SQL 준비기를 추가했다. 기존 `resolveUnifiedDrops`의 분기·확률·호출 정책은 그대로다.
- `js/pve-continuous-session-v1.mjs`: 결과 확인 전까지 계정별 요청번호만 저장한다. 새로고침은 동일 영수증 조회, 중복 탭은 Web Locks와 서버 활성 원정 번호로 수렴한다. 자동 재시도는 횟수 제한·백그라운드 정지·이탈 정리가 있으며, 코인/카드/피해를 계산하지 않는다. 운영 UI에는 미연결이다.
- Cloudflare D1의 batch 원자성과 운영 PostgreSQL 호환 계층의 실제 BEGIN/COMMIT/ROLLBACK 동작을 기준으로 구현했다. 테스트 DB는 메모리 SQLite와 로컬 PGlite다. 실계정 재화를 사용하지 않았다.

### 다음 통합 단계 — 아직 남은 작업

1. 새 `scrapyardEncounter` 응답을 기존 V3 아트 어댑터·개체 교체 렌더러에 연결한다. `deckCards`는 원화 도크, `battleSprite`는 몬스터 전장에만 사용한다. 개체 ID의 `ENCOUNTER` 세대도 이전 개체의 대체 매칭으로 해석하면 안 된다.
2. 압축 설비·용광로의 나머지 SD 4종과 해체·회수 연출을 준비하고 3구역 화면을 검수한다. 미완료 SD는 현재 `null/resourceReady:false`로 명시했다. 배경 원화를 임시 전투 SD로 사용하지 않는다.
3. 입장/복구/진행/결과 UI와 CMS 설정을 연결한다. 라이브 호스트는 인증과 기존 계정 mutation lock을 유지하고, 스키마는 적절한 마이그레이션 권한으로 준비한다. 새 저장 모듈을 가져오는 것만으로 스키마가 만들어지지는 않는다.
4. 실제 계정 구조의 로컬 fixture → 통합 프리뷰 → 모바일 장시간/전 구역/경제 검수를 완료한다. 이 단계가 끝나기 전에는 전용 feature 플래그를 false로 유지한다.
5. 전체 묶음을 검수한 뒤 정식 번들·캐시·범위 커밋·깨끗한 배포 트리·원격 기준을 일치시키고 `npm run release:gate`를 다시 통과한 회차에만 `npm run deploy:production`을 실행한다.

### 2026-09-11 — 점유 자리만 그리는 전장 / PC 배치 승인

- 후속 사용자 검수에 따라 `preview/v3-wide-grid-v1/`의 전면 63칸 바닥을 제거하고 실제 유닛 자리만 표시하는 배치형 그리드로 교체했다. 기존 공통 V3·운영 진형·하단 카드 도크는 변경하지 않았다.
- 최종 용병 한도는 진영당 최대 1장이다. PVP 6 대 6, PVE 아군 일반 5 + 용병 1 + 슈트 1이며 슈트는 PVE 아군 진영 가운데에 둔다. 두 번째 용병 시안은 철회됐고 일반 덱 5장/API 분리 계약은 유지한다.
- 사용자가 PC 배치를 승인했다. PC 좌표는 동결하고, 모바일만 캐릭터 크기 유지 상태에서 가로·세로 배치 간격을 약 22% 줄였다. 모바일 수정안은 사용자 검수 대기다.
- 좌표·자산·검증 및 재생/취소 결과는 해당 프리뷰 README와 브라우저 검수 출력이 기준이다. 이 부분 승인으로 통합 출시 게이트나 용병 등급·획득·실제 전투 활성화 대기를 해제하지 않는다.
