## 확인한 원인과 수정

- 제작소의 장비 메뉴(`fusion`)도 최초에는 차량 화면을 만든 뒤 탭을 클릭했다. 차량 부품·설계도 원본 이미지 요청과 두 번의 화면 조립이 발생했다. 라우터가 최초 렌더링에 목적 섹션을 전달하고, 리소스 대기 중 셸 요약이 다시 그려져도 목적 섹션을 보존한다. 이미 선택한 탭 클릭은 DOM을 다시 만들지 않는다.
- API 선조회 응답의 1초 만료가 파일 다운로드 중에도 적용되어 느린 환경에서 최초 조회가 중복됐다. 첫 사용 전에는 계정·재화 변경 여부로 유효성을 확인하고, 첫 사용 후 1초 이내 셸 재표시는 같은 요청을 공유한다. 새로고침·거래 재확인·계정 변경·재화 변경·실제 화면 이탈 후 재진입은 새 조회다. 실패는 재시도 가능하며 늦은 응답이 다른 화면을 덮지 않는다.
- 작은 부품·코어·장비·차량에도 대형 원본을 요청했다. 기존 장비 WebP를 재사용하고 제작소 부품·코어·차량 14개 파생본을 추가했다. 원본 자산은 변경하지 않았다. 부품 세 개 1,719,774 → 17,230 bytes, 추가 파생본 전체 21,370,369 → 580,080 bytes. CMS의 새 이미지나 외부 URL은 기존 URL을 유지한다.
- 목록 이미지의 lazy/async 속성을 DOM 삽입 전에 부여한다. 큰 조립 연출 라이브러리는 계속 필요 시에만 로드한다.
