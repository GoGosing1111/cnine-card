# 2차 인증 유저 SSS 재뽑기권 메시지 지급 — 2026-10-15

사용자 요청: `2차인증메세지 전체유저에 SSS 재뽑기권 지급해`.

- 발송 시점 ACTIVE 상태이며 2차 인증을 완료한 계정 전체에 `MERCENARY_SSS_REROLL_TICKET` / SSS 재뽑기권 **1장씩** 메시지 첨부로 지급한다. 역할·인증 제공자·접속 여부로 누락하지 않는다. 정지 계정은 제외한다.
- 작업 키 `ops:verified-sss-reroll-message:20261015:v1`, 캠페인 `verified-sss-reroll-message-20261015-v1`로 대상 목록을 고정한다. 재실행·응답 유실·발송 이후 신규 인증으로 추가 발송하지 않는다.
- 서버 메시지 보상 허용 목록에 이 아이템만 추가한다. 기존 클라이언트의 서버 메타데이터 표시, 개별 수령·일괄 수령, 인벤토리 갱신을 그대로 사용한다. 쿠폰 허용 목록에는 추가하지 않는다.
- 메시지·첨부 보상·감사 로그·완료 영수증을 한 PostgreSQL 거래로 저장한다. 발송은 인벤토리를 변경하지 않으며 유저가 수령하면 기존 원자 수령 거래로 1장을 적립한다.
- SSS 재뽑기 운영 설정·확률·보유 용병은 변경하지 않는다. 재뽑기 실행은 기존 CMS 정책을 따른다.

관련 검사는 전체 대상/역할/제공자, 발송·수령 재시도, 실패 전체 롤백, 실 PostgreSQL 호환 수령, 일괄 수령, 기존 클라이언트 보상 버튼 표시다. 서버 허용 목록 1행 변경으로 scoped 배포한 다음 운영 DB dry run·발송·재실행·독립 조회를 기록한다.

운영 완료 수량·시각·감사 ID·배포 식별자는 실행 후 이 문서와 같은 이름의 JSON에 보존한다.
