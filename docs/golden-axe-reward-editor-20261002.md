# 금도끼·은도끼 CMS 보상 편집 — 2026-10-02

사용자 요청: 다양한 아이템 추가, 용병 등급 내 개별 확률 설정, 불필요한 보상 삭제. 뒤이어 나온 재료·보장 횟수 확인은 사용자가 다른 대화와 혼동했다고 철회했다.

- CMS 설정 → 핑두의 금도끼 은도끼에서 활성 인벤토리 아이템을 이름·코드로 검색해 추가한다. 아이템은 1~1,000,000개 수량을 지정하고 새 보상 확률은 0%에서 시작한다. 기존 배틀슈트·코인·S/SS/SSS 용병·꽝도 삭제 후 다시 추가할 수 있다.
- 보상 행에 수량·확률·삭제 버튼을 제공한다. 저장 전 마지막 삭제 취소를 지원하며, 삭제한 확률을 다른 상품에 자동 분배하지 않는다. ON 저장 시 전체 합계 100%와 적어도 하나의 당첨 보상을 요구한다.
- S/SS/SSS 등급 내 균등 또는 용병별 직접 설정을 유지하고 진입점을 명확히 표시한다. 직접 설정은 소수점 4자리, 합계 100%, 0% 제외를 적용한다. 균등값 채우기는 반올림 잔여분까지 배분해 정확히 100%를 만든다. 실제 추첨은 전역 획득 정책의 출시·OFF 제한을 계속 따른다.
- 서버는 저장된 보상 키·아이템 수량만 받아 카탈로그에서 지급 종류·코드·이름·이미지를 결정한다. 미등록 아이템, 중복 상품/동일 아이템 별칭, 잘못된 수량을 거부한다. 비활성 상품에 양수 확률을 주고 ON 저장하거나 참가하는 것을 막는다.
- 새 보상 배열이 없는 기존 운영 설정은 기존 13행과 확률 그대로 읽는다. 구 CMS 요청에 보상 배열이 없으면 현재 배열을 유지하므로 삭제한 상품을 되살리지 않는다. 보상 추가·삭제와 변경 내용은 기존 관리자 감사 로그에 기록된다.
- 아이템 지급·도끼 차감·영수증은 기존 단일 트랜잭션과 요청 중복 방지를 사용한다. 보상 삭제는 이벤트 추첨 목록만 바꾸고 인벤토리 카탈로그, 이미 받은 보상 및 영수증을 삭제하지 않는다. 구버전 참가 요청은 revision/quote 검증으로 차감 전에 거부한다.
- 유저 상품표·종수·수량·상세 설명은 저장된 목록에서 표시한다. 선택하던 보상이 없어지면 첫 상품으로 이동하고 빈 목록도 처리한다. 사용자 화면/API의 확률 비공개는 유지한다.
- 이번 배포는 운영 설정 자체를 저장하거나 초기화하지 않는다. 운영 기간, 회차 경계, 1개·하루 5회와 기존 확률을 유지한다. CMS 날짜 입력은 밀리초를 유지해 이후 보상 저장으로 운영 시각이 반올림되지 않게 한다.
