## 작업 기록

### 2026-09-13 계정·운영 정책 연결 완료분

- `functions/_pve_v3_routes.js`를 기존 인증과 계정 mutation lock에 연결했다. 서버가 보유 덱·용병·시드·결과·보상을 만들며 브라우저는 층/구역과 요청 ID만 보낸다. 탑·폐차장·카우방 결과는 소유자만 복구한다. 공동 활성화 시 예전 `tower/fight`, `scrapyard/run`은 거절해 구·신 보상을 동시에 열지 않는다.
- `pve-v3/`의 입장·진행·결과·복구와 OWNER CMS를 연결했다. 원정은 기존 오프라인 서버 진행·누적 보상을 사용하며 화면을 닫아도 중지하지 않는다. 수령은 진행 중인 원정을 끝내지 않고 기존 적립금만 원자적으로 지급한다.
- 용병은 5장 배열과 별개 보유/편성/성장 테이블을 사용한다. 등급 내 균등 복원 추첨, 최초/중복 집계, 묶음 개봉, 훈련/레벨 비용과 요청 재시도를 연결했다. `mercenary-hangar/`는 실제 보유 카드·코인·경험치·별도 슬롯을 표시한다. 운영 CMS 43종의 등급·스킬 배정·확률은 변경하지 않았다.
- 서버 17개 스킬 기믹을 순번/대상/준비/중단/피해/정화/상태/추가타로 처리한다. 2단계와 광역 타격은 서버 `skillPhaseIndex`를 사용하며 피해 예산을 복제하지 않는다. 피해 배율은 `1 = 100%`, `2.5 = 250%`다. 추가타·반격으로 자원을 다시 채우지 않는다.
- 총기·활 용병은 전열에 있어도 원거리로 분류한다. 응수와 접근 억제는 명시적인 `MELEE` 기본 공격만 받으며 미분류·사격·마법을 근접으로 간주하지 않는다. 일반 카드·몬스터는 서버 스냅샷의 명시적 공격 방식만 승계한다.
- PVP 양 진영·클랜·영토 고정 편성·공성·호위·PVE에 별도 용병을 전달한다. 호위는 구간 시작 용병과 HP를 고정하고 다음 구간에 승계하며, 용병이 생존했는데 일반 카드가 모두 쓰러졌다는 이유만으로 전멸 처리하지 않는다.
- 강화 견적·성공/유지/파괴·보호권 소비·정확한 장비 파괴 기록·새 인스턴스 복구를 한 거래로 처리한다. 재시도는 원래 견적·정책·추첨을 재사용한다. 바뀐 장비의 미완료 요청은 취소 상태로 끝내며 다른 장비에 비용을 전가하지 않는다. 강화된 장비는 제작 재료로 자동 소비하지 않는다.
