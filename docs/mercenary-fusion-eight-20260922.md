# 용병 중복 8장 합성 준비

## 확정 지시

2026-09-22 사용자가 용병도감의 중복 합성과 리니지M을 모티브로 한 고급 연출을 요청했다. 같은 등급의 서로 다른 용병을 섞을 수 있고, 중복 카드 8장을 소모한다. 모든 재료 등급의 승급 확률은 **10%**, 추가 비용은 **0**이다. 성공하면 한 단계 상위 등급 랜덤 1장, 실패하면 재료와 같은 등급 랜덤 1장을 지급한다.

- 기본 보유 1장은 항상 보존한다. 중복 8장을 쓰려면 기본 보유분과 별도로 8장이 있어야 한다.
- SSS는 더 높은 등급이 없으므로 재료에서 제외한다.
- 등급 안의 용병 선택은 기존 CMS 카드별 가중치를 따른다. 보유 여부는 가중치에 관여하지 않는다. 기존 SSS 개별 가중치를 새 합성이 임의로 초기화하지 않는다.
- 정책 단일 기준은 `shared/mercenary-fusion-policy-v1.mjs`다.

## 공개 준비판

용병도감 상단의 **중복 합성**에서 전체 화면 성소를 연다. 내 중복 카드의 등급 필터·8장 자동 선택·개별 추가·슬롯 제거를 제공한다. 기본 카드와 편성은 보존한다. 별도 연출 시연 목록은 보유 수량으로 표시하지 않으며 실제 계정 데이터를 수정하지 않는다.

`/mercenary-codex/?fusion=preview`는 같은 도감에서 성소를 바로 여는 주소다. 연출 시연의 도전 등급과 성공·동일 등급 결과를 직접 선택할 수 있다. 시연 결과는 확률 표본이나 실제 획득 기록이 아니다.

이번 요청은 준비 작업이다. `MERCENARY_FUSION_RELEASE_ENABLED=false`, 실제 합성 버튼 비활성화, 모든 계정 소모·지급 OFF를 유지한다. 사용자 시각 검수와 실제 합성 개방은 별도이며, 준비판 배포를 재료 소모 활성화로 해석하지 않는다. 향후 개방 시 서버 플래그뿐 아니라 현재 시연 UI를 실제 영수증 요청·복구 흐름에 연결하는 최종 작업이 필요하다.

## 연출

2026-09-22 후속 사용자 답변 **“연출자체는 좋네”**로 성소·흡수·봉인 파열·결과 공개 연출 방향을 승인했다. 같은 요청의 **“ui는 현재 메타에 맞춰서”**는 조작 UI를 현재 게임 기준으로 맞추는 지시다. 이 승인은 실제 합성 소모·지급 ON 지시가 아니다.

실제 구현: `mercenary-codex/fusion/fx.mjs`, 조작 화면: `app.mjs`, 원본 자산 및 프롬프트: `assets/manifest.json`, `assets/PROMPTS.md`.

기존 UI 공용 **PixiJS 8.20.0 / GSAP 3.13.0** 번들을 재사용한다. 합성 화면을 열 때만 로딩하며 전투 렌더러를 바꾸지 않는다. 카드 원화와 기존 프레임을 사용하고 SD는 사용하지 않는다. 작은 재료 카드는 도감의 기존 WebP 파생본을 재사용한다.

| 구간 | 시각 구성 |
|---|---|
| 0–1.6초 | 여덟 장이 각각 깨어나고 떠오름 |
| 1.6–3.7초 | 개별 나선 궤적·빛의 연결선으로 중심 봉인에 흡수 |
| 3.7–4.65초 | 봉인 균열과 압축 광원, 불규칙한 파열 가지 |
| 4.65–5.05초 | 암전과 예고음 감쇠로 짧은 정적 |
| 5.05초 | 전용 16프레임 아틀라스의 실제 형태 변화, 파편·지면 충격파 |
| 5.8–8.4초 | 결과 카드 공개·등급·이름, 잔광 정착 |

S·SS·SSS는 광선 수, 타원 고리 수·크기, 후광·왕관 모양을 달리한다. 동일 등급 결과는 대형 폭발·화면 흔들림·승급 후광을 생략하고 봉인이 잦아든 뒤 카드를 공개한다. 실패를 SSS 승급처럼 축하하지 않는다.

프레임, 궤적, 광원, 결과와 사운드는 한 GSAP 논리 시각을 사용한다. 재생·일시정지·탐색·다시 보기·닫기·탭 숨김을 처리하고, 종료 시 타임라인·렌더러·ResizeObserver·AudioContext·예약 음원을 정리한다. 공유 텍스처는 파괴하지 않는다. OS의 동작 줄이기 설정에서는 흔들림과 점멸을 없애고 바로 결과를 표시한다.

실녹음 기반 기존 라이선스 음원을 사용하며 생성 톤이나 오실레이터는 없다. 출처·해시·원본 가공 기록은 자산 매니페스트가 기존 사운드의 출처 문서를 참조한다. 충돌과 공개 피크는 5.05초와 5.8초에 예약한다. 오디오 장치 자체의 출력 지연은 측정하지 않았다.

## 현재 게임 UI 정렬 — UI2

`docs/ui-fixed-reference-20260915.md`와 현재 운영 용병도감·장비 강화 화면을 기준으로 조작 화면을 정리했다.

- 기존 도감의 배경·패널·경계·본문·보조문·라임 CSS 변수를 사용한다. 버튼·탭·선택 테두리·수량 표시도 같은 네이비/라임 기준을 따른다.
- 조작부는 기존 Noto Sans KR와 Barlow Condensed를 사용한다. 도감 진입과 헤더의 로마 숫자는 카드 아이콘으로, 비어 있는 재료 슬롯은 01~08로 바꾼다.
- 재료의 등급 표시는 도감의 공용 `rank-chip[data-rank]` 스타일을 그대로 사용한다. 성공률 10%, 성공/실패 결과, 추가 비용 없음은 조작 패널에서 함께 표시한다.
- 8개 슬롯, 목록 스크롤, 모바일 하단 버튼과 닫기 후 공통 메뉴 복귀를 유지한다. 공통 메뉴를 별도로 복제하지 않는다.
- 승인된 `fx.mjs`, 프레임 타임라인, 원본 이미지 3종, 사운드, 정책과 거래 코드는 변경하지 않았다. 무대의 금빛 연출과 결과 서체도 보존한다.
- UI 캐시는 `20260922-ui2`다. 공개는 계속 준비판이며 소모·지급 OFF다.

## 서버 준비

`functions/_mercenary_fusion.js`의 트랜잭션 코어는 기존 사용자 잠금, `joint_operations_v1` 영수증, 중복 수량 테이블과 카드 획득 기록을 재사용한다. HTTP에서 DDL을 실행하지 않는다.

- 8개 코드 배열을 코드별 수량으로 정규화해 요청 순서만 바뀐 재시도도 같은 영수증으로 처리한다.
- 서버 CMS 등급과 현재 중복 수량을 검사한 뒤 확률·카드·정책·CMS 버전을 영수증 계획에 먼저 고정한다.
- 정확한 소모 전 수량, 기본 보유 보존, 소모 후 수량, 결과 획득 행을 같은 DB 트랜잭션에서 검증한다.
- 지급 실패는 모든 차감을 되돌린다. 응답 유실과 동일 요청 재시도는 재추첨·재차감·재지급하지 않는다.
- 대기 영수증은 결제 전 결과를 노출하지 않는다. 중복 수량이 바뀐 대기 요청은 취소한다.
- 코인·별·경험치·레벨·편성은 변경하지 않는다.

읽기 전용 feature는 `/api/mercenaries/v3/fusion/feature`다. 합성 POST는 현재 OWNER도 423으로 차단되며 DB에 접근하지 않는다. 완료 영수증은 소유자 인증을 거쳐서만 조회한다. 실제 계정에서 시연을 위해 차감/지급하지 않는다.

## 검증

`tests/mercenary-fusion-eight.test.mjs`와 `tests/mercenary-fusion-transactions.test.mjs`는 SQLite 및 실제 PostgreSQL 호환 어댑터(PGlite)를 사용한다. 10% 경계, 기존 등급 내 가중치, 8장·혼합 등급·초과·최상위 등급 거부, 기본 카드 보존, 성공/실패 지급, 비용 0, 영수증 재생, 교차 계정 조회 거부, 지급 실패 롤백, CMS 변경 후 고정 결과 복구, 동시 요청, 응답 유실, 공개 OFF를 검사한다.

브라우저 검수는 `tests/serve-mercenary-fusion-qa.mjs`의 로컬 읽기 전용 서버에서 현재 공개 도감과 명시적인 가상 보유 수량을 사용한다. 해당 서버는 모든 쓰기 요청을 405로 거부한다. 1280×720, 1440×1000, 390×844, 320×740에서 실제 WebGL 화면·카드 선택·승급/동일 등급 공개·탐색·닫기를 확인했다. 운영 배포는 깨끗한 후보에서 전체 `npm run release:gate`를 거치는 `npm run deploy:production`만 사용한다.

최초 준비판의 개별 회귀 18개가 통과했다. 네 화면 크기에서 가로 잘림 없음, 8개 슬롯, 모바일 고정 버튼, S·SS·SSS 승급과 동일 등급 결과, 소리 켜기·재생·정지, 다시 열기, 닫은 뒤 캔버스 0개와 진입 버튼 포커스 복귀를 확인했다. 브라우저 경고·오류는 없었다. 이후 위 후속 답변으로 연출 방향만 승인됐으며, UI2 검수와 실제 활성화는 구분한다.

UI2도 1280×720, 1440×1000, 390×844, 320×740에서 실제 화면을 다시 확인했다. 8장 자동 선택·등급 변경·성공/동일 등급 공개·내부 스크롤·닫기 후 도감과 모바일 공통 메뉴 복귀가 동작한다. 320px 화면의 문서 폭은 320px 이내, 하단 버튼 영역 끝은 740px, 무대 시작과 헤더 끝은 일치했다. S 등급 재료의 색은 도감의 `rgb(191, 160, 251)`과 같으며, 닫은 뒤 연출 캔버스 0개·본문 스크롤 복구·브라우저 경고/오류 0개를 확인했다.
