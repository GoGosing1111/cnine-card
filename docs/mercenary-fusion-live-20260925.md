# 용병 합성 실제 ON · 2026-09-25

## 승인과 범위

- 사용자 지시: `이렇게 설정했다 이제 ON으로 돌리고 그전에 최적화 병목현상 점검 한번 더해`와 합성 진입창 장비 강화 링크 삭제, 메인 사이드메뉴 `제작소` → `장비 - 제작`.
- `MERCENARY_FUSION_RELEASE_ENABLED=true`. 기존 서버 합성 계약을 사용자 화면에 연결한다. 이전 준비/OFF 기록은 이 승인으로 합성에 한해 대체된다.
- CMS `용병 관리 → 합성 관리`의 저장된 공용 가중치를 그대로 읽는다. 운영 DB 설정·재화·보유량을 배포 준비나 검수 목적으로 수정하지 않는다. 사용자 화면에 표시한 8991:100:10의 SSS 추첨 경계를 회귀검사했다. 이 값들을 코드에서 강제하거나 운영 CMS에 재저장하지 않는다.
- 같은 등급 중복 8장, 기본 보유 1장 보존, 승급 10%, 동일 등급 90%, 추가 비용 0, 결과 1장, SSS 재료 제외를 유지한다. 다른 출시 플래그·공동 출시 정책은 변경하지 않는다.

## 실제 합성과 복구

- 일반 사용자의 내 중복 카드 선택 → 실제 POST → 서버 확정 결과 → 보유 목록 갱신으로 연결한다. 결과 선택·가짜 지급은 명시적인 `연출 시연` 탭에만 있다.
- 계정별 요청 ID와 8개 재료를 저장한 뒤 POST한다. 동일 화면 연타는 하나로 합치고, Web Lock을 지원하는 브라우저에서는 다른 탭의 동시 제출도 막는다. 서버의 기존 사용자 잠금·원자 트랜잭션·고정된 추첨 계획이 최종 지급을 보장한다.
- 빈 응답·연결 끊김·타임아웃·화면 닫힘에는 요청 ID를 남긴다. 재입장은 GET으로 기존 결과만 확인하며, 미완료 요청은 사용자가 `이전 결과 확인`을 눌러 같은 ID로 이어서 처리한다. 결과를 실제로 본 뒤에만 완료 기록을 정리한다.
- 저장 공간 오류에는 제출하지 않는다. 다른 계정으로 바뀌거나 화면을 닫으면 늦은 응답을 폐기한다. 보유 목록 갱신 실패는 합성 성공과 분리하여 결과를 유지하고, 목록을 다시 확인하기 전 추가 합성을 막는다.
- 연출 재생·결과 복구·시연은 재추첨하지 않는다. 지급이 완료된 뒤 원화를 표시하지 못해도 텍스트로 결과를 제공한다.

## 병목·무한 로딩 점검

- POST는 이미 확정된 거래 계획을 사용해 영수증용 거래 재조회를 1회 생략한다. 외부 GET 영수증의 계정 검사는 그대로 유지한다. 공통 DB/트랜잭션 구현·스키마·인덱스·인증·의존성은 변경하지 않는다.
- 재료 선택은 API 요청을 발생시키지 않는다. 실행 상태와 최신 보유 목록을 연출 초기화와 병렬 조회하며, 상태 재조회·보유 조회·실제 합성 각각의 중복 요청을 합친다.
- 소모 전 실제 결과 이미지를 미리 불러오지 않는다. 기존 재료 320px·결과 640px 파생 이미지, 같은 카드의 텍스처 재사용, 8초 이미지/12초 연출 기한과 닫힘 취소를 유지한다. API는 15초 중단 및 16초 최종 기한으로 무한 대기를 막고 한국어 오류와 복구 동작을 남긴다.
- 기존 PixiJS 8.20.0 + GSAP 3.13.0 번들, 승인된 연속 합성 연출·사운드·아트는 그대로 사용한다.
