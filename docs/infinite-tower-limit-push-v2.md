# 무한의탑 개편안 V2 — 나의 한계까지

2026-09-09 · 사용자 검토용 기획안 · 운영 수치·보상·출시 미확정

## 제안의 핵심

**한 번 끝내는 탑을, 해금한 층에 언제든 다시 들어가 성장하고 자신의 최고 기록을 경신하는 탑으로 바꾼다.**

층은 긴 여정의 중간 저장점이 아니라 독립된 난도다. 50층을 깬 유저는 40층에서 편하게 재료를 모으고, 편성을 바꾼 뒤 51층에 도전한다. 실패해도 50층 기록과 해금한 층은 남는다. 1층부터 다시 오를 의무는 없으며 원한다면 저층부터 연속 등반할 수 있다.

카우방은 다수의 적을 쓸어버리는 반복 사냥, 탑은 같은 편성을 얼마나 높은 난도까지 밀어 올리는지 시험하는 콘텐츠로 역할을 나눈다. 신규 레이드의 협동·QTE를 탑에 그대로 붙이지 않는다.

## 현재 구조에서 바꿀 것

현재 `js/tower-v1038.js`는 다음 한 층을 요청하고, 서버 `tower/fight`는 최고 설정층에 도달하면 `TOWER_COMPLETED`로 재등반을 막는다. `current_floor`와 `highest_floor`가 앞으로 갈 위치와 완료 여부를 함께 결정하며, 랭킹은 최고층 및 도달 시각을 사용한다.

| 현재 | 개편안 |
| --- | --- |
| 최고층 완료 후 재입장 불가 | 해금한 모든 층에 반복 입장 |
| 다음 한 층만 도전 | 층 선택: 반복 파밍 / 최고 기록 도전 |
| 한 층의 단일 몬스터 전투 | 소규모 무리·정예를 연속 처치하고 수호자와 결전 |
| 최고층에 먼저 도착한 순위 | 높은 층 → 해당 층의 짧은 공식 공략 시간 |
| 최초 클리어 중심 보상 | 최초 돌파 보상과 재등반 보상을 별도 관리 |
| 운영자가 상단 층을 계속 수동 배치 | 몬스터 묶음·난도 곡선으로 상위층 생성, 예외층만 수동 설정 |

기존 ‘시즌제 미사용’ 정책은 유지한다. 평생 최고 기록과 해금은 정기 초기화하지 않는다. 내부 DB의 `season_id`는 기존 호환용 운영 단위로 남길 수 있다.

## 실제 플레이 흐름

1. 로비에 **내 최고 50층 / 도전 가능 51층 / 추천 파밍 45층**을 표시한다. 추천은 최근 성공률·공식 공략 시간으로 계산하며, 전투 결과를 미리 보장하지 않는다.
2. `45층 재등반` 또는 `51층 한계 도전`을 누른다. 해금한 층 직접 입력과 ±1·±5 선택을 제공한다.
3. 저장된 PVE 일반 카드 정확히 5장, 계정 장비·마법·배틀슈트 상태를 서버가 입장 시 고정한다. 전투 중 장비 변경은 다음 입장부터 반영한다.
4. 선택층에서 무리와 정예를 처치해 **수호자 소환 진행도**를 채운다. 마지막 수호자까지 제한 안에 처치하면 성공이다.
5. 결과 화면에서 **같은 층 재도전 / 다음 해금층 / 편성 변경**을 바로 선택한다. 승리 후 각 원정은 체력·마법 예산을 새로 시작하고, 한 원정 안에서는 중간 회복·시작 효과 재발동을 하지 않는다.
6. 자동 재등반은 직접 켠 경우에만 시작한다. 횟수 제한을 지정하고, 패배·설정 변경·보상 예산 소진·사용자 중지 시 다음 입장을 멈춘다. 접속 종료 후 무한 자동 정산은 추가하지 않는다.

### 한 판의 구성 — 검수 시작안

| 구간 | 제안 |
| --- | --- |
| 진행도 0~100% | 일반 24마리 + 정예 3마리, 기존 적 슬롯 최대 3개 재사용 |
| 소환 규칙 | 일반 2점 ×24 + 정예 18점 ×3 =102점. 화면은 100%까지만 표시 |
| 수호자 | 진행도 충족 및 현재 교전 종료 후 1마리 등장. 추가 무리 생성 중지 |
| 공략 시간 | 공식 전투 시간 180초를 초기 검수안으로 제안. 실제 시간 단위 보정 검수 후 확정 |
| 패배 | 제한 초과, 원정대 전멸, 수호자 미처치 |

무리 구성은 현재 공통 엔진의 대기 개체 40마리 한도 안에서 시작한다. 무조건 개체 수를 늘려 난도를 만들지 않고, 높은 층에서도 처치 목표와 한 판 길이를 관리한다. 소환 진행도는 서버가 개체별 최초 KO에만 더한다. 복제 이벤트·재접속으로 중복 누적할 수 없다.

## 나의 한계를 만드는 난도와 해금

**적은 선택층과 고정된 난도 버전으로 결정한다. 유저 전투력에 따라 적을 같이 키우지 않는다.** 40층이 쉬워지는 것이 성장의 증거여야 한다.

- HP는 지속 피해량을, 공격은 생존력을 시험하도록 서로 다른 성장률을 둔다. 방어·방벽·반복 공격은 별도 상한과 역할을 가진다. 모든 능력치를 같은 배수로 올려 고층을 즉사·무적 구간으로 만들지 않는다.
- 10층 단위로 몬스터 계열과 전장을 교체한다. 방벽형, 다수형, 강타형 등 이미 서버가 지원하는 성향을 이용한다. 특정 카드 한 장이 없으면 절대 못 깨는 속성 면역·즉사 검사부터 도입하지 않는다.
- 기본 성공은 도전층 +1까지 해금한다. 압도적으로 빠른 성공에는 +2 또는 +3 해금을 제안한다. 임계치는 **남은 공식 시간 40% / 60%**로 검수를 시작한다.
- 빠른 클리어로 건너뛴 층은 ‘입장 해금’만 한다. 해당 층의 최고 기록·최초 보상까지 자동 지급하지 않는다.
- 이미 해금한 낮은 층을 반복해도 최고 해금층이 계속 늘어나지 않는다. `maxUnlockedTier = max(기존값, 완료층 + 해금폭)`으로 계산한다.
- 최고층 실패는 기록 하락·저층 강제 재등반·강화 재료 몰수를 만들지 않는다. 그 층에서 재도전하거나 낮은 층으로 내려간다.
- ‘최상층 클리어로 콘텐츠 종료’ 상태를 제거한다. 실제로 도달 가능한 범위를 넘는 수치도 안전하게 검증하되, 숫자 오버플로를 강제 승리·공짜 보상·동일 스펙 반복층으로 처리하지 않는다. 난도 생성 불능은 입장 전 오류로 막고 입장 비용을 차감하지 않는다.

### 예시

최고 기록 50층인 유저가 51층에서 수호자 HP 12%를 남기고 시간초과 → 최고 기록은 50층 유지 → 45층을 여러 번 돌아 재료 확보 → 광역 위주 편성을 수호자 피해량 중심으로 변경 → 51층 성공 → 52층 해금. 같은 51층을 더 빨리 깨면 그 층의 개인 최고 시간이 갱신된다.

## 재등반 보상과 경제

**도전 가능 횟수와 보상 수령량을 분리한다.** 보상을 다 받은 날에도 한계 도전·연습·기록 갱신은 가능해야 한다.

| 보상 | 지급 기준 | 중복 방지 |
| --- | --- | --- |
| 층별 최초 돌파 | 해당 층의 첫 성공, 마일스톤은 별도 연출 | 계정·층별 1회 영수증. 보상표 버전이 바뀌어도 재지급하지 않음 |
| 반복 클리어 | 선택층의 고정 반복 보상표, 일일 지급 예산 안에서 지급 | 원정 ID별 1회 정산 |
| 기록 달성 | 일정 최고층 도달 시 칭호·도감 표식 등 | 업적 ID별 1회 |
| 실패 | 최고 기록 유지, 원정 진단 제공 | 성공 보상·최초 보상 지급 없음 |

추천 방향은 **반복 보상은 기존 성장 재료 중심, 거래 가능한 코인은 낮은 비중**이다. 새 강화 시스템과 신규 재화부터 추가하지 않는다. 최초 보상에 있던 마력석·큐브·장비 드롭·주간 프리미엄 누적을 반복 루프에 그대로 복사하지 않고 각각 적용 여부를 정한다.

일일 예산은 새로운 아이템을 파는 방식보다 서버 카운터를 권장한다. 반복 보상 예산 소진 후에는 입장 버튼에 `보상 소진 · 기록 도전 가능`을 명확히 표시한다. 한 판 중 예산이 갱신되거나 자정이 지나도 입장 시 예약한 예산과 지급 정책을 그대로 사용한다.

입장 비용, 일일 보상 예산, 층별 재료 종류·수량, 코인 상한, 희귀 드롭 확률은 **미확정**이다. 위 원칙에 맞춘 실제 경제 시뮬레이션 후 확정하며 이번 기획으로 운영 값을 바꾸지 않는다.

## 공략 시간·랭킹·실패 진단

V3의 화면 재생 길이는 기기·배속·일시정지에 따라 달라진다. **랭킹 시간은 서버 전투 시뮬레이션의 공식 시간만 사용한다.** 렌더러가 끝났다는 클라이언트 신호나 벽시계 경과로 시간·승패를 결정하지 않는다.

현재 엔진의 `maxDuration`는 화면의 초 단위 제한과 다르다. 신규 `elapsedCombatMs`와 시간 변환 기준을 엔진 버전에 고정한 뒤 180초 검수안을 맞춘다. 공식 남은 시간은 서버 이벤트에 실어 V3가 표시하고, 일시정지하면 표시만 멈춘다. 현재 내부 값 `3`을 그대로 ‘3초 나락’처럼 노출하지 않는다.

- 랭킹: 최고 완료층 내림차순 → 그 층의 최단 공식 시간 → 같은 기록 최초 달성 시각. 배속, 탭 가림, 휴대폰 성능이 순위에 영향을 주지 않는다.
- 원정의 몬스터 묶음·시드는 서버가 발급하고 저장한다. 클라이언트 시드 제출, 새로고침 시 재추첨, 동일 입장의 편성 교체를 금지한다.
- 같은 층 순위는 같은 난도·엔진 버전에서 비교한다. 큰 밸런스 변경 시 구버전 기록을 보관하고 새 기록판을 사용하되, 평생 최고층과 이미 받은 보상을 삭제하지 않는다.
- 결과에는 격파 진행도, 수호자 잔여 HP, 아군 생존, 카드·슈트 피해, 공식 시간, 종료 사유를 보여준다. `시간 초과 / 전멸 / 수호자 미처치`는 서버 확정값이다. 편성 조언은 관측된 지표에 근거한 참고 제안으로 표시한다.

## 서버 저장·복구와 기존 데이터 이전

`최고 완료층`, `최고 해금층`, `이번에 고른 층`, `이번 원정`을 각각 저장한다. `current_floor` 하나를 되돌려 재등반하는 방식은 사용하지 않는다.

| 데이터 | 핵심 필드 |
| --- | --- |
| 개인 진행도 | userId, bestClearedTier, maxUnlockedTier, bestRunId, selectedTier |
| 원정 | runId, requestId, userId, tier, seed, rulesVersion, snapshot, status, result |
| 개인 층별 기록 | userId, rulesVersion, tier, bestCombatMs, completedAt |
| 정산 | runId, policyVersion, firstClearTier, dailyBudgetDate, rewardPlan, status |

- 기존 최고층과 최초 보상 내역은 보존한다. 기존 최고층은 새 진행의 해금 출발점으로 이전하되, 구형 단일 몬스터 기록에 새 공략 시간을 꾸며 넣지 않는다. 신규 규칙의 랭킹 기록은 새 도전에서 만든다.
- 재화 예약·전투 스냅샷·보상 추첨을 서버가 고정한다. 결과 지급·지급 행수 검증·영수증 완료는 한 트랜잭션이다. 이미 받은 최초 보상을 재등반·정책 이전으로 다시 받을 수 없다.
- 계정당 활성 원정 하나, 중복 탭과 응답 유실은 같은 runId로 수렴한다. 재접속은 기존 원정을 재생하거나 결과를 조회한다.
- 일반 카드 배열은 정확히 5장이다. 배틀슈트와 용병을 카드 배열에 끼워 넣지 않는다. 용병은 별도 편성 연결 승인이 난 경우에만 전용 슬롯 규칙을 따른다.

## CMS와 구현 순서

CMS에는 모드(TEST/OFF/ON), 난도 버전, 기본 적 능력치와 단계별 성장 곡선, 무리·정예·수호자 풀, 진행도 값, 공식 시간 제한, 해금폭, 층별 최초/반복 보상표, 일일 예산, 자동재등반 최대 연속 횟수를 둔다. 수치 누락·역전·오버플로는 저장 시 차단한다. 보상 예산 0을 무제한으로 해석하지 않는다.

1. 공통 V3 연속 교전의 서버 결과→렌더러 연결과 원정 복구를 완성한다. 카우방 구현의 무리·정예·보스 교체도 이 경로를 재사용한다.
2. 탑 서버를 독립 원정·층 선택 계약으로 바꾼다. 기존 운영 탑은 전환 전까지 유지한다.
3. 최초/반복 보상 분리와 기존 진행도 이전을 검증한다.
4. 로비·결과·자동 재등반·공식 시간·기록판을 연결한다.
5. 저전력·고전력, 같은 층 100회 반복, 재접속·다중 탭·자정·CMS 변경, 보상 0행 롤백, 모바일·배속·가려진 탭을 검수한다.
6. 기획·경제 확정 후 별도 출시 회차를 정한다. 이 기획서만으로 탑을 기존 PVE 통합 배포 묶음에 다시 넣거나 운영 API를 전환하지 않는다.

## 참고한 나락 구조

블리자드의 [공식 나락 소개](https://news.blizzard.com/en-us/article/24077223/galvanize-your-legend-in-season-4-loot-reborn)에서 `몬스터 처치 → 수호자 출현 → 제한 내 성공 → 더 높은 난도 해금`과 빠른 성공의 추가 난도 해금을 참고했다. 해당 글은 시즌 4 소개이며 최신 시즌의 모든 수치를 뜻하지 않는다. 위 제안의 층 구조·180초·진행도·보상 예산은 숲켓몬용 초안이다.
