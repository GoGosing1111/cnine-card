# 펀딩 사은품 상자 개봉 잠금 충돌 수정 — 2026-09-30

## 재현·원인

지급된 상자 3개를 보유한 이용자가 개봉할 때 `같은 계정의 요청을 처리 중입니다`(409)가 표시됐다. `inventory/use`는 `SERIALIZED_GAME_PREFIXES`의 `inventory/` 규칙으로 요청 진입 시 사용자 잠금을 획득한다. 같은 요청 안에서 펀딩 상자와 영입전 상자 분기가 `withJointUserMutationLock`을 다시 호출해 자기 자신과 충돌했다.

운영 읽기 전용 조회(2026-09-30 18:48 KST): 펀딩 상자 77계정·218개 보유, 펀딩 상자 개봉 영수증 0건, 차감 원장 0건, 활성 DB 사용자 잠금 0건. 상자는 차감되지 않았고 보상 지급도 시작되지 않았다.

## 수정·검증 범위

`functions/api/[[path]].js`의 펀딩·영입전 상자 개봉에서 두 번째 잠금 호출만 제거한다. 진입 시 `inventory/use`의 기존 잠금과 계정 인증은 유지한다. 보상 계획·재화 차감·원자적 지급·요청 번호 재시도 코드는 변경하지 않는다. 관리자 지급 분기의 잠금도 그대로 둔다.

기존 두 상자 거래 회귀 18개는 모두 통과했다. 개봉 보상·중복 요청·잔액 보호·중간 오류 롤백·기존 영수증 재확인과 관리자 지급을 포함한다. 별도 `tests/gift-box-double-lock-20260930.test.mjs`는 실제 경로 코드에서 바깥 잠금과 두 상자 분기를 결합해 중복 획득이 없는지 확인한다.

직전 운영 Pages 소스는 `4c93018bb07cf12b3f0aa36012d136f917813096`(배포 `db8bf907-ce12-4cd9-9c6b-adf25be29e42`)이다. 그 이후 이번 수정 전까지의 원격 변경은 문서·일회성 운영 스크립트뿐이다. 국소 라우트 수정이므로 `npm run deploy:production -- --scoped`를 사용한다. 선택 검사는 새 잠금 회귀 1개와 Worker 문법 검사이며, 출시 플래그·캐시·Hyperdrive·깨끗한 커밋 검사는 배포 도구가 수행한다.
