# PROJECT V 용병 시스템 준비 규정

- 규정 ID: `PV-MERCENARY-SYSTEM-1.0`
- 상태: 전투 편성 준비 · 읽기 전용 도감 공개 승인
- 확정일: 2026-08-29
- 최종 갱신: 2026-09-07 (도감 정보 열람 예외 승인)
- 적용 범위: 숲켓몬 PVE·PVP 편성에 추가될 PROJECT V 용병 전용 슬롯

## 1. 편성 구조

용병은 기존 덱의 여섯 번째 일반 카드가 아니다. 기존 덱과 분리된 전용 계약 슬롯이다.

| 구분 | 수량 | 저장 필드 | 비고 |
|---|---:|---|---|
| 일반 카드 덱 | 정확히 5장 | `cardIds` | 기존 PVE/PVP 덱·프리셋·시너지 규칙 유지 |
| 용병 전용 슬롯 | 최대 1장 | `mercenaryCode` | 선택 사항, 일반 카드 배치 불가 |
| 실제 전투 편성 | 최대 6장 | 두 필드를 전투 시작 시 합성 | 5장 + 용병 1장 |

- 용병이 없으면 기존과 동일한 5장 편성이다.
- 용병이 있으면 전투 필드에서만 6번째 독립 유닛으로 합류한다.
- 일반 덱 검증의 `length === 5` 조건은 바꾸지 않는다.
- 일반 덱 시너지는 기존 5장만 평가한다. 용병 효과가 일반 덱 시너지에 관여할 경우 별도의 명시적 규칙을 추가한다.
- 용병 전투력과 효과는 일반 카드 합계에 억지로 포함하지 않고 별도 항목으로 계산한 뒤 최종 전투력에 합산한다.

## 2. 저장·API 계약

권장 저장 구조는 아래와 같다.

```text
mercenary_loadouts
- user_id
- deck_type        // PVE, PVP_ATTACK, PVP_DEFENSE 등
- mercenary_code   // V-001 형식, 비어 있으면 미배치
- updated_at
- PRIMARY KEY(user_id, deck_type)
```

요청·응답 예시는 다음처럼 분리한다.

핵심 계약은 `cardIds` 5장과 `mercenaryCode` 1개를 별도 필드로 유지하는 것이다.

```json
{
  "cardIds": ["101", "102", "103", "104", "105"],
  "mercenaryCode": "V-001"
}
```

`cardIds`에 용병 코드를 여섯 번째 원소로 추가하지 않는다. 이 분리는 기존 덱 프리셋, 클랜전, 레이드, 랭크전, 시너지와 관리 도구의 5장 전제를 보호한다.

## 3. 카드 원화와 SD

- 도감·상점·덱·용병 선택·상세·스킬 컷인은 `sourceArt`를 사용한다.
- 실제 전투 필드의 6번째 유닛은 승인된 투명 `battleSprite`만 사용한다.
- V-001~V-012는 기존 SD가 보존되어 있다.
- V-013~V-020은 승인 원화와 별도 투명 SD가 준비되어 있으며 SD는 기술검수 완료·사용자 시각검수 대기 상태다. SD를 원화로 대체하지 않는다.
- V-021 오메가-X는 사용자가 원본 그대로 추가하도록 지정한 736×1104 RGB JPEG다. 준비 프리뷰에서는 `USER_SUPPLIED_SOURCE_ART`로 보존하되 승인 마스터 최소 규격을 충족한 것으로 표시하지 않는다.
- V-021 역시 원본과 분리된 투명 SD가 준비되어 있으며 기술검수 완료·사용자 시각검수 대기 상태다. 원화를 전투 스프라이트로 대체하지 않는다.
- V-001~V-012의 과거 원화는 로스터 식별용 기존 자산이다. 신규 작화 앵커 권한은 없다.

## 4. 등급 정책

- 전체 37종의 신규 시스템 등급 초기값은 `null`이다.
- 등급 상태는 `PENDING_USER_ASSIGNMENT`로 고정한다.
- 과거 V-001~V-012 매니페스트와 V-013~V-020 초기 프리뷰에 표시된 등급은 참고 이력일 뿐 신규 시스템에 자동 반영하지 않는다. 신규 V-021도 등급을 자동 추정하지 않는다.
- 사용자가 통합 프리뷰를 확인해 코드별 등급을 지정한 뒤 새 버전 로스터로 확정한다.
- 등급 미확정 상태에서는 드랍률, 획득 경로, 전투력, 강화 한도와 확률을 결정하지 않는다.

- 단일 준비 로스터: `assets/ui/project-v/mercenaries/mercenary-system-roster-v1.json`
- 통합 프리뷰: `preview/project-v-mercenary-system-v1/index.html`
- 편성 계약 모듈: `js/project-v-mercenary-loadout-v1.js`
- 전투 SD 해석 모듈: `js/project-v-mercenary-battle-art-adapter-v1.js`
- 현재 상태: `PREVIEW_ONLY_NOT_RUNTIME_CONNECTED`

2026-08-31 기준 전투 SD 21종은 모두 로스터와 검수 프리뷰에 연결됐다. 전투 SD 해석 모듈은 `BATTLE_FIELD` 계열 소비자에만 `battleSprite`를 반환하고 도감·상점·덱·상세·스킬 컷인·하단 카드 도크에는 반환하지 않는다. 등급 21종은 여전히 `PENDING_USER_ASSIGNMENT`이므로 운영 DB·덱 저장 API·라이브 전투 편성 활성화는 아래 금지선을 유지한다.

사용자가 등급을 확정하고 라이브 연결을 지시하기 전에는 다음 작업을 하지 않는다.

- 운영 DB 마이그레이션 실행
- PVE/PVP 저장 API 변경
- 기존 5장 전투엔진에 임시 여섯 번째 원화 투입
- 드랍풀·상점·도감·강화 시스템 노출
- 과거 임시 등급에 따른 밸런스 수치 확정

### 2026-09-07 · 읽기 전용 용병도감 공개 승인

사용자의 “도감 공개해봐 라이브로 보고 수정사항 적게” 지시에 따라 위 노출 금지선 중 **도감 정보 열람만** 예외로 승인됐다. `/mercenary-codex/`를 운영 `도감·강화 → 용병도감`에서 같은 탭으로 연다.

- 이름·칭호·역할·원화·전투 SD 21종을 준비 로스터 그대로 조회한다. 원화/SD와 승인 상태를 구분한다.
- 등급·능력치·스킬·획득 경로는 확정 대기다. 기존 임시 등급을 승계하지 않는다.
- 도감은 계정 API를 호출하지 않으며 즐겨찾기는 브라우저 로컬 정보다. 보유 카드나 편성으로 취급하지 않는다.
- 이번 승인은 뽑기·상점·강화·덱 저장·전투·운영 DB 연결을 포함하지 않는다. 로스터의 `PREVIEW_ONLY_NOT_RUNTIME_CONNECTED` 및 5+1 편성 계약은 유지한다.
- 기존 독립 검수 화면은 유지하고, 공개 HTML은 동일한 UI를 공유하는 빌드 결과다. `npm run build:mercenary-codex`로 갱신한다.

### 2026-09-07 · 신규 승인 원화 16종 추가

- 사용자의 `맨 위 사진부터 다 승인하니까 용병 도감 라이브에 추가해라` 지시에 따라 금발 여성·남성 기준 원화 2종, 무기별 8종, 여성 총기 추가 6종을 V-022~V-037로 추가한다.
- 기존 V-001~V-021은 보존한다. 전체 원화 37종, SD 준비 21종, 신규 SD 제작 대기 16종이다.
- V-024는 후속 지시에 따라 검은 드레스·얼굴·배경을 유지하고 권총을 판타지 SKS로 수정한 최종본을 사용한다. 이전 권총 V1·파지 V2는 독립 작화 기록에 보존한다.
- 승인 기록은 `assets/ui/project-v/mercenaries/mercenary-art-approval-20260907.json`이다. 신규 이름·칭호는 콘셉트 기반 가칭이며 역할도 원화의 무기 콘셉트 기준임을 상세에 표시한다.
- `sourceArtStatus=APPROVED_SOURCE_ART`, `battleSprite=null`, `battleSpriteStatus=NOT_YET_PRODUCED`로 구분한다. 신규 카드를 전투 소비자가 요청하면 SD 아트 어댑터는 `null`을 반환하고 원화로 대체하지 않는다.
- 이번 연결도 읽기 전용 도감에 한정한다. 전원 등급 `null`, 5+1 계약, 계정 API·뽑기·덱·전투 연결 금지선을 유지한다.
