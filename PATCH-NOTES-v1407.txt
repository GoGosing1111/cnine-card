CNINE CARD v1407 - STARTUP / DRAW OVERLOAD STABILITY CUMULATIVE PATCH

기준
- cnine-card(38).zip 최신 전체본
- v1400~v1406 누적 변경 포함
- 전체 프로젝트가 아니라 수정·신규 파일만 포함한 누적 패치

점검 결론
- 일반 카드팩 개봉 연출은 서버 요청과 동시에 실행되므로 연출 시간이 D1 과부하의 직접 원인은 아니었다.
- 가장 큰 문제는 과부하 시 여러 사용자가 새로고침하면서 시작 API 요청이 다시 몰리는 재접속 폭주였다.
- 기존 시작 흐름은 상태, 세션, 버닝, 상단 요약, 카드, 팩, 선택 기능 조회가 짧은 시간에 겹칠 수 있었다.
- 자동뽑기 100장 묶음 응답은 동일 카드 메타와 전체 사용자 도감 스냅샷을 반복 전송해 응답 직렬화와 네트워크 사용량이 컸다.
- 동일 Worker isolate 안에서도 여러 대형 뽑기가 동시에 인증·처리를 시작해 D1에 순간 부하를 줄 수 있었다.

v1407 변경
1. 시작 연결 통합
- /api/bootstrap 신규 경량 시작 API 추가.
- 점검 상태, 로그인 세션, 버닝 상태, 사용자 재화 요약, 필요 시 카드팩 목록을 한 HTTP 요청으로 통합.
- 인증과 점검/버닝 설정을 한 D1 batch 왕복으로 묶음.
- 팩 목록은 서버 60초 isolate 캐시 재사용.
- 기존 service/status → me/summary → burning → packs 연속 호출 제거.

2. 새로고침 폭주 방지
- 정상 시작 캐시가 있으면 서버 응답을 기다리지 않고 기존 화면을 즉시 표시.
- 연결 복구는 5/10/20/30초 기반에 사용자별 임의 지연을 추가.
- 백그라운드 GET 요청은 과부하 시 자동 재시도하지 않고 최대 60초 회로 차단.
- 카드 카탈로그 최신화는 로그인 직후가 아니라 60~150초 후 분산 실행.
- PVP/마법 상태는 30~60초 후 분산 실행.
- 상단 요약은 8~17초 후, 보급상자 설정은 5~12초 후 지연 조회.
- 브라우저 포커스 복귀 시 버닝 fresh 강제 조회 제거.

3. 서버 핵심 경로 경량화
- 로그인, 카드, 팩, 카드뽑기, 버닝, 레이드 상태, 영토전 등 핫 경로에서 전역 정리 작업 시작 금지.
- 완료된 운영 DB에서 핫 경로가 전체 런타임 업그레이드 게이트를 반복 대기하지 않도록 분리.
- 경량 로그인 복구는 전체 사용자 도감 profile을 생성하지 않음.
- 세션 생성의 만료 정리, 생성, 계정당 20개 상한 정리를 한 D1 batch로 합침.

4. 카드뽑기 입구 부하 제어
- Worker isolate별 무쓰기 입구 제어 추가.
- 수동 단일 뽑기 weight 1, 자동/서버 묶음 weight 2, 총 weight 3까지만 동시에 진입.
- 초과 요청은 인증 D1 조회와 영수증 쓰기 전에 즉시 DRAW_ADMISSION_BUSY로 반환.
- 클라이언트는 동일 requestId를 유지하고 5~12초 임의 지연 후 안전 복구.
- 이 장치는 전역 큐가 아니라 isolate별 순간 폭주 완화 장치이며 D1에 추가 잠금 행을 만들지 않음.

5. 버닝 자동뽑기 요청 분산
- 일반: 내부 최소 5초 + 35~75% 임의 지연.
- 버닝: 내부 최소 10초 + 40~90% 임의 지연.
- 하이퍼 버닝: 내부 최소 15초 + 45~100% 임의 지연.
- 자동뽑기 시작 시에도 모드별 0.9~10초 임의 분산.
- 화면의 설정값은 유지하지만 서버 보호 최소 간격을 우선 적용.
- 최대 5회/100장 서버 묶음, 확률, 천장, FUR 최초 보정, 중복 보상 규칙은 변경하지 않음.

6. 100장 응답 경량화
- 동일 카드 전체 메타는 cardCatalog에 한 번만 전송.
- 각 결과는 카드 ID/제목/등급만 전송하고 클라이언트에서 복원.
- 전체 사용자 도감/수량 스냅샷 대신 coin, shards, stars 등 DRAW_PARTIAL 요약만 전송.
- 대표 100장/25종 모델에서 JSON 91,554 bytes → 38,650 bytes, 약 57.8% 감소.
- 완료 영수증은 기존 compact 구조를 유지.

7. 기타
- draw context 서버 캐시 15초 → 30초.
- 자동뽑기 복구 시도 최대 3회.
- 기존 v1405 SQL 변수 81/75개 이하 청크 유지.
- js/app.js 정적 캐시 버전을 v1407로 갱신.

변경하지 않은 항목
- 카드팩 확률과 카드 풀
- SSR 천장과 FUR 최초 보정
- 버닝 할인/중복 배수 수치
- 수동 뽑기 지급 규칙
- 카드 연출, 전투, 장비, 영토전 판정
- 기존 D1 테이블과 운영 데이터

운영 확인 필요
- 이 패치는 재접속 폭주와 카드뽑기 순간 부하를 크게 줄이지만 Cloudflare D1 자체의 전역 단일 쓰기 한계를 제거하지는 않는다.
- 배포 후 버닝 시간대 D1 rows read/write, queued-too-long, Functions 5xx, bootstrap 응답시간을 확인해야 한다.
- 실제 동시 접속에서도 계속 D1 과부하가 발생하면 Durable Object 전역 큐 또는 MySQL/PostgreSQL 이전이 최종 해결책이다.
