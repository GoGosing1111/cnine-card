CNINE CARD v1405 - AUTO DRAW D1 SQL VARIABLE LIMIT HOTFIX

기준
- v1404 누적 패치 위에 적용하는 누적 패치입니다.
- v1400~v1404의 수정 파일을 모두 포함합니다.
- 전체 프로젝트와 이미지 리소스는 포함하지 않습니다.

원인
- v1403 서버 묶음 자동뽑기는 최대 100장을 한 번에 처리합니다.
- 100장 결과에 고유 카드가 많으면 아래 SQL이 D1의 문장당 바인드 변수 한도를 초과했습니다.
  1) 보유 카드 조회: user_id 1개 + card_id 최대 100개 = 최대 101개
  2) user_cards 다중 UPSERT: 카드 1종당 3개 변수, 최대 100종 = 최대 300개
  3) 완료 영수증 복구용 카드 상세 조회도 고유 카드 수만큼 변수가 증가
- 결과적으로 D1_ERROR: too many SQL variables 오류가 발생하고 자동뽑기가 0회에서 중단될 수 있었습니다.

수정
- 카드 ID IN 조회를 최대 80개씩 분할했습니다.
- user_id가 추가되는 보유 카드 조회도 최대 81개 변수로 제한했습니다.
- user_cards 지급 UPSERT를 최대 25종씩 분할했습니다.
  - 문장당 최대 75개 변수
- 분할된 모든 지급 UPSERT는 기존과 동일한 최종 env.DB.batch 안에 넣어 원자 처리를 유지합니다.
- 완료 영수증 결과 복구용 카드 상세 조회도 80개씩 분할했습니다.
- 추첨 확률, SSR 천장, FUR 최초 보정, 10장/20장 보장, 버닝 배수, 재화 계산은 변경하지 않았습니다.
- 서버 묶음 최대치는 기존과 동일하게 5회 x 20장 = 100장입니다.

적용 후
- 기존 실패 화면은 닫고 같은 설정으로 자동뽑기를 새로 시작하면 됩니다.
- 실패한 요청은 카드/코인 지급 전에 중단된 건이므로 중복 지급 복구 작업은 필요하지 않습니다.
