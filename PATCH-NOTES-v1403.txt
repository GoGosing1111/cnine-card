CNINE CARD v1403 — 버닝/하이퍼 버닝 자동뽑기 서버 묶음 최적화 누적 패치

적용 기준
- v1400, v1401, v1402 변경 사항을 모두 포함한 누적 패치입니다.
- 전체 프로젝트가 아니라 수정·신규 파일만 포함합니다.
- 기존 프로젝트 루트에 그대로 덮어씁니다.

핵심 변경
1. 자동뽑기 서버 묶음 처리
- 간소화 연출 사용 + 등급 정지 조건 없음일 때 자동뽑기 최대 5회를 한 요청으로 처리합니다.
- 20장 기준 최대 100장을 한 서버 요청에서 순차 판정합니다.
- 1장/10장/20장 개봉 단위는 그대로 유지합니다.
- 등급 정지 조건 또는 전체 연출 사용 시에는 기존처럼 1회씩 요청합니다.

2. 기존 확률·보정 규칙 유지
- SSR 천장, FUR 최초 획득 보정, LIMITED 품절 대체, 크리티컬 판정을 회차별 순서대로 계산합니다.
- 10장/20장 보장 규칙을 각 회차마다 별도로 적용합니다.
- 카드 지급, 코인·조각·마스터의 별, 천장·보정 상태는 최종 결과를 합쳐 한 D1 배치로 반영합니다.
- 확률값과 카드 풀은 변경하지 않았습니다.

3. 동시 요청 파도 분산
- 자동뽑기 최초 시작 시 0.7~3.5초 임의 지연을 적용합니다.
- 이후 요청에도 설정 간격의 25~60% 임의 지연을 추가합니다.
- 여러 사용자가 같은 시각에 시작해도 요청 주기가 계속 겹치지 않도록 했습니다.

4. D1 과부하 회로 차단
- 자동뽑기 복구 재시도 상한을 5회로 제한합니다.
- D1_BUSY가 반복되면 15~90초 보호 대기 후 재개합니다.
- 서버가 15~25초 범위의 retryAfterMs를 반환해 재시도 시점도 분산합니다.
- PENDING 요청은 새 요청 ID로 중복 제출하지 않고 동일 영수증을 복구합니다.

5. 버닝 설정 조회 완화
- Worker 인스턴스 내 버닝 설정 캐시를 1초에서 10초로 조정했습니다.
- 카드뽑기마다 버닝·하이퍼 버닝 설정을 반복 조회하는 빈도를 줄였습니다.

6. 대형 영수증 억제
- 자동뽑기 묶음 결과는 경량 runs 요약과 카드 식별 정보로 응답합니다.
- 직전 대형 완료 영수증은 다음 묶음 성공 시 즉시 보관형으로 축약합니다.
- 페이지 새로고침 또는 응답 유실 시 동일 requestId로 묶음 결과를 안전하게 복구합니다.

변경하지 않은 영역
- 수동 뽑기 동작과 연출
- 카드 등급 확률 및 카드 풀
- SSR 천장 및 FUR 보정 수치
- 카드 전투·강화·진화·PVE·PVP·레이드·영토전 판정
- 기존 D1 테이블과 운영 데이터
